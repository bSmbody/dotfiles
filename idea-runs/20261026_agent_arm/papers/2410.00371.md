# AHA: A Vision-Language-Model for Detecting and Reasoning Over Failures in Robotic Manipulation

## What this paper does
AHA instruction-tunes a 13B LLaVA-style VLM on 49k synthetic failure image-text pairs produced by FailGen, which perturbs RLBench keyframes along a seven-mode taxonomy (no grasp, slip, translation, rotation, no rotation, wrong action order, wrong object). Per sub-task it predicts Yes/No success and, if No, a free-form explanation, from one concatenated grid of keyframes across views. It is plugged into Eureka reward reflection, PRoC3S TAMP replanning and Manipulate-Anything sub-task verification.

## Goal-by-goal answers
### Goal: How does it produce failure examples and what is the verifier's input?
FailGen "systematically perturbs successful robot trajectories"; e.g. No_Grasp omits gripper close commands, Slip "introduces a timed release of the gripper shortly after activation" [full text, Sec 3.1–3.2, 4.2]. Input is a single image: keyframes up to the current sub-task concatenated in time, rows for each camera view [Sec 4.1].

### Goal: How is the verdict consumed and what limitation does it state?
In PRoC3S the VLM checks whether a plan "truly achieves the natural language goal, with replanning triggered if not"; in Manipulate-Anything it replaces GPT-4V in the sub-task verification module (+5% average success) [Sec 5.3]. Limitation: outputs are "closely aligned with the failure scenarios in the fine-tuning data" [Sec 6].
