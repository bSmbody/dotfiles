# Large Multimodal Models for Direct Robot Control: GPT-6 as a Beginning (GPT-GEAR)

## What this paper does
Evaluates GPT-6 Astra as a direct closed-loop manipulation controller through GPT-GEAR, a tool-mediated agent (Observe / Reference / Act / Status / Finish). Astra emits bounded end-effector pose increments that a controller executes synchronously; it is tested on five simulated benchmarks (164 tasks; 26.92% RoboDojo, 76.0% RoboTwin 2.0), a new LIBERO-GeoMotion benchmark and five real tasks (40% zero-shot, 80% with one in-context demo). Identifies deficits in long-horizon execution, precision, coordination and latency.

## Goal-by-goal answers
### Goal: Under what protocol is the agent evaluated (world paused during inference? episodes per task, success judge)?
Act "converts a model decision into a bounded, synchronous control command" and returns observations only after execution [full text, Sec 3.6]; Observe "does not recapture images, advance the simulator, or consume environment control steps" [Sec 3.4], so the world does not advance while the model reasons. Commands are increments relative to "the measured end-effector pose ... at the start of the call" [Sec 3.6, Eq 7], which is only the pose the model saw because the arm is stationary during reasoning. "Given the computational cost of closed-loop evaluation, we use a reduced set of trials rather than the full official evaluation protocols": 10 trials/task on LIBERO-Plus, RoboTwin 2.0, RoboDojo; 20 on RoboCasa GR1 and UniVTAC [Sec 4.5]. Real robot: 5 trials per task per condition, 50 trials total [Sec 7.2]. Success = benchmark-specific success condition [Sec 4.3].

### Goal: Which costs does it count and which does it leave out?
Metrics include action rounds and total tokens [Sec 4.3]. Wall-clock: 7.82 min/episode on LIBERO-Plus (8.6–9.1x starVLA), 28.43 min on RoboDojo (>10x), ~20 min real-world [Sec 5.3.4]. The demonstration package for embodied ICL (keyframes, text steps, action trajectories) is "prevalidated" and supplied before the first Act [Sec 3.5]; the 40%→80% real-robot ICL gain does not count the cost of producing that demonstration [Sec 7.3].

### Goal: What limitation does it report about timing / dynamic scenes?
No moving-object tasks; latency is named as a deployment obstacle but no mechanism addresses it [Sec 5.3.4]. Recovery attempts "consume additional environment steps" so long tasks fail "under a limited execution budget" [Sec 5.3.1].

# Large Multimodal Models for Direct Robot Control: GPT-6 as a Beginning

## What this paper does
GPT-GEAR is a tool-mediated agent (Observe/Reference/Act/Status/Finish) through which GPT-6 Astra issues bounded end-effector increments executed synchronously. Evaluated on five simulated benchmarks (e.g., 26.92% RoboDojo, 76.0% RoboTwin 2.0), a new LIBERO-GeoMotion benchmark and five real tasks; identifies deficits in long-horizon consequence-aware planning, precision, high-order operation and latency.

## Goal-by-goal answers
### Goal: How much wall-clock time does a frontier-model controller take per episode?
LIBERO-Plus 7.82 min/episode (8.6-9.1x the starVLA family); RoboDojo 28.43 min/episode (>10x); RoboTwin 2.0 and RoboCasa GR1 ~9.1-10.6x starVLA-OFT; real-world episodes up to ~20 min, attributed to "repeated multimodal reasoning, tool invocations, and iterative action correction" [full text, Sec 5.3.4]. No mechanism addresses latency; settings "are not directly comparable" [Sec 5.3.4].

### Goal: Which limitations does the frontier model itself show (i.e., what a frontier planner does not solve)?
Long horizon: it "does not sufficiently consider how executing one action constrains the next" (open drawer blocks bowl) and recovery costs accumulate under limited budgets [Sec 5.3.1]; precision under tight geometry (key/charger insertion) [Sec 5.3.2]; high-order operations such as pouring and rotation [Sec 5.3.3].
