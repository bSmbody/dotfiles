# Exploring the Limits of Combinatorial Generalization in Embodied Manipulation

## What this paper does
Introduces RoboCombine (19 unseen two-stage compositions of RoboTwin atomic skills, 380 episodes per policy) and HSE, a diagnostic interface running an instruction-conditioned atomic VLA under a subtask queue (LLM decomposer or oracle) and handoff cue (predicted or oracle). Finds that the start-state gap at handoffs, not the queue, is the bottleneck, and proposes PRTI, which post-trains atomic skills from start states sampled from late segments of successful atomic trajectories.

## Goal-by-goal answers
### Goal: How does the method handle a handoff state produced by an upstream skill that the downstream skill cannot start from, and what defines the target start distribution?
Training-time coverage. Under oracle-queue, oracle-cue HSE, ordered success is only 19.7% for Motus (1.6% for pi0.5) because "the downstream atomic skill must start from a handoff state rather than from the canonical start distribution" [full text, Sec 4.1]. PRTI "builds an auxiliary pool S from late segments of successful atomic trajectories", and for each target skill z_i uses "the task valid subset S_i ... containing states from which z_i remains executable"; canonical and PRTI trajectories are mixed 1:1 and the policy is conditioned only on z_i [Sec 4.2, Eq 7]. Validity is defined relative to the next skill alone; the upstream skill's behaviour is unchanged. Result: 2.63% base, 4.21% random perturbation, 9.47% robot-reset oracle, 18.16% PRTI [Sec 5.2, Table 2].
### Goal: What limitation does it report on composition?
Atomic-only data regime with known atomic labels; two-stage chains; future work: longer variable-length chains, handoff-aware training, "richer progress supervision", and systems where "decomposition, progress prediction, recovery, and execution are learned and evaluated jointly" [App A].
