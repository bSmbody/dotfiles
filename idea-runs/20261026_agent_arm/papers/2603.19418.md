# Speculative Policy Orchestration: A Latency-Resilient Framework for Cloud-Robotic Manipulation

## What this paper does
SPO masks cloud network latency in continuous manipulation: a cloud-hosted world model and high-frequency policy autoregressively pre-compute K future state–action pairs and stream them to an edge buffer; an edge ε-tube verifier compares observed state to the cached predicted state and blocks on divergence; Adaptive Horizon Scaling grows/shrinks K (additive increase, multiplicative decrease). Evaluated on three RLBench tasks under emulated network delays, mostly with an oracle policy/world model.

## Goal-by-goal answers
### Goal: What mechanism does it use to act on stale observations during remote inference, and what does it assume?
It models delay as a_t = π(s_{t−δ}) with τ_net = 30–100 ms against 10–20 ms control intervals [full text, Sec III-B]. Speculation needs a world model M_φ that predicts the next K states from the latest state, ŝ_{k+1} = M_φ(ŝ_k, â_k) [Sec IV-A, Eq], and the verifier compares cached predicted state to observed state at each step [Sec IV-C]. The state includes "task-relevant object poses" [Sec III-A]; experiments use an "algorithmic Oracle derived from RLBench expert demonstrations" as policy and world model so divergence reflects execution drift only [Sec V-A2].

### Goal: Does it address frontier-model deliberation latency in manipulation?
No. Delays are network round-trips of tens of milliseconds, not seconds-to-minutes of model deliberation; the remote policy is a state-based policy with a state-level world model, not a language-model agent; future work plans to integrate VLA models and test on hardware [Sec VI]. It reduces network-induced idle time by >60% vs blocking remote inference [Abstract].
