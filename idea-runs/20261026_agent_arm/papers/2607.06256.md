# Diagnosing Semantic Handoff Failures in Agent-Orchestrated Vision-Language-Action Skill Composition

## What this paper does
Builds a BEHAVIOR-1K harness in which an agent calls pi0.5-based skill checkpoints (move_to, pick_up_from, place_on, open_door, ...) as typed skill contracts with a budget and natural-language postcondition, verified every K steps by a multi-view Gemini-2.5-Flash verifier that decides advance / retry / replan. Compares the same checkpoints from clean skill-boundary snapshots (77-100% for selected skills) and from chained terminal states (near-zero task success, 19.5% mean progress over 30 rollouts), and labels failed attempts as next-skill readiness, target grounding or control execution. Preliminary diagnostic study.

## Goal-by-goal answers
### Goal: How does the method detect or handle an action that succeeds locally but makes a later stage fail, and is the dependency anticipated before commitment or only found after failure?
It names the "semantic handoff problem": "a skill can satisfy phi_t and still strand the robot, objects, or camera views in a state from which s_{t+1} cannot execute" [full text, Sec II]. The implemented handling is a hand-authored clause in the move_to postcondition requiring the target "close-up and at arm-reach distance"; a "next-skill-indexed readiness predicate rho(s_t, s_{t+1})" from a finite template library indexed by the next skill type is proposed as future work, not evaluated [Sec II, Sec V-C, App template library]. Readiness looks one skill ahead only.
### Goal: How does it attribute a downstream failure to a cause, and is the attribution validated causally?
Failed attempts are classified "from structured verifier reasons as diagnostic labels, not human ground truth"; a two-annotator audit validates only the binary failure decision (20/21), "the failure-category labels remain verifier-derived" [Sec IV-A, V-B]. No counterfactual restoration: "an oracle skill-boundary reset remains a future upper bound because our current live execution setup does not expose arbitrary skill-start state restoration" [Sec V-B].
### Goal: What does it do when a failure-causing state is irreversible, and what limitation does it report?
Recovery is agent replanning within budget, "in practice it usually re-navigates to re-establish the handoff before retrying" [Sec V-B]. Small number of pilot traces; counts are not population estimates [Sec V-B]. Authors hypothesize scaling snapshot-only data will not close the gap; chained-state data and readiness-aware verification are needed [Sec IV-C].
