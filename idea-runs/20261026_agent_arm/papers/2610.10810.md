# Diagnosing and Recovering from Observation-Space Shift at Long-Horizon Skill Seams

## What this paper does
Studies three-skill chains on BOSS-44 (LIBERO-90 scenes) where frozen per-task BC-Transformer skills (79% alone) collapse to 7.6% full-chain success because each downstream skill starts from its predecessor's terminal state (observation-space shift). Privileged component-wise resets show the dominant shift is displaced articulation (open drawer) and secondary objects, not arm configuration or the target object. It builds detect (progress-slope stagnation monitor) - restore (RL-trained drawer-restoration policy distilled to camera student) - resume (seam-robust fine-tuning), raising full-chain success to 26.5% vs 51.8% for a privileged restoration oracle and 12.9% for re-home-and-retry.

## Goal-by-goal answers
### Goal: How does the method detect or handle an action that succeeds locally but makes a later stage fail, and is the dependency anticipated before commitment or only found after failure?
Only after a stall. The monitor regresses per-frame progress and fires when "progress-slope stagnation over an 8-sample window" exceeds a conformally set threshold for 3 consecutive samples; prediction-surprise signals were anti-predictive at stalls [full text, Sec IV-A]. Nothing changes the upstream skill's behaviour; the upstream skills are frozen [Sec III].
### Goal: How does it attribute a downstream failure to a cause, and is the attribution validated causally?
Causally, but with privileged simulator interventions offline: a teleportation oracle and component-wise resets restore arm, target object, articulation or secondary objects to canonical values and measure recovered chain success; articulation and secondary-object restoration are complementary, single-component fixes reach 0.13-0.27 of the 0.52 oracle [Sec I, VI, Table II]. Online the system does not attribute; it applies the drawer restorer on every alarm (up to 2 per skill) [Sec IV-B].
### Goal: What does it do when a failure-causing state is irreversible or off the next skill's support, and what limitation does it report?
Restoration targets the next skill's canonical start state. The paper scopes this: restoration "is well defined only for side effects, and only when the change is reversible toward a known canonical target"; when the inherited change is a precondition, "restoring it destroys what the next skill needs" [Sec III, Scope]. Empirically, when the downstream skill is itself a drawer operation, restoration "undoes the skill's own effect" and regresses a working chain 0.32 -> 0.21; for displaced free objects the object restorer reaches 0.65 in isolation but ~0.10 at chain level [Sec V-D]. Open problems named: restoration quality, "re-entry timing (when to hand control back)", and "a learned re-entry value function" [Sec VI]. Scaling seam data 10x does not help (0.117) [Sec VII].
