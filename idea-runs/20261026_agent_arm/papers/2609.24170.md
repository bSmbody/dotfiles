# An Unexpected Robot Policy: evaluating LLM as policy on RoboDojo (GPT-6 Astra)

## What this paper does
Evaluates frozen LLMs (GPT-6 Astra, GPT-5.5, DeepSeek-Flash) as direct manipulation policies on all 42 RoboDojo-Sim tasks through a single `move_eef` / `give_up` tool loop (no learned policy in the control path; non-learned IK/path planner executes waypoints at 25 Hz). Astra reaches 22.48% SR (28.97 Score) over 2,100 trials, above all 40 public leaderboard policies; GPT-5.5 gets 0.88%. Astra is strong on semantic tasks, weak on precision, dynamic and bimanual tasks; one-shot demonstrations give no aggregate gain; a real-robot campaign was stopped for safety.

## Goal-by-goal answers
### Goal: Under what protocol is the agent evaluated (world paused during inference? episodes per task, seeds, success judge, privileged information)?
Turn-based: each turn the model must call `move_eef`; the accepted path is planned, executed, "and only then produces the next observation" [full text, Sec 3.2 / Fig 2], i.e. the scene does not advance while the model deliberates. 50 episodes/task for Astra and GPT-5.5 (official protocol), only 10/task for DeepSeek-Flash "because of evaluation cost"; one evaluation seed per model, medium reasoning effort, budget 100 model calls/episode [Sec 3.3]. Success is set only by the environment's criterion; the model gets no depth, privileged object pose or reward state, but does get 14 grasp-point state dims and a wiki-derived task recipe plus scoring-stage ladder that public policies did not receive, so the comparison "shares outcome metrics but not identical input information" [Sec 3.3; App H].

### Goal: What does the paper itself say its protocol cannot separate (harness, budget, latency, variability)?
App H: no repeated trials to estimate variability; the call budget "is a condition, not a neutral setting"; "inference latency and action timing may also limit deployment. This evaluation does not isolate their contribution"; image_horizon=2 means the Memory axis "measures the model together with this context policy"; a task needing "continuous contact or non-quasi-static motion may fail because this action representation cannot express the behaviour" [full text, App H]. Ranking transfer to other simulators/hardware is untested; the 33 real trials are a selected sample [App H, App I].

### Goal: What method-level failure does the protocol expose on dynamic tasks?
In pick_from_conveyor_by_image Astra "misses a moving target during grasping" [Sec 4.4]; the agent's only actuation is a blocking waypoint call followed by a fresh observation, so there is no mechanism for acting on a scene that changes between observation and execution. One-shot demonstrations (340 matched pairs) do not raise aggregate success; each cell is one episode on one seed, so small differences "may reflect stochastic variation" [Sec 4.5; App C.5].
