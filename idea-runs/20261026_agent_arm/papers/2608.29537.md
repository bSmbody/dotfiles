# AGM: Achievement-Grounded Memory for Closed-Loop Agents with Frozen VLA Policies

## What this paper does
AGM wraps a frozen subgoal-conditioned π0.5 with a fixed, instruction-expanded typed subgoal list and one progress pointer. A gripper-load state machine localizes grasp/release events; only then do type-specific verifiers decide whether the physical achievement occurred: a zero-training CoTracker3 coherent-lift test for grasps, and a 2.43M-parameter head over frozen SigLIP pre/post-release front+wrist embeddings conditioned on subgoal text for placements. Verified success advances the pointer, a rejected grasp retains it, a rejected recoverable placement rolls it back. RoboMME Counting: 100% PickXTimes, 84% BinFill; real-robot validation.

## Goal-by-goal answers
### Goal: What mechanism does it use to decide that a step physically succeeded, and when is verification triggered?
Verification fires only at proprioceptive gripper-load transitions ("an interaction alone is not evidence of achievement") [full text, Sec 2 Verifying manipulation outcomes, Fig 1]. Grasp success = coherent upward point motion under a frozen tracker; placement = language-conditioned pre/post cross-view evidence under frozen SigLIP [Sec 1, Sec 3.2]. Pointer transition advances/retains/rolls back [Sec 3.3].

### Goal: What happens when progress is written without verification?
Same policy and pointer: 100% PickXTimes with verified writes vs 32% attempt-based vs 36% whole-instruction; "A pointer that advances on attempts converts every transient grasp or placement failure into a permanent counting error" [App C.2, Table 10]. On BinFill attempt-based nearly matches (82 vs 84) because a release into the container is "irreversible and self-evidencing"; the head "has no reliable discrimination on container placement" [App C.2].

### Goal: How is the verifier trained, and how sensitive is it to deployment conditions?
788 events from two controllers: AGM itself ("covering the deployment distribution") and an attempt-based controller supplying "missed grasps, misplaced objects, and incorrect progressions"; labels from environment predicates unavailable at test [Sec 3.4]. "Even a 20-frame mismatch" in the post-release window "substantially degrades downstream performance" [Sec 3.4, App B.4].

### Goal: What limitation does it report on verification coverage?
"The verification vocabulary is anchored to prehensile events": pushing, sliding, articulated objects and tool use under persistent grasp "produce no compatible event and fall through to the frozen policy"; widening coverage "calls for a broader family of interaction detectors" [App E, Sec 5]. Task memory is a linear sequence, not a graph [App E].
