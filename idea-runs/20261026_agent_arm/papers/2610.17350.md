# Can a Frontier VLM Serve as a Robot Policy for Memory-Dependent Manipulation?

## What this paper does
Uses frozen GPT-6-Astra directly as an end-effector waypoint policy on all 16 RoboMME memory-dependent tasks, with the whole episode (goal, demo video, front frames at stride 3, wrist frame, TCP pose, its own previous answers including free-text descriptions) kept in one chained API conversation. 737/800 episodes succeed (92.1%); all 63 failures are audited, and the model is also evaluated in RoboMME's oracle-planner setting.

## Goal-by-goal answers
### Goal: How does the agent decide the task is done, and how often is that decision wrong?
Completion is the model's own declaration within its answer stream; no separate verifier [full text, Sec 3, Eq 2]. 25 of 63 failures are premature completion: "the model declared the task complete before the environment judged success". 23 are MoveCube push variants whose success check requires an open gripper; "in all 23 failures ... its last gripper command before declaring completion was to close" (11 still holding the stick, 12 gripper closed) [Sec 5, Premature completion].

### Goal: Are the agent's own state descriptions checked against physical state?
No. In StopCube the model's last description always names an arrival, but "We did not check these statements against the cube's state"; 12 failures are unintended button contact while the model described itself as "positioning" [Sec 5]. Cost: 9.5 calls/episode, 18.3 s per call, $0.39/episode [Sec 4, Resources].
