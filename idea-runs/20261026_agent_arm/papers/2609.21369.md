# ProTracer: Proprioception-Guided Failure Diagnosis in Robot Manipulation

## What this paper does
A training-free, post-hoc failure-diagnosis framework: change-point detection (PELT on a symbolic gripper-velocity/motion matrix) over proprioception selects key moments; rule-based narratives convert robot-state signals (aperture, displacement, rotation) into text; a VLM (Gemini-3.1-pro) jointly reasons over keyframe descriptions and these narratives to predict success/failure, failure type, explanation and failure onset time. Introduces the FailTime benchmark and optional reflective memory for few-shot adaptation.

## Goal-by-goal answers
### Goal: What non-visual evidence does it add to the VLM judge, and how much does it help?
Proprioception: "simply appending raw proprioceptive signals to the same dense-frame Gemini-3.1-pro baseline ... reduces MAE from 1.32 s to 0.90 s and raises acc@0.5s from 27.83% to 48.03%"; full ProTracer 71.18% and 0.59 s zero-shot [full text, Sec V-B]. On FailTime-Short binary failure detection is already >95% for all baselines; the challenge is onset localization [Sec V-B].

### Goal: Can it serve as an online verifier during execution?
No: it is "post-hoc failure diagnosis" over the full recording, where "a failed grasp followed by a successful retry is not treated as a failure onset" [Sec III-A]; "Since ProTracer runs offline, it is not latency-constrained", ~$0.09 and 40–60 s per episode [Sec V-A]. Causal runtime detectors (RND-OE, FIDeL, value drop) are poor onset estimates (≤1.7% acc@0.5s); "Runtime detection and onset localization thus answer different questions" [Sec V-D].
