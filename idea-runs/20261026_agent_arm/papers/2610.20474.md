# AdaRSI: On-Demand Recursive Self-Improvement for Embodied Agents

## What this paper does
A coding agent improves an embodied system (agent + self-written harness of tools/procedure + VLA executor library, GR00T N1.5) on RoboCasa365. It first refines the harness over rounds from validation feedback, then attributes persistent failures by retrying a failing sub-step from saved simulator snapshots under other instructions / poses / approaches; sub-steps no retry makes reliable are "executor-limited" and get a fine-tuned sub-step policy from self-collected demos (rejection sampling or privileged scripted expert), adopted only where validation shows it helps. Composite-Unseen success 4.6% -> 13.8%, at 28% of the GPU time of fine-tuning every sub-step.

## Goal-by-goal answers
### Goal: How does it attribute a downstream failure to a cause, and is the attribution validated causally?
Yes, counterfactually, but locally: "Snapshots enable counterfactual re-execution, in which a single sub-step is retried from the same state under a different instruction or approach, and this separates a poor instruction or a poor approach from a motion the executor cannot make" [full text, Sec 4.1]. The attribution is binary (harness vs executor) and placed at the sub-step that fails, "although the robot is in place and the instruction is one the executor knows" [Sec 4.2]. The snapshot state itself is taken as given: the text does not attribute a failure to an earlier sub-step that produced an unfavourable start state, though harness refinement "sets the states from which the executor is called" [Sec 1].
### Goal: How does the method handle an action that succeeds locally but makes a later stage fail?
Not explicitly. The harness procedure can be revised so the robot is positioned differently before a call [Sec 4.2], but this is found by trial over rounds in development with privileged resets, not by modelling downstream dependency. Unsolved Composite-Unseen tasks "chain several sub-steps beyond the executor and succeed only if every fine-tuned policy in the chain succeeds in the same episode" [Sec 6].
### Goal: What limitation does it report?
Agent may adopt a change that looks better on few development scenes but hurts at test (CuttingToolSelection: an added grasp step halves success) [Sec 6]; simulation only, privileged state needed to label data [Sec 6, Limitations].
