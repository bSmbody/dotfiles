# From Reasoning to Action: Benchmarking Frontier AI Models on LIBERO-10 Robot Manipulation Tasks

## What this paper does
Builds a closed-loop harness on Inspect Robots in which a frontier model controls a LIBERO Franka arm through `move_to` (target EEF pose + gripper), `done` and `give_up` tool calls, with RGB (agentview + wrist) and a 12-value robot state but no object poses or success signal. Evaluates six models (GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna, Opus 5, Opus 5.5, Gemini-4 Argon) at three reasoning efforts: 18 configurations x 100 episodes = 1,800 episodes, ~99,000 API calls, $4,936. Best: Astra (high) 44%, Argon 43%.

## Goal-by-goal answers
### Goal: Under what protocol is the agent evaluated (world paused during inference? episodes per task, success judge)?
Each `move_to` is interpolated to ~11 actions at 20 Hz and executed step by step; only then are new images returned and the model queried [full text, Sec 2.2, Alg 1, Sec 2.3], so the simulator is stepped only by actions and does not advance during inference. Ten initial states per task (indices 0–9 of LIBERO's 50) → 100 episodes per configuration [Sec 3.1]. Success = LIBERO goal predicates checked on simulator state after every control step; the episode ends as success "even if actions of the current call remain" [Sec 2.3]. Limits: 80 LLM calls, 900 control steps, per-episode spending cap [Sec 2.3].

### Goal: How strongly do results depend on reasoning effort and model?
Model-dependent and non-monotone: Astra 28%→44% and Opus 5.5 9%→33% from low to high effort, but Opus 5 falls from 12% (medium) to 6% (high) [Sec 3.2]. Astra/Argon cost ~$7–8 per episode vs ~$1.6–2.0 for Sol/Opus 5.5 at 33% [Sec 3.2].

### Goal: What does the agent get wrong about its own success and its own actions?
Of 1,400 failures, 287 end with the model calling `done` while the success predicate is unsatisfied — the model "mistakes an incomplete task for a complete one" [Sec 3.6]. Achieved displacement averages 64–72% of commanded displacement, with 21–36% of motions covering less than half the request; models notice this in 16%–91% of failure notes depending on model [Sec 3.6]. Hindsight notes are logged but never fed back, so each episode stays zero-shot [Sec 2.2].
