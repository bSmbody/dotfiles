# Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

## What this paper does
PyRUA-Lean replaces per-primitive tool calls with Python code cells in which a planner composes robot primitives (motion, SAM 3 perception, frozen VLA policies) with local checks and retries, returning only requested images/state. With GPT-6 Astra over 700 simulated instances (LIBERO-PRO, RoboTwin 2.0, RoboCasa365) success rises 63.1% -> 71.7% with 49% fewer LLM calls and 65% fewer input tokens. Section 5 trains an open Qwen3.5-4B planner (PyRUA-Lean Coder) with outcome-reward GRPO from base weights on 45 LIBERO-PRO instances: unseen-instance success 18.8% -> 44.1% versus 69.8% for Astra.

## Goal-by-goal answers
### Goal: Where do tokens, calls and dollars go in a frontier-planner robot episode?
On jointly solved instances calls fall from 17.0 to 8.7 and input tokens from 788k to 276k per episode; estimated cost $1.63 -> $0.74 [full text, Sec 3.5]. Billing at Astra list prices ($10/M input, $1 cached, $12.50 cache write, $50 output) [App E]. Input dominates: median first prompt 20-24k tokens, and "output tokens, reasoning included, are at most 17% of either agent's bill" [App E]. On RoboCasa365 atomic tasks the two interfaces cost the same ($0.94 vs $0.96) because failed episodes run to the 40-call limit [App E]. Wall-clock is not measured: "We count LLM calls rather than time episodes, because the latency of an LLM call on a shared model gateway varies too much" [App E].

### Goal: How is the 4B planner trained and is any stronger model used as teacher?
GRPO with reward 1 iff the benchmark success check passes, "no shaping and no penalty for LLM calls or simulator steps"; group of 8 episodes per instance, advantage = reward normalized in the group, clipped loss "applied to every token the model generated in the episode"; no KL/entropy; "no supervised stage and no demonstration data"; 30 iterations = 3,840 episodes, one 8-GPU node, ~12 h; training episodes capped at 24 cells and 25 min [Sec 5.1]. The frontier model is only a reference row [Table 8].

### Goal: What did RL improve and what remained limited (long horizon, manipulation skill)?
Unseen: LIBERO-PRO other tasks 13.5 -> 37.4, RoboTwin 14.0 -> 52.4, RC365 atomic 52.2 -> 76.7, RC365 composite 12.5 -> 19.4 (Astra 39.4) [Table 8]. Training mainly changed interface use: code cells per call 9.0 -> 1.0, images requested 19.3 -> 0.8; cell-budget and context-overflow endings fell, but "gave up" endings rose to 25.2% and wall-clock endings to 16.8% [Table 9]. "We do not claim that training improved manipulation skill as such" and the model "remains far below the frontier model" [Sec 5.3, Sec 6]. Limitations: "one model size and one training run, on 45 instances of one benchmark and with success as the only reward" [Sec 6].

### Goal: Is the outcome of a planner decision confounded with executor stochasticity?
Yes for the frontier comparison: some success differences arise because "a VLA succeeds in one run and fails in the other", so success cannot be attributed entirely to planner logic [Sec 3.8]; the RoboDojo agent leaves VLA policies out "because of their run-to-run variance" [Sec 6]. The RL recipe does not model this; the episode reward is shared by all tokens.
