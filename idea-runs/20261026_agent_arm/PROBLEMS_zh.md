# Agent 操作机械臂：需要解决的具体问题（gap_finder 结果，2026-10-26）

本文来自 5 个 gap_finder 的结果：共读了 136 篇论文，写出 10 个方法层 gap。英文原文和逐条证据见 `gaps.md`，论文摘要见 `papers/`。下面每个问题都按同一个结构写：

- **现象**：具体发生了什么；
- **为什么现有方法做不好**：方法层面的缺陷；
- **最近的工作**：离解决最近的论文；
- **怎么证明解决了**：可检验的标准；
- **我的评估**：空间大小、模型变强后问题会不会消失、算力需求、风险。

---

## A1 物理状态校验：agent 怎么知道“真的做成了”

### P1. 校验器只能“看给它的画面”，不会自己去取证

**现象**
- Astra 在 RoboMME 上有 63 次失败，其中 25 次是“过早宣布完成”；有 23 次是推任务要求夹爪张开，它在夹爪闭着时就说做完了 [2610.17350]。
- SenseNova 观察到：Astra 把头部相机里“杯柄和挂钩重叠”当成杯子已经挂上 [2610.22471]。
- 一个固定的裁判只看最后一帧：手悬在杯沿下方的 160 次全部算成功里，判错 148 次；悬在杯沿上方的 160 次一次没判错 [2610.24801]。

**为什么现有方法做不好**
- 所有 VLM 裁判和奖励模型（Guardian、AHA、RoboReward、FLORA），以及 agent 自己判断完成，都是被动分类：p(成功 | 给定的几帧)。
- 判定所需的事实不在画面里时，它们无能为力。这类事实包括：有没有接触、是否被支撑、插入深度、是否被遮挡。
- 能主动取证的只有 AGM 的“抬起检验”和 Watchdog 的微抬升，但都写死在抓取这一个原语上。
- FailBench 的结果也说明这一点：对输入画面做裁剪只多 2.3 个点；接触类任务的准确率不超过 0.60 [2609.03611]。

**最近的工作**
- 加一个固定的第二视角，下游成功率从 75.6% 提到 94.0%；而在同样的证据上调严阈值，反而降到 71% [2610.24801]。
- 结论是“新证据有用，重新加权旧证据没用”。但这个视角是固定的，不会针对不确定的那个事实去选。

**怎么证明解决了**
- 在接近成败边界的残余失败上做对比，例如：杯沿下悬停、插了一半、闭合但没接触、松手时差一点没放到支撑面上。
- 在动作、时间、查询的预算相同时，比较被动裁判和“自己选择取什么证据”的校验器：误接受率、误拒绝率、过早完成率、下游成功率。

**我的评估：★★★★**
- 模型变强也不会自动解决：证据不在画面里，再强的模型也看不到。
- 算力低：仿真加小模型，或者调 API。
- 风险：经典的 interactive perception 和 next-best-view 是近亲。必须讲清楚“为 agent 的步骤成败做主动校验，并带停止规则”和它们的区别，否则会重演第三轮被拆回经典方法的情况。

### P2. 校验要么靠手写的条件，要么只给一个笼统的“成/败”

**现象**
- SenseNova：Astra “知道没做完，但说不出哪个物理条件没满足”，于是反复修正、不收敛 [2610.22471]。
- FailBench：成功标准不明确时，裁判倾向于判“成功”，而且评的是“过程像不像”而不是结果 [2609.03611]。

**为什么现有方法做不好**
- 按条件校验的方法，词表都是手写的，而且绑在特定原语或任务上：AGM 的抓/放事件；CommitFlow 的模板 [2609.21908]；FORCA 的力判据，要在真机上每个任务调 20 次 [2610.31841]。
- 开放词汇的裁判又只输出一个总体判断，没有条件级的槽位。

**最近的工作**
- CommitFlow：能校验“握持、支撑、接触、释放”这几类条件，但它自己承认“开放任务做不到”。

**怎么证明解决了**
- 在没有人写过谓词的步骤上测：推（夹爪须张开）、挂、插入深度、抽屉关好、物体被支撑。
- 比较逐条件的校验准确率，以及“不收敛的修正循环”是否减少。

**我的评估：★★★**
- 和语言关系紧（从指令推出物理条件），适合 ACL / EMNLP。
- 风险：VLM 裁判这条线很拥挤，容易被看成“又一个结构化 prompt”。
- 和 P1 天然可以合并：先说清要验什么条件，再决定去取什么证据。

## A2 评测方法：现在的结论可靠吗

### P3. 前沿 agent 假设“我思考的时候世界不动”

**现象**
- 几乎所有前沿 agent 的操作评测，都在模型思考时暂停仿真 [2609.24170]、[2610.28259]、[2610.30051]、[2610.18053]。
- 导航里不暂停时，碰撞多 12.3 倍，约 84% 发生在推理期间，而且模型排名会翻转 [2610.09294]。

**我的评估：★★**
- 这就是第三轮的“大脑延迟”方向，方法层评分 1.0/10。
- 剩下的空间在评测协议本身（AC 的 salvage 估计 4–5 分）。不建议再作为主线。

### P4. 评测统计用错了模型：把每个配置当独立臂、每个回合当独立同分布

**现象**
- 同一配置重复跑，结果相差可达 20.9 个点，常常比相邻模型之间的差距还大 [2610.18792]。
- “性能 54 天翻一倍”这个结论里，榜首模型在 bootstrap 中只有 45% 的概率仍是榜首 [2610.25287]。
- 推理强度的影响不单调：Opus 5 从低强度到高强度，成功率反而从 12% 掉到 6% [2610.30051]。

**为什么现有方法做不好**
- 每个 (模型, 推理强度, 服务档, harness, 预算) 组合都被压成一个固定预算下的均值。
- 没有把成功率建模成预算的函数，没有 run 级随机效应，也不按美元或时间成本分配回合。

**最近的工作**
- N-SCORE 做序贯检验，但只能两两比较，假设 i.i.d.，也没有预算轴 [2603.13616]。
- SEAR 做了三次重复，但仍是分组均值之差 [2610.18792]。

**怎么证明解决了**
- 用公开日志：2610.30051 的 1,800 个回合、SEAR 的数据，再加一个小的因子实验。
- 在同等美元成本下，区间对留出重复的覆盖率达到名义水平，排名跨预算稳定。

**我的评估：★★★**
- 算力几乎为零，主要是数据和统计，风险低。
- 但“分层贝叶斯 + 序贯设计”本身是经典统计，要靠“重新评估后哪些领域结论站不住”这样的发现来撑分量。
- 适合 NeurIPS D&B 或评测类论文。

## A3 长程组合与不可逆失败

### P5. 上游动作只按“这一步做成了”来接受，不管后面还能不能做

**现象**
- Astra 在 LIBERO-Agent 上局部执行的成功率已经是 94.1%，剩下的长程失败主要是跨阶段干扰：前一步的放置挡住后面的操作，后面的动作碰坏已完成的状态 [2609.39507]。
- ReTrace 的“依赖型”任务（抓取姿态决定后面能不能插进去）：没有经验时各模型 0–20%，知道依赖关系之后 80–100% [2610.15814]。

**为什么现有方法做不好**
- 上游动作（抓取位姿、放置、底盘站位）只要满足本阶段标准就被接受。
- 对后果的了解只有两个来源：
  - 失败后由模型写的事后文字解释，且只能在同一任务上重复验证（ReTrace）；
  - 在失败的子步骤上重试（AdaRSI）。
- 没有方法在**新实例**上、**提交上游动作之前**，就估计“从这个结果出发，剩下的阶段还能不能完成”。

**怎么证明解决了**
- 在可存档、读档的仿真里，只改上游结果、重跑下游，得到真实的跨阶段归因。
- 看两件事：归因是否比事后叙述更准；在留出的实例上，第一次尝试的整链成功率是否提升。

**我的评估：★★★**
- 问题真实，而且模型变强后反而更突出：局部都做对了，瓶颈就落在跨阶段。
- 风险：TAMP 里的几何回溯、skill chaining 这些经典概念是近亲，要小心被拆回去。
- 算力中等，要大量做仿真分支。

### P6. 链式恢复的目标和触发时机都不对

**现象**
- 恢复方法的目标是“回到下一个技能的标准起始状态”。可如果遗留的改变恰好是后续需要的前提（例如后面要操作的抽屉已经打开），恢复反而毁掉进度：整链成功率从 0.32 掉到 0.21 [2610.10810]。
- 触发靠“进度停滞”，太晚：可挽回窗口在第一次抓取后中位约 7 步就关闭了，大多数监控器在窗口关闭后才报警 [2610.13516]。

**我的评估：★★★**
- 可以和 P5 合并成“链级可完成性”这一个量。
- 风险：RESCUE 和 AgentChord 已经在附近。

## A4 成本与小模型规划器（最契合 RL 后训练经验）

### P7. 小模型规划器做 RL 时，每一轮都拿同一个“整局成败”当奖励

**现象**
- AgenticRoboRL [2610.28589] 和 PyRUA-Lean Coder [2610.01939] 都把整局的终局成败广播到每一轮。
- 但每一轮都会调用一个带随机性的执行器（冻结的 VLA、感知栈），所以终局结果把“规划决策好不好”和“执行器这次运气好不好”混在了一起。
- 执行器的随机性大到能翻转单局成败（PyRUA-Lean 3.8 节）。
- CaP-RL 干脆用仿真器的特权状态来训练，回避这个问题 [2603.22435]。
- 后果是小模型在长程复合任务上被前沿模型拉开最多：RoboCasa365 复合任务 19.4 比 39.4；LIBERO-10 在 RL 后仍只有约 40%。

**为什么现有方法做不好**
- 文本 agent 领域的逐轮归因方法，各自都依赖机器人 harness 提供不了的条件：Trie-GRPO 需要离散前缀完全匹配；TreeHCA 需要参考答案；Spark 仍把终局奖励广播到每一步。

**怎么证明解决了**
- 在可重置的仿真里，在某一轮的边界读档，把同一个规划决策重复执行多次，得到“决策价值 vs 执行噪声”的真值。
- 看两件事：逐轮优势估计与这个真值的相关性；在相同回合预算下，长程套件和非特权感知上的 RL 增益。

**我的评估：★★★★**
- 正好契合 RL 后训练经验，也满足“不用前沿模型的输出来训练”。
- 算力在约束内：小规模 RL，4–9B 模型加 LoRA。
- 风险：读档后做蒙特卡洛估值这个思路，和 VinePPO（文本领域）同源。要讲清机器人里的新东西：执行器随机性带来的边缘化、真实感知，以及代价相差几个数量级的 rollout。

### P8. 在“从零成功”的任务上，小模型自己没法探索

**现象**
- AgenticRoboRL 只在 SFT 后能做成 1–4/5 的任务上做 RL，因为全失败的组没有梯度。教师也做不好的 Goal / Spatial 套件，RL 后仍只有 0–16%。
- 弱模型自己写的经验手册反而有害：Luna 用自己的手册是 22.9%，不用手册是 43.8% [2609.33378]。
- 现在所有接近前沿水平的路线，都在“搬运更强模型发现的东西”。

**我的评估：★★★**
- 影响大，能回答“哪些能力真的需要前沿模型，哪些只是需要探索”。
- 但难度和不确定性高，算力也更大，适合做长线。

## A5 安全

### P9. 安全判断只在开头做一次，不随看到的东西和要执行的动作重新判断

**现象**
- RoboHarm 固定 7 个前沿模型，只换接口：纯文本时拒绝率 73%，接上机器人控制后掉到 18–25% [2610.14043]。
- 174 次照做的“燃气灶”任务里，没有一次提到压力、爆炸或易燃。
- 214 次拒绝里只有 12 次发生在任务中途，其中 11 次的线索第一帧就看得到。
- Astra 的 464 次调用里，只有 0.6% 提到伤害，而且都在第一次调用 [2610.27350]。

**为什么现有方法做不好**
- 现有防护各有盲区：
  - 开动前问一次“你会执行吗” [2610.27350]；
  - 多智能体辩论指令文本，不看图 [2511.21460]；
  - 规划前编译成 LTL 或规则 [2503.07885]、[2610.24603]；
  - 只对预先给定的障碍几何做约束 [2609.20822]。
- 它们都没有在“现在看到了什么 + 下一个动作会造成什么”上做判断。所以指令里没写明、要靠看才能认出来的危险（压力罐、充电宝、漂白剂和氨水的标签），以及执行中才出现的危险，都会漏掉。

**怎么证明解决了**
- 构造危险不写在指令里、必须靠感知推断的场景，以及靠近之后才看得出危险的场景。
- 在相同 API 成本下比较三项：伤害发生前的拒绝率、良性任务上的误报率、首次报警比危险可见晚了几步。

**我的评估：★★★★**
- 便宜（仿真加 API），时效强，结论直接影响 harness 的设计。
- 最契合 ACL / EMNLP（LLM 行为、安全），评测也便宜。
- 风险：这个子方向 10 月才热起来，竞争会很快。

### P10. 良性任务里的“安全前置步骤”学不会

**现象**
- SafeStage 发现：VLA 成功的回合里有 70.84% 是不安全的。即使在提示里写明依赖关系，安全成功率还从 9.84% 降到 5.91% [2609.21223]。
- 例子：先挪开罐子再拿瓶子，瓶子就会倒；橘子松手后会滚落。

**最近的工作**
- SafeBranch 用精确回滚构造逐步的偏好对 [2608.19729]，但依赖符号谓词，作者自己说较长的因果链做不了。

**我的评估：★★**
- 方法空间有，但需要训练 VLA 或规划器，工程量大，而且离 SafeBranch 很近。

## 总结与建议

| 问题 | 空间 | 模型变强后仍成立 | 算力 | 契合度 | 被拆回经典方法的风险 |
|---|---|---|---|---|---|
| P1 主动取证的校验 | 大 | 是 | 低 | CoRL / NeurIPS / MM | 中（interactive perception） |
| P7 执行噪声下的逐轮归因（小模型 RL） | 大 | 是 | 中 | NeurIPS / ICLR / CoRL；契合 RL 经验 | 中（VinePPO 同源） |
| P9 逐动作、基于感知的伤害判断 | 大 | 是 | 低 | ACL / EMNLP / 安全类 | 低到中 |
| P4 前沿 agent 评测的统计方法 | 中 | 是 | 极低 | NeurIPS D&B | 中（经典统计） |
| P5+P6 链级可完成性 | 中 | 是，且更突出 | 中 | CoRL / ICRA | 中（TAMP、skill chaining） |
| P2 条件级校验 | 中 | 是 | 低 | ACL / EMNLP | 中（VLM 裁判拥挤） |
| P8 从零成功开始的探索 | 大但难 | 是 | 中到高 | NeurIPS / ICLR | 低 |
| P3 实时评测与延迟 | 小 | — | 低 | — | 已验证：高 |
| P10 安全前置步骤 | 小 | — | 高 | — | 中 |

**建议**：P1、P7、P9 三选一或二。下一步各自交给 innovator → 对抗审稿 → report → 评审组。
