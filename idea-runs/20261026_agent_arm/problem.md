# Frontier-model agents operating robot arms: what still needs to be solved

## Problem definition
A robot-arm manipulation system in which a general-purpose foundation-model agent (a frontier multimodal LLM such as GPT-6 Astra, Claude Opus 5.x or Gemini 4, or an open model) perceives the scene, decides what to do and acts, either directly (end-effector targets, primitives, tool calls), by writing control code, or by orchestrating lower-level executors (VLA policies, scripted skills). Input: language instruction, camera images (optionally depth, proprioception, force/touch), the agent's interaction history. Output: executed robot behaviour and task outcome. The question for this run is which concrete, currently unsolved problems in such systems are worth a paper, and what method or evidence would solve one of them.

## Challenge
Since September 2026, frontier models used directly as robot policies beat specialist policies on several benchmarks (RoboDojo, RoboMME, visuo-tactile suites), and agent harnesses (code-as-policy, perception tools, VLA orchestration, self-evolving skill libraries) are appearing weekly. Yet the same systems fail on precision, dynamic and bimanual tasks, are slow and expensive per episode, cannot reliably verify physical success (VLM judges are near chance on contact events), collapse when skills are composed over long horizons, are evaluated under protocols that pause the world and run few episodes, and carry out hazardous instructions when acting even though they refuse them when asked. Because the field moves fast, a contribution must address a problem that does not simply disappear when the next frontier model ships, and must not reduce to a known classical mechanism re-applied to a frontier model.

## Constraints
- **Venue and timeline**: no fixed venue. Candidate venues include CoRL / RSS / ICRA, NeurIPS / ICLR, ACL / EMNLP (language-centric angles) and ACM MM (multimodal angles). Time is relatively ample: assume about 4–6 months from today (2026-10-26) to submission.
- **Compute**: a few consumer GPUs with 24 GB each (RTX 3090 / 4090) on a shared cluster, single-GPU jobs; the whole paper ≤ about 100 GPU-days. Open models that fit: π0 / π0.5 (~3B), SmolVLA (~0.5B), OpenVLA-7B with LoRA, Qwen-VL / Qwen3-VL up to ~8B (LoRA/QLoRA), small RL post-training runs. No pretraining of large models.
- **Frontier-model access**: API access to frontier models (e.g. GPT-6 Astra) for evaluation, as a reference controller, or as a component; total API spend for the paper about US$2,000. Do not train a competing model on frontier-model outputs (provider terms); RL from one's own environment reward is fine.
- **Robots and simulators**: simulation first (LIBERO and variants, RoboTwin 2.0, RoboCasa, ManiSkill, RoboDojo-Sim, MuJoCo/Isaac). Real-robot work at most a low-cost arm (e.g. SO-101) for a small validation, if any. The team is new to robotics but experienced in LLM / RL post-training.
- **Significance bar**: the paper must change what the community believes or does; thin deltas over 2026 work and "frontier model + known classical mechanism" combinations have been rejected in previous rounds of this project.
