# Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

## What this paper does
PyRUA-Lean replaces tool calling with a code-execution interface: GPT-6 Astra writes Python cells that compose robot primitives (including frozen VLA policies), check outcomes and retry inside the cell, and return only requested images/state. On 700 LIBERO-PRO/RoboTwin 2.0/RoboCasa365 instances success rises 63.1% → 71.7% at the same LLM-call budget, with 49% fewer calls and 65% fewer input tokens on jointly solved instances; also RoboDojo SOTA and a GRPO-trained 4B coder.

## Goal-by-goal answers
### Goal: What mechanism decides when to call the expensive model, and does the decision depend on the remaining call budget or remaining horizon?
The frontier model is always the top-level controller; every return of control from a cell is an LLM call [full text, Section 3.1–3.2]. Calls are reduced by moving dependent operations and retries into code, not by a decision rule about when to call. The per-episode LLM-call budget is a hard cap; "Of the 96 instances solved only by PyRUA-Lean, the baseline exhausts its LLM-call budget in 52" [Section 3.8].

### Goal: What signal estimates the value of a call, and does it model how much the expensive model's answer will help (not just whether the cheap policy is failing)?
None; no per-call value estimate. Token savings come mainly from fewer calls (LIBERO-PRO: 2.55× fewer calls, 1.76× fewer tokens per call) [Section 3.6, Fig 5]. On-demand images alone in the tool-calling baseline lower success 83.0% → 68.5% [Section 3.6, Table 14].

### Goal: What does the paper report as the limitation of its call-allocation mechanism?
Gains smallest on RoboCasa365 atomic tasks where the VLA completes most of the task; including failed episodes, cost is about equal [Section 3.8, Appendix E]. Single run per instance; interface features not isolated [Section 6].
