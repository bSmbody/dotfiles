# Enabling Intelligent Interactions between an Agent and an LLM: A Reinforcement Learning Approach (When2Ask)

## What this paper does
When2Ask uses a Planner-Actor-Mediator setup: an LLM planner issues option-level plans, hard-coded or pre-trained option policies execute them, and a mediator's asking policy decides at each step whether to query the LLM for a new plan. The asking policy is trained with PPO on task reward minus a penalty for asks that return an unchanged plan. Evaluated on five MiniGrid tasks and a Habitat Pick&Place task, it cuts LLM interactions relative to always-ask while matching or exceeding success.

## Goal-by-goal answers
### Goal: What target does the help trigger learn — the cheap agent's failure risk or the value of the expert's help — and how is it supervised?
The value of asking: the MDP's actions are {Ask, Not Ask}, the LLM planner is treated as part of the environment, and the objective is Σ γ^t r_t − λ·1(Ask ∧ plan unchanged) [full text, Section 4.2, Eq 1]. The policy therefore learns from the task return obtained with and without fresh LLM plans, i.e. a helper-conditioned target, trained on-policy.

### Goal: How many expert interventions does training consume, and is the expert cheap?
Data are collected on-policy with the LLM queried whenever the asking policy asks during PPO training [Section 4.2]; the learning curves show interaction counts across RL iterations and multiple seeds (5 seeds on MiniGrid, 10 on Habitat) [Sections 5.2.1, 5.3, Figs 5, 8]. No budget is placed on training-time LLM queries; savings are reported only at test time (e.g. 7.99 vs 295.60 interactions for random on Habitat) [Table 2]. Options are high-level and the translator is an expert oracle [Section 4.1].
