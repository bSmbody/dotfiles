# RoboICL: Embodied In-Context Learning with GPT-6 Astra

## What this paper does
RoboICL controls robots with frozen GPT-6 Astra via in-context learning: demonstration context plus bounded anchored interaction memory in a shared observation–action–receipt–observation grammar, with stable prefixes for KV-cache reuse and a fixed step-limit-based action-chunk horizon H(T). Evaluated on 30 RoboDojo tasks and three real-robot tasks; an optional Jev gate decides whether to reuse a predicted action suffix instead of calling Astra again.

## Goal-by-goal answers
### Goal: What mechanism decides when to call the expensive model, and does the decision depend on the remaining call budget or remaining horizon?
Main benchmarks: a fixed schedule, chunk horizon H(T) from the task step limit (5–25 actions), nominal calls ⌈T/H⌉ [full text, Section 3.4, Eq 5]. Optional Jev: a System One decision model that, after each 5-action segment, may approve one further segment of the current 20-action plan using proprioception, execution tracking and the plan note but no RGB [Section 4.5]. No remaining-budget term.

### Goal: What signal estimates the value of a call, and does it model how much the expensive model's answer will help (not just whether the cheap policy is failing)?
Jev judges whether replanning is unnecessary from structured state; it does not estimate the gain of a fresh Astra call. Results: calls fall 181 → 121 (Align Blocks) and 116 → 60 (General Pickup), tokens 9.53 → 5.08M and 4.95 → 1.39M, but success changes 3/5 → 2/5 on Align Blocks and 4/5 → 5/5 on General Pickup; gate tuned on these same layouts [Section 4.5, Table 5, Appendix C.2].

### Goal: What does the paper report as the limitation of its call-allocation mechanism?
"Jev gating reduces GPT-6 Astra calls … with task-dependent effects on success"; Jev evaluated only on development layouts [Section 5].
