# Do As I Can, Not As I Say: Grounding Language in Robotic Affordances

## What this paper does
SayCan grounds an LLM planner in a robot's skills. Each skill in a fixed menu has a language label, a policy and a value function giving the probability of completing the skill from the current state. At each step the LLM scores every skill label as the next step for the instruction, the value functions score feasibility, and the skill with the highest product is executed; the loop repeats until "done". It is evaluated on long-horizon instructions with a real mobile manipulator in a kitchen.

## Goal-by-goal answers
### Goal: Does SayCan score a fixed skill menu by combining an LM's choice probability with a per-skill value from the current state?
Yes. "For each skill, the affordance function and the LLM probability are then multiplied together and ultimately the most probable skill is selected, i.e. π = argmax p(c_π|s, ℓ_π) p(ℓ_π|i)" [full text, Section 3, Algorithm 1]. The affordance p(c_π|s, ℓ_π) is "the value function for the skill if we take the reward to be 1 for successful completion" [Section 3], learned by TD backups from multi-task RL [Section 4]. It is skill-level completion probability, instruction-agnostic; relevance to the instruction comes only from the LLM term.

### Goal: Is there any budget on LLM calls or any rule for when to consult the LLM?
No. The LLM scores every skill at every step until termination [Section 3, Algorithm 1]. Limitations name skill capability as the main bottleneck and failure to react when a skill fails despite a high value [Section 8]; LLM cost and call scheduling are not discussed.
