# Reflex First, Reflect Later: Latency-Aware Embodied LLM Agents for Dynamic Response

## What this paper does
Studies LLM inference latency in the HAZARD dynamic-rescue simulator by a Time-Conversion Mechanism (TCM) that advances the simulator by ceil(t_inf × FPS) frames per decision. Proposes RRARA: a rule-based constant-latency Rapid-Reflex controller executes a cached plan, an LLM-PrePlanner emits an ordered list of object IDs as subgoals, a deterministic staleness score triggers replanning, and an asynchronous LLM reflector validates the running action and optionally proposes a replacement. Uses remotely hosted (black-box) LLMs. CVPR 2025 Embodied AI Workshop.

## Goal-by-goal answers

### Goal: What mechanism maps a delayed high-level decision/observation onto the current state?
None by prediction. The LLM outputs object-ID subgoals (walk_to/pick_up/drop of o_i) [full text, Section 3.3, Eq. 3], which the executor resolves against the current object poses. Staleness is detected post hoc: Stale(t,τ) = λ_T S_T + λ_A S_A + λ_O S_O + λ_H S_H comparing the planning snapshot with the current state; if ≥ δ the cached plan is discarded and regenerated [Section 3.3, Eqs. 4-7]. The async reflector returns (valid, a_new) on the latest observation [Section 3.4, Eqs. 8-9].

### Goal: What does the method assume about the slow decision-maker (trainable, white-box features, output type, delay scale)?
Black-box LLM, discrete symbolic outputs (object IDs) over a structured, tabular object list; no robot-arm spatial targets; latency in seconds mapped to frames [Sections 3.1-3.3].

### Goal: What does it report as a limitation relevant to this axis?
TCM models blocking inference (agent stationary while thinking); Response Latency excludes background computation; remote LLM latency is not reproducible; no physical robots [Section 5, Limitations]. The compensation is discard-and-replan, so a decision invalidated by drift costs another full LLM call.
