# Make π0.5 Learn to Call Astra for Reliable Robot Manipulation

## What this paper does
Adds a lightweight CALL head on frozen π0.5 features that predicts when help is needed; a temporal trigger (hard threshold or 4-of-5 window, 6-query cooldown) hands control to GPT-6 Astra, which issues 30–50-step end-effector correction chunks or returns control. On 200 LIBERO episodes it reaches 97.5% vs 95.5% for pure π0.5, with Astra executing 5.49% of steps and ~5,027 tokens per episode in three suites.

## Goal-by-goal answers
### Goal: Does the system measure, ignore or compensate the brain's latency, and does the environment pause while the model thinks?
It measures but does not compensate. On handoff "the host clears the remaining π0.5 action queue and transfers environment control to Astra" [full text, Sec 2.3]; "each accepted correction advances one LIBERO environment step" [Sec 2.4], so the simulator does not advance while Astra reasons (step-driven LIBERO). Throughput is measured in environment steps per wall-clock second: 8.25 steps/s for pure π0.5 vs 2.58 steps/s across all hybrid episodes "due to the latency of Astra consultation and recovery" [Sec 3.6, Table 8]. Latency is reduced only by calling Astra rarely.

### Goal: What mechanism (if any) reconciles a stale high-level decision with the current state?
None. Astra receives the current images, state, policy proposal and history at handoff; the executor is stopped, so the state does not change during the call and no reconciliation is needed. After Astra returns control, "the host validates the response and queries a fresh policy proposal" [Sec 2.3].

### Goal: What limitation does it report on dynamic tasks or long latency?
Only static LIBERO tasks are used; no dynamic tasks and no real-time (non-paused) evaluation. The executor idles (queue cleared) whenever the brain is consulted.
