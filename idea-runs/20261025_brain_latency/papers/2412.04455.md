# Code-as-Monitor: Constraint-aware Visual Programming for Reactive and Proactive Robotic Failure Detection (CaM)

## What this paper does
CaM (CVPR 2025) has GPT-4o generate, at the start of each subgoal, the next subgoal plus textual constraints to hold during execution (C_d) and at completion (C_u). A trained constraint-aware segmenter (ConSeg, LISA-based) turns constraints into 3D "constraint elements" (points/lines/surfaces), which are tracked with CoTracker; GPT-4o writes monitor code over element positions with tolerances. If the code returns False, the policy halts and the reason string is fed back to GPT-4o for re-planning. Evaluated in CLIPort, OmniGibson, RLBench and a real robot with disturbances.

## Goal-by-goal answers
### Goal: Does the brain pre-specify monitors and local recoveries that fire without re-calling the brain, and how are they parameterized?
Monitors yes, recoveries no. The VLM emits per-subgoal constraints and then monitor code returning a boolean and a reason string "if the computed result exceeds a predefined tolerance (e.g., ... within 15°)" [full text, Sec. 3.3]. Thresholds come from a manually initialized knowledge base or VLM internal knowledge [App. A.2]. On violation, "the policy execution halts immediately, and the accompanying string is used as feedback f_pre for re-planning" [Sec. 3.1, Eq. 1] — every recovery goes back through the brain. VLM and segmenter are invoked once at each subgoal's beginning [App. A.2].

### Goal: Does it measure wall-clock latency/time saved by avoiding brain re-calls, and does the world keep evolving (no pause) during brain calls?
It reports execution time (e.g., 31.8% reduction under severe disturbances vs. baselines) and token usage [Abstract; Sec. 4.1], with savings attributed to fewer VLM calls than DoReMi/IM. The text does not model world evolution during a VLM call; the halt-then-replan loop implies the robot stops while GPT-4o reasons. AgentChord later attributes CaM's longer execution time to re-invoking the MLLM after each subgoal/failure [2605.11951 digest].

### Goal: What limitation does it report on recovery/monitoring?
Constraint elements cover displacement/rotation failures but not force-direction failures without visible displacement, and drop multimodal cues [App. A.3]; threshold-sensitivity under diverse conditions "remains unexplored" [App. A.2]; hallucination in code generation persists [App. A.3].
