# Latency-Tolerant Cloud-Edge Collaborative Vision-Language-Action Models via Emergent Representational Specialization

## What this paper does
CloudEdgeVLA: a cloud VLA backbone (LoRA-adapted VLM) encodes possibly-delayed observations into planning features h_{t-k}; a lightweight edge action head fuses the latest received h with a frozen local SigLIP encoding of the current frame. Training uses paired fresh/stale frames from the same episode both supervised to the same current action target (dual-path loss), with gradients flowing into the backbone, so the backbone learns slowly varying "what to do" features. LIBERO with uniformly sampled delays up to 40 steps.

## Goal-by-goal answers

### Goal: What mechanism maps a delayed high-level decision/observation onto the current state?
Rather than predicting the present, it makes the cloud representation delay-invariant: L = (1-λ)||g(h_fresh, z_t) - a_t|| + λ||g(h_stale, z_t) - a_t||, where z_t is current edge vision; "when h_stale is misaligned with the current state, the action head must rely more heavily on z_t" [full text, Section 3.3, Eqs. 4-6]. Spatial grounding is moved entirely to the edge head [Section 3.2].

### Goal: What does the method assume about the slow decision-maker (trainable, white-box features, output type, delay scale)?
Backbone is trained (LoRA) and backpropagated through the stale path ("h_stale is not detached") [Section 3.3]; output is a continuous feature tensor, not text. Delay is in control steps (d_max up to 40) [Section 4.3, Table 1].

### Goal: What does it report as a limitation relevant to this axis?
At d_max=40 it keeps 63.8-78.0% LIBERO success vs ≤6.4% for VLASH [Section 4.3, Table 1]. Limits: robustness only for tested delay distributions; extended disconnection invalidates task-level context; frozen RGB encoder may miss cues needed for dynamic manipulation [Section 6].

# Latency-Tolerant Cloud-Edge Collaborative Vision-Language-Action Models via Emergent Representational Specialization

## What this paper does
CloudEdgeVLA: a cloud VLA backbone encodes delayed observations o_{t−k} into planning features; a lightweight edge head fuses the latest received feature with current local vision to output actions without blocking. Paired-frame training (fresh and randomly delayed frames mapped to the same current action) induces the cloud features to carry slowly varying task information and the edge path to supply state-sensitive corrections. On LIBERO it keeps 63.8–78.0% success under a 40-step uniform delay window where VLASH reaches ≤6.4%.

## Goal-by-goal answers
### Goal: What mechanism reconciles a stale high-level output with the current state, and what does it assume?
The edge head ĝ_φ(h_{t−k}, v_ψ(o_t)) learns to ground stale features with fresh vision [full text, Sec 3.1, 3.4]. There is no prediction; staleness is absorbed by training the representation to be delay-invariant. Assumes white-box access to and training of the backbone features (two backbone passes per sample) [Sec 6]; the slow component is a VLA backbone, not an API reasoner.

### Goal: What limitation does it report on dynamic tasks or long latency?
Robustness holds "only for the tested delay distributions; an extended disconnection can invalidate even task-level context"; a frozen RGB encoder may miss cues useful for dynamic manipulation [Sec 6]. Evaluation is on static LIBERO tasks.
