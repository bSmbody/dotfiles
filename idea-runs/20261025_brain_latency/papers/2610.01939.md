# Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

## What this paper does
PyRUA-Lean replaces per-primitive tool calls with Python code cells in which GPT-6 Astra composes robot primitives (motion, perception, VLA policies) with local checks and retries, returning only requested images/state. Over 700 simulated instances (LIBERO-PRO, RoboTwin 2.0, RoboCasa365) success rises 63.1%→71.7% with 49% fewer LLM calls and 65% fewer input tokens; on RoboDojo it reaches 51.6%. A 4B coder trained with GRPO learns the interface.

## Goal-by-goal answers
### Goal: Does the system measure, ignore or compensate the brain's latency, and does the environment pause while the model thinks?
It deliberately does not measure latency in seconds: "We count LLM calls rather than time episodes, because the latency of an LLM call on a shared model gateway varies too much" [full text, App E]. The execution model is strictly sequential: the LLM writes a cell, the runtime executes it, and the returned feedback informs the next call [Sec 3.1]; nothing acts while the model reasons, and the robot is idle between cells. Latency is reduced indirectly by fewer LLM calls (local retries inside a cell). Future work lists "measure execution latency and recovery on physical robots" [Sec 6].

### Goal: What mechanism (if any) keeps a high-level decision valid when the state changes before it is applied?
Within a cell, code reads fresh primitive results (e.g. object positions) at run time and branches on them (conditional checks, guarded descent, local retry) [Sec 3.2]. This is a form of late binding: geometry is computed when the code runs, not when the LLM wrote it. But the plan structure assumes the world is static between the observation the LLM saw and cell execution, and there is no prediction of state at cell-execution time.

### Goal: What limitation does it report on dynamic or moving-object tasks?
No dynamic tasks are evaluated. RoboDojo failures "concentrate on tasks that involve contact it gets no feedback on, or tight fits" [Sec 6].

### Goal: Does the brain pre-specify monitors and local recoveries that fire without re-calling the brain, and how are they parameterized?
Partly. Each cell can "approach an object, attempt a grasp only if the approach succeeds, and retry or stop based on the resulting state. These checks and branches execute within the cell without additional LLM calls" [full text, Sec. 3.2]; agents define helpers such as a guarded descent [Sec. 3.2]. The checks are whatever the LLM writes ad hoc over primitive return values (motion outcome, robo.state(), robo.done); there is no explicit representation of expected sensory events or task-relevant tolerances, and the checks run only at primitive boundaries inside a cell, not as a continuous monitor during a VLA primitive. At cell end, control returns to the LLM for replanning.

### Goal: Does it measure wall-clock latency/time saved by avoiding brain re-calls, and does the world keep evolving (no pause) during brain calls?
No. Savings are measured in LLM calls, tokens and dollars ($1.63 to $0.74 per episode). Appendix E states explicitly: "We count LLM calls rather than time episodes, because the latency of an LLM call on a shared model gateway varies too much from one call to the next to compare" [App. E]. The Codex CLI can time out a tool call after 300 s with the cell still running and subsequent cells queued [Sec. 3.1]; the simulator does not advance world dynamics during LLM thinking (tasks are static benchmark instances). Future work lists "measure execution latency and recovery on physical robots" [Sec. 6].

### Goal: What limitation does it report on recovery/monitoring?
Failures concentrate on tasks "that involve contact it gets no feedback on, or tight fits" [Sec. 6, RoboDojo]; success differences are partly VLA run-to-run variance, not recovery logic [Sec. 3.8].


### Goal: What per-call price does a read paper state for GPT-6 Astra, grounded in token counts?
App E: each call is billed from its own token usage "at GPT-6 Astra's list prices as of September 2026: $10 per million input tokens, $1 for cached input, $12.50 for cache writes and $50 for output, reasoning included". On jointly solved instances, calls fall from 17.0 to 8.7 and input tokens from 788k to 276k per episode, or $1.63 to $0.74 per episode [Sec 3, "Results"], roughly $0.085–0.096 per call. Those calls carry heavy context (median first prompt 20–24k tokens; output ≤17% of the bill) [App E]. RoboDojo episodes cost about $2.2–2.4 [App H, Sec 4]. The paper does not time calls, because gateway latency "varies too much" [App E].
