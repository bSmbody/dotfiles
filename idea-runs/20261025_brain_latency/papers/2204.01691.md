# Do As I Can, Not As I Say: Grounding Language in Robotic Affordances (SayCan)

## What this paper does
SayCan grounds an LLM planner in what the robot can actually do: for each skill in a fixed library it multiplies the LLM's probability that the skill's text is a useful next step by a learned value function (affordance) giving the probability that the skill succeeds from the current state, and executes the argmax skill; this repeats step by step. Evaluated on 101 mobile-manipulation instructions in a kitchen.

## Goal-by-goal answers
### Goal: How does SayCan use executor-side feasibility to constrain the LLM's choice, and at what time is feasibility evaluated?
The affordance p(c_π | s, ℓ_π) "indicates the probability of completing the skill ... successfully from state s"; the chosen skill is argmax_π p(c_π|s,ℓ_π) p(ℓ_π|i) [full text, Sec 3]. Feasibility is evaluated at the current state s at selection time, the selected skill is executed, and the loop re-queries [Sec 3, Algorithm 1]. The combination is a product of scores for one chosen skill per step; there is no conditional/contingent output, and no notion of the state at a later time when the decision takes effect. The only asynchrony mentioned is in the low-level RL policy, which "is given how much of the previous action is left to execute" [Appendix C.1].
