# Deferred-Decision Trajectory Optimization

## What this paper does
DDTO (Elango, Sarsilmaz, Acikmese; MERL/UW, 2025) generates trajectories that keep a collection of candidate targets reachable for as long as possible under constraints, so time is bought to resolve which target is viable. Formulated as constrained reachability, recast as cardinality minimization; solved by MICP, quasiconvex bisection on branch times, or SCP for nonlinear systems. The solution is a trunk/branch tree: coincident trunk segments, branches detaching at branch points to individual targets. Demonstrated on quadrotor and spacecraft-landing style planning examples with four static targets.

## Goal-by-goal answers
### Goal: Does DDTO weight candidate targets by a probability/belief, or only by count/priority?
Only by count and a fixed priority order. The objective maximizes the duration of reachability (latest branch time) or the number of reachable targets; "(9) is agnostic to prioritization of targets", so Algorithm 1 rejects targets at each branch time "based on a given priority order lambda^1..lambda^n" [full text, Sec "Solution Method", ddto-qcvx]. No probability-weighted objective appears; the framework is described as "fully deterministic" [Introduction].

### Goal: Are targets static or moving, and is the uncertainty resolved by a decision-maker with latency?
Targets are fixed states (landing sites; four target states in the quadrotor examples) [Sec "Numerical Results"]. Information is gathered by perception over time ("the computation of the latest branch time can use new information acquired by perception") [Sec Algorithm]; there is no model of a slow reasoner or of a random reveal time. Related work mentions AESOP-style LLM+MPC [Related Work, ref 20].
