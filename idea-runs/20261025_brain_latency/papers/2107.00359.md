# Model Mediated Teleoperation with a Hand-Arm Exoskeleton in Long Time Delays Using Reinforcement Learning

## What this paper does
Model-mediated teleoperation (MMT) for grasping under long delays: the operator demonstrates on a local physics-simulated replica (instant haptic/AR feedback); the demonstrated trajectory is encoded as DMP parameters, sent over the delayed channel, decoded on the avatar side and re-generated "given the updated values from the avatar robot and the environment"; the reconstructed trajectory is verified in simulation and, if it fails, refined by policy-search RL (PI², PoWER, eNAC) before execution on the real robot. DLR Exodex Adam + LWR/five-finger hand.

## Goal-by-goal answers

### Goal: What mechanism maps a delayed high-level decision/observation onto the current state?
Two layers: (1) a local model of the remote site gives the operator undelayed feedback (classical MMT/predictive display); (2) the delayed command is transmitted not as a raw trajectory but as a re-parameterizable DMP, which the avatar side re-targets to the current object/robot state, then simulates and RL-repairs if the re-targeted grasp fails [full text, Sections I, II-A, II-B]. The intent is: "providing instant haptic and visual feedback does not require the precise future state of the environment, and a simple approximation is sufficient" because avatar-side intelligence corrects errors [Section I].

### Goal: What does the method assume about the slow decision-maker (trainable, white-box features, output type, delay scale)?
The decision-maker is a human; MMT "requires an accurate model of the remote environment and avatar device" for the local replica [Section I]; the command is a continuous demonstrated trajectory, re-targetable because DMP goal/start are explicit parameters [Section II-A]. Cited delays in space teleoperation are 20-800+ ms (Kontur-2, METERON) [Section I].

### Goal: What does it report as a limitation relevant to this axis?
Policy-search RL explores locally and may stay near local minima; deep RL would need too much data and time "the inconsistency between demonstration and the environment may increase" [Section V]. Re-targeting requires knowing which parameter (goal pose) of the command refers to which object.
