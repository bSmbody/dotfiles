# TypeGo: An OS Runtime for Embodied Agents

## What this paper does
An OS-style runtime for LLM-planned embodied agents (Unitree Go2 prototype, GPT-5.4 planners). Planning runs as asynchronous loops at several cadences: a reflex layer S0, an action streamer S1, a task decomposer S2 and a scheduler S3. A Skill Kernel arbitrates actuator subsystems among concurrent task processes. S1 overlaps LLM generation with execution through a bounded queue of speculatively generated, condition-branched skill steps. A fast first-action path (S1P, Groq-hosted GPT-OSS-120B) emits one immediate skill while the slow planners deliberate. Preliminary evaluation on a small task suite: per-step delay −50% vs ReAct, time-to-first-action −73% vs plan-and-execute.

## Goal-by-goal answers
### Goal: Does TypeGo execute physical actions speculatively during a slow LLM call, using a fast model's guess of the slow planner's answer, and how does it handle wrong guesses?
Partly. S1P "emits one immediate skill call at process creation, overlapping the first action with the higher-level planners' deliberation and pulling reaction latency under one second; this action matches the eventual plan in roughly 60% of cases" [full text, Sec 8.1]. So a fast model acting physically while a slow LLM plans, and being overridden when the plan lands, is already prototyped. The S1 streamer generates up to three future steps into a queue while the current skill runs. Each step holds mutually exclusive branches (condition → skill) chosen by the executor at run time [Sec 6, Fig. 4]. Wrong guesses are simply preempted or replaced. There is no model of irreversibility, no hedging across several candidate answers, and no feasibility certificate.

### Goal: Does it deal with moving targets, closing reachability windows, or choosing among several candidate objects during the call?
No. The tasks are navigation and search tasks for a quadruped (find an apple, take pictures); a static or slowly changing scene is assumed; no moving objects or interception. The speculation hides planning stalls, not the loss of feasibility during the call [Sec 8].
