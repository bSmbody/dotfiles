# DoReMi: Grounding Language Model by Detecting and Recovering from Plan-Execution Misalignment

## What this paper does
DoReMi (IROS 2024) has an LLM (Vicuna-13B or GPT-4) emit the next skill and, by continuing generation after "Constraint:", the constraints that must hold during that skill (e.g., "robot holds box"). A VLM (BLIP-2-style, optionally fine-tuned) is queried every Δt seconds with yes/no questions on each constraint; if any is violated, the skill is aborted and the LLM re-plans with the violation in the prompt. Evaluated on pick-place/stacking arm tasks and humanoid tasks with drop probability and controller noise.

## Goal-by-goal answers
### Goal: Does the brain pre-specify monitors and local recoveries that fire without re-calling the brain, and how are they parameterized?
Monitors yes (as language constraints), recoveries no. Constraints are generated with each planned step [full text, Sec. III-B]; the VLM checks them "every Δt second" (Algorithm 1, line 6); on any false answer the loop breaks and "the language model is invoked for immediate re-planning" [Sec. III]. No tolerances: constraints are binary VQA predicates. No pre-armed correction exists; every correction is a new LLM call.

### Goal: Does it measure wall-clock latency/time saved by avoiding brain re-calls, and does the world keep evolving (no pause) during brain calls?
It measures task execution time (Tables I, II; "only measure execution time under high success rates") and shows earlier abort shortens episodes vs. Inner Monologue. The saving comes from detecting failure earlier, not from avoiding the brain call; the re-plan call is always made. The text does not model the world evolving during the LLM call.

### Goal: What limitation does it report on recovery/monitoring?
The detector's reliability depends on VLM fine-tuning (Appendix V-A); periodic VQA querying cost is the trade-off with Δt. Recovery quality is entirely the re-planner's.
