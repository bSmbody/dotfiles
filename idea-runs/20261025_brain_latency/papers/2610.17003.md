# Multi-Agent Deferred-Decision Trajectory Optimization with Anytime-Valid Target Retention for Moving Candidates

## What this paper does
Multi-agent terminal interception when one of several moving candidates is the unknown target. A receding-horizon controller combines conformal prediction of each candidate's terminal location, sequential rejection of non-target candidates via an e-process over identity queries, capacity-constrained assignment of candidates to agents, and deferred-decision trajectory optimization (DDTO): one branch per assigned candidate, all sharing a common prefix (the applied control) and separating as late as feasible. Gives coverage/retention guarantees and evaluates in 100 paired HoloOcean scenarios (79% capture under a strict effort budget, 85% relaxed). Submitted to RA-L, Oct 2026.

## Goal-by-goal answers
### Goal: What is the deferred-decision mechanism for moving candidates and why does it work?
"Committing too early can direct an agent toward a non-target, whereas excessive deferral can leave insufficient time or control authority for capture"; so "each agent must choose a single input that preserves feasible trajectories toward all assigned candidates" [full text, Sec I]. DDTO builds one state-control branch per candidate, forces δ_0=0 so all branches share the applied control, and makes separation monotone; each branch must stay feasible to its candidate's conformal terminal region [Sec III-C, Eqs 5a–5c]. Related contingency MPC and delayed-decision motion planning likewise share the applied input across branches [Sec I].

### Goal: What does it assume, and what happens when no branch is verified?
Deterministic known agent dynamics, a centralized controller with candidate tracking histories at every replan, exogenous candidate motion, and exchangeability of residuals for the guarantees [Sec II, IV]. When an agent has no verified DDTO plan, "the controller instead applies fallback guidance toward a retained candidate" [Sec I, III-C]. The decision-maker is an optimizer that re-solves every replan; there is no slow semantic reasoner and no latency of the decision itself.
