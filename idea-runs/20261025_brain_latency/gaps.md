
## Axis: execution monitoring with brain-pre-specified local recovery for LLM/VLM-planned manipulation

### What has been done
- **Brain emits monitors, recovery still goes through the brain.** DoReMi [2307.00329] has the LLM emit language constraints with each skill ("robot holds box"), checked by periodic VLM yes/no queries every Δt; any violation aborts the skill and triggers an LLM re-plan. Code-as-Monitor [2412.04455] has GPT-4o write, at each subgoal start, during/at-completion constraints, which a trained segmenter turns into tracked 3D elements; VLM-written monitor code with tolerances (e.g. 15° tilt) returns a boolean, and on False "the policy execution halts immediately" and the reason is fed back for re-planning. Both report execution time, and both save it by detecting failures earlier, not by avoiding the re-plan call.
- **Brain pre-arms recoveries that fire with no brain call (the closest prior work).** AgentChord [2605.11951] (RSS 2026) builds a task graph from (instruction, o_0). For every edge, a recovery agent predicts failure modes, writes each as a scalar monitor over geometric and gripper features (object shift ‖p_t − p̄‖ − δ against the last stable reference p̄; tilt; gripper width; attachment distance; visibility), and attaches forward-moving recovery branches. Online, a persistence-window trigger switches to the pre-compiled branch "without re-invoking full task planning", and a receding-horizon solver re-grounds the recovery geometry from current perception. It reports end-to-end execution time including MLLM inference: 105.6 s, against 128.4 s for its own backtracking variant and 122.4 s for ReKep, over three real tasks. The arming mechanism this axis proposes therefore already exists, with time savings measured. What AgentChord does not do: it arms everything once from o_0 with shared default tolerances, its scenes are static apart from discrete injected disturbances, and it never varies brain latency.
- **Local checks inside LLM-written code.** PyRUA-Lean [2610.01939] lets GPT-6 Astra write cells with conditional checks and local retries over primitive return values, cutting LLM calls from 17.0 to 8.7. It explicitly counts "LLM calls rather than time episodes" because gateway latency varies too much to compare. The checks are ad hoc. They have no expected-event or tolerance representation and run only at primitive boundaries.
- **LLM-authored, retained fallback structure (behavior trees).** BETR-XP-LLM [2409.13356] calls the LLM after a failure to add preconditions that the planner expands into a BT, so the same failure is later handled reactively. SCBT [2610.25455] has an LLM propose grammar-constrained BT patches after failures; CMA-ES tunes them, a bandit decides reuse vs. a new call, and they are crystallized into an LLM-free tree. SCBT measures 31–105 s per frontier proposal, yet "the runner pauses the simulator" during each call, and it models the call's cost as a constant penalty κ in the bandit reward.
- **Learned or library monitors with fixed recoveries.** Tri-System VLA [2603.05185] runs a trained Florence-2 critic asynchronously at ~20 Hz; an anomaly token wakes the Brain to re-plan. CarryOn [2610.21453] runs one shared library recovery skill (re-localize, re-grasp, gripper-width holding checks) whenever a Judge flags a subtask failure, and refines that skill offline between rounds. Neither arms corrections per stage from the planner.
- **Failure reasoning and detection quality.** REFLECT [2306.15724] and AHA [2410.00371] are post-hoc (post-sub-task) LLM/VLM judges whose explanations feed a new LLM plan. REFLECT assumes the environment stays static. FailBench [2609.03611] finds the best VLM judge at 0.77 balanced accuracy, near chance when success hinges on whether contact was established (≤0.60 on contact-rich assembly), while "which object moved" events are reliable. RESCUE [2610.13516] shows monitor alarms often land after the recoverability horizon, and that routing alarms to a cheap scripted Recover instead of stop-and-reset cuts excess cost 3.1–13.4×. Recoverability depends on the intervention repertoire.
- **Recency trail (since 2025-10-01).** Queries run: "proactive failure recovery manipulation", "anticipatory recovery branches", "LLM behavior tree recovery", "contingency LLM robot", "anticipated failures robot LLM", "runtime monitor VLA", "failure detection VLM robot recovery", "event-triggered replanning VLM manipulation", "frontier model latency robot real time". The only work that pre-arms recoveries from the planner is AgentChord. The other hits are VLA-internal monitors, rollback (SafeLoop), or post-hoc judges. **No read or retrieved work measures success or time saved by avoiding brain re-calls as a function of brain latency in a world that keeps moving during the call.** That empirical absence alone is not a method gap; the method gaps it exposes are below.

### Open gaps on this axis
- **Gap:** Planner-armed recovery methods arm monitors once against a static snapshot. AgentChord compiles all branches from o_0, uses a static reference p̄ and shared default tolerances; CaM generates monitor code per subgoal from the current image. Such a monitor has no model of how the world and the arm are expected to evolve over a stage or during a seconds-long brain call. Expected motion (a conveyor object, arm drift while the brain thinks) is therefore indistinguishable from failure, and expected events (contact, grasp-hold, object-moved) carry no timing. In real-time manipulation with moving objects, a pre-armed reflex would either fire falsely or stay silent.
  - **Near-miss methods and coverage:** [2605.11951] is the closest. It pre-arms per-edge failure monitors and forward-moving recovery branches that fire with no MLLM call, but its shift monitor is ‖p_t − p̄‖ − δ with p̄ "the last stable estimate at node v^i or ... expected in-hand pose", all branches come from o_0, tolerances are shared defaults, and its scenes are static apart from discrete disturbances. [2412.04455] regenerates monitor code at each subgoal and halts plus re-plans on violation, with thresholds from a knowledge base and threshold sensitivity "unexplored". [2307.00329] uses binary VQA predicates with no tolerance or timing. [2306.15724] states that it assumes the environment stays static. All four share the deficiency that the monitor's nominal model is a time-invariant predicate over the current or initial state. Recency queries ("anticipatory recovery branches", "event-triggered replanning VLM manipulation", "contingency LLM robot") turned up no planner-armed monitor with a time-indexed expectation.
  - **Methodological deficiency:** This is a representation limitation. The brain-to-monitor interface is a static constraint c(z) ≤ 0 with fixed tolerance, not a time-indexed expectation (event, expected time window, expected state trajectory, tolerance band) conditioned on the stage's motion. The monitor cannot tell expected change from failure, and it cannot recognize that an expected event has not happened by its deadline (missed contact, no object motion). The second case is exactly the contact-type event that FailBench [2609.03611] shows VLM judges cannot reliably detect after the fact (≤0.60 balanced accuracy).
  - **Why it matters:** Systems with a slow frontier brain over a fast executor cannot run pre-armed reflexes in dynamic scenes or while the brain is mid-call. Every deviation then becomes either a false alarm or a brain re-call, which brings back the multi-second latency that pre-arming was meant to remove. Closing this gap would extend latency-free local recovery from static tabletop scenes to moving objects and targets.
  - **Evidence route:** Run real-time sims (no pause during brain calls) with moving objects and swept brain latency Δ. Compare false-alarm rate, missed-event rate, recovery success, and wall-clock time between static-snapshot monitors (AgentChord/CaM-style) and any monitor whose expectations are time-indexed. Isolate cases where the object moves as expected versus cases where it is perturbed.
- **Gap:** Methods that trade brain re-calls for local structure treat the cost of a brain call as latency-independent: tokens or calls in PyRUA-Lean, a constant penalty κ with the simulator paused in SCBT, serial summed execution time in AgentChord. The choice of which corrections to pre-arm locally and which to escalate to the brain therefore ignores the fact that the state degrades during the call. Real-time manipulation turns a correct but late brain decision into a failure once Δ exceeds the failure's recoverability horizon.
  - **Near-miss methods and coverage:** [2610.25455] learns with a contextual bandit when to reuse a stored patch versus CallLLM, but CallLLM "always pays κ" and the live episode is paused during each 31–105 s call. [2610.01939] cuts LLM calls with local checks and retries but explicitly does not time episodes. [2605.11951] arms every predicted failure mode uniformly and evaluates only summed time in static scenes. [2610.13516] shows that intervention value depends on the alarm landing before the recoverability horizon, and that cheap scripted recovery beats stop-and-reset by 3.1–13.4×, but it models no planner latency. The shared deficiency in [2610.25455], [2610.01939] and [2605.11951] is that the escalation and arming rule does not depend on Δ relative to the time-to-unrecoverability of the specific failure.
  - **Methodological deficiency:** This is a credit-assignment and objective mismatch. The arming and escalation decision is optimized against token cost, call count, or a constant per-call penalty, not against the latency-dependent loss in recoverability during the brain call. The methods have no mechanism for deciding that one failure mode must be handled by a pre-armed reflex because its recoverability window is shorter than Δ, while another can safely wait for the brain.
  - **Why it matters:** Without such a rule, pre-arming is either exhaustive (expensive upfront brain reasoning, and more false triggers as RESCUE's false-alarm break-even shows) or arbitrary. No method can say which corrections need a local reflex at a given brain latency. That knowledge is what would let a system use the frontier model less without losing time-critical recoveries.
  - **Evidence route:** Inject failures with known recoverability horizons (RESCUE-style counterfactual branching) under real-time execution and a sweep of Δ. Measure success and wall-clock time when arming is latency-blind (all modes or none) versus latency-aware. The crossover where brain escalation stops succeeding should track Δ against the horizon.


## Axis: compensating delayed high-level commands — classical and learned

### What has been done
Searches (arXiv, plus WebSearch for classical items): "delay-aware Markov decision process", "random delay reinforcement learning", "model-mediated teleoperation time delay", "predictive display teleoperation latency", "delay compensation model predictive control robot", "conveyor picking moving object grasp", "dynamic manipulation VLA moving objects", "delayed observation world model", "dual-system VLA asynchronous", "execution delay policy optimization", "inference latency embodied agent real time", "time-delayed vision-language model robot"; recency (since 2025-10-01, cs.RO): "latency", "delay compensation", "stale", "asynchronous planner", "moving target", "anticipatory planning frozen VLM", "stale plan re-grounding".

**Verdict on direct transfer.** None of the four families gives a method that drops into "black-box frontier VLM, seconds of latency, discrete semantic/spatial decision, fast VLA/scripted executor". Each one depends on at least one thing this setting lacks: a known plant/environment model, a decision that is repeated every control step or is a continuous time-indexed stream, a sub-second delay of known size, or gradient/feature access to the slow model. What does carry over is (i) stamping each decision with the time of its observation, (ii) using the executor's committed actions during the delay as the exactly known part of the state change, (iii) sending a command that can be re-parameterized and re-targeted on the executor side, and (iv) giving the decision-maker a forecast instead of the stale input.

1. **Time-delay teleoperation (classical).** Predictive displays: Bejczy, Kim & Venema 1990, "phantom robot" graphics overlay driven without delay (not on arXiv, not read). Supervisory control, where a human gives high-level goals to local autonomy: Sheridan (not on arXiv, not read). Smith predictor (Smith 1957; not on arXiv, not read). The Xu et al. 2016 MMT survey (not on arXiv, not read). Among papers read: in MMT [2107.00359] the operator works against a local replica of the remote site. The delayed command is sent as DMP parameters, and the avatar side regenerates it "given the updated values from the avatar robot and the environment", checks it in simulation, and repairs it with policy-search RL. MMT presumes an accurate model of the remote site, and its command is a continuous human trajectory. Generative predictive display [2605.09670] forecasts the current frame from delayed frames with off-the-shelf video models. Even at 15 FPS and horizons of tens to hundreds of ms, no zero-shot model met accuracy, temporal consistency and real-time speed together, and diffusion models drifted.
2. **Delay-aware RL and delay-aware imitation (Smith-predictor analogues).** Katsikopoulos & Engelbrecht 2003 reduce delayed MDPs to augmented MDPs (not on arXiv, not read). DCAC [2010.02966] augments the state with the buffer of the last K actions plus the measured delays, and uses timestamps to throw out superseded messages; the buffer grows with the maximum delay. Delayed-Q [2101.11992] rolls a forward model over the queue of pending actions to forecast s_{t+m} and acts on that forecast. The paper proves state augmentation costs exponentially more, and warns that point-estimate forecasts "can be devastating" when the future is multimodal. DA-Dreamer [2509.20869] filters the world-model belief up to the present, using the prior wherever an observation is still missing; its error builds up over the filtering steps. Imitation-side versions retrain the delayed policy itself. DA-DP [2512.07697] time-compresses the demonstrations for a measured delay of tens to hundreds of ms. RAPAC-DP [2608.15924] conditions a LoRA-adapted policy on the pending actions, for a known fixed delay.
3. **Delayed perception in dynamic manipulation.** Conveyor picking [2003.08517] specifies the goal as an object pose on a belt of known velocity, so planning means planning an intercept, and it replans within a guaranteed time bound as the pose estimate improves. This works because the planner can be re-run within the budget. DynamicVLA [2601.22153] streams only the part of an action chunk whose execution time has not yet passed. This needs the decision to be a time-indexed trajectory that reaches past the delay. AHEAD [2606.02486] gives a frozen VLA forecast patch tokens: optical flow, a constant-acceleration analytic update, and a flow-matching latent model, stopped by sample variance. It forecasts at most 10 steps (~158 ms loop) and works inside the VLA's own feature space.
4. **Learned slow-fast stacks with stale semantics, and black-box LLM planners.** TIC-VLA [2602.02459] feeds a fast action expert the slow VLM's stale KV cache plus Δt and the ego-motion offset. The expert is trained with delays of 0–10 s and then with PPO. Removing the ego-motion offset drops SR from 47.1 to 41.2. The VLM is a fine-tuned InternVL3-1B, and the task is navigation. Acting While Understanding [2606.15285] trains the action head on stale caches (up to ~1 s) together with the history of executed actions. CloudEdgeVLA [2608.00569] trains the backbone through a stale path so that its features stop depending on delay, and leaves all spatial grounding to the current edge vision. On the black-box side, RRARA [2506.07223] has an API LLM emit object-ID subgoals that the executor resolves against current poses. It discards and replans when a handcrafted global staleness score crosses a threshold, and an asynchronous LLM reflector checks the running action. Agentic Fast-Slow Planning [2604.01681] measured 4.13 s LLM latency, emits symbolic directives as soft A* costs, and does no latency compensation.

### Open gaps on this axis
- **Gap:** Some prior latency compensators learn to reinterpret a stale decision as an opaque latent inside a white-box slow-fast stack (stale KV/feature conditioning: [2602.02459], [2606.15285], [2608.00569]). Others forecast the decision-maker's input in its own feature or pixel space ([2606.02486], [2605.09670], [2101.11992]). Neither applies when the slow model is a black-box API whose output is a discrete, structured spatial decision ("grasp object o at pixel/point p", "move 5 cm left of the gripper") anchored to the frame at t−Δ. Such a decision's referents have to be carried to the execution time. The part of the change caused by the robot itself is exactly known from the committed actions. The part caused by object motion has to be predicted. No method separates the two or re-anchors the decision itself.
- **Near-miss methods and coverage:** [2602.02459]: comes closest. It timestamps the VLM output, passes Δt and the ego-motion offset Δp, and gains about 6 SR points from Δp. But the correction is learned implicitly by an action expert trained on the VLM's KV cache. Object motion during the delay is left to the current image, and the VLM must be fine-tuned. [2107.00359]: re-targets a transmitted, re-parameterizable command (DMP goal) to the current remote state, but needs an accurate environment model and a continuous human trajectory. [2506.07223]: black-box LLM. Object-ID subgoals are re-resolved against current poses, but they carry no spatial or relative content, and staleness is handled only by discard-and-replan. [2608.15924] / [2010.02966]: use the committed action buffer, the exactly known part, but only as a conditioning input to a policy that must be retrained, with a known fixed or short delay. [2606.02486]: forecasts for a frozen model, but only in that model's token space and only over ~5–10 steps. Recency queries since 2025-10-01 ("delay compensation", "stale", "asynchronous planner", "anticipatory planning frozen VLM", "stale plan re-grounding") found no method that acts on a black-box brain's structured output.
- **Methodological deficiency:** Representation limitation. Every read method represents the delayed decision either as an internal latent (KV cache or features) or not at all, compensating its input instead. None exposes the decision's spatial referents (target object identity, target point, reference frame of a relative command) as explicit, transformable variables. Without that, the Smith-predictor split cannot be applied: the deterministic, fully known effect of the executor's committed actions (which [2602.02459] shows matters, Table 6) cannot be removed in closed form, apart from the uncertain motion of objects. Separately, the forecast-the-input route has to work in the black-box model's input space (pixels) over seconds. That is where [2605.09670] reports zero-shot video models drifting and failing even at sub-second horizons, and where [2101.11992] shows point forecasts fail when the future is multimodal.
- **Why it matters:** Every system that puts a frozen frontier model on top of a VLA or scripted executor is blocked. Those systems cannot fine-tune the brain or read its features, so the learned stale-feature recipes do not apply, and forecasting seconds of video for the brain is unreliable and costly. If decisions can be re-anchored in a way that separates ego motion from object motion, a brain call made 4 s ago could still be executed correctly against the current scene: a grasp on a moving conveyor box, or a relative move after the arm has kept going. It would also become clear how much of the latency penalty is the exactly removable ego part versus the inherently uncertain world part.
- **Evidence route:** Run a frozen API brain at a controlled latency Δ (simulator not paused) on static-table relative-command tasks and on moving-target tasks (conveyor/rolling objects). Compare executing the raw stale decision, discard-and-replan in the style of [2506.07223], forecasting the brain's input image, and a method that transforms the decision's referents to execution time. Report success and spatial error (cm) against Δ and object speed. On static tasks, ego-only re-anchoring should bring error close to the Δ=0 level. On moving tasks, the residual should scale with object-motion predictability rather than with Δ × arm speed.

- **Gap:** Prior compensators decide whether a delayed high-level output is still usable with signals that ignore the decision itself. Examples: a fixed refresh schedule or a cache-age bound ([2606.15285]), a handcrafted whole-scene staleness score with one threshold ([2506.07223]), or the forecaster's own variance as a stopping rule ([2606.02486]). Over multi-second delays, many scene changes leave a given decision valid while a few invalidate it: its target occluded, grasped or knocked away, or the task phase advanced. These signals cannot tell the two cases apart, so the system either keeps executing an invalid decision or throws away a valid one and pays for another full brain call.
- **Near-miss methods and coverage:** [2506.07223]: the only read black-box method with an explicit staleness test. Its score Stale(t,τ) adds value-weighted changes over all objects plus agent motion, time and hazard, and regenerates the plan above δ; the test does not depend on which object or region the cached plan actually uses. [2606.15285]: authors state the action module "may still be limited when semantic cache age becomes too large or when the environment changes significantly" and that a fixed refresh schedule lets "stale semantics ... mislead the controller before the next refresh". [2606.02486]: stops its forecast when sample variance passes a training-set percentile, a measure of forecast uncertainty and not of whether the downstream decision still holds. The authors also note the variance "can be confidently wrong". [2608.00569]: states that an extended disconnection "can invalidate even task-level context" and proposes only timestamping plus a local fallback. [2101.11992]: shows point estimates break under multimodal futures but offers no rejection test.
- **Methodological deficiency:** Missing mechanism. No read method has a validity test conditioned on the decision. In every case, applicability is judged from a global or forecaster-internal quantity: cache age ([2606.15285]), whole-state difference ([2506.07223], Eqs. 4–7), or prediction variance ([2606.02486], Eq. 4). None comes from whether the specific referents and preconditions of this decision still map onto the predicted execution-time state. The re-anchoring step therefore has no principled way to decide between applying the compensated decision, applying it with the executor holding back, or asking the brain again.
- **Why it matters:** With seconds of latency, each extra brain call costs seconds and API dollars. An over-eager staleness rule wastes calls and adds idle time. An under-eager one executes wrong grasps. A decision-specific validity signal is what would let a system call a slow brain less often without acting on stale decisions, which is the problem's stated cost/performance target.
- **Evidence route:** In real-time simulation with scripted perturbations that hit either the referent of the current decision or irrelevant parts of the scene, measure for each policy: the rate of re-queries, the rate of wrongly executed stale decisions, task success, and wall-clock time. Policies to compare are fixed refresh, a global staleness threshold, forecaster variance, and a decision-conditioned test. A decision-conditioned test should cut both errors at once, i.e. move the Pareto front of success versus brain calls, and not just trade one error for the other.


## Axis: latency of frontier-model (LLM/VLM) high-level brains in real-time robot manipulation

### What has been done
Search trail (arXiv, since 2025-10-01 unless noted): "latency-aware high-level planner robot manipulation", "asynchronous VLM planner robot", "real-time VLM planner dynamic manipulation", "think while acting robot", "slow fast dual system latency robot", "LLM planner moving objects manipulation", "dual-system VLA asynchronous", "hierarchical VLA latency", "stale plan robot", "dynamic manipulation VLM", "predictive planning latency robot", "planner latency manipulation", "asynchronous reasoning VLA", "moving object grasp VLA", "reasoning latency embodied", "delayed reasoning VLA", "cloud LLM robot latency", "real-time embodied agent benchmark latency", "GPT-6 Astra robot", "staleness VLM robot", "delay-aware VLA", plus citation follow-ups from RT-Safe (AgenticCache).

- **Frontier-brain manipulation systems measure latency only as cost, and the world waits.** GPT-GEAR executes Astra's pose increments as "bounded, synchronous" commands anchored to the end-effector pose measured at the start of the call, and Observe does not advance the simulator; latency appears only as 7.82–28.43 min per episode, 8.6–10x specialist VLAs [2610.28259]. CALL clears π0.5's action queue and hands environment control to Astra; LIBERO advances one step per accepted correction, and throughput drops from 8.25 to 2.58 steps/s [2610.14117]. PyRUA-Lean counts LLM calls instead of seconds and runs cells strictly sequentially; late binding happens only inside a cell, where code reads fresh primitive results [2610.01939]. In a π0.5-derived waypoint hierarchy, the planner is blocking: token-AR planning (1.1 s) leaves the arms moving 28.7% of the time, and Block-AR raises that to 65.6% by decoding faster, not by overlapping [2609.30833]. All are evaluated on static tasks. The mitigation in this line is calling the brain less or decoding faster.
- **Non-paused evaluation exists, but not for frontier brains in manipulation.** RT-Safe shows that paused-world evaluation hides latency failures of eight VLM agents: completion is similar (91.3% vs 94.1%), but collisions rise 12.3x and ~84% of them happen while the agent idles during inference; the only adaptation is prompt-level [2610.09294]. The SPARK-VLN suite has paused and non-paused modes [2607.16806]. RAVEL's Dynamic Object Manipulation benchmark advances the simulator during policy inference [2609.34170]. Those two are navigation, and RAVEL tests a low-level VLA. None of these benchmarks uses an API frontier model driving a manipulation executor.
- **Latency-aware slow/fast systems put the stale reasoner's output into the fast layer.** (i) Learned reinterpretation: TIC-VLA feeds the fast policy cached VLM KV features from t−Δt plus Δt and the accumulated ego-motion offset, trained with Δt∼U[0,10] s; it is navigation-only and needs a white-box, fine-tuned VLM [2602.02459]. CloudEdgeVLA trains stale backbone features to be delay-invariant, and an edge head grounds them with fresh vision [2608.00569]. (ii) Earlier delivery: SPARK-VLN streams intermediate hidden states while the VLM is still generating (needs white-box access) [2607.16806]. (iii) Training-free re-scoring: Slow Brain, Fast Planner motion-compensates a stale black-box VLM trajectory choice into the current frame using odometry and fuses it into fresh candidate scores with exp(−Δt/τ) decay. It holds above 80% success at 5 s delay, while executing the stale choice directly collapses past 2 s; ego-motion only [2606.20458]. (iv) Object-anchored re-binding: DualManip expresses the VLM's decision as grasp contacts on a pre-scanned object template and moves them to the live point cloud in 139 ms, against 4.3–6.4 s for VLM replanning. It is reactive, needs templates, and replanning fails completely under continuous change [2609.31112]. (v) Symbolic reconciliation: AgenticCache executes cached plans and, when the LLM answer arrives k steps late, checks it against the executed trajectory, then confirms it or replaces the plan [2604.24039]. (vi) Verify-then-hold: SPO's cloud world model rolls out states, and an edge ε-tube check against measured state stops the robot on a miss (ms-scale network delay) [2603.19418]. In every case the slow reasoner itself still reasons over the stale frame.
- **Forward models of the execution-time state exist only inside low-level VLAs, sub-second, in private latents.** EagleVLA predicts the compressed VLM final-layer state at t+Δ from the state at t plus the committed actions (Δ≤9 steps) [2607.12659]. FutureRTC rolls proprioception forward through the committed actions and warps the stale encoder latent; it states it may fail when independent agents dominate scene change [2607.24008]. DSDyn-VLA rolls kinematics forward and adds a 30 Hz RL residual [2609.39198]. AHEAD forecasts future patch tokens for a frozen OpenVLA under a constant-acceleration prior, K_max=10 steps [2606.02486]. ForeTime-VLA distills a future code from a world-action-model teacher; its horizon is not tied to any delay [2608.20735]. FlashVLA, RAVEL and REACT hide latency through decoder continuity or freshness without prediction (delays of 1–4 steps; embedding age ≤416 ms) [2608.27384, 2609.34170, 2610.12007].

**Novelty check for the seed idea** (a forward model predicts the state when the brain's answer arrives, the brain plans on that predicted state, and its output is then reconciled to the actual state):
- *Part (a), predicting state at t+Δ from committed actions:* already done, but only for the low-level VLA's own inference delay. The closest is [2607.12659], an action-conditioned, Δ-adaptive prediction of the VLM hidden state at t+Δ. Next are [2607.24008] (state plus visual latent), [2606.02486] (object motion, frozen VLA), [2609.39198] (kinematic rollout) and [2603.19418] (state-space speculative rollout plus verification). All of them work in white-box VLA latent or low-dimensional state space, over horizons under a second, and feed the executor, not a reasoner.
- *Part (b), the brain reasons on a predicted future state:* no read paper does this. In [2602.02459], [2607.16806] and [2606.20458] the brain reasons on the inference-start frame. [2610.09294] only tells the model in the prompt that the world moves. AHEAD [2606.02486] gives predicted inputs to a frozen decoder, but that decoder is the executor, not a semantic planner.
- *Part (c), reconciling a stale output to the actual state:* partly done. Closest: [2606.20458] (training-free, black-box VLM, ego-motion-only compensation plus staleness decay) and [2609.31112] (object-anchored contact transfer, reactive, template-dependent). Learned, white-box versions: [2602.02459] and [2608.00569]. Symbolic: [2604.24039]. Verify-and-hold: [2603.19418].
- *Net:* the combination with a black-box frontier brain in manipulation with independently moving objects and seconds-scale Δ is not covered. A paper doing only (a) or only (c) would be a thin delta over [2607.12659], [2606.20458] and [2609.31112].

### Open gaps on this axis
- **Gap:** Latency-aware brain+executor systems compensate a seconds-late high-level decision only downstream, by reinterpreting the stale output in the fast layer ([2602.02459], [2606.20458], [2608.00569]), while the brain itself still reasons over the inference-start frame. The execution-time forward models that do exist ([2607.12659], [2607.24008], [2606.02486]) predict sub-second futures in the executor's private latent space. So in real-time manipulation with moving objects, no method gives a black-box API brain (e.g. GPT-6 Astra) a prediction of the scene at answer-arrival time that it can actually read. Its choice of target, grasp side or still-feasible subgoal is made about a state that no longer exists.
- **Near-miss methods and coverage:**
  - [2607.12659]: predicts the VLM hidden state at t+Δ from committed actions. This is the cerebellum-like forward model, but in a white-box latent consumed only by the action expert, with Δ≤9 action steps.
  - [2606.02486]: forecasts the motion of independently moving objects in patch-token space for a frozen VLA, with K_max=10 steps under a constant-acceleration prior. The consumer is the action decoder.
  - [2607.24008]: forecasts state and visual latent at execution time, but assumes the robot is the main source of scene change.
  - [2602.02459]: handles multi-second reasoning delay (Δt up to 10 s in training) but has the reasoner work on the delayed frame and leaves compensation to a policy trained on its KV features. Ego-motion only, navigation.
  - [2607.16806]: shortens staleness by streaming hidden states; the reasoner still sees x_{t'}.
  - [2610.28259], [2610.14117], [2610.01939]: frontier-brain manipulation systems that pause the world or idle the executor, so the issue never shows up.
  - Repeated deficiency: the predicted state lives in a representation the frontier brain cannot read, over a horizon shorter than one brain call, or does not exist at all. The query trail above (17+ queries) found no paper that hands a predicted future observation or state to the reasoner.
- **Methodological deficiency:** Representation limitation plus missing mechanism. The forward models are trained to produce the executor's own conditioning tokens: the VLM final-layer state in [2607.12659], VLA patch tokens in [2606.02486], encoder latents in [2607.24008]. Their output therefore cannot be shown to a black-box API model. They are also trained for horizons of a few control steps: EagleVLA's sweeps stop at Δ=9 steps; AHEAD's constant-acceleration rollout is capped at 10 steps and degrades under non-linear motion. The latency-aware dual systems, in turn, structurally anchor the reasoner to t−Δt ([2602.02459], Sec 3.2: "the VLM operates on visual observations anchored at time t−Δt"). No existing mechanism produces an explicit, brain-readable (image or object-state) forecast over a horizon of seconds, conditioned on the committed executor actions and on object motion.
- **Why it matters:** Downstream reinterpretation can fix where a decision lands, but not which decision was made. If the conveyor box the brain chose has left the reachable zone, or the arm's committed motion makes the chosen subgoal infeasible, re-targeting cannot save the episode. Systems that use a frontier model as cortex (the Astra-driven systems above) cannot run without pausing until the brain's input reflects the world at actuation time. Closing this would show whether frontier-model reasoning stays useful in dynamic manipulation once Δ is several seconds.
- **Evidence route:** Run a non-paused simulator (a moving-object variant of LIBERO, ManiSkill or RoboCasa) and sweep injected brain latency Δ (e.g. 0–8 s) and object speed. Compare the brain fed the stale frame, the stale frame plus reinterpretation in the style of [2602.02459] or [2606.20458], and the brain fed a forecast. Report success and wall-clock time against Δ, and separate decision errors (wrong target or infeasible subgoal) from placement errors. The gap is closed if decision errors stay flat as Δ grows while they rise for the stale-frame baselines.

- **Gap:** When a black-box brain's output is a spatial command expressed in a frame fixed at query time, prior work reconciles it with the actual state in one of five limited ways:
  - motion-compensating only the robot's ego-motion with odometry [2606.20458] (or the arm pose at call start [2610.28259]);
  - learning the reinterpretation end-to-end from white-box features [2602.02459], [2608.00569];
  - reactively re-binding to object templates [2609.31112];
  - reconciling at the symbolic plan level [2604.24039];
  - stopping the robot on any state mismatch [2603.19418].
  None of these re-anchors a semantically specified target ("grasp the box at (x,y)", "5 cm left of the gripper") to the independently moving object or frame it refers to without per-object templates or retraining. In real-time manipulation the command therefore lands where the object was, not where it is.
- **Near-miss methods and coverage:**
  - [2606.20458]: training-free reconciliation of a stale black-box VLM choice. It maps the choice through odometry into the current frame and decays its weight by exp(−Δt/τ). Ego-motion only; the authors note their delayed-oracle simulator "cannot exhibit real-world scene drift".
  - [2609.31112]: re-binds a VLM-grounded grasp to the live object geometry via template correspondence (139 ms per update), but needs a pre-scanned template and object-specific training, does no prediction, and handles changes during execution rather than during the brain call.
  - [2602.02459]: reinterprets stale semantics in the current frame using latency and ego-motion metadata, but needs KV-cache access and RL training; navigation.
  - [2604.24039]: confirms or replaces a k-step-late LLM plan against the executed trajectory, but only for discrete symbolic plans.
  - [2603.19418]: verifies predicted against measured state and holds on a miss, which makes the executor idle.
  - [2610.28259]: anchors relative commands to the arm pose at call start, which is valid only because the arm is stationary.
  - Repeated deficiency across these: the stale command is bound to the robot's or the world's frame at query time, so only robot motion can be corrected.
- **Methodological deficiency:** Representation limitation. Prior systems represent the brain's decision as a pose, trajectory or plan token in a robot/world frame fixed at query time: an odometry-compensated polyline [2606.20458], a start-of-call pose increment [2610.28259], waypoints relative to t−Δt [2602.02459]. The only object-anchored representation [2609.31112] needs per-object 3D templates and trained correspondence. So the reconciliation step has no general, training-free binding between the command and the moving entity it refers to, and object displacement during Δ is invisible to it. [2606.20458] states this directly: its fusion handles ego-motion while its simulator lacks scene drift, and DualManip's limitation section names template dependence [2609.31112, Sec V].
- **Why it matters:** The problem's concrete failures (a 4 s call against a box moving at 5 cm/s leaves the grasp 20 cm off; a relative "5 cm left" command lands 5 cm off because the arm moved) are exactly the cases ego-motion-only or symbolic reconciliation cannot fix. Without object-anchored reconciliation, a black-box frontier brain cannot specify targets on moving objects at all unless the system pauses. Closing this decides whether a slow brain can stay the source of spatial targets rather than being relegated to symbolic sub-task selection.
- **Evidence route:** In a non-paused moving-object benchmark, give the same black-box brain outputs to five reconciliation schemes: none, odometry-only re-projection as in [2606.20458], template re-binding where templates exist as in [2609.31112], verify-and-hold as in [2603.19418], and the candidate method. Measure the distance between target and true object pose at execution time and task success, as functions of object speed × Δ. Also report executor idle time. The gap is closed if the target error stays near the Δ=0 level as speed × Δ grows, without per-object templates and without the brain-call count rising.
