
## Axis: execution monitoring with brain-pre-specified local recovery for LLM/VLM-planned manipulation

### What has been done
- **Brain emits monitors, recovery still goes through the brain.** DoReMi [2307.00329] has the LLM emit language constraints with each skill ("robot holds box"), checked by periodic VLM yes/no queries every Δt; any violation aborts the skill and triggers an LLM re-plan. Code-as-Monitor [2412.04455] has GPT-4o write, at each subgoal start, during/at-completion constraints, which a trained segmenter turns into tracked 3D elements; VLM-written monitor code with tolerances (e.g. 15° tilt) returns a boolean, and on False "the policy execution halts immediately" and the reason is fed back for re-planning. Both report execution time, and both save it by detecting failures earlier, not by avoiding the re-plan call.
- **Brain pre-arms recoveries that fire with no brain call (the closest prior work).** AgentChord [2605.11951] (RSS 2026) builds a task graph from (instruction, o_0). For every edge, a recovery agent predicts failure modes, writes each as a scalar monitor over geometric and gripper features (object shift ‖p_t − p̄‖ − δ against the last stable reference p̄; tilt; gripper width; attachment distance; visibility), and attaches forward-moving recovery branches. Online, a persistence-window trigger switches to the pre-compiled branch "without re-invoking full task planning", and a receding-horizon solver re-grounds the recovery geometry from current perception. It reports end-to-end execution time including MLLM inference: 105.6 s, against 128.4 s for its own backtracking variant and 122.4 s for ReKep, over three real tasks. The arming mechanism this axis proposes therefore already exists, with time savings measured. What AgentChord does not do: it arms everything once from o_0 with shared default tolerances, its scenes are static apart from discrete injected disturbances, and it never varies brain latency.
- **Local checks inside LLM-written code.** PyRUA-Lean [2610.01939] lets GPT-6 Astra write cells with conditional checks and local retries over primitive return values, cutting LLM calls from 17.0 to 8.7. It explicitly counts "LLM calls rather than time episodes" because gateway latency varies too much to compare. The checks are ad hoc. They have no expected-event or tolerance representation and run only at primitive boundaries.
- **LLM-authored, retained fallback structure (behavior trees).** BETR-XP-LLM [2409.13356] calls the LLM after a failure to add preconditions that the planner expands into a BT, so the same failure is later handled reactively. SCBT [2610.25455] has an LLM propose grammar-constrained BT patches after failures; CMA-ES tunes them, a bandit decides reuse vs. a new call, and they are crystallized into an LLM-free tree. SCBT measures 31–105 s per frontier proposal, yet "the runner pauses the simulator" during each call, and it models the call's cost as a constant penalty κ in the bandit reward.
- **Learned or library monitors with fixed recoveries.** Tri-System VLA [2603.05185] runs a trained Florence-2 critic asynchronously at ~20 Hz; an anomaly token wakes the Brain to re-plan. CarryOn [2610.21453] runs one shared library recovery skill (re-localize, re-grasp, gripper-width holding checks) whenever a Judge flags a subtask failure, and refines that skill offline between rounds. Neither arms corrections per stage from the planner.
- **Failure reasoning and detection quality.** REFLECT [2306.15724] and AHA [2410.00371] are post-hoc (post-sub-task) LLM/VLM judges whose explanations feed a new LLM plan. REFLECT assumes the environment stays static. FailBench [2609.03611] finds the best VLM judge at 0.77 balanced accuracy, near chance when success hinges on whether contact was established (≤0.60 on contact-rich assembly), while "which object moved" events are reliable. RESCUE [2610.13516] shows monitor alarms often land after the recoverability horizon, and that routing alarms to a cheap scripted Recover instead of stop-and-reset cuts excess cost 3.1–13.4×. Recoverability depends on the intervention repertoire.
- **Recency trail (since 2025-10-01).** Queries run: "proactive failure recovery manipulation", "anticipatory recovery branches", "LLM behavior tree recovery", "contingency LLM robot", "anticipated failures robot LLM", "runtime monitor VLA", "failure detection VLM robot recovery", "event-triggered replanning VLM manipulation", "frontier model latency robot real time". The only work that pre-arms recoveries from the planner is AgentChord. The other hits are VLA-internal monitors, rollback (SafeLoop), or post-hoc judges. **No read or retrieved work measures success or time saved by avoiding brain re-calls as a function of brain latency in a world that keeps moving during the call.** That empirical absence alone is not a method gap; the method gaps it exposes are below.

### Open gaps on this axis
- **Gap:** Planner-armed recovery methods arm monitors once against a static snapshot. AgentChord compiles all branches from o_0, uses a static reference p̄ and shared default tolerances; CaM generates monitor code per subgoal from the current image. Such a monitor has no model of how the world and the arm are expected to evolve over a stage or during a seconds-long brain call. Expected motion (a conveyor object, arm drift while the brain thinks) is therefore indistinguishable from failure, and expected events (contact, grasp-hold, object-moved) carry no timing. In real-time manipulation with moving objects, a pre-armed reflex would either fire falsely or stay silent.
  - **Near-miss methods and coverage:** [2605.11951] is the closest. It pre-arms per-edge failure monitors and forward-moving recovery branches that fire with no MLLM call, but its shift monitor is ‖p_t − p̄‖ − δ with p̄ "the last stable estimate at node v^i or ... expected in-hand pose", all branches come from o_0, tolerances are shared defaults, and its scenes are static apart from discrete disturbances. [2412.04455] regenerates monitor code at each subgoal and halts plus re-plans on violation, with thresholds from a knowledge base and threshold sensitivity "unexplored". [2307.00329] uses binary VQA predicates with no tolerance or timing. [2306.15724] states that it assumes the environment stays static. All four share the deficiency that the monitor's nominal model is a time-invariant predicate over the current or initial state. Recency queries ("anticipatory recovery branches", "event-triggered replanning VLM manipulation", "contingency LLM robot") turned up no planner-armed monitor with a time-indexed expectation.
  - **Methodological deficiency:** This is a representation limitation. The brain-to-monitor interface is a static constraint c(z) ≤ 0 with fixed tolerance, not a time-indexed expectation (event, expected time window, expected state trajectory, tolerance band) conditioned on the stage's motion. The monitor cannot tell expected change from failure, and it cannot recognize that an expected event has not happened by its deadline (missed contact, no object motion). The second case is exactly the contact-type event that FailBench [2609.03611] shows VLM judges cannot reliably detect after the fact (≤0.60 balanced accuracy).
  - **Why it matters:** Systems with a slow frontier brain over a fast executor cannot run pre-armed reflexes in dynamic scenes or while the brain is mid-call. Every deviation then becomes either a false alarm or a brain re-call, which brings back the multi-second latency that pre-arming was meant to remove. Closing this gap would extend latency-free local recovery from static tabletop scenes to moving objects and targets.
  - **Evidence route:** Run real-time sims (no pause during brain calls) with moving objects and swept brain latency Δ. Compare false-alarm rate, missed-event rate, recovery success, and wall-clock time between static-snapshot monitors (AgentChord/CaM-style) and any monitor whose expectations are time-indexed. Isolate cases where the object moves as expected versus cases where it is perturbed.
- **Gap:** Methods that trade brain re-calls for local structure treat the cost of a brain call as latency-independent: tokens or calls in PyRUA-Lean, a constant penalty κ with the simulator paused in SCBT, serial summed execution time in AgentChord. The choice of which corrections to pre-arm locally and which to escalate to the brain therefore ignores the fact that the state degrades during the call. Real-time manipulation turns a correct but late brain decision into a failure once Δ exceeds the failure's recoverability horizon.
  - **Near-miss methods and coverage:** [2610.25455] learns with a contextual bandit when to reuse a stored patch versus CallLLM, but CallLLM "always pays κ" and the live episode is paused during each 31–105 s call. [2610.01939] cuts LLM calls with local checks and retries but explicitly does not time episodes. [2605.11951] arms every predicted failure mode uniformly and evaluates only summed time in static scenes. [2610.13516] shows that intervention value depends on the alarm landing before the recoverability horizon, and that cheap scripted recovery beats stop-and-reset by 3.1–13.4×, but it models no planner latency. The shared deficiency in [2610.25455], [2610.01939] and [2605.11951] is that the escalation and arming rule does not depend on Δ relative to the time-to-unrecoverability of the specific failure.
  - **Methodological deficiency:** This is a credit-assignment and objective mismatch. The arming and escalation decision is optimized against token cost, call count, or a constant per-call penalty, not against the latency-dependent loss in recoverability during the brain call. The methods have no mechanism for deciding that one failure mode must be handled by a pre-armed reflex because its recoverability window is shorter than Δ, while another can safely wait for the brain.
  - **Why it matters:** Without such a rule, pre-arming is either exhaustive (expensive upfront brain reasoning, and more false triggers as RESCUE's false-alarm break-even shows) or arbitrary. No method can say which corrections need a local reflex at a given brain latency. That knowledge is what would let a system use the frontier model less without losing time-critical recoveries.
  - **Evidence route:** Inject failures with known recoverability horizons (RESCUE-style counterfactual branching) under real-time execution and a sweep of Δ. Measure success and wall-clock time when arming is latency-blind (all modes or none) versus latency-aware. The crossover where brain escalation stops succeeding should track Δ against the horizon.
