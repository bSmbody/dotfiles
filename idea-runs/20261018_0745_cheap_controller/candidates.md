### C1 — Seed-keyed counterfactual replay: make the VLA's noise exogenous so the culpable controller decision becomes identifiable

- **Intuition**: In simulation, the only chance in a flow-matching VLA's execution is the noise it draws for each action chunk. If that noise is keyed to "which sub-task, which chunk of it" rather than drawn from one running random stream, a failed student episode becomes a replayable world. Swapping one controller decision while all execution noise stays fixed then answers the "but-for" question: would this episode have succeeded had the controller decided differently here? Repeating that paired replay under a few noise draws separates controller-caused failures (the outcome flips when the decision is swapped) from execution-caused ones (the episode fails either way). The frontier teacher is then called only at decisions the replays have already shown to be culpable, which restores WebKD-style "localize the first fatal step, then rewrite" distillation to a stochastic VLA executor.

- **Gap it attacks**: Axis "distilling frontier-model controller traces into small embodied controllers", Gap 1. On-policy black-box correction [2610.19834, 2609.09134] finds the first fatal step by reading or replaying a deterministic trajectory. WebKD's unique-first-fatal-step result and its state re-rendering both assume "deterministic transitions and parsing" [2610.19834]. With a VLA in the loop, the same "advance to the drawer" decision succeeds in one run and fails in the next, so controller error and execution error are entangled. Embodied controller training therefore falls back to supervision at demonstration states only [2609.20791, 2502.19417] or to a single binary reward spread over the whole episode, where VLA run-to-run variance confounds attribution [2610.01939]. Closing this gap would let a ≤8B controller be corrected at exactly the states it drives the robot into (e.g. the premature move to the drawer after the first bowl), spending frontier calls only on mistakes that are really the controller's. Beyond this problem, it would give a general rule for blaming a planner when the executor beneath it is a stochastic learned policy.

- **Source inspiration**: Three ideas, all from outside embodied learning.
  (1) **Counterfactuals as replay with fixed exogenous noise** [1905.05824]. Oberst & Sontag treat an episodic POMDP as a structural causal model. A counterfactual trajectory is "a deterministic function of the exogenous U variables": recover the noise that produced the observed episode, change the policy, and re-run with the same noise. This decomposes a policy-value gap into per-episode but-for outcome differences, which they use to flag the episodes where a different policy would have changed the result. Their hard part is that the noise must be inferred, and inferring it is non-identifiable under stochastic transitions. They need an untestable stability assumption to fix it.
  (2) **Event-keyed common random numbers** [2603.11084]. In simulators, "same seed" pairing is causally valid only if each modeled event receives the same noise in both worlds. A single stateful random stream breaks this whenever the intervention changes the execution path, because every later draw shifts by one position (Prop 1 / Corollary 3.1). Counter-based generators keyed by a stable event identifier fix it. A placebo replay, which must reproduce the baseline outcome, tests whether the coupling is valid.
  (3) **Safe coupling and reset-based credit** [2605.04732, 2410.01679, 2609.35215]. Sharing random numbers between two compared policies can raise variance in general. Sampling independently while the policies differ and sharing noise once they agree provably never does worse than independent sampling, and does strictly better when the shared suffix is random [2605.04732, Theorem 2]. VinePPO and ASCT show that when an environment can be reset to an intermediate state, a few rollouts from the agent's own visited states give per-step credit that learned critics cannot match [2410.01679]. Evaluating alternative actions there beats state-value credit [2609.35215]. But both use independent random streams and environments that are recoverable by construction.
  Novelty type: **recombination-of-distant-concepts**. SCM counterfactuals and simulation CRN are combined with on-policy teacher-rewrite distillation, a combination that the setting makes uniquely clean: unlike in [1905.05824], the noise does not have to be inferred, because we drew it ourselves.

- **How it maps to this problem**:
  - The **exogenous noise U** is the VLA's per-chunk initial Gaussian noise. For π0, executing a sub-task means integrating a learned vector field from a sampled Gaussian start with a fixed Euler rule, so given the observation this draw is the only random input [2410.24164]. Together with a restorable simulator state, the whole controller–VLA–simulator loop becomes a deterministic function of (start state, controller decisions, noise).
  - The **event key** is the identity of an execution event that is "the same" across worlds: a given sub-task instance and the chunk index within it. If a swap changes the plan ("pick up the second bowl" instead of "close the drawer"), the shared drawer-closing chunks that follow still receive the same noise, instead of every draw shifting by one position as with a single stream [2603.11084].
  - The **intervention** is a swap of one controller decision at a snapshot taken at that decision point, after which the same student controller continues. This has exactly the "differ at one step, agree afterwards" structure for which shared noise is provably safe [2605.04732].
  - The **but-for test** is defined per noise draw: did the swap flip failure to success? Across a handful of draws, the flip rate estimates how necessary that decision was for the failure. The first decision with a high flip rate is the embodied analogue of WebKD's first fatal step, now well defined under stochastic execution. Decisions whose swaps never flip the outcome mark execution failures, and those are not used to train the controller's judgement.
  - **Where swaps come from**: a controller's options at a decision point are few and structured (continue the current sub-task, retry it, advance, or issue the student's own next-best sub-task). So candidate swaps come from the student itself, and replays cost only local VLA GPU time; π0 needs 73 ms per chunk on an RTX 4090 [2410.24164]. When a student-proposed swap already flips the outcome, the replay itself gives a verified correction with no API call. The frontier teacher is called only at decisions that were found culpable but where no cheap swap fixed the episode, and there it rewrites the decision and the suffix in the student's style, as in [2610.19834]. Flip rates also weight how strongly each corrected decision is trained, in place of a whole-episode reward.

- **Why it could work / feasibility**: The mechanism needs three conditions, and each is supported or checkable.
  (a) **The randomness is controllable.** In flow-matching VLAs, sampling enters only through the initial noise of each chunk [2410.24164]. Simulators can be snapshotted and restored, the same resettability that makes MC credit unbiased and cheap in VinePPO [2410.01679], where small numbers of rollouts per state already work.
  (b) **The coupling is valid.** [2603.11084] says event-keyed noise gives causally coherent pairs and supplies a direct check: replaying with the identical decision must reproduce the original outcome.
  (c) **Pairing reduces variance.** Variance falls through the covariance the shared suffix induces. Under the "differ then agree" structure, the paired estimate is never worse than independent sampling [2605.04732]. ASCT's evidence that evaluating alternative actions at the actor's own states beats state-value credit [2609.35215] suggests decision-level comparisons are the right unit.
  On the distillation side, WebKD shows that rewriting from the localized failing step in the student's own style beats behaviour cloning and teacher takeover, and that without an external signal "the student cannot reliably tell which of its own decisions were wrong" [2610.19834]. The paired replay supplies that signal without spending API calls on localization.
  The key assumption is that, for the same noise keys, VLA execution of a shared sub-task stays correlated enough across the two worlds to make flips informative. This also requires the simulator step and the VLA forward pass to be run deterministically, which the placebo replay tests directly.

- **Novelty vs. closest in-domain work**: WebKD [2610.19834] has the frontier teacher read a failed rollout to localize the first fatal step and replays it in a deterministic container, which it assumes. C1 instead manufactures determinism by keying the VLA's execution noise and localizes the culpable decision with noise-matched counterfactual replays, not teacher judgement. It therefore applies when the executor is stochastic, and it spends teacher calls only after localization. Against the embodied on-policy alternative, PyRUA-Lean Coder [2610.01939] uses an episode-level binary reward. Against reset-based credit methods [2410.01679, 2609.35215], those are text-only, use independent random streams, and do not separate the agent's error from an executor's.

- **Main risk**: Swapping a controller decision changes the images and language the VLA conditions on, so even with identical noise keys the two worlds' executions may decorrelate quickly. Then flips reflect execution luck almost as much as with independent seeds, and localization needs many more replays per decision than the GPU budget allows.


### C2 — Luck-adjusted blame: treat the VLA as poker's "chance player", and call the teacher only for losses a controller decision made final

- **Intuition**: Score each failed episode the way poker analysts score a hand: subtract the VLA's luck, meaning how much better or worse each sub-task execution went than this executor usually does from that progress state with that command. What remains is the controller's own contribution, and it includes bad phrasings and premature "done" calls. The frontier teacher is then called only at the decision that made the loss final, and only when the student's own alternatives cannot fix it. Execution-luck failures cost no API call and no penalty.

- **Gap it attacks**: Axis "distilling frontier-model controller traces into small embodied controllers", Gap 1. On-policy correction finds the failing decision by reading or replaying a trajectory, which presumes deterministic transitions [2610.19834, 2609.35303]. Above a stochastic VLA, a failure can come from the controller or from the executor. The embodied fallbacks are off-policy demonstration labels [2609.20791, 2502.19417] and one binary reward per episode, where "a VLA succeeds in one run and fails in the other" [2610.01939]. The one embodied method that turns failures into controller corrections calls an LLM coach on every failed stage, and 45% of its proposals do not survive re-execution [2609.20056]. The waste is structural. In LADDER's audit of subgoals lost on SimplerEnv-Long, an orchestrator decision made the loss final for 47.8 of 60.1 points under a periodic trigger. Under a verifying orchestrator the figure is 4.0 of 49.0 points, and the rest are lost while the robot carries out a correct command [2610.18053]. So the more a controller improves, the more of a failure-triggered teacher's budget goes to diagnosing VLA misses. Closing the gap would let a ≤8B controller be corrected at its own states, such as the premature move to the drawer, with a frontier budget that scales with the controller's mistakes rather than with the executor's error rate.

- **If improving prior candidate**: C1's headline mechanism was keyed VLA noise (CRN) to make blame identifiable. That is PEGASUS-era practice [1301.3878], CAR names it as its next step [2606.08275], and it buys nothing in the canonical culpable case. C2 drops noise coupling entirely: every rollout and re-execution uses fresh VLA noise. Blame now comes from a chance-node decomposition fitted on pooled rollouts, not from paired replays. C1's localization rule ("first decision with a high flip rate") is replaced by a commitment rule: the latest decision at which the task was still recoverable and whose own controller term carried the collapse. This combines CAR's latest-significant-step rule [2606.08275], LADDER's "decision that made the loss final" [2610.18053] and WebKD's recoverability definition [2610.19834], made probabilistic as PIVOT's limitations ask for continuous control [2609.35303]. The contribution is re-centred on what C1's review found genuinely new: separating controller failures from execution failures above a stochastic executor, and using that separation to gate frontier calls. C2 also commits to an effect size.

- **Source inspiration**: **AIVAT** from computer-poker agent evaluation [1612.06915]. Poker results are dominated by the cards, so a player's skill is invisible in raw winnings. AIVAT adds a correction at every chance event: the value expected before the card falls, averaged over the known card distribution, minus the value after the card that actually fell. Summed over the hand, these terms remove the luck and leave the contribution of the evaluated player's decisions. Two properties carry over. First, the corrections have exactly zero mean for any value function, so the estimate stays unbiased even with a crude heuristic. Only the chance probabilities must be right [Lemma 1, Theorem 1]. Second, a crude value model from a tiny abstraction of the game still cut the standard deviation by 68%, about ten times fewer hands for the same conclusion [Sec No-limit Texas Hold'em, Conclusions]. Within RL, counterfactual Shapley credit also separates skill from luck, but only by counterfactually re-simulating a single agent's trajectories on toy MDPs [2607.16999]. AIVAT's form fits a two-level stack better: an executor whose outcomes are chance events, and a decision-maker whose share is whatever is left. Novelty type: **recombination-of-distant-concepts** (poker luck-adjustment × on-policy teacher-rewrite distillation × hierarchical VLA control).

- **How it maps to this problem**:
  - **Chance player = the VLA.** Each sub-task execution is one chance event. Its outcome is what happened to the task's sub-goal predicates: achieved, not achieved, or an earlier one undone. In simulation, these predicates are read from the simulator during training only, as LADDER and LIBERO-style suites expose them [2610.18053]. The controller never sees them at test time.
  - **Chance probabilities = the executor's reliability**, estimated from the student's own pooled rollouts. Every episode contains many executions, so for each progress state (which sub-goals hold) and each kind of command, we know how often this VLA achieves the targeted predicate. To keep an episode from scoring its own luck, its table is estimated from other episodes.
  - **Value function = chance of finishing from a progress state** with the current student and VLA, estimated in the same pooled way. AIVAT tolerates a crude estimate here.
  - **The split.** An episode's outcome decomposes into executor-luck terms (each execution's realized value minus its expected value) and controller terms (how much each decision moved the expected value). The controller terms carry everything the controller could have predicted. Commanding a sub-task in a phrasing this VLA rarely executes, or one it has already completed, lowers expected value, so it is blamed on the controller. Advancing to the drawer while a bowl predicate is still false is blamed the same way. A VLA miss on a well-chosen, well-phrased command is luck. So is a retry that the VLA then fumbles. Neither is charged to the controller.
  - **Where to look = the commitment decision**: the latest decision at which finishing was still reasonably likely and whose controller term carried the collapse in value. If the collapse is carried by luck terms, the episode is an execution failure. It triggers no teacher call and, unlike in episode-reward GRPO [2610.01939], puts no negative pressure on the controller's decisions.
  - **Who fixes it, cheapest first.** At the commitment state, the student's own next-best decisions that the value table already rates high (e.g. "pick up the other bowl") are re-executed a few times from a simulator snapshot with fresh noise on the local GPU. A verified one becomes the training target with no API call. Only if none verifies is the frontier teacher called once, at that state. It rewrites the decision and a one-line state description in the student's style, as in WebKD [2610.19834], and the rewrite is trained on only if re-execution confirms it, as in MAGMA-GEN [2609.20056]. The luck-adjusted score also replaces the raw 0/1 outcome as the weight on all other on-policy decisions.

- **Why it could work / feasibility**:
  (a) **The chance structure is explicit.** In a controller-over-VLA stack, the only stochastic step between two controller decisions is one VLA execution. Its outcome is summarized by a handful of discrete predicates, which LADDER uses to assign every lost subgoal to an orchestrator decision or a physical cause [2610.18053]. That is the "known chance node" layout AIVAT needs. The executor tables are small (progress states × command kinds), and executions are plentiful.
  (b) **Unbiasedness does not depend on the value model** [1612.06915, Lemma 1]. This answers the VinePPO objection that learned critics are near chance [2410.01679], because a bad value model only costs variance reduction. The value model here is also a pooled table over symbolic progress states, not a neural critic over images.
  (c) **Snapshot re-execution is used only for verification.** It runs on a few candidate fixes per controller-blamed episode, not on every decision as in VinePPO and ASCT [2410.01679, 2609.35215]. MAGMA-GEN shows such verification is necessary: CSR 16.8 vs 8.2 without it [2609.20056]. π0-class execution costs 73 ms per chunk on an RTX 4090 [2410.24164].
  (d) **Teacher calls are where the leverage is.** Student self-edits fail without an external signal [2610.19834], and teacher hints add only 0.3-3.5 points once the right state is restored [2609.35303]. So the scarce resource is the right state, not more teacher text. A GPT-6-Astra call costs about $0.04 [2610.17350], so even 2,000 gated calls stay within budget.
  **Committed effect (the paper stands or falls on this).** Take a LADDER multi-subgoal suite or LIBERO-Long, a frozen π0.5 executor, a Qwen3-VL-8B controller, and an equal number of frontier calls (~1,500). Each method's calls go to the following:
  1. **Triage precision.** At least 75% of luck-adjusted calls land on failures that LADDER's forensic audit attributes to an orchestrator decision. Calls triggered by every failure land there at the audit's base rate. That rate is expected to be ≤ 45% and to fall during training as the student stops making orchestrator mistakes.
  2. **Success against the baselines.** Multi-subgoal success beats failure-triggered on-policy correction (MAGMA-GEN/WebKD-style) by ≥ 8 points absolute, off-policy trace SFT by ≥ 12 points, and binary-outcome GRPO at equal rollouts by ≥ 10 points.
  3. **Calls needed.** C2 matches off-policy SFT's success with ≤ 1/3 of its calls.
  4. **The canonical error.** "Moved on before done" losses are cut by at least half.
  Key assumption: the executor's reliability depends mainly on the progress state and the command, not on unlogged scene details. Otherwise the controller's systematic choices leak into "luck".

- **Novelty vs. closest in-domain work**: MAGMA-GEN [2609.20056] is the closest. It disambiguates decision errors from execution failures in hierarchical manipulation, but by calling a 20B coach on every failed stage (3,585 calls for 180 tasks) above scripted skills with injected noise. C2 instead estimates the controller-vs-executor split from pooled rollouts before any call, gates a frontier API on it, and handles a learned VLA executor whose reliability depends on the controller's phrasing. Against the others:
  - PIVOT [2609.35303] needs deterministic feasibility certificates.
  - CAR [2606.08275] is an attribution tool with no executor/agent split and no training.
  - Counterfactual Shapley credit [2607.16999] and LENS-OPD [2609.33409] are single-agent or text-only, and LENS-OPD queries its white-box teacher densely.
  - LADDER [2610.18053] uses a hand-written, post-hoc audit for evaluation, which C2 uses as its yardstick.

- **Main risk**: Unlike poker cards, the VLA's outcome probabilities are estimated, not known. If execution success depends strongly on continuous scene details outside the progress state, the correction terms are no longer zero-mean given the controller's choice. For example, the controller may choose to grasp the occluded bowl first. Controller mistakes then get written off as luck, and teacher calls are under-triggered.
