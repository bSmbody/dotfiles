# Where Memory Belongs: Ledger, an Object Ledger for Memory-Augmented VLAs

## What this paper does
Ledger splits memory for a single fine-tuned pi0.5: short-term perceptual memory (32 sampled past frames modulating the action expert via FiLM-style cross-attention) stays inside the policy, while long-term object memory lives outside as an explicit ledger built from SAM3 tracks (per-object positions, stationary intervals, cover timestamps) plus a Qwen3-VL-30B transcript of the demonstration. A frontier LLM planner (Claude Sonnet 5) reads the ledger, one annotated frame and an execution log at each step boundary and either grounds a templated subgoal with a coordinate target or defers with an empty subgoal. On RoboMME it reaches 64.3% vs 45.9% for the best prior method.

## Goal-by-goal answers
### Goal: What mechanism does it use for task-state tracking and step-completion judgement?
State = tracker-derived ledger L_t (Eq 1) + action transcript + an execution log of completed steps with timestamps, read by the planner at step boundaries [full text, Sec 3.2, 3.4]. Step completion "is determined entirely from robot proprioception rather than visual trackers or VLM evaluators": gripper aperture regimes shut/hold/open; a grasp = entering hold, a release = hold->open, a press = reach-and-retreat with gripper shut [Sec 3.4]. So a step is logged complete when the gripper event occurs, not when the intended outcome is verified.
### Goal: What failure of state tracking does it report when the planner re-decides?
Re-deciding from scratch after each step lifts PlaceButton 58->66 and UnmaskSwap 68->86 but drops Repick 60->28: "without a record of its own earlier decisions, the planner re-attributes completed repetitions to the remaining goal and miscounts"; carrying the remaining plan across decisions and counting repetitions from the execution log restores Repick to 54 [Sec 4.2, Table 2]. Counting is done "from confirmed step completions" (i.e. proprioceptive events) on BinFill/PickXtimes [Sec 4.2].
### Goal: What limitations does it report on this axis, and what controller does it need?
The planner is a frontier model (Claude Sonnet 5), queried 2.7 times per episode on average [Sec 3.4, App B]. Action transcripts introduce errors: VideoPlaceOrder 64% vs 100% oracle "as temporal event semantics cannot be verified via geometry alone" [Sec 5]. On Object/Reference tasks the ledger reaches 60.7% vs 95.2% oracle; given a correct target the policy executes well, so "what remains is resolving what to act on and when" [Sec 4.2]. Grounding a target where the policy should defer costs 15 points on MoveCube [Sec 4.2].
