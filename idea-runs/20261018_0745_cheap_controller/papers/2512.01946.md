# Guardian: Detecting Robotic Planning and Execution Errors with Vision-Language Models

## What this paper does
Guardian builds GuardianFail-36k by perturbing successful RLBench trajectories (no gripper close, wrong placement, wrong object, imprecise grasp) and, for BridgeDataV2 real data, by perturbing only the paired subtask text or replacing the end image with the start image; a VLM writes step-by-step reasoning traces for each example. It LoRA-fine-tunes InternVL3-8B (frozen vision encoder, each view encoded separately) to answer, with CoT, whether a plan is valid and whether a subtask succeeded from pre/post multi-view images. Integrated into 3D-LOTUS++ as a per-step verifier with up to 3 retries.

## Goal-by-goal answers
### Goal: What mechanism does it use for sub-task success judgement?
Binary VQA: VLM_exec(I_start, I_end, T, P_i) -> {0,1} with a CoT before the answer [full text, Sec 4.1 Eq 2, Sec 4.2]. Per-subtask, stateless: only the pre- and post-action images of that subtask and the task/subtask text; no persistent task state across subtasks [Sec 4.1]. Thinking mode 0.83 exec accuracy at 4.3 s/sample vs vanilla 0.80 at 0.68 s [Table 4].
### Goal: Where does its failure training data come from, and does it cover the states a deployed controller produces?
Simulated failures are synthesized by perturbing subtask-level actions of successful trajectories; real failures are derived from successful demonstrations by altering the instruction text or swapping the end image for the start image ("revert action") [Sec 3.2]. Only the UR5-Fail evaluation set uses autonomous policy rollouts (3D-LOTUS++, manual labels) [Sec 3.4]. Single-source training transfers weakly across sim and real; combining sources and scaling data helps [Sec 5.3].
### Goal: What does it report as its limitations on success judgement?
Recall on failures (76%) is below recall on successes (91%) [App B]. Missed failures are concentrated in semantic categories such as wrong object state/placement [App B]. Misclassifications are dominated by perception errors (75%, 68%, 93% on UR5-Fail, RoboFail, RoboVQA) rather than reasoning [App C, Table 8]. Off-the-shelf InternVL3-8B as verifier "damages the base robot policy performance in nominal cases" (e.g. put food 15/20 -> 12/20) [Sec 5.6, Table 7]. Downstream RLBench success 0.45 -> 0.54 [Sec 5.6].
