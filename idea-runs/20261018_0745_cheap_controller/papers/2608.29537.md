# AGM: Achievement-Grounded Memory for Closed-Loop Agents with Frozen VLA Policies

## What this paper does
AGM wraps a frozen subgoal-conditioned pi0.5 with a fixed, instruction-expanded subgoal list and a single progress pointer. The pointer is written only after a gripper-load state machine detects a grasp or release event and a verifier confirms the physical achievement: CoTracker3 coherent-lift test for grasps, and a 2.43M-parameter head over frozen SigLIP front/wrist before-after embeddings conditioned on the subgoal text for placements. Verified success advances, a rejected grasp retains, a rejected recoverable placement rolls back. On RoboMME Counting it reaches 100% PickXTimes and 84% BinFill, beating LoRA-tuned Qwen3-VL-4B subgoal controllers and MemER; no autoregressive VLM is used at deployment.

## Goal-by-goal answers
### Goal: What mechanism does it use for task-state tracking and sub-task success judgement?
State = (fixed subgoal sequence G with type labels, pointer p_t) [full text, Sec 3.1, Eq 1-2]. G comes from a deterministic expansion of the instruction (benchmark decomposition, cross-checked with an instruction-only parser) [Sec 3.1]. Success is judged only at detected gripper events (Eq 3), by type-specific verifiers and thresholds (Eq 12), and the pointer transition (Eq 13) advances / retains / rolls back. Non-recoverable container placements get a permissive threshold and bounded rejections; a final occupancy recheck precedes termination [Sec 3.3].
### Goal: What failure mode of attempt-based / unverified progress tracking does it document?
"A progress memory that advances after every attempt can perform worse than no progress memory at all"; a transient grasp/placement failure written as progress becomes a persistent task-state error [Sec 1]. Controlled: same policy and pointer, PickXTimes 100% with verified writes vs 32% attempt-based vs 36% whole instruction [App C.2, Table 10]. Frozen pi0.5 alone collapses from 100% at N=1 to 0% at N=5 [Sec 4.3, Table 2]. LoRA-tuned Qwen3-VL-4B SimpleSG controller: 95.3 / 77.6 on PickXTimes/BinFill but 5.1 / 0.4 on SwingXTimes / StopCube [Table 1].
### Goal: How is the verifier trained, and on which state distribution?
788 execution events from the RoboMME training split, collected from two controllers: AGM itself ("covering the deployment distribution") and an attempt-based controller that "supplies the missed grasps, misplaced objects, and incorrect progressions scarce in planner-generated demonstrations"; labels come from environment predicates (lift, containment, container count) that are unavailable at test [Sec 3.4]. Verification timing must match deployment: a 20-frame mismatch in the post-release window substantially degrades results [Sec 3.4, App B.4].
### Goal: What does it report as its limitation on this axis?
Verification vocabulary is "anchored to gripper interactions"; subgoals not tied to grasp/release (SwingXTimes, StopCube) are delegated to the frozen policy with no gain (35.56 / 6.67) [Table 1, Sec 5]. The head "has no reliable discrimination on container placement" [App C.2]. The subgoal sequence is fixed per episode and not chosen online, so AGM does no re-planning beyond pointer rollback [Sec 3.1].
