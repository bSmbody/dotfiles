# Hi Robot: Open-Ended Instruction Following with Hierarchical Vision-Language-Action Models

## What this paper does
Hi Robot splits control into a high-level PaliGemma-3B VLM that maps images plus an open-ended prompt to a short low-level language command, and a pi0 VLA that executes it. The high-level policy is trained by next-token cross-entropy on teleoperated demonstrations segmented into 1-3 s skill labels, plus synthetic user prompts/interjections and robot utterances that a large VLM generates conditioned on each labelled segment. High-level inference reruns every second or on user input. Evaluated on real UR5e, bimanual ARX and mobile ARX tasks against a GPT-4o high-level policy and a flat VLA.

## Goal-by-goal answers
### Goal: How is the small high-level controller trained from large-model outputs, and on which state distribution?
The large VLM p^gen is used offline only, to imagine user prompts l_t and utterances u_t that "might have led to" an existing human skill label; the controller is SFT'd on D_syn ∪ D_labeled with cross-entropy [full text, Sec 4.3]. All states are from teleoperated demonstrations; no rollouts of the hierarchical system, no failure states, and no correction of the controller at states it drives the robot into [Sec 4.3]. The large model never acts as a controller teacher on robot states; it only augments language.
### Goal: How does it track task state and decide when a sub-task is done?
It does not track state explicitly: high-level inference is re-run on the current images every second, regardless of whether the command finished, with "intelligent strategies where the system detects when the command has been completed" left unexplored [Sec 4.1]. Listed high-level failure: "Difficulty with instructions requiring long-context reasoning, since the current system lacks memory" [App C.4].
### Goal: What does it report as its limitation on controller–VLA coupling and failure coverage?
"The training process decouples the high-level and low-level models, and they are not aware of one another's capabilities except through the training examples"; coupling so the high-level policy knows "how successfully the low-level policy completes each command" is future work [Sec 6]. Low-level error accumulation and OOD recovery (dropped objects) are failure modes; suggested mitigations are adversarial edge-case data and "diverse data collection including failure recovery and annotation" [App C.4]. GPT-4o as controller "often fails to maintain a coherent internal state", e.g. picking new objects with an occupied gripper or prematurely switching tasks [Sec 5.3].
