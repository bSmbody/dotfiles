# Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

## What this paper does
PyRUA-Lean is a code-execution interface in which a frontier planner (GPT-6 Astra) composes robot primitives, including frozen VLA policies, into Python cells that check and retry locally and return only requested images/state. On 700 instances (LIBERO-PRO, RoboTwin 2.0, RoboCasa365) it lifts success 63.1% to 71.7% over tool calling. Section 5 trains an open Qwen3.5-4B planner (PyRUA-Lean Coder) with outcome-reward GRPO on 45 LIBERO-PRO instances, raising unseen-instance success 18.8% to 44.1% versus 69.8% for GPT-6 Astra.

## Goal-by-goal answers
### Goal: How is the small open controller trained, and is the frontier model used as a teacher?
GRPO from base weights with reward 1 iff the benchmark success check passes, no shaping, "no supervised stage and no demonstration data"; 16 instances x 8 rollouts per iteration, 30 iterations (3,840 episodes), full fine-tuning on one 8-GPU node for ~12 h [full text, Sec 5.1, App J]. The frontier model is never used to supervise the student; it is only a reference row [Table 8].
### Goal: What did the small controller learn, and what did it not learn, on long-horizon / state-judging behaviour?
Training changed interface usage: one code cell per LLM call instead of 9.0, and images requested per episode fell from 19.3 to 0.8; cell-budget and context-overflow endings dropped but "gave up" endings rose to 25.2% and wall-clock endings to 16.8% [Sec 5.3, Table 9]. On RoboCasa365 composite (long-horizon) tasks it reaches only 19.4% vs 39.4% for GPT-6 Astra, the smallest relative gain (12.5 to 19.4) [Table 8]. Authors: "We do not claim that training improved manipulation skill as such" and the model "remains far below the frontier model on the same tasks" [Sec 5.3, Sec 6].
### Goal: What does it report as limitations of the training recipe?
"One model size and one training run, on 45 instances of one benchmark and with success as the only reward" [Sec 6]. Frontier-side: some success differences come from VLA run-to-run variance ("a VLA succeeds in one run and fails in the other"), so success cannot be attributed entirely to planner logic [Sec 3.8].
