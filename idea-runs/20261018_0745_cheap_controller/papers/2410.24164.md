# π0: A Vision-Language-Action Flow Model for General Robot Control

## What this paper does
π0 builds a VLA on a PaliGemma VLM plus a ~300M action expert that generates H-step action chunks by flow matching. It is pre-trained on a large multi-robot mixture and post-trained per task, executes chunks open-loop, and can take language sub-task commands from a high-level VLM policy that decomposes long tasks (SayCan-style). Evaluations cover zero-shot tasks, language following, fine-tuning to new skills, and multi-stage tasks such as laundry folding and table bussing.

## Goal-by-goal answers
### Goal: Where does randomness enter π0's action generation at inference time, and is the rest deterministic?
At inference actions are generated "by integrating the learned vector field from tau=0 to tau=1, starting with random noise A^0 ~ N(0, I)" using forward Euler with 10 steps [full text, Sec IV, integration rule after Eq 1]. So, given the observation, the per-chunk initial Gaussian noise is the only sampled input; the integration itself is a deterministic computation (numerical GPU nondeterminism is not discussed). Each new chunk requires a fresh noise draw [App A-D].
### Goal: What does one VLA call cost, and how often is it called?
On an RTX 4090: image encoders 14 ms, observation forward 32 ms, 10 flow steps 27 ms, 73 ms on-board in total [App A-D, Table I]. Chunks are executed open-loop; inference runs every 0.8 s (16 actions) on 20 Hz arms and every 0.5 s on 50 Hz robots; temporal ensembling hurt and was not used [App A-D].
### Goal: How does π0 interface with a high-level controller?
Because it is trained on language inputs, a high-level VLM can decompose tasks like "bus the table" into sub-tasks ("pick up the napkin") that π0 executes, analogous to SayCan [Sec V-B]; this is used for several multi-stage tasks [Sec VI].
