# Can a Frontier VLM Serve as a Robot Policy for Memory-Dependent Manipulation?

## What this paper does
Uses frozen GPT-6-Astra directly as a waypoint policy on all 16 RoboMME memory-dependent tasks: the whole episode (goal, task video, front frames at stride 3, wrist frame, its own previous answers with free-text descriptions) stays in one chained API conversation, and it outputs end-effector waypoints plus gripper commands. It reaches 92.1% on 800 test episodes, audits all 63 failures, and separately evaluates the model in RoboMME's oracle-planner (skill + image point) setting against GPT-4o, Gemini-2.5-Pro and Qwen3-VL-32B.

## Goal-by-goal answers
### Goal: How does the frontier controller keep task state, and what does that cost?
No explicit state structure: it conditions on all subsampled observations and its own previous responses y_j, which "include a free-text description of what happened" [full text, Sec 3, Eq 2]. 9.5 calls per episode, 18.3 s per call, median 148 images and 16.5k input tokens in the final request, $309 total ($0.39/episode); "a capability baseline, not a real-time controller" [Sec 4, Resources].
### Goal: What are its failure modes on completion judgement?
25 of 63 failures are premature completion: the model declared the task complete before the environment judged success; 23 in MoveCube push variants, where success requires an open gripper, and in all 23 the last gripper command was close [Sec 5, Premature completion]. Stated arrivals in button tasks were "not checked against the cube's state" [Sec 5].
### Goal: How do smaller / open VLMs compare as high-level planners on the same benchmark?
In the oracle-planner setting GPT-6-Astra gets 77.8% vs Gemini-2.5-Pro 47.9%, GPT-4o 30.6% and Qwen3-VL-32B 27.9% (the last three from RoboMME's evaluation) [Sec 6, Table 3]. Interface corrections (denser frames, prompt note) give GPT-6-Astra +119/-3 episodes but GPT-4o only +26/-17 (n.s.), interaction 35.7 points [Sec 6, Paired control], i.e. the weaker model does not exploit denser evidence.
### Goal: What limitations does it state?
Adaptive development on the test split, API drift, single run per episode; the evidence does not separate memory demands from current-state shortcuts [Sec 7].
