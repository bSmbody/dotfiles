# Realizing Common Random Numbers: Event-Keyed Hashing for Causally Valid Stochastic Models

## What this paper does
For agent-based simulators used to estimate treatment effects by paired "same seed" runs (common random numbers, CRN), the authors show that a single stateful pseudorandom stream makes the noise an event receives depend on how many draws happened before it, so an intervention that changes the execution path silently gives "the same" downstream events different noise. They formalize the needed property (execution invariance: noise is a function of seed and a stable event identifier) and restore it with counter-based generators keyed by event identifiers, with guidelines for designing those keys.

## Goal-by-goal answers
### Goal: Why does same-seed replay fail to give a valid counterfactual when the intervention changes the execution path?
With a stateful PRNG, event e receives draw R_{n+1} where n is the number of prior calls; if the intervention changes n, "event e receives different noise" and execution invariance is violated [full text, Sec 3.3, Prop 1]. Consequently "seed-matched CRNs using stateful PRNGs fail to produce valid counterfactual couplings when interventions alter execution paths" [Corollary 3.1], making variance reduction "unpredictable or even negative" and individual-level effects ill-defined [Sec 3.3, App A].
### Goal: What is the remedy, and what modeling choice does it require?
Execution invariance requires U_e = g(s, event_id_e) with an identifier "stable across scenarios, not dependent on execution history" [Sec 2.3, Def 2.1]. Counter-based generators (Philox/Threefry) keyed by event ids make each draw a function of the modeled event, so an extra or missing event "doesn't shift other events" [Sec 4.1]. Choosing the key is "equivalent to defining what constitutes 'the same event' across counterfactual worlds", a substantive modeling choice that is "not automatable" [Sec 4.2]; keys must be granular enough that distinct events get distinct draws [Sec 4.3]. Events that occur in only one scenario are fine; the problem is only shared events receiving different noise [Sec 2.3].
### Goal: How can one check that a coupled replay is valid?
A placebo scenario that is mechanistically identical to baseline should reproduce the baseline outcome; "any divergence in outcomes indicates an execution-invariance violation," though identical outcomes do not prove invariance [Sec 2.3]. Paired-difference variance is Var(Y1)+Var(Y0)-2Cov, so the gain comes entirely from the covariance the coupling induces [Sec 1, Eq 1].
