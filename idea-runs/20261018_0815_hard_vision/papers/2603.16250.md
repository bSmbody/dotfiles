# Visual Prompt Discovery via Semantic Exploration (SEVEX)

## What this paper does
Automates discovery of task-wise visual prompts (image-manipulation code plus text prompt) for black-box LVLMs. An agent searches a tree over natural-language "ideas", implemented with a toolbox (crop, grayscale, draw line/box, overlay, GroundingDINO detection, SemanticSAM, DepthAnything, ask_to_LVLM), using novelty-guided UCT and semantic backpropagation of sample-wise insights on a development split. Evaluated on BlindTest and BLINK.

## Goal-by-goal answers
### Goal: How much of the BlindTest perceptual gap do black-box visual prompts close, and at what cost?
On Gemini-2.5-flash BlindTest: LineIntersections 73.0 -> 90.5, CircledLetter 78.8 -> 83.7, SubwayMap 60.0 -> 62.8, OverlappingShapes 50.4 -> 52.4; SketchPad (zero-shot tool use) is worse than naive on several (e.g. 33.3, 16.3) [full text, Sec 4, Tab 2]. Inference cost ~10.9% above naive, but an upfront exploration cost ~3,442 naive inferences per task [full text, Sec 4.2]. On GPT-4o average 38.8 -> 62.4 (LineIntersections 8.2 -> 57.1); Claude Sonnet 4.0 66.8 -> 75.2 [full text, Sec 4.5].

### Goal: What mechanism assumption limits it?
The final answer is still produced by the same LVLM reading the transformed image; the prompt changes what pixels it sees, it does not supply the measured quantity. With only basic drawing tools the gains hold (65.6 -> 73.3), and external detectors help only some tasks (OverlappingShapes 45.6 vs 52.4) [full text, App 0.C.1]. Discovered prompts are model-specific and "rarely transferable"; a prompt good for Claude can hurt GPT [full text, Sec 4.6]. Prompts are fixed per task, not per instance, and there is no per-instance reliability signal.
