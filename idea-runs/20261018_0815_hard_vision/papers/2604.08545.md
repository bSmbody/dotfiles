# Act Wisely: Cultivating Meta-Cognitive Tool Use in Agentic Multimodal Models

## What this paper does
Trains Metis (Qwen3-VL-8B, SFT then RL) with code (crop/enlarge) and search tools, targeting "blind tool invocation". Its RL algorithm HDPO keeps two separately normalised GRPO advantages: an accuracy channel over all rollouts and a tool-efficiency channel (reward 1/(T+1)) computed only among correct rollouts, combined only in the loss. Data curation drops SFT samples the base model already solves (pass@8 = 1) and keeps RL prompts with pass@8 in (0,1). Reports tool-call rate dropping from ~98% (GRPO) to ~2% with accuracy gains on V*, HRBench, CharXiv.

## Goal-by-goal answers

### Goal: What mechanism decides whether to call a tool and whether to trust its output over the model's own reading?
The decision lives entirely inside the policy weights: HDPO trains the 8B VLM so that, among correct rollouts, fewer tool calls get higher advantage [full text, Section 3.2.1, Eq 8-10]. No separate step judges whether a returned tool output is correct. Tools are crop/code and search, not specialist perception models [full text, Section 1, Section 4.4]. Trusting a tool output is never modelled. Redundant calls are only described as "injecting extraneous noise" [full text, Section 1].

### Goal: What signal (and at what granularity) is the trust/necessity decision based on, and does it require the VLM's weights or logits?
The signal is the final-answer correctness (LLM judge) plus the tool-call count per rollout, aggregated by group-relative advantages per prompt [full text, Eq 6-10]. Necessity is also built into the data: the base model's pass@8 without tools filters SFT data [full text, Section 3.3.1]. It requires full RL on the model's weights (8x B200, G=16 rollouts) [full text, Section 4.1]. It cannot be applied to a black-box API model.

### Goal: What limitation does it report or show on handling incorrect tool outputs or confidently wrong VLM readings?
The paper does not evaluate wrong tool outputs. The efficiency weight shows an inverted U: w_tool=0.20 lowers every benchmark because "overemphasizing tool parsimony forces the policy into a conservative regime, stifling necessary ... tool usage" [full text, Section 4.3, Table 3]. So the abstain/call boundary is a global trade-off scalar, not an instance-level reliability estimate. Whether the model answers confidently and wrongly when it abstains is not analysed.
