# It's About Time: Analog Clock Reading in the Wild

## What this paper does
CVPR 2022. A two-stage clock reader: an off-the-shelf detector (CBNetV2) crops the clock, then a ResNet-50 spatial transformer predicts a homography to a canonical fronto-parallel view and a second ResNet-50 classifies the time as one of 720 joint (hour, minute) classes. Trained on a procedural synthetic clock generator (SynClock) plus pseudo-labelled real timelapse videos (uniformity of time as the filter), with zero manual training labels. Introduces COCO, OpenImages and Clock Movies clock test sets with minute-level labels.

## Goal-by-goal answers
### Goal: How accurately can an existing specialist read real in-the-wild clocks, and is it a natural baseline for a training-free clock reader?
End-to-end top-1 overall accuracy (hour correct and minute within +-1) is 80.4% on COCO, 77.3% on OpenImages and 79.0% on Clock Movies; top-1 hour 86.9/83.5/82.3, minute 84.4/81.9/82.4 [full text, Sec 7.1, Table 3]. Homography augmentation adds +31.5/+25.2 points and pseudo-labelled real video adds +14.3/+14.1 [Sec 7.3]. So a specialist trained without human labels already reads in-the-wild clocks at ~80% under a +-1 minute tolerance; it is a direct, cheap baseline for any clock-reading claim, though the metric (minute +-1) differs from exact-minute accuracy and test sets differ from TickTockVQA.

### Goal: Does it already use joint hour-minute state or the hand coupling, and what are its stated failure modes?
It classifies the 720 joint (hour, minute) states directly, so the hour hand's dependence on the minute is learned implicitly rather than imposed as theta_h = 30h + m/2 [Sec 3.2, Eq 4]. Stated limitations: it cannot "logically reason ... such as using the cue of relative position of hands relative to the hour mark" and generalises poorly to "clocks with unique artistic designs" [Sec 14 Limitations]. Hands ambiguity is acknowledged via top-2/3 accuracy reporting [Sec 6.3].

# It's About Time: Analog Clock Reading in the Wild

## What this paper does
CVPR 2022 (Yang, Xie, Zisserman). A trained clock reader: off-the-shelf CBNetV2 detector crops the clock, a ResNet-50 spatial transformer predicts a homography to a canonical fronto-parallel view, and a ResNet-50 classifies the time as one of 720 (hour, minute) classes. Trained on an on-the-fly synthetic generator (SynClock, with homography, artefacts, shadows) and then on pseudo-labelled timelapse videos filtered by a time-uniformity constraint (RANSAC sawtooth fit). Introduces COCO (1,911), OpenImages (1,311) and Clock Movies (1,244) clock test sets annotated to the minute.

## Goal-by-goal answers
### Goal: Does it already use a joint 720-state (hour, minute) formulation, and how well do trained vs training-free geometric clock readers do on real clocks?
Yes: recognition is posed as 720-way joint classification of hour and minute together [full text, Sec 3.2, Eq 4], i.e. the joint state space that the C3 proposal sweeps with theta_h = 30h + m/2 is the standard output space of this reader (learned, not enforced geometrically). End-to-end top-1 overall accuracy (hour exact, minute within +-1) is 80.4 / 77.3 / 79.0 on COCO / OpenImages / Clock Movies [full text, Sec 7, Tab 3]. A geometry-based Sobel + Hough line reader with the same detector reaches only 9.7 / 7.7 / 8.2 [full text, App 12, Tab 7], "struggl[ing] with variations in design, resolution, lighting and artefacts". Named failure modes of the trained model: swapped hands, failed detection, and artistic designs it has not seen [full text, Fig 6, App 14].

### Goal: Is this a baseline a clock-reading reviewer would expect, and what does it imply for a training-free pipeline?
It is the canonical in-the-wild clock reader and its benchmarks are the standard pre-VLM clock test sets; TickTockVQA reports it at 18.54% full-time accuracy on its harder test set [per 2603.08011 digest]. Its Table 7 is direct evidence that hand-engineered edge/line clock geometry collapses on in-the-wild images (<10%), which is the prior a training-free tick/needle pipeline must overcome.


### Goal: Can the reader be run as a baseline on new images (code, checkpoint, input assumptions)?
The paper's test protocol uses CBNetV2 crops and then the STN + 720-way classifier [full text, Sec 3.1-3.2, Sec 6.2]. The authors' repository (github.com/charigyang/itsabouttime, checked 2026-10-18) provides predict.py and eval.py, links its datasets on Google Drive, and notes that predict.py "assume[s] the images being already cropped"; the README does not state whether trained weights are bundled, so checkpoint availability must be confirmed on day 1. TickTockVQA's authors did run it on their test set (18.54% full-time) [per 2603.08011 digest].
