# RSure-Agent: Reliable Use of Tool Observations for Remote Sensing Agents

## What this paper does
Analyses 1,229 remote-sensing agent trajectories. At least 22.7% of tool-dependent tasks contain incorrect observations despite successful execution, and these errors reach the final answer in at least 82.0% of affected tasks. It proposes verifying every observation before it enters the reasoning history. Tools must return process evidence (backend, thresholds, boxes and scores, numerators and denominators, validity masks). Deterministic rules run first. A semantic verifier, the same backbone VLM (GPT-4o/GPT-5 etc.) in a separate context, then accepts, rejects or requests more evidence, informed by an offline task-type × tool-configuration reliability prior.

## Goal-by-goal answers

### Goal: What mechanism decides whether to call a tool and whether to trust its output over the model's own reading?
The trust decision is V_t = M_eval(I, q, z, a_t, o_t, E_t, r̂_t) ∈ {accept, request_evidence, reject}. M_eval "uses the same model as the backbone but does not share its dialogue context" [full text, Section IV-D, Eq 10]. It "judges whether the image and process evidence support the current observation", for example checking the class of the instance in each detection box. So the backbone VLM's own reading of the image is the reference used to accept or reject the specialist output. Whether to call a tool is left to the ReAct backbone [full text, Section IV-A].

### Goal: What signal (and at what granularity) is the trust/necessity decision based on, and does it require the VLM's weights or logits?
It is black-box: prompting only, with a shared reliability matrix across 11 backbones [full text, Section IV-C]. The prior r̂(z,v) = (n_valid+1)/(n+2) is computed per task type (21 CHOICE types) and per tool configuration. It comes from one GPT-4o run on 1,200 calibration tasks, and a call is "valid" if it executed and "belonged to a task whose final answer was correct". The paper notes that "all calls in a task share the outcome of that task" [full text, Section IV-C, Eq 6]. So reliability is a static type-level table with task-level credit, not an estimate for each instance. It is fixed after calibration and only looked up online.

### Goal: What limitation does it report or show on handling incorrect tool outputs or confidently wrong VLM readings?
Even with verification, "the error propagation rate of RSure-Agent is still 69.6% to 75.5%" [full text, Section V-H]. The rule checks "do not directly assess whether an observation matches the image content" [full text, Section IV-C]. That judgement falls to the VLM verifier. Verification is weaker for tools that return only final results without process evidence [full text, Section V-H]. Gains in the ablation are modest: +1.4 to +3.3 points from verification and +1.1 to +3.1 from the prior with GPT-5 [full text, Section V-C, Table VI]. The paper also shows that CRITIC and Tools Fail style self-checks cost more tokens for smaller gains [full text, Section V-D, Table VII].
