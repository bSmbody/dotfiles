# A Vision Check-up for Language Models

## What this paper does
Tests whether text-only LLMs (GPT-3.5/GPT-4 etc.) can draw visual concepts by writing rendering code (matplotlib, turtle, Processing, TikZ) for shapes, objects and scenes, recognise concepts from code, and improve drawings with self-generated text feedback; then pretrains a ResNet-50 with MoCo-v2 on 1.3M LLM-generated images and evaluates on ImageNet.

## Goal-by-goal answers
### Goal: Can LLMs write code that renders requested visual concepts, including parametrised families, and where do they fail?
Yes for many concepts: LLMs compose shapes, objects and scenes and handle spatial relations such as "a row of bicycles" [full text, Sec 4.1]. Diversity can be produced by "sampling a parametrized function that allows creating a new drawing of the concept by changing parameters" [full text, Sec 4.1 "Diversity and Realism"]. Failures: concepts combining a set of shapes with a specific spatial organisation, coarse drawings lacking detail, incomplete depictions, and drawing digits [full text, Sec 4.1 "What can LLM not visualize?"]. Competence drops from shapes to objects to scenes (CLIP-rank fidelity) [full text, Sec 4.1, Fig 3]. Models tested are 2023-era (GPT-4 text).

### Goal: Do images from LLM-written programs carry signal that transfers to natural images?
Partly: MoCo-v2 on LLM-generated images gives 36.16% ImageNet-1k linear accuracy, above dead-leaves/fractals but below StyleGAN and Shaders-21k, attributed to lack of texture; combined with Shaders-21k it beats all procedural alternatives (46.03%) [full text, Sec 5, Tab 2]. LLM images score poorly on FID realism [full text, Sec 4.1].
