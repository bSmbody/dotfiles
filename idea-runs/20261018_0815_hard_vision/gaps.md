
## Axis: deciding when a VLM should trust a visual tool or specialist model over its own reading

### What has been done
- **Trained call/abstain policies (white-box RL/SFT on the VLM).** HDPO trains an 8B VLM with an accuracy advantage and a separate tool-parsimony advantage (1/(T+1)) computed only among correct rollouts. It learns *when to call* and never models whether a returned output is correct [2604.08545]. ToolVision rewards tool use through a frozen, question-level necessity weight w(x,π_SFT), estimated from 16 tool-free vs 8 tool-enabled rollouts. Its tool-success term checks only execution errors and the final answer, and after RL it routes by task type (counter on 100% of FSC-147, OCR on 84% of OCRBench) [2608.08907]. Selective Change-VQA LoRA-tunes the VLM to a fixed question-family routing policy, with observations computed from oracle maps [2609.14523].
- **Learned re-reading gates from the target model's own likelihoods.** GapSight mines labels for each backbone from answer-NLL or option-margin gains under crops, and trains a router on the VLM's hidden states. Its decisions are instance-level, but it needs logits and hidden states, and it still causes 27 right-to-wrong regressions against 107 repairs [2608.21762].
- **Self-arbitration of tool outputs by the same VLM.** VG-Refiner adds an RL-trained "rethink" turn in which the VLM accepts or overrides a REC detector box (reward 1 for fixing a wrong tool box). Correction is capped at the base model's own grounding ability [2512.06373]. RSure-Agent verifies each tool observation with the backbone VLM in a separate context, using process evidence and a static task-type × tool-configuration reliability prior. Error propagation still stays at 69.6-75.5% [2610.04836].
- **Black-box confidence signals.** Self-consistency over K sensor samples is used as the trust signal for an LLM reasoner, and it "becomes a trap" when the VLM is confidently wrong [2610.07751]. Verbalised VLM confidence is effectively constant (AUROC about 0.5). Token probability works under mild degradation but falls to chance exactly where perception collapses [2607.22034]. A specialist-first cascade routes on the CNN's closed-set softmax margins and accepts VLM overrides on self-reported confidence > 0.8 [2609.10065].
- **Diagnostics.** Fixed crop or zoom evidence views do not reliably make frontier VLMs override their priors. For counting, zoom lowers accuracy (−3.1) [2607.16311].

### Open gaps on this axis
- **Gap:** Black-box methods that decide whether a frontier VLM should accept a specialist output compute the trust decision from the VLM itself. This takes the form of a same-model verifier reading the image [2610.04836], a rethink turn [2512.06373], self-consistency [2610.07751] or stated confidence [2609.10065]. On perceptual blind spots (exact counts, thin-line lengths, fine geometry) the needed signal is missing from the VLM's visual encoding. The arbiter is therefore blind on exactly the instances where tool and VLM disagree, and it cannot tell a correct tool output from a wrong one.
  - **Near-miss methods and coverage:** [2610.04836] comes closest for black-box frontier backbones (GPT-4o/GPT-5). It verifies each specialist observation before use, but its semantic verifier is "the same model as the backbone" judging "whether the image and process evidence support the observation", and 69.6-75.5% of tool errors still propagate. [2512.06373] learns an explicit accept/override turn, but only on RefCOCO, where the base VLM already scores 86.6. Its refinement reaches only "performance comparable to its own grounding ability". [2610.07751] uses black-box self-consistency, which fails when the VLM is confidently wrong. [2607.22034] shows stated confidence is at chance (constant 0.87 at 22% accuracy) and that token probability also collapses under catastrophic perceptual failure. [2609.10065] accepts VLM overrides on self-reported confidence > 0.8. The repeated deficiency across these five papers is that the reliability judgement is anchored on the VLM's own perception or introspection. Query trail: "tool trust VLM", "erroneous tool outputs multimodal", "tool reliability agent", "noisy tool feedback VLM", "VLM defer to specialist", "black-box VLM uncertainty", "tool feedback refinement grounding".
  - **Methodological deficiency:** Wrong inductive bias / missing mechanism. These methods assume the VLM's reading of the image is a usable reference for checking the specialist. In the perceptual-blind-spot regime this assumption is false, because the VLM's error and its verification share the same lost signal. No method supplies a reliability estimate independent of the VLM's visual encoding, for example one derived from the specialist's behaviour under input transformations, agreement between independent specialists, or properties of the instance. The evidence: RSure's rule checks "do not directly assess whether an observation matches the image content" and leave that to the VLM, which caps error removal. VG-Refiner's correction is bounded by the base model's own grounding [2512.06373]. Consistency and confidence signals stay high when the VLM is confidently wrong [2610.07751, 2607.22034].
  - **Why it matters:** The problem's named failure, a confident wrong answer that overrides a correct detector or counter output, cannot be fixed by any arbiter that relies on the VLM's own perception. A reliability signal not derived from the VLM would let a black-box frontier model use local specialists only where they are right. It would also show which hard-vision failures are recoverable by deferral at all, and do so without extra frontier calls for self-verification.
  - **Evidence route:** On instances where VLM and specialist disagree in counting and fine-geometry benchmarks, report the accept/override decision accuracy, split by whether the specialist or the VLM was correct, with error-detection AUROC. Compare against same-VLM verification (RSure-style), self-consistency and stated-confidence arbiters at matched frontier-API cost. A closing method should keep its AUROC on the subset where the VLM is confidently wrong (high self-consistency), where VLM-derived signals fall to chance.
- **Gap:** Methods that learn when to call or believe a visual tool estimate reliability at question, family or task-type granularity, or with outcome-level credit. Examples are the frozen necessity weight w(x,π_SFT) [2608.08907], question-family routing trained on oracle observations [2609.14523] and RSure's task-type × configuration prior with task-level credit [2610.04836]. The one instance-level method needs the VLM's logits and hidden states [2608.21762]. None gives a per-instance estimate of tool-vs-VLM relative reliability usable with a black-box frontier model, so the learned rule turns into blind trust in a tool on instances of a "tool-favoured" type where the tool is wrong.
  - **Near-miss methods and coverage:** [2608.08907] learns tool necessity per question for the trained model. Its reward gives credit for tool use whenever execution succeeds and the answer is correct, so the policy routes all FSC-147 questions to the counter, with no term for a specialist that executes cleanly but returns a wrong count. [2609.14523] loses 11.32 points (F4 and F6 fall from about 99.8% to 63-66%) when oracle maps are replaced by predicted ones, because its family-level routing has no way to discount bad observations. [2610.04836] computes r̂(z,v) from one calibration run where "all calls in a task share the outcome of that task", fixed after calibration. [2608.21762] gets instance-level labels, but from answer NLL and router hidden states, which are white-box only. It also never arbitrates between the first and the second reading (27 regressions). [2604.08545] trains when-to-call into the weights with a global efficiency weight whose inverted-U shows a single trade-off scalar, not per-instance reliability.
  - **Methodological deficiency:** Credit-assignment flaw / representation limitation. Reliability is credited by final-answer outcome, pooled over a question, a family or a task type. It is not attributed to whether this specialist's output on this instance was correct relative to the VLM's answer. Where instance-level attribution exists, it is read from white-box internals (NLL, hidden states). The black-box frontier setting is thus left with only static type-level priors [2610.04836] or retraining the VLM, which is impossible for an API model [2604.08545, 2608.08907, 2609.14523].
  - **Why it matters:** The problem fixes the frontier model as an untrainable API. The decision must therefore come from an external, cheap, per-instance component. Today such a component has either type-level resolution (it misses the tool's instance failures) or requires weights. Closing this would make cost-aware deferral to ≤3B specialists possible for a closed frontier model, with only the questions that need it paying for extra calls.
  - **Evidence route:** Within a single task type where a specialist is reliable on average (for example counting), measure accuracy and cost on instances where the specialist is wrong and the VLM is right, and the reverse. Compare type-level priors (RSure-style), question-level necessity routing, always-call and never-call baselines. A closing method should beat the type-level prior on both subsets at equal or lower API calls per question, with gains concentrated on the specialist-wrong subset.


## Axis: perceptual blind spots of frontier VLMs that more reasoning does not fix

### What has been done
- **More reasoning and prompt-side steering of the same visual reading.** On GPT-6 Astra, higher reasoning effort closes 2D spatial reasoning and 3D detection gaps. Segmentation gains plateau, though, and metric geometry, depth, fine boundaries and small structures stay in the "substantial gap" tier, at up to 13.22× cost [2609.35718]. On BlindTest, slow-thinking variants (Gemini Flash-Thinking, QVQ) score below their base models. CoT, meta-prompting ("describe first"), 2-shot examples and asking for code reconstruction (SVG/PIL) also fail to help or make things worse [2407.06581]. Label-balanced visual in-context demonstrations fix training-prior dominance (+27.2% on counterfactual images). They do not fix an unreliable capability: for counts of 8–16, gains are erratic and some counts fall below zero-shot [2610.12942]. Test-Time Hinting trains a 4B generator to prepend contrastive, non-leaking natural-language hints in one black-box call, with 49–62% repair on A-OKVQA MCQ [2605.16410].
- **Pixel-side visual prompts and specialist tools.** SEVEX searches, per task and per model, for image-manipulation programs (crop, draw lines, overlays, GroundingDINO, SAM, DepthAnything). The final answer is still read off the transformed image by the black-box VLM. It lifts LineIntersections a lot (GPT-4o 8.2→57.1), barely moves OverlappingShapes (50.4→52.4), costs about 3.4k inferences of exploration per task, and its prompts do not transfer across models [2603.16250]. Astra's built-in tools (point-then-count) and specialist-as-tool pipelines (segmentation for counting, depth for distance comparison) help where a named specialist task matches the query, at 1.04–1.20× cost [2609.35718].
- **Reading the signal out of encoders, bypassing the LLM.** Linear probes on frozen SigLIP/CLIP features of 0.5B–4B VLMs solve two-circles and line intersections at ≥99.47%, while the VLMs fail. The probes are supervised per-task classifiers trained on thousands of synthetic images [2407.06581]. Direct encoder readouts (e.g. DINOv2 with a DPT head, zero-shot correspondence) beat their own VLMs, which fall to near chance. The information survives through every LLM layer until the last, and only LLM LoRA tuning on 5k task examples recovers it [2506.08008]. ADR reads relation direction from frozen CLIP/SigLIP features with no training: Sinkhorn patch–word alignment followed by a signed centroid displacement. Its margin gives 99.8% accuracy on the 30% most confident items. Its kernel is hand-derived for directed noun-pair relations [2610.06324].
- **Training the VLM's perception (white-box).** PARA attributes errors to perception when a frontier reference's question-blind description repairs them, and shows that RL gains shrink as perceptual headroom grows. GRAD distils the best rollout's visual attention into worse sibling rollouts [2610.21380].

### Open gaps on this axis
- **Gap:** Black-box remedies for frontier-VLM perceptual blind spots change the text or pixels the frontier model receives: reasoning effort, CoT and ICL [2407.06581, 2610.12942], learned hints [2605.16410], and task-wise visual prompts [2603.16250]. The quantity is then still read out by the frontier model's own encoder-to-language pathway. The mechanisms that do recover the lost quantity read frozen encoders directly: per-task supervised probes [2407.06581], task-specific heads or LLM fine-tuning [2506.08008], or a readout hand-derived for one relation family [2610.06324]. So for low-level measurements such as intersections, overlaps, line length and high-cardinality counts, no readout of a small frozen encoder is both question-conditioned and task-general, and none can be handed to a black-box frontier model as answer-bearing evidence.
  - **Near-miss methods and coverage:** [2610.06324] comes closest. Its ADR is training-free, runs on a frozen small encoder at about 6% of an MLLM's FLOPs, and its margin is calibrated. However, its antisymmetric kernel and parse rule are derived by hand for directed spatial relations between noun pairs, and it is never connected to a generative VLM's answer. [2407.06581] shows the signal is linearly present (≥99.47%), but extracts it with a logistic-regression probe trained per task on 4.4k–8.9k synthetic images. [2506.08008] recovers it only with task-specific heads or LLM LoRA on 5k examples, and treats this as diagnosis, not a solution. On the black-box side, [2603.16250] still relies on the VLM reading the edited image: it stays near 52% on OverlappingShapes, and its basic-tools-only variant matches its full-tool variant. [2610.12942] shows prompt-side intervention only "redirects a reliable capability" and does not strengthen counting at 8–16. [2605.16410] hints may not carry the answer, so they cannot carry a measurement. [2609.35718] specialist pipelines cover only named specialist tasks (segmentation, depth, grounding). Query trail also checked: "linear probe readout VLM", "visual prompting black-box VLM", "encoder probe answer", "perception module black-box", "small model perception frontier".
  - **Methodological deficiency:** Representation / readout limitation (missing mechanism). Readouts that recover the encoder-resident signal are fixed functions: a per-task trained head [2407.06581, 2506.08008] or a hand-derived relation kernel [2610.06324]. Every black-box channel into the frontier model goes back through the frontier's own lossy visual readout. This is grounded in BlindTest, where probes on the same features score ≥99.47% while slow-thinking and CoT variants score at or below base, and in Hidden-in-plain-sight, where the signal survives until the last LLM layer. The bottleneck is the readout interface, not the reasoning budget and not the encoder. No method turns a natural-language question into a readout of a frozen local encoder, or of a ≤8B VLM's internal states.
  - **Why it matters:** Groups using API-only frontier models cannot fix measurement-type errors (gear teeth, thin-line comparison, overlapping-shape counts) by any means that ends with the frontier model looking at pixels. A question-conditioned local readout would turn evidence that exists in cheap encoders but is lost in the language decoder into something the frontier model can use. It would also show which "hard vision" failures are readout failures and which are true encoder limits.
  - **Evidence route:** On BlindTest-style primitives, high-cardinality counting and direction-balanced relation sets, compare four things: the frontier model alone and with reasoning effort raised; SEVEX- or hint-style black-box prompting; per-task supervised probes as an upper reference; and a candidate readout evaluated on tasks it was not built for. A closing method should approach probe-level accuracy on held-out primitive types without per-task heads or hand-derived kernels. Its gain should hold on the subset where higher reasoning effort does not move the frontier model's answer, at a measured API cost no higher than one extra call.
- **Gap:** Methods that learn how to help a VLM perceive build their training signal from some model in the loop that already perceives the instance correctly. Test-Time Hinting keeps only hints that flip the target VLM and drops unrepairable instances [2605.16410]. GRAD distils attention only from a better-rewarded sibling rollout [2610.21380]. PARA counts a failure as perception-recoverable only when a frontier reference's description repairs it [2610.21380]. Instances where every model in the loop is blind, which are exactly the frontier blind spots, therefore get no gradient and no attribution.
  - **Near-miss methods and coverage:** [2605.16410] is the closest black-box learner. Its agentic loop "excludes unsuccessful repair targets from downstream phases", SFT discards trials where the verifier never got the answer right, and GRPO down-weights unrepaired outcomes to −0.5. The reason given is that on hard inputs "every candidate hint is likely to leave the target wrong", and pushing on them produces assertive hints that cause harm elsewhere. [2610.21380] GRAD sets w_i = max(−A_i, 0), so "groups with identical rewards are naturally excluded". When all rollouts misperceive, no attention target exists. PARA's perceptual headroom is bounded by what Claude-Opus/GPT references perceive from a question-blind description. [2610.12942] confirms the consequence from the other side: demonstrations, which are another self-referential signal, do not strengthen capabilities the model lacks.
  - **Methodological deficiency:** Credit-assignment flaw. Supervision is defined by an outcome (answer flips, better sibling reward, reference repair) that needs at least one in-loop model to perceive the instance correctly. Credit is therefore zero, discarded or down-weighted on uniformly-failed instances, and is never routed to a source of perception from outside the loop. Each paper says so in its method: excluded unrepaired targets [2605.16410], excluded identical-reward groups [2610.21380].
  - **Why it matters:** Any cheap learned helper for a frontier model (hint generator, router, small model trained with RL) will quietly learn to fix the recoverable subset. The persistent blind spots that motivate the problem will then stay where they are, while the headline numbers improve on A-OKVQA-like data. A training signal that reaches uniformly-failed instances would tell apart helpers that add perception from helpers that only steer existing perception.
  - **Evidence route:** Split the test sets into instances the frontier model gets right under some prompt or sample (steerable) and instances it gets wrong under every prompt, sample and reasoning-effort setting tried (uniformly blind), using a fixed, reported budget. Report each method's repair rate separately on the two subsets. Hint generators [2605.16410] and attention-distilled models [2610.21380] are expected to repair mostly the steerable subset. A closing method should show a substantial repair rate on the uniformly-blind subset at modest API cost.
