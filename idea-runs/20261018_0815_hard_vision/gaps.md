
## Axis: deciding when a VLM should trust a visual tool or specialist model over its own reading

### What has been done
- **Trained call/abstain policies (white-box RL/SFT on the VLM).** HDPO trains an 8B VLM with an accuracy advantage and a separate tool-parsimony advantage (1/(T+1)) computed only among correct rollouts. It learns *when to call* and never models whether a returned output is correct [2604.08545]. ToolVision rewards tool use through a frozen, question-level necessity weight w(x,π_SFT), estimated from 16 tool-free vs 8 tool-enabled rollouts. Its tool-success term checks only execution errors and the final answer, and after RL it routes by task type (counter on 100% of FSC-147, OCR on 84% of OCRBench) [2608.08907]. Selective Change-VQA LoRA-tunes the VLM to a fixed question-family routing policy, with observations computed from oracle maps [2609.14523].
- **Learned re-reading gates from the target model's own likelihoods.** GapSight mines labels for each backbone from answer-NLL or option-margin gains under crops, and trains a router on the VLM's hidden states. Its decisions are instance-level, but it needs logits and hidden states, and it still causes 27 right-to-wrong regressions against 107 repairs [2608.21762].
- **Self-arbitration of tool outputs by the same VLM.** VG-Refiner adds an RL-trained "rethink" turn in which the VLM accepts or overrides a REC detector box (reward 1 for fixing a wrong tool box). Correction is capped at the base model's own grounding ability [2512.06373]. RSure-Agent verifies each tool observation with the backbone VLM in a separate context, using process evidence and a static task-type × tool-configuration reliability prior. Error propagation still stays at 69.6-75.5% [2610.04836].
- **Black-box confidence signals.** Self-consistency over K sensor samples is used as the trust signal for an LLM reasoner, and it "becomes a trap" when the VLM is confidently wrong [2610.07751]. Verbalised VLM confidence is effectively constant (AUROC about 0.5). Token probability works under mild degradation but falls to chance exactly where perception collapses [2607.22034]. A specialist-first cascade routes on the CNN's closed-set softmax margins and accepts VLM overrides on self-reported confidence > 0.8 [2609.10065].
- **Diagnostics.** Fixed crop or zoom evidence views do not reliably make frontier VLMs override their priors. For counting, zoom lowers accuracy (−3.1) [2607.16311].

### Open gaps on this axis
- **Gap:** Black-box methods that decide whether a frontier VLM should accept a specialist output compute the trust decision from the VLM itself. This takes the form of a same-model verifier reading the image [2610.04836], a rethink turn [2512.06373], self-consistency [2610.07751] or stated confidence [2609.10065]. On perceptual blind spots (exact counts, thin-line lengths, fine geometry) the needed signal is missing from the VLM's visual encoding. The arbiter is therefore blind on exactly the instances where tool and VLM disagree, and it cannot tell a correct tool output from a wrong one.
  - **Near-miss methods and coverage:** [2610.04836] comes closest for black-box frontier backbones (GPT-4o/GPT-5). It verifies each specialist observation before use, but its semantic verifier is "the same model as the backbone" judging "whether the image and process evidence support the observation", and 69.6-75.5% of tool errors still propagate. [2512.06373] learns an explicit accept/override turn, but only on RefCOCO, where the base VLM already scores 86.6. Its refinement reaches only "performance comparable to its own grounding ability". [2610.07751] uses black-box self-consistency, which fails when the VLM is confidently wrong. [2607.22034] shows stated confidence is at chance (constant 0.87 at 22% accuracy) and that token probability also collapses under catastrophic perceptual failure. [2609.10065] accepts VLM overrides on self-reported confidence > 0.8. The repeated deficiency across these five papers is that the reliability judgement is anchored on the VLM's own perception or introspection. Query trail: "tool trust VLM", "erroneous tool outputs multimodal", "tool reliability agent", "noisy tool feedback VLM", "VLM defer to specialist", "black-box VLM uncertainty", "tool feedback refinement grounding".
  - **Methodological deficiency:** Wrong inductive bias / missing mechanism. These methods assume the VLM's reading of the image is a usable reference for checking the specialist. In the perceptual-blind-spot regime this assumption is false, because the VLM's error and its verification share the same lost signal. No method supplies a reliability estimate independent of the VLM's visual encoding, for example one derived from the specialist's behaviour under input transformations, agreement between independent specialists, or properties of the instance. The evidence: RSure's rule checks "do not directly assess whether an observation matches the image content" and leave that to the VLM, which caps error removal. VG-Refiner's correction is bounded by the base model's own grounding [2512.06373]. Consistency and confidence signals stay high when the VLM is confidently wrong [2610.07751, 2607.22034].
  - **Why it matters:** The problem's named failure, a confident wrong answer that overrides a correct detector or counter output, cannot be fixed by any arbiter that relies on the VLM's own perception. A reliability signal not derived from the VLM would let a black-box frontier model use local specialists only where they are right. It would also show which hard-vision failures are recoverable by deferral at all, and do so without extra frontier calls for self-verification.
  - **Evidence route:** On instances where VLM and specialist disagree in counting and fine-geometry benchmarks, report the accept/override decision accuracy, split by whether the specialist or the VLM was correct, with error-detection AUROC. Compare against same-VLM verification (RSure-style), self-consistency and stated-confidence arbiters at matched frontier-API cost. A closing method should keep its AUROC on the subset where the VLM is confidently wrong (high self-consistency), where VLM-derived signals fall to chance.
- **Gap:** Methods that learn when to call or believe a visual tool estimate reliability at question, family or task-type granularity, or with outcome-level credit. Examples are the frozen necessity weight w(x,π_SFT) [2608.08907], question-family routing trained on oracle observations [2609.14523] and RSure's task-type × configuration prior with task-level credit [2610.04836]. The one instance-level method needs the VLM's logits and hidden states [2608.21762]. None gives a per-instance estimate of tool-vs-VLM relative reliability usable with a black-box frontier model, so the learned rule turns into blind trust in a tool on instances of a "tool-favoured" type where the tool is wrong.
  - **Near-miss methods and coverage:** [2608.08907] learns tool necessity per question for the trained model. Its reward gives credit for tool use whenever execution succeeds and the answer is correct, so the policy routes all FSC-147 questions to the counter, with no term for a specialist that executes cleanly but returns a wrong count. [2609.14523] loses 11.32 points (F4 and F6 fall from about 99.8% to 63-66%) when oracle maps are replaced by predicted ones, because its family-level routing has no way to discount bad observations. [2610.04836] computes r̂(z,v) from one calibration run where "all calls in a task share the outcome of that task", fixed after calibration. [2608.21762] gets instance-level labels, but from answer NLL and router hidden states, which are white-box only. It also never arbitrates between the first and the second reading (27 regressions). [2604.08545] trains when-to-call into the weights with a global efficiency weight whose inverted-U shows a single trade-off scalar, not per-instance reliability.
  - **Methodological deficiency:** Credit-assignment flaw / representation limitation. Reliability is credited by final-answer outcome, pooled over a question, a family or a task type. It is not attributed to whether this specialist's output on this instance was correct relative to the VLM's answer. Where instance-level attribution exists, it is read from white-box internals (NLL, hidden states). The black-box frontier setting is thus left with only static type-level priors [2610.04836] or retraining the VLM, which is impossible for an API model [2604.08545, 2608.08907, 2609.14523].
  - **Why it matters:** The problem fixes the frontier model as an untrainable API. The decision must therefore come from an external, cheap, per-instance component. Today such a component has either type-level resolution (it misses the tool's instance failures) or requires weights. Closing this would make cost-aware deferral to ≤3B specialists possible for a closed frontier model, with only the questions that need it paying for extra calls.
  - **Evidence route:** Within a single task type where a specialist is reliable on average (for example counting), measure accuracy and cost on instances where the specialist is wrong and the VLM is right, and the reverse. Compare type-level priors (RSure-style), question-level necessity routing, always-call and never-call baselines. A closing method should beat the type-level prior on both subsets at equal or lower API calls per question, with gains concentrated on the specialist-wrong subset.
