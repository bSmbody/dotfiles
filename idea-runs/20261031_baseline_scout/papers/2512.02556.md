# DeepSeek-V3.2: Pushing the Frontier of Open Large Language Models

## What this paper does
Technical report for DeepSeek-V3.2 (and V3.2-Exp / V3.2-Speciale). The only architecture change from DeepSeek-V3.1-Terminus is DeepSeek Sparse Attention (DSA), added by continued training: a lightning indexer (few heads, ReLU, FP8) scores every preceding token, and the main MLA attention (run in MQA mode so each latent KV entry is shared by all query heads) attends only to the top-k (k=2048) tokens. The indexer is warmed up by KL to head-summed dense attention, then trained on the selected set only. The rest of the report covers scaled GRPO, agentic task synthesis and evaluations.

## Goal-by-goal answers
### Goal: How does the DSA lightning indexer score and select tokens, and what is its per-token cost relative to main attention?
I_{t,s} = sum_j w_{t,j} ReLU(q^I_{t,j} . k^I_s) over H^I indexer heads; ReLU chosen "for throughput", and "the lightning indexer has a small number of heads and can be implemented in FP8" [full text, Section 2.1 / Eq 1]. Top-k tokens (token-level, not block-level) of I_{t,:} are kept and attended by MLA in MQA mode because "each key-value entry must be shared across multiple queries for computational efficiency" [Section 2.1, "Instantiate DSA Under MLA"]. Training: dense warm-up (only indexer trained, 1000 steps x 16 x 128K = 2.1B tokens, KL to L1-normalized head-summed attention, Eq 3), then sparse training with k=2048 for 15000 steps x 480 x 128K = 943.7B tokens, KL restricted to the selected set S_t, indexer input detached [Section 2.1.1 / Eq 4]. No numbers for H^I or d^I are given in the body text (the open inference code on HF is cited for details).

### Goal: What inference cost does it report at long context, and what still grows with length?
"DSA reduces the core attention complexity of the main model from O(L^2) to O(Lk) ... Although the lightning indexer still has a complexity of O(L^2), it requires much less computation compared with MLA" [Section 2.3]. Per decoded token, the indexer therefore still reads index keys for all L previous tokens, and the full MLA latent cache is kept (DSA selects from it; it does not shrink stored KV). Cost is shown only as a plot (Figure 3, USD per million tokens vs token position, measured on the deployed H800 service at 2 USD/GPU-hour) for prefill and decode; no table of numbers in the text. For short prefill they "implement a masked MHA mode to simulate DSA" because it is faster at short lengths [Section 2.3].

### Goal: What limitations do the authors state, relevant to inference?
Section 5: (i) less world knowledge than frontier closed models; (ii) "token efficiency remains a challenge; DeepSeek-V3.2 typically requires longer generation trajectories (i.e., more tokens) to match the output quality of models like Gemini-3.0-Pro"; also for Speciale, "token efficiency ... remains significantly inferior to that of Gemini-3.0-Pro" [Section 4.2]. (iii) weaker on complex tasks. The parity evidence for DSA itself is benchmark parity with V3.1-Terminus, ChatbotArena Elo, and third-party AA-LCR (+4) and Fiction.liveBench [Section 2.2]; no ablation of k or indexer size is reported.
