# Self-Speculation for Faster Reasoning Models

## What this paper does
SSR is a training-free self-speculative method for reasoning models. While the CoT is still being generated, a parallel child request forks from an intermediate CoT prefix and drafts the final answer. Once the full CoT is done, the same model verifies that draft under the full-budget context. It accepts the longest matching prefix, then uses suffix decoding (a suffix cache built from the draft) to reuse later spans past the first mismatch. An iterative variant drafts at several points and bootstraps later drafts from earlier ones. Implemented in vLLM. Code: https://github.com/Ravi-VK/SSR/ [abstract].

## Goal-by-goal answers
### Goal: What is measured, on which models and lengths?
Models: Qwen3.5-4B and Gemma-4-E4B-IT. Hardware: RTX A6000, batch size 1 [Section 5.1]. Benchmarks: ClassEval, HumanEval, and LongProc 2K (~2K-token outputs). End-to-end latency reduction: up to 24.1% on ClassEval (Gemma) and 18.5% (Qwen), 7.1-9.1% on LongProc 2K, 2.9-14.6% on HumanEval [Section 5.2, Table 1]. Drafting costs <2% effective throughput [Section 5.2]. Suffix-only verification gives 24.1% vs 7.9% for prefix-only [Table 2].

### Goal: What does it NOT accelerate and what limitations are stated?
SSR speeds up only answer generation, not the CoT. "When reasoning dominates generation time, gains are limited since CoT generation is not accelerated" [Section 6]. On HumanEval with Qwen3.5-4B, CoT takes 20.9 s and continuation 4.6 s [Section 5.2]. On high-entropy tasks drafts overlap little lexically [Section 6]. The draft child request holds its own KV copy of the CoT prefix during drafting, and only bs=1 is evaluated [Section 5.1]. Future work: extend SSR to speed up the CoT itself [Section 6].
