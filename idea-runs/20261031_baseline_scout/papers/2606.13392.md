# MiniMax Sparse Attention

## What this paper does
MSA attaches a lightweight Index Branch to a GQA layer: one index query head per GQA group and one shared index key head score tokens, max-pooled to blocks, and each group selects top-k blocks (plus a forced local block); the Main Branch runs softmax attention over the selected blocks. Kernels cover exp-free top-k selection, sparse attention with pre-scheduled tiles, and a fused sparse KL loss. Evaluated at 109B-MoE scale with 28.4x less attention compute at 1M context, staying close to full attention on RULER/HELMET.

## Goal-by-goal answers
### Goal: How does the indexer receive a training signal given non-differentiable top-k?
Top-k is non-differentiable, so the LM loss cannot train the index projections; MSA uses a KL loss between the head-averaged Main Branch distribution (stop-grad teacher) and the index distribution, both normalized over only the tokens of the selected blocks [full text, Section 3.2 / Eq 9-10]. The index input is detached so the KL only updates W_idx [Eq 11]. A warmup runs full attention in both branches to train the indexer before switching to sparse; after warmup "L_KL is computed over the top-k selected positions" [Section 3.2, "Indexer Warmup"].

### Goal: What evidence does it give about the failure modes of indexer credit assignment?
With LM loss only (index branch contributing an output), the indexer "receives little direct pressure to select relevant blocks" and long-context retrieval is poor; KL only improves retrieval; both together balance [Appendix B.2, Figure 7]. Without the detach, KL gradients spike into the backbone and cause divergence, and the backbone lowers KL by simplifying its own attention (self-distillation) [Appendix B.3]. After 140B-token long-context extension, MSA-CPT is within about ±2 points of full attention on HELMET-128K and RULER-128K subsets (e.g. Rerank/RAG -2.1) [Section 5.3, Table 3]. The authors list "closing the residual long-context retrieval gap" via longer training, larger budget, or a richer indexer as next steps [Section 7].


### Goal: What is MSA's inference cost profile (what still grows with N per decoded token), and how close is measured speedup to the FLOP reduction?
Eq 12: F_GQA = 2 H_q d_h N^2 vs F_MSA = H_kv d_idx N^2 (Index Branch) + 4 H_q d_h N k B_k (Main Branch) [full text, Section 3.3]. So per decoded token the index branch still scans all N keys (with H_kv index-query heads and one shared index key head), while main attention is fixed at k*B_k = 16 x 128 = 2048 tokens; the full GQA KV cache is still stored. At 1M context: 28.4x lower per-token attention FLOPs, but measured 14.2x prefill and 7.6x decode speedup (64 q heads, 4 KV heads, d_h=128) [Section 1; Section 5.4, Figure 4]. The authors attribute the gap to "index construction, top-k selection, reverse-index materialization, query gathering, and load-balancing overheads" and less regular memory access [Section 5.4].

### Goal: Does MSA compare against a sliding window or a hybrid linear baseline, and what does it say about hybrids?
It positions itself against hybrids (MiniMax-01/M1 lightning attention, Qwen hybrids, SWA in gpt-oss/MiMo) and sparse attention (DSA, NSA, MoBA) [Section 1], choosing sparse softmax "to maximally reuse existing software and hardware infrastructure". The only structural baseline besides dense GQA is a FLOP-matched sink+sliding-window pattern, which has higher perplexity on agent tasks throughout training [Appendix B.6, Figure 14]. No head-to-head against a linear-attention hybrid is reported. MSA supports "near-lossless conversion from pretrained GQA checkpoints" [Section 1].
