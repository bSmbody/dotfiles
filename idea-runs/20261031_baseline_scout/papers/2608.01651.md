# Bole: Efficient Tree Speculation for Hybrid-Attention Language Models

## What this paper does
Bole is a kernel-runtime co-design for tree speculative decoding on hybrid models (Gated-DeltaNet linear attention plus full attention, e.g. Qwen3.5). It recasts the gated-delta recurrence over a draft tree in a closed form and verifies all tree nodes in parallel in one kernel (3.4-7.7x faster linear-attention tree verification). It encodes speculative state updates as token-level factors and reconstructs only the accepted state, which cuts transient state memory by 82-99x. It adds hardware-aware batch-level verification budgeting and is integrated into SGLang. The drafter is each model's native MTP head.

## Goal-by-goal answers
### Goal: What is the problem specific to SD on hybrid models?
Existing engines verify recurrent layers node by node (T sequential steps) and snapshot the full GDN state at every tree node [Section II-C]. Going from 8 to 64 tree nodes raises the linear layers' share of the target forward from 4% to 27%. Snapshots on Qwen3.5-122B-A10B (4xA100, T=32) take 36 GiB at B=8 and 72 GiB at B=16, displacing KV-cache capacity. For one request with a 100-node tree, snapshots take 4.7-14.1 GB vs 57-151 MB for factors [Section II-C, Fig 1, Table I].

### Goal: What speedups, and how do they change with batch?
Qwen3.5-4B/9B/27B/122B-A10B on A100 and GB10, MTP drafter, top-k=4, depth 8, workloads MBPP/GSM8K/ShareGPT/CNN-DM plus an online SWE-agent trace [Section VI-A]. Geometric-mean speedup is 2.74x over SGLang-AR and 1.26x over the best speculative baseline. Peaks: 3.62x on A100 and 4.72x on GB10 over AR [Section VI-B]. On GB10 the advantage over the best speculative baseline grows from 1.11-1.14x at bs=1 to 1.70-2.03x at bs=8 [Section VI-B]. Long-CoT generation length is not the focus; the offline workloads are short-output benchmarks.

### Goal: Limitations?
No explicit limitations section in the parts read. Implicitly, Bole fixes the verification side only. It uses the shipped MTP head as drafter and does not improve drafting or acceptance. Custom kernels for the GDN tree closed form are required (an engineering cost).

# Bole: Efficient Tree Speculation for Hybrid-Attention Language Models

## What this paper does
Kernel-runtime co-design for tree speculative decoding on GDN-based hybrid models (Qwen3.5 family). It derives a closed-form, tree-structured version of the linear-attention recurrence so all proposal nodes are verified in parallel, stores speculative state updates as token-level factors instead of per-node full states, reconstructs only the accepted branch's state, and calibrates a batch-wide verification budget. Integrated into SGLang; evaluated on four Qwen3.5 models on A100 and GB10.

## Goal-by-goal answers
### Goal: Why does speculative decoding break down on hybrids, with what measured magnitudes?
(L1) Each tree node needs its parent's recurrent state, so existing engines run T sequential recurrent steps; growing the tree from 8 to 64 nodes raises the linear layers' share of the target forward from 4% to 27% [full text, Section II-C, Fig. 1(a)]. (L2) Engines materialize a full GDN state per tree node: on Qwen3.5-122B-A10B (4xA100-80GB), T=32 snapshots take 36 GiB at B=8 and 72 GiB at B=16 [Section II-C, Fig. 1(b)]. Per-request linear state is 48 MB (Qwen3.5-4B/9B) and 144 MB (27B, 122B-A10B); snapshots for T=100 are 4.7 GB / 14.1 GB [Table I].

### Goal: What does Bole achieve and what remains?
Linear-attention tree verification 3.4-7.7x faster; transient state memory 82-99x smaller (57-151 MB at T=100); up to 4.72x offline decode throughput over autoregressive and up to 2.03x over the strongest tree-serving baseline; online agent TTFT/TPOT down up to 67.6%/49.9% [Abstract; Section VIII]. Mean accepted tokens are similar across SGLang-Tree, AdaServe and Bole (e.g. MBPP 6.57/6.68/6.70) [Table V], so the gains are systems-side. Workloads are short-generation (MBPP, GSM8K, ShareGPT, CNN/DM); long-CoT generation at 32K+ is not evaluated in the sections read.
