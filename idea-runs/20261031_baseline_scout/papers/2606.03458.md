# KVarN: Variance-Normalized KV-Cache Quantization Mitigates Error Accumulation in Reasoning Tasks

## What this paper does
Argues that prior KV quantizers are evaluated in prefill-like settings, while in long decoding the quantized cache feeds later layers and timesteps so errors accumulate, driven mainly by wrong per-token scales (magnitude error). KVarN applies a QuaRot-style Hadamard rotation over channels, then a Sinkhorn-style iterative dual-axis variance normalization (token and channel scales) before 2-bit RTN, calibration-free. Introduces a "pseudo-decode" evaluation that quantizes every b-token block. Reports SOTA 2-bit results on AIME24, MATH500, HumanEval, IFEval; vLLM implementation released.

## Goal-by-goal answers
### Goal: What models, lengths and headline results are reported?
Qwen3-4B, Phi-4-14B (reasoning), Llama-3.1-8B [full text, Section 4.1]. AIME24 / MATH500 at ~2.3 bits/element: Qwen3-4B FP16 61.1/82.6, KVarN 60.0/79.2, KIVI 55.5/77.8, QuaRot 56.7/78.9, TurboQuant (3/3, 4.6 bits) 48.9/77.0; Phi-4-14B FP16 62.2/84.9, KVarN 61.7/84.8, KIVI 57.8/74.4 [Section 4.1.1, Table 1]. Token counts: KVQuant-1% inflates Qwen3-4B MATH500 output from 3857 to 5021 tokens, KVarN 3925 [Table 1]. Bits include scales: 2 bits + two FP8 scales + one FP16 zero per 128 = 2.25 bits [Appendix D].
### Goal: What runtime overhead and framework support exist?
Normalization of each 128-token chunk takes 1.9 ms vs 1050 ms to generate 128 tokens in vLLM (0.18%) [Section 4.2]; dual-scale dequant within 1.4% of KIVI in a fused Triton kernel [Appendix I]. Code: https://github.com/huawei-csl/KVarN (vLLM) [abstract]. TurboQuant was run from the community vLLM PR #38479, which leaves the first and last two layers in FP16 [Appendix D].
### Goal: What limitations do the authors state?
Not for SSMs; "it is unclear how [MLA] affect[s] quantization quality"; "End-to-end evaluation on a publicly available serving framework is hindered by the fact that currently such frameworks do not support 2-bit KV-Caches" [Appendix E]. Eviction methods are compared only on line retrieval with prompt-only compression [Appendix F, Table 5].
