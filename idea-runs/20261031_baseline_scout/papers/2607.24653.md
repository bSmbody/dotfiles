# Kimi K3: Open Frontier Intelligence

## What this paper does
Technical report of Kimi K3 (2.8T total / 104B active MoE, 1M context, native vision). Sequence mixing is a layerwise hybrid of Kimi Delta Attention and Gated MLA (3 KDA : 1 Gated MLA per block, plus one extra MLA layer at the end), with NoPE on MLA and a channel-wise full-rank output gate on MLA. Also Attention Residuals across depth, Stable LatentMoE (16 of 896 experts), and a large infrastructure section with KDA kernels (FlashKDA), KDA context parallelism, KDA-aware prefix caching, and speculative-decoding-aware KDA decode kernels.

## Goal-by-goal answers
### Goal: What hybrid attention does K3 ship and what does each cache grow with?
"Each block contains 3 KDA layers followed by 1 Gated MLA layer, giving a 3:1 mixing ratio"; an additional Gated MLA layer at the end; NoPE on all MLA layers following Kimi Linear; MLA gets an input-dependent channel-wise output gate [full text, Section 2.1, 2.1.2]. "The MLA KV cache grows with sequence length and is paged per token, whereas the KDA recurrent state is fixed in size with a single copy per request" [Section 5.4.1].

### Goal: What inference-side problems of the hybrid do the authors report and how do they handle them?
Prefix caching: a hit is reusable only if the KDA state at that boundary was persisted; state snapshots are "affordable only at sparse boundaries", which forced the shared block size to 1024-6144 tokens, at which "caching is nearly useless"; they decouple hash granularity (512-token hash blocks) from the allocation block, keep checkpoints at hash endpoints and retain those at conversation-turn boundaries [Section 5.4.1, Figure 12]. Speculative decoding: in-place state updates cannot be rolled back after rejected drafts; per-draft snapshots "would also multiply state traffic — a cost that dominates at the large batch sizes typical of online serving"; they cache only projected inputs and rebuild accepted states on-chip in a fused kernel (similar to concurrent ReplaySSM) [Section 5.4.2]. No numbers on cache-hit rate loss or verification latency are given in the sections read.
