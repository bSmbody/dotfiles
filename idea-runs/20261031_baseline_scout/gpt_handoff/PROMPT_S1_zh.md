# 给 GPT 的选题 prompt：长思维链解码阶段的 KV 压缩（新开对话，整段复制粘贴）

---

你是一位资深的机器学习研究员，在帮一位刚入学的博士生在**一个已经定好的 scope**里出 idea。他的组里有大约 1 TB 显存的 H200 集群（约 8 张卡），算力不受限。他本人是新手：方法原型可以自己写，但 kernel 要靠组里的人。请**联网检索到今天为止的最新论文**（arXiv、OpenReview、会议论文集），提出**方法层面**的 idea，目标是 NeurIPS / ICML / ICLR / MLSys 主会。

## 一、Scope（不要跳出这个范围）

**在长思维链（16K–64K 生成 token）的解码阶段压缩 KV cache，让推理模型在显存打满的真实服务条件下，"每解出一道题"的墙钟时间和显存都更少。** 只在准确率上无损是不够的，还必须不让推理变长。

这个 scope 是先读了 32 篇最新的 baseline 论文才定下来的。三个独立的调研方向得出了同样的结论：
1. **长 CoT 服务的瓶颈是 KV 显存容量。**
   - 稀疏注意力只减少 KV 的读取，不减少 KV 的占用。GLM-5.1 一个 128K 请求占 13.09 GB KV，8×H200 在 128K 下只能同时跑约 15 个请求（arXiv 2608.07009）。
   - 所有无损的投机解码都要保留完整的 BF16 KV，所以 batch 被显存卡住。ASPIRE 在 Qwen3-8B 上只能开到 B=30（2609.17943）；Dustin 自己承认不减少显存（2606.24957）。
2. **"长生成"是被测得最少的场景。** 多数论文测的是长 prompt 加 90 个 token 左右的输出。TurboQuant 在 prefill 类任务上接近无损，但在长 CoT 解码中，4.6 bit 还不如 2-bit KIVI（2504.19874 对比 2606.03458 Table 1）。
3. **token 少不等于时间少，准确率不变也不等于成本不变。** KV 量化可能让输出长度膨胀到 5.1 倍；ThinKV 只做思维自适应量化时，吞吐只提高 1.1×，原因就是输出变长（2510.01290 §6.3）。

## 二、这个 scope 里已经确认的事实（请当作约束，并自行核实）

1. **KV 量化会让推理变长。** ThinKV 测到纯 KV 量化让 R1-Llama-8B 的输出长度最多变成 5.1 倍（2510.01290 §6.3 Table 4）。KVQuant-1% 让 Qwen3-4B 在 MATH500 上的输出从 3857 涨到 5021 token（2606.03458 Table 1）。淘汰预算太低时，模型会陷入不终止的循环（2512.12008 §4.7）。
2. **"权重量化让推理变长"已经有人研究过，但都只针对权重：**
   - 2606.25519 提出了 CTIR 指标。结论是 INT4/INT3 权重量化能保住准确率，但推理会变长；只有 QAT 能同时改善两者（Pareto 改进）。
   - 2606.02011 研究 2-bit 权重量化下的"循环 / 迟迟不下结论"失败模式。做法是检测到循环后直接提交答案，或者用 FP16 从头重跑，加上 FP16 规划步。
   - 两篇都是 **weight-only**。"KV 量化让推理变长"目前只在 ThinKV 和 KVarN 里顺带出现，还没有方法专门针对它。
3. **离线代理指标会选错分配方案。** 在相同字节数下，离线失真曲线在 3 个模型里有 2 个选错了 bit 宽：Qwen3-8B 离线选 4 bit，端到端最优是 2 bit（2610.05685 §1、§5.3）。OSCAR 的最优性只在"冻结误差"的假设下成立（2605.17757 附录 D）。
4. **同一类方法在不同论文里结果差别极大。** QuaRot-INT2 在 Qwen3-4B 上 AIME24 能到 56.7（2606.03458），在 Qwen3-4B-Thinking-2507 上 AIME25 却是 0.00（2605.17757）。TurboQuant 是否保留首尾两层为 BF16，会改变它在排名中的位置（2606.20474 §6.3）。BF16 sink/recent 窗口大小、元数据是否算进 bit 数，各篇也都不一样。
5. **4-bit KV 只有在显存不够时才比 FP8 快。** FP4 KV 加 Hadamard 旋转后吞吐和 FP8 持平（1.38× 对 1.37×），字节数只有一半，但只有当上下文或并发超过 FP8 的显存容量时才更快（2606.20474 §9）。
6. **淘汰和量化在长 CoT 中的互动有争议。** ThinKV 说淘汰不会让输出变长；另外两篇（2512.12008、2610.05685）说会。差别来自淘汰策略不同。在固定字节数下，用更多 token、更低精度，通常比用更少 token、更高精度好（2610.05685）。
7. **推理任务上，只要保住 prompt，随机淘汰就和 SnapKV / R-KV 等方法相当**（2609.03430）。但单次出现的 passcode 远距离检索是一个重要反例。
8. **KV 缓存的任何微小差异都会改变后续轨迹。** BF16 舍入级别的 KV 差异就会让 83% 的贪心后缀分叉，首次分叉的中位位置在第 88 个 token（2607.28495）。所以任何"要求两条轨迹逐 token 一致"的方法都不可行，评测只能比较分布和统计量。
9. **精确卸载（所有 KV 都取回并参与计算）不伤准确率**，但选择性回读不能自动算作无损（2605.09490）。
10. **低比特分层缺一个便宜又可靠的触发信号。** 加一个 INT2 层，能把被丢弃的未来注意力质量从 64.8% 降到 35.7%（2608.05326）。但 sound 证书在 4 bit 时松了 1289 倍，在 1–2 bit 时完全空洞（2607.28699）。

## 三、三个开放的切入点（可以在其中做，也可以提出更好的；更好的要说明为什么更好）

**(a) 把轨迹健康状况作为信号，在线调整 KV 精度。** 出现循环、反思词密集、长度失控时，在线把相关块的 KV 精度提上去，而不是从头重跑。
- 必须正面区分的近邻：2606.02011（权重量化，循环检测加 FP16 从头重跑）、ThinKV（按思维类型静态分配精度）、QEvict / 2608.05326（按累计注意力在精度层之间升降）、PM-KVQ（预算用满后逐级降低位宽）。
- 关键风险：如果最强的 KV 量化器（KVarN 2.3 bit）本身几乎不让推理变长，这个切入点就不成立。

**(b) 一个能反映端到端误差累积的分配代理指标。** 用一个便宜的信号，正确预测哪种 bit / token / 层分配在长生成里每题成本最低。
- 近邻：KVTuner、PM-KVQ、MultiAlloc（2610.18642，离线、静态、依赖校准数据）；KVarN 的 pseudo-decode 协议只用于诊断，没有用于分配。

**(c) 把省下来的显存换成更大的 batch，同时保证输出不偏。** 设计让 verifier 读取压缩 cache 的 draft/verify 方案，带精确性或有界误差保证，并在显存打满的 batch、16–64K 长度的 CoT 上评测。
- 近邻：QuantSpec（INT4 draft + INT8 verify，只测了 bs=1、90 token）、VeriCache（2605.17613，压缩 draft + 完整 KV 验证）、Vegas / ASPIRE（稀疏自投机，保留全部 KV）。
- 工程量最大。

## 四、硬性要求（缺任何一条，这个 idea 作废）

**A. 从有数字的瓶颈出发。** 引用具体的论文、章节和数字。

**B. 成本账。** 写出每个 token 的 FLOPs、HBM 字节数、额外工作区（scale、码本、BF16 窗口、元数据都要算），和最强的融合实现对比：FP8 KV、KVarN 的 vLLM kernel、FlashDecoding。按 H200 计算：HBM 约 4.8 TB/s，BF16 dense 约 1 PFLOP/s。写清楚收益在 batch 和长度的什么区间成立。**账算不过来的不要提。**

**C. 关键假设要有量级证据。** 给出已发表论文中实测的量级。找不到的，就把"测量这个量级"写成第一周的 kill test，并在排序时降级。

**D. 近 30 天检索。** 为每个 idea 单独检索最近 30 天的 arXiv，列出最接近的 3 篇近期论文及差别。特别要排查近邻：KVarN、OSCAR、OptR（2608.02691）、TurboQuant、PM-KVQ、ThinKV、KVTuner、MultiAlloc、Spend Bytes on Breadth、QEvict、WitCert、QuantSpec、VeriCache，以及 2606.25519 和 2606.02011。**找不到确切论文就写"未找到"，不要编造标题或编号。**

**E. 一句话死刑测试。** 写正文之前，先写出领域专家最可能否掉它的那句话，然后在正文里正面回应。

**F. 评测协议要统一。** 所有方法在相同字节数下比较（scale、BF16 窗口、保护层都计入）。报告准确率、生成 token 数、撞长度上限或循环的比例、每解出一题的墙钟时间，batch 从 1 扫到显存打满。AIME 要 avg@16 以上，只能比较分布，不能要求轨迹一致。

## 五、已经被否掉的方向（不要再提）

- KV 淘汰按"事实覆盖度 / k 份拷贝 / 熵或意外度 / 重算代价"打分（预算紧时覆盖不过来；见事实 7、8）
- 用"双胞胎解码"给每次淘汰算功劳（见事实 8）
- 混合模型里借用状态精度来推迟 KV 降级（KVpop、LazyEviction、BreadthKV 已有；而且"借出去的"永远还不回来）
- PQ 码组合统计 + Tensor-Train 读取（省不掉 top-k 扫描；Transformer-VQ 和 RAM-Net 已有）
- MLA 量化的 score/value 联合误差证书（latent 只占约 7.5% 的 logit；2–4 bit 下按格子求的最坏界本身就空洞）
- 低秩 pre-RoPE K + NUFFT（频率太少，算不过直接矩阵乘；Palu 已做融合重建）
- 只是"发现量化让推理变长"、不给方法的测量研究（2606.25519 已经做了权重的版本）
