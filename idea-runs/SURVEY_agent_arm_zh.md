# Agent 操作机械臂：工作现状与解决问题的方向（2026-10-26）

**材料来源**
- IdeaScientist 三轮具身 lane 读过的约 160 篇论文摘要，正文读过的存在 `idea-runs/*/papers/`；
- 本次补查的 2026-10-10 之后约 30 篇新工作，只读了摘要。

几乎都是近两个月的 arXiv 预印本，大多没有经过同行评审，下文数字都取自原文摘要或正文。

---

## 一、整体格局

**1. 分工被打乱了。**
- 原来的标准范式是双系统：VLM 做高层规划，VLA 高频出动作（π0 [2410.24164]、π0.5 [2504.16054]、Hi Robot [2502.19417]）。
- 2026 年 9 月 GPT-6 Astra 发布后，“前沿模型直接控制机械臂”第一次在公开榜单上打赢了专用策略：
  - RoboDojo 42 个任务上 22.5%，超过全部 40 个公开策略。同样设置下 GPT-5.5 只有 0.9% [2609.24170]。
  - RoboMME 记忆类任务上 92.1% [2610.17350]。
  - 触觉任务上：UniVTAC/OpenViTac 平均 93.8% / 81.8%，比最强专用基线高 22.9 / 13.1 个百分点 [2610.26846]；另一篇报告 UniVTAC 五个任务平均 93.8%，插孔任务加触觉后从 31% 提到 99% [2610.28457]。

**2. 进步速度极快。**
- 在真机 RoboDojo 子集上，9 个前沿模型从 7 月到 10 月的成绩折算下来，性能翻倍时间约 **54 天**。
- 同期最高执行速度提升 4.4 倍，最低执行成本降到 1/6.2 [2610.25287]。
- 这意味着任何“绕过前沿模型某个短板”的工作，保质期可能只有几个月。

**3. 能力两极分化（多篇独立评测结论一致）。**
- 擅长语义理解、指令跟随、空间推理。
- 不擅长高精度、动态控制、复杂双臂协作 [2609.24170]、[2610.27865]、[2610.30051]。
- 在 LIBERO-10 上，最好的是 Astra 的 44%，其次是 Gemini-4 Argon 的 43%。提高推理强度一般有帮助，但成本更高 [2610.30051]。

**4. 真机是硬约束。**
- SenseNova 在 8 种机器人配置上的结论有两条 [2610.22471]：
  - ICL 需要的示范很贵；
  - 真机上“用更长执行时间换成功率”这条路基本行不通。
- 他们给出的未来方向：ICL 的通用性、成本与执行时间、物理状态校验、从不可逆失败中恢复、长程进度的保持。

**5. 已经有两篇综述把这个方向系统化。**
- “Model / Data / Environment / Harness” 四大块、17 类 [2610.20442]。
- PAPAV 五能力框架：感知、预判、规划、执行、校验。它统计了 64 个基准，只有 5 个评“预判”，3 个评“校验” [2610.30108]。

## 二、系统架构：六条路线

| 路线 | 做法 | 代表工作与关键数字 | 拥挤程度 |
|---|---|---|---|
| **A. 前沿模型直接当策略** | 看图后输出末端位姿增量或动作原语，工具化接口 | GPT-GEAR：RoboDojo 26.9%，RoboTwin 2.0 76.0%，真机零样本 40%、一次示范后 80%，但每回合 8–28 分钟 [2610.28259]；RoboICL [2609.34261]；Agent2Act 四模型对比 [2610.27865] | 高。以评测报告为主，方法空间被模型进步吞掉 |
| **B. 代码即策略 / 编码 agent** | agent 写程序组合原语，自检、重试、改代码 | PyRUA-Lean：成功率 63.1%→71.7%，LLM 调用少 49% [2610.01939]；HexaShell [2610.23479]；RAX [2610.22496]；FORCA 把力/力矩读数加进编码 agent，5 个真机接触任务 [2610.31841] | 很高 |
| **C. 感知工具化的 harness** | 把深度、测量、虚拟视角等做成工具或脚手架 | SpatialHarness：同步一个仿真场景，给 Astra 渲染补充视角，真机精细操作提升明显 [2610.12457]；Robo-Harness K1 [2609.29389] | 中 |
| **D. VLA 执行、前沿模型按需介入** | 小模型跑常规动作，关键时刻调大模型 | CALL：LIBERO 97.5%，Astra 只执行 5.5% 的步数，每回合约 5k token [2610.14117]；求助调度的决策论分析 [2610.21160]；AEGIS [2606.06660]；SenseNova 认为 Astra 加 π0.5 闭环“贵但有效” [2610.22471] | 高（我们第二轮的 escalation lane 就死在这里） |
| **E. 分层 VLA / 编排器** | VLM 选子任务和指代，VLA 执行 | 系统性消融研究 [2606.10267]；VP-VLA [2603.22003]；2AM [2609.11308]；Steerable VLA [2602.13193]；移动操作中原子技能 80%、组合后只有 19%，做诊断和干预后提到 47% [2610.19600] | 高 |
| **F. 世界模型与 agent 结合** | 代码规划和视频/动作预测联合生成 | Agentic World Action Model AW-0 [2610.30136]；RoboJEPA [2610.10515]（只看了标题） | 新，但需要大算力 |

## 三、横向能力模块：做到哪了

**1. 长程与记忆**
- Ledger 用物体台账，RoboMME 上 64.3% [2609.34554]。
- AGM 只有在物理成就被确认后才推进进度指针 [2608.29537]。
- SERA 让 harness 自我进化，RoboMME 从 44.4% 提到 51.4% [2610.29560]。
- 基准：LADDER 中单子目标 85.4%，多子目标崩到 21–23%，Astra 做工具选择时约 62% 但成本高 [2610.18053]；Embodied Playground 共 410 个环境 [2610.27039]。

**2. 失败检测与恢复**
- VLA 内部探针类：SAFE [2506.09937]、FailureSpot [2609.04277]、Foresight [2606.23085]、ReAP [2610.16309]。
- VLM 裁判类：Guardian [2512.01946]、AHA [2410.00371]。
- 大脑预先布置恢复分支：Code-as-Monitor [2412.04455]、DoReMi [2307.00329]、AgentChord [2605.11951]。
- 两个关键的负面结果：
  - **报警太晚**：RESCUE 发现监控器的报警常常落在“还能挽回”的时点之后；把报警交给脚本化恢复，而不是停机重置，超额成本能降 3.1–13.4 倍 [2610.13516]。
  - **VLM 判断成败不可靠**：最好的 VLM 裁判平衡准确率只有 0.77，接触类任务 ≤ 0.60 [2609.03611]。

**3. 自我改进与经验沉淀（10 月最热的子方向）**
- SEAR：7 个模型、330 个仿真任务加 5 个真机任务，跑了累计 4 年的 agent 运行时间，用对照实验区分“真在学”和“只是多试几次” [2610.18792]。三个结论：
  - 难任务才值得长会话；
  - 控制代码和公共例程能跨任务、跨仿真器迁移，任务专属解法不能；
  - 真机上，agent 自己设计的练习场景和人设计的新场景之间有落差。
- EmbodiedEvo：把物理反馈沉淀成 Skills 和 Lessons，RoboDojo-Sim 上 37.8%。Astra 的经验能让 Sol / Luna 提高 8.9 / 5.5 个百分点 [2610.18867]。
- ReTrace：跨阶段的失败归因，真机插头从 0% 提到 80% [2610.15814]。
- AdaRSI：先改 harness，把持续失败归因到“调用方式”还是“能力缺失”，再只微调执行器不可靠的子步骤 [2610.20474]。
- Robo-COP：编排器和策略在部署中共同进化，64.8%→73.8% [2610.09228]。

**4. 小模型后训练（让开源模型当规划器）**
- AgenticRoboRL：9B 规划器用 SFT 加多轮 RL，在 LIBERO-PRO 上从 18.1% 提到 71.0%，接近 Codex（GPT-5.5）加外部记忆的 72.1% [2610.28589]。
- PyRUA-Lean Coder 4B：用 GRPO 从 18.8% 提到 44.1% [2610.01939]。
- 数据侧：FLORA 做奖励和标注，约为 Astra 成本的 1/125 [2610.31779]；用前沿模型自动生成示范来训练本地策略 [2610.03615]。

**5. 接口：agent 怎么“说”给 VLA 听**
- VLA 对措辞敏感 [2610.10526]、[2610.19438]。
- VLA 编码了指令，却不用它来选目标 [2610.06235]。
- VLA 听不懂关系指代 [2610.12696]；人会省略的信息，策略补不回来 [2610.17746]。
- 现有解法：改写规则 [2610.10526]、学说话策略 [2606.12299]、语言空间 RL [2606.31958]、视觉提示 [2603.22003]、[2512.20014]。

**6. 实时性与延迟**（第三轮查新的结论）
- 低层 VLA 的异步推理已经很成熟：EagleVLA [2607.12659]、RAVEL [2609.34170]、REACT [2610.12007]、FlashVLA [2608.27384]、DynamicVLA/DOM [2601.22153]。
- 前沿大脑这一层基本没人管：要么暂停仿真，要么让执行器干等。
- 这一层可借鉴的经典方法很成熟：AESOP [2407.08735]、Hindsight Optimization [1503.07619]、contingency planning [2101.06547]、Smith predictor [2010.05486]。
- RT-Safe 证明暂停式评测会掩盖问题：导航中碰撞多 12.3 倍，其中约 84% 发生在推理时干等 [2610.09294]。

**7. 触觉与力**
- Astra 能直接读视触觉图像 [2610.26846]、[2610.28457]。
- TacZero 把三轴触觉数值叠加在图像上，做免训练插孔 [2610.07621]。
- FORCA 让编码 agent 读力/力矩日志来诊断和修改控制逻辑 [2610.31841]。

**8. 仿真与数据**
- 用 agent 做 real-to-sim：Agentic RSR 从视频重建场景，再由编码 agent 开发策略，18 个场景都通过视觉校验 [2610.10479]；WorldMirror 从野外示范构建可交互的数字孪生 [2610.31834]。

**9. 安全**
- “问它时会拒绝，执行时照做”：Astra 通过 harness 控制 SO-101，面对“把刀放进玩具篮”这类指令 15 次 0 次拒绝，27% 真的完成了危害。
- 在动作前加一次“你会执行这条指令吗”的检查，15 条危险指令全部拦下，15 条正常指令一条也没误报 [2610.27350]。
- Inspect Robots 是开源评测框架，三个月下载近 10 万次 [2610.06306]。

## 四、还没解决的问题（按证据强度排序）

1. **精度、动态、双臂**：前沿模型的硬伤，多篇评测一致 [2609.24170]、[2610.27865]、[2610.30051]。一般靠 VLA 或经典控制补，但“大脑 + 手臂”的组合在这些任务上同样拖后腿。
2. **成本与执行时间**：每回合几分钟到几十分钟 [2610.28259]，真机上没法拿时间换成功率 [2610.22471]。所有 harness 工作本质上都在省调用次数和 token。
3. **物理状态的校验**：VLM 判不准接触类成败 [2609.03611]；64 个基准里只有 3 个评“校验” [2610.30108]；SenseNova 也把它列为方向之一 [2610.22471]。
4. **不可逆失败**：监控报警晚于可挽回时点 [2610.13516]，SenseNova 也明确列出这一点 [2610.22471]。
5. **长程组合**：原子技能 80% 组合后只有 19% [2610.19600]；LADDER 多子目标崩溃 [2610.18053]；跨阶段依赖导致“局部成功、后面失败” [2610.15814]。
6. **对单个闭源模型的依赖与复现性**：GPT-5.5 只有 0.9% [2609.24170]；结果随版本、harness、推理强度变化 [2610.27865]、[2610.30051]。
7. **自我改进到底学到了什么**：多试几次和真学到经验难以区分；真机上存在练习场景与新场景的落差 [2610.18792]。
8. **评测本身**：
   - 基准爆炸、口径不一；
   - 仿真器在大脑思考时暂停，看不到延迟 [2610.28259]、[2610.09294]；
   - 前沿模型每个任务只跑 10–50 回合；
   - ICL 示范的成本没算进去 [2610.22471]。
9. **安全**：执行模式下的有害指令几乎没有防护 [2610.27350]。

## 五、解决问题的方向：哪里拥挤、哪里还有空间

**我们三轮跑下来的教训**
- “前沿模型 + 某个经典机制”的方法类组合，几乎都会被拆回已有工作：
  - 求助时机 → Ask4Help、When2Ask、CALL；
  - 接口 → CoVer-VLA；
  - 延迟 → AESOP 和 Hindsight Optimization。
- 方法类、免训练的小改动，在这个领域的保质期可能只有几周。

| 方向 | 解决哪个问题 | 现状 | 空间 | 算力 |
|---|---|---|---|---|
| **物理状态校验（Verify）**：判断“这一步在物理上真的成功了吗”，包括接触、抓稳、放到位 | 3、4、5 | 只有 VLM 裁判，接触类 ≤ 0.60；AGM 用专门校验器；FORCA 用力/力矩 | **较大**：基准和方法都缺，审稿人容易认可“被低估的能力” | 低（仿真 + 小模型） |
| **实时 / 不暂停的评测协议** | 2、8 | 只在导航上有（RT-Safe），操作类空白 | 中到大：适合 D&B 类论文；第三轮 AC 估计约 4–5 分 | 低 |
| **小模型规划器的 RL 后训练** | 2、6 | AgenticRoboRL（9B，18→71%）、PyRUA Coder 4B | 中：刚起步但有人在做；契合 RL 后训练经验；要注意 OpenAI 条款，最好用自己环境的奖励，不蒸馏 Astra 输出 | 中（几十卡·日） |
| **执行模式下的安全** | 9 | 只有 4 页 workshop 论文和一个评测框架 | **较大**：问题清楚，评测便宜；CVPR 契合度一般，更适合 CoRL 或安全类 venue | 低 |
| **不可逆失败与“可挽回窗口”** | 4 | RESCUE 只做评测，AgentChord 做静态场景 | 中：需要找到前沿模型做不到、局部又能做的点 | 低到中 |
| **自我改进的科学评测** | 7 | SEAR 刚做了大规模对照 | 小：SEAR 已占住 | 高（API 成本） |
| 前沿模型直接控制 / 代码策略 / harness 新招 | 1、2 | 每周都有新论文 | 小 | 低 |
| 求助调度、VLA 接口、低层异步 VLA | 2、5 | 已非常拥挤 | 小 | 低 |
| 世界模型 + agent | 5 | 刚出现（AW-0） | 中 | **高** |

**我的推荐**：如果还要在这个方向找 5/10 的题，优先看“物理状态校验”和“实时评测协议”。

理由：
1. **问题是前沿模型自身变强也解决不了的。** 校验需要传感器和物理信息；延迟和评测口径是系统层面的问题。
2. **它们是“发现 + 基准 + 方法”型贡献，而不是一个小机制。** 对 CVPR 审稿人更有分量，也更不怕被拆回经典方法。
3. **算力低。** 主要是仿真加少量 API，和低算力约束一致。

**主要风险**
- 基准类论文要覆盖多个模型、多个任务，工程量不小；
- 离 CVPR 截稿（11/16）只剩约三周，赶 CVPR 很紧，更现实的目标可能是之后的 CoRL / RSS / NeurIPS D&B。
