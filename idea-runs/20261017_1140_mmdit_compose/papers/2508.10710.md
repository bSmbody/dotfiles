# CountCluster: Training-Free Object Quantity Guidance with Cross-Attention Map Clustering for Text-to-Image Generation

## What this paper does
CountCluster controls object count without external modules by optimizing the latent once, at the first denoising step. It thresholds the object token's cross-attention map (tau=0.35), adjusts the connected components to exactly k (drop smallest regions, or split the largest with K-means), turns each into a Gaussian target, and minimizes a per-cluster KL appearance loss plus a LogSumExp separation loss that suppresses activation outside clusters. Evaluated on SD2.1 and SDXL with "a photo of [count] [object]" prompts (2–10), it beats Counting Guidance, TokenOpt and CountGen on CountGD/TIFA accuracy with near-base cost.

## Goal-by-goal answers
### Goal: What mechanism does it use for count control and at which timestep(s)?
The premise is that instance number is "largely determined in the early timesteps", with high-activation clusters in the object cross-attention map (CAM) predicting the count [full text, Section 1]. At the first step only, the CAM is thresholded, connected components are forced to k (remove small regions, or split the largest by K-means), each cluster becomes a Gaussian with value 1 at the center and tau at the boundary, and the latent takes one gradient step on L_appear (KL per cluster, scaled by 1/sqrt(k)) + L_sep (ReLU(LogSumExp(A - tau)) outside clusters) [full text, Section 3.3.1, 3.3.2, Eq 2-6]. The target is built by editing the model's own first-step attention, not from a separate instance representation.

### Goal: What happens when the optimization is applied over more timesteps or with random targets?
Random Gaussian cluster targets give only modest gains: gradients are "misaligned with the diffusion model's natural denoising process" [full text, Section 3.2, Section 5.1]. Optimizing over steps 50 to 25 reaches the count but degrades quality and yields "highly unstable predictions and large RMSE", so the method restricts itself to one step [full text, Section 3.2, Section 5.1]. Accuracy falls as the count rises for all methods; the authors note peaks at 4 and 9, likely from grid layouts the model favors [full text, Section 5.2]. On the T2I-CompBench count set, SDXL+CountCluster loses some ImageReward against base SDXL (0.368 vs 0.379) [full text, Appendix E, Table 11].

### Goal: Which backbones and prompt types does it cover; does it address MM-DiT or spatial relations?
Only U-Net backbones (SD2.1, SDXL) [full text, Section 4.1]. Prompts are single-category "a photo of [count] [object]" templates; complex prompts are shown only qualitatively [full text, Section 4.1, 5.2]. There is no relational term and no MM-DiT experiment.
