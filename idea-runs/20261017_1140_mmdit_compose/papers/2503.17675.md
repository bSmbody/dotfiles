# Towards Transformer-Based Aligned Generation with Self-Coherence Guidance

## What this paper does
CVPR 2025. Training-free attribute/style binding for transformer T2I models. At step t, a mask for each concept token is extracted from the layer-averaged cross-attention of step t+1 (K-means into two clusters, or an LLM-estimated area ratio for part-level binding), and the attribute token's cross-attention inside that mask is multiplied by c = 4, replacing the map directly rather than taking latent gradients. Main experiments are on PixArt-alpha-512 (separate cross-attention), with new coarse, fine-grained and style binding benchmarks; FLUX appears only qualitatively in the appendix.

## Goal-by-goal answers

### Goal: What mechanism does it use against attribute leakage or object omission, and which part of MM-DiT joint attention (image-to-text, text-to-image, text-to-text, image-to-image quadrant, or token states) does it read or modify?
Map edit: (A_hat_t)_{p,q} = c (A_t)_{p,q} if q is attribute token r_i and M^{o_i}_{t+1}[p] = 1 (Eq 2) [full text, Section 3.2]. Masks come from K-means on the averaged map (coarse binding, style) or top-ratio selection with an LLM-inferred part ratio (fine binding) [full text, Section 3.2]. On FLUX, "we still treat the dot product between the image queries and text keys as the cross-attention map on which our method operates" [full text, Section 10]: only the image-to-text quadrant is edited.

### Goal: Does it account for text tokens being rewritten by image tokens across MM-DiT blocks, or does it treat text tokens as fixed keys or apply a uniform text-side transform?
Text tokens are fixed keys. The main backbone (PixArt-alpha) has no text stream, and the MM-DiT port edits only the image-query rows over text keys, leaving the text-query rows (text-to-image, text-to-text) and thus the text-token update untouched [full text, Section 3.1, Section 10].

### Goal: What limitation, failure case, quality or runtime cost, or external dependency (layout, LLM/VLM, fine-tuning) does it report on this axis?
Directly transferring U-Net methods (Divide-and-Bind, CONFORM) to a transformer binds only one attribute, lowers quality and can add an extra object [full text, Section 4.1]. Transformer maps are "more evenly distributed", making the core map harder to find [full text, Section 3.2]. Fine-grained binding needs an LLM [full text, Section 9]. MM-DiT evidence is qualitative only (Fig 8) [full text, Section 10].
