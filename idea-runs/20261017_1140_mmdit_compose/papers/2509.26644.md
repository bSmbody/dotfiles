# Stitch: Training-Free Position Control in Multimodal Diffusion Transformers

## What this paper does
Stitch adds training-free position control to MM-DiT flow models (FLUX, SD3.5, Qwen-Image). An LLM (GPT-5/GPT-4) splits the prompt into object sub-prompts with bounding boxes on a 32x32 grid, plus a background prompt. Each object is generated separately for the first S steps (S=10 of 50 on FLUX/SD3.5) under hard joint-attention masks (Region Binding). A selected text-to-image attention head then cuts out each object's latent tokens (Cutout); these are pasted onto the background latent and the image is finished unconstrained with the full prompt. On the PosEval benchmark it raises FLUX from 22% to 70% on 2-object position.

## Goal-by-goal answers
### Goal: How does it impose positions in MM-DiT and what external inputs are required?
An MLLM produces sub-prompts p_k and boxes b_k [full text, Section 3.2]. For S steps the model runs one masked generation per object plus a background generation. In every layer and head, attention is blocked from inside-box image tokens to outside, from outside-box image tokens to the sub-prompt text, and from the sub-prompt text to outside-box tokens [full text, Section 3.2, Region Binding]. Cutout ranks visual tokens by the attention they receive from non-padding text tokens in one model-specific head (e.g., FLUX block 14, head 20: IoU 62%, IoT 92% vs SAM), keeping tokens up to fraction eta=0.95 [full text, Section 3.2, 5.2]. Positions therefore come entirely from LLM-generated boxes (GPT-5/GPT-4) [full text, Section 5].

### Goal: What trade-off does the hard masking create?
On FLUX, Region Binding alone gives 2-Obj 0.81 / 3-Obj 0.58 / 4-Obj 0.52, but 32% of images fail to blend (Blend 0.68). Adding Cutout raises Blend to 0.99 but cuts 2-Obj to 0.51; eta=0.95 recovers it to 0.70 (Blend 0.95) (Table 2) [full text, Section 6]. A longer constrained phase S raises position accuracy but lowers blend, with a steep drop between 10 and 20 steps (Fig. 8) [full text, Section 6]. Aesthetic score falls slightly (FLUX 6.3 to 6.1) [full text, Section 6].

### Goal: Does it handle counts?
Only through the LLM layout: each requested object instance needs its own box and sub-prompt, so the count is fixed by the external planner. The method has no mechanism to infer, check or correct instance count from the model's own state [full text, Section 3.2]. PosEval tasks contain 2–4 distinct objects with position relations, not counted repeats of one noun [full text, Section 4, 5.3].
