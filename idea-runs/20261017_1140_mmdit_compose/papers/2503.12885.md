# DreamRenderer: Taming Multi-Instance Attribute Control in Large-Scale Text-to-Image Models

## What this paper does
Training-free FLUX plug-in for depth- or canny-conditioned multi-instance generation with user boxes or masks. Hard Text Attribute Binding duplicates each instance's image tokens as Bridge Image Tokens that attend only with that instance's text tokens, so each instance's T5 tokens absorb visual information as in single-instance generation. Hard Image Attribute Binding (instance image tokens attend only to their own text and image tokens) is used only in the middle layers, with Soft binding elsewhere. Evaluated on COCO-POS and COCO-MIG, and as a re-renderer for layout-to-image models.

## Goal-by-goal answers

### Goal: What mechanism does it use against attribute leakage or object omission, and which part of MM-DiT joint attention (image-to-text, text-to-image, text-to-text, image-to-image quadrant, or token states) does it read or modify?
Text-binding mask: M_text^i[q,k] = 1 iff q, k in T_i or B_i (instance text tokens and bridge tokens) (Eq 2) [full text, Section 3.5]. Image binding: hard mask (instance image tokens attend to own text and image tokens, Eq 3) in vital middle layers, soft mask (all image tokens, Eq 4) elsewhere [full text, Section 3.6]. It controls the text-query and image-query rows of the joint attention mask.

### Goal: Does it account for text tokens being rewritten by image tokens across MM-DiT blocks, or does it treat text tokens as fixed keys or apply a uniform text-side transform?
It directly targets the text-token update: T5 embeddings "rely on Joint Attention with image embeddings to incorporate visual information ... In scenarios where multiple instances are controlled, attribute confusion can easily arise" [full text, Section 1, Section 3.2]. Naively isolating each instance's text and image tokens "disrupts the visual harmony ... and substantially lowers the quality" (Fig 7); bridge tokens fix this [full text, Section 3.5]. The benefit of Hard Text Attribute Binding grows with instance count: Instance Success Ratio gain rises from 3.5% to 6.2% from 2 to 6 instances [full text, Section 4.3].

### Goal: What limitation, failure case, quality or runtime cost, or external dependency (layout, LLM/VLM, fine-tuning) does it report on this axis?
Requires user boxes or masks plus a depth or canny map to define instance regions and bridge tokens [full text, Section 3.4], so it does not apply to plain text prompts. Hard image binding at input/output layers degrades quality [full text, Section 3.6, Section 4.3].


### Goal: Does Hard Text Attribute Binding isolate only what text tokens absorb from image tokens, or also cross-instance text-text attention, and where do its regions come from?
Both. Each instance description is first encoded separately by T5 and then concatenated [full text, Section 3.4]. The mask M_text^i[q,k] = 1 only if q and k are both in T_i or B_i, so instance-i text tokens see only their own text tokens and bridge image tokens. This blocks cross-instance text-text attention as well as text-to-other-image attention [full text, Section 3.5, Eq 2]. The instance regions are user boxes or masks on a depth/canny map, so they are well defined from the first step [full text, Section 3.2, Section 3.4]. The reported 3.5% to 6.2% ISR gain therefore does not isolate the text-query-to-image path [full text, Section 4.3].
