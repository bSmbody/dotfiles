# Diagnosing and Correcting Concept Omission in Multimodal Diffusion Transformers

## What this paper does
ICML 2026. Linear probes on the key vectors of concept text tokens, per attention head, detect whether the concept is present or omitted in the emerging image (up to 91.0% accuracy, middle layers; top-300 of 1,368 heads on FLUX); probe probability rises in step with visual emergence. Omission Signal Intervention (OSI) adds a fixed, normalised mass-mean-shift "omission" direction (scaled by alpha times sigma) to the keys of concept tokens in the top-K heads for the first 15 of 30 steps. It improves object omission (GenEval 2-6 objects, T2I-CompBench non-spatial) and attribute neglect on FLUX.1-dev and SD3.5-Medium, beating TACA and PLADIS.

## Goal-by-goal answers

### Goal: What mechanism does it use against attribute leakage or object omission, and which part of MM-DiT joint attention (image-to-text, text-to-image, text-to-text, image-to-image quadrant, or token states) does it read or modify?
Direction delta = E[k | omitted] - E[k | present] per (layer, head), normalised to theta; intervention k_c <- k_c + alpha sigma theta on the key of concept token c (Eq 5-7) [full text, Section 4]. Top-K heads by probe accuracy (300 FLUX, 100 SD3.5), alpha = 5.0 / 7.5, applied for the first 15 of 30 steps [full text, Section 5.1]. Modifying a text token's key changes how image queries and other text queries attend to it. Token spans come from rule-based parsing (GenEval) or Llama 3.1 8B (T2I-CompBench); for attribute prompts both object and attribute tokens are shifted [full text, Section 5.1].

### Goal: Does it account for text tokens being rewritten by image tokens across MM-DiT blocks, or does it treat text tokens as fixed keys or apply a uniform text-side transform?
It explicitly relies on text tokens absorbing image state: probes in early layers are near chance because "text tokens at these layers have not sufficiently incorporated information from image tokens yet", and become accurate in middle layers [full text, Section 3.2]. But the intervention is open-loop: the probe is used offline to obtain the direction, and at inference the same alpha, heads and step window are applied to every selected token, whatever the probe currently reports. Applying OSI to already-present tokens changes little (probe 0.292 to 0.298, accuracy 0.14) while applying it to the omitted token works (0.70) [full text, Section 5.4, Table 5]. The direction is concept-agnostic; a time-dependent direction scored lower (0.87 vs 0.92) [full text, Appendix F].

### Goal: What limitation, failure case, quality or runtime cost, or external dependency (layout, LLM/VLM, fine-tuning) does it report on this axis?
Limitation: "our intervention is sufficiently strong that it occasionally leads to over-generation" (more instances than requested, Fig 7) [full text, Section 7]. Presence amplification is not binding control: intervening only on object tokens lowers FLUX colour binding 0.7923 to 0.7678, and attribute-only lowers SD3.5 colour 0.7955 to 0.7923; only the joint variant improves (0.8014 / 0.8048) [full text, Appendix E.2, Table A3]. Image quality (MUSIQ, MANIQA) is comparable [full text, Appendix E.1]. Needs a labelled probing dataset per model and a parser for token spans.
