
### G3 verdict
- **Verdict**: `reject(reason=coupling tightens the minor score path of an already-vacuous worst-case cell bound)`
- **Evidence**:
  - [2605.10974] Source grounding is accurate. Vertex-Softmax solves min c^T softmax(s) over independent score boxes with c fixed, via linear-fractional (Dinkelbach-type) structure and K+1 threshold vertices [full text, Sections 2-3]. Cor 3.3 and Section 6 say tighter bounds need "score-value coupling". The G3 math checks out: the Dinkelbach split is separable per token for independent latent boxes, only the lower hull matters when minimizing e^s(v - t), and on an edge v = a s + b the stationary point is s = (t - b)/a - 1. But the paper's own Section 7 names "jointly optimizing over scores and values" as the next step, so the delta is the source's flagged follow-up applied to quantization cells. It is not a non-obvious transfer.
  - [2610.33625] The premise "保留耦合确实大幅缩小低bit真实码格的范围" is contradicted by the closest MLA paper. On GLM-4.7-Flash the content (latent) term carries 7.5% of logit attribution against 92.5% for the positional key. Under INT4 the latent's output error is 1.7% through the content key versus 8.3% through the value [full text, Section 3, Fig 3]. Score-value coupling only helps through the latent's score effect, which is the small route, so the joint oracle can only trim the minor term of the bound. G3's own kill test points at this, and the cited evidence already leans toward triggering it.
  - [2609.36760] Across six MLA models (DeepSeek-V2-Lite/V3/R1, Kimi-K2, LongCat, GLM), RoPE-path output distortion per unit cache error is 1.9-6.9x the content path's [full text, Section 2.2]. So the RAQ-MLA finding is not specific to one model. The shared latent also acts on all heads at once (Y = sum_h A_h C B_h, Eq 1), and G3 concedes its per-head merge is only conservative.
  - [2607.28699] [2605.20868] The worst-case-over-the-cell bound is vacuous at the bit widths G3 targets, so it bounds the wrong object. A data-independent cell bound (TV <= tanh(max|eps|) from the quantization step) "authorizes zero compression" at tau <= 0.2, and residual-norm witnesses are 1289x loose at 4 bits and vacuous at 1-2 bits [2607.28699, Sections 1, 4.1]. An exact oracle over the cell can never go below the cell's true worst case, which sums sign-aligned errors over 512 latent dims (~sqrt(d_c) above realized error). WitCert also finds failures come from cross-layer accumulation, so per-step bounds stay conservative however tight [2607.28699, Section 6.4.1].
  - [2608.05863] Novelty and gap claims are overstated. G3's gap says latent caches are excluded from per-token witnesses (true only of WitCert Tier A, Section 4.1). The companion paper already certifies MLA latent caches at runtime (GLM-5.2, DeepSeek-V4) and moved to a centred tanh(osc/4) bound on the exact rounding distribution. It still reports "no family reaches tau=0.2 retention at two-bit coarsening" [full text, Sections 5.3, 5.6]. G3 does not cite it. Bound-driven reading of FP16 originals from a CPU copy is also already the mechanism of [2605.20868] (Sections 3.3-3.4) and [2607.28699] (Sections 6.3.4-6.3.5). The remaining delta is narrow: a joint score-value oracle per (head, direction). My searches ("score-value coupling softmax bound", "exact softmax bound joint scores and values", "certified attention bound quantized latent cache", "KV cache quantization certificate" since 2025-10, "multi-head latent attention quantization" since 2025-10) found nothing doing exactly that.
  - Mapping and feasibility: G3 certifies a single output direction u per head, but the gating rule needs a scalar risk for the whole head output, across 128 heads sharing one latent. G3 never says which direction(s) are used at runtime. Bounding the output norm needs on the order of d_v directions, each with an O(N·d_c)-per-iteration root search. That is more work than the dequantized attention it guards and needs a new kernel, which the Constraints say to avoid. The listed sources A021 and R018 are the same arXiv paper (v2/v1) [2607.28699], counted as two.
  - Scope and contribution: this is a runtime certificate (observability) more than a new way to decide what history to keep for long-CoT. The quality benefit comes only through gating, and it adds nothing beyond [2605.20868]/[2607.28699] gating unless the bound becomes non-vacuous below 8 bits, which the evidence above argues against.
- **Strongest objection in 1 sentence**: In real MLA models the latent barely moves the attention score (7.5% of logits; RoPE path 2-7x more damaging), so exploiting latent score-value coupling can only tighten the minor term of a worst-case-over-the-cell bound that prior runtime-certificate work already finds vacuous at the 2-4-bit widths G3 targets.


### G4 verdict
- **Verdict**: `reject(reason=NUFFT cannot beat direct evaluation with only d/2 RoPE frequencies; speed premise false)`
- **Evidence**:
  - Algebra checks out. With pre-RoPE K = U B and RoPE in complex form, s_n = Re sum_l U_{n,l} f_l(n), where f_l(n) = sum_{j<=d/2} c_{l,j} e^{-i theta_j n} and c_{l,j} = q~_j conj(B~_{l,j}) e^{i theta_j m}. This is a type-1 sum, f_k = sum_j c_j e^{i k x_j} [1808.06736, Section 1 Eq 1], with M = d/2 sources (32-64) and N output modes. So the mapping (frequencies = sources, q·basis products = strengths, positions = modes) is correctly stated.
  - The speed claim fails on the source's own cost model. Type-1 NUFFT costs O(wM) spreading plus an FFT of size n ≈ 2N, regardless of M, against O(NM) for the direct sum [1808.06736, Section 3.1.1]. FINUFFT benchmarks only "high density" tasks where M is close to or above N, and it says that for small problems a ZGEMM approach wins [1808.06736, Remark 2; Section 6]. Here M/N ≈ 64/128K. Per output, the FFT costs about 5·log2(2N) ≈ 90 real flops on CUDA cores. The direct sum costs 2 real MACs per frequency, i.e. a dense (r × d/2)·(d/2 × N) GEMM that can run on tensor cores. Tensor cores have roughly 10x the throughput, so the FFT flop saving disappears and becomes a loss. Chunked direct evaluation needs only a T×d/2 phase table (FINUFFT's own "phase winding") and is exact. It is algebraically the same contraction as reconstruct-then-rotate.
  - The working set grows instead of shrinking. One query needs r FFTs of size 2N, and the strengths depend on q, so this repeats for every query head in a GQA group, while a reconstruction is amortized over the group. At N = 128K, r = 32, in fp32 that is about 64 MB of FFT traffic per query head per step. That is more than reading the uncompressed bf16 K of a KV head (N·128·2 B = 32 MB). Under SALS-style joint latents (r ≈ 25% of n·d, i.e. hundreds) the count of transforms is far larger [2510.24273, Section 5 setup].
  - The gap premise holds only partly. SALS Figure 1a and Section 3.1 do show that reconstruction plus RoPE dominates at 32K [2510.24273, Section 3.1]. But Palu already computes full RoPE scores from a low-rank key cache in a fused, on-chip reconstruct-RoPE-dot kernel: 3.56x over GEMV for per-head ranks. It becomes compute-bound only for joint/grouped ranks [2407.21118, Section 4.5.2; Appendix B]. The NUFFT would cut flops by at most about d/(c·log N), a small constant, and those flops run on slower units. So it does not remove the compute bound where one exists.
  - Closest prior work, checked. RelFlexformer applies NU-FFT to a relative-position mask matvec inside Performer linear attention, with no softmax. Its Lemma 3.3 shows that for RoPE the frequency set reduces to the d/2 discrete RoPE frequencies, so the sum is just evaluated at them [2605.10706, Section 3.2]. That supports the direct-sum objection above. Alman–Song already use FFTs to exploit RoPE's Toeplitz structure, but for all-query prefill, where the FFT gain comes from amortizing over n queries [2505.11892, Section 4]. G4 does not cite it. In single-query decode that amortization is absent. My searches ("non-uniform FFT attention rotary", "rotary position embedding low-rank key without reconstruction", "pre-RoPE low-rank KV cache compression fused kernel", plus a since-2025-10 recency sweep) found no one doing exactly G4. The method is novel but not useful.
  - Even if the method worked, the byte saving is small. Values stay full: SALS notes that values are "almost full rank" and quantizes them instead [2510.24273]. So rank-r keys at most halve KV traffic, while trained or converted alternatives sidestep RoPE reconstruction entirely through partial-RoPE plus latent absorption [2502.14837, Section 3.1-3.2]. The method also does nothing about the run's priority, which is long-CoT retention: no eviction, and the frozen prompt basis drifts during generation (which the candidate itself flags in its kill test).
  - Contribution type: methodological (a kernel or algorithm). It passes this gate. Its key transfer assumption, "NUFFT's N log N and its constants are below reconstruction or rotation", is named, but it is false for d/2 ≤ 64 sources. The candidate's own kill test would almost certainly fire on the first microbenchmark.
- **Strongest objection in 1 sentence**: With only d/2 ≤ 64 RoPE frequencies per sum, an FFT of size 2N per rank component per query head costs about as many flops as the direct tensor-core GEMM (which equals fused reconstruction, already done by Palu) while moving more bytes than the uncompressed key cache, so no setting exists where the NUFFT path is faster.
