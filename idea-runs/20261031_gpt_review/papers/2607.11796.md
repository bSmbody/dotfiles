# An Exact Instrument for State Usage in Selective State-Space Models, and the Input-Driven Migration It Reveals

## What this paper does
Builds an exact per-mode output decomposition for diagonal selective SSMs (Mamba-1, Falcon-Mamba-7B; approximate for Mamba-2) and a Gram tensor that gives the exact output error of dropping any subset of state modes. Uses it to show that which modes carry a layer's output migrates with the input, attributes this to the input-dependent write map B_t, and measures the headroom that input-dependent mode selection would have over static pruning rules (calibration energy, modal-HSV, LAST, GHOST).

## Goal-by-goal answers
### Goal: Is a fixed (calibration-ranked) set of state units adequate for selective SSMs, and what drives deviation from it?
No. At the most affected layers a same-window top-r selector roughly halves the output error of the calibration-ranked static set (migration gap rho 0.44-0.57) in Mamba-1 130M-2.8B, Falcon-Mamba-7B and Mamba-2 [full text, Section 4.1]. Frozen-signal counterfactuals put the cause in the write map B_t, partly C_t, and almost none in the timestep Delta, so a static timestep-activity criterion collapses [full text, Sections 1, 4.2]. Existing methods (GHOST, PerfMamba, LAST, balanced truncation) "each choose a single fixed set of states" [full text, Section 2].
### Goal: What does it report as its limitation, i.e. can input-dependent selection be done causally?
At half the state budget the retrospective same-window oracle beats every static rule and even the unpruned model (e.g. 130M PPL 11.84 vs static 14.16, unpruned 12.38) [full text, Section 4.3, Table 2]. But it reads the mask from the window being scored, so it is headroom, not a deployable method. Cheap causal schedulers recover little: regime-conditioned masks 2-6% of the gain, a 256-token prefix estimator 2-9%, half-window selection 18-26%; "the important set decorrelates within a few hundred tokens" and "predicting the mask before the tokens it prunes remains an open problem"; contexts beyond 1024 tokens are untested [full text, Section 5].

### Goal: Exactly how are the causal schedulers built (what do they fix, and over what span), and is the write map shared across channels?
Every causal scheduler fixes one keep-set ahead and holds it over a span: a regime-conditioned mask (one static set per domain) captures 2-6% of the same-window oracle's gain; a 256-token prefix estimator 2-6% (5-9% with a per-mode ramp-up correction); a mask selected on the first 512 tokens of a window and applied to the second half captures 18-26% (25% at 130M, 18% at 790M) and does not beat the unpruned model [full text, Section 4.3, Table 3]. None tracks the state contents token by token or lets a mode re-enter when it is written. The oracle's ranking is per-window diagonal energy e_i = sum_t m_{t,i}^2 with m_{t,i} = g_t C_{t,i} x_{t,i}; the full-Gram and diagonal gaps correlate at 0.96 [full text, Sections 3.2, 3.4]. In Mamba-1, B_t and C_t carry no channel index (Eq 1-2), so the write and read selection is shared by all H channels of a layer [full text, Section 3.1]. Freezing B_t removes the migration (gap 0.70->0.96 Mamba-1; 0.77->0.96 Mamba-2), keeping only B_t live reproduces much of it (rho 0.87), freezing C_t removes part, freezing Delta almost none [full text, Section 4.2]. On LAMBADA, static half-budget pruning drops 790M accuracy 0.63->0.41 and the same-passage mask recovers 86% of the drop [full text, Section 4.3].


### Goal: Does the same-window oracle prune what is stored or only what is read, and does any memory-saving policy face the same headroom?
It prunes reads. "Pruning a mode means omitting its contribution from the output": the per-mode term is m_{h,t,i} = g_{h,t} C_{t,i} x_{h,t,i}, where x is the full, unpruned state accumulated over all past tokens, and the mask S_w is fixed over the 1024-token window [full text, Section 3.2, Eqs 3-4; Section 4.3]. The scheduled oracle uses "a first pass" to measure the window's energies, then "a second pass prunes that same window to its top-r modes", so it is "not a causal deployment protocol and does not by itself constitute a compute saving" [full text, Sections 4.3, 5]. The paper defines no oracle with irreversible eviction (a mode that was not kept loses its past content and restarts from new writes); its headroom numbers apply to read masks over a fully stored state. In Mamba-1, B_t in R^N is dense, so every token writes every mode of every channel [full text, Section 3.1, Eq 1]. The authors name "a learned scheduler that exploits it cheaply" as the natural next step [full text, Section 6]. The migration is "strongest in the slow, long-horizon modes" and contexts beyond 1024 tokens are untested [full text, Section 5]. The sub-unpruned margin is "same-window adaptation" and "does not survive out-of-window selection" [full text, Sections 4.3, 5].
