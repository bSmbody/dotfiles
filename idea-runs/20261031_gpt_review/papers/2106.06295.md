# Going Beyond Linear Transformers with Recurrent Fast Weight Programmers

## What this paper does
Extends linear Transformers / Delta Net (fast weight programmers) with recurrence. Fast-net extensions (Delta RNN, Delta LSTM) make the fast network itself recurrent; the slow-net extension, the Recurrent Delta Net (RDN), feeds the previous output of the fast net (the previous read-out from the fast-weight memory) back into the generation of key, value, query and the delta learning rate. Evaluated on Wikitext-103, code execution, sequential ListOps and Atari RL; RFWPs beat linear and regular Transformers on the algorithmic tasks and compete on language modelling.

## Goal-by-goal answers
### Goal: Does any delta-rule variant condition its write/erase signals on what the memory returned to earlier queries?
Yes, one step back. RDN sets k_t = W_k x_t + R_k tanh(y_{t-1}), and likewise v_t, q_t and beta_t = sigma(W_beta x_t + R_beta tanh(y_{t-1})), where y_{t-1} is the fast net's previous output, i.e. the previous query's read-out of the memory [full text, Section 3.2 / Eq 15-18]. So write address, value and write strength already depend on what the memory returned to the previous query. Nothing accumulates a per-direction or per-association record of reads over many steps; the feedback is only through the previous read vector (and, in a deep stack, through the residual stream). Recurrence within the slow net on its own previous k/v/q was "sub-optimal" in their LM experiments [Section 3.2].
### Goal: What does this read feedback cost in parallelism?
Space and time stay linear/constant in length, but the dependence on y_{t-1} makes the model "a proper RNN" [Section 3.2], so it is trained token-by-token with a custom CUDA kernel: 35K words/s for RDN vs 63K for Delta Net [Section 4.1, Computational efficiency]. No chunkwise-parallel form is given.
### Goal: Does the paper test retention of specific stored associations under overload?
No. Code execution tests maintaining and updating variable states, ListOps tests hierarchical computation [Sections 4.2-4.3]; there is no multi-query recall or capacity-overload study, and no analysis of which associations are kept.
