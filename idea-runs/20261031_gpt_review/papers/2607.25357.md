# Raven: High-Recall Sequence Modeling with Sparse Memory Routing

## What this paper does
Frames SSMs, linear attention and sliding-window attention as Routing Slot Memories: a fixed set of slots, a router that decides where each token writes, and a decay that decides how long content persists. SSMs are the dense all-ones router, SWA the FIFO one-hot router. Raven uses a sparse, input-dependent top-K sigmoid router (MoE-style, Gumbel noise against collapse) with decay applied only to selected slots, so unselected slots are frozen. Trained from scratch at 400M-800M; strong NIAH and recall, 16x length extrapolation, gains also in hybrids.

## Goal-by-goal answers
### Goal: How does Raven decide which memory slots are written, and is the router a function of the stored state?
The router is r_t = r(x_t, t): sigmoid scores of the current input, top-K sparsified and normalised, adapted from DeepSeek MoE routing [full text, Sections 3.1 Def 2, 4.1]. It does not read the slot contents. Unselected slots get no write and no decay, so content persists until reselected [full text, Section 4.1].
### Goal: Is Raven a post-training compression of an existing model?
No. It is a new architecture trained from scratch with the router; all M slots are stored. Its contrast with SSMs is that SSMs write densely to every slot [full text, Sections 1, 3.4, 9].
