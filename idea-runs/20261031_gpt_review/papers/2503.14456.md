# RWKV-7 "Goose" with Expressive Dynamic State Evolution

## What this paper does
Introduces RWKV-7, a linear-time RNN language model whose matrix state evolves by a generalized delta rule: a vector-valued in-context decay w_t, a vector-valued in-context learning rate a_t, and a removal key that is decoupled from the replacement key, giving a diagonal-plus-low-rank (DPLR) transition. It trains 0.19B-2.9B models, proves it can recognize all regular languages, and provides fast CUDA kernels plus a Triton implementation in flash-linear-attention.

## Goal-by-goal answers
### Goal: What is the generalized delta-rule transition, and is the low-rank direction tied to the write key?
The state evolves as wkv_t = wkv_{t-1}(diag(w_t) - kappa_hat_t^T (a_t ⊙ kappa_hat_t)) + v_t^T k_tilde_t [full text, Section 4.1 / Eq 16-17]. The removal key kappa_hat (normalized) is separate from the replacement key k_tilde, and a_t is a vector, so the transition "is no longer a Householder matrix" but keeps eigenvalues in [-1,1] [Section 4.1 / Eq 19; Appendix C]. Hence a DPLR transition whose low-rank direction is not the current write key is an established, stable design.
### Goal: Is this transition class trainable with existing parallel kernels?
Yes. Parallelizing DeltaNet showed DPLR state evolution parallelizes over time; RWKV-7 "further extends that parallelization to cover the generalized delta rule formulation" [Section 2, Delta Rule]. CUDA kernels are tuned for head dim 64 and are about three times faster than RWKV-6's; flash-linear-attention offers a Triton implementation for larger heads [Section 8, Speed]. At 16K, the RWKV-7 forward+backward is faster than FlashAttention-3 forward [Section 8].
### Goal: What does the paper say about removing information only at specific directions?
Plain decay "is a blunt tool that cannot remove only the values stored at specific keys"; the delta rule removes per key, and RWKV-7 extends this to a per-channel removal amount [Section 2; Section 4.1]. The removal direction and amount are still computed from the current token's projections, not from any record of reads.
