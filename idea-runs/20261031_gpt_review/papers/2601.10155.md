# LOOKAT: Lookup-Optimized Key-Attention for Memory-Efficient Transformers

## What this paper does
Applies product quantization with asymmetric distance computation to the key cache: keys are split into m subspaces (m=4, 256 codewords each), each query builds m lookup tables of inner products with the codewords, and each token's score is the sum of m table lookups, so keys are never reconstructed. Values stay FP16 and the softmax-weighted sum runs over all tokens. Evaluated on GPT-2 with sequence lengths up to 1024, reporting up to 64x key compression at ~95.7% output cosine fidelity.

## Goal-by-goal answers
### Goal: Does LOOKAT still compute a score per cached token, and how are values handled?
Yes. Algorithm 1 loops over every compressed key: s_l = sum_i LUT_i[k_l[i]], then standard softmax and o = sum_l alpha_l v_l over all L tokens [full text, Section 3.5, Algorithm 1]. Complexity O(m*256 + L*m) vs O(L*d) [Section 4.7]. Only keys are compressed; values stay FP16 and are read in full; value PQ is listed as future work, "non trivial because of the weighted sum requirements" [Sections 5.1-5.2].

### Goal: At what lengths and models is it tested?
GPT-2 only, sequence lengths 64-1024 in the long-context scaling table [Section 4.5, Table 3]; no LLM-scale long-context or kernel timing, and hardware-specific kernels are named as needed [Section 5.1].
