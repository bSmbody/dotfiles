# GPT 生成候选的审查结果（2026-10-31）

审查对象：GPT 按 `gpt_handoff/PROMPT_zh.md` 生成的两样东西，1000 条候选目录（`candidates-1000.csv`）和精选 10 个的报告（`selected10-report.html`）。
审查方法：先由我核查整体情况，再把 GPT 排名前 5 的候选原样导入 IdeaScientist。每个候选派一个独立的对抗式审稿人，审稿人自己去读源论文、自己做新颖性检索，不采信 GPT 的自审结论。
原始记录：`candidates.md`（导入的 G1–G5）、`scores.md`（审稿意见）、`papers/`（读书笔记）。

## 2. 前 5 个的独立审稿结果

| # | 候选 | GPT 的判断 | 审稿结论 | 最强反对意见 |
|---|---|---|---|---|
| G1 | B-C0005 先解输出层再更新记忆内部（VarPro 消元用于两层 TTT 快记忆） | 保留，第一推荐 | **修改（新颖性）** | **ParaTTT**（arXiv 2610.38255，2026-10-28 发布，GPT 没引）已经对两层记忆做逐 token 的精确联合损失更新，有并行 kernel，并把"最优读出层"列为下一步。G1 的两块组件也都有先例：近端 ridge 读出层就是 Longhorn 的更新方式，搬到 chunk 级而已；MesaNet 和 GKA 已经做精确 ridge 读出。真正新的只是这两者的组合。G1 唯一的证据是"内部拟合误差更低"，可已有工作显示这个指标可能和下游召回反向变化 |
| G2 | A-C004 把整段记忆变成小矩阵链（PQ 码组合统计 + Tensor-Train） | 高风险保留 | **否决** | PQ-HSA 的逐 token 扫描主要服务于 top-k 选择，贡献 +0.16 macro。它的背景求和已经离全注意力只差 0.01。TT 只能返回求和，给不出 token 身份，所以既省不掉扫描，也消除不了有意义的误差。"码组合统计的 TT 秩很低"这个假设也没有任何支撑 |
| G3 | A-C007 让误差检查记住键值的联系（MLA 量化的 score/value 联合误差证书） | 保留 | **否决** | 在真实 MLA 模型里，latent 对注意力分数的影响很小，只占 logits 的约 7.5%，RoPE 路径造成的损害是它的 2–7 倍。利用耦合只能收紧误差界里的次要项。已有运行时证书工作还发现，在 2–4 bit 下这类最坏情况界本来就是空洞的 |
| G4 | A-C118 不用还原整片键也能加上位置（低秩 pre-RoPE K + NUFFT） | 修改后保留 | **否决** | 每个求和只有 d/2 ≤ 64 个 RoPE 频率。每个秩分量、每个 query 头都要做一次 2N 点 FFT，计算量和直接用 tensor core 做矩阵乘差不多；后者就是融合重建，Palu 已经做过。它搬运的字节反而比不压缩的 key cache 还多，找不到任何能更快的设置 |
| G5 | C0102 共享一次结果不把它当成多次证据（图 RL 共享 rollout 的方差加权） | 修改后保留 | **否决** | 本质上只是用教科书里考虑偏差的 GLS 去重调 GraphPO 的那一个汇总权重 w；EPIG-Tree 和 EBPO 已基本覆盖。GPT 声称的"终局结果到梯度的线性算子"在 GraphPO 经过标准化和裁剪的优势值下并不存在。而且它和长生成的记忆管理无关 |

**结论：前 5 个里 4 个否决，1 个需要修改，而这一个的新颖性空间刚被一篇 3 天前的论文大幅压缩。**
精选的后 5 个（A-C002、A-C005、A-C064、B-C0007、B-C0002）没有送审。GPT 自己把它们排在后面，它的自审也已指出每个都有很强的近邻（Nectar、Delta Attention、SANTA、quasi-DEER/ELK、GSA-2）。需要的话可以再审。

## 3. GPT 候选的共同问题

1. **把经典数学工具迁移到注意力上，却没先核算成本。** VarPro、Tensor-Train、NUFFT、Taylor 模型、最大耦合、Parareal、RTLS 都属于这一类。迁移本身没问题，但 G2、G4 都死在"连理论上的成本账都算不过来"，这一步本来不用做实验就能先算。
2. **关键假设没有量级证据。** G3 假设 score/value 耦合足够强，可真实模型里只占约 7.5%；G2 假设 TT 秩低，没有任何证据。GPT 的自审一般都会点出这些假设，但仍然把候选判为"保留"。
3. **检索漏掉了最新工作。** ParaTTT 是 10-28 才发布的。这个方向更新太快，GPT 的检索窗口跟不上。

## 4. 建议

- **到目前为止**：Claude 这边 20 个候选、GPT 这边 5 个候选，都经过了对抗式审稿。在这个领域里，纸面上能站住的 idea 只剩 C14，而 C14 的分数也就是 2.7–3.2/10。**继续在纸面上出 idea，边际收益已经很低了。**
- **最划算的下一步是跑便宜的真实实验，让数据说话**：
  1. **C14 的第一周闸门**：转换 Qwen3-4B 后，看不同层分配之间的差距是否 ≥ 5 pp，见 `../20261027_efficient_attention/IDEAS_zh.md` 第 8 节。
  2. 如果你们对 TTT 记忆感兴趣，**G1 的固定 KV 测试**也只要 1–2 张 GPU、一周时间，但要把 ParaTTT 作为必比的 baseline。
- **如果还想让 GPT 再出一轮**，建议在 prompt 里加三条硬要求：
  - 每个 idea 先写出理论上的 FLOPs/字节账，并和最强的融合实现对比；
  - 每个关键假设都要给出已发表论文里测到的量级；
  - 检索必须覆盖到最近一周。
- **和师兄确认**：组里有没有一个具体的、自己系统里遇到的瓶颈，比如某个模型、某种部署场景下哪一步最慢、哪里显存最紧。从真实瓶颈出发选题，比在拥挤领域里找空白更容易做出东西。
