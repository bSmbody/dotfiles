## 1. Scope 与成功标准

- **问题**：长思维链生成 16K–64K token 时，在解码阶段压缩 KV cache。目标是在**显存打满的真实服务条件下**，让每**答对一题**的墙钟时间和每个请求的显存都下降。
- **只有下面 6 条全部满足才算成功**：
  1. 准确率没有统计显著的下降；
  2. 生成长度没有实质膨胀；
  3. 循环率和撞长度上限率没有上升；
  4. KV 实际占用的字节数下降，元数据要算进去；
  5. 显存打满时能承载的 batch 变大；
  6. 每答对一题的墙钟时间下降，并且要**优于 FP8/FP4 KV**。

  只改善 MSE、注意力 KL 或单个 kernel 的耗时，不算成功。
- **约束**：H200 共约 1 TB 显存；执行者是新手学生，有组内 kernel 工程师支持；目标会议 NeurIPS / ICML / ICLR / MLSys。

## 2. 已核实的事实（作为约束使用）

## 4. 建议的挑战轴（供 Gap Finder 使用）
1. **超低比特（1.25–2.5 bit）下难题与长距检索的准确率损失**：TaSQ、AsymKV、KVarN 的掉分集中在哪里，是哪些头、哪些 token、哪些推理阶段。
2. **在线、按头或按角色的 K/V 精度分配**：现有分配都是离线静态的（KVTuner、MultiAlloc），或者按 token 预算而不是按精度分配（DuoAttention）。
3. **能反映端到端误差累积的分配依据**：离线代理会选错（F5），冻结误差的假设不成立（OSCAR）。
4. **显存打满时的每题成本最优点**：低比特省下的 batch 增益，和它造成的难题掉分之间怎么权衡。

## 5. 已被否掉的方向（不要再提；如果重提，必须说明怎样绕开它的死因）

| 方向 | 死因 |
|---|---|
| K 用共享阈值同调舍入，V 用保和 dependent rounding（"C2"） | 同调 SR 最多追平 RTN；V 在注意力集中时更糟（F9、F10）；K2/V1 已有人试过（F8） |
| PQ 码组合统计 + Tensor-Train 读取 | 省不掉 top-k 扫描；Transformer-VQ 和 RAM-Net 已经做过 |
| MLA 的 score/value 联合误差证书 | latent 只占约 7.5% 的 logit；2–4 bit 下的最坏界是空洞的 |
| 低秩 pre-RoPE K + NUFFT | 频率数 ≤64，FFT 算不过直接矩阵乘；Palu 已经做了融合重建 |
| KV 淘汰按"事实覆盖 / k 份拷贝 / 熵或意外度 / 重算代价"打分 | 预算紧时覆盖不了；用熵加权会适得其反；中间结果很快就不再被用到 |
| 用"双胞胎解码"给每次淘汰算功劳 | 见 F13 |
| 混合模型中借状态精度来推迟 KV 降级 | KVpop、LazyEviction、BreadthKV 已有；而且借出去的精度永远还不回来 |
| 删 KV 时先看 GDN 是否还记得 | LoLA、ContextCite、AT2 已有；预训练混合模型的检索几乎全部依赖注意力 |
| 只发现"量化让推理变长"、不给方法的测量研究 | 权重量化的版本已被 F4 覆盖；而且 TaSQ 和 KVarN 测到的长度都接近 BF16 |
| 以"更低比特"为唯一卖点 | TaSQ 已经到了 1.25 bit，再往下拼比特数，空间很小 |

## 6. 统一评测协议

- **模型**：Qwen3-8B、**Qwen3-4B-Thinking-2507**（TaSQ、OSCAR、KVarN 共用，方便直接对比已发表的数字）、R1-Distill-Qwen-14B/32B、gpt-oss-20b（滑窗混合结构）；可选 Qwen3.5-9B（GDN 混合结构）。
- **数据集**：AIME 2025/2026（至少 avg@16）、MATH-500、GPQA-Diamond、LiveCodeBench v6；长距检索用 NIAH / RULER 到 64K。
- **字节核算**：所有方法在相同字节数下比较。scale、zero point、码本、sink/recent 的 BF16 窗口、保护层都要计入。
- **指标**：
  - 准确率，按题目聚类计算置信区间；
  - 生成 token 数的分布、CTIR、循环率、撞上限率；
  - 峰值 HBM、显存打满时的最大 batch；
  - 每答对一题的墙钟时间，batch 从 1 一直扫到显存打满。
- **禁止**：只看 MSE 或 KL；要求两条轨迹逐 token 一致；只在 prefill 或短输出上评测；只汇报理论 FLOPs，不给实测时间。
- **第一周的基线实测**：在 vLLM 或 SGLang 上，用 Qwen3-4B-Thinking 和 Qwen3-8B 跑 FP8、FP4、KVarN（2 bit）、TaSQ（1.25 bit，如果能拿到代码）、PM-KVQ，在 AIME25 和 MATH-500 上测上面的全部指标，并**按头统计量化误差和 n_eff**（供种子一使用）。
