# 完整 idea：长推理中低比特 KV 的"按需精度救援"

> 版本：2026-11-05。状态：**纸面方案，尚未做任何实验**。P0 实验（`REVIEW_CP2_zh.md`、`REVIEW_CP3_zh.md`）用来决定这个方案是否成立。
> 文中带"粗算"字样的数字都是用已发表论文的数据做的估算，不是我们的实测结果。

---

## 0. 一句话

**所有请求默认用 2 bit 存 KV，把显存腾出来多装请求；在线识别正在失控的少数请求，用它已生成的 token 把 KV 重算成 FP8，再接着生成。目标是用接近 2 bit 的成本，拿到接近 FP8 的准确率。**

暂定英文标题：*Spend Precision Only Where It Pays: Mid-Trajectory KV Precision Rescue for Long-Reasoning Serving*

## 1. 动机：三个观察

### 观察 1：在 Qwen3-8B 上，2 bit KV 的损失主要表现为"失控"，不是均匀掉分

以下数据来自 WUSH-KV（2609.38121）表 2，Qwen3-8B，AIME25：

| KV 精度 | 准确率 | 平均长度 | 写到上限的比例 |
|---|---|---|---|
| BF16 | 67.8 | 45.4k | 11% |
| OSCAR（INT2） | 34.4 | 63.0k | 42% |
| WUSH-KV（INT2） | 46.7 | 53.4k | 12% |
| TurboQuant 式 INT2 | — | — | 91–100% |

写到上限是按请求发生的事件：一部分请求开始绕圈子，一直写到上限。同类现象在 LiveCodeBench v6 上更严重（BF16 11%，OSCAR 71%）。

### 观察 2：在显存打满时，一个请求的成本与长度的平方成正比，所以失控请求的成本被放大

显存打满时，batch 能装多少请求，由每个请求平均占多少显存决定。一个请求的 KV 随长度线性增长，又要占着显存跑完全程，所以它消耗的是"显存 × 时间"：

> 一个请求的显存-时间 ≈ 每 token 字节数 b × L² / 2

（推导见第 3.4 节。）写满 64K 的失控请求，消耗约为一个 20K 正常请求的 (64/20)² ≈ 10 倍。**少数失控请求就能吃掉大部分算力**，而它们最后还答错了。

**粗算**：用"每答对一题的显存-时间"比较，以下用平均长度的平方近似 E[L²]，会低估方差的影响：

| 方案 | b（有效 bit） | 平均长度 | 准确率 | b × L² / 准确率（相对值） |
|---|---|---|---|---|
| FP8（假设准确率 ≈ BF16） | 8 | 45.4k | 67.8 | **24,300** |
| OSCAR INT2 | 2.5 | 63.0k | 34.4 | 28,800（**比 FP8 还贵**） |
| WUSH-KV INT2 | 2.5 | 53.4k | 46.7 | 15,300（比 FP8 便宜 37%） |
| 目标（我们） | 大部分 2.5、少数 8 | 接近 BF16 | 接近 67.8 | 约 10,000–12,000（假设，见第 5 节） |

这张表说明两件事：
- 弱的 2 bit 方法按"每答对一题"算，可能比 FP8 还贵。现有论文用 tokens/s 衡量，看不到这一点。
- 2 bit 本来的显存优势有 3 倍以上，大部分被少数失控请求吃掉了。把它们救回来，收益很大。

### 观察 3：KV 量化造成的损伤，在状态层面可以撤销

- KV 完全由 token 序列决定。把"题目 + 已生成的 token"用 FP8 重新 prefill 一遍，得到的就是精确的 FP8 KV。
- 权重量化做不到这一点。2606.02011 遇到权重量化导致的循环，只能用 FP16 整条重跑。
- 代价很小：Qwen3-8B 在 H200 上重算 16K 前缀不到 1 秒，而同一个请求在 batch 中续写 16K token 要 5–13 分钟。
- 限制：重算只修复状态，**已经采样出的错误 token 撤不回来**。所以能不能救回来，取决于发现得够不够早。这一点要靠 P0 的分叉实验测量。

## 2. 研究问题与假设

| 编号 | 假设 | 检验方式 |
|---|---|---|
| H1 救援空间 | 强 2 bit（OSCAR+OptR）下，FP8 能做对、2 bit 做错的比例 ≥ 5 个百分点 | P0 Q1 |
| H2 成本集中 | 失控请求（写到上限或循环）的显存-时间占比，远高于它们的数量占比（比值 ≥ 1.5） | P0 Q2 |
| H3 早期可识别 | 只看前 4K token，预测"最终会失败"的 AUC ≥ 0.65 | P0 Q3 |

| H5 中途优于重开 | 中途升级比"用 FP8 从头重开"更省，或者救回得更多 | P0 Q4 + 成本模型 |

## 3. 方法

### 3.1 整体流程

```
新请求 → 用 INT2（OSCAR+OptR）开始生成
         │
         ├─ 每 256 个 token：失控检测器根据 token 流算出风险 r_t
         │
         ├─ r_t 超过阈值 τ(负载)：
         │     ├─ 升级：用已生成的 token 重新 prefill 成 FP8，释放 INT2 页，接着生成
         │     ├─（可选）先试：跑一小段 FP8 分支，确认有好转再提交
         │     └─ 发现太晚或风险极高：用 FP8 从头重开，或直接终止
         │
         └─ 否则继续用 INT2
```

### 3.2 两档分页 KV 池（系统部分）

- 每个请求整体只用一种精度：INT2 或 FP8。不做 token 级混合，这样分页内核基本不用改。
- 在 SGLang 中维护两个 KV 池（INT2 页和 FP8 页），按字节共享同一块显存。
- 每层注意力按精度把 batch 拆成两组，各调用一次对应的内核。两次调用的额外开销需要实测，预计很小。
- 升级时用 chunked prefill，避免一次性阻塞同一 batch 里其他请求的解码。

### 3.3 失控检测器

输入只用生成过程中本来就有的信息，在 CPU 上计算，不增加 GPU 开销：

| 信号 | 含义 |
|---|---|
| 熵的均值和趋势 | 模型越来越"犹豫" |
| n-gram 重复率（最近窗口） | 开始兜圈子 |
| 反思词频率（wait、let me double check、alternatively 等） | 反复自我检查 |
| 新片段与之前内容的相似度 | 在重复同样的推理 |
| 长度增速、思考是否迟迟不结束 | 预计会写满上限 |

- 模型：逻辑回归或小型梯度提升树，输出校准后的失败概率。
- **训练用独立的数据**（例如 AIME 2022–2023、HMMT、OmniMath 的难题子集），不能用 AIME24/25 测试题，避免信息泄露。
- 必须正面回应 RECAP（2610.15259）的发现：按 token 的重要性跨轨迹不可迁移（AUC 0.43–0.50）。我们预测的是请求级的失控，不是 token 重要性，P0 会给出实测 AUC。

### 3.4 什么时候升级：一个可推导的阈值策略

**为什么用显存-时间作为成本。** 显存打满时：
- 并发请求数 ≈ 显存总量 / 单个请求的平均占用；
- 每一步解码都要读完显存里的所有 KV，所以单步时间近似为常数；
- 于是吞吐（请求/秒）∝ 1 / 每个请求的显存-时间，而显存-时间 ≈ b·L²/2。

所以 GPU 时间可以按显存-时间分摊给各个请求。这个近似在显存未打满时不成立，需要实测验证。

**单个请求的决策。** 一个请求在长度 t、风险 r 时，升级的收益和代价是：

- 收益：Δp(t, r) × V。Δp 是升级后答对概率的提升，由 P0 的分叉数据按 t 和 r 估计；V 是答对一题的价值。
- 代价：λ × (b₈ − b₂) × E[剩余显存-时间] + c_重算。λ 是显存的"影子价格"，由当前负载决定。

**策略：当 Δp·V ≥ 代价时升级。**这是一个阈值策略，阈值 τ 随负载变化：
- 显存空闲时 λ ≈ 0，应该尽量升级，甚至全部用 FP8；
- 显存打满时 λ 很大，只升级 Δp 最大的那批请求。

这样，系统会自动在"全 FP8"和"全 INT2"之间按负载切换。论文里要给出 λ 的在线估计方法，以及这个策略在显存-时间模型下的最优性条件。

### 3.5 四个递进策略（归因用）

| 策略 | 做法 | 回答的问题 |
|---|---|---|
| P-direct | 风险超过阈值就直接升级 | 最简单的方案够不够 |
| P-H | 先跑一小段 FP8，看风险是否下降再提交 | 先试再提交值不值 |
| P-LH | INT2 和 FP8 各跑一小段，比较后决定 | 多花的对照成本有没有回报 |
| P-LL | 不升精度，只用 INT2 换随机种子重跑同样长度 | 救回来是不是只靠重新采样 |

除非数据证明更复杂的策略更好，否则默认用 P-direct。

### 3.6 扩展（不作为主线）：只升 K 或只升 V

关于"K 更重要还是 V 更重要"，现有论文的结论互相矛盾（AsymKV、PN-Mix、KV-COBRA）。我们的推导认为，这取决于各个头注意力的集中程度：
- V 误差的危害 ∝ Σp²，注意力越集中越大；
- K 误差的危害 ∝ Var_p(δs)，注意力越分散越大。

如果成立，可以只升级 K 或只升级 V，进一步降低升级的代价。这部分作为论文中的分析章节，核心公式要引用 RECAP 和 HeadQ（已撤稿）作为先前的工作。

## 4. 和最近邻工作的区别

| 工作 | 它做了什么 | 我们多做了什么 |
|---|---|---|
| DiffKV 2412.03131 | 按请求、头、token 的注意力稀疏度分档 | 决策依据是请求是否失控，目标是答对率 |
| ThinKV 2510.01290 | 按思维类型分配精度 | 检测失控，并且能中途升级 |
| QAQ 2403.04643 | 在线按 token 重新分配 K/V 位宽，CPU 上保留原值 | 不需要 CPU 副本，用重算升级；决策单位是请求 |
| PM-KVQ 2505.18610 | 显存紧张时逐步降精度 | 方向相反，可以升精度 |
| 2606.02011 | 权重量化下检测循环，用 FP16 整条重跑 | 针对 KV，可以中途升级，并量化了中途与重开的差别 |
| KV-Rescue 2608.15797 | 换一个保留完整 KV 的小模型救援 | 同一个模型，只换精度 |
| The Price of Precision 2610.15629 | 用时间成本模型分配精度 | 目标里加入答对率和失控；在线、按请求决策 |
| DPS 2609.34380、GrowPage 2609.03494 | 按全局压力切换权重精度；按请求扩 KV 容量 | 按请求切换 KV 精度 |

**不能声称是新的**：在线分配精度、K/V 用不同位宽、按请求分档、用重算恢复 KV（vLLM 被抢占后的做法）。

**可以声称的贡献**：
1. **测量**：首次在显存打满、以每答对一题的成本为指标、并以 FP8 为基线的条件下，说明低比特 KV 的损失和成本主要集中在少数失控请求上，并给出显存-时间 ∝ L² 这一解释。
2. **洞察**：KV 量化的损伤在状态层面可以撤销；通过分叉实验，把救援的收益拆成"精度的贡献""重新采样的贡献"和"中途接续相对重开的贡献"。
3. **方法**：一个以显存影子价格为阈值、随负载变化的升级策略，以及 SGLang 中的两档分页实现。
4. **系统结果**：在固定题集上，实测每答对一题的墙钟成本。

## 5. 实验计划

### P0：诊断（1–2 周，几十 GPU 小时）
按 `REVIEW_CP3_zh.md` 执行，顺序是 S0 长度校准 → S1 主采样（Q1–Q3）→ 闸门 → S2 分叉实验（Q4）。任何一条假设不成立，就按第 7 节的预案处理。

### P1：离线策略模拟（约 1 周，几乎不用 GPU）
- 用 P0 记录的轨迹和分叉结果，离线模拟各个策略的每答对一题成本：
  - 本方法的 P-direct、P-H、P-LH、P-LL；
  - 检测后重开、随机升级（升级比例相同，用来检验检测器是否有用）；
  - 理想上界：事先知道哪些请求会失败。
- 阈值在校准集上选，在 AIME 上评估。
- 产出：选定的策略、阈值，以及预计的收益区间。这一步决定是否值得投入 P2 的工程量。

### P2：系统实现与实测（4–6 周）
- 在 SGLang 中实现两档 KV 池、重算升级和在线检测器。
- 在 8×H200 上，用固定题集、在显存打满的条件下测量。指标：每答对一题的 GPU 秒数、准确率、平均长度、写到上限的比例、循环率、升级比例、最大并发、p99 延迟。
- 对照组：
  - 固定精度：BF16、FP8、INT2（OSCAR+OptR、NOVA-KV）；
  - 静态混合：随机挑 x% 的请求用 FP8，字节数和本方法相同；
  - 检测后重开（把 2606.02011 的做法移植到 KV）；
  - P-LL；
  - 理想上界。

### P3：泛化（2–3 周）
- 模型：Qwen3-14B 或 32B、DeepSeek-R1-Distill 系列；可选一个混合架构模型（GPT-OSS-20B，OSCAR 在它上面会崩溃）。
- 任务：LiveCodeBench v6、GPQA-Diamond、HMMT。
- 编码方法：换成 NOVA-KV 或 KVarN，验证策略和具体编码方法无关。
- 长度：64K。

### 预期结果（目标，不是承诺）
- **Qwen3-8B**：准确率比 FP8 低不超过 2–3 分，每答对一题的成本 ≤ FP8 的 0.6 倍。
- **Qwen3-4B-Thinking**：几乎不触发升级，成本接近 INT2，准确率不下降。这说明策略会根据模型自动调整。

## 7. 风险与预案

| 风险 | P0 中的表现 | 预案 |
|---|---|---|
| 强 2 bit 已经接近无损，没有可救的 | Q1 < 5 个百分点 | 方法线停止。第 2 节的测量研究（按每答对一题成本比较各种 KV 精度）仍可以单独整理成一篇分析或评测论文 |
| 救回来只靠重新采样 | H 续写 − L 续写 < 10 个百分点 | 改成"检测后低精度重采样"，更便宜，但新意变弱 |
| 中途升级不比重开好 | H 续写 ≈ H 重开 | 改成"检测后用 FP8 重开"，方法更简单，故事依然成立 |
| 检测不准 | AUC < 0.65 | 放弃早期准入，只在明显失控（重复、长度异常）时触发 |
| 系统开销吃掉收益 | P2 中实测的升级干扰、双内核开销过大 | 升级只在负载低谷时执行，或者按批次集中升级 |
| FP8 实现偏弱 | fork 的 FP8 比原生 FP8 低 5 分以上 | Q1、Q4 改用 BF16 口径，并在文中写明 |
