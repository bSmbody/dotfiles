## 创新点 1：重新定义低比特 KV 的代价

### 数据
P0 的 S1 主采样：2 个模型 × 60 题 × 16 次 × 3 种精度（BF16、FP8、INT2）。

### 每条轨迹要记录
- 是否答对；
- 长度 L；
- 是否写到上限；
- 是否打转：用 2606.02011 的 n-gram 循环定义；
- 思考是否结束（`</think>` 是否出现）。

### 计算
1. **显存-时间（成本代理）**：M = b × B × (L_p·L + L²/2)。
   - b 是有效比特：INT2 按 2.5，FP8 按 8，BF16 按 16；
   - B 是每 token 每 bit 的字节系数（层数 × KV 头数 × 头维度 × 2 / 8）；
   - L_p 是题目长度。
2. **每答对一题的成本**：同一精度下，所有轨迹的 M 之和除以答对的数量。
3. **成本集中度**：打转或写满上限的轨迹占总 M 的比例，除以它们占轨迹数的比例。画一条洛伦兹曲线。

### 验证这个成本代理（P1 中做，便宜）
- 显存-时间只是代理指标，必须和真实墙钟时间对上。
- 方法：**长度回放**（参考 AbridgeKV 的做法）。把 S1 中各精度实际生成的长度分布原样回放：设置 `ignore_eos`，`max_tokens` 等于记录的长度，在显存打满的条件下测完成全部请求的墙钟时间。
- 这样可以避开准确率的干扰，单独测出"长度分布 × 精度"对真实时间的影响。
- 报告代理指标和实测时间的相关性（R²），以及在哪些区间偏差较大。

### 论文中的图表
- 三种精度的长度累积分布；
- 失控请求的"数量占比 vs 成本占比"洛伦兹曲线；
- 成本表：BF16、FP8、INT2 每答对一题的显存-时间和墙钟时间。如果有余力，加上 NOVA-KV。

## 创新点 2：KV 损伤可撤销

### P0：不改引擎，只验证可行性
- 升级方式：把"题目 + 已生成部分"的 **token id** 原样提交给 FP8 引擎（`input_ids`），不重新套 chat template。
- **一致性检验**：把一条 BF16 轨迹在 BF16 引擎上重新 prefill，下一个 token 的分布应该和原轨迹一致。KL 接近 0，top-1 一致率接近 100%。这一条不过，后面的结果全部作废。

### P2：在引擎内实现
- SGLang 已经有"撤回请求、之后重新 prefill"的机制（显存不足时的 retract）。升级可以直接复用它：
  1. 撤回请求，释放它的 INT2 页；
  2. 把它的精度标记改为 FP8；
  3. 重新入队，以全部 token 作为 prompt 进行 prefill。复用 chunked prefill，切成小块执行；
  4. 采样参数不变，继续解码。
- 需要实测：
  - 重算耗时随前缀长度的变化（4K、8K、16K、32K）；
  - 重算期间，同批其他请求每步解码时间（TPOT）的变化；
  - 正确性：重算得到的 FP8 KV，与一开始就用 FP8 生成同样 token 得到的 KV 对比，teacher-forced 下的 logit 差应该为 0 或在数值误差以内。

## 创新点 3：救援功劳的三分拆解

### 实验
P0 的 S2 分叉实验（详见 `REVIEW_CP3_zh.md`）：
- 每个模型从 INT2 的失败轨迹中抽至多 60 条，每题至多 3 条，抽样用固定随机种子；
- 在第 4K、8K、16K 个 token 处切开；
- 每个切点跑以下分支，每支 4 次：H 续写（FP8，另跑一组 BF16）、L 续写（INT2 换种子）、H 重开、L 重开；
- 另抽 50 条 INT2 下答对的轨迹，做 H 续写和 L 续写作对照。

### 三份功劳的计算

| 功劳 | 怎么算 |
|---|---|
| 精度的功劳 | H 续写恢复率 − L 续写恢复率 |
| 重新采样的功劳 | L 续写恢复率（原轨迹失败，换种子后答对的比例） |
| 中途接续的功劳 | H 续写恢复率 − H 重开恢复率，同时比较两者的 token 成本 |

### 统计方法（预先登记）
- 主分层：Qwen3-8B、8K 切点、FP8 口径。
- 置信区间：按题聚类的 bootstrap，95%。
- 其余分层：用 Holm 方法做多重比较校正。
- 判断"两者相当"：差值的置信区间完全落在 ±5 个百分点以内。

### 附带回答"回退多少最好"
切点越早，相当于回退得越多。所以"恢复率与切点位置"的曲线就能回答这个问题。

## 创新点 4：按负载调整的升级规则

### 需要估计的三个量

**1. Δp(t, r)：在位置 t、风险为 r 时升级，答对概率能提高多少。**
- 来源：分叉实验的结果。失败轨迹来自 S2；成功的对照轨迹提供"误升级"一侧的数据。
- 按切点 t 和风险分箱估计，或者拟合一个逻辑回归。

**2. E[剩余显存-时间 | t, r]：如果升级，这个请求接下来还会占多少显存-时间。**
- 来源：S1 和 S2 中，各状态下的剩余长度分布。

**3. λ：显存的影子价格。**
- 在线估计：λ ≈ 当前这批请求每单位显存-时间产出的答对题数。也就是说，多占一单位显存-时间，就会挤掉这么多潜在的答对产出。
- 显存没有打满时，λ = 0。

### 升级规则
当 Δp(t, r) ≥ λ × (b₈ − b₂) × E[剩余显存-时间] + c_重算 时升级。

其中 c_重算 是重算时间折算的成本。λ 越大（负载越重），阈值越高。

### P1：离线模拟器（几乎不用 GPU）
- 用离散事件模拟一台显存打满的服务器：
  - 显存容量 C 固定；
  - 请求排队，有空位就进；
  - 每个请求按 P0 记录的真实轨迹回放长度和对错；
  - 每 256 个 token 让策略决策一次；
  - 如果升级，结果从分叉实验最接近的那个切点的分支结果里抽取。
- 输出：每个策略单位时间内答对的题数，以及每答对一题的成本。
- 比较的策略：
  - 本方法的四个变体：P-direct、P-H、P-LH、P-LL；
  - 检测后重开；
  - 按相同比例随机升级（用来检验检测器有没有用）；
  - 全 FP8、全 INT2；
  - 事先知道结果的理想上界。
- 阈值在校准集上选，在 AIME 上评估。
- P2 实测出来后，要和模拟器的预测对比，验证模拟器是否可信。

### 失控检测器
- 特征计算的代码离线和在线共用一份，见 `IDEA_FULL_zh.md` 第 3.3 节。
- 训练数据：往年 AIME（2022–2023）、HMMT、OmniMath 的难题子集，用 INT2 采样得到带标签的轨迹。这需要额外采样一次，规模和 S1 中单一精度相当，放在 P1 里做。
- 模型：逻辑回归，或者小型梯度提升树，做概率校准。
- 评估：在 AIME 上按题分组算 AUC，并画校准曲线。

## 创新点 5：两档 KV 池（SGLang 补丁）

| 模块 | 改动 |
|---|---|
| 显存管理 | 维护两个 KV 池：INT2 页和 FP8 页。第一版用一个全局字节计数器来控制准入，两个池各自预留足够空间。第二版再做按字节共享的动态分配 |
| 请求状态 | 新增一个精度字段，取值为 INT2 或 FP8 |
| 前向计算 | 权重部分整批计算；每层注意力按精度把 batch 拆成两组，分别调用 INT2 和 FP8 的注意力内核，结果拼回原顺序 |
| CUDA graph | 第一版先关掉，或者只给"全 INT2"这种常见组合录制，接受一定的性能损失；第二版再为两组的不同大小组合分别录制 |
| 检测器 | 挂在输出处理模块上，每 256 个 token 为每个请求更新一次特征和风险，超过阈值就向调度器发出升级指令 |
| 升级 | 复用 retract 和重新 prefill 的流程，见创新点 2 |
| 日志 | 记录每个请求的精度切换时间点、风险轨迹、重算耗时、最终对错 |

### P2 的实测设置
- 8×H200，在显存打满的条件下，跑固定题集。
- 对照组：
  - 全 BF16、全 FP8、全 INT2；
  - 随机挑选相同比例的请求用 FP8；
  - 检测后重开；
  - P-LL；
  - 本方法。
- 指标：每答对一题的 GPU 秒数（主指标）、准确率、平均长度、写满上限的比例、打转比例、升级比例、最大并发数、p50 和 p99 延迟。

## 附加分析（可选）：K/V 不对称

- 用 HuggingFace 的 eager 模式，在少量轨迹上抓取注意力分布，计算每个头的有效 token 数 n_eff = 1/Σp²，以及 Var_p(δs)。
- 用 OptR 分别做"只量化 K"和"只量化 V"的对照，检验推导的预测：注意力集中的头对 V 误差更敏感，分散的头对 K 误差更敏感。
- 如果预测成立，可以做"只升级 K"或"只升级 V"的低成本升级版本。
