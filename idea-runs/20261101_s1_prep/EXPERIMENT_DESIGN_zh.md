## 一、要证明什么

一句话：**默认用 2 bit 存 KV，发现某个请求失控时，把它升到 FP8 接着写，可以在显存打满时降低每答对一题的成本。**

这个结论要成立，下面这条链必须每一环都成立。每个阶段检验其中一环，任何一环不成立就停。

```
H1  2 bit 让一部分题从对变错（有可救的）              ← S1
H2  失控的请求占了不成比例的成本（值得救）            ← S1
H3  早期能看出谁会失控（来得及救）                    ← S1
H4  中途升到 FP8 能救回来，而且是精度的功劳，不是运气   ← S2
H5  中途升级比从头重做更划算                          ← S2
H6  合在一起，满载时每答对一题的成本确实更低           ← P1 预估，P2 实测
H7  换模型、换任务、换 2 bit 方法，结论仍成立         ← P3
```

## 二、固定不变的实验条件

| 项目 | 设置 | 理由 |
|---|---|---|
| 模型 | Qwen3-8B（thinking 模式）、Qwen3-4B-Thinking-2507 | 8B 预计在 2 bit 下掉分多，有救援空间；4B 预计几乎无损，作为对照，检验方法会不会帮倒忙、检测器会不会乱报警 |
| KV 精度 | BF16（参照）、FP8（升级目标）、INT2（OSCAR+OptR，按有效 2.5 bit 记账） | INT2 选强方法，避免拿稻草人当对手 |
| 推理框架 | OptR 的 SGLang fork，固定 commit，三种精度都在这里跑 | 精度之间的差别只来自精度本身 |
| 交叉校验 | vLLM 原生 FP8，每题 4 次 | 检查 fork 里的 FP8 实现是否偏弱 |
| 采样 | temperature 0.6，top-p 0.95，种子固定 | Qwen 官方推荐值 |
| 生成上限 | 由 S0 确定 | 避免把"上限太短"误判为"失控" |
| 模型权重 | 始终是原版 BF16，不做任何训练 | 只改变 KV 的存储精度 |

## 三、各阶段

### S0：定生成上限

| | 内容 |
|---|---|
| 目的 | 选一个足够长的上限，保证 BF16 本身很少写满 |
| 做法 | 两个模型都用 BF16，上限设为 81,920，60 道题每题做 2 遍 |
| 产出 | 长度分布、实测吞吐；在 32K、48K、64K、80K 中，取让 BF16 写满比例 ≤ 10% 的最小一档 |
| 题目 | AIME 2024 + 2025 |

### S1：主采样（检验 H1、H2、H3）

| | 内容 |
|---|---|
| 做法 | 2 个模型 × 3 种精度 × 60 题 × 每题 16 次，共 5,760 条完整做题记录；另加 vLLM FP8 校验 480 条 |
| 记录 | 每个 token 的 id 和概率（含前 20 个候选）、长度、是否写满上限、思考是否结束、预测答案、是否答对 |
| 题目 | AIME 2024 + 2025（60 题） |

**H1 有多少可救：**
- 每道题分别算 FP8 和 INT2 的正确率之差，再对 60 题求平均。同一批题在不同精度下配对比较，能抵消题目难度带来的噪声。
- 报告按题 bootstrap 的 95% 置信区间。FP8 和 BF16 两种口径都报。
- **两个模型在两种口径下都低于 5 个百分点 → 停止。**

**H2 成本是否集中：**
- 按 2606.02011 的定义标出打转的记录。
- 计算"打转或写满上限"的记录占总显存-时间（∝ 长度²）的比例，除以它们占记录条数的比例。画洛伦兹曲线。
- **比值低于 1.5 → "成本集中"不成立**，论文只剩准确率这一条贡献。

**H3 能否早期识别：**
- 只用前 2K、4K、8K 个 token 计算特征：熵的均值和趋势、n-gram 重复率、反思词频率、自相似度、思考是否结束。
- 标签是"最终答错或写满上限"，用逻辑回归。
- **交叉验证时按题目分组**：同一道题的记录不能同时出现在训练集和测试集，否则分类器学到的只是"哪道题难"。
- 补充一个"只看当前长度"的基线预测器，用来证明其他信号确实提供了额外信息。
- 两个模型都报。4B 上的报警率用来检验检测器抓的是"量化导致的失控"，而不只是"难题"。
- **4K 时 AUC 低于 0.65 → 放弃提前准入**，只在明显失控时才触发升级。

**FP8 校验：**fork 里的 FP8 如果比 vLLM 原生 FP8 低 5 个百分点以上，或者平均长度多 10% 以上，H1 和 H4 改用 BF16 口径。

**闸门：**H1 不成立就不做 S2。

### S2：分叉实验（检验 H4、H5，核心因果实验）

**选样本**（规则在 S1 开始前固定并提交）：
- 每个模型从 INT2 的失败记录（答错或写满上限）中，按固定种子抽至多 60 条，每道题至多 3 条，按题分层；
- 另抽 50 条 INT2 下答对的记录作对照。

**切点：**第 4K、8K、16K 个 token（超过记录长度的切点跳过）。

**分支**（每个分支跑 4 次，每次换一个随机种子）：

| 分支 | 做法 | 作用 |
|---|---|---|
| **H 续写（FP8）** | "题目 + 前 t 个 token"的 id 原样交给 FP8 服务，重新 prefill 后接着写 | 主角：中途升级精度 |
| H 续写（BF16） | 同上，交给 BF16 服务 | 不受 FP8 实现影响的干净参照 |
| **L 续写** | 同样的输入交给 INT2 服务，换种子接着写 | **排除"只是运气"**：精度不变、位置相同，只重新采样 |
| **H 重开** | 只给题目，用 FP8 从头做 | 排除"从头重做就够了" |
| L 重开 | 只给题目，用 INT2 从头做 | 基础对照 |

- 重开的分支和切点无关，同一条源记录只跑一组，所有切点共用，计费时去重。
- 50 条答对的对照记录只跑 H 续写和 L 续写，检验升级会不会把本来能做对的题搞坏，并估计误升级的成本。

**为什么 L 续写必不可少：**挑出来的都是失败的记录，其中有一部分只是运气差，换个种子重写也可能答对。所以"H 续写救回了多少"必须减去"L 续写救回了多少"，剩下的才是精度的功劳。

**判定（预先登记）：**

| 问题 | 判定规则 |
|---|---|
| H4 精度有没有用 | 主分层（Qwen3-8B、8K 切点、FP8 口径）中，H 续写 − L 续写 ≥ 10 个百分点，且按题聚类的 95% 置信区间下界 > 0，才算成立。主分层的样本不够时，顺延到 Qwen3-8B 的 4K 切点。其余分层用 Holm 方法校正，只作探索性结果，不能单独救活机制。**不成立 → 停止** |
| H5 中途是否优于重开 | 比较 H 续写和 H 重开的恢复率，以及各自多花的 token。差值的置信区间完全落在 ±5 个百分点内，判为"相当" → 方法简化为"检测到失控就用 FP8 重开"。置信区间太宽时判为"不确定"，不作为任何一方的证据 |
| 误升级的代价 | 对照组升级后准确率下降多少、多花了多少成本 |
| 什么时候救最有效 | 恢复率随切点位置变化的曲线 |

**功效检查：**S2 开跑前，先用 S1 的实际失败数估算主分层能否检出 10 个百分点的差距。检不出的话，在 60 条的上限内扩大主分层的抽样。

### P1：离线策略模拟（检验 H6 的前一半，几乎不用 GPU）

| | 内容 |
|---|---|
| 做法 | 模拟一台显存打满的服务器：请求排队进入，按 S1 的真实记录回放长度和对错；请求被升级后，结果从 S2 中最接近的切点、对应分支的结果里抽取 |
| 比较的策略 | 本方法的四个变体（直接升级、先试再提交、两路对照、只换种子重采样）、检测后用 FP8 重开、**相同比例的随机升级**、全 FP8、全 INT2、事先知道结果的理想上界 |
| 关键对照 | 随机升级：证明检测器挑中的确实是该救的请求 |
| 阈值 | 在校准题（往年 AIME、HMMT、OmniMath 难题）上选定，再到 AIME 2024/2025 上评估 |
| 验证成本代理 | 长度回放：把各精度实际的长度分布原样回放，在满载条件下测真实墙钟时间，检查"显存-时间"这个代理指标准不准 |
| 判定 | **最好的策略比全 FP8 省不到 20% → 不做系统** |

### P2：系统实测（检验 H6，论文主结果）

| | 内容 |
|---|---|
| 系统 | 默认 INT2；每 256 个 token 检测一次失控风险；超过阈值就用已生成的 token 重新 prefill 成 FP8 KV，从当前位置接着写。阈值随负载变化 |
| 环境 | 8×H200，显存打满，固定题集 |
| 负载 | 难易混合：MATH-500、AIME/HMMT、LiveCodeBench，比例可调 |
| 对照 | 全 BF16、全 FP8、全 INT2（OSCAR+OptR，以及 NOVA-KV）、相同比例随机升级、检测后用 FP8 重开、只换种子重采样、理想上界 |
| 指标 | **每答对一题的 GPU 秒数（主指标）**、准确率、平均长度、写满上限比例、打转比例、升级比例、最大并发、p50/p99 延迟 |
| 负载扫描 | 改变并发量或可用显存。预期：负载低时接近全 FP8 的准确率，负载高时接近全 INT2 的成本 |
| 消融 | 去掉某一类检测信号；固定阈值 vs 随负载变化的阈值；直接升级 vs 先试再提交 vs 两路对照 |
| 实现 | 第一版可以先用"双服务 + 外部控制器"，不改 SGLang 内部；第二版再在同一个服务内共享显存。具体另定 |

## 五、统计原则

1. **配对比较**：不同精度用同一批题，按题配对计算差值。
2. **重复采样**：AIME 每题 16 次，分叉实验每个分支 4 次。
3. **置信区间按题目聚类**：同一道题的多条记录不独立。
4. **预先登记**：主分层、顺延规则、Holm 校正、±5 个百分点等价区间、FP8/BF16 口径切换条件、抽样规则和阈值，全部在看到结果前写定并提交，之后不改。
5. **不显著 ≠ 相同**：等价判定要求置信区间完全落在区间内，否则报告"不确定"。
