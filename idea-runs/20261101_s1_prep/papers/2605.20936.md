# DASH: Fast Differentiable Architecture Search for Hybrid Attention in Minutes on a Single GPU

## What this paper does
DASH converts Qwen2.5-3B-Instruct into a hybrid by differentiable architecture search over per-layer operators {Full, Window(512), Linear(GDN)}: Stage 1 aligns linear candidates (100M tokens), Stage 2 optimizes only softmax architecture logits per layer with a teacher KL plus a relative-cost regularizer and temperature annealing (12.3M tokens, ~20 min on one GPU), Stage 3 distills the discretized architecture (600M tokens). Reports better RULER than selector baselines and Jet-Nemotron.

## Goal-by-goal answers
### Goal: What mechanism does it use to decide which layers keep full attention, and on what data/objective?
Soft routing Mix = sum_o p_o Operator_o with p = Softmax(alpha/T_arch) (Eqs 11-12, 17); search loss L_KL (teacher-forced temperature KL over token positions) + lambda * expected cost with c = (1, w/T, 0) (Eqs 13-16); argmax discretization (Eq 18) [full text, Section 4.3]. All stages use DCLM generic text; RULER is evaluated at 4096 context [Section 5.1]. Layer 0 is fixed by convention [Appendix B].

### Goal: What does it report as its limitation?
Validated only on Qwen2.5-3B with GDN and a predefined operator set; 600M-token final distillation; the cost proxy is operator type and window ratio rather than calibrated latency/memory; hitting a target budget needs a sweep over lambda [full text, Section 6]. The search sequence length T (4096) enters the window cost, so the searched allocation is tied to that length. No reasoning / long-generation evaluation.
