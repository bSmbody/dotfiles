# Read What Matters: Query-Adaptive Quantization for KV Caches

## What this paper does
ReadKV separates stored bits per scalar (W) from bits read per query (R). Every key and value scalar is stored as a W-bit progressive (nested, non-uniform scalar-tree) code laid out as bit planes. At each decode step a two-stage reader first assigns key-channel prefix depths from the current query, computes attention from the reconstructed keys, then assigns value-token prefix depths from that reconstructed attention. A greedy marginal-gain allocator (exact under diminishing gains) solves min sum a_i D(t_i) under a per-stage budget. Theory: finite-dimensional families where query-dependent reading strictly beats any query-independent reader. Evaluation: perplexity on six base models, QA/retrieval on two instruct models, single-layer A10G kernel.

## Goal-by-goal answers
### Goal: How does ReadKV decide value precision, and is it tied to attention concentration (sum p^2)?
Yes, directly. The value-token importance is a^V_{g,j} = s_g * sum_{h in S(g)} alpha_hat_{h,j}^2 (squared reconstructed attention, summed over the GQA query heads sharing the KV head) [full text, Sec 3.2 Eq 3]. Key-channel importance is a^K_{g,c} = sum_h (q'_{h,c} sigma^K_{g,c})^2, i.e. squared query coefficient times calibrated channel scale, also aggregated over the GQA group [Eq 2]. So the V-side "error weight = p^2" law and GQA aggregation that seed 1 wants to derive are already the operating rule here, but used for per-step READ depth, not for per-head stored precision, and the key side uses query magnitude per channel, not any concentration statistic. The K/V budget split (B_K, B_V) is a fixed input, "it optimizes the allocation within each stage, not that split" [Sec 3.3].

### Goal: What is stored where; is there CPU/tiered offload of residual bits?
All W bits (e.g. W=8) stay resident; the paper only reduces bytes moved per step. Tiered memory that keeps rarely-fetched refinement levels in slower memory is named only as a possible future direction [Sec 7]. Closest precedent cited: Xie et al. 2025 (precision tiers + floating-point bit-plane retrieval for ranked pages with a compression-aware memory controller) [Sec 6, App B.3]. QAQ is noted to keep an unquantized CPU copy and transfer back to requantize [App B.2].

### Goal: What evidence exists on long-CoT / reasoning or end-to-end serving?
None on reasoning. Results: (W=8,R=4) within 0.66% of uncompressed C4 perplexity across six base models; QA/retrieval on two instruct models. GPU: single-layer, 8K tokens, batch 1, A10G: ReadKV(8,2) 0.093 ms vs TurboQuant K4/V4 0.154 ms vs dense 0.051 ms; 62-65% fewer DRAM read bytes than TurboQuant [Sec 5.1 Table 4]. Authors state it "does not yet establish an end-to-end serving advantage" [Sec 7]. Note storage is 8 bits, i.e. 2x a 4-bit cache: it does not raise batch at memory saturation.

# Read What Matters: Query-Adaptive Quantization for KV Caches (ReadKV)

## What this paper does
ReadKV separates retained precision from fetched-per-query precision. After a fixed Hadamard-sign transform and calibrated per-channel standardization, each K/V scalar is stored as a W-bit path in a Gaussian Lloyd binary quantization tree (a progressive/embedded code), so any prefix is a valid coarser reconstruction. At each decode step a two-stage causal reader runs. First it allocates key-channel prefix depths from the current query (channels with large query coefficients get more bits) and computes attention from the reconstructed keys. Then it allocates value-token prefix depths using that attention. Stored entries never change. The paper proves exact greedy allocation under diminishing refinement gains, relates the objectives to attention-output error, and exhibits an attention family where query-dependent reading strictly beats every query-independent reader at equal read budget.

## Goal-by-goal answers
### Goal: Headline numbers?
Across six base models, reading 4 bits on average from an 8-bit cache (W=8, R=4) raises C4 perplexity by at most 0.66%, with about 1/4 of the logical reads and 1/2 the retained capacity of a 16-bit cache. It is more accurate than storing and fully reading 4 bits at the same read budget (Abstract, Section 5). On a single-layer, 8K-token, batch-1 workload on an A10G, a restricted 8-bit reader with a 2-bit mean read budget has 39% lower latency than the tested TurboQuant codec (Section 5.1). Per the web summary, its QA quality advantage over protected TurboQuant is not uniform.
### Goal: Relation to seed 4 (read-time residual bit-plane fetch)?
This is direct prior art for "store more bits, fetch a query/attention-dependent prefix". ReadKV already uses query-dependent key-channel depth and attention-dependent value-token depth (Section 3.2-3.3). A new seed would need to differ in its allocation signal (for example attention concentration), its granularity (pages or heads vs. channels/tokens), or in end-to-end serving, which ReadKV explicitly has not established.
### Goal: Limitations?
No end-to-end serving advantage was shown; the GPU study covers one layer at batch 1 (Section 7). Retaining 8 bits does not save capacity relative to 8-bit storage, so the benefit is bandwidth only. There is no long-CoT reasoning evaluation; the paper uses perplexity, long-context QA and retrieval on two instruction-tuned models.
