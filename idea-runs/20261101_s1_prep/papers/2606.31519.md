# RaBitQCache: Rotated Binary Quantization for KVCache in Long Context LLM Inference

## What this paper does
RaBitQCache (ICML 2026) is a sparse-attention framework, not a compressed-storage KV quantizer. It builds a randomized-rotation binary (RaBitQ-style 1-bit) index of the keys and estimates q·k with binary-INT4 arithmetic as an unbiased estimator with a proven error bound. It then selects tokens adaptively by Top-p (the smallest set that covers probability mass p) instead of a fixed Top-k, and fetches the corresponding full-precision KV. Asynchronous pipelining and lazy index updates hide the overhead. It is implemented in vLLM with FlashInfer and a fused Int4DotBinary GEMV kernel.

## Goal-by-goal answers
### Goal: Is the KV itself stored at low bit?
No. The index costs about 3.5% of FP16 memory and stays in HBM, while the full-precision KV is retained (offloadable) and fetched for the selected tokens (Section 3.3, App. memory note at line ~1724). Its role relative to KV quantization is "1-bit keys as a retrieval proxy", the same family as QJL-style estimators and PQ-HSA.
### Goal: Headline numbers?
LongBench (13 datasets): close to Full with an adaptive budget (Table 2). Decoding is up to 3.88x faster than full attention at 30K context; end-to-end up to 2.16x at matched scores; prefill overhead under 10% (Section 5.3, Figs. 2-3).
### Goal: Limitations for long-CoT?
Evaluated on LongBench with Longchat-7B and LLaMA-3.1-8B. No long-generation reasoning evaluation. It does not reduce KV capacity, so it does not raise batch size at memory saturation unless combined with offloading.
