# DeepSeek-V3 Technical Report

## What this paper does
DeepSeek-V3 is a 671B-total / 37B-active MoE model with MLA attention, auxiliary-loss-free load balancing, FP8 training, and a multi-token-prediction (MTP) training objective. This digest covers only the MTP and decoding parts. Checkpoints: https://github.com/deepseek-ai/DeepSeek-V3 [abstract].

## Goal-by-goal answers
### Goal: How is MTP built, and how is it used at inference?
The MTP module at depth k contains a projection M_k that combines the previous-depth hidden state with the embedding of token t_{i+k}, plus one Transformer block. Embedding and output head are shared with the main model. Predictions stay sequential and causal, similar to EAGLE [Section 2.2, Eq 21-23]. The loss is lambda times the mean CE over depths [Eq 24-25]. Pre-training sets depth D=1, so the model predicts one extra token [Section 4.2, line "MTP depth D is set to 1"]. At inference MTP can be dropped or reused as a speculative-decoding drafter [Section 2.2, "MTP in Inference"]. The primary goal of MTP is better training, not acceleration [Section 2.2].

### Goal: What speedup / acceptance is measured?
The second token is accepted 85-90% of the time "across various generation topics", for 1.8x TPS [Section 5.4.3]. No breakdown by batch, context length or generation length is given. Decoding deployment: minimum unit is 40 nodes / 320 GPUs, attention TP4+SP with DP80, MoE EP320. Per-expert batch is usually ≤256 tokens and "the bottleneck is memory access rather than computation" [Section 3.4.2].

### Goal: Limitations relevant to long generation?
There is only a single MTP module (D=1), so the draft is one token per step. The paper gives no evaluation at long CoT lengths. A separate vLLM study reports that the released single MTP module of another model (GLM-4.5-Air), reused autoregressively, loses acceptance with depth. That study is [2601.11580], not this paper.
