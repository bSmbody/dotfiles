# When Is Thinking Enough? Early Exit via Sufficiency Assessment for Efficient Reasoning

## What this paper does
DTSR (ACL 2026 Main) is a training-free early-exit method for reasoning models. It watches the stream for reflection signals ("Wait", "Alternatively", "But wait", …). When one appears, and at least k=64 tokens have passed since the last check, the same model is prompted to give a 0-100 sufficiency score for the current CoT. If the score is ≥ tau (100), DTSR appends </think> and the model answers. Otherwise reasoning resumes. Runs on vLLM with continuous batching.

## Goal-by-goal answers
### Goal: Which models/lengths, and how much length/latency is saved at what accuracy?
Models: Qwen3-8B, 14B, 32B. Benchmarks: GSM8K, MATH-500, AMC23, OlympiadBench, GPQA-D, LiveCodeBench. Max generation 16K, T=0.6, 3 runs [Section 3.1]. Sequence length drops 28.9%-34.9% with "almost the same level of accuracy" vs vanilla [Section 3.2]. On LiveCodeBench the reduction is >50% with minimal degradation [Section 3.2]. End-to-end latency [Section 4.2, Table 2]: MATH-500 3.1 s → 1.9 s (length 4480 → 2247); AMC 8.3 s → 6.2 s. DEER, a baseline, cuts length to 2601 but raises latency to 4.2 s, because its synchronous evaluation blocks continuous batching [Section 4.2].

### Goal: How does it interact with serving / KV cost?
Each check reruns the question plus the current CoT through a separate sufficiency prompt. That is an extra prefill and extra KV over the full trace, unless the prefix is cached; the paper does not quantify this. Gains are reported as length and latency, not memory. The paper notes that implementation (synchronous vs continuous batching) flips whether early exit saves wall-clock [Section 4.2].

### Goal: Stated limitations?
[Limitations]: only models up to 32B; only text math/code, no multimodal or agent settings. Also from the paper: DTSR is slightly below training-based methods on accuracy [Section 3.2, Table 5]; Qwen3 is overconfident in its self-scores, which motivates tau=100 [Section 4.3].
