# Dual-QK: Sharp Queries and Flat Keys for Prunable 2-bit KV Caches

## What this paper does
Dual-QK replaces the shared orthogonal rotation of rotation-based KV quantization with a paired non-orthogonal query/key transform (A for queries, B for keys, A B^T = I): partial key whitening flattens key scales for INT2, while a query-aligned basis concentrates query energy so that dynamic query-channel pruning (40%) can skip key-channel reads. Key channel 0 (the largest-energy query coordinate) is kept in BF16; a calibrated diagonal rescaling refines scales; values follow OSCAR's rotation and clipping recipe; bucket-relative RoPE bounds positional offsets. Keys are stored channel-major per 128-token page so the decode kernel copies only selected channel rows. SGLang implementation.

## Goal-by-goal answers
### Goal: Method and storage format?
Calibrated dual transforms (Section 3.1), dynamic query-channel mask (3.2), one asymmetric INT2 grid per token and KV head, channel 0 in BF16, first 64 and last 256 tokens in BF16 (3.3), bucket-relative RoPE (3.4). Effective 2.34 bits per element (capacity) and 1.93 (bandwidth) at 128K (Table 1).
### Goal: Headline numbers on reasoning models?
With 40% query-channel sparsity for all quantized methods (Table 1, five seeds): Qwen3-4B-Thinking-2507 AIME25: BF16 74.7, KIVI(3.01 bits) 42.0, OSCAR(2.28) 6.0, TurboQuant(3.13) 0.0, Dual-QK 48.0; GPQA 65.6 / 54.3 / 23.1 / 3.5 / 60.8. Qwen3-8B AIME25: BF16 65.3, KIVI 47.3, OSCAR 13.3, Dual-QK 53.3. So with channel pruning, a 2-bit cache still loses about 12-27 AIME25 points. Note that OSCAR here is pruned, unlike in OSCAR's own paper; results without pruning are in App. D.1. Throughput: 3.75x BF16 decoding at 90K and batch 1 on Qwen3-4B-Thinking (90 vs 24 tok/s); OSCAR and Dual-QK both reach batch 16 at 90K where BF16 runs out of memory at batch 8 (Section 4.4).
### Goal: Limitations?
Accuracy gaps to BF16 remain at long contexts; the pruning gain shrinks at small batch; the 2K positional calibration window can be exceeded by query offsets (Section 5). There is no output-length or loop-rate analysis in the main text.
