# FSA: An Alternative Efficient Implementation of Native Sparse Attention Kernel

## What this paper does
Re-implements the NSA selected-attention kernel by swapping the loop order: outer loop over KV blocks (per query head), inner loop over the non-contiguous batch of query tokens that selected that block, with separate online-softmax-statistics and reduction kernels to avoid atomics. This removes the padding NSA needs when a GQA group has few query heads.

## Goal-by-goal answers
### Goal: What hardware limitation of the NSA kernel does FSA address, and what new costs does it introduce?
NSA batches the query heads of one GQA group at one token as the matmul M dimension; with few heads per group this is below the wgmma/wmma minimum tile (e.g. 8 on Hopper), forcing padding and wasted loads/FLOPs [full text, Section 1 and Section 3.1]. FSA instead batches query tokens per KV block, but must gather non-contiguous queries via index tensors, precompute softmax statistics in a separate kernel (in-kernel statistics would be wrong because a query's blocks are processed by different thread blocks), and write partial outputs to an HBM buffer for a separate reduction kernel [Section 3.1-3.2]. Reports up to 3.5x (avg 1.6x) kernel speedup and avg 1.09x end-to-end training speedup over NSA [Section 1].
