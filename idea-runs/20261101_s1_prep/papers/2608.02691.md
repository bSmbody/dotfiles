# Output-Aware Rotation for INT2 KV-Cache Quantization (OptR)

## What this paper does
OptR learns per-KV-head orthogonal corrections on top of a base rotation (QuaRot Hadamard or OSCAR covariance rotation) by minimizing post-W_O attention-output error through the full INT2 quantize-attend path, during a one-time offline calibration with frozen weights. Keys are optimized first (they set the attention distribution), then values under that distribution. It also subtracts a per-channel calibration key mean before rotation (softmax-invariant). Rotations are fixed at inference; value rotation is absorbed into W_V/W_O; a Triton write kernel fuses rotate/mean-subtract/clip/quantize/pack into the paged INT2 cache.

## Goal-by-goal answers
### Goal: What is the method and what does it require (calibration, kernels)?
Per-head orthogonal corrections R_K,h, R_V,h trained offline on calibration data against post-W_O output error; key reparameterization k - mu (Section 4.1-4.5). Requires calibration; same group size, BF16 sink and recent windows as the baselines (Section 5, Baselines). Inference overhead within 2% of the base INT2 pipeline in decode latency/throughput, +18 MiB memory at B=128, same max batch (Section 6, Efficiency).
### Goal: Headline numbers on long-CoT reasoning at ~2 bits?
At 2.32 bits per element (BPE), on Qwen3-4B-Thinking-2507: BF16 mean 67.58 (AIME24 78.0, AIME25 71.3); QuaRot-INT2 2.61 (collapse, AIME 0.0); QuaRot+OptR 61.63; OSCAR 62.71 (AIME25 63.3); OSCAR+OptR 65.38 (AIME24 72.0, AIME25 70.7). Qwen3-8B: BF16 65.66, OSCAR 61.34, OSCAR+OptR 65.68 (AIME25 66.0 vs 68.0). TurboQuant without mixed precision at 3.25 BPE scores only 18.66 (4B) / 43.88 (8B) (Table 1, five seeds). RULER-NIAH up to 64K: QuaRot-INT2 degrades fast, OptR closes much of the gap (Table 2).
### Goal: Limitations relevant to long-CoT serving?
No report of generated-length or loop-rate changes in the main text. Static offline rotations (no online adaptation). It stays at a uniform 2.32 BPE with BF16 sink/recent windows; it does not go below 2 bits. Only three dense GQA models; no MLA. Throughput is only shown as matching the base INT2 pipeline, not as cost per correct answer versus FP8/FP4.
