## 一、事实更正与新增（接在资料包 F15 之后）

**F16（更正 F 系列中"长度基本不涨"的说法）：低比特 KV 是否拉长输出，取决于方法和模型，不能当成已解决的问题。**
- WUSH-KV [2609.38121] 表 2 按格子给出平均生成长度和"打满上限"的比例。Qwen3-8B、AIME25：BF16 平均 45.4k token，11% 打满；OSCAR（INT2）63.0k，42% 打满；WUSH-KV 53.4k，12% 打满。
- 同一表中，LiveCodeBench v6 上打满比例 BF16 为 11%，OSCAR 为 71%；Qwen3-32B 的 LiveCodeBench 上为 3% 对 53%。TurboQuant 式 Hadamard INT2 让 91–100% 的样本打满上限。
- Qwen3-4B-Thinking 上长度变化很小（21.8k 对 24.2k）。
- 准确率：Qwen3-8B AIME25 上 BF16 67.8，WUSH-KV 46.7，OSCAR 34.4。
- 结论：TaSQ、KVarN、NOVA-KV 报告的长度接近 BF16，但较弱的 2-bit 方法确实会拉长输出、触顶。ThinKV [2510.01290] 报告量化可让长度膨胀到 5.1 倍。**所以长度、触顶率、循环率必须作为一级指标报告，不能默认没问题。**

**F17：2-bit 的强基线已经比 TaSQ 资料里列的更强，而且彼此的协议不统一。**
- NOVA-KV [2608.04074]：2.22 bit/元素，非正交的保注意力 key 变换加 VQ，SGLang 实现。Qwen3-4B-Thinking AIME25：67.3，BF16 70.0，OSCAR 63.3。GPT-OSS-20B（滑窗混合 MoE）上 OSCAR 崩到均值 13.9，NOVA-KV 保持 72.4。
- OptR [2608.02691]：2.32 bit/元素，输出感知旋转。Qwen3-4B-Thinking 均值 65.38（OSCAR 62.71，BF16 67.58），AIME25 70.7 对 BF16 71.3。QuaRot-INT2 崩到 2.61。
- PN-Mix [2610.19605]（EMNLP 2026）：key 2.26 bit，按 RoPE 对的 q·k 范数分显著性。Qwen3-8B AIME25 64.0 对 FP16 67.0。**它还发现只量化 V 到 2.25 bit 几乎无损，只量化 K 则掉分。**
- Block-GTQ [2606.24033]：按 RoPE 块静态分 key 的比特，V 保持均匀。R1-Distill-Qwen-7B K3V2 下 AIME24/25 为 49.6/38.8（FP16 54.2/37.9）；不保护 sink 的均匀 TurboQuant-MSE 是 0/0。它把"K、V 联合分配"列为未做的工作。
- Dual-QK [2610.09827]：INT2 加 40% query 通道剪枝，90K 下解码 3.75 倍，但 4B-Thinking 的 AIME25 掉约 27 分。
- 注意：各论文的 BF16 参照值不同（同一模型 AIME25 有 70.0、71.3 等），说明采样数、上限、模板不一致。**任何跨论文的比较都必须在我们自己的协议下重跑，不能抄数。**

**F18：TaSQ 的基线只有 VQ 方法（CQ、NSNQuant、NOVA-KV），没有和 KVarN、OSCAR、OptR 在 2 bit 下比过。** KVarN、OSCAR、OptR 用的 TurboQuant 配置各不相同（3/3 bit 保留首尾层、全层 2 bit 关混合精度、不开混合精度）。所以目前**没有一个公认的 2 bit 最强方法**，我们的对比表需要自己统一。

**F19：系统侧，FP4 级 KV 的收益主要来自容量，不来自带宽。**
- MpFA [2609.33135]：B200 上 NVFP4 K + FP8 V，解码比 BF16 快 2.08 倍，但端到端只比 FP8 FlashInfer 快 1.06 倍。
- KV4-RL [2610.14448]：高并发下 KV 精度是主导杠杆，KV4 让解码快 1.44–1.97 倍，而 W4A16、W8A8 约 1.0 倍。朴素 INT4 KV 会伤 RL 训练（8B 上 −4.6 分），INT8 保护 sink 16 个和最近 128 个 token 后修复，长度变化在 1% 以内。
- SAW-INT4 [2604.19157]（只读摘要）：块对角 Hadamard + 按 token 的 INT4 是最好的"能放进分页、能融合"的 4 bit 设计。它还指出按通道 scale、混合精度、VQ 码本、token 淘汰都难以做成分页融合内核，并且在 HF 下测的方法常常低于 SGLang 的 BF16。
- TriAxialKV [2605.17170]：SGLang 的 FP4 KV 在不同模型上不稳定。
- SoK [2609.30854]：同一个 2 bit 方法的推算加速比，在不同 batch/上下文区间从 1.25 倍到 4.82 倍不等。

**F20：评测协议的分歧（来自 R3 的专门检索）。**
- 生成上限从 4K 到 32K 不等；2606.02011 证明 4K–8K 上限会截断循环，系统性高估低比特的端到端收益。
- 压缩比的定义不统一（固定预算除以平均长度 / 按样本的动态预算 / 相对上限）。RLKV [2510.08525] 指出前者会让短样本实际没被压缩。
- 只有 RLKV 表 3 和 SkipKV 表 1 报告了"固定题集的总时间"，**没有任何论文直接报告每个正确答案的成本**。几乎没有论文把 FP8 KV 当基线（例外：UltraQuant、2606.02011 的 B200 容量表）。
- 置信区间几乎没人报告。
- 2608.01631：在固定轨迹回放下，淘汰方法能保住答案却让推理链失效，准确率排名和链的有效性**负相关**；KIVI-2 能保住链。

**F21：校准与离线代理的问题。**
- RECAP [2610.15259]（只读摘要）：在模型自己读的长前缀上校准 W4A4KV4，Qwen3-4B AIME +15.8。它发现按 token 的重要性**跨轨迹不可迁移**（AUC 0.43–0.50）。
- KV-COBRA [2609.24298]：在代理目标上精确求解，反而让困惑度变差。说明代理会误导。
- ReQAT [2606.15682]（只读摘要）：W4A4KV4 FP4 的失败集中在低熵的"符号承诺" token 上。

**F22：MLA。** RoLaQ [2610.20686]：MLA latent 2 bit，容量 3.96 倍，256K 下解码 2.51 倍，但 RoPE key 保持 BF16。同类还有 QuantMLA [2609.36760]、RAQ-MLA [2610.33625]。

## 三、种子查新状态与修订后的指令

### 种子一：状态 **收窄**（不是被否）
已被别人占掉的部分：
- **water-filling 形式本身**：RateQuant [2605.06675] 已发表按（层、头）、K/V 分开、单一字节预算下的闭式解 b_i = b̄ + (ln w_i − mean ln w)/ln β，还给了 AM/GM 形式的增益公式。敏感度来自离线梯度，静态。
- **V 侧 Σp² 律和 K 侧的一种形式**：RECAP [2610.15259] 已写出对未来查询求期望、含 GQA 聚合的逐项敏感度 g^V = E[a²]、G^K = E[a²‖v−y‖² qqᵀ/d]，但只当校准损失的权重用，不做分配，不在线。它的 K 侧是输出 MSE，不是 KL。
- ReadKV [2610.11245] 用 Σ_h α̂² 在读时决定 V 的读取深度，用 query 能量加权决定 K 的通道深度。这是 8 bit 存储上的逐步读取深度，不是存储精度，K/V 分配是固定输入。
- KV-COBRA [2609.24298] 写了 Fisher 形式 ½ΔsᵀF(p)Δs，然后用 F(p) ≤ I/2 放缩，**恰好丢掉了种子一依赖的集中度信息**，可以作为反面对照。
- K 和 V 谁更重要，现有证据互相矛盾：2502.15075、AsymKV 说 K 更重要；PN-Mix 说只量化 V 几乎无损；KV-COBRA 说偏 V 的分配更好。

还剩下的新意（GPT 只能主张这些）：
- (a) 用**同一个**注意力分布统计量（n_eff 或 Σp²，加上"分数差距 vs |q|"的分解）**反向**同时决定 K 和 V 的比特；
- (b) **解码过程中在线**做（RateQuant、Block-GTQ、KVTuner、MultiAlloc、RDKV、KV-COBRA 都是静态或只在 prefill）；
- (c) K 侧用 KL 视角（Var_p(δs)）并把 |q| 和分数差距分开，这点 RECAP 没覆盖；
- (d) 一个可检验的解释：**"K 重要还是 V 重要"取决于头的集中度分布**，可以统一上面互相矛盾的结论。这条如果成立，是种子一最有价值的产出。

修订后的指令：
1. 不要把 water-filling 推导当贡献，直接引用 RateQuant，推导重点放在敏感度的来源和 K/V 反向性。
2. 推导要和 RECAP 的公式对齐，写清楚我们的式子在什么条件下退化成它的，以及多出来的是什么。
3. 必须给出对 (d) 的预测：给定某模型各头的 n_eff 分布，预测"只量化 K"和"只量化 V"哪个掉分更多，然后对照 PN-Mix 的现象。
4. 在线的必要性要有证据：WakeKV [2610.02713] 说 63–85% 的头会漂移，支持在线；但 PN-Mix 发现通道显著性从 prefill 起就稳定。所以在线收益必须来自**头或 token 级集中度的漂移**，而不是通道漂移。要给出漂移量和收益的关系。
5. **一周 kill test 增加一项**：在同字节下和 RateQuant 的离线分配比，而不仅是和均匀分配比。如果在线反向分配比 RateQuant 的输出误差降低不到 10%，或在长 CoT 上的准确率差异落在置信区间内，就放弃在线这一点，只保留 (d) 作为分析性贡献。

### 种子二：状态 **开放**（唯一没找到直接撞车的方向），升为与种子一并列首选
- 没找到任何"按请求难度选择 KV 精度"的论文；据网页摘要，KVTuner 把"按请求的精度需求自适应调 KV 精度"列为开放问题（未核对原文）。
- 最近邻：DPS [2609.34380] 按全局 KV 压力切换**权重**精度（不按请求，不改 KV 精度）；MorphServe [2506.02006] 按负载换量化层；GrowPage [2609.03494] 按请求扩**容量**而不是精度；2606.02011 检测到循环后用 FP16 整条重跑（权重，整条重来）；2510.10964 说精度与数量的最优取舍取决于模型规模，但是全局选。
- 升级代价的积木：可读前缀的渐进码（ReadKV、Fathom）、CPU 上的 FP16 副本（Runtime-Certified、WitCert）。Geodesia-KV 明确说没有稠密副本就无法升级。
- **主要风险**：RECAP 发现按 token 的重要性跨轨迹不可迁移（AUC 0.43–0.50），所以早期难度信号可能很弱。

修订后的指令：
1. 先做**理想上界**（原 kill test 不变），再做**可实现上界**：只用前 1K/2K/4K token 内可得的信号（熵、长度增速、反思词频率、F16 中的长度膨胀早期迹象）预测"低比特会答错"，报告 AUC。AUC < 0.65 就放弃"提前准入"，只保留"中途升级"。
2. 优化模型的目标是**固定题集上每个正确答案的成本**（F20 指出没人报过），约束是显存。把"答对题数/秒"写成 batch、比特、长度、触顶率的函数，长度必须是比特的函数（用 F16 的数据），不能当常数。
3. 升级代价分三种情况分别建模：保留旧低比特 KV 只对新 token 升精度；从 CPU 副本回取重建；从头重跑。给出每种情况在 H200 上的盈亏点。
4. 和种子一的组合是自然的：种子一决定请求内部的按头分配，种子二决定请求之间的总预算。可以合并，但必须分别给出各自的增量收益。

### 种子三：状态 **收窄**
- RECAP 已用"后续查询读它有多强"对历史 K/V 误差加权，但只是一阶、单层，不建模跨步、跨层传播。
- Information-Aware KV [2606.26875]（只读摘要）定义了 token 对远处未来的 Forward Influence，但用于保留，不是误差放大。
- RateQuant 的 Fisher 代理是教师强制下的下一 token 损失，不是多步解码。
- **仍然开放**：2610.05685 的反转（离线选 4 bit、端到端最优是 2 bit）没有任何论文给出解释。

修订后的指令：种子三缩成一个**分析性问题**："为什么离线失真会选错比特宽？"如果能给出跨步传播的解释并预测反转，就作为种子一或种子二论文中的一节（解释分配为什么必须在线或端到端），不单独成文，除非推导出的指标在线可算且明显优于 RateQuant 的 Fisher。

### 种子四：状态 **拥挤**，降为备选
- Runtime-Certified [2605.20868] 已经做了 GPU 上 INT8 K / INT4 V、CPU 上 FP16 原件、按注意力质量（覆盖 0.995）和 ρ_b·η_b 提升最高的块。这就是"在注意力集中的块上回取精确数据"，只是在 4–8 bit。
- WitCert [2607.28699] 用可靠界触发从 CPU 回取 FP16，但在 1–2 bit 下界是空洞的。ReadKV 做了渐进位平面读取，但所有位都常驻。Fathom 把位平面放在主机内存，但只用于 key 扫描。TRACE 在 CXL 控制器里做位平面按精度回取。
- 剩下的窄缝：(i) 基础码在约 1.25 bit；(ii) 只用基础码算出的**期望或概率触发条件**，在 1–2 bit 下仍然有效；(iii) 长 CoT、显存打满时的 PCIe 代价模型。
- 指令：只有在种子一的推导给出了"V 误差 ∝ Σp²·残差方差"的可用触发量之后，才把它作为种子一的读时扩展；单独的"回取高质量块的残差"不能作为贡献。

### 新的排序
1. **种子二**（开放，系统贡献，收益上界一周可测）和 **种子一**（收窄，但 (d) 有解释力）并列。建议优先做"一 + 二"的组合方案：请求间按难度分预算，请求内按集中度反向分 K/V。
2. 种子三降为分析章节。
3. 种子四降为种子一的可选扩展。

## 四、追加给 GPT 的指令

1. **评测协议**（覆盖资料包中冲突的部分）：
   - 生成上限至少 32K，主实验 64K；报告上限值、触顶率、循环率（n-gram，按 2606.02011 的定义）、think 闭合率、平均长度（全部样本和答对样本分开报，RLKV 指出只报答对样本会偏向简单题）；
   - AIME 每题至少 16 次采样，报告 95% 置信区间；
   - 压缩比按每个样本自己的长度算，比特数按有效比特算；
   - 效率指标只用两个：固定题集的总墙钟时间、每个正确答案的成本（GPU·秒）。tokens/s 不作为主指标，因为它会奖励长度膨胀；
   - 吞吐必须在 vLLM 或 SGLang 的分页引擎里测，不接受 HF 下的数字。
2. **成本账本**：任何方案都要写出相对 FP8 和 NVFP4 的端到端收益来源（容量 → batch，还是带宽 → 单步时延），并引用 F19 说明为什么"只省带宽"在 FP8 之上收益很小。按通道 scale、VQ 码本、混合精度是否能放进分页融合内核，要逐项说明（SAW-INT4 的质疑）。
3. **对每个候选方案，Reviewer 必须回答**：
   - 和 RateQuant、NOVA-KV、OptR、KVarN、TaSQ 在同有效比特下怎么比？
   - 如果 F16 中的长度膨胀出现，收益还剩多少？
   - 只读摘要的依据有哪些？如果它们不成立，方案还成立吗？
4. **检查点不变**：完成检查点 1 后停下来，等我审。检查点 1 的输出里，要先单独列一张"补遗吸收情况表"：本补遗的每条 F16–F22 和每个种子的修订指令，你分别怎么处理（采纳 / 部分采纳 / 反驳及理由）。
