# Candidates (orchestrator-proposed, quick novelty check only; see MECHANISMS_zh.md)

### C1 — Foveated in-place refinement: re-look without growing the context

- **Intuition**: Re-looking today appends a newly encoded crop (thousands of tokens) and keeps the old low-resolution view. Instead, encode the image at low resolution first; when the model zooms on region R, encode R at high resolution and REPLACE the KV slots of R's low-resolution tokens in place, giving the new tokens sub-grid 2D M-RoPE coordinates inside R's footprint. The visual memory stays one coherent image map that sharpens locally; its size is constant regardless of how many re-looks occur, and the model cannot ignore the zoomed pixels by falling back on the old view, because the old view of R is gone.
- **Gap it attacks**: Context growth and wasted re-look compute in thinking-with-images (DeepEyes 2505.14362, Pixel Reasoner 2505.15966, ZoomEye, ViCrop 2502.17422); crops are ignored (2510.23482); PRCR 2606.26631 reuses stale KV but still appends.
- **Source inspiration**: Foveated vision and saccades (biology); adaptive mesh refinement in numerical PDEs (refine cells in place instead of appending a second grid).
- **How it maps**: Low-res encode at prefill (e.g., 1/4 of native tokens). A zoom action (tool call or special token) triggers high-res encoding of R through the vision encoder, then the new tokens' KV for all LLM layers is computed with attention to the prompt prefix and the rest of the (current) image, at positions inside R's footprint, and written into the slots of R's old tokens (variable count handled by a small paged slot table). Later CoT tokens attend to the refined map. Earlier CoT tokens' KV were computed against the old view (as with appending).
- **Why it could work / feasibility**: Qwen2.5-VL/Qwen3-VL use native dynamic resolution and 2D/3D M-RoPE, so sub-grid positions are expressible; light LoRA on mixed-resolution inputs may be needed. Memory upper bound is constant.
- **Novelty vs. closest in-domain work**: Foveated Compression 2610.07729 chooses one native-resolution cell at prefill (one shot, no in-reasoning refinement; finds whole-image resizing a strong baseline); PRCR 2606.26631 (rebinding, append); LoRe 2610.27341 (strengthens existing KV, no new pixels). (quick check only)
- **Main risk**: Writing new tokens into earlier positions after CoT has been generated (causality/positional consistency like PRCR's failure mode); mixed-resolution OOD; downsampling may already be enough.

### C2 — Visual KV pyramid: coarse resident, fine on demand

- **Intuition**: Keep only pooled coarse visual KV (e.g., 4x4 pooled, 1/16 of tokens) resident in HBM, each coarse token carrying a log(count) bias so its attention mass approximates its region's; keep full-resolution visual KV in host memory (or recompute it from the image, since visual KV depends only on image + prompt). Each decode step reads coarse tokens; regions whose coarse attention mass is high get their fine tokens fetched and attended exactly. Because the coarse layer always covers the whole image, a changing critical set never hits a permanently deleted token.
- **Gap it attacks**: VisionPulse 2605.31457 shows the per-step critical visual set is sparse and changing, so it reads sparsely but keeps all visual KV in HBM; eviction methods (MM-ShiftKV 2607.22586, HAE 2602.02197, MadaKV 2506.15724) delete permanently.
- **Source inspiration**: Image pyramids / mipmaps (graphics), Barnes-Hut / fast multipole (far field approximated by aggregates, near field exact).
- **How it maps**: At prefill, per layer and KV head, pool keys/values of each spatial cell into one coarse entry (mean key + log-count bias, mean value); offload fine KV to pinned CPU memory with prefetch; per step, compute coarse logits, choose top cells by mass, fetch their fine KV, compute attention over fine tokens of selected cells plus coarse tokens of the rest plus all text KV.
- **Why it could work / feasibility**: Images have 2D locality; attention to visual tokens is sparse per step; training-free.
- **Novelty vs. closest in-domain work**: Text analogues Quest 2406.10774 (page min/max bounds), ShadowKV, InfiniGen, OasisKV 2608.08097 (offload + sparse fetch); VisionPulse (step-wise sparse read, all HBM); VisMemo 2610.25136 (cross-request approximate reuse). (quick check only)
- **Main risk**: PCIe bandwidth at full batch; coarse logit approximation under RoPE; reviewers calling it "Quest for images".
