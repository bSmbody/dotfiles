# SaccadeKV 设计审阅：哪些合理，哪些要改（2026-11-11）

审的是 `SACCADE_FULL_zh.md`。结论：整体框架合理，可以开工；有 4 处机制设计和 6 处实验设计需要改。按重要程度排序。

---

## 一、合理、不用动的部分
- **底图 + 固定容量缓冲区的两层结构**：底图不删，所以退回是精确的；总量是常数。
- **扫视后重算"图像 + 问题"**：只有 1–2K token，代价小，换来一个干净的不变量。
- **物理上拼到末尾、逻辑上原地**：不需要自定义 mask 或 kernel，原型好写。
- **由模型自己决定看哪里**：方法只管"看了之后记忆怎么变"。
- **先跑 E1 再做别的**：一周内就能知道地基成不成立。
- **主指标用每答对一题的成本**，并且在显存打满时实测。

---

## 二、机制设计要改的 4 处

### 1. 坐标系应该固定在"底图网格"上，而不是"原生网格"上（重要）
**现在的设计**：以原生网格为整数坐标，底图 token 取中心，相邻底图 token 的坐标间隔是 2。

**问题**：模型训练时见到的图像，相邻视觉 token 的坐标间隔永远是 1。按现在的设计，**所有底图 token** 的间隔都变成 2，连一次都没放大时，输入就已经偏离训练分布了。

**改法**：反过来。
- 底图 token 用整数坐标、间隔 1，和普通低清图完全一样；
- 高清 token 用底图格子内部的小数坐标，例如 2 倍时取 i+0.25、i+0.75。

**好处**：
- 没放大时，输入和"普通低清图"一模一样，不会比整图缩小更差；
- 偏离训练分布的只有少数高清 token；
- 图像后面文本的起始位置按底图大小算，和模型平时的行为一致。

原来的"原生网格坐标"保留为消融对照。

### 2. 注视区域的分辨率不能固定成"原生"，要按 token 预算定放大倍数（重要）
**现在的设计**：注视区域用原生分辨率（L1），可选 2 倍（L2）。

**问题**：
- V* 的目标很小，在 2K 的图里可能只有 30×30 像素。原生分辨率下，一个 28 像素的 token 就把它盖住了，看不清。DeepEyes 这类模型之所以放大有用，是因为它把裁剪图**放大**到固定尺寸再编码。
- 反过来，模型框了很大一块时，按原生分辨率编码会超过缓冲区容量。

**改法**：每次注视给一个 token 预算（例如 256），放大倍数取"不超过预算的最大倍数"，在 2、4、8 倍（相对底图）里选。小框放大得多，大框放大得少。

**连带影响**：系统版不能只用整数坐标了，需要让 vLLM 对视觉 token 在线计算位置编码。这是一处小的 kernel 改动。

### 3. 视频版"原地放进时间坐标"在 Qwen3-VL 上不能直接成立（重要）
**问题**：Qwen3-VL 的视频输入是"时间戳文字 + 一帧图像"交替排列，位置是顺序往后排的。在两帧之间插入更多帧，后面所有 token 的位置都要往后挪，思维链的 KV 就全部失效了。图像上的二维子网格办法在这里用不上。

**改法**：
- 给视觉块预留固定的位置范围：文本从一个固定位置开始，这个位置按"底图 + 缓冲区"的最大长度算；
- 每次时间扫视，把整个视觉块（底图帧 + 高清片段，按时间顺序排好）重新 prefill 一遍。约 2 万 token，在 H200 上不到 1 秒；
- 思维链的位置不变，KV 保留。

**还缺一个前提**：需要一个会主动"细看某一段"的开源视频模型，相当于图像上的 DeepEyes。第 1 周要确认有没有可用的。没有的话，视频版只能用注意力引导的变体，说服力会弱一些。

### 4. 重复注视和重叠框的处理要写明
- 模型再次放大同一区域时：不重新编码，只更新它在缓冲区里的"最近使用"时间；
- 新框和已有注视区域部分重叠时：重叠的格子以新的为准，旧注视整体移出。

## 三、实验设计要改的 6 处

### 1. E2 的训练要和推理时的用法一致（重要）
**现在的设计**：只在"开头就给好的混合分辨率图"上做自蒸馏。

**问题**：推理时的真实情况是，模型发出放大调用后，要**回头去读图上变清楚的那块**。DeepEyes 训练时学的是"读紧跟在后面的裁剪图"，从没学过回头读。静态蒸馏教不会这一点。

**改法**：加一部分轨迹级蒸馏。
- 老师：DeepEyes 用原本的追加方式跑出的完整轨迹；
- 学生：同一条轨迹，放大时改用 SaccadeKV；
- 目标：放大之后那一段的输出分布对齐老师。

### 2. E1 加一组"只有底图"，并把"原地 vs 追加"定为第一个判断信号
- 加 **G0：只有底图**，作为下限。这样才能算出高清区域到底带来多少提升。
- G4 改成按"问题 2"的方式选放大倍数，并加 2、4、8 倍的对比。
- **最重要的比较是 G4 − G3**：token 数相同时，原地放入比追加裁剪图好多少。这直接决定论文的核心论点能不能成立。

### 3. 把"原分辨率 + 2 bit 视觉 KV"放进主对比
已有结果显示，视觉 KV 直接量化到 2 bit 只掉约 1 分，体积缩小 8 倍。这是一个很强又很简单的基线，必须在 E3、E4 里按**相同字节数**和 SaccadeKV 比，而不能只当作可叠加的技术。

### 4. E4 换成天然需要看很多次的任务
**现在的设计**：靠提示词要求模型逐个核实，逼它多看。这是人为制造的场景，结论不好推广。

**改法**：
- 主要任务换成天然多次注视的：长文档问答（几十页，底图是所有页的低清版，注视某一页）、多图对比、8K 图的跨实例题；
- 提示词逼迫只作为补充的压力测试。

### 5. 统计功效
V* 只有 191 题，准确率的 95% 置信区间约 ±6 分，1–2 分的差距测不出来。
- 主要结论用 HR-Bench 4K/8K 和 MME-RealWorld-Lite 合并的约 3.5K 题来下，V* 单独报告但不作为判断依据；
- 用配对检验。

### 6. 成本里要算上重算的开销
SaccadeKV 每次扫视要重算图像和问题。原型阶段的"KV 占用积分"没有计入这部分。
- 加一列"额外 prefill 的 token 数"；
- 系统阶段实测的 GPU·秒本来就包含它，不用改。

## 四、对实验安排的影响
| 改动 | 影响 |
|---|---|
| 坐标系、放大倍数 | 都在 E1 的代码里，工作量几乎不变 |
| 轨迹级蒸馏 | E2 从 1 周变成约 1.5 周；要先跑出老师轨迹（E0 的副产品） |
| vLLM 在线位置编码 | 系统版多 2–3 天 |
| 视频位置方案 + 找视频模型 | 第 1 周加一项调研；视频实现多约 3 天 |
| 长文档任务 | E4 多一个数据集的适配，约 2–3 天 |

总时间从 11 周变成约 12–13 周。

---

## 五、建议的第一周清单
1. 用底图网格坐标实现混合分辨率组装，跑 E1 的 G0–G5，同时对比两种坐标系。
2. 跑 E0，顺便存下 DeepEyes 追加式的完整轨迹，留给 E2。
3. 调研有没有会主动细看片段的开源视频模型。
4. 看 G4 − G3：这是整个项目最早、最重要的信号。
