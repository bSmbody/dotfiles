
### C2 verdict

**Verdict**: `reject(reason=core computation already published - SeKV and Multipole in text, Gaze Attention and ViMoD on visual KV - and host offload loses to HBM-resident 2-bit visual KV)`

**Novelty search (37 queries, arXiv, mostly --since 2025-01-01; recency sweep --since 2026-06-01, which covers 2026-06..2026-11)**: hierarchical KV cache vision; multi-resolution KV cache; visual KV cache offloading; coarse-to-fine visual token attention; multimodal KV cache retrieval; visual KV sparse fetch; pooled visual tokens decoding; multimodal KV offloading CPU; vision language KV retrieval decoding; multimodal sparse attention decoding; cluster KV retrieval; centroid KV cache retrieval; ClusterKV; RetrievalAttention; MagicPIG; ShadowKV; InfiniGen; RetroInfer; fast multipole attention; Barnes-Hut attention; hierarchical attention approximation; multimodal KV cache eviction; visual token recall decoding; recoverable visual token; and 2026-06+ sweep: visual KV cache reasoning; visual memory on demand; multimodal reasoning KV cache; thinking VLM efficient decoding; visual KV quantization; image KV cache compression; long video KV offloading; region-level visual KV selection; spatial block sparse attention VLM; video KV cache retrieval; dynamic visual sparsity decoding; KV cache CPU offload sparse; coarse fine KV cache; visual token pyramid. Full text read: [2606.31145] [2506.13059] [2605.13080] [2610.12060], plus [2605.31457] [2406.10774] [2611.07593] [2610.07729] for grounding/baselines. Abstract-only near hits, not used as evidence: Reroute 2606.12412, CatchUp 2610.23324, ReTrace 2610.25005 (recoverable visual tokens, prefill depth); RCR 2610.31433 (drift-triggered visual KV re-selection vs InfiniGen); V-Rex 2512.12284 (cluster KV retrieval, streaming video); CTkvr 2512.15550 and LycheeCluster 2603.08453 (centroid-then-token / hierarchical text indices); Bifocal 2610.18399 (pooled coarse image plus native patches, prefill).

**Evidence**:
- [2606.31145] SeKV is the C2 computation in text, almost word for word: per span a mean key/value "coarse entry" stays on GPU, fine detail sits on CPU, a per-step, per-head zoom-in restores selected spans, and unselected spans stay in the same softmax "with log|S| added to its score so that one entry competes in proportion to the tokens it stands for" [full text, Section 3.2]. Two results hurt C2 directly. Training-free routing by q·k̄ (C2's selector) costs 2.8-3.8 points compared with a trained router [Section 4.4, Table 3]. Fixed-length chunks (the 1D analogue of fixed spatial cells) cost 2.4-2.9 points compared with content-aware spans.
- [2506.13059] Multipole Attention already does the Barnes-Hut / fast-multipole step for long-CoT reasoning models, training-free. Clusters outside the top set contribute N_i·exp(q·Kc_i)·Vc_i, which is C2's mean key plus log count. Top clusters get exact attention, and a hierarchical coarse-to-fine refinement is included [Section 3.1-3.4 / Eq 1-2]. It beats Quest at aggressive sparsity. It keeps the KV in HBM.
- [2605.13080] Gaze Attention applies this to visual KV. It uses fixed spatial regions (6x6 tokens), mean-pooled keys as region descriptors, and per-head TopK region selection at every decoding step. Selected regions are loaded from CPU (ReKV-style offload, 79.8% less KV memory) [Section 3.2, 4.4]. The differences from C2: it needs full fine-tuning (~384 H100-h), and unselected regions get zero mass, with learnable context tokens standing in for coarse entries. It also argues that training-free sparse visual KV fails because the model "was never exposed to such sparse visual inputs" [Section 4.2].
- [2610.12060] ViMoD applies this to visual reasoning on Qwen3-VL. Grid-initialized pooled Coarse visual KV stays in attention throughout decoding, and selected Fine groups are added in the same attention [Eq 1, 4-5, 8]. Its router is learned, Fine KV stays on GPU (peak memory 42.67 vs 38.40 GiB), and the coarse entries have no log-count term.
- What is left of C2 after these four: it is training-free, uses a fixed spatial grid, selects by coarse attention mass, and offloads fine KV to host, on thinking VLMs. Each piece has a published precedent, so the paper reads as "SeKV/Multipole on Gaze Attention's regions without training". That is a recombination, not a new mechanism. It also inherits SeKV's measured penalty for training-free routing and Gaze Attention's warning about training-free sparsity.
- Are spatial cells a real difference from token pages or clusters? Yes, but in the wrong direction for the coarse approximation. The coarse-logit error is the within-cell spread of q·k (see attack a). k-means in key space ([2506.13059]) or content-aware spans ([2606.31145]) shrink that spread directly. Image adjacency shrinks it only where the content is smooth, and Barnes-Hut's working condition is smoothness of the kernel, which here is smoothness in key space, not in pixel space. Spatial cells win only on zero clustering cost and alignment with crops. In raster order a 4x4 cell is 4 runs of 4 tokens, versus a 16x1 strip for a 16-token page. Even that is not new for visual KV: [2605.13080] uses spatial regions and [2610.12060] starts from a grid.
- [2605.31457] VisionPulse gives the motivation, and token-level FastV-style top-K per step keeps 5% of visual tokens with all KV in HBM [Section 4.2]. That 5% is the fetch fraction used in attack (c).
- [2406.10774] Quest selects pages by a channel-wise max/min upper bound precisely "in order not to miss critical tokens" [Section 3.4]. C2's mean-key selector is the opposite choice: a lower bound that is weakest exactly on isolated sharp tokens.
- [2611.07593] Plain 2-bit visual-KV quantization (KIVI) on Qwen3-VL-8B, Video-MME: 71.30 vs bf16 72.33 [Section 3.5, Table 5]. That is 8x smaller visual KV, all in HBM, no PCIe traffic, no selection error, and the method gives up to 8x larger decode batch at equal HBM [Section 3.6].
- [2610.07729] Whole-image downsampling is a strong iso-token baseline (matched-budget downsample 70.99 vs a learned one-region selector 69.61), and only 21.5% of examples are sensitive to which 3x3 cell keeps native detail [Section 4.2-4.3, Table 1]. So the visual stream is often compressible uniformly, which favors (e).

**Plausibility attacks**:
- (a) Coarse logit. The true cell logit is LSE_i(s_i) = log n + log mean exp(s_i). C2 uses log n + mean(s_i). By Jensen this is always an underestimate. The gap is about Var(s)/2 for diffuse scores and huge for one spike: with n=16, one token 8 nats above 15 flat ones, LSE ≈ 8.0 while the coarse value is 2.77+0.5 = 3.27, a 4.7-nat (~110x) underestimate of the mass. A cell holding one decisive digit or tick label therefore ranks below a cell of uniformly mediocre tokens. That is the V*/HR-Bench/chart failure mode, in the sharp retrieval heads that matter most. SeKV's needle analysis shows the same: 38% of failures are routing misses, and only 25-29% of heads expand the needle span [2606.31145, Appendix F]. The coarse value (mean V) carries the same bias for unselected cells. RoPE / M-RoPE: averaging post-RoPE keys over a 4x4 cell shrinks each rotary pair by |sin(2θ)/(4 sin(θ/2))| per axis (≈0.47 at θ=1 rad, ≈0.85 at 0.5). That erases the high-frequency position channels, which matter for "which cell". This part is fixable by pooling pre-RoPE and rotating at the cell center ([2606.31145] reconstructs pre-RoPE; [2506.13059] uses windowed RoPE), but it is another approximation. Fixing selection with Quest's upper bound makes C2 Quest-on-cells plus Multipole.
- (b) Visual share of KV. This is an estimate from the Qwen3-VL-8B LLM config (36 layers, 8 KV heads, head_dim 128 → 144 KiB/token in bf16) and 32x32 px per merged visual token; measure before relying on it. MathVista/MathVerse images (~0.2-1.3K tokens) with 2-8K CoT give a visual share of decode reads of roughly 5-35%, so the pyramid saves at most that on the math benchmarks. V* (~2246x1582 → ~3.5K tokens), HR-Bench 4K (~8K) and 8K (capped near ~16K) put visual at 60-90%, but those tasks have short CoT. Video-MME/LVBench (~15-60K tokens) are >90% visual with short answers. Long CoT and large visual KV mostly do not occur in the same request. Where visual KV dominates, prefill and capacity dominate cost, not per-step reads over a 5-20K CoT. A 16K-token image is ~2.3 GB/sequence: a real capacity problem, but one that (e) also solves.
- (c) PCIe versus HBM. An H200 reads HBM at ~4.8 TB/s against ~50 GB/s practical PCIe Gen5 x16 per GPU (often shared on HGX boards), a ~96x ratio. Take N_v=8K, a 5% fetch per step [2605.31457], and no reuse: 410 tokens x 144 KiB ≈ 59 MB per sequence per step. That caps throughput at ~50 GB/s / 59 MB ≈ 850 tok/s per GPU regardless of batch. Reading all visual KV from HBM at batch 64 is 75 GB / 4.8 TB/s ≈ 16 ms per step, faster than fetching 5% of it over PCIe (≈ 75 ms). An HBM-resident 2-bit visual KV reaches a batch of ~230 at ~26 ms per step (≈ 8-9K tok/s, estimate). The pyramid matches that only if the fetched-cell hit rate in an HBM cache is ≥ ~90%. Selection also needs layer-l queries, which puts every fetch on the per-layer critical path unless it is predicted, InfiniGen-style. The "recompute from image" fallback is not exact: visual KV at layer l>0 depends on attention over the whole prompt+image prefix at lower layers, and that prefix is exactly what was offloaded.
- (d) Spatial clustering. The per-stage evidence covers 11.8% of the image, but the union over stages is 36.5% [2610.12060, Fig 1]. Only 21.5% of examples prefer a particular 3x3 cell [2610.07729]. Trained 6x6 spatial routing hits the right object only 51-58% of the time [2605.13080, Table 4]. Charts and documents need scattered small tokens (ticks, legend, labels), and visual attention sinks are scattered high-mass tokens [2610.12060, Section 2]. All of these inflate the cell-level fetch-amplification factor (cells fetched x16 / critical tokens), and per-KV-head selection in GQA multiplies it again. Nobody has measured this; it is load-bearing.
- (e) Simpler baselines dominate on the main axis. Uniform 2-bit visual KV costs ~1 point at 8x compression with no new failure mode [2611.07593]. Iso-token downsampling is hard to beat [2610.07729]. Either can be combined with HBM-resident step-wise sparse reading (VisionPulse/Quest) for read savings. C2 has to beat "2-bit visual KV + Quest-style sparse read" at matched resident bytes, and attacks (a) and (c) predict it will not.
- Mapping and grounding: the far-field/near-field mapping is clearly stated, but the source's validity condition (Barnes-Hut opening criterion: kernel nearly constant across the cell) is never named. Spatial cells do not ensure it (see attack a). The contribution type (method) passes.

**Cheapest falsification experiment (≤1 week, 8xH200, HF + hooks, no offload kernels)**: Qwen3-VL-8B-Thinking on V* (191), HR-Bench-4K (200 sampled), MathVerse vision-only (300), Video-MME long (150).
- Day 1-2: log per step, every 4th layer, per KV head: visual attention mass and the top-mass visual tokens.
- Offline, measure (i) the visual share of KV bytes and decode reads; (ii) for 4x4 cells, recall of the oracle top-cell set at 5/10/20% fetch budgets under three selectors: mean-key + log n, Quest max bound, and k-means clusters of the same size; (iii) the fetch-amplification factor; (iv) the step-to-step hit rate h of an HBM cell cache sized at 2x the per-step fetch.
- Day 3-5: run end-to-end accuracy with the pyramid simulated in HBM (masking: coarse entries for unselected cells, exact tokens for selected ones). Compare at matched resident visual bytes (1/8 of bf16) against (B1) KIVI-style 2-bit visual KV, (B2) iso-byte image downsampling, and (B3) VisionPulse token top-K.
- Day 6: microbenchmark pinned-memory gather H2D with all 8 GPUs fetching concurrently, then plug the measured h and fetch fraction into the throughput model.
- **Kill if any of these holds**: (1) the pyramid is not ≥1.0 point above B1 averaged over V*, HR-Bench and MathVerse at matched resident bytes; (2) h < 0.90 at the accuracy-preserving fetch budget, so the PCIe-bound throughput falls below B1's HBM-resident throughput; (3) the mean-key selector's oracle-cell recall is <80%, or ≥10 points below the Quest bound or k-means clusters, which reduces C2 to Quest/Multipole on cells. Separately, if the visual share of decode reads is <30% on MathVerse, drop the long-CoT math claim.

**Strongest objection in 1 sentence**: SeKV (text, log-count coarse entries plus CPU fine detail plus per-step zoom-in) and Gaze Attention/ViMoD (per-step spatial visual-KV routing with CPU offload, or with persistent pooled coarse KV) already cover the computation. The only new choices left, training-free mean-key selection and PCIe fetch, are the two that the evidence says lose: SeKV measures a 2.8-3.8 point penalty for training-free routing, and PCIe is ~96x slower than HBM while 2-bit visual KV costs ~1 point.

Verdict: reject(reason=already done in text by SeKV/Multipole and on visual KV by Gaze Attention/ViMoD; offload is dominated by 2-bit HBM-resident visual KV)


### C1 verdict

- **Verdict**: reject(reason=the in-place delta over appending saves only the displaced low-res tokens, about 1-2% of KV; the low-res-first saving is already FoveateR's; it adds stale, question-blind visual KV and untested mixed-resolution inputs)

- **Evidence**:
  - **Novelty search** (26 queries, 2025-01 to 2026-11, including a 2026-06 to 2026-11 recency sweep of 13 queries; full text read for 6 papers). No paper replaces a region's visual KV in place with newly encoded high-resolution tokens during decoding. The four closest papers each do part of it:
    - [2604.21079] FoveateR (ECCV 2026): Qwen2.5-VL starts from a 224²/336² view. It emits `<fov>`, encodes the high-res crop and *appends* it to the KV cache (M_t = M_{t-1} ⊕ o_t, Section 3.1). Its limitations section names "linear growth in memory & compute" and "which evidence to retain, update, or discard" as future work. C1 is the follow-up that paper already names.
    - [2610.07729] Foveated Compression: in-place native-in-compressed replacement on a shared native-grid M-RoPE. Compressed tokens sit at the top-left coordinate of their 3x3 block. It runs once at prefill, and its compressed tokens needed a self-distilled merger.
    - [2610.12060] ViMoD: Coarse plus swappable Fine groups during decoding. All Fine KV comes from the full-res prefill and stays stored, and peak memory goes *up* (42.67 vs 38.40 GiB).
    - [2606.26631] PRCR: re-inserts prefill visual KV during decoding by appending, with no new pixels. Its limitations section says it fails for zoomed or re-encoded regions.
    - Hits read at abstract level only, not used as evidence: Blink 2512.10548 (in-forward token super-resolution then drop, layer-wise, no decode-time re-encode), ReMAP 2610.05097 (re-encoded local latent tokens inserted into the sequence), GazeVLM 2605.07817 (no new tokens).
    - Conclusion: the mechanism is new as stated, but a reviewer will read it as FoveateR plus Foveated Compression's in-place grid, applied late.
  - **(c) The efficiency delta is small.**
    - Token count. Qwen3-VL encodes 32x32 px per token, so a V*-sized image (2246x1582, [2604.21079] Section 4.2) gives N ≈ 3.5k native tokens. Low-res-first at 1/4 gives N_low ≈ 870. A zoom on a region covering f = 5% of the image adds ≈ 175 tokens at native resolution (≈ 700 if upsampled 2x). In-place replacement removes only f·N_low ≈ 43 tokens. The new tokens are needed either way.
    - Effect on total KV. A thinking model also holds thousands of CoT tokens (to be measured), so the extra saving of in-place over appending is roughly 1-2% of KV per zoom. Most trajectories make 1-2 calls; DeepEyes almost always makes a single call ([2608.06270] Section 3.3.3).
    - The "constant budget" bound is the full image at zoom resolution. Native-once already meets that bound with no machinery.
    - The large saving (N → N_low) belongs to any low-res-first-then-zoom method, i.e. [2604.21079], or simply DeepEyes run on a downsampled input.
    - Resizing is a strong baseline. At about 20% tokens, whole-image resizing beats the best single native cell: 70.99 / 72.43 vs 69.61 macro ([2610.07729] Table 1). Region choice matters on only 21.5% of examples (Section 4.2).
    - Compression can raise cost. Under compression, responses grow 15.9-29.9% longer and total time can exceed the uncompressed model ([2610.12060] Section 4.4). Cost per correct answer can therefore rise even when tokens per step fall.
  - **(a) Causality and position.** PRCR is evidence that inserting visual KV mid-decode at positions far from the decode point is the failing configuration:
    - Direct reuse at the original image coordinates: 23.5% accuracy, 81% stuck rate. The best placement is within L=2 of the current token, and accuracy falls as entries move further left ([2606.26631] Sections 2.2 and 4.4).
    - C1 differs in one way: it replaces tokens instead of duplicating them, so the query-to-image offset stays in distribution.
    - The harder problem is computing the new tokens' deeper-layer KV. Recomputing them causally (they attend only to tokens before R's slots) keeps positions in distribution, but the new tokens never see the question or the CoT. That is weaker than an appended crop, which is encoded with the reasoning that asked for it.
    - Letting them attend to the question and CoT from image-region positions means negative relative distances. A causally trained model never sees those.
    - Every token after R (later image rows, the question, all CoT so far) keeps KV computed against the *old* R. The old view is therefore not "gone": it persists in those tokens' stored K/V. Recomputing them costs a re-prefill of thousands of tokens.
    - This undercuts C1's claim that the model "cannot ignore the zoomed pixels". Separately, [2608.06270] attributes crop-ignoring to policy calibration from outcome-only RL, not to the old view staying in context.
  - **(b) Mixed resolution without training.** No paper read here shows that untrained Qwen-VL tolerates sub-grid or stride-2 coordinates. The only working mixed-resolution grid ([2610.07729] Section 3.4) trained a merger with self-distillation.
    - From background knowledge, not checked in this run: Qwen3-VL's DeepStack also injects multi-level ViT features at the visual positions in the early LLM layers. Each recomputed token would need those features, which is extra serving-engine work.
    - A LoRA is likely needed, as the candidate admits. That LoRA would also be learning the stale-KV mismatch.
  - **(d) Re-looks add little on V*/HR-Bench.** At max_pixels = 16384 tokens:
    - Removing interleaved images from DeepEyes-7B changes V*/HR-4K/HR-8K by 0.0 / -0.5 / +0.2 ([2607.27830] Appendix Table 2).
    - A single-pass routing method reaches a 79.1 mean, against 76.0 for DeepEyes ([2607.27830] Section 5).
    - The exception is Qwen3-VL-8B, whose crops do carry signal (+21.3 pp policy gain on VisualProbe, [2608.06270] Section 3.3.1). Re-looks may matter mainly where the pixel cap forces downsampling, e.g. HR-Bench 8K. There, C1 still saves only the displaced tokens compared with appending.
  - **Mapping, grounding and contribution type.**
    - Contribution type: methodological (passes).
    - The AMR / foveation mapping is clear (cell = region's token block, refine in place). However, both sources are budget-neutral: AMR coarsens elsewhere and the fovea moves. C1 only refines, so the "constant budget" principle it borrows is not actually carried over.
  - **Salvage path**, if the orchestrator wants to keep this lineage: a budget-neutral saccade. Refine R while re-pooling the previous fovea, so visual KV = N_low + N_fovea exactly. It inherits every attack in (a) and (b), and it must beat downsampled DeepEyes / FoveateR on KV per correct answer by more than 5%.
  - **Cheapest falsification experiment** (≤ 1 week on 8xH200, HF transformers with manual DynamicCache edits; Qwen3-VL-8B-Thinking with crop tool, plus Qwen2.5-VL-7B; V* with its GT target boxes, HR-Bench 4K/8K with the model's own zoom boxes):
    - Day 1, accounting: log visual vs CoT tokens, number of zooms and box areas f on the native baseline. Compute the ceiling on in-place savings, Σ f_k·N_low / total KV.
    - Days 2-5, five conditions at matched visual tokens:
      - (1) native once;
      - (2) whole-image downsample to N_low + f·N;
      - (3) low-res + crop appended at the zoom point;
      - (4) low-res + crop placed in place *at prefill* (the mixed-resolution upper bound, no staleness);
      - (5) C1 proper: low-res prefill, decode to the zoom point, causally recompute the crop's KV at native-grid coordinates (low-res tokens at stride 2), overwrite R's slots, continue decoding.
    - Report accuracy, PRCR-style stuck/repetition rate, generated length, peak KV, and KV·steps per correct answer under a memory-saturated batch.
    - **Kill criterion**: abandon C1 if any one of these holds:
      - the day-1 median ceiling is < 5% of total KV;
      - (5) is more than 1.0 pt below max((2), (3)) on mean(V*, HR-4K);
      - (5) cuts KV per correct answer by < 5% vs (3);
      - (5)'s stuck rate is more than 2x that of (3).
    - Read (4) − (2) as the value of local fidelity and (4) − (5) as the cost of stale KV.

- **Strongest objection in 1 sentence**: Writing the zoomed region in place, rather than appending it, saves only that region's displaced low-res tokens (roughly 1-2% of a thinking model's KV); the real saving comes from starting low-res, which FoveateR [2604.21079] already does, and in exchange C1 gets question-blind, stale, mixed-resolution KV that the model was never trained on.

One-line verdict: reject (reason=the in-place delta saves only the displaced low-res tokens, about 1-2% of KV, vs appending; the low-res-first saving is prior art in FoveateR; it adds stale/question-blind KV and mixed-resolution OOD risk).
