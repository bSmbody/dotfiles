# VisionPulse: Dynamic Visual Sparsity for Efficient Multimodal Reasoning

## What this paper does
Training-free step-wise visual token pruning for thinking LMMs (e.g., Qwen3-VL-4B-Thinking). At every decoding step it scores visual tokens by head-averaged attention at an anchor layer (FastV-style, l_a), keeps the top-K_t visual tokens for later layers, and sets K_t from the step's visual attention mass (which correlates with the number of activated visual tokens). Reports ~5% visual tokens kept per step, 11.2% shorter reasoning traces, near-unchanged accuracy, up to 1.30x end-to-end speedup (batch 8, 1K generated tokens). All visual KV stays in GPU memory.

## Goal-by-goal answers
### Goal: How is the per-step critical visual set chosen, and at what granularity?
Token-level: S_i^t = mean over heads of attention probability from q_t to v_i at anchor layer l_a, then Top-K_t tokens retained from l_a onward [full text, Section 4.2 / Eq 2-3]. K_t is set by the step-wise visual attention mass M_vis^t [Section 4.3 / Eq 4].
### Goal: What evidence shows the critical set is sparse and changing?
Qwen3-VL-4B-Thinking visual attention mass is step-dependent (rises when the model checks visual details, falls in text-only reasoning), and the activated regions shift with reasoning content; prefill-time attention gives little guidance [Section 3.2, Fig 1]. Keeps 5% visual tokens per step [Abstract; Section 6].
### Goal: Does it save memory, and what speedup?
It prunes reads, not storage: no offload or eviction is described; end-to-end speedup up to 1.30x vs dense at batch 8 and 1K generation [Section 5.7, Fig 5]. Cost analysis: decode cost scales as O(g(p+v)+g^2), so visual tokens add a per-step baseline cost [Section 3.1 / Eq 1].
