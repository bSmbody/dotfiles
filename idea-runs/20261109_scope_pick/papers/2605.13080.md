# Gaze Attention: Query-Adaptive Visual Routing for Efficient Multimodal LLMs

## What this paper does
Gaze Attention partitions visual keys into fixed spatial(-temporal) regions (default 6x6x1 tokens), summarizes each region by its mean-pooled key, and at every decoding step lets each attention head pick the TopK regions by q·descriptor and attend only to their tokens, plus text KV and a few learnable per-image "context tokens" that are always visible. Trained end to end (Cambrian recipe with full fine-tuning and a progressive TopK schedule, ~384 H100 GPU-hours per config). Matches dense attention on 13 image and 6 video benchmarks with up to 90% fewer attended visual KV entries; with ReKV-style CPU offload, reduces KV memory ~80%.

## Goal-by-goal answers
### Goal: Does it do per-decode-step region-level selection of visual KV using pooled keys?
Yes. "Each region is summarized by a descriptor d_g, obtained by mean-pooling the key vectors"; at decoding step j the query selects TopK regions and "attends only to the visual key-value pairs within these regions"; "re-selects regions per query at every decoding step", so ignored regions can return later [full text, Section 3.2 / Eq 2]. Each attention head selects independently [Section 4.1].
### Goal: Are unselected regions represented in attention (far-field approximation)?
No coarse per-region entries. Unselected regions get zero attention; global information comes from |C|=4 learnable context tokens per visual unit that attend only to their unit's tokens and stay visible [Section 3.3-3.4 / Eq 3-4].
### Goal: Does it offload fine visual KV to host and fetch selected regions?
Yes, in the efficiency analysis: "we adopt the KV-cache offloading strategy of ReKV, where the full cache resides in CPU RAM/SSD and only the selected regions are loaded onto the GPU", giving ~83.9% fewer attention FLOPs and 79.8% less KV memory; wall-clock with plain PyTorch is 1.5-1.6x dense, due to selection/gather overhead [Section 4.4, FLOPs & Memory].
### Goal: Is it training-free? What about training-free baselines?
Not training-free: full fine-tuning with progressive TopK [Section 4.1, Appendix E]. It argues training-free eviction (InfiniPot-V, HERMES) degrades at small KV because "the MLLM was never exposed to such sparse visual inputs during training" [Section 4.2]. Routing accuracy vs SAM-derived masks is only 51-58% (random 11%) [Section 4.4, Table 4]. Limitations: fixed-size regions may not align with objects; mean-pooled descriptors treat all tokens equally [Appendix C].
