# Look Back, Think Ahead: Visual Memory on Demand for Efficient Multimodal Reasoning

## What this paper does
ViMoD keeps a frozen Qwen3-VL-4B. After a full-resolution prefill it keeps the original (Fine) visual KV and builds a small set of learned, deformable Coarse KV entries (pooled keys, value-encoded pooled values, 9:1 or 4:1) linked to Fine groups by a coarse-to-fine map (DART). During decoding a state-space router (TRACE) at fixed intervals proposes Fine groups and HOLDs or UPDATEs (adds/removes/replaces) the active set; attention reads Coarse + active Fine + text (Joint-KV). Trained by distillation, supervised routing and RLOO.

## Goal-by-goal answers
### Goal: Does ViMoD swap high-resolution visual tokens in and out during decoding, and are new pixels encoded on demand?
It swaps which Fine KV entries are attended during decoding ("select, retain, or replace active Fine-token groups"), but all Fine KV is computed once at full-resolution prefill and "Unselected Fine entries remain stored for later access" [full text, Sections 3.1, 3.3, Eq 1, Eq 8]. No new pixels are encoded during reasoning; Fine tokens keep their original prefill positions, so there is no positional re-binding issue.

### Goal: Does it reduce memory, or only attention reads?
Only reads/compute. "Retaining Fine and Coarse KV banks keeps peak memory fixed at 42.67 GiB (Full: 38.40 GiB)" [Section 4.4]; Limitations: retaining both banks "increases storage requirements" [Section 5].

### Goal: What does it show about cost per complete response?
One-shot pruning (FastV, VisionZip, DivPrune) makes responses 15.9-29.9% longer than Full on MMMU-Pro, offsetting per-token savings and increasing total time; total decoder FLOPs can exceed the uncompressed baseline [Section 1, Fig 3; Section 4.4]. ViMoD keeps length close to Full and cuts total time 15.2-20.4% vs baselines at 40% budget; at 50% target it matches Full accuracy with 3.9% less total time [Section 4.4]. Measured at batch 8, one H200, max_new_tokens 8192.

### Goal: Which benchmarks and model?
Qwen3-VL-4B-Instruct frozen, eight reasoning benchmarks (incl. MathVerse, MMMU-Pro) at 20/30/40% budgets [Section 4.1]. Not V*/HR-Bench in the main table.


### Goal: Is the Coarse layer pooled from spatial cells, and does it carry a log-count bias? How is the Fine set chosen?
Groups start from a spatial grid partition and are then made deformable by learned capacities and content affinity, so groups can cross grid boundaries [full text, Section 3.2 / Eq 2-3, Fig 5]. Coarse KV per layer: K^C = W^T K^F, V^C = W^T E_phi(V^F), with W normalized within each group (a weighted mean); no log-count term is described [Eq 4-5]. All Coarse entries stay active; selected Fine entries are added alongside them in the same attention [Eq 1, Eq 8]. Fine selection is by a learned router (SSM state matched to Coarse descriptors, learned boundary, HOLD/UPDATE gate) at fixed token intervals, not by coarse attention mass [Section 3.3 / Eq 6-7; Appendix A.2.2 / Eq 19-20]. Related work notes that attention-based recovery (DSTP) is complicated by visual attention sinks and head-specific behavior [Section 2].

### Goal: How spatially concentrated is the per-stage visual evidence?
Gradient-attributed regions occupy 11.8% of the image per reasoning stage on average, while their union across stages covers 36.5% [Section 1, Fig 1]. At 70% of Full accuracy, stage-wise access needs ~23.9% visual budget vs 36.0% for a fixed union oracle [Section 1, Fig 2b].
