# Multipole Attention for Efficient Long Context Reasoning

## What this paper does
Training-free sparse attention for long-CoT reasoning models (Qwen3-8B, DeepSeek-R1-Distill-Qwen-14B). Keys are k-means clustered (blockwise, with fast online updates for generated tokens). Per query, centroid scores pick the top clusters, whose tokens get exact attention; every other cluster contributes N_i·exp(q·Kc_i)·Vc_i (count-weighted centroid key and mean value), merged into the same softmax. A hierarchical version refines coarse centroids into finer ones only where promising. Triton kernels give up to 4.5x attention speedup; better accuracy than Quest and Squeezed Attention at aggressive sparsity. KV stays on GPU.

## Goal-by-goal answers
### Goal: Does it implement the far-field (mean key + log count) / near-field (exact) approximation that C2 borrows from Barnes-Hut?
Yes. Importance: S_i = exp(q·Kc_i)/Σ_j N_j exp(q·Kc_j) [full text, Section 3.1 / Eq 1]. Non-important clusters contribute N_i exp(q·Kc_i) Vc_i (equivalent to logit q·Kc_i + log N_i with mean value), merged with exact attention for important clusters [Section 3.2 / Eq 2; Section 4 centroid replacement kernel]. Hierarchical multi-level refinement [Section 3.4].
### Goal: How does it deal with RoPE when pooling keys?
RoPE rotates keys by position so similar keys at different positions do not cluster; it uses Windowed RoPE (fixed relative offset) when computing centroids and rotates the query at a fixed position for lookup [Section 3.1].
### Goal: Does it help over pure sparse selection, and is it for long reasoning?
Yes: outperforms Quest and Squeezed Attention on LongBenchV2 (Qwen3-8B) and GSM-Infinite; gains are largest at aggressive sparsity because it "always ensures that we retain at least an approximate representation" of discarded tokens [Section 5.2]. Up to 4.5x attention speedup at batch 16 on A6000 [Section 5.3]. No offload; memory overhead of centroids noted as a limitation [Section 7].
