# Quest: Query-Aware Sparsity for Efficient Long-Context LLM Inference

## What this paper does
Quest keeps the full KV cache on GPU in pages (e.g., 16 tokens) and stores per page the channel-wise min and max of keys. For each decoding query it computes an upper bound of q·k over each page, selects the top-K pages, and runs exact attention only over them, reducing KV memory movement (e.g., 8x at 64K context with 16-token pages) without reducing KV storage.

## Goal-by-goal answers
### Goal: What page-level criticality estimate does Quest use, and why an upper bound rather than a mean?
"in order not to miss critical tokens, we should select pages containing the token with the highest attention weights"; it uses U_i = max(Q_i m_i, Q_i M_i) summed over channels, an upper bound on q·k for every key in the page regardless of the sign of Q_i [full text, Section 3.4, Algorithm 1].
### Goal: Does it offload or approximate unselected pages?
Neither: full cache stays on GPU; unselected pages are skipped (no coarse contribution); memory load is 1/PageSize + K/PageNum of the full cache [Section 3.5]. The first two layers are left dense because of low sparsity [Section 3.4].
