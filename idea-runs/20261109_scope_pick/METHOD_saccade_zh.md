# 扫视式视觉记忆（SaccadeKV）：让视觉 KV 成为可编辑的记忆

> **注意（2026-11-11）**：`SACCADE_FULL_zh.md` 修订版对以下几点做了改动，与本文不一致时以修订版为准：
> - 坐标系改为底图网格：底图 token 用整数坐标、间隔 1；高清 token 用格子内的小数坐标 `i − 0.5 + (k + 0.5) / m`；
> - 注视区域的放大倍数按每次注视的 token 预算在 2 / 4 / 8 倍中选，不再固定为原生分辨率；
> - 视频版按模型分两套位置方案；
> - 系统版需要让 vLLM 对视觉 token 在线计算位置编码，不能只用整数坐标。

> 方法设计稿，2026-11-09。面向：思考型多模态模型（Thinking VLM）在高清图、多图和长视频上的推理效率。

---

## 1. 一句话

现在的 VLM 把图像编码一次写进 KV，之后只能追加；每"再看一眼"，就在上下文末尾再追加几百到几千个 token。

**SaccadeKV** 把视觉 KV 分成两部分：
- **底图**：整张图的低清版本，常驻；
- **中央凹缓冲区**：固定容量。

模型想看哪里，就把那块区域编码成高清，**原地放进它在图上的位置**：底图里对应的低清 token 被遮蔽，缓冲区满了就把最早看的区域退回低清。

不管模型看多少次，视觉 KV 的总量都是常数：底图 + 缓冲区。模型对图像的记忆始终是"一张图"，只是注视点在移动、局部在变清晰。人眼也是这样工作的：中央凹看清，周边模糊，靠扫视移动注视点。

## 2. 动机

### 2.1 现在的"再看一眼"只追加、不编辑
| 方法 | 再看一眼怎么进上下文 | 视觉 KV 随看的次数 |
|---|---|---|
| DeepEyes 2505.14362、Pixel Reasoner 2505.15966、ViCrop 2502.17422、ZoomEye | 裁剪 → 重新编码 → 追加到末尾 | 线性增长 |
| FoveateR 2604.21079（ECCV'26） | 先看低清，推理中途放大，结果**追加**进 KV | 线性增长 |
| PRCR 2606.26631 | 复用开头存下的视觉 KV，重绑定位置后追加 | 线性增长，且没有新像素 |
| Foveated Compression 2610.07729 | 在 prefill 时一次性决定哪一块用原分辨率 | 不变，但推理中不能再看 |
| ViMoD 2610.12060 | 推理中在粗细两套视觉 KV 之间切换 | 细的那套始终在显存里，峰值反而更高 |

FoveateR 在局限性一节明确写道：缓存会增长，哪些该保留、更新或丢弃留作未来工作。**SaccadeKV 回答的正是这个问题。**

### 2.2 为什么值得做
- **视觉 KV 是高清图和视频推理的大头**：按 Qwen3-VL-8B 估算，V*、HR-Bench 上视觉 KV 占每步读取的 60–90%，视频上超过 90%。每个 token 的 KV 约 144 KiB（36 层 × 8 个 KV 头 × 128 维 × K/V × bf16）。
- **看得越多，追加越贵**：8K 图、多图对比、长视频、多步智能体任务里，模型要看很多次。追加式方法的显存随看的次数线性涨，显存打满时 batch 只能越开越小。
- **把"感知"变成一个有固定预算的操作**：推理多长可以由模型决定，但视觉记忆的大小是一个固定的、可设计的量。
- **查新结论**：46 组检索、6 篇全文精读，没有工作在**解码过程中**把某块区域的视觉 KV 原地换成新编码的高清 token。

## 3. 方法

### 3.1 视觉记忆的表示
以 Qwen3-VL 为例：ViT 的 patch 是 16 px，2×2 合并后，每个视觉 token 对应 32×32 px。

- **网格与层级**：把图像划成边长 64 px 的格子（tile）。每个 tile 有一个分辨率层级：
  - L0（低清）：1 个 token；
  - L1（原生）：4 个 token；
  - L2（2 倍放大）：16 个 token。
- **底图**：整张图按 L0 编码，常驻显存，约为原生 token 数的 1/4。V* 大小的图，原生约 3.5K token，底图约 870。
- **中央凹缓冲区**：容量固定为 F 个 token（例如 F = 512 或 1024），存放最近几次注视的高清 tile。
- **槽位表**：记录每个 tile 当前用哪个层级、KV 在哪些页。注意力读取时：
  - 被高清覆盖的 tile，遮蔽它的底图 token；
  - 读它在缓冲区里的高清 token。

### 3.2 位置编码：连续坐标
Qwen-VL 的 M-RoPE 给每个视觉 token 一组 (t, h, w) 坐标，RoPE 的旋转角是坐标乘以频率，**坐标取实数也成立**。约定如下：
- 以 L1（原生）网格为整数坐标；
- 一个 L0 token 覆盖 2×2 个原生 token，取它们的中心坐标（例如 h+0.5, w+0.5）；
- L2 token 取 1/2 步长的子网格坐标（h+0.25, h+0.75, …）。

于是不管哪个层级，同一块像素都落在同一片坐标区域里。之后的文本 token 读这些视觉 token 时，相对位置和读普通图像 token 完全一样，不会出现 PRCR 那种"位置过期"。

### 3.3 一次扫视怎么做
模型发出看某区域的动作，例如 DeepEyes 格式的 zoom 工具调用加 bbox。之后：

1. **编码**：把 bbox 对齐到 tile 边界，裁出区域 R，按 L1 或 L2 过 ViT。Qwen3-VL 的 DeepStack 特征也一并算出。
2. **补算 LLM 各层的 KV（核心步骤，见 3.4）**。
3. **写入**：新 token 的 KV 写进缓冲区，槽位表把 R 内的 tile 标为高清，遮蔽对应的底图 token。
4. **退回**：缓冲区放不下时，按最近最少使用（LRU）淘汰最早的注视区域：
   - 删掉它的高清 token；
   - 解除它底图 token 的遮蔽。

   底图从来不删，所以退回是精确的，不需要任何近似池化。
5. **继续推理**：模型照常往下写思维链。上下文里不追加任何视觉 token，只追加工具调用那几个文本 token。

### 3.4 新 token 的 KV 怎么算：重算"图像块 + 问题"，等价于混合分辨率 prefill
在普通 VLM 里，图像 token 只看得到它前面的内容：系统提示，以及光栅顺序上更早的图像 token。它们看不到后面的问题，只负责"把图编码好"，由后面的文本 query 去读。

一次扫视以后，图像块里的内容变了。图像块中 R 之后的 token，以及问题 token，原来是在旧视图下算的。所以有两种模式：

- **精确模式（默认）**：按光栅顺序，把整个"混合分辨率图像块 + 问题"在系统提示的 KV 之上重新 prefill 一遍，替换缓存里的这一段；思维链的 KV 保持不动。
  - 这一段只有约 1–2K 个 token：底图约 870 个、缓冲区 ≤ F 个、问题约 100 个。在 H200 上对 7B 模型只要几十毫秒，和追加式方法 prefill 一张裁剪图的量级相同。
  - 得到 SaccadeKV 的**不变量**：任何时刻，缓存里"系统提示 + 图像块 + 问题"这一段，和"从一开始就用当前这张混合分辨率图做 prefill"的结果完全相同。
- **快速模式**：只算新的高清 token。它们只看系统提示和底图里 R 以外的 token，算完直接写入，不重算其他 token。代价是 R 之后的图像 token 和问题 token 保留旧视图下的 KV。用于消融实验，看精确重算到底值多少。

两种模式下，**已经写出的思维链 KV 都保留在旧视图下**。这和追加式方法一样：追加之前写的 token 也没看过裁剪图。之后写的 token 读的是新视图。

不让新 token 去看问题和推理，是因为那样会出现负的相对位置，这是训练中没见过的分布。

实现细节见 `IMPL_saccade_zh.md`。

### 3.5 模型能不能直接读混合分辨率？
- **先试不训练**：Qwen2.5-VL 和 Qwen3-VL 本身就是原生动态分辨率，不同图像的 token 尺度本来就不一样；连续坐标在 RoPE 里也成立。
- **需要时加轻量适配器**：LoRA，只加在 LLM 上。训练数据合成即可：
  - 取高清图，随机选 1–4 个注视框，构造混合分辨率输入；
  - 用同一模型在全分辨率输入下的输出做自蒸馏，对答案分布做 KL；
  - 不需要人工标注，预计 1–2 个 GPU 日。

### 3.6 谁决定看哪里
**由模型自己决定**：沿用 thinking-with-images 模型已有的 zoom 动作（DeepEyes-7B；Qwen3-VL-8B 配合 zoom 工具提示），只把"追加"换成"原地写入"。

也提供一个不训练的变体给不支持工具的模型：用解码时对底图的注意力质量选注视框，类似 ViCrop。

SaccadeKV 本身只规定"看了之后视觉记忆怎么变"，和"怎么决定看哪里"正交。

### 3.7 推广到视频：时间上的扫视
- **底图**：整段视频按低帧率、低分辨率编码，常驻。
- **中央凹缓冲区**：模型要细看某一段时，把那段按高帧率、高分辨率编码，原地放进那段的 (t, h, w) 坐标区域，遮蔽对应的底图 token。
- 一小时的视频，视觉 KV 也只有"底图 + 缓冲区"。这是收益最大的场景。

## 4. 实现

| 阶段 | 实现方式 | 用途 |
|---|---|---|
| 原型 | HF transformers，手动编辑 `past_key_values`；遮蔽用 attention mask | E1–E3 |
| 系统 | vLLM 分页 KV：缓冲区占固定页，槽位表决定每个请求的块表；遮蔽通过块表跳过对应的底图页实现（底图按 tile 对齐分页） | E4–E5，显存打满时测吞吐 |

改动集中在三处：视觉 token 的坐标生成、扫视时的局部 prefill、块表管理。不需要写新的注意力 kernel。

## 5. 实验

**模型**：
- DeepEyes-7B（基于 Qwen2.5-VL-7B，原生带 zoom 动作）；
- Qwen3-VL-8B-Thinking（配合 zoom 工具）；
- 视频用 Qwen3-VL-8B。

**数据集**：
- 高清图：V*、HR-Bench 4K/8K、MME-RealWorld；
- 多图：MMIU 或 BLINK 的多图子集；
- 视频：Video-MME（长视频子集）、LVBench。

**主指标**：固定 8×H200、显存打满时每答对一题的成本；同时报准确率、视觉 KV 峰值、注视次数、输出长度、卡住或重复的比例。

### E0 现象测量（第 1 周）
- 每道题的视觉 token 数、思维链长度、注视次数、追加 token 占总 KV 的比例；
- 注视次数上限从 1 放开到 16 时，准确率怎么变（看"多看几次"有没有用）。

### E1 混合分辨率能不能读（不训练）
V* 上用标注框作为注视区域，在相同视觉 token 数下比较：
1. 原分辨率编码一次；
2. 整图缩小到相同 token 数；
3. 低清 + 追加裁剪图；
4. **低清 + 原地高清（在 prefill 时放好）**：检验连续坐标和混合尺度能不能直接用；
5. **SaccadeKV**：解码中原地写入，按 3.4 计算 KV。

### E2 LoRA 适配器
如果 E1 里 4 或 5 明显掉分，就按 3.5 训练适配器，再重复 E1。

### E3 主实验：模型自主扫视
- DeepEyes-7B 和 Qwen3-VL-8B 自己决定看哪里，比较"追加"和"SaccadeKV"；
- 扫描缓冲区容量 F，画出"准确率—视觉 KV 峰值"曲线。

### E4 多次注视的情形（最能体现优势）
- 把注视次数放开到 8–16 次，用 HR-Bench 8K、多图、长视频；
- 追加式方法的显存随次数线性涨，SaccadeKV 保持常数；
- 在 vLLM 上显存打满，测 batch 大小、吞吐和每题成本。

### E5 视频版
Video-MME 长视频、LVBench：比较"均匀高帧率"、"低帧率 + 追加片段"和 SaccadeKV 时间扫视。

### E6 消融
- 遮蔽底图 vs 不遮蔽（高低清并存）；
- 连续坐标 vs 把高清 token 放到末尾位置；
- 3.4 的精确模式 vs 快速模式；
- 缓冲区淘汰策略：LRU vs 按注意力质量。

### 对比方法
| 类别 | 方法 |
|---|---|
| 不做视觉压缩 | 原分辨率；整图缩小到相同 token 数 |
| 追加式再看 | DeepEyes、FoveateR 2604.21079、ViCrop、ZoomEye |
| 视觉 KV 复用 / 切换 | PRCR 2606.26631、ViMoD 2610.12060 |
| 一次性混合分辨率 | Foveated Compression 2610.07729 |
| 视觉 KV 压缩（可叠加） | VisionPulse 2605.31457、2-bit 视觉 KV（KIVI） |

最后一类和 SaccadeKV 是正交的，可以叠加，例如底图本身用 2 bit 存。

## 6. 预期贡献
1. **新的视觉记忆语义**：视觉 KV 从"只追加的日志"变成"可原地编辑的记忆"。再看一眼是编辑，不是追加；视觉记忆大小与注视次数无关。
2. **一个精确的不变量**：任何时刻，"系统提示 + 图像块 + 问题"的 KV 都等价于当前混合分辨率图像的 prefill 结果。由此得到：
   - 连续坐标的 M-RoPE 放置；
   - 只重算图像块和问题的局部 prefill；
   - 精确可逆的退回（底图不删，只遮蔽）。
3. **图像和视频统一**：空间扫视（高清图）和时间扫视（长视频）是同一个机制。
4. **系统实现与评测**：在 vLLM 上实现常数视觉预算，在显存打满的条件下报每答对一题的成本，并给出"多次注视"这一新的评测设置。

## 7. 后续延伸
- **视频 KV 的 I 帧 + P 帧编码**：底图本身按帧间差分存储，进一步压缩视频底图。
- **并行推理共享视觉记忆**：多条采样共享同一块底图和缓冲区，一条样本放大的区域，其他样本也能读到。
