# 一、要解决的问题

## 1. 背景："看图推理"的模型越来越贵

现在的多模态推理模型（Qwen3-VL-Thinking、DeepEyes 等）答题分两步：
1. **读图**：把图像切成很多小块，每块变成一个"视觉 token"。一张高清图大约 3,500 个，一段视频有几万个。
2. **思考**：写一段思维链。写到一半发现没看清，就"放大看一眼"：把某块区域裁下来，重新编码成新的视觉 token，**追加到上下文末尾**，然后接着想。

## 2. 问题出在"只能追加"

每个 token 都要在显存里存一份 KV（Qwen3-VL-8B 每个 token 约 144 KB），之后每生成一个字都要把它读一遍。
- **每看一次，上下文就长一截**：一次放大新增几百到几千个 token，旧的模糊视图还一直留着。
- **显存撑满，并发上不去**：视觉 KV 吃掉显存，同时能服务的请求变少，每道题的成本变高。
- **最需要看清楚的场景最贵**：8K 高清图、几十页的长文档、多图对比、长视频，恰恰都需要反复看。

现在的做法：
- DeepEyes、ViCrop、ZoomEye：追加裁剪图；
- FoveateR（ECCV 2026）：先看低清图，放大时也是追加。它在局限性里自己写了："缓存会增长，怎么保留、更新、丢弃留作未来工作。"
- VLM-in-Sandbox（2609.24362）：在上下文层面限制同时保留几张图，按整张图放进或移出，不涉及 KV。

## 3. 出发点

**视觉 KV 不该是一本只能往后写的日志，而应该是一块可以修改的记忆。**

人眼就是这么工作的：只有中央凹那一小块看得清，周边是模糊的。想看哪里，眼睛扫过去，那里就变清楚，原来看的地方又变模糊。大脑里始终是"一张图"，不会因为看了十次就存了十张图。

# 二、方法：SaccadeKV（扫视式视觉记忆）

## 1. 视觉记忆分两层

| | 内容 | 大小 | 是否变化 |
|---|---|---|---|
| **底图** | 整张图的低清版 | 约为原图 token 的 1/4（例如 3,500 → 870） | 一直保留，从不删除 |
| **中央凹缓冲区** | 最近注视过的几块高清区域 | 固定容量 F（例如 1,024 个 token） | 随注视点变化 |

- 每次注视有一个 token 预算 f（例如 256），所以缓冲区大约能放 F / f 次注视。
- 视觉记忆的总大小 ≤ 底图 + F，**是一个常数**，和模型看了多少次无关。

## 2. 一次"扫视"发生了什么

模型在推理中说"放大看这里"，并给出一个框：

1. **对齐**：把框对齐到底图格子的边界，记它盖住 n 个格子。
2. **定放大倍数**：在 2、4、8 倍（相对底图；2 倍就是原图分辨率）里，选满足 n × m² ≤ f 的最大倍数 m。
   - 小框放大得多：一个 30×30 像素的小目标可以放大到 8 倍；
   - 大框放大得少；
   - 框很大、连 2 倍都超出整个缓冲区时，以框的中心为准，裁到缓冲区放得下的范围。
3. **编码**：把这块区域从原图裁下来，按选定的倍数缩放后过 ViT，得到高清 token。
4. **原地放入**：高清 token 不追加到末尾，而是放到这块区域在图上原本的位置，同时把底图里这块的低清 token 遮掉。
5. **退回**：缓冲区满了，就把最久没用的那次注视退回去：删掉它的高清 token，放出它原来的低清 token。底图从没删过，所以退回是精确的。
6. **继续思考**：上下文里没有多出任何视觉 token，只多了一句"已放大区域 [x1,y1,x2,y2]"。

**两条补充规则**：
- **重复注视**：模型再次放大已在缓冲区里的同一块时，不重新编码，只刷新它的使用时间；
- **重叠**：新框和已有注视区域部分重叠时，旧注视整体移出，重叠的格子以新的为准。

从模型的角度看，它面前始终是**一张图**，只是看过的地方变清楚了。

## 3. 三个关键设计

### ① 位置怎么放：以底图网格为坐标系
Qwen-VL 给每个视觉 token 一个二维坐标（第几行、第几列），位置编码按坐标计算，坐标可以是小数。

- **底图 token 用整数坐标、间隔 1**，和一张普通的低清图完全一样。
- **高清 token 用底图格子内部的小数坐标**：放大 m 倍时，格子 i 里的第 k 个 token（k = 0…m−1）的坐标是 `i − 0.5 + (k + 0.5) / m`。
  - 例如 m = 2 时是 i − 0.25 和 i + 0.25；
  - 这几个坐标的平均值正好等于 i，也就是被它们替换的那个底图 token 的坐标。
- 图像后面文本的起始位置按底图的大小算，和模型平时的行为一致。

这样设计的理由：
- 模型训练时，相邻视觉 token 的坐标间隔永远是 1。**没放大时，我们的输入和普通低清图一模一样**，不会比"整图缩小"更差。
- 偏离训练分布的只有少数高清 token。
- 同一块像素，不管清晰度如何，都落在同一片坐标上，后面的文字读它们时相对位置不会错乱。PRCR 把旧视觉 KV 挪到新位置导致解码崩溃，就是栽在这里。

（"以原生网格为坐标系、底图 token 间隔 2"保留为消融对照。）

### ② 新 token 怎么算：重算"图像 + 问题"这一段
在 VLM 里，图像 token 只看得到它前面的内容，看不到后面的问题。扫视之后图像变了，所以把"混合分辨率图像 + 问题"这一段重新算一遍：
- 这一段只有 1–3K 个 token（底图约 870、缓冲区 ≤ F、问题一百左右），在 H200 上几十毫秒；
- 已经写好的思维链 KV 不动。因为坐标系固定，它们的位置一个都不用改。

由此得到一个**精确的不变量**：任何时刻，缓存里"系统提示 + 图像 + 问题"这一段，都和"从一开始就用这张混合分辨率图"的结果完全一样。

（另有一个**快速模式**：只算新 token、不重算其余部分。它只用来做消融实验。）

### ③ 谁决定看哪里：模型自己
沿用 DeepEyes、Qwen3-VL 已有的"放大"动作，我们只改"看了之后记忆怎么变"。SaccadeKV 和"怎么决定看哪里"互不干扰，可以接到任何会放大的模型上。

## 4. 推广到视频：时间上的扫视

- **底图**：整段视频用低帧率、低分辨率编码。
- **缓冲区**：模型想细看哪一段，就把那段用高帧率、高分辨率编码，替换掉底图里对应的帧。
- 一小时的视频，视觉 KV 也只是"底图 + 缓冲区"。

**位置怎么放，取决于模型**（写代码前对照源码确认）：

| 模型 | 视频位置的特点 | 方案 |
|---|---|---|
| Qwen2.5-VL 系 | 位置编码的时间分量按**绝对时间**取值，所有帧共用同一段行列坐标 | 高清帧直接用它们的真实时间作为时间坐标，自然落在底图帧之间；后面文本的位置不变。和图像版一样是"原地放入" |
| Qwen3-VL 系 | "时间戳文字 + 一帧"交替排列，位置按顺序往后排 | 中间插帧会让后面的位置全部错位。所以给视觉块**预留一段固定的位置范围**（按"底图 + 缓冲区"的最大长度算），问题和思维链从固定位置开始；每次扫视，把整个视觉块按时间顺序重排并重算一遍（约 2 万 token，H200 上 1 秒左右） |

**前提**：需要一个会主动"细看某一段"的开源视频模型，相当于图像上的 DeepEyes。第 1 周调研。优先找基于 Qwen2.5-VL 的，它用第一套方案，更自然。找不到的话，用"按注意力选片段"的变体。

## 5. 实现上的两个关键观察
1. **"原地"只是逻辑上的。**注意力对所有 key 做 softmax，和它们在缓存里的物理顺序无关，只看位置编码和是否可见。所以实现时：
   - 新的高清 token 直接拼到 KV 张量末尾，坐标设成区域的坐标；
   - "遮掉底图"就是把那几个 token 从缓存里删掉；
   - 精确模式下每次扫视都会重算整个图像块，所以连备份都不需要。

   解码时用标准因果注意力即可，不需要自定义 mask。
2. **坐标系固定在底图网格上。**扫视前后图像的坐标范围不变，问题和思维链的位置不用改，KV 原样保留。

**系统版的一处改动**：vLLM 的位置编码是按整数位置查表的。高清 token 用小数坐标，所以要让视觉 token 在线计算位置编码。这是一处小的 kernel 改动。

## 6. 一句话总结
> 把"再看一眼"从"追加一段新上下文"变成"编辑一块固定大小的视觉记忆"。视觉记忆的大小和看的次数无关，而且任何时刻都等价于一张合法的混合分辨率图像。

# 三、实验设计

## 0. 统一设置

### 模型
| 模型 | 用途 | 原因 |
|---|---|---|
| DeepEyes-7B（基于 Qwen2.5-VL-7B） | E0–E4、E6 的主力 | 原生带"放大"工具调用，结构简单 |
| Qwen3-VL-8B-Thinking | E0、E1、E3、E4 | 当前主流的思考型 VLM |
| Qwen2.5-VL-7B-Instruct / Qwen3-VL-8B-Instruct | E1 | 不带工具的基座，检验"读懂混合分辨率"是否依赖工具训练 |
| 会主动细看片段的视频模型（第 1 周确定） | E5 | 视频版的决策模型 |

### 数据集
| 类型 | 数据集 | 用在 |
|---|---|---|
| 高清图（找小目标） | V*（191 题）、HR-Bench 4K / 8K（各约 800 题） | E0–E4、E6 |
| 真实场景高清图 | MME-RealWorld-Lite（约 1.9K 题） | E0、E3、E4 |
| 长文档（几十页） | MMLongBench-Doc（约 1.1K 题） | E4 |
| 多图对比 | BLINK 多图子集、MMIU 子集 | E4 |
| 长视频 | Video-MME 长视频子集（约 900 题）、LVBench（约 1.5K 题） | E5 |

### "原分辨率"的定义
8K 图按真正的原生分辨率编码会超过 8 万个 token，不现实，所以统一规定：
- **原分辨率** = 模型默认的视觉 token 上限（例如 16,384 个视觉 token）；
- **底图** = 原分辨率 token 数的 1/4（长和宽各缩一半）。

### 指标
| 指标 | 定义 |
|---|---|
| 准确率 | 各数据集官方评测脚本 |
| 视觉 KV 峰值 | 推理过程中视觉 token 数的最大值，换算成 GB |
| KV 占用积分 | 对每一步解码，把当时缓存的 token 总数加起来（token·步）。显存打满时，吞吐大致和它成反比 |
| 额外 prefill 的 token 数 | 每题因放大而重新编码、重算的 token 总数。追加式算裁剪图的 token，SaccadeKV 算每次重算的"图像 + 问题" |
| **每答对一题的成本**（主指标） | 原型阶段：KV 占用积分 / 答对题数，同时报额外 prefill 的 token 数；系统阶段：实测 GPU·秒 / 答对题数（固定 1 张 H200，显存打满），已经包含全部开销 |
| 放大次数、输出长度 | 每题统计 |
| 卡住率 | 写满长度上限，或出现长段重复的比例 |

### 统计
- E1 用贪心解码（确定性）。
- E3–E5 按模型推荐的温度采样，每题 2–4 次，报均值和 95% 置信区间，组间差异用配对检验。
- **主要结论在合并题集上下**：HR-Bench 4K + 8K + MME-RealWorld-Lite，共约 3.5K 题。V* 只有 191 题，准确率的置信区间约 ±6 分，测不出 1–2 分的差距，所以单独报告，不作为判断依据。

## E0 摸底：现在的模型是怎么"看"的

**目的**：搞清楚在不同任务上，视觉 KV 占多大比例、模型放大几次、多看几次有没有用；同时为后面的实验准备素材。

**做法**：
1. DeepEyes-7B 和 Qwen3-VL-8B-Thinking（配合 zoom 工具提示）在 V*、HR-Bench 4K/8K、MME-RealWorld-Lite 上正常答题，用原本的追加方式。
2. 每题记录：
   - 初始视觉 token 数、思维链长度；
   - 放大次数、每次放大框占全图的比例、每次追加的 token 数；
   - 相邻两次放大框的重叠程度（重复看同一块的比例）；
   - 结束时视觉 KV 占总 KV 的比例。
3. **放大次数上限扫描**：把最大工具调用轮数设为 0 / 1 / 2 / 4 / 8 / 16，看准确率和 KV 峰值怎么变。
4. **保存完整轨迹**：每道题的输入、每一步输出、每次放大的框和裁剪图。E1 用它取放大框，E2 用它做老师。
5. **调研视频模型**：找会主动细看片段的开源视频模型，确认 E5 用哪个，以及它属于哪套位置方案。

**输出**：
- 一张"任务 × 视觉 KV 占比 × 放大次数"的统计表；
- 一条"放大次数上限 → 准确率 / KV 峰值"曲线；
- 一份轨迹库。

**规模**：约 3.7K 题 × 2 个模型 × 6 档上限。HF 原型 8 卡并行，粗估 1–2 天。

## E1 可行性：模型能不能读懂"混合分辨率"的图

**目的**：验证方法的地基。这一步不涉及推理中途的扫视，一次 prefill 就出答案。

**做法**：在 V* 和 HR-Bench 4K/8K 上，用标注的目标框（V*）或 E0 轨迹里模型自己给出的放大框（HR-Bench）作为注视区域，每个框的 token 预算 f = 256。比较：

| 组 | 输入 | 作用 |
|---|---|---|
| G0 | 只有底图 | 下限：不放大能做到多少 |
| G1 | 原分辨率整图 | 上限参照（token 数约为其他组的 3–4 倍） |
| G2 | 整图缩小到与 G4 相同的 token 数 | 最简单的省法 |
| G3 | 底图 + 把框内区域作为第二张图追加在后面，裁剪图的 token 数和 G4 的高清 token 数相同 | 追加做法的静态版 |
| **G4** | **底图 + 框内区域原地换成高清**，放大倍数按预算自动选，底图网格坐标 | 本方法的静态版 |
| G4-2 / G4-4 / G4-8 | G4，放大倍数固定为 2 / 4 / 8 倍 | 放大倍数的影响 |
| G4-原生坐标 | G4，改用原生网格坐标（底图 token 间隔 2） | 两种坐标系哪个好 |
| G5 | G4 的高清 token 改用"图像末尾之后"的位置坐标 | 位置放对有没有用 |

**设置**：4 个模型（两个基座、DeepEyes、Qwen3-VL-Thinking），短答案提示，贪心解码。

**看什么**（按重要程度）：
1. **G4 − G3**：token 数相同时，原地放入比追加裁剪图好多少。**这是整个项目最早、最重要的信号**，它决定核心论点能不能成立。
2. G4 − G0：高清区域带来多少提升。
3. G4 和 G2 的比较：比整图缩小好多少。
4. G4 和 G4-原生坐标、G5 的比较：坐标设计的作用。

**进入下一步的条件**：
- G4 ≥ G3 且 G4 ≥ G2 → 直接进 E3；
- G4 明显低于 G3（模型读不懂混合分辨率）→ 先做 E2 的第一部分；
- G4 和 G3 持平 → 进 E3，看解码中途多次注视时两者有没有差别（有界追加会丢掉旧裁剪图，原地放入不会多占位置）。

**规模**：约 1.8K 题 × 10 组 × 4 个模型，都是短答案，粗估半天。代码约 250 行，3 天左右写完。

## E2 适配：教模型用这种视觉记忆（按需）

分两部分，各自有触发条件。

### 第一部分：读懂混合分辨率（E1 中 G4 明显低于 G3 时做）
1. **数据**：从带高清图的训练集（TextVQA、DocVQA、ChartQA、InfographicVQA 的训练集，加上 SA-1B 子集）取图像和问题。注视框随机选 1–4 个；文字类数据优先选包含答案文字的区域。
2. **构造**：每个样本生成一份混合分辨率输入。
3. **老师**：同一个模型在原分辨率整图上的输出分布。
4. **学生**：同一个模型加 LoRA（rank 32，只加在 LLM 注意力层的 q/k/v/o 上，ViT 冻结），输入混合分辨率，对答案 token 做 KL 蒸馏。
5. **规模**：约 5 万条样本，1 个 epoch，8×H200 上 1–2 天。

### 第二部分：学会"回头读变清楚的地方"（E3 小规模试跑中 SaccadeKV 低于有界追加时做）
**为什么需要**：DeepEyes 训练时学的是"读紧跟在工具调用后面的裁剪图"。SaccadeKV 里，放大之后新内容出现在前面图像的位置上，模型要回头去读，这是它没学过的。

1. **老师**：E0 保存的 DeepEyes 追加式完整轨迹（只用答对的题）。
2. **学生**：同一条轨迹，每次放大改用 SaccadeKV（原地放入 + 一句文字提示），其余文字照搬老师。
3. **目标**：对每次放大之后的那一段输出（到下一次放大或答案为止），让学生的输出分布对齐老师。
4. **数据**：E0 的轨迹不够时，在 DeepEyes 的训练数据或 SA-1B 加合成问题上再跑一批，目标 2–3 万条轨迹。
5. **规模**：LoRA 同上，8×H200 上 2–3 天。

**验证**：重做 E1，以及 E3 的小规模试跑。之后所有实验用适配后的模型，并同时报告不训练的结果。

## E3 主实验：模型自己决定看哪里

**目的**：在真实使用中，证明 SaccadeKV 用常数大小的视觉记忆，达到和追加式相当或更好的准确率，并且成本更低。

**做法**：
- **模型**：DeepEyes-7B、Qwen3-VL-8B-Thinking。
- **数据**：V*、HR-Bench 4K/8K、MME-RealWorld-Lite。
- **配置**：

| 配置 | 说明 |
|---|---|
| 原分辨率 + 追加 | 模型原本的做法 |
| 原分辨率 + 2 bit 视觉 KV | 很强的简单基线：视觉 KV 缩小 8 倍。按**相同视觉 KV 字节数**和 SaccadeKV 比 |
| 底图 + 追加 | FoveateR 式：先看低清，放大时追加 |
| **底图 + 有界追加** | 追加裁剪图，但只保留最近几张，旧的从缓存里删掉，视觉 token 总数与 SaccadeKV 相同。**最关键的对照**：它同样是常数显存，SaccadeKV 必须在准确率上赢它 |
| SaccadeKV，F = 256 / 512 / 1024 / 2048 | 精确模式，每次注视预算 f = 256 |

- **流程**：模型正常推理。每次发出放大调用，追加配置追加裁剪图；SaccadeKV 执行一次扫视，然后在上下文里追加一句"已放大区域 [x1,y1,x2,y2]"。
- **先小规模试跑**：先在 HR-Bench 4K 的 200 题上跑"有界追加"和 SaccadeKV（F = 1024）。SaccadeKV 明显更低，就先做 E2 第二部分。
- **采样**：每题 2–4 次。

**输出**：
- **主表**：每个配置的准确率、视觉 KV 峰值、KV 占用积分、额外 prefill 的 token 数、每答对一题的成本、放大次数、输出长度、卡住率；
- **主图**：横轴视觉 KV 峰值（字节），纵轴准确率。SaccadeKV 的 4 个 F 连成一条曲线，其余配置是散点。

**规模**：约 3.7K 题 × 8 个配置 × 2 个模型 × 2 次采样，约 12 万次生成。HF 原型 8 卡并行，粗估 5–7 天。先在 HR-Bench 4K 上跑通，再扩到全部数据。

## E4 核心卖点：天然要看很多次的任务，显存打满

**目的**：展示 SaccadeKV 最大的优势。追加式的显存随放大次数线性上涨，SaccadeKV 始终是常数，所以在需要反复看的场景里，成本差距会越拉越大。

**做法**：
1. **系统实现**：在 vLLM 上实现 SaccadeKV，包括视觉 token 的在线位置编码、扫视时的局部重算、块表替换。
2. **任务**：天然需要多次注视的任务。
   - **长文档问答**（MMLongBench-Doc）：几十页文档，底图是所有页的低清版，一次注视看清其中一页或一页的局部；
   - **多图对比**（BLINK、MMIU 的多图子集）；
   - **8K 图的跨实例题**（HR-Bench 8K 中涉及多个物体的题）、MME-RealWorld 的多目标题。
3. **放大次数**：不人为限制，用模型自然的行为；另外报告上限设为 2 / 4 / 8 / 16 时的结果。
4. **显存打满**：单张 H200，一次性提交全部请求，让调度器自动开到最大并发。
5. **配置**：
   - 原分辨率 + 追加；
   - 原分辨率 + 2 bit 视觉 KV；
   - 底图 + 追加；
   - 底图 + 有界追加（token 总数与 SaccadeKV 相同）；
   - SaccadeKV（F 取 E3 中最好的一档）；
   - SaccadeKV + 底图用 2 bit 存（两者叠加）。
6. **补充的压力测试**：在提示里要求模型逐个核实候选目标，把放大次数推高，看两类方法的成本曲线各自怎么走。这部分只作为补充，不作为主要结论。

**测量**：
- 最大并发数；
- 吞吐（tokens/s，以及每小时答对的题数）；
- 每答对一题的 GPU·秒；
- 延迟的 p50 和 p90。

**输出**：
- 一张"任务 × 配置"的成本和并发数对比表；
- 一张"放大次数 → 每答对一题的成本"曲线图。

**规模**：vLLM 实现约 4 周；长文档数据适配 2–3 天；跑实验 2–3 天。

## E5 视频版：时间上的扫视

**目的**：证明同一个机制在时间维度上同样成立。长视频是视觉 KV 最大的场景，和高清图并列作为主实验。

**做法**：
- **模型**：第 1 周选定的、会主动细看片段的视频模型；优先用基于 Qwen2.5-VL 的。
- **数据**：Video-MME 长视频子集、LVBench。
- **底图**：整段视频均匀抽 256 帧，每帧压到约 64 个 token，共约 16K 个 token。
- **时间扫视**：模型给出要细看的时间段。这一段按 2 fps、每帧约 256 个 token 重新编码，替换掉底图里对应的帧。缓冲区容量 F 取 4K / 8K。
- **位置方案**：按二.4 的表，根据模型选第一套或第二套。
- **备选**：找不到会主动细看的模型时，用解码时对底图各帧的注意力质量自动选片段。

**配置**：

| 配置 | 说明 |
|---|---|
| 均匀高帧率 | 在模型 token 上限内尽量多抽帧 |
| 均匀高帧率 + 2 bit 视觉 KV | 简单基线，按相同字节数比 |
| 底图 + 追加片段 | 现有"先粗看再放大"智能体的做法 |
| 底图 + 有界追加片段 | 只保留最近几个片段，token 总数与 SaccadeKV 相同 |
| SaccadeKV 时间扫视 | 本方法 |

**输出**：准确率、视觉 KV 峰值、每答对一题的成本；按视频长度分桶，看成本随视频长度怎么变。

**规模**：约 2.4K 题 × 5 个配置 × 2 档 F，粗估 4–5 天；实现约 1.5 周。

## E6 消融：每个设计是否必要

**统一设置**：DeepEyes-7B，HR-Bench 4K/8K（V* 附带报告），F = E3 中最好的一档。

| 消融 | 对照组 | 回答的问题 |
|---|---|---|
| 遮掉底图 | 不遮，高低清并存 | 原地替换比"叠加"好在哪里 |
| 底图网格坐标 | 原生网格坐标；高清 token 放在图像末尾之后 | 坐标设计有没有用 |
| 精确模式 | 快速模式（只算新 token） | 重算"图像 + 问题"值不值得 |
| 按使用时间退回 | 按注意力质量退回 | 缓冲区策略的影响 |
| 放大倍数按预算自动选 | 固定 2 / 4 / 8 倍 | 自动选倍数的作用 |
| 每次注视预算 f = 256 | f = 64 / 128 / 512 | 单次注视要多少 token |
| 底图 1/4 | 底图 1/9、1/16 | 底图能压到多小 |
| 用 LoRA 适配 | 不训练 | 训练带来多少 |
| （视频，Qwen3-VL 系）预留位置范围 | 不预留、每次重算全部上下文 | 位置跳跃有没有影响 |

**规模**：每项一到三组配置，粗估共 2–3 天。

## 对比方法汇总

| 类别 | 方法 | 出现在 |
|---|---|---|
| 不压缩 | 原分辨率、整图缩小 | E1、E3、E4 |
| 视觉 KV 量化 | 原分辨率 + 2 bit 视觉 KV | E3、E4、E5 |
| 追加式再看 | DeepEyes、FoveateR、ViCrop、ZoomEye | E3、E4 |
| 有界追加 | 只保留最近几张裁剪图；VLM-in-Sandbox 2609.24362 | E3、E4、E5 |
| 复用或切换视觉 KV | PRCR、ViMoD | E3 |
| 开头一次性混合分辨率 | Foveated Compression | E1、E3 |
| 视觉稀疏读取（可与本方法叠加） | VisionPulse | E4 |
| 视频 | 均匀抽帧、粗看再放大的智能体 | E5 |
