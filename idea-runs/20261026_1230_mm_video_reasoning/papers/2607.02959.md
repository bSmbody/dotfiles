# Incentivizing Vision Language Models to Search for Long Video Question Answering

## What this paper does
VSeek is a single-VLM agent that answers long-video questions by issuing natural-language search actions over a pre-built index (8-second clips embedded with ViCLIP, plus a subtitle index), receiving at most 16 frames per turn, and appending them to its context until it answers. VETL turns each question and reference answer into a temporal-logic specification via an LLM generator–judge loop, extracts its visual primitives, and rewards the trajectory by the fraction of primitives that a ViCLIP detector finds in the retrieved observations, mixed 0.3/0.7 with exact-match accuracy. ECCV 2026.

## Goal-by-goal answers
### Goal: What mechanism does it use to locate or re-inspect temporal evidence in long videos?
Tools: <search> (ViCLIP text-to-clip top-k cosine retrieval), <search_subtitle>, and <summary> (16 uniform frames of the whole video); context c_j = [c_{j-1}, think, action, o_j] [full text, Sec 4.1–4.2, Eq 4–5].
### Goal: How does its RL reward assign credit to the evidence the model uses (outcome-only, IoU vs annotation, other)?
R = 0.7·R_em + 0.3·R_VETL, R_VETL = (1/|P_φ|) Σ_p max_t D_p(o_t), with D_p a ViCLIP presence detector [full text, Sec 4.3, Eq 6]. Although φ is a temporal-logic formula, "we use temporal operators only to disentangle semantics from their temporal relationships ... we ignore the order in which evidence is retrieved" [Sec 4.3]. So the evidence reward is an order-free coverage score over primitives: it checks that evidence was seen, not that temporal relations between evidence moments hold, nor that the answer depended on it. The paper motivates VETL by noting outcome-only supervision "would fail to certify whether an agent has constructed a query-specific context" [Sec 1].
### Goal: What limitation or failure mode does it report on long-video temporal reasoning?
Sequential search causes out-of-order frame processing relative to the timeline; more expressive temporal logics are needed "to capture more complex causal and temporal dependencies"; grounding is bounded by the retriever/indexer [full text, Sec 6].
