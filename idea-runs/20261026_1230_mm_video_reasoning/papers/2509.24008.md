# FrameMind: Frame-Interleaved Video Reasoning via Reinforcement Learning

## What this paper does
FrameMind trains a video MLLM to run a Frame-Interleaved CoT (FiCOT): it starts from uniformly sampled frames, and in up to 3 turns calls FrameAt(t) (one 448x448 frame) or VideoClip(t_start,t_end) (8–20 frames) to fetch new evidence. Dynamic Resolution Frame Sampling (DRFS) varies the initial frames/resolution trade-off within each GRPO group, and DRFS-GRPO compares rollouts across these initial views. Training needs only video–question–answer triples. Evaluated on Video-MME, MLVU, MVBench.

## Goal-by-goal answers
### Goal: What mechanism does it use to locate or re-inspect temporal evidence in long videos?
At turn k the policy receives the full textual history H_{k-1} and only the visual evidence E_{k-1} returned at the previous turn, then emits thought T_k and tool calls C_k; E_0 is uniform frames [full text, Sec 3.2, Eq 1]. Earlier visual evidence is thus carried forward only through text. Max 3 turns [Sec 3.2].
### Goal: How does its RL reward assign credit to the evidence the model uses (outcome-only, IoU vs annotation, other)?
R = R_acc (1 if final answer correct) + R_format (−1 if malformed) + R_tool + R_turn, where R_tool = s_tool × (0.2 + 0.8·R_acc) rewards using one tool type (1.0) or both (1.2), and R_turn = 0.5 for 2–3 turns [full text, Sec 3.5, Eq 5–9; App. B.1]. The advantage is trajectory-level and shared by all tokens [Sec 3.4, Eq 4]. The paper highlights that "FiCOT only requires video-question-answer triplets for outcome-based reward signals" [Sec 3.2]: no signal checks whether the fetched frames contained or were used as evidence.
### Goal: What limitation or failure mode does it report on long-video temporal reasoning?
The body does not report an explicit limitation for long-video temporal reasoning; it notes effectiveness "depends entirely on the quality of the visual evidence it receives" and the coverage/detail trade-off [Sec 3.3].
