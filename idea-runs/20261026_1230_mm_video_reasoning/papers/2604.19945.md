# Visual Reasoning through Tool-supervised Reinforcement Learning (ToolsRL)

## What this paper does
ToolsRL teaches Qwen2.5-VL-7B a set of native visual tools (zoom-in, rotate, flip, draw point/line) via a two-stage RL curriculum: stage 1 optimizes only tool-specific rewards computed against ground-truth tool annotations (e.g. a recall-weighted pixel F1 between the zoom box and the GT evidence box; rotation angle match), stage 2 optimizes only task accuracy while tools remain callable. Evaluated on rotated documents (DocVQA-RF, InfoVQA-RF), V*, HR-Bench and charts.

## Goal-by-goal answers

### Goal: How are individual visual operations credited, and what supervision does the step-level reward require?
Per-state tool rewards: for zoom, R_zoom(s_t) = max_g ModF1(b, g) with ModF1 = 2TP/(2TP + w_fp·FP + w_fn·FN), w_fp=0.1, w_fn=1.0, against ground-truth boxes G (Eqs 2–3) [full text, Section 3.2.2]; rotate/flip use the known rotation. These need annotated evidence boxes or known transforms per sample. The step reward judges geometry of the call, not whether the returned image changed the answer. In stage 2 only accuracy rewards are optimized [Section 3.3.2].

### Goal: What does it report about combining operation-level and answer-level rewards?
Joint optimization "is ineffective, as models frequently defaulted to text-only reasoning", failing "to establish a critical link between tool manipulation and successful task completion", hence the decoupled curriculum [Section 1, Section 3.3.3, Table 2]. Prior RL rewards "rely solely on the final task outcome or provide only generic encouragement for any tool invocation", leading to "infrequent tool invocation (typically fewer than one per episode)" [Section 1].
