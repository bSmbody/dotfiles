# LongVT: Incentivizing "Thinking with Long Videos" via Native Tool Calling

## What this paper does
LongVT trains a Qwen2.5-VL-7B agent to skim a long video (64 uniform frames), then call a native crop_video(start,end) tool that resamples dense frames inside a proposed window, interleaving these clips into the chain of thought (iMCoTT) and self-correcting when a window is wrong. Training is cold-start SFT on 247.9K tool-augmented traces, agentic GRPO with a joint answer + format + temporal-IoU reward, then RFT on filtered self rollouts. It also releases VideoSIAH, a "segment-in-a-haystack" dataset/benchmark whose evidence lies in a narrow window.

## Goal-by-goal answers
### Goal: What mechanism does it use to locate or re-inspect temporal evidence in long videos?
Global skim over uniformly sampled frames to form a hypothesis of when evidence occurs, then crop_video(start_time,end_time) resamples finer-grained frames in that window; the model can call again with a revised window ("hypothesis-verification" cycle) [full text, Sec 1; Sec 4; App. 4]. No external retriever: the window comes from the LMM's own latent grounding. Base model without SFT collapses to near-zero tool calls under RL [full text, Sec 4.1; Sec 5.3].
### Goal: How does its RL reward assign credit to the evidence the model uses (outcome-only, IoU vs annotation, other)?
R = R_acc (LLM-judge, 1/0.5/0) + R_format + R_time, where R_time is temporal IoU between the predicted span and ONE ground-truth span [t's,t'e] [full text, Sec 4.2]. A Recall reward was hacked by span inflation; IoU chosen instead [Sec 5.3]. A binary tool-call reward "brings little benefit" and "may suppress exploration", so it was dropped [Sec 5.3]. Credit therefore goes either to answer correctness or to overlap with an annotated interval; nothing measures whether the answer actually used the cropped frames. The RL-only failure case shows the model calling the tool and then ignoring the returned frames, reverting to generic captioning [App. 9].
### Goal: What limitation or failure mode does it report on long-video temporal reasoning?
Context accumulation: each crop_video call appends dense visual tokens; for ultra-long videos repeated calls exhaust the context window, risking OOM in training and truncation [full text, App. 10]. RL-only training is unstable and the model becomes "confused by the returned crop rather than using it as supporting evidence" [Sec 5.3].
