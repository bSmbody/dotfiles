# 任务：为"高效推理"产出 50 个**机制级创新**的研究 idea（构思时同步查新）

你是一名做 LLM 推理效率的研究员，我是导师。请在下面给定的方向内，直接产出 **50 个机制级创新的 idea**，每个都在构思时做轻量查新。

这一轮的目标是**广度和新意**，不需要论证"一定能做出效果"，也不做对抗式自审。只要机制清楚、原理说得通、查新没有撞车，就可以列出来。筛选和验证由我来做。

## 2. 什么叫"机制创新"（每个 idea 都要对照）

**合格的 idea 满足三条：**
1. **改变推理时算什么、存什么或交换什么**。例如：缓存里一个 token 用什么来表示；注意力怎么读记忆；推理历史用什么结构来承载；几条推理线之间传递什么；视觉信息以什么形式进入推理。
2. **效果来自一个"按设计就成立"的原理或不变量**，而不是靠运行时去监视、发现问题再补救。
3. **能用一句话讲清楚。**

**参考范例（只参考思路，不要照抄）**：SwarmEvolve（arXiv 2611.08483）换掉了计算的"介质"：agent 不写文字，而是在潜空间里思考；agent 之间不传文字消息，而是传 KV cache；把多个 agent 的 KV 拼起来，就实现了想法的融合。整个方法没有任何"监视器 + 开关"。

**明确不要以下几类**：
- **"检测 → 修复"控制回路**：检测到某种情况，然后回退、重算、升精度、重选、淘汰或切换模型；
- **分配规则、调度器、阈值策略**：例如按某种重要性给 token 分配比特、预算或层数；
- **把已知原语换个场景重新包装**：和最近的已有工作相比，区别只是"同一件事用在另一个设置上"；
- **纯分析、纯 benchmark、纯工程实现**：只改内核实现，不改计算语义。

**鼓励**：从领域外借机制，例如数值线性代数、信号处理、编码理论、数据库与存储、编译器、计算物理、控制论、生物学、经济学、密码学等。**50 个里至少一半的机制来源应在 ML 之外。**

### 3.2 背景事实（供构思参考，不用逐条论证）

**文本：**
- KV 可以从 token 精确重算（2603.19664）。在 H200 上重算 16K 个 token 不到 1 秒，而续写同样长度要几分钟。
- 2 bit KV 会让一部分请求失控：Qwen3-8B 在 AIME25 上写满上限的比例从 11% 涨到 42%（2609.38121）。
- 混合模型的 GDN 状态主要控制语言和风格，内容主要存在注意力 KV 里（2609.04434）；状态只占请求显存的 7–17%（2610.36950）。
- 63–85% 的注意力头会在生成过程中改变关注位置（2610.02713）。
- 训练过的滑动窗口注意力只比全注意力低 0.4–1 分（2606.11634）。

**多模态：**
- 7B 多模态推理模型的失败中，72–78% 是"看错"，而不是"想错"（2506.07218）。
- RL 训练过的推理模型对视觉 token 的注意力更低，而且思维链越长越低（2505.21523）。
- 把裁剪后的图换成噪声，DeepEyes、Pixel Reasoner 的答案几乎不变（2510.23482）。
- 现有自适应推理方法只调节文字长度；视觉输入要么在开头就固定，要么由外部决定（EcoFrame 2608.03918、ResAdapt 2603.28610、L2T 2610.15810）。

## 4. 输出格式

先给一张总表，然后逐条展开 50 个 idea。

**总表**：编号 | 方向 | 标题 | 一句话 | 机制来源领域

**每个 idea 展开写（每条控制在 150–250 字）：**
- **编号与标题**：例如 D3-04 xxx
- **一句话**：它改变了什么计算
- **机制**：具体怎么算、存什么、交换什么，可以写简单的公式
- **为什么按设计就成立**：背后的原理或不变量，一两句话
- **机制来源**：借自哪个领域、哪篇论文（附编号）
- **查新**：最接近的 1–3 篇工作（附 arXiv 编号）+ 各一句话的区别
- **最小验证实验**：一句话，用哪个模型、哪个数据集、和谁比

如果篇幅太长，可以分几次输出，每次 10 个，我会回复"继续"。
