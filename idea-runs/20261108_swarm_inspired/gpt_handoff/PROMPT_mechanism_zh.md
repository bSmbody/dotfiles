# 任务：为"高效推理"产出**机制级创新**的研究 idea

你是一名做 LLM 推理效率的研究员，我是导师。请按下面的流程，在给定方向内产出机制级创新的研究 idea。流程中有 3 个检查点，每到一个检查点就停下来，等我审完再继续。

---

## 0. 背景与约束

- **研究者**：一名博士新生，可以用 AI 辅助写代码，单个项目周期约 3 个月。
- **算力**：8×H200（约 1 TB 显存）。优先选择**不训练或只需轻量训练**的方案；需要重训练的，必须说明训练规模。
- **模型**：开源模型。文本选 Qwen3 4B–32B、DeepSeek-R1-Distill；混合模型选 Qwen3.5、Qwen3-Next、Falcon-H1；多模态选 Qwen2.5-VL、Qwen3-VL 及其 Thinking 版本。
- **评测**：
  - 文本：AIME、HMMT、LiveCodeBench、GPQA；
  - 多模态：MathVista、MathVerse、MMMU、V*、Video-MME、LVBench 等。
  - 主指标是**固定硬件上每答对一题的成本**（GPU 秒或字节）。不要只报 tokens/s。
- **目标会议**：NeurIPS、ICLR、MLSys 档次的**方法论文**。分析、benchmark、综述都不算。

## 2. 什么叫"机制创新"（最重要，请逐条对照）

**合格的 idea 必须同时满足：**
1. **改变推理时算什么、存什么或交换什么**：比如缓存里一个 token 用什么来表示、注意力怎么读记忆、推理历史用什么结构承载、几条推理线之间传递什么、视觉信息以什么形式进入推理。
2. **效果来自一个"按构造成立"的原理或不变量**，而不是来自运行时的监视和补救。你要能说出"它为什么在设计上就成立"。
3. **能用一句话讲清楚**，而且有一个可以量化的、能证伪的核心预测。

**参考范例（只看思路，不要照抄）**：SwarmEvolve（arXiv 2611.08483）的创新在于换了计算的介质：agent 在潜空间思考而不写文字，通过 KV cache 而不是文字消息通信，把多个 agent 的 KV 拼接起来就实现了"想法融合"。它没有加任何"监视器 + 开关"。

**明确不要以下类型**（出现即淘汰）：
- **"检测 → 修复"控制回路**：检测到 X，然后回退、重算、升精度、重选、淘汰、切换模型。这类方法只是在模型外面加一个监工，上限被检测器卡死。
- **分配规则、调度器、阈值策略**：例如"按某种重要性给不同 token 分配比特、预算或层"。
- **把已知原语换个场景重新包装**：如果和最近工作的唯一区别是"同一件事用在另一个设置上"，就不算。
- **纯分析、纯 benchmark、纯系统工程**（例如只改内核实现、不改计算语义）。

## 3. 我们之前踩过的坑（必须吸收）

我们已经用同样的方向构思过两轮共 10 个机制 idea，结果全部被已有工作覆盖，或者被反面实验证据否定。教训有三条：

1. **这个领域在 2026 年极其拥挤。**"从别的领域借一个机制过来"的大部分方案都已经有人做过。**所以查新必须在构思阶段就做**，不能等到最后。
2. **比撞车更致命的，是价值前提和已有实验相反。**每个 idea 都要先找"有没有实验结果否定我的前提"。
3. **每个关键假设都要有已发表论文中测到的数量级**，不能凭直觉。

### 3.2 必须尊重的硬事实（价值前提要和它们对得上）

**文本推理：**
- **KV 可以从 token 精确重算**（KV-Direct 2603.19664）。重算 16K token 在 H200 上不到 1 秒，而续写 16K token 要几分钟。
- **2 bit KV 的失控现象**：Qwen3-8B 在 AIME25 上写满长度上限的比例，从 BF16 的 11% 涨到 OSCAR INT2 的 42%（2609.38121）；强的 2 bit 方法在 Qwen3-4B-Thinking 上几乎无损（2608.02691）。
- **FP4 级 KV 的收益主要来自容量**：MpFA 相对 FP8 只快 1.06 倍（2609.33135）。
- **永久删除的比例决定准确率**（2605.09490）；63–85% 的注意力头在生成过程中会改变关注位置（2610.02713）。
- **滑动窗口注意力经过 SFT+RL 后，只比全注意力低 0.4–1 分**（2606.11634）。新机制要能赢过这个"训练过的简单基线"。
- **GDN 状态只占请求显存的 7–17%**（2610.36950）；把状态清零，NIAH 只降不到 1 点（2608.30386）；状态管风格，KV 管内容（2609.04434）。
- **不训练时的"过期信息"代价极大**（2501.06589）；复用早先的注意力计算，必须有相似度门控和回退机制（2604.00235）。

**多模态推理**（来自我们之前的调研）：
- 7B 多模态推理模型的失败中，72–78% 是"看错"而不是"想错"（2506.07218）；
- RL 训练过的推理模型对视觉 token 的注意力更低，而且思维链越长越低（2505.21523）；
- 把裁剪得到的图换成噪声，DeepEyes 和 Pixel Reasoner 的答案几乎不变（2510.23482）；
- 编辑图像后，标准答案在 81–86% 的样本上变了，而模型预测只在 5.7–13.1% 的样本上变（2609.34563）；
- 自适应推理方法只调节文字长度；视觉输入要么一开始就固定，要么由外部决定（EcoFrame 2608.03918、ResAdapt 2603.28610、L2T 2610.15810）；
- 视觉 token 剪枝和合并已经很拥挤：FastV、SparseVLM、VisionZip、PyramidDrop、LongVU 等，请自行查新。

## 4. 工作流程

### 阶段 A：缺口（每个方向 1–2 个）
每个缺口要写清：已经做了什么（至少 2 篇近邻论文）；现有方法**具体在哪里失败**，附一个有数字的失败例子；为什么这个失败值得解决。

### 阶段 B：原始 idea（至少 30 个，覆盖全部 6 个方向）
- 每个 idea 用一句话说明它**改变了什么计算**，以及它借用的机制来源（至少一半来自领域外，比如数值线性代数、信号处理、编码理论、数据库和存储、编译器、计算物理、控制论、生物学、经济学等）。
- 先用第 2 节的标准自检，淘汰"检测 → 修复"类和分配规则类。

**→ 检查点 1**：交出阶段 A 的缺口，以及 30 个原始 idea 的一行列表（每行：编号、方向、改变了什么计算、机制来源、是否已通过第 2 节自检）。然后停下来等我。

### 阶段 C：构思中查新 + 反面证据（对我选中的约 10 个）
对每个 idea：
1. **查新**：至少 8 组检索，必须覆盖 2026 年的 arXiv，关键词用"借来的机制 + 目标问题"的组合，而不只是大方向。列出最接近的 3 篇（附 arXiv 编号），逐条写**精确的区别**。如果区别只是"换了个场景"，直接淘汰。
2. **反面证据**：专门检索有没有实验结果会否定这个 idea 的价值前提（参照 3.2 节的写法）。把前提量化成已发表论文中的数字。
3. **成本账**：在 H200（4.8 TB/s、约 1 PFLOP/s BF16）上，算出相对最强基线省了多少字节或 FLOPs，以及多出多少开销。

**→ 检查点 2**：交出每个 idea 的查新表、反面证据和成本账，以及是否保留的结论。然后停下来等我。

### 阶段 D：对抗式自审 + 最终方案（最多保留 5 个）
用三个审稿人视角各审一遍，每人给出结论（survive / revise / reject）和最强反对意见：
- **R1 新意**：最接近的工作是否已经实现了同样的计算？
- **R2 机制正确性**：数学上是否成立？"按构造成立"的不变量是否真的成立？有没有反例？
- **R3 系统收益**：在内存打满的批量解码下，真实收益是多少？会不会被 FP8、MAC-Attention、自投机解码、训练过的滑动窗口这些强基线压制？

每个最终方案需要写清：
- 一句话 idea；
- 改变了哪一步计算（可以写公式）；
- 按构造成立的原理；
- 与最近 3 篇工作的区别；
- 价值前提及其量化证据；
- 最大的三个风险；
- **最便宜的证伪实验**：最好不超过 1 个 GPU 天、不训练，写清楚对照组、指标和判死标准；
- 预期结果（给出数字区间，不要承诺）。

**→ 检查点 3**：交出最终方案后停下。
