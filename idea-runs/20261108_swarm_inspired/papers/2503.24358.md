# SQuat: Subspace-orthogonal KV Cache Quantization

## What this paper does
Training-free key-cache quantization: builds a subspace from the prompt's query tensors, then quantizes each key element by element (or in ≤4 blocks) and, after each step, updates the not-yet-quantized coordinates in closed form so that the residual stays as orthogonal as possible to the query subspace (an OBS/GPTQ-style error-compensation update). Runs on the fly on a residual buffer of recent tokens. Compared with KIVI, GEAR and ZipCache at 2 bits.

## Goal-by-goal answers
### Goal: Has GPTQ-style error compensation been applied to the KV cache at write time during decoding?
Yes, for keys. "At each step, an element (or block of elements) of the key tensors is quantized, followed by an update to the remaining elements. This update minimizes the quantization error's impact on inner products with vectors in the query subspace" [full text, Section 1, Section 3.3, Proposition 1]. It runs once a residual buffer of recent full-precision tokens fills (32 in experiments, 128 also tested) [Appendix, Figure 5; Section 4 "Efficiency comparisons"]. The compensation is within each key vector across channels, not across tokens; values use standard quantization.
### Goal: What reasoning / long-generation evidence and overhead does it report?
LM-Eval reasoning (GSM8k, GPQA, BBH, ...) and LongBench on Llama-2-7B, Llama-3.1-8B, Mistral-7B; DeepSeek-R1-Distill-Llama-8B on MATH-500 with 8K new tokens, where it beats KIVI/GEAR/ZipCache [Section 4, Figure 3]. Throughput 2.45-3.60x over FP16 vs KIVI 2.63-3.82x, same peak memory as KIVI [Section 4, Figure 4].
