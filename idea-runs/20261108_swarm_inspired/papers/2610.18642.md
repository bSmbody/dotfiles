# MultiAlloc: Budget-Aware Precision Allocation for KV Cache Quantization

## What this paper does
MultiAlloc treats KV-cache quantization under a fixed memory budget as an allocation problem between two granularities: a per-layer bit-width q_l and a per-layer count k_l of tokens kept at high precision per group. Offline profiling on calibration data estimates layer sensitivity and token importance; a budget-coupled solver picks a static policy (q, k) that is then applied at inference. Evaluated on Llama-3-8B, Mistral-7B, DeepSeek-R1-Distill-Qwen-7B/14B and QwQ-32B on GSM8K, GPQA and LongBench-v2 with greedy decoding, against OTT, PM-KVQ and KVmix at matched KV budgets.

## Goal-by-goal answers
### Goal: Does it allocate a fixed KV byte budget across layers and granularities on reasoning models, and does it ever drop whole layers' KV?
It allocates a fixed budget B over (q_l, k_l) per layer by min L(q,k) s.t. M(q,k) <= B [full text, Section 4.1, Eq 5], i.e. a matched-bytes allocation across layer-wise precision and token-wise preservation, and compares methods "under the same KV cache memory budget" with a unified memory-accounting protocol [Section 5.1]. All layers keep a quantized KV; there is no option to remove a layer's cache or replace it with a recurrent mixer, and no hybrid model. Reasoning evaluation is GSM8K/GPQA with greedy decoding, not long-CoT competition math [Section 5.1, Appendix A].

### Goal: What does it find about where accuracy is bought at a fixed budget?
Adaptive allocation between layer precision and token preservation beats fixed splits and single-granularity methods (PM-KVQ layer-wise, OTT token-wise) at matched budgets on all five models [Section 5.2, Table 1; Appendix E.3]. Limitations: profiling overhead and need for representative calibration data [Section 7].
