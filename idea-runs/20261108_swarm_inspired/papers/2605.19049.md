# KVBuffer: IO-aware Serving for Linear Attention

## What this paper does
Serving mechanism for the linear-attention layers of hybrid models (Qwen3.5 GDN, Nemotron-3 Mamba-2) in SGLang. It buffers the K and V of recent tokens, computes outputs in chunkwise form (state query plus exact attention over the buffer), and flushes the buffer into the state in one batched update. It also verifies speculative draft tokens in parallel without temporary states, and uses KV-only decoding for short contexts.

## Goal-by-goal answers
### Goal: Is the deferred update exact, and does the far summary still get read every step?
It is exact. Every step loads the state together with the buffered KV to compute the output (chunkwise form, Eq 4). Only the state *write* is deferred until the buffer is full (Eq 5) [full text, Section 3.2, Fig 1]. So the far summary is still read every step for the fresh query, and nothing is answered late. The deferral works because the linear-attention state can be queried exactly and cheaply. The optimal buffer is m* = 2 sqrt(d), about 22 for d = 128 [Section 3.2, Eq 6].
### Goal: What gains are measured?
Kernel latency is 0.17-0.55x of recurrent decoding with the best buffers (16/4/22/8). End-to-end batch decoding throughput rises 1.18-1.47x (256-token input, 1,024-token output, batch 128/512) [Section 4.2.1]. Throughput with speculative verification of 4 drafts is up to 1.9x [Section 1].
