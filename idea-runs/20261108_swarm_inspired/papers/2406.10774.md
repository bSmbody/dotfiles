# Quest: Query-Aware Sparsity for Efficient Long-Context LLM Inference

## What this paper does
Shows that which tokens are critical depends strongly on the current query, so history-based eviction (H2O) has low recall of top-attended tokens. Quest keeps the whole KV cache, stores per-page channel-wise min and max of keys as metadata, and at each decoding step computes an upper bound on each page's attention for the current query, then attends only over the top-K pages. Achieves up to 7.03x self-attention speedup at 32K and 2.23x end-to-end, with near-full accuracy on PG19, passkey and LongBench.

## Goal-by-goal answers

### Goal: What signal does it use to decide which KV entries to keep, evict, or recall, and is the decision reversible?
Query-dependent page score: sum over channels of max(q_i*m_i, q_i*M_i) using the page's min/max key vectors, an upper bound on any token's q.k in the page; top-K pages are attended [full text, Section 3.4, Algorithm 1]. Nothing is evicted — "retains all of the KV cache" — so selection is fully reversible every step [Section 2.2].

### Goal: What does it report as its failure mode or limitation for tokens that are needed later (long chain-of-thought or long context)?
Example "A is B. C is D. A is": token B has very low attention for all earlier queries and becomes critical only for the final query, so history-based eviction prunes it [Section 3.3, Fig 2]; H2O's top-10 recall falls along generation while Quest stays near full [Fig 4]. Quest reduces memory movement to 1/PageSize + K/PageNum of the cache but does not reduce memory footprint [Section 3.5].

### Goal: What method assumption does its scoring or training rely on (per-token additive utility, per-head independence, teacher-forced or offline training)?
Assumes the full KV cache stays resident (memory is not reduced) and that page-level bounds are tight enough; first two layers are not sparsified [Section 3.4].
