# MixKVQ: Query-Aware Mixed-Precision KV Cache Quantization for Long-Context Reasoning

## What this paper does
MixKVQ is a plug-and-play key-cache mixed-precision scheme for long-CoT reasoning: key channels get BF16 / INT4 / INT2 according to a salience A_d = I_d * S_d (accumulated query magnitude per channel times key quantization scale), recomputed every R tokens with a full-precision residual buffer of R tokens; values are uniform per-token 2-bit. Evaluated on reasoning models (Qwen-family up to 32B) on AIME 2024-2025, MATH500, GPQA-Diamond, LiveCodeBench and on LongBench vs KIVI, KVQuant, SKVQ, RotateKV.

## Goal-by-goal answers
### Goal: How is precision decided and is it online during decode?
Per key channel, online: a running accumulator of query magnitudes over decode steps (post-RoPE) gives I_d; quantization and channel selection happen lazily when the residual buffer fills [full text, App D.1-D.2; Sec 4.2]. Query magnitude correlates weakly with key scale (Pearson 0.16), so scale-only channel boosting misallocates [Sec 4.1]. No per-head budget and no attention-distribution statistic; V is fixed 2-bit because value error "is more uniform and lacks distinct outliers" and "preserving higher precision for the key cache is more critical" [Sec 4.1].

### Goal: What accuracy is reported on reasoning?
On Qwen-32B the reasoning-suite average is 66.04 vs BF16 67.84, RotateKV-4bit 64.51 and KIVI-2 58.89 [Sec 5.2 Table 3]. Generation length is not analysed in the main text. Overhead of tensor transformations is "non-negligible"; no vLLM integration; MLA excluded [Limitations].

# MixKVQ: Query-Aware Mixed-Precision KV Cache Quantization for Long-Context Reasoning

## What this paper does
KIVI-style (channel-wise K, token-wise V, group 32, residual 128 BF16 tokens) mixed-precision KV quantization for long CoT. It argues key errors matter more than value errors, and that key-scale-only saliency picks the wrong channels; it scores each key channel by A = I·S (mean query activation intensity × key scale) and gives high bit-widths to high-A channels online (lazy, amortized updates), reaching ~2.7 effective bits. Evaluated on R1-Distill-Qwen-14B/32B, R1-Distill-Llama-8B over AIME24-25, MATH-500, GPQA-D, LCB, vs KVQuant, KIVI, KVTuner, RotateKV.

## Goal-by-goal answers
### Goal: What accuracy at what bits, with what protocol?
T=0.6, top-p 0.95, max 32,768 generated tokens; G=32 and R=128 for all methods [full text, Section 5.1; Appendix F]. On R1-Qwen-32B: MixKVQ average 66.04% vs BF16 67.84%, 4-bit RotateKV 64.51%, 2-bit KIVI 58.89% [full text, Section 5.2, Table 3]. Effective bit-width ~2.70 [full text, Section 5.3]. KVTuner's static layer-wise allocation fails by over-quantizing sensitive layers [full text, Appendix B]. No generation-length or loop statistics are reported.

### Goal: How is efficiency measured?
vLLM-style ShareGPT workloads on Llama2-13B-chat (not a reasoning model), batch pushed to memory saturation: up to 2.25× larger batch and 2.63–2.81× throughput vs FP16; vLLM integration is future work [full text, Section 5.4]. No FP8-KV baseline and no long-CoT serving run.

# MixKVQ: Query-Aware Mixed-Precision KV Cache Quantization for Long-Context Reasoning

## What this paper does
MixKVQ is a plug-and-play mixed-precision key-cache quantizer for long-CoT reasoning. It scores each key channel by A = I·S, where I is the average query activation intensity of the channel (its contribution to attention scores) and S is the key quantization scale/difficulty. High-A channels get higher precision; the rest use ~2-bit per-channel quantization. Values are quantized per token. A full-precision residual window of R=128 tokens and group size G=32 are used, as in KIVI.

## Goal-by-goal answers
### Goal: Headline numbers on reasoning?
On R1-Distill-Qwen-32B, the average over AIME24-25, MATH-500, GPQA-Diamond and LiveCodeBench is 66.04 for MixKVQ vs BF16 67.84; RotateKV-4bit 64.51; KIVI-2bit 58.89 (Section 5.2, Table 3). Also evaluated: R1-Distill-Qwen-14B and R1-Distill-LLaMA-8B, plus LongBench (Table 4).
### Goal: How does it relate to PN-Mix/Kitty and to per-head/online allocation?
It uses the same family of query-aware channel saliency as PN-Mix (2610.19605), which later refines it to RoPE pairs and q·k pair-norm products and calls it the "ChanMix"-style baseline. Allocation is over channels, not heads or tokens, and is fixed from statistics (Section 4.2).
### Goal: Limitations?
Non-negligible transform overhead and no vLLM integration. MLA is excluded. The latency analysis covers only memory-bound decode (Limitations). No generated-length analysis was found. Evaluated with T=0.6, top-p=0.95 on a single A800.
