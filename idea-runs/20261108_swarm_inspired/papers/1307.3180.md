# Path storage in the particle filter

## What this paper does
Studies the memory cost of storing all surviving particle paths of a particle filter / SMC sampler. Because resampling makes lineages coalesce (path degeneracy), the ancestry tree is a single "trunk" up to the full-coalescence time plus a small "crown" of branches near the present. The paper gives a parallel data structure that inserts each new generation into free slots and prunes nodes with no surviving descendant (reference-count style), and proves that the expected number of stored nodes is at most T + C N log N instead of T x N. Numerical experiments show the bound is tight in N and also holds for other resampling schemes.

## Goal-by-goal answers
### Goal: What is the bound on the size of the ancestry tree of N particles over T steps, and under what assumptions?
Theorem 3.2: for N >= 3, E[n_T] <= T + Delta_2 N log N, with Delta_2 independent of N and T; Theorem 3.1: the expected distance from the present to the most recent common ancestor is <= Delta_1 N log N, independent of T [full text, Section 3.1]. Assumption 1 bounds the weight function above and below (sqrt(eps) <= g <= 1/sqrt(eps)), which is strong outside compact spaces; the proof uses multinomial resampling, but Fig 3(a) indicates the same scaling for other schemes [Section 3.1, Section 4]. The crown size is independent of T; only the trunk grows linearly [Section 2.2]. Caveat stated by the authors: with constant weights, systematic resampling gives every particle exactly one child and removes path degeneracy entirely, so coalescence requires weight variability (or multinomial noise) [Section 3.1].
### Goal: What storage algorithm achieves it?
Nodes live in M slots with parent pointers and offspring counts. insert places the new generation into slots whose offspring count is zero (found by a prefix sum); prune walks up from each leaf with no offspring, decrementing parents' counts and freeing nodes whose count reaches zero [full text, Section 2.1, Algorithms 2-3]. The authors suggest storing the trunk separately, since trunk nodes are never overwritten, which makes per-step cost constant in T [Section 2.2]. This is functionally reference-counted copy-on-write storage of paths.
### Goal: How is path degeneracy framed?
As a defect for estimating marginals of early states, but "despite its negative consequence on the estimation of filtering quantities, the particle degeneracy phenomenon results in crowns of small sizes, allowing full trees to be stored at low memory cost" [Section 1].
