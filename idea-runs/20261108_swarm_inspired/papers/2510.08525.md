# Which Heads Matter for Reasoning? RL-Guided KV Cache Compression (RLKV)

## What this paper does
RLKV attaches a per-(layer, KV-head) gate α mixing full-causal and sink+local attention, freezes the LLM, and trains only the gates with GRPO (no KL term) plus an adaptive L1 penalty, using self-distilled curriculum data (3K DeepScaleR problems the model already solves). At inference the top-α heads keep the full KV cache; the rest keep only sink+recent tokens (16+64). Evaluated on Llama-3.1-8B-R1, Qwen-2.5-7B-R1, Qwen3-4B-Thinking over GSM8K, MATH500, AIME24, MBPP, MMLU-Pro subsets and LongReason, against H2O, R-KV, DuoAttention, KVzip; integrated into SGLang.

## Goal-by-goal answers
### Goal: How are budgets set and what evaluation-fairness issue does the paper raise?
It argues fixed token budgets are unfair for reasoning because outputs vary in length: with a 1K budget, short samples are uncompressed. R-KV's reported 66.2% compression on MATH500 Llama-8B-R1 is budget 200 / mean length 3019, while many samples are never compressed. RLKV uses a per-sample dynamic budget = sparsity × that sample's full-cache length for H2O/R-KV [full text, Section 4.1; Appendix E–F].

### Goal: What failure modes and length effects does head compression cause?
Error taxonomy on full-cache-correct instances: repetitive, incorrect, overlength (exceeds max length). Compressing retrieval heads (DuoAttention's) mainly causes overlength errors; compressing RLKV's reasoning-critical heads causes repetition and incorrect answers [full text, Section 5; Appendix D]. On jointly-correct samples, token-dropping methods appear shorter only because they solve easier instances; R-KV often lengthens reasoning; DuoAttention needs much longer reasoning. On LongReason R-KV "collapses into a repetitive loop" [full text, Section 4.2, Section 5].

### Goal: What accuracy/compression and end-to-end serving gains are reported?
Near-lossless at 20–60% KV reduction depending on model/task; up to 20% better than baselines [full text, Section 4.2, Table 1]. SGLang dual pool (paged cache for full heads + circular sink/local buffer for compressed heads), Llama-3.1-8B-R1 on one A100-40G, MATH500 continuous batching: full = concurrency 150, 1036 s, 79.4%, 1500 tok/s; sparsity 0.4 = concurrency 250, 1.56× (79.6%); 0.6 = concurrency 375, 2.06× but 73.8%. Measured speedups track the bound 1/((1−s)+sW/L) [full text, Section 4.3, Table 3]. No cost-per-correct metric; speedup is wall time for a fixed problem set.
