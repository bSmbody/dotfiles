# QJL: 1-Bit Quantized JL Transform for KV Cache Quantization with Zero Overhead

## What this paper does
Quantizes keys by a random Gaussian (orthogonalized) JL projection followed by the sign bit, and estimates q·k with an unbiased asymmetric estimator (query projected but unquantized). Outlier channels get a separate QJL instance with more bits. Values use standard token-wise quantization. CUDA kernels; LongBench on longchat-7b at 3 bits per FPN.

## Goal-by-goal answers
### Goal: How does QJL get 1-bit keys, and what does it guarantee?
Sign of a JL projection of the key; the estimator is unbiased (Lemma 3.2) with distortion comparable to an unquantized JL transform (Lemma 3.5), giving 1±ε relative distortion on attention scores (Theorem 3.6) [full text, Section 3, Section 3.1]. No per-group scale or zero point is needed [Section 1.1]. The randomness is a shared random projection, not per-element stochastic rounding.
### Goal: How are values handled, and was 1-bit V tried?
No. "The value cache quantization ... is known to be a straightforward task, and a standard token-wise quantization is very effective", so values use per-token normalization and rounding to a few bits [Sections 1.1, 3.2]. End-to-end runs are at 3 bits per FPN overall vs KIVI 3 bits and KVQuant 4.3 bits; on LongBench QA QJL is close to FP16 (e.g. HotpotQA 35.62 vs 33.05) [Section 4.2, Table 1]. No reasoning or long-generation evaluation.
