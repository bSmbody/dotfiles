# More GPUs or a Smaller Cache? Tensor Parallelism versus KV Compression for Memory-Bound LLM Serving

## What this paper does
Simulation study (Vidur simulator, profiled on A100/A40/H100 by its authors; the authors had no GPU access) that puts tensor-parallel degrees 1–8 and KV-compressed configurations (16/8/4-bit, eviction keep-ratio down to 0.25) on one cost-per-million-tokens vs latency axis for Llama-2-7B and 70B. Finds no cost crossover: compression is always cheaper below a model-size/device-memory wall, while TP is the only lever that lowers latency.

## Goal-by-goal answers
### Goal: How is KV compression modelled, and what is not modelled?
Per-device KV bytes m_kv = 2·L·h_kv(p)·d_head·(b/8)·n_ctx·r_keep, patched into the simulator's memory planner [full text, Sec III-D, Eq 3]. Dequantization and kernel latency effects are deliberately not modelled (best case for compression); Fig 7 gives the penalty that would reverse each verdict [Sec III-D, V-A]. Quality is not evaluated at all; contexts capped at 4096; synthetic workloads W1 (2048+256, unsaturated) and W2 (3840+256, 30 QPS, 384 requests) [Sec IV-B, Table I, Sec VII].
### Goal: What are the main quantitative findings?
Compression is cheaper than TP by 1.20–2.00× at every matched level of memory relief, with the gap widening as relief deepens; boundary ≈36B params for an 80 GB card under FP16 weights; Llama-2-70B is infeasible on one A100 at any KV setting since weights bind [Abstract, Sec V-A–V-C]. Compression worsens per-token latency by 8–93% through batching contention, but multiplies capacity per dollar by 16.5× vs 1.21× for 8× GPU spend [Abstract, Sec V].
### Goal: Relevance to long-CoT KV compression cost-per-correct?
Shows why cost-per-token framing favours KV compression when memory binds, but it ignores output-length changes, accuracy loss and dequant overhead, and never reaches long contexts (≥16K) or reasoning workloads — exactly the factors this run's success criteria add [Sec VII].
