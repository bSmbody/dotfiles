# SAS: Simple Attention Sparsification via End-to-End Optimization of Context Ranking

## What this paper does
Post-training sparsification of pretrained LLMs (Qwen3-4B/8B/14B) with a lightweight block selector. Instead of distilling dense attention (SeerAttention-R style), SAS injects the selector's softmax-normalized scores as log-gates inside the attention softmax so the LM loss trains the ranking end to end; continuous scores are kept rather than binarized, and a custom kernel is used. It ablates gate position, activation, ranking preservation and training scope (all blocks vs selected blocks only), and evaluates on reasoning (MATH500, GPQA, AIME), long-context and agentic tasks, plus continued pretraining.

## Goal-by-goal answers
### Goal: Under SAS's sparse training scope, do unselected blocks get their own gradient signal, and how does sparse scope compare with full scope?
No. "Under sparse scope, only the current Top-K blocks participate in attention. A block outside the selected set therefore has no direct gate gradient"; its score moves only indirectly through the softmax normalization over selector scores, which "does not evaluate the content of the unselected block itself" [full text, Section 4.2.2 "Training scope" / Eq 8]. Full scope gives each block its own term dg_m but needs attention over all blocks. Empirically sparse scope starts worse and catches up, matching full scope at convergence on MATH500/GPQA/AIME across 4B-14B and 1K-4K budgets, so SAS uses sparse scope [Section 4.2.2, Appendix C / Table 9]. Early in training a random selector "frequently leaves high-score blocks outside Top-K", producing large gradient norms under hard gating [Section 4.2.2, "Ranking preservation"].

### Goal: What limitations does SAS report on long-context retrieval and on what its selector covers?
SAS's per-layer selected blocks cover less dense attention mass than distillation, although the cross-layer union recalls more of the dense oracle's blocks [Section 6.1, Figure 5]. On RULER with 64K training and YaRN to 128K, SAS beats SeerAttention-R at shorter lengths but "its performance still degrades substantially as the context length increases, leaving a considerable gap from full attention", attributed to pooled block summaries losing needle-like information [Appendix B / Table 8].
