# WUSH-KV: KV Cache Quantization with Data-Adaptive Transforms

## What this paper does
WUSH-KV adapts WUSH, a data-aware transform built from the second-order statistics of both factors of a matrix product, to KV-cache quantization. Separate key and value transforms are built from calibration data. The value transform is folded into the weights; the dense key transform is applied online after RoPE. Paired with QuEST INT clipping, the transform is shown to be near-optimal under mild assumptions. The end-to-end evaluation integrates it into SGLang with OSCAR-style percentile-clipped affine INT2 quantization, reusing OSCAR's clipping ratios and BF16 sink (64) and recent (256) windows.

## Goal-by-goal answers
### Goal: Headline accuracy on long-CoT at 2 bits?
Table 2 (three seeds; AIME25 budget 92,160 tokens): Qwen3-4B-Thinking-2507 AIME25: BF16 77.8, OSCAR 65.6, WUSH-KV 71.1, TurboQuant-style Hadamard 0.0. Qwen3-8B AIME25: BF16 67.8, OSCAR 34.4, WUSH-KV 46.7. Qwen3-32B AIME25: BF16 74.4, OSCAR 63.3, WUSH-KV 60.0. LiveCodeBench v6 on 8B: BF16 47.8, OSCAR 20.4, WUSH-KV 35.2 (Section 5, Table 2).
### Goal: Does 2-bit KV inflate generated length / budget exhaustion? (critical for this problem)
Yes, strongly, and this paper reports it per cell. Qwen3-8B AIME25: mean generated tokens 45.4k (BF16, 11% budget exhaustion) vs 63.0k (OSCAR, 42%) vs 53.4k (WUSH-KV, 12%). LCB v6: 45.7k/11% (BF16), 73.8k/71% (OSCAR), 53.9k/26% (WUSH). The TurboQuant-style Hadamard transform runs to the cap: 91.8k tokens, 100% exhaustion on AIME25 for 4B. Qwen3-32B LCB: 40.9k/3% (BF16) vs 71.4k/53% (OSCAR) vs 54.3k/9% (WUSH). On 4B-Thinking, lengths stay close: 21.8k vs 24.2k/24.3k (Table 2). Length inflation is therefore method- and model-dependent and can be large at 2 bits, which qualifies the RESEARCH_PACK claim (Section 5, item 9) that measured lengths are "near BF16".
### Goal: Limitations?
The dense post-RoPE key transform must run online, which adds compute. There is no throughput evaluation, which is left to future work (Section 6). Clipping ratios were not retuned. In a single-run diagnostic, OSCAR calibrated on GPQA with the QuEST quantizer scored 0.0 on AIME25 (App. D), which shows calibration fragility.
