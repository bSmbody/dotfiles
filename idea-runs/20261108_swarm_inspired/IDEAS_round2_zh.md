## C6（低比特 KV）：Sigma-Delta KV——把舍入误差"传下去"，让它在注意力求和里抵消

**改变了什么**：KV 写入缓存时的舍入方式。码本、页面布局、注意力内核都不改。

**机制**：
- 注意力从来不单独读一个 token，读的总是很多 token 的加权和。
- 现在的低比特量化对每个 token 独立舍入，误差直接丢掉。长推理里相似的 token 很多（打转时尤其多），它们带着同方向的误差，在每次加权求和里不断累加。
- 改成音频 ADC 里 sigma-delta 调制器的做法：把一个 token 的舍入误差（"欠账"）加到**下一个 key 相似的 token** 上，再对那个 token 舍入。这样一组相似 token 的误差总和最多只有一个量化步长，不管这组有多少个 token。
- 缓存里还是 2 bit 码，但注意力求和的结果接近精确。

**借鉴来源**：信号处理中的噪声整形和 sigma-delta 帧量化 [1502.05807]；分布式优化中的误差反馈 [1901.09847]。

**最大风险**：单个 token 的最坏误差大约翻倍。对"只盯着一个特殊 token"的检索头（比如盯着一个数字或变量名），如果那个 token 没有相似的邻居，效果反而会变差。

**导师注**：这和我们之前否掉的 GPT 方案 C2 有相似之处。C2 当时的问题是：注意力集中在一个 token 上时，"保持块和"会比普通舍入差约 23 倍。C6 的不同在于，它把误差传给 **key 相似**的 token，而不是位置相邻的 token。相似的 key 拿到的注意力权重也相似，误差抵消的前提更成立。但"集中型头"的风险依然存在，审稿时要重点检查。

## C7（并行推理）：滚动视野的潜空间群体——在每个分叉点都看一眼没走的路

**改变了什么**：一条推理在写的过程中，同时能"看到"它没选的那些分支会往哪走。

**机制**：
- 只跑一条正常的文字推理，称为"主干"。
- 主干每写几百个 token，到段落边界时，从它**没有采样的那些分叉词**（"Wait""Alternatively""So"……）出发，分出几十到几百个短的潜空间推演，每个往前想几十步，不输出文字。
- 这些推演按引用共享主干的 KV，几乎不占额外显存，一次批量就能算完。
- 主干写下一段时，注意力可以读到所有推演的 KV；写完就把它们丢掉。
- 结果是：每个分叉点都做了探索，显存始终约等于一条推理加一个很小的临时群体。

**借鉴来源**：控制论中的 MPPI 滚动优化 [2112.09988]：每一步都采样大量短的未来轨迹，只执行第一步；天气预报的奇异向量集合预报 [2506.22450]。原语来自 LatentMAS [2511.20639] 和 SwarmEvolve [2611.08483]。

**为什么可能行**：LatentMAS 在不训练的情况下把 Qwen3-8B 的 AIME24 从 50.0 提到 53.3–56.7。SwarmEvolve 证明一张卡上可以同时跑几百个潜空间 agent。

**最大风险**：几十步潜空间推演携带的信息可能太少。LatentMAS 在 AIME 上相对文字 agent 的提升只有 0–1 道题。主干也可能直接无视这些推演，甚至被插进来的外来 KV 打乱。

## C8（淘汰/剪枝）：伪 token 折叠——把一段旧推理压成几个"伪 token"，什么都不删

**改变了什么**：推理历史的存储形式。从"一长串 token"变成"近处是原始 token，远处是逐层折叠的伪 token"。

**机制**：
- 一段推理滑出最近的精确窗口后，每个 KV 头把这段几百个 KV 换成少数几个**合成的伪 token**（key、value、对数质量）。
- 伪 token 的构造目标是：对未来**任意** query，它们吸引的总注意力质量、返回的加权 value 都和原来那段近似相同。具体做法是匹配原来那段的总质量、平均 value，以及 key 和 value 的低阶矩。
- 注意力内核完全不用改，伪 token 就是普通的缓存条目。
- 更老的段再一层层折叠：子块合成父块，就像天体物理里的快速多极子方法，用一个"伪粒子"代表远处的一整团星。
- 不挑选、不删除，每个旧 token 都通过伪 token 保留了它在注意力里的份额。

**借鉴来源**：Makino 的伪粒子多极子方法 [astro-ph/9806213]；kernel herding [1203.3472]：用少量样本匹配一个分布在核空间里的均值。

**最大风险**：旧段里如果藏着一个"尖锐的事实"，比如一个很久以后才会用到的变量值，低阶矩没法还原它。另外，RoPE 会让一段 key 在高频维度上散开，使这一段的"半径"变大、更难压缩。

## C9（混合模型）：私有思维、共享磁带

**改变了什么**：多条推理分支在混合模型里的记忆分工。

**机制**：
- 混合模型本来就有两种记忆：每个 token 都会被改写的递归状态（GDN/Mamba），和写入后永不修改的注意力 KV。
- 让 N 条推理分支把注意力 KV 写进**同一个共享、只追加的池子**，每条分支的注意力层都能读到所有分支写的内容；而每条分支的 GDN/Mamba 状态保持私有，永远看不到别的分支的 token。
- 分支之间随时交换中间结果，不额外占 KV 显存，也不需要合并任何递归状态。这绕开了 SwarmEvolve 说的"混合模型状态没法合并"的难题。

**借鉴来源**：并行 SAT 求解器：各求解器共享学到的子句（一旦写下就不变），但各自的搜索状态私有 [2207.13577, 2205.06590]。对照 Hogwild! Inference [2504.06261]（Transformer 上多个 worker 共享 KV）。

**最大风险**：只有约 1/4 的层能看到其他分支的 token，递归状态又完全不知道这些内容。外来信息可能太弱，各分支互相无视，最后效果和普通的"多采样投票"差不多。

**导师注**：Hogwild! 已经在 Transformer 上做了"共享 KV、并发推理"。C9 的新意只在混合模型上"共享 KV、状态私有"的分工，新意边界要靠查新确认。

## C10（变种注意力）：远端注意力延迟 B 步作答

**改变了什么**：注意力本身的计算方式。

**机制**：
- 现在每一步解码都要为一个 query 把整个远端 KV 读一遍，这是受显存带宽限制的矩阵-向量乘，重复几万次。
- 改成：近处窗口（sink、prompt、最近的 token）每一步照常实时计算；**远端历史的贡献延后 B 个 token 才加进来**。
- 这样连续 B 步对远端的读取互不依赖，可以合成一次批量计算。远端缓存每 B 个 token 才读一次，而且每个远端 token 仍然会被每个 query 用精确 softmax 打分，不做任何挑选。
- 远端缓存也因此可以放在 CPU 内存里流式读取。

**借鉴来源**：深度流水线共轭梯度法 [1801.04728]：全局内积晚几步再用，以隐藏通信延迟；分子动力学的多时间步长积分 [1312.1284]：远程力隔几步算一次。

**为什么可能行**：很多头本来就不太用远端信息。DuoAttention 发现"流式头"只看 sink 和最近窗口，长上下文能力几乎不受影响 [2410.10819]，这些头延迟远端读取没有代价。

**最大风险**：改变了模型的计算语义，大概率需要训练。像"逐位抄写远处的一个数字"这类操作，query 依赖刚写出的 token，没法提前 B 步发出。
