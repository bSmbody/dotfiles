## 1. Scope（本轮最终采用的）

**统一的问题**：长生成推理（尤其是长思维链）时的记忆管理。KV cache 是边生成边涨的，在标准注意力模型和混合模型里，要回答四件事：历史信息留哪些、用什么形式存（精确 KV / 量化 KV / 递归状态）、放在哪、存多久。

| 优先级 | Lane | 对应师兄说的 |
|---|---|---|
| 核心 | L1 长思维链的 KV 淘汰 | 标准注意力剪枝 |
| 核心 | L2 混合模型里 KV 和 GDN 状态的联合管理 | 混合架构 + KV 量化/释放时机 |
| 核心 | L3 记忆矩阵的更新规则 | 记忆矩阵 |
| 核心 | L6 混合架构选层（按长推理表现） | 混合架构 |
| 次要 | L4 稀疏注意力 selector 的训练 | 变种注意力的算法 |
| 次要 | L5 递归状态剪枝 | 变种注意力剪枝 |

**不在范围内**：权重量化或剪枝、MoE、只做系统调度的工作、以 benchmark 为主要贡献的工作、多模态视觉 token 剪枝（留作以后的扩展）。
**约束**：目标是 NeurIPS 档主会；算力按 H200 集群（约 1 TB 显存）计；优先选能复用现有 kernel 的方法。

|---|---|---|---|

## 3. 存活的 idea：C14

### 3.1 标题与一句话
**Fewer Full-Attention Layers from the Failures On-Policy Training Leaves Behind: Verified Repair Sets for Hybrid Reasoning Models**

> 把 Transformer 改成混合模型后，它在自己生成的长推理里仍会出错。找出哪些层恢复成全注意力就能修好这些错，只给这些层保留全注意力，这样用更少的、会随长度增长 KV 的层就能保住准确率。

### 3.2 要解决什么问题（大白话）
- 把 Qwen3 这类模型改成混合模型时（多数层换成 GDN），**保留哪几层全注意力**，现在要么按规则定（Opal：每 4 层留 1 层，即 9/36），要么在固定文本上打分（KL、passkey、NLL、teacher 轨迹似然等）。
- 但长推理的失败发生在**模型自己生成的轨迹**上：前面算出的中间值，几千 token 后要用，GDN 只记得一个模糊的版本，于是出错。在固定文本上打分看不到这种失败。
- 全注意力层的 KV 是长推理时**唯一随长度增长**的显存。多留一层，每生成一个 token 都要为它付费。

### 3.3 方法（四步）
1. **搭"teacher 锚定"的超网**：teacher 的全注意力路径和其他权重全部冻结，只训练 GDN 路径。这样"所有层都换回全注意力"就**严格等于 teacher**，任何失败都保证存在一个修复方案。
2. **on-policy 蒸馏 GDN 路径**：学生在自己的长推理 rollout 上，跟冻结的 teacher 做 reverse KL。
3. **挖失败事件、诊断修复集**：在答错的轨迹里，找第一个和 teacher 明显分歧的位置。用"修复后答案确实会翻转"过滤掉无害的分叉（两边各 8 次续写）。对每个事件，从"全部换回全注意力"出发，逐层退回 GDN，每一步都实测，找到**最小的修复层集合**。这借用了软件调试里的 delta debugging，不需要假设"修复是单调的"。
4. **按覆盖率分配，按数据停止**：哪一层（或 ≤3 层的组）能修好最多事件，就把它定为全注意力。定完再做 on-policy 训练、重新诊断。等到最好的候选也修不了 5% 以上的事件时停止，这时的层数就是 K。最后用 Opal 的联合训练方案训出真正发布的模型。

### 3.4 头条主张与评测
- **头条**：真正发布的模型只用 **K ≤ 6** 层全注意力，就能在 AIME avg@32 上和 Opal 9/36 打平（非劣效边界 −2 pp，3 个种子，所有方法总 GPU 小时对齐）。也就是**增长部分的 KV 至少小 33%**。
- **第一步先过闸门**：联合训练之后，"选哪几层"还重要吗？在 K=4、6 下跑 5 组随机分配，如果它们之间的差距 < 5 pp，说明选层不是有效的杠杆，整篇论文就停掉。
- **主模型**：Qwen3-4B（thinking，36 层）。复现模型：MiMo-7B-RL（1 个种子）。线性层：flash-linear-attention 里的 GDN。
- **Benchmark**：AIME 2024/2025（avg@32，最长 32K）、MATH-500、GPQA-Diamond、NIAH 4K–32K（单针 / 多 key / 多 query）、RULER 4K–32K，以及显存、吞吐、GPU 小时。

### 3.6 可证伪的预测与 kill condition（节选）
| 预测 | 什么情况算失败 |
|---|---|
| 联合训练后选层仍重要：随机分配的差距 ≥ 5 pp，且 ≥ 2 倍种子噪声 | 差距不够 → 选层不是杠杆，停 |
| K_stop ∈ {4,5,6}，且非劣于 Opal 9/36 | CI 下界 ≤ −2 pp，或均匀穿插本身就已经非劣 |
| 比三个强 baseline 都高 ≥ 3 pp | 有任何一个差距在 3 pp 以内 → 那个 baseline 就是更好的推荐方案 |
| 修复集比"只做事件定位的 KL"高 ≥ 2 pp | 达不到 → 去掉 ddmin，方法退化成事件定位 KL |
| 首轮 pilot：最好的候选能修好 ≥ 10% 的事件 | < 5% → 失败是弥散的，方法作废 |
| KL 修复和答案修复一致 | 一致性太低 → 修复判据不可信 |

### 3.7 模拟评审组怎么看
| | v1 | v2 |
|---|---|---|
| R1 领域专家 / R2 资深外行 / R3 实验派 | 3 / 3 / 3 | 4 / 4 / 3 |
| AC 给的录用把握 | 1.8 / 10 | **3.2 / 10** |
| 核心预测成立的概率 | 0.2 | 0.25 |
| 风险调整后 | 0.8 / 10 | 1.6 / 10 |

**v2 仍然存在的关键弱点（AC 认定）**：
1. **三位评审一致指出**：没有在**相同 KV 字节数**下和"Opal 9/36 + 现成 KV 压缩"（FP8/INT4、长推理淘汰、混合模型淘汰）做对比，也没证明两者能叠加。如果打开 KV 量化开关就能省 33%，"少几层"就没有说服力。
2. 在预测门槛上，所有结论都是勉强过线，统计设计偏薄（种子方差、多重比较、AIME 只有 60 题，还有污染风险）。
3. "K 由数据决定"站不住：换超参数，K_stop 会浮动 2 层。
4. 修复集机制只比简单的消融多 2 pp；缺一个"只跑轮次、不做诊断"的对照（LOOP [2610.25679] 提示收益可能主要来自迭代本身）。
5. 范围窄：一个主模型、只有数学、生成长度只到 32K。

### 3.8 如果做 v3，按 AC 的排序该改什么
1. **头条换成"准确率 vs KV 字节数"的 Pareto 图**：Opal 9/36 + FP8/INT4 + 一种长推理或混合模型淘汰方法（BreadthKV、R-KV、GateSight 等），放在 K=4、K=6 对应的字节数上，再和 C14 + 同一种压缩比较。要证明"少层"要么胜过压缩，要么能和压缩叠加。
2. **重做统计**：在 K* 下跑 10–20 组随机分配，报告 C14 排在第几百分位；用分层种子 bootstrap 加 Holm 校正；K* 在开发集上选；加 AIME 2026 和 HMMT 扩大并去污染；做功效分析。
3. **加"只跑轮次"的对照**和启发式布局（中间连续一段、跳过首尾层），讨论 LOOP；把故事重心放在"on-policy 失败定位"，ddmin 放进附录。
4. 让 Opal 9/36 的复现先达到它论文里的数字，误差在约定范围内，否则非劣效比较不算数。
5. 固定 K=6 作为头条，或预测 K_stop 在整个超参数网格上都 ≤ 6。
6. 扩大范围：Qwen3-8B 跑 3 个种子，加一个跨域任务（LiveCodeBench），生成长度超过 32K，再和头级别的分配方法（ConSA、HydraHead）比较。

### 3.9 可行性：对你来说难在哪
- **算力**：够。诊断约 5–30B prefill token，在 8×H200 上约一天。真正耗时的是大约 40 次"发布级"训练。
- **工程**：不需要新 kernel（复用 fla、FlashAttention、vLLM）。但流水线很长：超网 → 32K on-policy 蒸馏 → 事件挖掘 → 诊断 → 分配 → 联合训练，没有现成代码可用。**4–6 个月对一个新手单打独斗偏紧**，需要师兄或组里一起做。
- **最大风险**：闸门不通过。已有证据显示，on-policy 训练能让模型绕开架构上的限制：纯滑动窗口注意力加 RL，数学成绩只比全注意力低 0.4–1 pp [2606.11634]。如果联合训练后选哪几层都差不多，这篇论文的前提就不存在了。**这一点可以先用一个很便宜的 pilot 测出来。**

## 4. 审稿中挖到的硬事实（选题时很有用）

| 事实 | 出处 | 对选题的含义 |
|---|---|---|
| 推理任务上，保住 prompt 后随机删 KV，效果和 SnapKV、R-KV、VaSE、TriAttention 相当 | [2609.03430] | 现有 KV 打分思路整体有问题，"随机"必须作为 baseline |

| 纯滑动窗口注意力加 RL，数学成绩只比全注意力低 0.4 pp（1.5B）和 1 pp（4B） | [2606.11634] | on-policy 训练可能抹平架构上的差异，这是 C14 的最大风险 |
| 生产环境的 indexer 每步漏掉约 40% 的精确 top-k，而且多数无害 | [2512.03494] | "漏选"本身未必是问题 |

## 6. 诚实说明
- "x/10"是模拟评审组在"所有预测恰好达到门槛"这个假设下给出的估计，**不是真实的录用率**。所以 p_core（核心预测真正成立的概率）和风险调整后的分数一起看更有意义。
- 所有引用都有读书笔记（`check_run.py` 已检查）。但文献库只覆盖 arXiv，没上 arXiv 的工作可能漏掉了。
- 这一轮中途两次撞到 5 小时额度上限，被打断的子 agent 都从断点续跑，没有丢失进度。

## 7. 下一步建议

**选项 A（推荐）：C14 v3，同时把 L1/L2 的成果并进来。**
三位评审一致要求的"相同字节数下和 KV 压缩比较"，正好用得上 L1/L2 调研出的 baseline（BreadthKV、R-KV、GateSight 等）。这样合起来就是一个完整的故事：**少用几层全注意力，再对剩下几层的 KV 做压缩，看两者在长推理上能否叠加。**这也贴合师兄说的"混合架构下 KV 管理不一样"。
动手前**先做一个便宜的 pilot**：转换一个 Qwen3-4B 混合模型，联合训练后在 K=4、6 下各跑几组随机分配，看差距是否 ≥ 5 pp。差距不够就别继续投入。

**选项 B：换题。** 第 4 节的硬事实说明有几个方向被高估了：压缩状态、"意外度"式的 KV 打分、双胞胎对照。如果想换题，可以基于这些事实重新派 gap_finder。例如"推理模型的 KV 卸载 / 分层存储"（"永久删除才致命"这条事实，提示这个方向动机很强）。
