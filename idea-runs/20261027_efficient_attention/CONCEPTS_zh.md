# 概念对齐：KV cache 的生命周期，传统注意力 vs 混合注意力（2026-10-27）

师兄的意思可以概括成一句话：**在混合架构下，什么时候量化、什么时候释放、怎么剪枝，都和传统注意力不一样。**
要理解这句话，先把“模型在推理时到底缓存了什么、这些东西从生到死经历了哪些阶段”讲清楚。

带 `[arXiv id]` 的结论来自本次 run 读过的论文（见 `papers/`）；其余是通用背景知识，标了“（背景）”的部分没有逐篇核对。

---

## 1. 先搞清楚推理的两个阶段

一次请求在推理时分两段：

- **Prefill（预填充）**：把整个输入（prompt、文档、图像 token）一次性并行过一遍模型。这一段算力密集，主要决定首 token 延迟（TTFT）。
- **Decode（解码）**：一个 token 一个 token 地往外生成，每步只算一个新 token。这一段受显存带宽限制：每生成一个 token，都要把权重和缓存从显存里完整读一遍。它决定每个 token 的生成耗时（TPOT）和吞吐。

长思维链推理的特点是 **decode 极长**：输入可能只有几百 token，输出却有几万 token。所以缓存主要是在 decode 阶段一边生成一边长出来的。这一点后面很重要。

---

## 2. 传统 Transformer：KV cache

### 2.1 是什么、有多大

每一层注意力都要用到前面所有 token 的 K 和 V。为了不在每一步重算，就把它们存下来，这就是 KV cache。

大小（背景）= 2（K 和 V）× 层数 × KV 头数 × 头维度 × 序列长度 × 每个数的字节数。

以 Llama-3.1-8B 为例（32 层、8 个 KV 头、头维度 128、BF16）：
- **每个 token 约 128 KB**；
- 32K token 约 4 GB，128K token 约 16 GB，比 16 GB 的模型权重还大；
- 如果同时服务多个请求，每个请求各占一份。

为了减小它，大家在注意力的“形状”上做过很多改动（背景）：
- **MHA**：每个头各有一份 K、V。
- **GQA / MQA**：多个 query 头共享一份 K、V。Llama 3 用的是 GQA。
- **MLA**（DeepSeek）：把 K、V 压成一个低维潜在向量再缓存，只缓存这个向量。

### 2.2 生命周期：写一次，读很多次，到点释放

```
token t 生成 ──→ 算出 K_t, V_t ──→ 追加进 cache ──→ 之后每一步都被读 ──→ 请求结束时释放
                                    （一旦写入就不再改变）
```

**关键性质：每个 token 的 K、V 写入之后就固定不变，而且一个 token 对应一个条目。**
这两个性质决定了传统方法里量化、剪枝、释放分别怎么做：

| 操作 | 什么时候做 | 为什么可以这么做 |
|---|---|---|
| **量化** | ① **写入时**：新 token 的 K、V 一算出来就量化。常见做法（背景，如 KIVI）是最近的几十个 token 先保持高精度，凑满一组再整组量化，K 按通道量化、V 按 token 量化。② **Prefill 后一次性**量化整段 prompt。③ **分层降级**：冷 token 降到 INT2/INT4，热 token 留高精度，可以升级也可以降级 [2608.05326] | 条目不再改变，**只需要量化一次，误差不会累积** |
| **剪枝 / 淘汰** | ① **Prefill 后一次性**：比如 SnapKV，用 prompt 末尾的注意力挑出要保留的 token。② **Decode 中持续**：比如 H2O、R-KV，每生成一段就删一批。③ **只读不删**：比如 Quest，每个 query 只读最相关的页，所有条目仍然保留 [2406.10774] | 一个 token 对应一个条目，**可以按 token、页、头为单位删** |
| **释放** | ① 请求结束，整块回收（背景：vLLM 的 PagedAttention 按页管理）。② 被淘汰的条目立即释放。③ **卸载**：不删，而是挪到 CPU 内存，需要时再取回 [2610.02713] [2605.09490]。④ **前缀缓存**：多个请求有相同前缀时共享 KV，**在任意长度截断都能复用** | 条目之间互相独立，删、挪、共享都可以按条目做 |

推理模型上有一个重要发现：在长推理里，准确率取决于**永久删掉**了多少，而不是 GPU 上留了多少。挪到 CPU、需要时再取回的 token 不影响准确率 [2605.09490]。所以“释放”和“删除”要区分开：释放显存不等于丢掉信息。

### 2.3 传统方法的剪枝粒度

由细到粗：

- **位**：量化，即每个数用几位存。
- **token / 页（block）**：淘汰、稀疏读取。
- **头**：给不同的头分配不同的预算。比如有的头只看局部，给它一个短窗口就够了。但研究发现 63–85% 的头在生成过程中会改变“看哪里”，所以**一次性给头分类是不对的** [2610.02713]。
- **层**：给不同的层分配不同的预算。

## 3. 线性注意力 / GDN 层：递归状态

### 3.1 是什么

线性注意力（以及 Mamba、GDN）不存每个 token 的 K、V，而是**每个头维护一个固定大小的矩阵 S**，大小是 d_k × d_v，也就是第 3 节综述里说的记忆矩阵。

- 每来一个 token：**读出 S → 按当前 token 修改 S → 写回 S**，即读-改-写。GDN 的修改是“先衰减，再按误差修正”。
- 查询时：用 q 乘以 S，得到输出。
- 大小**不随序列长度变化**。另外还有一个很小的卷积缓存，只记最近几个 token（背景）。

### 3.2 和 KV cache 的根本区别

| | 传统 KV cache | 递归状态 S |
|---|---|---|
| 大小 | 随长度线性增长 | 固定 |
| 更新方式 | **只追加**，旧条目不变 | **原地覆盖**，每个 token 都改写整个矩阵 |
| 信息组织 | 一个 token 对应一个条目，可以单独定位 | 所有 token 的信息**混叠在同一个矩阵里**，没有“第 t 个 token”这个条目 |
| 回退 | 截断到某个长度即可 | 被覆盖了就回不去，除非事先存了快照 |

这四点区别，直接导致了量化、释放、剪枝的时机全部不同，详见第 5 节。

## 4. 混合注意力架构：两套缓存并存

混合架构是指大部分层用 GDN（或 Mamba、KDA）这类线性层，少数层保留全注意力。具体例子：

- Qwen3-Next 系列（背景）：GDN 和全注意力的比例约为 3:1，全注意力层带输出门。
- Qwen3.8-27B：48 层 GDN 加 16 层全注意力 [2610.14754]。
- Kimi-Linear：KDA 线性层加 MLA 全注意力层（背景：比例约 3:1）[2608.27513]。

于是一个请求在推理时同时持有**两种性质完全不同的缓存**：

```
            ┌───────────────── 一个请求 ─────────────────┐
 GDN 层 ×48 │ 递归状态 S：固定大小，每个 token 原地读-改-写  │ ← 不随长度增长
 全注意力×16 │ KV cache：随长度增长，只追加                 │ ← 唯一随长度增长的部分
            └──────────────────────────────────────────┘
```

到 100K token 时，全注意力层的 KV 是 GDN 状态的 **42 倍** [2610.14754]。也就是说：
- 混合架构的 KV 总量比传统模型少很多，因为只有约 1/4 的层存 KV；
- 但**剩下的这部分 KV 仍然是唯一随长度增长的东西**，长上下文和长推理时它照样是瓶颈；
- GDN 状态虽然不增长，但每步都要完整读写一遍，它的存储格式影响每 token 的生成速度。把它量化后，每 token 耗时最多能降 19% [2608.27513]。

## 5. 正题：混合架构下，时机为什么不一样

### 5.1 量化时机

**传统 KV：写一次，量化一次。** 误差固定，不累积。

**递归状态：每步都要“反量化 → 更新 → 再量化”。** 如果状态以低精度存储，每生成一个 token，都要先恢复成高精度，加上这一步的更新，再量化回去。问题出在这里：

- **误差会随解码长度不断累积。** 在位宽 × 解码长度这个平面上存在一条“失败前沿”：位宽越低，越早崩溃 [2610.15139]。
- **小更新被舍入吃掉。** 状态累积了很多 token 之后数值很大，量化网格的间距也随之变大，而单个 token 的更新远小于网格间距，一舍入就没了。这些丢失的误差方向一致，会相干地叠加 [2610.15709]。
- **反馈环。** 如果量化的 scale 是从当前状态动态算出来的，状态的误差会影响 scale，scale 又反过来影响状态 [2610.15139]。

所以递归状态的量化时机要专门设计，已有的几种思路：

| 思路 | 做法 |
|---|---|
| 计算时保持高精度，只在存储或换出时量化 | 背景：kernel 内部的分块计算本来就用 FP32 |
| 小更新先攒着，再定期合并 | 把小更新以低秩形式先缓冲起来，攒够了再合并进低精度状态，避免每一步都被舍入 [2610.15709] |
| 按“误差能活多久”分配精度 | 衰减慢的单元，误差会留存很久，就给更多位；衰减快的单元，误差很快会被遗忘，就少给 [2609.38169]。也有按“量化误差 × 衰减保留率”挑出部分通道留 FP16、其余用 INT8 的做法，在 Qwen3.6-35B、Kimi-Linear-48B 上接近 FP32，状态存储降低 69% [2608.27513] |
| 换个 scale 策略 | 固定 scale、设上限、定期重置、分组量化等 [2610.15139] |

而**全注意力层的 KV** 量化方法和传统模型一样，可以写入时量化。但因为只剩约 1/4 的层负责精确检索，这些层对误差可能更敏感，这一点还缺系统研究。

### 5.2 释放时机

**传统 KV：可以按 token 释放**，请求结束、被淘汰、被换出时都能释放；前缀可以在任意位置截断复用。

**递归状态：**
- **没法按 token 释放。** 信息已经混叠在矩阵里，不存在“删掉第 t 个 token”这个操作。旧信息只能靠衰减门“自然遗忘”，遗忘的节奏由模型自己的门控决定，不由系统决定。
- **前缀缓存变难了。** 传统 KV 在任意长度截断就能复用前缀；递归状态只在**保存过快照的位置**才能复用。系统必须决定在哪些位置存快照，快照本身也要占存储，还要决定什么时候删掉它们。已经有工作专门压缩这些快照：只保留衰减慢的头或通道，复用时把丢掉的部分填零，或者重放一小段后缀来恢复，首 token 延迟降低 16–42% [2608.30386]。
- **回退需要快照**（背景）。投机解码要回滚没被接受的 token，传统 KV 截断一下就行；递归状态已经被原地覆盖，必须事先保存中间状态。

**全注意力层的 KV**：释放方式和传统一样，但多了一个新问题，见 5.3 的第 3 点。

### 5.3 剪枝方式

在混合架构下，剪枝的对象和准则都变了：

1. **递归状态剪的不是 token，而是维度。** 剪的是状态的通道、头或模态 [2602.04852] [2602.02195]。而且真正被用到的状态单元会随输入内容迁移，几百个 token 内就会变化，所以离线固定的掩码会损失很多 [2607.11796]。
2. **全注意力层的 KV 剪枝更“危险”。** 在混合架构里，精确检索全靠这少数几层，剪错的代价更大。已有的做法有：
   - 每个 KV 头离线分配一个固定的历史长度（8K/16K/32K/全部），最大可验证上下文从 114K 提到 161K [2609.02029]；
   - prefill 后一次性压缩，用 GDN 层自己的信号（写入门、衰减、value 范数）预测每个条目将来有没有用，预算按注意力输出门来分配 [2610.14754]。
3. **两套记忆有冗余，剪枝准则应该考虑这一点。** 从全注意力 KV 里删掉一个 token 时，它的信息可能还以有损的形式留在 GDN 状态里，也可能已经彻底丢了。现有方法只看“删掉它对本层注意力输出的影响”，没区分这两种情况。理想的做法是两套记忆分工：GDN 已经记住的，KV 就不必再存。这是综述 §2 的缺口 2。
4. **层本身就是一种剪枝粒度。** 把一个 Transformer 改造成混合模型，本质上就是在**层级别**上决定哪些层“剪掉”全注意力、换成线性层。选哪些层、留多少层，就是综述 §2 的缺口 1。

### 5.4 一张总表

| | 传统 Transformer | 混合架构：全注意力层的 KV | 混合架构：GDN 递归状态 |
|---|---|---|---|
| 大小 | 全部层 × 长度 | 约 1/4 的层 × 长度（唯一随长度增长的部分） | 固定 |
| 更新 | 追加 | 追加 | 每 token 原地读-改-写 |
| **量化时机** | 写入时量化一次，误差不累积 | 同传统，但这些层可能更敏感 | 每步反量化-更新-再量化，**误差随解码长度累积**，需要缓冲更新、按寿命分配位宽 |
| **释放时机** | 按 token、页释放；任意前缀可复用 | 同传统 | **不能按 token 释放**，靠衰减遗忘；前缀复用要靠快照，快照什么时候存、什么时候删是新问题 |
| **剪枝对象** | token、页、头、层 | token、页、头，**但要考虑 GDN 里是否还有这份信息** | 状态的通道、头、模态，**重要性随输入迁移** |
| 回退 | 截断即可 | 截断即可 | 需要事先存快照 |

## 7. 对上你师兄说的五个词

| 师兄的说法 | 对应本文 | 一句话 |
|---|---|---|
| 标准注意力剪枝 | §2，综述 §1 | 对 KV cache 按 token、页、头做淘汰或稀疏读取 |
| 变种注意力剪枝 | §3、§5.3 第 1 点，综述 §4 | 剪 GDN、Mamba 状态的维度，以及转 MLA 后的压缩 |
| 混合注意力架构 | §4，综述 §2 | 两套缓存并存，层是新的剪枝粒度 |
| 记忆矩阵 | §3，综述 §3 | 就是 GDN 的状态 S，研究怎么写、怎么忘 |
| 变种注意力的算法 | 综述 §5 | 让 S 的更新能分块并行、跑得快 |
| **KV 量化 / 释放时机** | **§5.1、§5.2** | 混合架构下，状态是原地更新的，所以量化误差会累积、不能按 token 释放、前缀复用要靠快照 |

## 8. 可以带回去问师兄的问题

1. 他说的“量化时机”，指的是**全注意力层的 KV**，还是 **GDN 递归状态**，还是两者怎么配合？这三种情况是三个不同的问题。
2. 关注的场景是**长输入**（prefill 重，一次性压缩就有效），还是**长推理输出**（decode 重，缓存一边生成一边长，必须持续管理）？
3. 落地的系统是 vLLM 还是 SGLang？前面提到的递归状态量化和快照压缩都是在 SGLang 里实现的 [2608.27513] [2608.30386]。前缀缓存、投机解码这类系统特性要不要考虑？
4. 用哪个混合模型做实验？Qwen3-Next 是 80B MoE，24 GB 的卡放不下。论文里用过的小一些的有 Qwen3.5-9B [2609.02029]、GDN 0.8B/2B [2610.15139]，需要确认能拿到哪些。
