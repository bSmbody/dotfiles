
### C5 — Recurrent state as a cache: learned unit replacement that imitates the exact pruning oracle

- **Intuition**: Treat each state unit of a gated linear-attention / SSM layer (a mode, a key-channel row or a balanced direction) as a cache line, and make the keep/drop decision a replacement decision revised at every chunk. A unit that a new write fills can be admitted at once, and the unit whose stored content is worth least in future reads is evicted. This avoids predicting one mask for a coming window, and the ranking policy is learned by imitating the exact future-aware pruning oracle, the way CPU caches learn to imitate Belady's policy.
- **Gap it attacks**: Axis "Pruning and compression of variant attention mechanisms", gap 1: every recurrent-state pruning and mixed-precision method (DRRQR [2602.04852], DASC horizons [2608.30386], DAMP [2608.27513], STEPQuant [2609.38169], and the new balanced-truncation BASS [2610.36617]) commits to one offline, input-independent unit set. Yet the units a gated layer uses migrate with the input write map B_t, which leaves a same-window headroom below every static rule and even below the unpruned model [2607.11796]. The causal schedulers tried so far all fix a mask ahead and hold it over a span (regime mask, 256-token prefix, first-half-of-window). They recover only 2-26% of that headroom, because the important set decorrelates within a few hundred tokens [2607.11796]. Closing this would let a halved state follow what is actually stored. It matters most for purely recurrent models, where static halving drops GDN-1.3B NIAH-4K from 81.3 to 61.9 [2602.04852], and for serving systems that keep and checkpoint these states for many requests [2608.30386].
- **Source inspiration**: Computer-architecture cache replacement, *recombination-of-distant-concepts*. Parrot [2006.16239] learns replacement for CPU caches by imitating Belady's optimal policy. Belady's needs future accesses, so it exists only offline, but on a fixed trace it can be queried exactly at any cache state. Parrot trains a causal policy that sees only the incoming access, the resident lines and recent history to rank resident lines for eviction the way the oracle would. Three ingredients carry the gain. DAgger roll-outs collect states under the learned policy, because its own evictions create cache states the oracle never visits (+9.8%). A ranking loss penalises evicting soon-needed lines more than near-optimal mistakes (+3.5%). An auxiliary head regresses each line's reuse distance (+16.8%). Hand-designed heuristics each fit one access pattern, whereas the learned ranking closes much of a gap that, by the paper's measurement, needs exact knowledge thousands of accesses ahead [2006.16239, Sections 3-5].
- **How it maps to this problem**: Cache lines become the r state units a head keeps in memory. A cache miss becomes a chunk whose writes put new content into units outside the kept set. The resident candidates are the kept units plus the newly written ones, ranked together, so that admission at write time absorbs the B_t-driven migration, the part [2607.11796] shows is necessary and largely sufficient. Belady's reuse distance becomes the exact future output error from dropping a unit's current content. For diagonal SSMs, the per-mode Gram instrument of [2607.11796] gives this error exactly over the following window. For Mamba-2 and GDN it comes from one look-ahead roll-out on the training trace. The causal policy is a tiny per-layer scorer that reads only what is known at the decision point: each unit's stored content, the chunk's write and read couplings, and the unit's static decay horizon (the timestep carries almost none of the migration [2607.11796]). DAgger matters more here than for CPU caches, because an evicted unit's content is gone and later states and downstream layers differ under the learned policy. Precision tiers (FP16 / INT8 / dropped) fit the same frame as a small cache hierarchy with promotion and demotion. For Mamba-2, the units can be the balanced directions of [2610.36617] instead of native coordinates.
- **Why it could work / feasibility**: Parrot's conditions hold here. (i) The oracle is exactly computable offline at any policy-induced state: [2607.11796] gives exact per-subset output error in one pass for diagonal SSMs, and for other layers a teacher roll-out on fixed text is cheap. (ii) Causal features carry real signal: the domain is linearly readable from a layer's mode energies at 99.7% [2607.11796], and the stored content after a write is observed exactly rather than predicted. (iii) Whole-span masks fail where per-decision ranking need not, since the oracle's advantage comes mostly from which units the current tokens write [2607.11796, Section 4.2], and a replacement policy sees those writes before deciding. In Mamba-1, B_t and C_t are shared by all channels of a layer [2607.11796, Eq 1-2], so one ranking can serve a whole layer, keeping index overhead and scorer cost small. In-domain, KVP [2602.10238] shows that a tiny per-head learned scorer trained offline on future utility outperforms heuristic proxies for KV tokens up to 128K, which supports the cost side. Compute is not binding: traces, oracle labels and DAgger roll-outs on 1.3B-8B GDN / Mamba checkpoints fit the H200 budget. Kernel cost is modest: fla chunk kernels run unchanged inside a chunk, and decode needs a gather/scatter of r units per head plus a top-r select (a small Triton change). Key assumption: the oracle's ranking of current units is predictable from stored content plus current writes and reads, without the future reads that a window oracle also sees.
- **Novelty vs. closest in-domain work**: [2607.11796] measures the headroom and tries only mask-ahead schedulers. Here the decision becomes per-chunk replacement with admission and a policy imitated on-policy from its exact oracle. KVP [2602.10238] learns eviction for immutable KV tokens offline from fixed traces, without modelling how evictions change later inputs. Here the evicted objects are evolving state units, whose eviction changes all later state. SSE [2507.16577] and Raven [2607.25357] route writes sparsely, but only in new architectures trained from scratch, with token-only routers and all slots stored. This method is post-training, state-aware, and it shrinks the stored state of existing dense-write models.
- **Main risk**: Most of the oracle's headroom may come from the future read map C_t and from its "denoising" gain over the unpruned model. Both depend on tokens not yet seen, so a causal replacement policy may top out near the 18-26% half-window scheduler, especially since the energy of stored content is dominated by a bias-like direction that the output barely reads [2610.36617].


### C4 — Exploration slots for sparse-attention selectors: off-policy-corrected feedback on blocks the selector missed

- **Intuition**: A block-sparse attention selector is a top-K recommender that only ever gets feedback on the items it showed. Borrow the recommender fix: spend a few extra block slots per query block on blocks sampled with known probability from outside the top-K, measure their true attention mass with the same sparse kernel, and use inverse-propensity weighting so the selector gets an unbiased signal about all blocks, including the ones it currently misses, without any dense attention.
- **Gap it attacks**: Axis "Hardware-efficient training and inference algorithms for linear and sparse attention", gap 2 (selector trained only on its own support). In every trainable selector read here, the signal that trains the selector is computed only over the blocks it already chose: NSA's selection gets no gradient of its own [2502.11089]; MSA's KL is normalized over the selected tokens after a dense warmup [2606.13392]; DashAttention's entmax Jacobian is zero off the support [2605.18753]; hard top-k gives dM/dG = 0 [2603.02227]. The newest end-to-end method, SAS, states it directly: under its sparse training scope "a block outside the selected set therefore has no direct gate gradient", and only full scope, meaning attention over all blocks, gives each block its own signal [2609.13141]. So a relevant block that is missed now, such as a needle, or an intermediate result a long chain of thought revisits later, is corrected only by dense phases: MSA's warmup, distillation on frozen dense attention, or SAS's full scope. Those phases bring back the O(N^2) cost that the kernel exists to avoid, and the cost grows fastest at 128K-1M, exactly where SAS and MSA report a remaining retrieval gap [2609.13141, 2606.13392]. Closing the gap would make the selector's recall trainable from sparse-only compute at any length, and would give a clean test of whether the long-context retrieval gap is a credit-assignment problem or a selector-capacity problem.
- **Source inspiration**: Large-scale recommendation and retrieval, which face the same structure: a model picks K of millions of items and observes reward only for the items it showed. (1) YouTube's top-K off-policy REINFORCE recommender [1812.02353] handles this in three ways. It weights logged feedback by the ratio between the learned policy and the logging policy, so learning stays unbiased even though feedback comes only from shown items. It rewrites the objective around the probability that an item enters the K-set, which adds a multiplier: an item with little probability mass is pushed up about K times harder, and an item already reliably in the set stops receiving gradient. This is what makes the learned policy good at top-K rather than top-1. And it uses Boltzmann exploration, returning the top K' items deterministically and sampling the rest, so that unshown items get feedback at all; weight capping keeps the variance under control [1812.02353, Sections 4.3-5, 6.2]. (2) Sampled softmax with a corrected logQ term [2507.09331] shows how to estimate a full-catalog softmax and its gradient from a few samples of a known proposal: terms that are present deterministically are computed exactly, and the rest is estimated with 1/Q weights. The paper also shows that mixing the two kinds of terms naively biases the estimate [2507.09331, Section 3.3]. (3) Inside attention, vAttention confirms the key condition at inference time: once the heavy blocks are covered, the residual attention mass is flat enough that a small random sample with inverse-rate rescaling estimates it well [2510.05688, Section 4.1]. Novelty type: recombination-of-distant-concepts (off-policy bandit learning from recommender systems carried over to sparse-attention selector training).
- **How it maps to this problem**: The selector (an NSA/MSA/SAS-style block scorer per GQA group) plays the recommender policy. The candidate KV blocks play the item catalog. Each query block's top-K selection plays the page of recommendations. The attention mass the main branch puts on a block, computable exactly only for blocks the sparse kernel actually visits, plays the reward. During sparse training, each query block keeps its usual top-K blocks and adds a small number of exploration blocks, sampled from the selector's own tempered distribution over the remaining blocks (mixed with a uniform floor so that every block has non-zero probability). The sparse kernel just receives a slightly longer block-index list, and the inclusion probability of each explored block is logged. The selector's target over all blocks is then formed in the sampled-softmax way: exact mass for the selected blocks, importance-weighted mass for the explored ones, and an importance-weighted estimate of the total off-support mass for normalization. Two choices are left to the report_writer. The first is whether explored blocks only feed the detached selector loss, which keeps the forward pass identical to inference and avoids routing absorption, or also enter the output as an unbiased estimate of the residual in vAttention's style. The second is whether the loss uses the top-K inclusion form, so that capacity goes to getting misses into the set rather than to matching mass within it.
- **Why it could work / feasibility**: The recommender mechanism needs three things, and all three hold here. (i) Feedback on an explored action has to be observable at the cost of taking that action. Here the exact attention mass of an explored block is a by-product of attending to it, and the block-sparse kernels of NSA/FSA/MSA already take arbitrary per-query-block index lists [2502.11089, 2508.18224, 2606.13392], so the extra cost is a few percent more blocks and no new kernel beyond a weight per entry in a fused KL kernel such as MSA's. (ii) Exploration probabilities have to be known and non-zero on every action. Here the trainer samples them itself, so propensities are exact and need not be estimated, which avoids the main variance source named in [1812.02353, Section 4.4]. (iii) The residual has to be estimable from a few samples. vAttention shows that after top-k the residual is flat enough for small-sample estimation [2510.05688], and a sequence has thousands of query blocks, layers and heads per step, so every block of a context gets sampled many times per batch even at one or two exploration slots each. The top-K inclusion multiplier of [1812.02353] matches the goal stated in this gap, recall on missed blocks. The key assumption: a block's usefulness is reflected in the main branch's attention mass on that block when it is explored, which is the same teacher signal MSA's KL and SAS's coverage analysis already rely on [2606.13392, 2609.13141].
- **Novelty vs. closest in-domain work**: SAS [2609.13141] is closest. Its sparse scope gives unselected blocks no signal of their own, and its only remedy is full scope with dense attention. MSA [2606.13392] restricts its KL to selected tokens after a dense warmup. vAttention [2510.05688] and kNN-attention [2411.04013] mix top-k with random sampling only to approximate attention or its gradients, with a fixed, untrained selector. None of these uses sampled off-support blocks with known propensities as an unbiased, sparse-only training signal for the selector.
- **Main risk**: Attention mass is heavy-tailed, so the blocks that matter most (a needle the selector ranks very low) get the smallest sampling probability and the largest, most variable importance weights. Capping or a uniform floor may then remove most of the signal on exactly those blocks. SAS also finds that sparse scope already catches up with full scope on reasoning benchmarks [2609.13141], so a gain may show only on long-context retrieval.


### C1 — Quorum-coverage eviction: keep each fact at "just enough" carrier heads, the way k-coverage sensor networks put redundant sensors to sleep

- **Intuition**: Treat the KV cache like a dense sensor network that must keep every "region" (a piece of information in the reasoning trace) watched by at least k sensors (copies in carrier heads). Evict a cached entry only when every piece of information it carries is still held by enough other copies, restated or in other heads, so the budget stops paying for copies above quorum and protects facts that are about to drop below it.
- **Gap it attacks**: Axis "KV cache and token pruning for standard softmax attention", gap 1 (per-token additive ranking vs set-level coverage). Current evictors give each entry, per head, its own scalar score (H2O, R-KV, LazyEviction, KVP, ForesightKV, DistillCache) or a diminishing-returns set score over positions (K-VEC, CORE). Neither form can express what the planted-fact probe measures: one carrier-head copy is almost worthless (3%), two or three are readable (60% / 83%), and more copies add little (99% with all eight) [2609.03430]. That is a threshold, not a sum and not a concave coverage curve. The concrete failure is the Challenge's long-CoT one. Restated intermediate results are over-held across heads and positions, while a once-stated value is dropped from each head independently until it falls below readable strength: 0% passcode retrieval for random eviction, 0.4% for SnapKV [2609.03430]. Closing it would let the budget be spent on how many distinct facts stay readable, which is the quantity that decides accuracy at 1-2K entries.
- **Source inspiration**: [0710.3918] (Controlled Greedy Sleep, k-coverage sensor scheduling). In dense sensor networks each region must stay covered by at least k awake sensors, and coverage above k "does not provide higher performance". The scheduler keeps a sensor–region incidence graph and gives each region a coverage ratio that is positive only when the region is over-covered. A sensor may sleep only if every region it covers stays over-covered (negative drowsiness means "not allowed to sleep"), and sensors are put to sleep greedily with recomputation after each one [full text, Section III.C, Eq 1-3]. Each node can run this from local information only (Section III.D). It works because the value of a sensor is defined by the coverage state of the regions it serves, not by its own reading. At matched lifetime, Randomized Independent Sleeping, where each sensor sleeps with a fixed probability, leaves only ~90% of the area 3-covered while CGS keeps all of it, and random needs many more awake sensors to approach CGS coverage (Section IV.B). Novelty type: recombination-of-distant-concepts (wireless-sensor coverage scheduling → KV eviction).
- **How it maps to this problem**: Sensors are cached entries, one per (layer, KV head, position). Regions are content units of the trace: a stated value or intermediate result, together with all the positions that restate it. The incidence edges say which entries hold a usable copy of which unit; only carrier heads count, because the probe shows only some heads hold a readable trace [2609.03430]. The coverage requirement k is a per-unit quorum of carrier-head copies, calibrated offline from a planted-fact curve like the one in [2609.03430] (the knee at 2-3 heads). Random Attention's independent per-head draw [2609.03430] plays the role of Randomized Independent Sleeping. At each eviction round the evictor recomputes how covered each unit is. Entries whose units are all over quorum (a restated reasoning step held in many heads and positions) are released first. An entry that is among the last k copies of a unit is pinned, which is how a once-stated passcode keeps exactly a quorum of carrier-head copies instead of all eight or none. Leftover budget can still go to an existing per-token score or to the random draw.
- **Why it could work / feasibility**: The mechanism needs two things: (i) value is a threshold in the number of covering copies, and (ii) the incidence between units and copies can be approximated cheaply. Condition (i) is measured directly in the planted-fact probe, where pooled retrieval jumps from 3% to 60% to 83% to 99% as carrier heads are added, and "the shape of the copies does not matter", so a count of copies is a usable coverage measure [2609.03430]. For (ii), CGS itself runs on a deliberately pessimistic, approximate incidence (squares instead of true sensing disks), and errors only make it keep extra sensors awake, not lose coverage [0710.3918]. Here a cheap pessimistic incidence also exists. Restatement is visible from token identity (the same number or variable) and from near-duplicate keys within a head, which is the signal R-KV's redundancy term already computes and the only signal that saved the passcode (84%) [2505.24133, 2609.03430]. The text-level restatement that makes random eviction work on MATH500 [2609.03430] is the over-coverage the scheduler can release. Engineering fits the constraints: the decision runs once per eviction round on per-head keep masks that existing per-head eviction code in vLLM / R-KV-style runtimes already applies, so it needs no new attention kernel. Key assumption: content units can be identified well enough that the scheduler rarely counts two copies of different facts as substitutes.
- **Novelty vs. closest in-domain work**: The closest is [2610.02235] CORE, which runs decode-time set-level coverage on AIME25 / Math500. Its log-determinant objective fuses all KV heads into one vector per position and is provably diminishing-returns only (cross derivative ≤ 0, Appendix B.4). It therefore cannot express "one copy worthless, k copies readable", and it chooses positions, not how many heads keep each fact. [2606.29563] K-VEC rewards positions kept in at least one head, which is 1-coverage of positions, not k-coverage of content. [2505.24133] R-KV is a pairwise per-token penalty within one head.
- **Main risk**: On real traces the text-level redundancy may already do most of the work (a shared draw is within 0.3 points of independent draws on MATH500 [2609.03430]), and the quorum curve is measured only on Qwen3-4B. Gains may then be limited to rare once-stated facts unless content units and carrier heads can be identified reliably across models.


### C3 — Reads count as use: least-recently-read retention for the linear-attention memory matrix

- **Intuition**: Let the memory matrix remember which of its key directions the model's own queries have been reading, and let forgetting and overwriting fall on the least-read directions instead of the oldest-written ones, the way the LRUA memory of memory-augmented networks counts every read as "use" and writes new content into the least-used slot. Retention then follows read demand, not write order.
- **Gap it attacks**: Axis "Memory matrix update rules in linear attention and fast-weight models", gap 1: every update rule (GDN, GDN-2, EDA, KDN, VLA, KLA) fixes how long an association survives at write time, from cumulative decay and gates of the current token [2501.12352, 2412.06464, 2605.22791]. Queries only read the state and never change it. So when more pairs are live than the state can hold, eviction follows write order: VLA "preferentially overwrites recently written directions" and drops to 0.044 MQAR at 1.5x capacity [2605.11196], and MK-NIAH-1 for GDN-2 falls from 72.6 to 37.8 between 1K and 4K [2605.22791]. MesaNet names the missing ability: an RNN must "anticipate when processing information which needs saving" [2506.05233]. Closing this would separate how much of the recall gap is the eviction policy and how much is raw capacity, and could let pure or lightly hybrid models hold the intermediate results that long chain-of-thought keeps re-reading.
- **Source inspiration**: Memory-augmented neural networks (meta-learning), *recombination-of-distant-concepts*. The LRUA module of [1605.06065] keeps a usage score per memory slot that is a decayed running sum of that slot's read weights plus its write weights. New content goes either into the slot just read (an update) or into the least-used slot, which is zeroed first, so "the least used memories simply get erased" [1605.06065, Section 3.2]. Because reads count toward usage, a memory survives because it was retrieved, not because it was recently written. The bet is temporal locality of reuse: what was read recently is "potentially useful" again. With everything else fixed, swapping the standard NTM access module for LRUA lifts 2nd-instance one-shot accuracy from 35.4% to 62.6% and 10th-instance from 88.4% to 95.3% [1605.06065, Table 2]. Cache replacement gives the same principle a target: the ideal policy evicts the item whose next use is furthest away (Belady), LRU-style use history is its causal proxy, and on a recorded trace the ideal is computable at training time, so a causal policy can be trained against it [2006.16239, Sections 2-4].
- **How it maps to this problem**: Memory slots become key directions of each head's state, at first the key channels that per-channel-decay rules (KDA, GDN-2) already treat as separately forgettable, later optionally a small learned subspace. The LRUA read weight becomes how strongly the current token's query points along each key direction, optionally weighted by how much the state actually returned for it (a "hit" vs. a read of empty memory). The usage score becomes a slowly decaying per-head trace of that read mass, carried next to the state. The update rule keeps its delta write. What changes is where forgetting and erasing pressure land: directions with high read usage are shielded from decay, and new writes are pushed to displace the least-read directions, mirroring LRUA's "write into the least-used slot". Writes alone give only a small initial usage, so a pair that is written and never read becomes the first candidate for eviction, whatever its age. The mapping from usage to retention is learned end-to-end. Because the future reads are known on a training sequence, a hindsight label ("is this direction read again before it is overwritten?") can additionally teach that mapping to anticipate, as Belady's labels do for learned caches [2006.16239].
- **Why it could work / feasibility**: The source relies on two conditions. (i) Past reads predict future reads. This holds on the target failures: long chain-of-thought revisits the same intermediate results, and multi-query recall re-asks earlier keys between distractor writes, which is exactly where write-order rules evict the queried pair. In LMs every token issues a query, so read history is dense rather than sparse. Learned caches show history is predictive up to a horizon (gains saturate at about 80 past accesses [2006.16239, Section 5.4]). (ii) Usage must be cheap to keep and act on. If usage is built from queries alone, it is a per-channel prefix scan that does not depend on the state, so the per-key-channel decay can be computed before the kernel runs and the existing flash-linear-attention chunk kernels for diagonal-decay delta rules run unchanged. The "hit-weighted" version can read the state once per chunk at the chunk boundary, the trick CARVE shows costs one small matmul per chunk with O(1/sqrt(L)) gate error and keeps the WY solver exact as long as gating stays on the key axis [2606.27229, Sections 4.2, 6.1, 6.3]. A protected-subspace version needs a transition whose low-rank direction is not the write key; RWKV-7's generalized delta rule already trains that diagonal-plus-low-rank class stably with parallel kernels [2503.14456, Section 4.1, Section 2]. Compute is not binding: ≤400M-1.3B pretraining against GDN/GDN-2/KDA in fla, plus MQAR with decoupled query order and RULER MK-NIAH, fits the H200 budget. Key assumption: when the state is overloaded, the pairs that will be queried are mostly ones that were already read, or that the learned usage-to-retention map can flag in advance.
- **Novelty vs. closest in-domain work**: CARVE [2606.27229] is closest: it conditions GDN-2's erase/write gates on what the current token's query reads from the chunk-boundary state, but that signal is recomputed for each token and nothing accumulates which associations past queries retrieved, so its retention is still decided at write time and its MK-NIAH-1 still falls from 76.8 to 41.4 between 1K and 4K. Here a persistent read-usage trace, not the current token, decides what is shielded and what is overwritten. GDN-2 [2605.22791], EDA [2606.26560] and KDN [2609.07816] gate from the current token or from write-side uncertainty only.
- **Main risk**: On benchmarks where the question appears once at the end (single-query NIAH), nothing reads the needle before it is asked, so read usage carries no signal there. The gain then rests on the learned or hindsight-trained anticipation, which end-to-end training of current gates may already approximate, and shielding read directions may crowd out new writes and cost perplexity.


### C6 — Forecast-targeted layer placement: keep full attention where it best stops drift on the hybrid's own rollouts, the way weather centers place sensors against forecast error
- **Intuition**: Treat each retained full-attention layer as an "observation" that re-reads the exact history and so corrects the drift of the lossy recurrent states. Place these observations the way ensemble weather forecasting places targeted sensors. Pick each layer by how much it would shrink the student-teacher divergence *later along the hybrid's own sampled reasoning trace* (forecast error), not by how much it shrinks the divergence at the current, teacher-forced position (analysis error). Re-sample the rollouts after each pick and stop adding layers when the gain levels off, so the budget K is also read off data.
- **Gap it attacks**: Axis "Hybrid architectures mixing full attention with linear or recurrent layers", gap 1. Every Transformer-to-hybrid selector scores a layer by a teacher-forced, off-policy quantity: one-swap KL on DCLM [2512.20569], passkey hidden-state alignment of a fixed prefill [2606.30562], KL+cost search at 4K [2605.20936], perplexity beam search [2603.26556], or MMLU leave-one-out [2511.02651]. The long-CoT failure comes from something else. A student error changes the prefix, the changed prefix changes every later recurrent state, and the deviation compounds. This shows up only on student-sampled trajectories (AIME'24 33.3 on-policy vs 17.1 off-policy [2609.31947]). Even so, the one on-policy method keeps a fixed every-fourth-layer allocation [2609.31947]. A layer that keeps the student's own long trace self-consistent can therefore be ranked low, and K stays hand-set. Closing this gap would give converted reasoning hybrids an allocation, and a ratio, chosen against the failure they are deployed to avoid. It would also show which layers carry long-horizon self-retrieval.
- **Source inspiration**: [2606.27267] (numerical weather prediction / ensemble Kalman filtering; recombination-of-distant-concepts). Conventional sparse sensor placement picks sites that minimize *analysis* error at assimilation time, and its D-optimal variant puts the first sensor at the peak of current error spread. This paper instead minimizes *forecast* error at a later lead time. It propagates each candidate's error reduction forward with a tangent-linear model approximated by an ensemble of the system's own forecasts. That surrogate is linearized around the no-new-sensor (background) trajectory, so a single propagated ensemble scores every candidate site, and greedy forward selection adds one site at a time [2606.27267, Sections 3.1, 3.5, 4.1]. The paper notes that minimizing analysis error suffices for forecast error only in linear systems, and that this equivalence breaks down in nonlinear ones [2606.27267, Section 1]. Empirically, forecast-targeted placement chooses sites away from the current-error peak and gives lower forecast RMSE. Analysis-targeted placement does worse "without accounting for the temporal evolution of forecast errors", and its selection order does not track post-hoc forecast impact (EFSO) [2606.27267, Sections 5.2-5.4]. A second source, DAgger [1011.0686], explains why the scoring states must come from the learner's own rollouts and must be re-collected. Under the expert's distribution, a per-step error epsilon can cost T^2 epsilon. Measured on the learner's own distribution, the cost decomposes into a sum over steps of the cost-to-go of a deviation, which is u T epsilon when deviations are recoverable (u = O(1)). Each new policy visits new states, so data must be aggregated iteratively [1011.0686, Theorems 2.1-2.2, Section 3].
- **How it maps to this problem**:
  - Each piece of the forecasting setup has a counterpart:
    - The dynamical system is the hybrid's own autoregressive decoding on reasoning prompts.
    - The "truth" is the original Transformer teacher.
    - A candidate sensor site is a layer that could be restored to full attention.
    - The "observation" is that layer reading the exact KV of the student's own prefix instead of its compressed state. The teacher's attention weights are kept, so this is one ordinary attention forward on the student's prefix.
    - Analysis error is what the current selectors measure: the divergence at the same position under teacher forcing.
    - Forecast error is the divergence some hundreds to thousands of tokens later along the same student rollout, and ultimately whether the final answer survives.
  - The ensemble is a batch of rollouts sampled from the current hybrid. It plays the role of the background trajectory: along these rollouts the method records, for each candidate layer, the correction it would apply, and how much those corrections at earlier steps account for the divergence that builds up later. Every candidate is scored from the same rollouts, as one propagated ensemble scores every site in [2606.27267].
  - After the best layer is added (and the hybrid is briefly re-fit), new rollouts are sampled, because the new hybrid drifts differently (DAgger's reason to re-collect [1011.0686]).
  - Layers stop being added once the next layer no longer reduces long-horizon divergence, i.e., once drift no longer compounds with trace length. That sets K.
  - Prior teacher-forced selectors correspond to placing sensors at the peak of current error.
- **Why it could work / feasibility**:
  - Why the transfer is plausible: the source mechanism needs (i) a system whose errors grow along its own trajectory, so analysis-optimal and forecast-optimal choices differ, and (ii) a cheap surrogate that propagates a candidate's effect from the current trajectory without re-running the system for every candidate. Condition (i) is shown for hybrids by [2609.31947]: off-policy-trained hybrids drift into degenerate long rollouts that teacher-forced KL does not see. [2603.26556] adds that perplexity and generation re-rank design choices. DAgger's bound says these per-step-equal but trajectory-unequal errors are exactly what distinguishes J under the two distributions [1011.0686].
  - Cost: (ii) holds because restoring a layer reuses frozen teacher weights, so a candidate's correction on a student prefix costs one attention forward. Rollouts use existing hybrid kernels (flash-linear-attention / vLLM), and no new kernel is needed. The search adds at most ~L/4 greedy rounds of batched rollouts for a ≤8B model, which fits comfortably on the 8×H200 budget next to the on-policy distillation that [2609.31947] already runs.
  - Key assumption: a layer's drift-reduction ranking, measured with the frozen teacher layer swapped into the current student, mostly survives the short re-fit that follows. This is the same assumption one-swap scoring makes after its brief re-distillation [2512.20569].
- **Novelty vs. closest in-domain work**: [2512.20569] also selects layers greedily, but it scores each by teacher-forced KL on generic text after a re-distillation and uses a hand-set K. [2609.31947] uses on-policy rollouts but only to train weights under a fixed 1:3 allocation. [2606.30562] optimizes joint gates on a teacher-forced passkey prefill. This idea makes the placement criterion itself forward-propagated, on-policy divergence, re-collected after each placement, with K set by when drift stops compounding. Recency searches (since 2025-10: "hybrid attention layer selection", "hybrid layer placement rollout", "distill reasoning model linear attention layer selection") found no on-policy allocation method.
- **Main risk**: Prolonged on-policy weight distillation may compensate for almost any reasonable allocation, so forecast-targeted placement could beat teacher-forced placement only before weight training and not after it. A second risk is that discrete token branching makes the ensemble's linear-sensitivity estimate of a layer's downstream effect too noisy; the source itself warns that its Gaussian/linear approximation degrades under strong nonlinearity [2606.27267, Section 6].


### C2 — The recurrent state as a credit line: borrow state precision to postpone irreversible KV commitment

- **Intuition**: In a hybrid, rounding the recurrent state is a loss the model repairs on its own, because later writes erase old state error within hundreds to a few thousand tokens. Demoting or evicting an attention-KV entry is permanent. So under one per-request byte budget, temporarily lower the state's precision to pay for keeping newly generated KV at full precision and uncommitted, until the model's own later attention shows which entries matter. Then commit the KV demotions in one informed batch and give the bytes back to the state. This is the "postpone, then commit and revise" structure of online knapsack with paid reservation and removal.
- **Gap it attacks**: Axis "Quantization and release timing of KV cache and recurrent state in hybrid models", gap 2: each method compresses one memory with the other held exact, and the precision split is fixed for the whole request. The concrete failure is about timing. Once decoding fills the budget, the stacked recipe has only one lever left: demote or evict KV on a fixed trigger. PM-KVQ shrinks bit-width when the block budget fills [2505.18610]. BreadthKV compresses every 128 steps behind a fixed 128-token fp16 window [2610.05685]. LazyEviction's window W is set offline [2506.15969]. Each trigger makes an irreversible decision about tokens just written, such as intermediate results, before any reuse evidence exists. A token that has not yet been re-read has no recurrence signal at all [2506.15969]. Meanwhile the state, which is about three quarters of a stored request at 4K-11K tokens [2610.36950], sits at a fixed precision that never responds to this pressure. Closing the gap would make the split depend on time and on evidence, and would give each memory its own release time: the state's bytes are lent and repaid, and KV bytes are committed only once informed.
- **Source inspiration**: Online algorithms, the knapsack problem with paid reservation and paid removal [2607.13955]. *Novelty type: recombination-of-distant-concepts.* Items arrive one by one and decisions are irrevocable. Without recourse no online algorithm has a bounded ratio, because a small item forces a commit-or-lose dilemma before the future is seen. Two paid recourses fix this. Reservation holds an item undecided at a cost proportional to its size. Removal revises a packed item at a proportional cost, but a removed item is gone for good. In the region where neither cost is extreme, the optimal algorithm blends the two. It reserves every arrival, "deliberately postponing commitment", until a commitment threshold is reached. That threshold drops as more reservation cost has been paid. It then packs greedily and revises by removal, while keeping the whole reserve packable at all times. Which regime applies is set entirely by the two prices: reserve-only when reservation is cheap, removal-only when it costs as much as the item, and the blend between [2607.13955, Sections 1-3, Algorithm 1, Theorem 1]. It works because the true bottleneck is irrevocability, and a cheap way to delay commitment turns a blind decision into an informed one.
- **How it maps to this problem**: The knapsack is the request's byte budget, counting both state and KV. Items are blocks of newly generated KV in the attention layers. "Pack" means committing a block to its long-term form, a low bit-width or eviction. "Remove" means a later further demotion or eviction of a committed block, which is permanent. "Reserve" means holding a new block at full precision, undecided. The reservation is not free: its bytes are borrowed by temporarily storing some state units (GDN heads or layers) at lower precision. Its price is the end-to-end loss per byte per step of that temporary state degradation. The price is low for heads whose errors are erased fast and for tasks that rely on retrieval, which the KV carries. It rises the longer the loan runs, because sustained low-bit rounding adds coherently. Each decode episode then follows the source's two phases. First, borrow and reserve until the reserve reaches a threshold that shrinks with how much has been borrowed. Then commit the reserved blocks in one batch, using the reuse evidence gathered meanwhile, with any existing scorer (cumulative attention, recurrence intervals). Finally, restore the state's precision. The split between the two memories thus moves within each episode and drifts with length. Early in a trace the state's bytes are a large credit line relative to the KV. Late in a trace they are small, so commitment comes sooner. The source's regime result becomes a testable prediction: the prices differ by layer type (fast-erasing GDN vs decay-only Mamba-2) and by task (retrieval vs aggregation and reasoning), so some (model, task) pairs should favour pure KV revision and others the blend.
- **Why it could work / feasibility**: The transfer needs three conditions, and the literature supports each.
  - (i) One memory's losses are temporary. In a GDN hybrid, a one-off state impulse falls to 1/e within 80-1,382 steps, against decay-implied horizons of 44K-62K, because "old errors are deleted key by key" [2609.04098]. Removing delta feedback raises output error 18.65-26.82x [2609.38169]. So a state that has been rounded and then restored heals, while a rounded KV entry never does.
  - (ii) Waiting yields information that commitment needs. Over 95% of reasoning tokens recur after a period of low attention. H2O and TOVA lose about 20% on GSM8K because tokens needed later fall outside the top set at earlier steps [2506.15969]. Importance is "persistent but not static" [2608.05326].
  - (iii) Borrowing has a moderate, task-dependent price. Zeroing every linear state moves NIAH by ≤1 point, because the attention KV carries retrieval, while states matter for multi-key, aggregation and reasoning [2608.30386]. Sustained 4-bit rounding compounds coherently [2610.15709], which caps how long a loan can run without hurting.

  Reusable parts: 4-8-bit state formats with per-window rounding already exist [2609.38166, 2610.29545], and BreadthKV's KIVI-format mix of fp16 and b-bit blocks already exists [2610.05685]. So the method needs no new attention kernel. It needs a per-head state-precision switch, which is modest Triton work, plus host-side budget logic. Compute is not binding: calibrating the two prices on public GDN hybrids up to tens of billions of parameters fits the H200 budget. Key assumption: at the budgets that matter (the 1-4K-entry regime of the Challenge, and short-to-mid lengths where the state is a large share of a request), the cost of a few hundred tokens of degraded state is smaller than what better-informed KV commitment gains.
- **Novelty vs. closest in-domain work**: DCKV [2610.36950] counts the state as most of a hybrid request's memory, but it keeps the state exact and codes the KV once after prefill. PM-KVQ [2505.18610] and BreadthKV [2610.05685] change KV precision over decode time, but only in dense models, on a memory-fill or fixed-period trigger, and they commit at once. Here the state's precision becomes an elastic reservation that pays for deferring irreversible KV commitment, and the prices of the two memories' losses set the length of the deferral and the split. A recency search turned up no method that moves bytes between a hybrid's two memories during decoding.
- **Main risk**: Waiting a few hundred tokens may buy little evidence, since attention-derived reuse predictors are weak (0.08-0.20 precision [2610.02713]) and many reuses come thousands of tokens later. Meanwhile GDN reasoning quality may be sensitive enough to state precision that the loan costs more than the deferral earns.


### C8 — Noah's Ark eviction: spend the KV budget to maximize the expected information that survives, valuing a fact by how irreplaceable it is
- **Intuition**: Treat the KV cache like a conservation budget spent on a family tree of facts. A fact counts as kept if at least one of its statements stays readable, readability grows with how much of that statement's token-head mass survives at carrier heads, and each fact is weighted by how much new information it introduced. Each eviction then removes the entry whose loss costs the least expected surviving information. Restated facts become cheap to thin out, a once-stated, information-heavy fact becomes the costliest thing in the cache to lose, and filler goes first when the budget cannot hold everything.
- **Gap it attacks**: Axis "KV cache and token pruning for standard softmax attention", gap 1: decoding-time eviction for long CoT ranks each cached entry per head with an independent additive scalar, while retention value depends on the whole retained set. The concrete failure is the once-stated value needed much later. A passcode stated once, 57 compression rounds before the question, is retrieved 0% by Random Attention and 0.4-34% by SnapKV, TriAttention and VaSE. Only R-KV reaches 84%, and the probe paper credits that plausibly to its key-dissimilarity term [2609.03430, 2505.24133]. On aggregate benchmarks random draws already match every scorer, because the text restates most content [2609.03430]. So the only headroom is a rule that knows which content is *not* restated and is worth keeping, and that spends no budget re-protecting what is restated. Closing this would turn the residual passcode-type failure into a budget decision instead of a side effect of a redundancy heuristic, at the 1-2K budgets of the Challenge.
- **If improving prior candidate**: C1 (quorum coverage from k-coverage sensor scheduling) assumed a surplus: every unit could be held at quorum, and only extra copies were removed. At 1-2K budgets most units must sit below quorum, so C1 still needed a per-unit value ranking. It also counted whole copies, while [2609.03430] shows that retained token-head mass is what matters. And its unit detector was R-KV's near-duplicate-key signal. This version changes all three. (i) The objective is a budgeted, partial one: expected surviving information under a fixed budget, the Noah's Ark Problem, with a unit-value term built in. It has no quorum and no surplus assumption. (ii) A statement's survival is a graded readability that rises with retained token-head mass at carrier heads, not a count of copies. (iii) Units come from what the model itself does at write time: surprise marks new information, and retrieval-head copy events mark restatements. Neither is a key-similarity signal. C1's core insight is kept: a copy's value depends on which other copies survive.
- **Source inspiration**: Phylogenetic conservation prioritization (novelty type: recombination-of-distant-concepts). In the Noah's Ark Problem, a limited budget raises the survival probabilities of chosen species, and the objective is expected phylogenetic diversity. A branch of the tree of life survives if at least one species below it survives, so close relatives insure each other, while a lineage with one surviving species is lost with it [0805.1661, Section 1.2]. Utility values of species can be folded into branch lengths [0805.1661, Section 1.2]. The objective is budgeted, partial and set-level by construction. It is NP-hard in general, but greedy solutions are exact for unit-cost special cases, and a clade dynamic program handles small tree heights [0805.1661, Sections 1.3, 2]. The "Hedging our bets" index makes the per-species consequence explicit and cheap. A species' expected contribution sums its ancestral branches, each discounted by the chance that all its relatives under that branch go extinct anyway. An isolated or poorly insured lineage (the Aye-Aye) ranks first, while species whose relatives are safe drop sharply in rank. A companion score, the survival-weighted contribution, is meant precisely for "actions that might cause extinction" [0704.2649, Sections II, III.1, IV, IV.1, Theorem III.1, IV.1]. It works because value is measured against the *likely surviving set*, not per species in isolation.
- **How it maps to this problem**:
  - The mapping, piece by piece:
    - A *species* is one statement of a content unit at some positions of the trace.
    - A *branch* is the information that a unit introduces. All restatements of a unit hang under the same branch, so the unit survives if any statement stays readable.
    - *Spending budget* on a species means keeping head-entries of that statement.
    - Its *survival probability* is how readable the statement remains, as a function of its retained token-head mass. The mass is weighted toward each model's carrier heads.
  - *Branch length* (the unit's value) is the surprise the model registered when the unit was first written: how unpredictable its tokens were from everything before them. EM-LLM uses the same signal to mark new events [2407.09450]. A copied restatement is predictable, so it adds almost no length of its own.
  - *Tree edges* (which statements restate which unit) come from copy events seen at write time. A retrieval head's top-attended position holds the same token the model is now emitting, which is exactly the copy-paste criterion used to detect retrieval heads [2404.15574]. The same offline detection names each model's carrier heads.
  - At every compression round the evictor scores each entry by the expected surviving information lost if it goes. That is the readability the entry's statement would lose, times the statement's insurance-discounted contribution. It then evicts the cheapest entries greedily and recomputes, and the fact that remains of a statement or unit grows more expensive as its relatives disappear.
  - Restated steps, the ones random eviction already handles, are cheap to thin, because their relatives insure them. A once-stated, high-surprise value keeps the mass that makes it readable: past the readability knee extra heads add little, so it is not pinned in all eight heads. Low-surprise once-stated prose is what the budget gives up first.
  - Non-carrier heads can keep Random Attention's uniform draw, the strongest known aggregate baseline [2609.03430].
- **Why it could work / feasibility**:
  - Why the transfer is plausible: the source mechanism needs three things. (i) The value of a holding depends on whether substitutes survive. (ii) Protection buys graded survival under a hard budget. (iii) Shared versus unique information can be read off a tree.
  - (i) holds in KV caches: on real traces, text restatement carries the load, and a shared random draw is within 0.3 points of independent draws on MATH500 [2609.03430].
  - (ii) holds as well: retrieval depends on retained mass of the fact's tokens across heads, not on intact copies. Dealing a fact token by token across heads, so that no head holds a readable span, gives 0.33 against 0.39 retrieval at equal mass, and graded recall pools mildly superadditively across heads (0.31 against 0.10 and 0.16) [2609.03430]. So a monotone readability-versus-mass curve, calibrated per model with the planted-fact probe, is a faithful "survival probability".
  - (iii) is plausible because chain-of-thought depends on retrieval heads that copy earlier information forward [2404.15574], so restatements leave copy events that can be recorded at the moment they are written. Surprise is a recognized proxy for new, boundary-worthy content [2407.09450].
  - Computation: the tree is shallow (unit → statements), and the eviction step is unit-cost. That is the regime where greedy is exact or near-exact [0805.1661], and the insurance-discounted contribution has a closed form [0704.2649].
  - Cost: surprise comes free from the sampling logits. Copy events need an argmax over at most about 2K retained keys for a handful of retrieval heads per step. Decisions run once per compression buffer, as in R-KV, and are applied as per-head keep masks, so no new attention kernel is needed. At most a small Triton op for the copy-event argmax.
  - Key assumption: write-time surprise plus copy events identify the units that are later needed well enough that their value ordering beats a uniform draw.
- **Novelty vs. closest in-domain work**: [2505.24133] R-KV values an entry by a per-head pairwise key-dissimilarity penalty added to attention, with no notion of a unit surviving elsewhere. [2610.02235] CORE is set-level but chooses positions under a diminishing-returns log-det over fused heads, with no unit value or readability-in-mass. [2609.22158] StepKV values units (agent steps) by textual overlap, then globally ranks tokens additively; there, reuse *raises* a step's score instead of making its copies substitutes. [2609.03430] Appendix H only suggests reserving a few slots per head for an unspecified content signal. [2407.09450] EM-LLM uses surprise to segment but keeps every entry and retrieves, never evicting under a budget. Recency searches since 2025-10 ("surprisal KV cache eviction", "copy attention KV cache eviction reasoning", "retrieval heads KV cache eviction decoding", "budgeted coverage KV cache reasoning") found no evictor that maximizes expected surviving unit information.
- **Main risk**: Write-time surprise may undervalue intermediate results the model computed itself. They look predictable when written, but they become irreplaceable once their operands are evicted. Paraphrased restatements may also leave few literal copy events. Either way the tree degrades to a near-star with noisy branch lengths, and the gain shrinks to synthetic passcodes.


### C7 — Content-selected checkpoint slices: learning-to-search for which value channels a hybrid's prefix-cache checkpoint keeps

- **Intuition**: When a hybrid model stores a recurrent-state checkpoint for prefix caching, keep only the quarter of each head's value channels whose current content would be lost and still read later, choosing them anew at every checkpoint from what is actually stored. Train the chooser the way learning-to-search trains structured predictors whose actions cannot be undone: roll in with the chooser itself so each checkpoint already lacks what earlier choices threw away, then price each choice by rolling the resumed trajectory forward.
- **Gap it attacks**: Axis "Pruning and compression of variant attention mechanisms", gap 1: state capacity is allocated by one offline, input-independent unit mask, while the units a gated layer uses move with the content. The deployment where this binds inside the run's scope is the hybrid prefix cache. A state checkpoint is about 1,500x the KV of one token in Qwen3.5-4B [2609.33477], and once the attention KV is coded, the state is about three quarters of a stored request at 4K-11K tokens [2610.36950]. The only state-pruning method for these checkpoints, DASC, uses a static decay-horizon mask. On head-wise GDN (Qwen3-Next) it reaches only 1.10-2.49x checkpoint compression, because every value channel of a head shares the head's decay, and its horizon correlates only 0.44-0.63 with the observed state magnitude [2608.30386]. The no-state alternatives, Tail-Replay and SuffixReplay, rebuild the state from a short replay. They lose quality exactly where content outlives the replay window: OLMo-Hybrid-7B keeps 92.8% of LongBench and 91.4% of RULER, and SuffixReplay "does not directly apply to recurrences that preserve all past contributions" [2608.30310, 2609.33477]. The state matters in these hybrids: zeroing it drops Qwen3.6-27B RULER from 0.987 to 0.299 [2608.30310]. Closing the gap means checkpoints at 25% or less of state bytes that keep the old content replay cannot rebuild.
- **If improving prior candidate**: C5's four flaws are fixed. (1) Teacher: C5 imitated the same-window oracle of [2607.11796], which only masks reads of a fully stored state. C7's teacher is an irreversible-eviction cost-to-go on the pruned trajectory: a dropped channel loses its past for good, and the price of dropping it is measured after resuming from the pruned checkpoint. Belady-style optimality is no longer claimed, since it needs a backing store [2006.16239]. (2) The cache-miss / admission framing is gone. Writes are dense, so the action is simply top-r re-selection at each checkpoint along a chained trajectory. (3) Units: for delta-rule layers (GDN, KDA), units are value channels instead of key channels, which removes the coupling. For diagonal and scalar-decay layers, the modes of [2607.11796] remain usable. (4) Payoff: hybrid prefix-cache checkpoint bytes at budgets of 25% or less, where DASC's head-wise static mask cannot go on GDN.
- **Source inspiration**: Learning to search for structured prediction (AggreVaTe [1406.5979], LOLS [1502.02206]); novelty type *recombination-of-distant-concepts*. These methods train a policy whose actions are irreversible and whose cost appears only later. AggreVaTe runs the current learner up to a random time, tries an action, lets an expert finish, and trains on the observed cost-to-go instead of copying the expert's action. This teaches it to avoid actions after which a large future cost is unavoidable [1406.5979, Sections 2.2-2.4]. Its stated failure is the case where the expert is much better than any learnable policy, which makes the expert's cost-to-go over-optimistic [1406.5979, Section 2.5]. LOLS fixes this. It rolls in with the learned policy and rolls out with a mixture of reference and learner. Its guarantee holds without any assumption on the reference's quality and includes local optimality (no single changed decision helps). It also proves that the two shortcuts fail: rolling in with the reference never shows the learner its own mistakes, and rolling out with a suboptimal reference blinds it to compounding errors [1502.02206, Section 3.1 Theorems 1-2, Section 3.2 Theorem 3]. With a bad reference, learned roll-out cut the loss from 1.670 to 0.316 [1502.02206, Section 5].
- **How it maps to this problem**: A search trajectory is one request's chain of checkpoints, for example successive turns of a dialogue or an agent run. Each checkpoint is stored pruned, the next segment resumes from it, and the next checkpoint is cut from that resumed state. The action at a checkpoint is which r value channels of each head to store. The rest are dropped, then zero-filled or rebuilt by a short replay on load. Roll-in is the learned chooser on all earlier checkpoints, so the state it faces already lacks what earlier choices destroyed. A roll-out prices one deviating choice by resuming the model from it, continuing with the reference or the learner, and measuring divergence from the unpruned model. Within one layer, this price can be computed without any search. In a delta-rule layer, the transition acts only on the key side of the state, and the output reads each value channel separately [2608.30386, Section 3.1; 2608.30310, Eq 1]. So each value channel evolves independently of the others, and readout errors from different channels simply add up. The cost of dropping a channel is the part of its content that the replay window cannot rebuild, carried forward by the coming transitions and read by the coming queries. One "future-read weighting" per head scores all of that head's channels. The reference policy is the greedy, future-aware version of this score, which is myopic, so roll-outs also mix in the learner. The deployable chooser sees only what is known when the checkpoint is written: each channel's exact stored content, its old-versus-recent split, the static decay, and a summary of recent queries that stands in for the unknown future reads. Its first rung is a fixed calibration estimate of the future-read weighting applied to the exact content, which is already input-adaptive. The learned rung predicts per-request corrections.
- **Why it could work / feasibility**: (i) LOLS needs only that roll-outs can be run from any state the roll-in reaches and their loss observed, with no claim that the reference is optimal [1502.02206, Section 3.2]. Here a roll-out is one resumed forward pass on fixed text, and the in-layer part is closed form, so cost labels are cheap on the H200 budget. (ii) The value-channel unit avoids the coupling that breaks per-unit ranking for key channels. The delta-rule error transition mixes key directions [2609.38169, Section 3.1 Prop 1], but it never mixes value channels. (iii) There is real content-dependent signal for a causal chooser. Migration in [2607.11796] is carried mostly by the write map, which decides what gets stored, and is observed exactly at checkpoint time, rather than by the decay [2607.11796, Section 4.2]. DASC's static ranking tracks the observed state magnitude only weakly [2608.30386]. (iv) There is headroom above the replay-only methods, in the old content they lose on long-memory models [2608.30310, 2609.33477]. (v) Engineering is light. The live forward pass and the fla kernels are untouched. Storing is a per-head gather of r channels into DASC-style ragged buffers. Loading is a scatter, plus optionally DASC-wr or Tail-Replay's existing replay path [2608.30386, 2608.30310]. Key assumption: the irreversible oracle's headroom over static masks at 25% is large. It is bounded above by the read-mask headroom of [2607.11796] and has not been measured. A Mamba-1 pilot can measure it cheaply, because the per-mode instrument there separates retained content from new writes.
- **Novelty vs. closest in-domain work**: DASC [2608.30386] is closest. It uses a static weight-derived mask over heads (GDN) or coupled key channels (KDA) and does not re-select per checkpoint. C7 selects value channels per checkpoint from stored content and trains the selection on the pruned, resumed trajectory. Tail-Replay and SuffixReplay [2608.30310, 2609.33477] store no state at all, and C7 stores exactly the residual their replay misses. [2607.11796] defines only a read-mask oracle and mask-ahead schedulers.
- **Main risk**: Within a head, trained GDN value channels may hold similar amounts of old content. Short replay may already rebuild most of what queries read in Qwen-class hybrids (which keep over 99% under SuffixReplay [2609.33477]). In either case, a content-selected 25% slice beats a static slice plus replay only on long-memory models such as OLMo-Hybrid or KDA, and only by a few points.


### C11 — Diagnose, don't search: spend full-attention layers on the minimal repair sets of the failures that on-policy distillation leaves behind
- **Intuition**: Treat each long-CoT failure that survives on-policy distillation as a failing test case, and diagnose it the way software and model-based diagnosis isolate faults. On the student's own prefix, find the smallest set of linear layers that must be switched back to exact attention for the student to agree with the teacher again at the point where the trace went wrong. Then give the full-attention budget to the layers that complete the most of these minimal repair sets, alternating with more on-policy distillation. Stop adding layers once the remaining failures have no small repair set, because those are errors that exact recall does not fix.
- **Gap it attacks**: Axis "Hybrid architectures mixing full attention with linear or recurrent layers", gap 1, with the reviewer's correction. The selectors that already use the hybrid's own outputs, PostNAS beam search [2508.15884] and DtR greedy replacement with a tolerance stop [2601.11667], reduce each candidate placement to one task score on short few-shot tasks, measured before any on-policy weight training. For long CoT that score fails in three concrete ways. (1) It is one bit per trace of 10K+ tokens. At 500 examples, the binomial 95% half-width is already about ±4.2 pp [2606.27791, Appendix A.4], and AIME has 30 problems, so placement differences of a few points sit inside the noise. (2) It cannot tell a failure that exact recall would fix from one that on-policy distillation fixes anyway. Opal's on-policy reverse KL recovers far more than off-policy training at the same allocation (AIME'24 33.3 vs 17.1 [2609.31947]), so a pre-distillation score spends budget on errors that weight training would remove. This was C6's own main risk. (3) It sees layer interactions only through whole-task greedy steps [2601.11667, Section 4.3], and teacher-forced single-layer toggles miss them entirely [2606.27791, 2512.20569]. Closing the gap would give converted reasoning hybrids an allocation aimed at the failures that remain after the training they will actually get, and a K justified by the kind of error left over rather than by a tolerance on a noisy score.
- **If improving prior candidate**: C6. Weaknesses addressed: (a) "outcome on own output + greedy + data-driven K" was already taken by PostNAS/DtR. The selector now sees what an end-task score cannot: where on the student's own trace each residual failure happens, whether exact attention repairs it at all, and which smallest layer combination does. K is set by the type of residual error, not by an accuracy tolerance. (b) The un-adapted one-swap assumption that [2512.20569] and [2511.02651] contradict is replaced. Every layer keeps a swappable exact path trained throughout (PostNAS's once-for-all path sampling [2508.15884]), and the diagnosis is redone after every distillation round, so rankings that shift after short training [2511.02651, Figure 2] are re-measured rather than assumed stable. (c) The unspecified forecast-ensemble surrogate is dropped. Each check is an explicit forward pass with a chosen subset switched to exact attention, and the subset search has a known, logarithmic number of checks. Kept from C6: the long-CoT target, on-policy rollouts, and re-collection after each placement (DAgger's reason [1011.0686]).
- **Source inspiration**: Two sources from software engineering and AI diagnosis; the novelty type is recombination-of-distant-concepts.
  - Delta debugging [2408.04735]. Given a failing input as a list of elements and a test predicate, ddmin tests subsets and complements and halves the granularity, ending with a 1-minimal set: removing any single element loses the property. ProbDD keeps a per-element probability of being essential and tries first the deletions most likely to succeed, avoiding ddmin's low-yield queries [2408.04735, Sections II-A, II-B, IV-F]. It works because a failure usually depends on a few elements, so most of the list can be eliminated with few tests. The guarantee is only local (1-minimal), and skipping revisits can leave results slightly non-minimal [Section IV-G].
  - Model-based diagnosis, FastDiag [2102.09005]. When a system is inconsistent with its specification, a minimal diagnosis is a smallest set of components whose removal restores consistency; minimal diagnoses are the minimal hitting sets of the minimal conflicts [2102.09005, Section 3]. FastDiag finds one preferred minimal diagnosis directly by divide and conquer, using only consistency checks. The number of checks grows with the logarithm of the number of components, about 2d·log2(n/d)+2d for a diagnosis of size d among n. A preference order picks among equally minimal diagnoses, and repeated calls enumerate more [Sections 4-5].
- **How it maps to this problem**:
  - The system under diagnosis is the current hybrid after its latest round of on-policy distillation. Its components are the layers that are currently linear. "Removing a component" means switching that layer back to its exact full-attention path. The specification is the teacher.
  - A failing test case is a failure event on the student's own rollout. It is a position where the teacher, reading the same student-generated prefix, sharply disagrees with the student's next-token distribution. On-policy distillation already computes the teacher's per-token log-probs on these rollouts [2609.31947], so events come for free. Only events on traces that end wrong are kept, preferring the first sharp disagreement on each trace, since later ones are consequences of an already-corrupted prefix.
  - A consistency check is one forward pass of the hybrid on that same prefix with a candidate subset of layers switched to exact attention. It passes if the student's prediction at the event returns close to the teacher's. All events of one trace are checked in the same pass.
  - The minimal diagnosis of an event is its minimal repair set: the smallest layer subset that brings the event back. A preference order (for example, layers already full or cheaper to keep) breaks ties among equally small sets. An event that only the full teacher repairs, or whose repair set is large, is marked as a non-recall error and left to weight training.
  - Allocation: add the layer, or small group, that completes the repair sets of the most residual events. Continue on-policy distillation, sample fresh rollouts from the new hybrid, and diagnose again. Layers are chosen against what distillation could not fix, and distillation then works on the new allocation.
  - Stopping: stop when most residual failures no longer have a small repair set. That sets K from the type of the remaining errors.
  - Contrast with prior selectors: PostNAS/DtR score whole placements by one task number; teacher-forced selectors score single layers on reference text. This method scores layers by the per-failure minimal sets that need them, on the student's own traces, after training.
- **Why it could work / feasibility**:
  - The diagnosis mechanism needs three things: a check that is cheap and nearly deterministic, failures that depend on few components, and components that can be removed independently without re-fitting. All three plausibly hold here.
  - Cheap check: a check is a forward pass on a fixed prefix, with no sampling, so it is deterministic as FastDiag and ddmin assume. It runs on existing kernels: flash-linear-attention for linear layers and FlashAttention or vLLM for exact ones. No new kernel is needed.
  - Few components per failure: [2606.27791, Sections 4.4-4.6] finds that the long-range-specific layer signal concentrates in a stable core of a few layers, so small repair sets are plausible.
  - Swapping without re-fit: PostNAS's once-for-all network trains linear and full paths by random path sampling, so any subset can be extracted and scored directly [2508.15884, Section 2.2]. DtR shows that blockwise-distilled drop-in linear blocks can be mixed in any subset with forward passes only [2601.11667, Sections 3.1-3.2]. Keeping path sampling during on-policy distillation preserves that property after training.
  - Cost: for about 27 linear layers and repair sets of 1-2 layers, FastDiag needs on the order of 20 forward passes per failed trace [2102.09005, Section 5]. A few thousand failed traces then add prefill-only work that is small next to Opal's 2B-token on-policy run [2609.31947]. This fits the 8×H200 budget.
  - Key assumption: the failures that persist after on-policy distillation are dominated by localized lost-recall events. It must also hold that repairing the first such event usually changes whether the trace succeeds, so repair-set counts track end accuracy.
- **Novelty vs. closest in-domain work**:
  - PostNAS [2508.15884] and DtR [2601.11667] search placements by one end-task score per configuration on short tasks, before any on-policy training, with K fixed or set by an accuracy tolerance.
  - This method allocates from minimal repair sets of individual residual failures on the student's own long-CoT traces, interleaved with on-policy distillation, and stops by failure type.
  - Also distinct from single-layer answer-NLL toggles on reference answers [2606.27791], teacher-forced KL selection [2512.20569], and Opal's fixed allocation [2609.31947].
  - Recency searches since 2025-10 ("delta debugging neural network layers", "failure-driven layer selection hybrid attention", "which layers need full attention reasoning errors", "hybrid attention placement residual errors distillation") found no diagnosis-based or residual-failure-based allocation.
- **Main risk**: The residual long-CoT failures may come from diffuse drift spread over many positions, not from a few lost-recall events. Then minimal repair sets would be large or unstable across events, and repairing a local event would not change the final answer, so the method would collapse into ranking layers by on-policy KL spikes.


### C10 — Survey the selector's misses like a rare, clustered species: adaptive-cluster exploration for native sparse-attention training

- **Intuition**: In native long-context sparse training, the places where the selector misses a relevant block are rare (a few query positions) and clustered (nearby queries and nearby key blocks miss together). That is the population ecologists survey with adaptive cluster sampling. Spend a thin screen of exploration blocks on every query, and when an explored block beats the weakest selected block, also probe its neighbours, so the off-support budget lands where the misses are and known inclusion probabilities keep the selector's training target unbiased. Uniform dense rows and short-length dense teachers do not do this.
- **Gap it attacks**: Axis "Hardware-efficient training and inference algorithms for linear and sparse attention", gap 2 (selector trained only on its own support), restricted to the regime where the cheap exact alternatives do not exist. Production learned sparse attention (DSA in GLM-5.1, CSA in DeepSeek-V4, QSA, MSA) trains natively at 256K-1M tokens with k = 2048 kept entries (0.2% at 1M). Its indexer loss is a detached KL "only through the k selected scores", and no dense teacher appears in that stage [2610.32057, Section 2.1 Eq 3, Section 2.3]. MSA likewise restricts its KL to selected tokens after a dense warmup [2606.13392]. The backbone keeps co-adapting for the whole sparse stage, which is routing absorption [2603.02227], so a blocks-missed error made at 500K is never seen by any teacher. Closing this would let selector recall keep improving during the long native sparse stage that frontier models actually run, rather than only in a short dense warmup.
- **If improving prior candidate**: C4. The reviewer's verdict was revise(focus=novelty): exact off-support signal is cheap from a short dense teacher [2606.22874] or dense rows on sampled queries, and SAS [2609.13141] blames selector capacity. What changed:
  - **(a) Regime, stated plainly, including where C4/C10 lose.**
    - Frozen-backbone plug-in selectors (SpotAttention, LISA): the short dense teacher wins and C10 does not apply [2606.22874, 2607.19358].
    - Sparse-rollout / dense-training RL: dense log-probs are already computed and reused nearly free [2606.08446, Section 4.5, Appendix D], so C10 does not apply there either.
    - Where C10 does apply: native sparse long-context training with a co-adapting backbone. There a short teacher is stale, and SpotAttention's no-decay result was measured on a frozen backbone at K = 0.5L, not at 0.2% budgets [2606.22874 digest].
  - **(b) Equal-FLOP case against dense rows.** At equal FLOPs, dense rows are a non-adaptive cluster sample whose cluster is a whole query row. At 1M tokens with 64-token blocks and two exploration slots per query block, the same FLOPs buy dense rows for about 1 query block in 8,000. Selector errors are concentrated on a small tail of query tokens (most tokens match dense to >0.999 [2606.08446, Section 3.1]), so almost every sampled row lands on a query with nothing to correct, and almost every entry of that row is a confident negative.
  - **(c) A different target.** The "hit" test compares an explored block's exact attention mass with the weakest selected block's mass for the same query. The softmax normalizer is shared, so this comparison is exact and needs no normalizer estimate. This removes OpenAttention's normalizer-variance objection [2610.30951, Appendix A.2]. Because the target is top-K set membership, not a full-support distribution, it also avoids the DenseKL "razor-sharp" miscalibration [2606.22874, Section 5.2].
  - **(d) Positioning** against Default MoE / SparseMixer and against SAS, below.
- **Source inspiration**: Adaptive cluster sampling from survey statistics and ecology (recombination-of-distant-concepts).
  - **ACS** [1304.2460]: draw an initial random sample. Whenever a unit meets a condition (a "hit"), add its whole neighbourhood, and repeat for newly added hits. This beats simple random sampling exactly when the population's variation sits inside patches. The relative variance is (m/n1)(N-n1)/(N-m)·[1 - within-network SS / total SS]. Gains reach about 2x for tight, rare clusters but fall to 20-50% for diffuse ones and shrink as hits become common [Sections 4-6].
  - **PoSA / CPoSA** [2004.02708] makes this practical under a fixed budget. Units are visited in a 1-D order, and a detected positive forces inclusion of its neighbour. Every inclusion probability is tracked, so a Horvitz-Thompson estimate stays exactly unbiased. CPoSA steers extra draws only to adaptively found positives while holding a target size. The gain is in detection per unit cost, which grows with clustering. The price is a noisier estimate of the overall mean [Sections 3-5].
- **How it maps to this problem**:
  - **Population and hits.** The population is the grid of (query block, KV block) pairs in a layer. A "positive" is a selector miss: a block outside the selected set whose exact attention mass exceeds that of the weakest selected block.
  - **Initial sample.** This is C4's exploration slots: a few extra blocks per query block, drawn with logged probability from the indexer's own scores (which native systems already compute for every entry [2610.32057]) plus a uniform floor.
  - **Neighbourhood.** When a slot hits, the neighbourhood is probed: the adjacent KV blocks for the same query, and the same block for adjacent query blocks. A probe needs only main-branch logits for the selector's detached loss, not a new forward output.
  - **Budget and weights.** As in CPoSA, the per-step budget is held fixed by lowering the initial screening rate. Every probed pair carries its inclusion probability, so the selector's pairwise set-membership loss is a design-unbiased estimate of the full-grid loss.
  - **Report_writer's choices**: whether the weights are used for unbiasedness or traded for detection, as in PoSA; the neighbourhood shape; and whether explored blocks also enter the forward pass to counter routing absorption.
- **Why it could work / feasibility**:
  - **ACS needs positives that are rare and patchy** [1304.2460, Section 7], and both conditions have in-domain support.
    - *Rare over queries.* Sparse-attention mismatch sits in a small lower tail of tokens [2606.08446, Section 3.1]. This was measured with heuristic block top-k selection, not a trained indexer.
    - *Clustered over queries.* Adjacent queries share 71% of their top-2048 keys in GLM-5.1 [2610.32057, Section 3.4.2], so a miss at one query predicts a miss at its neighbour.
    - *Clustered over keys.* Attention scores show blockwise clustering over adjacent keys [2502.11089, Section 6.2]. A selection's misses sit just past its rank boundary rather than scattered across the context [2610.22985, Section 3]; this was measured across layers, not for a trained indexer.
  - **Kernels.** The block-sparse kernels already take arbitrary per-query index lists [2502.11089, 2606.13392]. HyScale-style selection replay stores indices, so screen and neighbourhood indices are just more stored entries. That means modest Triton work for a logits-only gather and a weighted pairwise loss, and no new attention kernel.
  - **Compute.** Native sparse pretraining of ≤1-3B models at 64K-256K fits the 8×H200 budget.
  - **Key assumption**: under co-adaptation, a trained indexer's misses stay rare and clustered rather than becoming common or diffuse.
- **Novelty vs. closest in-domain work**:
  - **DSA-style indexer KL** [2610.32057, 2606.13392] and **SAS** [2609.13141]: no signal off the selected support in the sparse stage. SAS's capacity diagnosis is complementary, not competing. A richer block summary still needs training examples on exactly the blocks it loses, and C10's hits supply them. Hits that keep recurring on the same blocks after training mark where capacity is binding.
  - **LISA** [2607.19358]: its candidate-set dropout randomizes near-top candidates for regularization and logs no feedback.
  - **Prism** [2610.22985]: a deterministic expanded pool, at inference only. Its training analogue, a top-ρK KL, pays (ρ-1)K extra entries on every query, including the >99% with nothing to fix.
  - **Default MoE** [2504.12463]: fills unselected options with an input-independent EMA default whose error is zero only on average over inputs. In attention that default is a pooled block summary, exactly what SAS says loses needle information [2609.13141, Appendix B].
  - **SparseMixer** (as characterized in [2504.12463, Section 4.4]): estimates the router gradient with added noise.
  - Neither MoE method observes exact feedback on unselected options or adapts where it looks.
- **Main risk**: If a trained indexer's misses under native co-adaptation are common, or are diffuse deep-tail needles with no hit neighbours, ACS falls back to uniform exploration. Then it is no better than dense rows at equal FLOPs (the 20-50%-or-less regime of [1304.2460]), and C4/C10 have no regime left beyond the near-boundary misses that a cheap expanded-support KL already covers.


### C9 — Read-usage consolidation: forgetting in the linear-attention state avoids the key subspace its queries keep reading, as continual learning protects the input subspace a layer is used on

- **Intuition**: Treat the memory matrix as a small linear layer whose inputs are the model's queries, and protect it the way continual learning protects a network. Keep a decaying record, in key space, of the directions that recent queries (and fresh writes) have actually used. Let the layer's decay and erase fall mostly on the directions that have gone unused. A stored pair then survives because it keeps being read, and pairs nobody reads still fade in write order, exactly as they do today.
- **Gap it attacks**: Axis "Memory matrix update rules in linear attention and fast-weight models", gap 1. GDN, GDN-2, EDA, KDN and VLA set an association's retention at write time, from cumulative decay and current-token gates [2501.12352, 2412.06464, 2605.22791]. Under overload they evict by write order: VLA "preferentially overwrites recently written directions" [2605.11196], and GDN-2's MK-NIAH-1 falls from 72.6 to 37.8 between 1K and 4K [2605.22791]. The concrete failure targeted here is narrower than C3's: a pair that is read again and again is erased anyway once enough later writes pile up. Examples are an intermediate result that a long chain of thought keeps consulting, and a key that interleaved multi-query recall asks about repeatedly between distractor writes. Fixing this would let the recurrent layers of a hybrid hold the working set that long-CoT decoding re-reads, instead of leaving all re-reading to the full-attention KV.
- **If improving prior candidate**: C3, answering each point of "What a revision must supply" in its verdict. (1) *Usage unit.* C3 counted per-channel read mass, which cannot tell associations apart. C9 keeps the decayed sum of query outer products in key space. For a stored pair, the usage this assigns is the accumulated squared strength with which past queries retrieved that pair's key, i.e. how much of its value was actually emitted to past reads. This singles out associations to exactly the degree that the reads themselves did, and needs no channel sparsity. Reads are counted in proportion to the content they pulled from the state, read at chunk boundaries as CARVE does [2606.27229], so queries that land on empty memory shield nothing. (2) *Only forgetting is redirected.* Writes keep their own key as address, so retrieval is untouched. A delta write onto a heavily read direction still overwrites it, which is the "update the slot just read" case of LRUA [1605.06065]. (3) *Fresh writes count as use*, as in LRUA, where writes add full usage [1605.06065]. A just-written pair is therefore protected like a just-read one. Unread pairs compete only by how recently they were written, so recency stays the fallback and an unread needle is never ranked below the order GDN already uses. (4) *Claims* are limited to recurring reads: interleaved multi-query recall with repeated keys, and long-CoT re-reading of intermediate results. Single-query NIAH is a no-regression check, not a claimed gain. (5) *Hindsight label dropped.* The usage record is a causal input that current-token gates cannot compute. The few parameters that map usage to retention (how fast the record decays, how much a write counts, how strong the shield is) get exact credit from backprop through the state, and no discrete replacement decision is left that would need a Belady-style teacher. (6) *Priors:* RDN [2106.06295] and CARVE [2606.27229] already feed reads back into the write/erase signals, one step back and per token respectively. The contribution claimed here is the persistent, accumulated key-space usage record and its use as a retention metric. (7) C3's protected subspace needed an online top-r estimate. That is replaced by a smooth function of the whole usage matrix, so no eigendecomposition or subspace tracking is needed.
- **Source inspiration**: Continual learning, i.e. protecting a network's past function while it keeps learning. *Recombination-of-distant-concepts.* Memory Aware Synapses [1711.09601] measures each parameter's importance as the sensitivity of the network's output to it, accumulated online on whatever data the network is actually applied to, with no labels. Later changes to important parameters are penalised, so "frequently used knowledge is prevented from being erased" while "rarely utilized knowledge can be overwritten" [1711.09601, Abstract; Section 4.1-4.2]. When importance is computed only on the inputs the system really meets, forgetting on those inputs drops from 8% to 2%, and the freed capacity lifts the last task from 69% to 84% [1711.09601, Section 5.1, Adaptation Test]. MAS is per parameter. Scaled Gradient Projection [2302.01386] supplies the subspace form. For a linear layer, a weight change orthogonal to the span of the layer's past inputs leaves its past outputs unchanged. SGP therefore stores the input subspace past data occupied, gives each direction a soft importance from its share of the input energy, and scales new updates down along each direction by one minus that importance [2302.01386, Section 3, Eq 1-3, 10]. Soft scaling beats GPM's hard block (+3.5% ACC on Split CIFAR-100, +2.4% on miniImageNet), because most stored directions carry little energy; after 20 tasks only 18-37% of them are fully frozen [2302.01386, Section 4; Table 1-2]. From LRUA [1605.06065, Eq 5] the idea keeps one detail: a write counts as a use.
- **How it maps to this problem**: The protected network becomes one head's memory matrix. Its "inputs" are the queries that read it: the read is literally a linear map applied to the query. The "input subspace the layer has been used on" becomes a decaying key-space record of recent queries, weighted by how much each one retrieved, plus the keys of fresh writes. SGP's per-direction importance becomes how strongly a key direction stands out in that record relative to the busiest direction. SGP's "new-task gradient that would cause forgetting" becomes the state's forgetting pressure, i.e. its decay and any explicit erase (as in EDA [2606.26560]). That pressure is scaled down along heavily used directions and left at full strength along unused ones. The delta write is not projected. MAS's "importance measured at deployment" becomes a record that keeps running during prefill and decoding, so retention adapts to what this particular context keeps reading. Operationally, the shield is a key-side transform of the state applied at chunk boundaries, every chunk-length of tokens during decoding as well. The per-token kernel inside a chunk stays as it is. Initialised as the identity, it leaves a public GDN/KDA hybrid unchanged at the start of conversion fine-tuning.
- **Why it could work / feasibility**: (i) SGP's working condition holds by construction, not by analogy. The memory read is a linear map of the query, so changing the state only along directions orthogonal to past queries leaves past read-outs unchanged, and the soft version trades this off by usage, exactly as [2302.01386, Section 3] does for layer inputs. (ii) MAS's condition is that future use resembles past use [1711.09601, Sections 1, 4.4]. It holds on the claimed targets, where the same keys are queried repeatedly (interleaved multi-query recall) and long CoT keeps returning to earlier intermediate results. It does not hold for once-asked needles, which is why those are out of the claim, and the write-counts-as-use rule keeps them at today's recency order. (iii) Cost and kernels. A per-head d_k x d_k second-moment matrix carried by chunk scans next to the state is already practical: CCQ maintains one with one extra reduction per chunk, at about 16% training throughput and +50% state [2606.01294, Appendix B; Limitations]. A query-only record does not depend on the state, so all chunk-boundary transforms can be computed in parallel before the kernel runs. The hit-weighted record needs only the previous chunk-boundary state, which CARVE shows costs one small matmul per chunk [2606.27229, Sections 4.2, 6.3]. The transform sits between chunks, so the intra-chunk WY solver of fla's GDN/KDA kernels is untouched. The only kernel change is one extra matmul in the inter-chunk state-passing loop plus its backward, which is modest Triton work. Conversion of a public GDN/KDA hybrid and long-CoT fine-tuning fit the H200 budget. Key assumption: in trained models, the queries that retrieve content concentrate on a part of key space that is small relative to everything written. If reads spread isotropically, the record is flat and the shield does nothing.
- **Novelty vs. closest in-domain work**: Closest is CARVE [2606.27229], whose erase/write gates see what the current token's query reads from the chunk-boundary state, but which keeps no record of past reads. RDN [2106.06295] feeds back only the previous read-out. Elastic TTT [2604.07350] does bring EWC/MAS-style consolidation to fast weights, but its importance is the magnitude of past *write* updates, elementwise, for 4D vision. CCQ [2606.01294] carries a d_k x d_k *key* covariance but uses it only to modify the read, never retention. The Bayesian Layer [2605.31163] protects addresses by accumulated write evidence and redirects the writes themselves. Miras's retention gates [2504.13173] are elementwise or norm-based, with none weighted by reads. None steers forgetting with an accumulated key-space record of what was read.
- **Main risk**: Trained queries may be spread too broadly over key space (every LM token queries), or the long-CoT re-reading may happen mostly in the full-attention layers of a hybrid rather than in its recurrent layers. Either way, the usage record would barely differ from write-order decay and the gain would show only on synthetic repeated-key recall.



### C12 — Keep what the recurrent half will forget: forgetting-forecast KV eviction for hybrids, the way continual learning replays only the examples an update will make the model forget
- **Intuition**: A GDN state is an online learner that takes one corrective gradient step per token, and the full-attention KV cache next to it works like that learner's exact episodic memory. Continual learning keeps exact copies only of the examples the learner forgets, or will forget under its next updates, and drops the ones it holds stably. Apply the same rule to hybrid eviction: an attention entry is cheap to drop while the co-resident GDN states still hold its content and the coming writes are not forecast to erase it. It is expensive to drop once those states have lost it, or are about to.
- **Gap it attacks**: Axis "Hybrid architectures mixing full attention with linear or recurrent layers", gap 2. Every eviction criterion for the retained attention layers of pretrained hybrids is layer-local and fixed when the entry is written:
  - GateSight's label is the leave-one-out change of one attention layer's output with "the rest of the forward pass held fixed" [2610.14754].
  - HeadWiseKV uses a per-head output cosine [2609.02029].
  - DeltaS scores each chunk once, by how much it changed the state on arrival [2609.27470].

  None of these can see whether the GDN states still carry an evicted entry's content at the moment of eviction. The failure is concrete. GateSight finds that the entries the slow GDN heads (half-life ≥1K tokens) write strongly are the ones attention needs, at 1.82x chance [2610.14754, Section 3.2]. DeltaS keeps exactly the chunks the state absorbed most [2609.27470, Section 3.3]. Both therefore spend the scarce attention budget on duplicates of what the slow recurrent memory already holds, and both protect a fixed recent window (12.5% of the budget in DeltaS) that the fast GDN heads cover anyway. Closing the gap would let the two memories divide the history, so that the attention cache holds only what the recurrent half cannot keep. This bears directly on how small the attention budget can go for long-CoT decoding, where the attention KV is the only memory that grows.
- **Source inspiration**: Continual learning's treatment of forgetting; the novelty type is recombination-of-distant-concepts. Three linked mechanisms:
  - **Forgetting events** [1812.05159]. Each example's forgetting is tracked along the learner's own update trajectory. The examples it never forgets once learned ("unforgettable") can be removed: 30-35% of CIFAR-10 and 80% of MNIST with negligible loss, while random removal hurts. The repeatedly forgotten examples are the informative, support-vector part. The ordering is stable across seeds and architectures.
  - **Maximally Interfered Retrieval** [1908.04742]. A virtual step of the coming update tells which stored samples it will damage. Memory effort goes only to those, because samples whose loss the update leaves unchanged are "wasteful" to rehearse. On MNIST Split this gives ER-MIR 87.6 against ER 82.1, with forgetting halved.
  - **Forecasting forgotten examples** [2402.01865]. To first order, the interference of an update on a stored example is a kernel inner product. When only a linear readout is being trained, that kernel is just the inner product of representations, so the forecast is cheap and needs no learned parts (F1 about 69 with no training). A learned version with a per-example frequency prior does better, and replaying the forecast-forgotten examples cuts forgetting from 9.3% to 1.6%.

  These work because forgetting under online updates is structured and predictable from interference, so a small exact memory can be spent only where the learner is losing information.
- **How it maps to this problem**:
  - The *online learner* is each GDN head's state. The gated delta rule is literally test-time SGD on the regression loss ||S k − v||² with adaptive weight decay [2412.06464]. Each token is one update.
  - The *exact memory* is the full-attention KV cache. A *stored example* is a cached entry, that is, a token position.
  - *Learned* means the co-resident GDN heads (for example, the slow heads near that attention layer) still retrieve the token's own association from their current state. *Forgotten* means the retrieval has decayed or been overwritten. This is measured on a small per-entry probe of those heads' key/value for the token, re-read against the live state at each eviction round. It is a running quantity that later writes revise, unlike DeltaS's or HOLA's one-time write score.
  - The *coming update* is the next stretch of decoding. The delta rule's interference with a stored association is set by key overlap with future writes, plus decay. So the MIR-style "virtual update" reduces to the head's recent write-key statistics, and the forecast is exact in form: this is the linear-readout case in which [2402.01865]'s kernel is an inner product.
  - The *frequency prior* of [2402.01865] becomes the head's stable half-life. GDN head identity explains 71.7% of write-variance, and the fast/slow split is fixed per model [2610.14754, Section 3.1].
  - The *eviction value* of an entry is how much later reads will need it (any existing layer-local predictor supplies this) times the chance that the GDN will no longer hold it when it is needed. Entries that are needed but durably held are the "unforgettable examples" that can go first. Entries that are forgotten or forecast to be forgotten keep their exact copy.
  - End-to-end counterfactuals play the role of [2402.01865]'s ground-truth forgotten sets. An evicted set's effect on the model's final logits is measured with the GDN path live, and these labels calibrate the forecast offline. The report_writer decides the probe heads, the forecast form and the combination.
- **Why it could work / feasibility**:
  - The sources need three conditions: (i) the learner really holds some of the content the exact memory also holds; (ii) its forgetting is predictable from interference; (iii) what it holds stably is redundant with the exact copy for the downstream task.
  - (i) is supported. GDN alone retrieves single needles at 1-4K (S-NIAH-2 at 92.2 at 4K, collapsing to 29.6 at 8K [2412.06464]). Slow heads keep half of a contribution beyond a minute of video for 14.1% of heads [2609.27470, Section 3.1]. GateSight's positive correlations show the two memories overlap on the same important entries [2610.14754, Section 3.2].
  - (ii) holds by construction. Delta-rule erasure acts key by key, and the measured impulse lifetimes of 80-1,382 steps are far shorter than the decay-only horizons [2609.04098, Section 5.3]. This is the linear-head regime in which [2402.01865]'s inner-product forecast is first-order exact, not approximate.
  - (iii) is the key assumption and is testable cheaply. Evicting probe-certified "held" entries should move end-to-end logit KL far less than evicting equally useful "forgotten" entries. The evidence route of the gap already specifies this probe.
  - Cost: the probe stores a few slow heads' key/value per cached token, a few percent of attention-KV bytes, and can be low precision since it only scores. Each eviction round adds one batched state read over the cached entries, which is plain matmuls on states that flash-linear-attention already holds. Eviction reuses GateSight-style physical compaction in vLLM [2610.14754]. No new attention kernel is needed; the probe read is at most modest Triton work. Calibration labels need forward passes only, which is easy on 8×H200.
- **Novelty vs. closest in-domain work**:
  - GateSight [2610.14754] uses GDN write/decay signals only as write-time features to predict a layer-local utility, scores once after prefill, and its label rewards keeping duplicates.
  - DeltaS [2609.27470] retains what the state changed most at arrival, the opposite direction, fixed at write time, video prefill only.
  - HOLA [2607.02303] keeps the worst-represented tokens by write-time residual inside each recurrent layer of a model trained from scratch.
  - C12 credits each cached entry, at every eviction round during decoding, against its current and forecast retention in the co-resident GDN states, and evicts what the recurrent half durably holds.
  - Recency searches since 2025-10 ("hybrid KV cache eviction recurrent state", "KV cache compression hybrid linear attention", "gated deltanet KV cache eviction", "eviction recurrent memory redundancy attention cache", "KV cache eviction what recurrent state forgets", "state-aware KV eviction", "recurrent state retrieval residual KV cache selection") found no method of this kind.
- **Main risk**: A pretrained hybrid's downstream layers may route retrieval of a token through the attention path even when a GDN head still holds it (zeroing all GDN states barely moves NIAH [2608.30386]). In that case "held by GDN" would not mean "safe to evict", and C12 would gain only on local and restated content unless a short eviction-aware fine-tune teaches the model to fall back on the recurrent read.


### C13 — Rematerialization-priced Noah's Ark eviction: value a reasoning result by what it would cost the model to re-derive it from the cache that survives

- **Intuition**: Keep C8's budgeted "a fact survives if some statement of it stays readable" objective, but price each fact the way a checkpointing runtime prices an activation. Its value is what it would cost to recompute it from what is still resident. That cost is small while its operands survive, and it grows along the chain of operands that are already gone. A result the model computed itself becomes expensive to evict exactly when its inputs have been evicted. A restated copy, or a value one step from the pinned prompt, stays cheap.
- **Gap it attacks**: Axis "KV cache and token pruning for standard softmax attention", gap 1. Decoding-time eviction for long CoT ranks each cached entry per head with an independent additive scalar, but retention value depends on the whole retained set. The concrete failure is the Challenge's own: a 2K-budget reasoning model drops an intermediate result it later needs. Additive rankers lose such once-stated values (0-34% passcode retrieval, R-KV 84%) and do no better than a random draw on aggregate accuracy [2609.03430]. Segment-level allocators also value a step by the attention it receives now [2608.12331]. Set-level dependence has two sides. Restatements substitute for each other (C8 handled this). A result's worth also depends on whether the operands it came from survive, and no current scorer models that. Closing the gap would make "which intermediate results can the model no longer reconstruct" the quantity the budget protects.
- **If improving prior candidate**: C8 (Noah's Ark eviction). The reviewer found that its branch length, write-time surprise, rates self-computed results as the cheapest thing to evict. In a model's own trace, math expression tokens are written at near-zero entropy, and the surprise sits on "wait"/"however" forks [2506.01939]. The changes:
  - (i) Branch length is now irreplaceability given the surviving cache, measured as rematerialization cost along the operand chain (below), not surprise.
  - (ii) Downstream attention, the reviewer's other suggestion, is deliberately not the value signal either. Receiver heads attend to planning and uncertainty sentences, and "active computation sentences receive relatively minimal attention" [2506.19143, Section 4.2]. So it would fail on the same items.
  - (iii) Greedy entry-by-entry eviction is dropped, since it is not exact for a survival curve that is convex below its knee [0805.1661, Section 1.3; 2609.03430, Fig 4a]. Decisions are made over whole head-slices of a statement at a few protection levels, solved exactly by a two-level clade program.
  - (iv) The pooled-mass approximation is now stated (below).
  - (v) Copy edges need a span-level run, not single-token copy events.
  - (vi) Calibration uses a probe whose once-stated item is self-computed.
- **Source inspiration**: Dynamic Tensor Rematerialization [2006.09616], from ML systems (training under a memory budget). Novelty type: recombination-of-distant-concepts (activation checkpointing → value model for KV eviction), on top of C8's Noah's Ark objective [0805.1661, 0704.2649].
  - DTR evicts the tensor that is stalest, largest and cheapest to recompute. "Cheapest" is the projected cost: the tensor's own compute cost plus the costs of its evicted neighborhood. That neighborhood is the already-evicted ancestors that would have to be recomputed first, plus the evicted descendants that need this tensor to be recomputed [full text, Section 2; Appendix C.2].
  - So a tensor's value is not intrinsic. It is set by which of its dependencies are already gone. Evicting it is cheap while its parents are resident, and expensive once doing so would create a long chain of recursive recomputation. Constants are never evicted.
  - This matters empirically. Heuristics that see chain costs run at lower budgets with fewer recomputations than LRU, size-based or local-cost rules [Section 4.2, Fig 2]. A union-find approximation of the neighborhood keeps nearly all of the benefit at a small fraction of the bookkeeping [Section 4.1].
- **How it maps to this problem**:
  - **Pieces**:
    - The pinned prompt plays DTR's *constants*.
    - A *unit* (a stated intermediate result, at the sentence/step granularity of [2506.19143]) is a *tensor*.
    - Its *parents* are the earlier units it was computed from.
    - Its *own cost* is the derivation work the model spent producing it from those parents, i.e. the tokens between its operands and its statement. A literal copy costs nothing.
    - Losing every readable statement of a unit is *eviction*. The model can still "rematerialize" the unit by re-deriving it in new CoT tokens, but only from operands that are still readable. Otherwise it must first re-derive those, recursively, back to something resident or to the prompt.
  - **Branch length** of a unit in C8's Noah's Ark tree is its DTR projected cost given the current cache: its own cost, plus the cost of its already-unreadable ancestors, plus that of unreadable descendants that would need it. Each of these is weighted by how unlikely that relative is to still be readable, in the spirit of the HED discount [0704.2649]. Consequences:
    - A value derived straight from the prompt stays cheap. The model can redo it.
    - A result at the end of a long chain whose operands have been thinned becomes the most expensive thing in the cache.
    - The value goes up as its supports disappear, which the Challenge's failure case needs and write-time surprise could not give.
  - **Edges**: two kinds, both read from the same top-attended-position op on a few offline-selected heads while each unit is written.
    - *Restatement edges* come from copy events, under a span-level rule. A run of several consecutive emitted tokens must each copy from consecutive source positions in a retrieval head, the induction pattern behind the copy-paste criterion [2404.15574], and the run must contain at least one non-trivial token, such as a multi-digit number or a variable name. Isolated "=", "the" or single-digit copies are ignored. A paraphrased restatement leaves no edge, so the two statements count as separate units. The error is over-protection, never loss.
    - *Operand edges* are the trace positions a unit's tokens attend to most in "operand heads". These heads are chosen offline as the ones whose attention best agrees with the attention-suppression causal graph of [2506.19143] on a few hundred traces. That graph shows math CoT links are mostly short-range [Section 6.2], so operand detection is mostly local.
  - **Survival** is pooled mass, stated explicitly. A statement's readability is a calibrated function of its retained token-head mass at carrier heads, pooled across heads regardless of shape, as [2609.03430] measured ("the shape of the copies does not matter"). Separate statements of one unit are combined as independent chances (noisy-OR). This is a conservative approximation. Partial mass on two statements might pool, but cross-position pooling was not tested. Noisy-OR can only under-state survival, so the rule may over-keep but will not drop a unit it believes is safe.
  - **Decision**: at each compression round, re-price units, then choose per statement one of a few protection levels (drop; keep its slices in enough carrier heads to clear the readability knee; keep all carrier heads). Prices are frozen within the round, as DTR re-evaluates after each eviction. All value sits on the unit branch, so each unit's contribution is its price times its survival. The clade failure noted in [0805.1661] then cannot arise: there a budget split that maximizes a clade's diversity need not maximize its survival, but here the two coincide. A per-unit table (best survival for each slice budget) plus a cross-unit budget program over a few hundred units is exact for this menu.
  - Non-carrier heads and leftover budget keep Random Attention's uniform draw, the strongest known aggregate baseline [2609.03430].
  - **Calibration probe**: the model computes a chained quantity early in a real MATH500 trace, for example a value that takes several dependent steps whose operands are themselves trace values. It states the result once, continues with long unrelated reasoning, and is later asked for the result. Chain depth is varied. The item is self-generated and low-surprise, unlike the forced passcode of [2609.03430]. On this probe C8's surprise weighting should fail, and depth-aware pricing should not.
- **Why it could work / feasibility**:
  - **Why the transfer is plausible**. DTR's logic needs three things.
    - (i) The cost of losing an item depends on whether its dependencies survive. This holds in CoT. Reasoning steps refer back to earlier results through attention, and masking a sentence measurably changes the logits of the specific later sentences built on it [2506.19143, Section 5.1-5.2]. Masking retrieval heads breaks CoT because "the next step reasoning requires the model to refer to previous information" [2404.15574].
    - (ii) A recovery path exists whose cost grows with the evicted chain. A model that has lost a value re-derives it in new tokens from what it can still read, and the further back the readable operands are, the longer and more error-prone that is.
    - (iii) The dependency graph is cheap to track. DTR's union-find shows a relaxed, approximate neighborhood keeps nearly all the benefit [2006.09616, Section 4.1-4.2]. Here the same per-step top-attended-position op that C8 already needed for copy events also yields operand edges.
  - **Why it fixes the reviewer's objection**. A self-computed result is low-surprise [2506.01939] and gets little downstream attention [2506.19143]. It does, however, sit at the end of a derivation, so its price is set by its operand chain rather than by either of those signals.
  - **Cost**: decisions run once per compression buffer on per-head keep masks, as in R-KV-style runtimes, with no new attention kernel. At most a small Triton op takes the top-attended positions on a handful of retrieval/operand heads. The per-round program is over hundreds of units and is CPU-cheap. The offline head selection (carrier, retrieval and operand heads) needs only forward passes and attention-suppression runs, well within the H200 budget.
  - **Key assumption**: write-time operand attention recovers the true derivation parents well enough that projected cost ranks units by real irreplaceability. This can be checked offline against a unit's NLL when its statements and then its operands are masked.
- **Novelty vs. closest in-domain work**:
  - [2608.12331] TAM is closest: segment-level budget allocation for reasoning traces. It values each segment by the attention it currently receives from the frontier, under an explicitly linear, independent per-segment error model, and has no dependency, restatement or recoverability notion.
  - [2609.22158] StepKV ranks tokens additively by step utility, and reuse raises a step's score.
  - [2505.24133] R-KV uses a per-head pairwise key-redundancy penalty.
  - [2610.02235] CORE uses fused-head log-det coverage.
  - C8 used write-time surprise as value.
  - Recency searches since 2025-10 ("dependency graph KV cache eviction reasoning", "intermediate results KV cache reasoning eviction", "recomputation cost token eviction language model", "re-derive evicted reasoning", "sentence-level KV eviction reasoning", "thought anchors KV cache compression", "rematerialization KV cache") found no evictor that prices an entry by the re-derivation cost of its operand chain. The "rematerialization" hits (e.g. XQuant) recompute KV tensors from activations, a systems trick, not a value model.
- **Main risk**: Projected cost may mis-rank units in natural traces. Abandoned exploration branches have long derivation spans and would be over-priced. Attention peaks may name lexical neighbors rather than true operands. And the model may rarely re-derive at all, so "irreplaceable" and "unrecoverable" diverge. In any of these cases the budget goes to dead ends instead of the result the answer needs.


### C14 — Verified repair sets in a supernet whose all-exact path is the teacher: allocate full attention from the failures on-policy training leaves behind
- **Intuition**: Keep the converted model's shared weights and exact-attention weights frozen at the teacher's values and train only its linear paths on-policy, so that switching every layer back to exact attention gives the teacher itself. Then treat each long-CoT failure that remains as a failing test. Shrink the set of layers that must be exact to fix it with test-case reduction that confirms every step by an actual forward pass, instead of assuming that making more layers exact always helps. Give the full-attention budget to the layers whose addition actually repairs the most remaining failures.
- **Gap it attacks**: Axis "Hybrid architectures mixing full attention with linear or recurrent layers", gap 1: the choice of which layers keep full attention is made from signals computed off the student's own rollouts, while the long-CoT failure arises on those rollouts. The closest placement methods each miss this in a concrete way:
  - Super Apriel scores placements by the log-likelihood of *teacher-generated* MATH500/AIME traces under teacher forcing. It has no on-policy stage, and its own Limitations say likelihood and generation can diverge [2604.19877, Sections 7.1, 8, 9.1].
  - HALO keeps the top one-swap recall/commonsense ratios with k fixed at L/4, before distillation [2601.22156, Section 4.3].
  - PostNAS and DtR score whole placements by one end-task number on short few-shot tasks, before any on-policy training [2508.15884, 2601.11667].
  - Opal is the only method that trains on long student rollouts, and it fixes every fourth layer by rule [2609.31947].
  - None of these sees where on the student's own trace a failure happens, or which layers exact attention would have to cover to prevent it.
  - Why it matters: allocating against those positions would aim the KV budget at the failures that remain after the training the hybrid actually receives. It would also set K from what is left unrepaired, not from a hand-set ratio.
- **If improving prior candidate**: C11. The reviewer's points and what changed:
  - (1) System, specification and all-removed state are now named, and they agree by construction:
    - The system is the supernet at its current allocation, after the latest round of on-policy training of the linear paths.
    - The specification is the frozen teacher.
    - The all-removed state (every candidate layer switched to exact) uses the teacher's frozen attention, MLPs, norms and embeddings, so it *is* the teacher.
  - (2) Shared weights are frozen throughout allocation, and on-policy training updates only the linear mixers. An optional joint stage, with all weights trained as in Opal Stage 3, runs only after the allocation is committed. No diagnosis runs after that stage, because there the all-exact model is no longer the teacher.
  - (3) FastDiag, which needs monotone repair, is replaced by ddmin-style reduction. Its end state, "no single layer can be reverted", is checked by executed tests. A revisit pass runs to a fixpoint. Shortcuts that assume "a superset of a repairing set also repairs" are used only in proportion to how often that has been observed to hold. Coverage of a proposed allocation is re-tested event by event, never inferred from set inclusion.
  - (4) Novelty is re-positioned against Super Apriel and HALO.
  - (5) The claim about repair-set size taken from [2606.27791] is withdrawn. The size distribution is now the first quantity measured, and it is a kill criterion.
- **Source inspiration**: Test-case reduction in software engineering, which minimizes failure-inducing inputs when the test predicate is not monotone; the novelty type is recombination-of-distant-concepts.
  - ddmin [2408.04735, 2506.11614]: it shrinks a failure-inducing list by testing subsets and complements at finer and finer granularity. It stops only after every single-element removal has been tested and lost the property, so its 1-minimality is established by executed tests relative to the predicate [2408.04735, Section II-A; 2506.11614, Sections 2.1-2.2]. Monotonicity (a superset of a passing test also passes) is one of ddmin's three assumptions, but it mainly buys efficiency, by letting implied tests be skipped. When it fails, the guarantee becomes local (1-minimal, not globally smallest), and the global problem is NP-complete [2506.11614, Section 2.1]. Variants that skip revisits can miss reductions that an earlier deletion enabled. Wrapper frameworks recover those by iterating to a fixpoint [2408.04735, Section IV-G].
  - PMA [2506.11614]: it treats monotonicity as an empirical property of the particular search space. During a run it counts agreements and violations. It skips a test that monotonicity predicts only with a confidence that grows with the net agreement count, and otherwise runs the test [Sections 3.1.1-3.1.2]. In compiler and debloating benchmarks where real violations occur (removing an if-statement exposes a latent optimizer bug), it cut processing time by 59.2% against CHISEL with outputs no larger on average. The cost of a wrong skip was bounded, e.g. 1.3% larger output on clang-27137 [Section 4.3].
  - Why it works there: the expensive thing is the test, and failures usually depend on few elements. The reduction stays correct as long as every claim it outputs ("this set keeps the property, and no single element can go") is backed by a test that was actually run.
  - In-domain enabler, Super Apriel's frozen-backbone supernet [2604.19877]: only mixer weights are trained, "by design", so every mixer learns against "a stable reference representation" [Sections 3.2-3.3]. Even its all-FA placement, with FA weights also trained, stays at teacher level (74.2 vs 73.9) [Section 7.4].
- **How it maps to this problem**:
  - Elements are the layers that are currently linear. The input that "keeps the property" is a set of layers switched to exact attention. The property is "this failure event is repaired".
  - Supernet training: each layer holds the teacher's frozen exact attention and a trainable linear mixer. Shared parameters stay at the teacher's values (the Super Apriel design [2604.19877]). The linear mixers are trained by on-policy distillation in the manner of Opal [2609.31947]: the student samples rollouts, and the teacher gives token-level reverse KL. Each rollout batch is generated under a placement sampled across allocation sizes, not concentrated on the current allocation. Super Apriel shows that targeted sampling makes later evaluation of those placements "self-reinforcing specialization" [2604.19877, Sections 3.3, 5].
  - Failure events: rollouts are generated under the current allocation on reasoning prompts. On traces that end wrong, an event is the first position where the teacher, reading the same student-generated prefix, sharply disagrees with the student's next-token distribution. The teacher log-probs come with on-policy distillation for free.
  - Repair test: one forward pass of the supernet on that fixed prefix, with the current allocation plus a candidate set of extra layers switched to exact. The test passes if the student's prediction at the event comes back within a tolerance of the teacher's. It is deterministic, because the prefix is fixed and nothing is sampled. With every layer exact, the model is the teacher, so the test passes by construction, and reduction always has a valid starting point. Results inside a narrow band around the tolerance are recorded as "unclear". They count as failing for reduction but not as monotonicity violations, following PMA's observation that inconsistent outcomes masquerade as violations [2506.11614, Section 4.3].
  - Reduction: start from "all remaining layers exact" and revert layers to linear in ddmin fashion while the test still passes. Stop only when reverting any single remaining layer fails the test, and run a revisit pass to a fixpoint. Run a few random orderings and keep the smallest result. Under non-monotonicity this result is an upper bound on the true smallest repair set, and it is reported as such.
  - Measuring monotonicity: the run logs every case where a superset of a passing set failed. Inferred skips are allowed only at a confidence tied to the observed compliance, as in PMA. The violation rate per round is reported, so it is known how far the layer stack departs from monotone repair.
  - Allocation with verified coverage: build a shortlist of layers and small layer groups that occur in the found repair sets. For each shortlisted candidate, re-run the repair test of every residual event under "current allocation plus this candidate". Commit the candidate that repairs the most events in these actual tests. Then continue mixer-only on-policy training, sample fresh rollouts under the new allocation (DAgger's reason to re-collect, kept from C6 [1011.0686]), and diagnose again.
  - Stopping: stop when the best verified candidate repairs only a small share of residual events, or when most residual events need large repair sets. Large repair sets mean diffuse errors that exact recall at a few layers does not fix, and these are left to weight training.
  - Link to accuracy: for a sample of repaired events, regenerate from the event position under the repaired allocation and check whether the final answer flips. This measures how far repair counts track end accuracy.
  - After commitment: optionally unfreeze all weights and run joint on-policy distillation on the fixed allocation (Opal Stage 3 [2609.31947]). Report both the frozen and the jointly trained results.
- **Why it could work / feasibility**:
  - A teacher-identical endpoint is cheap to get, and the frozen design works for reasoning. In Super Apriel, mixer-only training with frozen FFNs, embeddings and norms reaches 88.3 math average with 26 of 48 layers FA (102.9% of the teacher) and 82.9 with 13 FA (96.6%). In a short-run ablation, mixer-only fine-tuning beat full fine-tuning [2604.19877, Sections 3.3, 7.4]. Freezing the exact-attention paths as well makes the all-exact model equal to the teacher exactly, not just close.
  - The search no longer needs monotone repair. ddmin's terminal guarantee is checked by tests, and the revisit fixpoint recovers reductions that interactions hide [2408.04735, Sections II-A, IV-G]. PMA shows that evidence-gated shortcuts keep most of the speed in a space with real violations [2506.11614, Section 4.3]. Coverage is tested directly, so a non-monotone layer interaction can lower the count but cannot inflate it.
  - Cost: a test is a prefill of a fixed prefix on existing kernels (flash-linear-attention for linear paths, FlashAttention for exact ones), and no new kernel is needed. A ~36-layer model has about 27 candidate layers. Small repair sets need tens of tests per event, and even quadratic worst cases need a few hundred prefills. Verification costs shortlist size times number of events. All of this is far below Opal's 2B-token on-policy run [2609.31947] and fits 8×H200, even with the supernet holding both paths per layer.
  - Key assumptions:
    - (a) On-policy, mixer-only training with frozen shared weights leaves residual failures that are informative. Super Apriel shows frozen-backbone quality only for off-policy distillation plus SFT. Opal's gains came with joint training [2609.31947], so the optional joint stage and the frozen-versus-joint comparison are part of the method.
    - (b) Residual failures have small verified repair sets. No cited evidence settles this. [2606.27791] shows only that *averaged* per-layer ΔNLL concentrates on four core layers across calibration sizes. It reports nothing about a single event [Sections 4.5-4.6]. So the first pilot measures the repair-set size distribution and the monotonicity violation rate on one converted model before any allocation run.
- **Novelty vs. closest in-domain work**:
  - Super Apriel [2604.19877] uses the same kind of frozen-backbone supernet. It differs from C14 in four ways:
    - It scores whole placements by mean teacher-forced log-likelihood of teacher-generated reasoning traces.
    - It models interactions with a global surrogate limited to order ≤3 and range ≤3.
    - It trains off-policy, and names on-policy RL as future work.
    - It never localizes failures.
  - C14 instead allocates from verified per-failure repair sets on the student's own prefixes. Interactions of any order and range are captured inside each event's set and confirmed by direct tests, the mixers are trained on-policy, and diagnosis is redone after every commitment.
  - HALO [2601.22156] uses one-swap ratios with a fixed k before distillation. PostNAS and DtR [2508.15884, 2601.11667] use a whole-task score on short tasks. Opal [2609.31947] uses a fixed allocation.
  - Activation patching in interpretability also searches for component subsets that restore a behavior, so "minimal component set by forward passes" is not itself new. The new part is using verified per-failure repair sets on on-policy traces, in a supernet whose all-exact endpoint is the teacher, to allocate the full-attention budget.
  - Recency searches since 2025-10 found no on-policy or residual-failure-based allocation method. Queries: "hybrid linear attention layer placement", "attention layer selection hybrid reasoning", "on-policy distillation hybrid layer allocation", "full attention placement student rollouts", "frozen MLP linear attention distillation reasoning", "repair set layers exact attention".
- **Main risk**: Residual failures may be diffuse drift rather than localized lost recall. Their verified repair sets would then be large or differ from event to event, and the method would collapse into ranking layers by on-policy KL spikes. The first pilot is designed to show this before any allocation run.


### C15 — Read-attributed erase shield: a delta write still overwrites its own slot, but stops erasing neighbours that past reads keep retrieving

- **Intuition**: When a delta-rule write lands near a stored association that the model keeps reading, it should still overwrite its own slot, but it should stop wiping out that neighbour. Keep a decaying key-space record of which stored pairs past reads actually retrieved, credited by a least-squares read so that crosstalk earns nothing. Then remove from each write's erase vector the part that points along heavily retrieved directions, and leave the write address and the on-key overwrite untouched.
- **Gap it attacks**: Axis "Memory matrix update rules in linear attention and fast-weight models", gap 1: retention is set at write time from recency and current-token gates, so under overload eviction follows write order, not later read demand [2412.06464, 2605.22791, 2605.11196]. The concrete failure here is the write channel. In pretrained GLA/GDN, recall loss is driven by load and by later writes that overlap the target. Going from 1 to 16 live facts costs 30-40 recall points, while stretching fact-to-query distance from 128 to 1024 tokens costs little. Aligning one later write key with the target's key lowers the target margin by 0.27-0.44 logits [2609.33093, Section 4.2]. In the GDN-2 update, a write at k_t changes the read at a stored key k_i only through (k_t·k_i), and the part that destroys v_i is the erase term, proportional to (k_t·k_i)(a_t·k_i) with a_t = b_t ⊙ k_t [2608.13668, Section 3.2 / Eq 9; 2605.22791]. That damage depends only on write geometry and current-token gates. So a pair the context keeps re-reading is erased by any later write that happens to overlap it. Examples are an intermediate result a long chain of thought consults again, or a key that interleaved multi-query recall asks about between distractors. Closing this would let recurrent layers hold the re-read working set instead of leaving it all to full-attention KV.
- **If improving prior candidate**: C9, against each item of its verdict's "What a revision must supply". (1) *Channel.* C9 redirected decay, but the evidence above says interference from later writes dominates. C15 therefore moves the shield into the erase vector. Only the component of a_t that is orthogonal to k_t and lies along heavily retrieved directions is damped. The on-key part (a_t·k_t) and the write address k_t stay as they are, so a write to the same key still replaces the old value, and the new pair is retrieved exactly as before. The residual channel C15 does not touch, the additive leak (k_t·k_i) w ⊙ v of the new value into neighbours, is reported as its own term. Decay is left to the model's gates. In fast heads content dies within about 1/(1-alpha) tokens by design, and C15 claims nothing there. Feeding the shield's diagonal into channel-wise decay is an optional arm, used only for heads where the decomposition shows decay dominates. (2) *Chunk operator.* There is none. Nothing acts on the state at chunk boundaries, so there is no sawtooth, no add-back, and no conflict with in-chunk overwrites. The shield is a per-token change of the erase vector inside the standard transition, the same slot QED edits, which "keeps the structure of the GDN-2 kernel" at one dot product and one subtraction per token and head [2608.13668, Appendix A]. The shield matrix is refreshed once per chunk and frozen inside it (a one-chunk lag). It depends only on keys, queries and gates, never on the state, so all erase vectors are computed before the recurrent kernel runs and the chunk kernel itself is unchanged. GDN and KDA checkpoints tie the erase vector to beta·k, so converting them needs a decoupled-erase kernel: GDN-2's, or fla's generalized (DPLR) delta-rule kernel used by RWKV-7 [2503.14456]. Both exist, so no new kernel is written. The added cost has two parts. One is a decayed d_k x d_k write-key second moment carried by chunk scan, which CCQ measured at about 16% training throughput and +50% state [2606.01294]. The other is one d_k x d_k solve per head per chunk to attribute reads, kept out of the backward pass. The bar to beat is Palimpsa's 1.5-3x training and about 4x decoding slowdown [2602.09075]. (3) *Hit measure.* C9 weighted a read by the mass it returned, which credits crosstalk. C15 credits reads through the least-squares read of the Mesa layer [2506.05233, Eq 10]. The decorrelated query (H + Lambda)^{-1} q gives each stored pair a weight equal to its regression coefficient. That weight is near 1 for the pair the query targets and near 0 for its crosstalk partners while live pairs stay within d_k, and a crowd of partial matches each gets a thin share, so crowds earn little protection. The strength of a hit is the share of the query that lies inside the span of written keys, so reads into empty memory credit nothing. *Composition with QED:* the two act on complementary directions. QED erases what the current read picks up off-key, which is crosstalk [2608.13668, Section 3.1]. The shield vetoes erasing what accumulated reads attribute to targets. It is applied to the full erase vector, QED's term included, so QED still removes crosstalk sources but cannot remove a repeatedly retrieved target. Both edit only a_t and keep the write address and the on-key eigenvalue, so they stack in one kernel slot. (4) *Prior and baselines.* Palimpsa [2602.09075] is the closest prior (see Novelty). The main ablation is the same shield built from the write-key second moment H instead of the read record, which is Palimpsa-style write importance carried in key space. Palimpsa-D itself and C9's read-mass weighting are further baselines, so the gain must be shown to come from the read term. (5) *Decomposition first.* On public GDN, KDA and GDN-2 checkpoints, run interleaved repeated-key MQAR and long-CoT traces that re-read intermediate results. Follow a re-read pair's read-out through the recurrence and charge each step's loss to decay, to the erase term, or to the additive write leak, per head. Apply the shield to the heads where the erase term dominates.
- **Source inspiration**: Continual learning, now applied to the object that actually causes forgetting. *Recombination-of-distant-concepts.* Scaled Gradient Projection [2302.01386] protects a linear layer by scaling the *new update* along each stored input-space basis by one minus its soft importance. This works because an update orthogonal to past inputs leaves past outputs unchanged, and because soft scaling freezes only 18-37% of directions after 20 tasks, so the layer stays plastic and gains +3.5 / +2.4 ACC over hard projection [2302.01386, Section 3, Eq 1-3; Section 4]. The reviewer noted that C9 used SGP only on decay. In the delta rule, the update that causes forgetting is the write's erase: a write changes the read at probe x only through (x·k_t), and the term that destroys stored value i scales with a_t·k_i [2608.13668, Eq 9]. Scaling a_t along protected directions is therefore SGP applied to the right update. Memory Aware Synapses [1711.09601] adds that importance should be measured on what the deployed system actually uses: on the data actually met, forgetting drops from 8% to 2% [1711.09601, Section 4.1-4.2; Section 5.1]. Here what is used is the reads. Attribution of those reads comes from the Mesa layer's least-squares read [2506.05233]: the read that is optimal in squared error weights each stored pair by its regression coefficient instead of its raw overlap.
- **How it maps to this problem**: The protected network becomes one head's memory matrix, and its past inputs become the queries that read it. SGP's stored input bases with soft importance become a decaying key-space record of read attributions: each read adds the direction its least-squares weights point to, scaled by how much of the query fell on written keys. SGP's update to be damped becomes the off-key part of the delta erase vector. It is damped along well-read directions and left at full strength elsewhere. The on-key erase and the write key are not touched, mirroring SGP's choice to leave the orthogonal complement free. MAS's "importance measured at deployment" becomes a record that keeps running through prefill and decoding, so each context protects what it re-reads. QED's query-derived erase, if present, sits in the same vector and passes through the same shield. Initialised with zero shield strength, a converted public GDN-2/KDA layer starts exactly at its checkpoint.
- **Why it could work / feasibility**: (i) The channel the shield acts on is the one that binds. In pretrained GDN, overlapping later writes and load, not distance, drive recall loss, and orthogonalising the overlapping write removes its effect [2609.33093, Section 4.2 / Figure 7]. Damping the overlap-borne erase targets that causal path. (ii) Reads are concentrated: recall passes through concentrated query-time read pathways [2609.33093, Section 3.2]. This is the key assumption, that read attributions occupy a small part of key space, and it now has causal support in pretrained models, not only on MQAR. (iii) Editing the erase vector is trainable and stable. QED's off-key erase edit gave up to +39 S-NIAH-1 points, and the transition eigenvalue stayed in [-0.011, 0.985] [2608.13668, Sections 6 and A]. GDN-2 and EDA show that erase can be decoupled from write [2605.22791, 2606.26560]. (iv) The cost is bounded by measured pieces: CCQ's chunk-carried key second moment [2606.01294], plus a once-per-chunk solve, against the per-token CG that the Mesa layer needs [2506.05233]. Conversion and long-CoT fine-tuning of public GDN/KDA hybrids fit the H200 budget. Key assumption: re-read pairs are not so overloaded in their head that least-squares attribution spreads out, i.e. live re-read pairs per head stay near or below d_k.
- **Novelty vs. closest in-domain work**: Closest is Palimpsa [2602.09075]. It also consolidates the linear-attention state, but its importance is built from *write* evidence (beta ⊗ k^2), is per element, and scales the whole write and the decay together, with no split between overwriting the slot at k_t and collateral removal at other keys [2602.09075, Section 2.2 / Eq 5; Appendix A.5-A.6]. C15's delta is narrower: importance from *reads*, attributed by least squares, held in key space, and applied only to the off-key erase. QED [2608.13668] uses the current query to erase more, with no record. CARVE [2606.27229] reads the boundary state per token, with no record. GSA-2 [2610.02816] adds a key-side Oja correction gated by the current token. CCQ [2606.01294] uses key covariance only at the read. A recency search (since 2025-10-27: "erase vector linear attention", "decoupled erase direction delta rule", "protect stored associations delta rule interference", "usage-weighted erase memory", "least squares attribution recurrent memory reads", "delta rule interference crosstalk retention", "generalized delta rule removal key", "linear attention memory interference") found only these and 2609.33093, an analysis paper.
- **Main risk**: In trained hybrids, recall is carried more than 99% by the full-attention KV and under 1-4% by recurrent state [2609.33093, Section 4.1]. The long-CoT gain may therefore appear only in pure-recurrent or SWA hybrids, unless conversion fine-tuning shifts load onto the recurrent layers. Separately, if the decomposition shows that the additive write leak rather than the erase term dominates in slow heads, damping the erase cannot help without moving the write address.
