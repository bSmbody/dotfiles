
### C5 — Recurrent state as a cache: learned unit replacement that imitates the exact pruning oracle

- **Intuition**: Treat each state unit of a gated linear-attention / SSM layer (a mode, a key-channel row or a balanced direction) as a cache line, and make the keep/drop decision a replacement decision revised at every chunk. A unit that a new write fills can be admitted at once, and the unit whose stored content is worth least in future reads is evicted. This avoids predicting one mask for a coming window, and the ranking policy is learned by imitating the exact future-aware pruning oracle, the way CPU caches learn to imitate Belady's policy.
- **Gap it attacks**: Axis "Pruning and compression of variant attention mechanisms", gap 1: every recurrent-state pruning and mixed-precision method (DRRQR [2602.04852], DASC horizons [2608.30386], DAMP [2608.27513], STEPQuant [2609.38169], and the new balanced-truncation BASS [2610.36617]) commits to one offline, input-independent unit set. Yet the units a gated layer uses migrate with the input write map B_t, which leaves a same-window headroom below every static rule and even below the unpruned model [2607.11796]. The causal schedulers tried so far all fix a mask ahead and hold it over a span (regime mask, 256-token prefix, first-half-of-window). They recover only 2-26% of that headroom, because the important set decorrelates within a few hundred tokens [2607.11796]. Closing this would let a halved state follow what is actually stored. It matters most for purely recurrent models, where static halving drops GDN-1.3B NIAH-4K from 81.3 to 61.9 [2602.04852], and for serving systems that keep and checkpoint these states for many requests [2608.30386].
- **Source inspiration**: Computer-architecture cache replacement, *recombination-of-distant-concepts*. Parrot [2006.16239] learns replacement for CPU caches by imitating Belady's optimal policy. Belady's needs future accesses, so it exists only offline, but on a fixed trace it can be queried exactly at any cache state. Parrot trains a causal policy that sees only the incoming access, the resident lines and recent history to rank resident lines for eviction the way the oracle would. Three ingredients carry the gain. DAgger roll-outs collect states under the learned policy, because its own evictions create cache states the oracle never visits (+9.8%). A ranking loss penalises evicting soon-needed lines more than near-optimal mistakes (+3.5%). An auxiliary head regresses each line's reuse distance (+16.8%). Hand-designed heuristics each fit one access pattern, whereas the learned ranking closes much of a gap that, by the paper's measurement, needs exact knowledge thousands of accesses ahead [2006.16239, Sections 3-5].
- **How it maps to this problem**: Cache lines become the r state units a head keeps in memory. A cache miss becomes a chunk whose writes put new content into units outside the kept set. The resident candidates are the kept units plus the newly written ones, ranked together, so that admission at write time absorbs the B_t-driven migration, the part [2607.11796] shows is necessary and largely sufficient. Belady's reuse distance becomes the exact future output error from dropping a unit's current content. For diagonal SSMs, the per-mode Gram instrument of [2607.11796] gives this error exactly over the following window. For Mamba-2 and GDN it comes from one look-ahead roll-out on the training trace. The causal policy is a tiny per-layer scorer that reads only what is known at the decision point: each unit's stored content, the chunk's write and read couplings, and the unit's static decay horizon (the timestep carries almost none of the migration [2607.11796]). DAgger matters more here than for CPU caches, because an evicted unit's content is gone and later states and downstream layers differ under the learned policy. Precision tiers (FP16 / INT8 / dropped) fit the same frame as a small cache hierarchy with promotion and demotion. For Mamba-2, the units can be the balanced directions of [2610.36617] instead of native coordinates.
- **Why it could work / feasibility**: Parrot's conditions hold here. (i) The oracle is exactly computable offline at any policy-induced state: [2607.11796] gives exact per-subset output error in one pass for diagonal SSMs, and for other layers a teacher roll-out on fixed text is cheap. (ii) Causal features carry real signal: the domain is linearly readable from a layer's mode energies at 99.7% [2607.11796], and the stored content after a write is observed exactly rather than predicted. (iii) Whole-span masks fail where per-decision ranking need not, since the oracle's advantage comes mostly from which units the current tokens write [2607.11796, Section 4.2], and a replacement policy sees those writes before deciding. In Mamba-1, B_t and C_t are shared by all channels of a layer [2607.11796, Eq 1-2], so one ranking can serve a whole layer, keeping index overhead and scorer cost small. In-domain, KVP [2602.10238] shows that a tiny per-head learned scorer trained offline on future utility outperforms heuristic proxies for KV tokens up to 128K, which supports the cost side. Compute is not binding: traces, oracle labels and DAgger roll-outs on 1.3B-8B GDN / Mamba checkpoints fit the H200 budget. Kernel cost is modest: fla chunk kernels run unchanged inside a chunk, and decode needs a gather/scatter of r units per head plus a top-r select (a small Triton change). Key assumption: the oracle's ranking of current units is predictable from stored content plus current writes and reads, without the future reads that a window oracle also sees.
- **Novelty vs. closest in-domain work**: [2607.11796] measures the headroom and tries only mask-ahead schedulers. Here the decision becomes per-chunk replacement with admission and a policy imitated on-policy from its exact oracle. KVP [2602.10238] learns eviction for immutable KV tokens offline from fixed traces, without modelling how evictions change later inputs. Here the evicted objects are evolving state units, whose eviction changes all later state. SSE [2507.16577] and Raven [2607.25357] route writes sparsely, but only in new architectures trained from scratch, with token-only routers and all slots stored. This method is post-training, state-aware, and it shrinks the stored state of existing dense-write models.
- **Main risk**: Most of the oracle's headroom may come from the future read map C_t and from its "denoising" gain over the unpruned model. Both depend on tokens not yet seen, so a causal replacement policy may top out near the 18-26% half-window scheduler, especially since the energy of stored content is dominated by a bias-like direction that the output barely reads [2610.36617].


### C4 — Exploration slots for sparse-attention selectors: off-policy-corrected feedback on blocks the selector missed

- **Intuition**: A block-sparse attention selector is a top-K recommender that only ever gets feedback on the items it showed. Borrow the recommender fix: spend a few extra block slots per query block on blocks sampled with known probability from outside the top-K, measure their true attention mass with the same sparse kernel, and use inverse-propensity weighting so the selector gets an unbiased signal about all blocks, including the ones it currently misses, without any dense attention.
- **Gap it attacks**: Axis "Hardware-efficient training and inference algorithms for linear and sparse attention", gap 2 (selector trained only on its own support). In every trainable selector read here, the signal that trains the selector is computed only over the blocks it already chose: NSA's selection gets no gradient of its own [2502.11089]; MSA's KL is normalized over the selected tokens after a dense warmup [2606.13392]; DashAttention's entmax Jacobian is zero off the support [2605.18753]; hard top-k gives dM/dG = 0 [2603.02227]. The newest end-to-end method, SAS, states it directly: under its sparse training scope "a block outside the selected set therefore has no direct gate gradient", and only full scope, meaning attention over all blocks, gives each block its own signal [2609.13141]. So a relevant block that is missed now, such as a needle, or an intermediate result a long chain of thought revisits later, is corrected only by dense phases: MSA's warmup, distillation on frozen dense attention, or SAS's full scope. Those phases bring back the O(N^2) cost that the kernel exists to avoid, and the cost grows fastest at 128K-1M, exactly where SAS and MSA report a remaining retrieval gap [2609.13141, 2606.13392]. Closing the gap would make the selector's recall trainable from sparse-only compute at any length, and would give a clean test of whether the long-context retrieval gap is a credit-assignment problem or a selector-capacity problem.
- **Source inspiration**: Large-scale recommendation and retrieval, which face the same structure: a model picks K of millions of items and observes reward only for the items it showed. (1) YouTube's top-K off-policy REINFORCE recommender [1812.02353] handles this in three ways. It weights logged feedback by the ratio between the learned policy and the logging policy, so learning stays unbiased even though feedback comes only from shown items. It rewrites the objective around the probability that an item enters the K-set, which adds a multiplier: an item with little probability mass is pushed up about K times harder, and an item already reliably in the set stops receiving gradient. This is what makes the learned policy good at top-K rather than top-1. And it uses Boltzmann exploration, returning the top K' items deterministically and sampling the rest, so that unshown items get feedback at all; weight capping keeps the variance under control [1812.02353, Sections 4.3-5, 6.2]. (2) Sampled softmax with a corrected logQ term [2507.09331] shows how to estimate a full-catalog softmax and its gradient from a few samples of a known proposal: terms that are present deterministically are computed exactly, and the rest is estimated with 1/Q weights. The paper also shows that mixing the two kinds of terms naively biases the estimate [2507.09331, Section 3.3]. (3) Inside attention, vAttention confirms the key condition at inference time: once the heavy blocks are covered, the residual attention mass is flat enough that a small random sample with inverse-rate rescaling estimates it well [2510.05688, Section 4.1]. Novelty type: recombination-of-distant-concepts (off-policy bandit learning from recommender systems carried over to sparse-attention selector training).
- **How it maps to this problem**: The selector (an NSA/MSA/SAS-style block scorer per GQA group) plays the recommender policy. The candidate KV blocks play the item catalog. Each query block's top-K selection plays the page of recommendations. The attention mass the main branch puts on a block, computable exactly only for blocks the sparse kernel actually visits, plays the reward. During sparse training, each query block keeps its usual top-K blocks and adds a small number of exploration blocks, sampled from the selector's own tempered distribution over the remaining blocks (mixed with a uniform floor so that every block has non-zero probability). The sparse kernel just receives a slightly longer block-index list, and the inclusion probability of each explored block is logged. The selector's target over all blocks is then formed in the sampled-softmax way: exact mass for the selected blocks, importance-weighted mass for the explored ones, and an importance-weighted estimate of the total off-support mass for normalization. Two choices are left to the report_writer. The first is whether explored blocks only feed the detached selector loss, which keeps the forward pass identical to inference and avoids routing absorption, or also enter the output as an unbiased estimate of the residual in vAttention's style. The second is whether the loss uses the top-K inclusion form, so that capacity goes to getting misses into the set rather than to matching mass within it.
- **Why it could work / feasibility**: The recommender mechanism needs three things, and all three hold here. (i) Feedback on an explored action has to be observable at the cost of taking that action. Here the exact attention mass of an explored block is a by-product of attending to it, and the block-sparse kernels of NSA/FSA/MSA already take arbitrary per-query-block index lists [2502.11089, 2508.18224, 2606.13392], so the extra cost is a few percent more blocks and no new kernel beyond a weight per entry in a fused KL kernel such as MSA's. (ii) Exploration probabilities have to be known and non-zero on every action. Here the trainer samples them itself, so propensities are exact and need not be estimated, which avoids the main variance source named in [1812.02353, Section 4.4]. (iii) The residual has to be estimable from a few samples. vAttention shows that after top-k the residual is flat enough for small-sample estimation [2510.05688], and a sequence has thousands of query blocks, layers and heads per step, so every block of a context gets sampled many times per batch even at one or two exploration slots each. The top-K inclusion multiplier of [1812.02353] matches the goal stated in this gap, recall on missed blocks. The key assumption: a block's usefulness is reflected in the main branch's attention mass on that block when it is explored, which is the same teacher signal MSA's KL and SAS's coverage analysis already rely on [2606.13392, 2609.13141].
- **Novelty vs. closest in-domain work**: SAS [2609.13141] is closest. Its sparse scope gives unselected blocks no signal of their own, and its only remedy is full scope with dense attention. MSA [2606.13392] restricts its KL to selected tokens after a dense warmup. vAttention [2510.05688] and kNN-attention [2411.04013] mix top-k with random sampling only to approximate attention or its gradients, with a fixed, untrained selector. None of these uses sampled off-support blocks with known propensities as an unbiased, sparse-only training signal for the selector.
- **Main risk**: Attention mass is heavy-tailed, so the blocks that matter most (a needle the selector ranks very low) get the smallest sampling probability and the largest, most variable importance weights. Capping or a uniform floor may then remove most of the signal on exactly those blocks. SAS also finds that sparse scope already catches up with full scope on reasoning benchmarks [2609.13141], so a gain may show only on long-context retrieval.


### C1 — Quorum-coverage eviction: keep each fact at "just enough" carrier heads, the way k-coverage sensor networks put redundant sensors to sleep

- **Intuition**: Treat the KV cache like a dense sensor network that must keep every "region" (a piece of information in the reasoning trace) watched by at least k sensors (copies in carrier heads). Evict a cached entry only when every piece of information it carries is still held by enough other copies, restated or in other heads, so the budget stops paying for copies above quorum and protects facts that are about to drop below it.
- **Gap it attacks**: Axis "KV cache and token pruning for standard softmax attention", gap 1 (per-token additive ranking vs set-level coverage). Current evictors give each entry, per head, its own scalar score (H2O, R-KV, LazyEviction, KVP, ForesightKV, DistillCache) or a diminishing-returns set score over positions (K-VEC, CORE). Neither form can express what the planted-fact probe measures: one carrier-head copy is almost worthless (3%), two or three are readable (60% / 83%), and more copies add little (99% with all eight) [2609.03430]. That is a threshold, not a sum and not a concave coverage curve. The concrete failure is the Challenge's long-CoT one. Restated intermediate results are over-held across heads and positions, while a once-stated value is dropped from each head independently until it falls below readable strength: 0% passcode retrieval for random eviction, 0.4% for SnapKV [2609.03430]. Closing it would let the budget be spent on how many distinct facts stay readable, which is the quantity that decides accuracy at 1-2K entries.
- **Source inspiration**: [0710.3918] (Controlled Greedy Sleep, k-coverage sensor scheduling). In dense sensor networks each region must stay covered by at least k awake sensors, and coverage above k "does not provide higher performance". The scheduler keeps a sensor–region incidence graph and gives each region a coverage ratio that is positive only when the region is over-covered. A sensor may sleep only if every region it covers stays over-covered (negative drowsiness means "not allowed to sleep"), and sensors are put to sleep greedily with recomputation after each one [full text, Section III.C, Eq 1-3]. Each node can run this from local information only (Section III.D). It works because the value of a sensor is defined by the coverage state of the regions it serves, not by its own reading. At matched lifetime, Randomized Independent Sleeping, where each sensor sleeps with a fixed probability, leaves only ~90% of the area 3-covered while CGS keeps all of it, and random needs many more awake sensors to approach CGS coverage (Section IV.B). Novelty type: recombination-of-distant-concepts (wireless-sensor coverage scheduling → KV eviction).
- **How it maps to this problem**: Sensors are cached entries, one per (layer, KV head, position). Regions are content units of the trace: a stated value or intermediate result, together with all the positions that restate it. The incidence edges say which entries hold a usable copy of which unit; only carrier heads count, because the probe shows only some heads hold a readable trace [2609.03430]. The coverage requirement k is a per-unit quorum of carrier-head copies, calibrated offline from a planted-fact curve like the one in [2609.03430] (the knee at 2-3 heads). Random Attention's independent per-head draw [2609.03430] plays the role of Randomized Independent Sleeping. At each eviction round the evictor recomputes how covered each unit is. Entries whose units are all over quorum (a restated reasoning step held in many heads and positions) are released first. An entry that is among the last k copies of a unit is pinned, which is how a once-stated passcode keeps exactly a quorum of carrier-head copies instead of all eight or none. Leftover budget can still go to an existing per-token score or to the random draw.
- **Why it could work / feasibility**: The mechanism needs two things: (i) value is a threshold in the number of covering copies, and (ii) the incidence between units and copies can be approximated cheaply. Condition (i) is measured directly in the planted-fact probe, where pooled retrieval jumps from 3% to 60% to 83% to 99% as carrier heads are added, and "the shape of the copies does not matter", so a count of copies is a usable coverage measure [2609.03430]. For (ii), CGS itself runs on a deliberately pessimistic, approximate incidence (squares instead of true sensing disks), and errors only make it keep extra sensors awake, not lose coverage [0710.3918]. Here a cheap pessimistic incidence also exists. Restatement is visible from token identity (the same number or variable) and from near-duplicate keys within a head, which is the signal R-KV's redundancy term already computes and the only signal that saved the passcode (84%) [2505.24133, 2609.03430]. The text-level restatement that makes random eviction work on MATH500 [2609.03430] is the over-coverage the scheduler can release. Engineering fits the constraints: the decision runs once per eviction round on per-head keep masks that existing per-head eviction code in vLLM / R-KV-style runtimes already applies, so it needs no new attention kernel. Key assumption: content units can be identified well enough that the scheduler rarely counts two copies of different facts as substitutes.
- **Novelty vs. closest in-domain work**: The closest is [2610.02235] CORE, which runs decode-time set-level coverage on AIME25 / Math500. Its log-determinant objective fuses all KV heads into one vector per position and is provably diminishing-returns only (cross derivative ≤ 0, Appendix B.4). It therefore cannot express "one copy worthless, k copies readable", and it chooses positions, not how many heads keep each fact. [2606.29563] K-VEC rewards positions kept in at least one head, which is 1-coverage of positions, not k-coverage of content. [2505.24133] R-KV is a pairwise per-token penalty within one head.
- **Main risk**: On real traces the text-level redundancy may already do most of the work (a shared draw is within 0.3 points of independent draws on MATH500 [2609.03430]), and the quorum curve is measured only on Qwen3-4B. Gains may then be limited to rare once-stated facts unless content units and carrier heads can be identified reliably across models.
