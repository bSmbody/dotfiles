## 第 1 章 语言模型在做什么

**一句话**：给定前面的文字，预测下一个词。然后把预测出的词接上去，再预测下一个，如此反复。

- **token**：模型处理文字的最小单位。一个英文单词大约 1–1.5 个 token，一个汉字大约 1–2 个 token。图像和视频也会被切成 token，比如一张图切成几百个小块（patch），每块是一个 token。
- **embedding**：每个 token 被映射成一个向量，比如 4096 个数字。模型内部处理的全是这些向量。
- **自回归生成**：一次生成一个 token，生成出来的 token 又成为下一步的输入。

```
输入: "今天天气"  →  模型  →  "很"
输入: "今天天气很" →  模型  →  "好"
输入: "今天天气很好" → 模型 →  "。"
```

**记住这个画面**：生成 1 万个 token，就要把模型跑 1 万次。后面讲的所有优化，都是为了让这 1 万次跑得更快、更省显存。

## 第 2 章 Transformer 的一层长什么样

现在的大模型基本都是 Transformer：同一种“层”叠几十次。比如 Llama-3.1-8B 有 32 层，70B 有 80 层。

每一层由两个部件组成：

```
输入向量
   │
   ├──→ [注意力 Attention]  ← 让每个 token 去“看”前面的 token，把相关信息取过来
   │        │
   └────(+)←┘               ← 残差连接：把结果加回原输入
   │
   ├──→ [前馈网络 FFN / MLP] ← 每个 token 自己做一次变换，没有 token 之间的交流
   │        │
   └────(+)←┘
   │
输出向量 → 送到下一层
```

（每个部件前面还有一个归一化，这里省略。）

- **注意力**是 token 之间唯一交换信息的地方。“它”指代的是谁、前面算出的结果是多少，都靠注意力从前文里取过来。
- **FFN** 占大部分参数，相当于模型的“知识库”，但它只处理当前这个 token。

**本方向研究的全部对象都是“注意力”这个部件。**

## 第 3 章 注意力机制：从直觉到公式

### 3.1 直觉：查资料

把注意力想成“去图书馆查资料”：

- **Q（query，查询）**：我现在想找什么。
- **K（key，索引）**：每本书的标签。
- **V（value，内容）**：每本书的内容。

做法是：拿 Q 和每个 K 比相似度，越相似权重越大，再按权重把各个 V 加权平均，得到的就是“查到的东西”。

每个 token 都会算出自己的 q、k、v：分别用三个矩阵乘以它的向量，这三个矩阵是训练出来的。

### 3.2 公式

```
相似度   s_i = (q · k_i) / √d          d 是向量维度，除以 √d 是为了防止数值过大
权重     w_i = softmax(s)_i = exp(s_i) / Σ_j exp(s_j)    所有权重加起来等于 1
输出     o   = Σ_i  w_i · v_i
```

**因果掩码**：生成时，第 t 个 token 只能看第 1 到第 t 个 token，不能偷看后面的。

### 3.3 一个算到底的小例子

假设向量只有 2 维，前面有 3 个 token：

| | k | v |
|---|---|---|
| token 1 | [1, 0] | [10, 0] |
| token 2 | [0, 1] | [0, 10] |
| token 3 | [1, 1] | [5, 5] |

当前的 query 是 q = [1, 0]：

1. 点积 q·k：1，0，1；除以 √2 得到 0.71，0，0.71。
2. softmax：exp 之后是 2.03，1，2.03，总和 5.06，所以权重是 **0.40，0.20，0.40**。
3. 输出 = 0.40×[10,0] + 0.20×[0,10] + 0.40×[5,5] = **[6, 4]**。

token 1 和 token 3 的 key 和 q 更像，所以它们的 value 贡献更大。

### 3.4 多头（multi-head）

上面的过程会并行做很多份，比如 32 份，每份叫一个“头”（head），各自用不同的 Q/K/V 矩阵。不同的头会学会关注不同的东西：有的看前一个词，有的看句子主语，有的专门做“复制”。最后把各头的输出拼起来。

## 第 4 章 为什么注意力贵：KV cache 的由来

### 4.1 问题一：计算量随长度平方增长

序列长度为 n 时，每个 token 都要和前面所有 token 算相似度，总共大约 n²/2 次。
长度从 4K 变成 128K（32 倍），注意力的计算量变成约 1000 倍。

### 4.2 问题二：生成时会重复计算，于是有了 KV cache

生成第 1001 个 token 时，需要前面 1000 个 token 的 k 和 v。如果每一步都重新算一遍，浪费就太大了。

**解决办法**：每个 token 的 k、v 算出来以后就存下来，以后直接用。这个存储区叫 **KV cache**。

- 好处：每一步只需要算新 token 自己的 q、k、v。
- 代价：显存占用随长度线性增长，**而且每一层都要存一份**。

### 4.3 KV cache 有多大

```
KV 大小 = 2(K和V) × 层数 × KV头数 × 头维度 × token数 × 每个数的字节数
```

| 模型 | 每个 token | 32K token | 128K token |
|---|---|---|---|
| Llama-3.1-8B（32 层，8 个 KV 头，头维度 128，BF16） | 128 KB | 4 GB | 16 GB |
| Llama-3.1-70B（80 层，8 个 KV 头，头维度 128，BF16） | 320 KB | 10 GB | 40 GB |

这只是**一个请求**的量。同时服务 32 个用户，就乘以 32。所以哪怕有 1 TB 显存，长上下文、高并发的推理也很快会被 KV cache 占满。这就是这个方向即使在算力充足时也有价值的原因。

### 4.4 推理的两个阶段

- **Prefill（预填充）**：一次性处理整个输入，所有 token 并行计算。瓶颈在**算力**，影响**首字延迟（TTFT）**。
- **Decode（解码）**：一个一个地生成。每一步只算 1 个 token，却要把**全部权重和全部 KV cache 从显存里读一遍**。瓶颈在**显存带宽**，影响**每个 token 的生成耗时（TPOT）**。

**为什么说 decode 卡在带宽上**：H200 的显存带宽约 4.8 TB/s。8B 模型的 BF16 权重约 16 GB，光读一遍权重就要约 3.3 ms，再加上读 KV cache 的时间。这时 GPU 的计算单元大部分在空等数据。
所以减小 KV cache 不只是省显存，还能直接让每个 token 生成得更快：要读的数据少了。

## 第 5 章 从注意力的“形状”上省 KV

不改变“看全部前文”的做法，只减少每个 token 要存的东西。

| 方案 | 做法 | KV 大小 | 代表 |
|---|---|---|---|
| **MHA**（多头注意力） | 每个头都有自己的 K、V | 基准 | 原始 Transformer |
| **MQA** | 所有头共用一份 K、V | 除以头数 | 早期的 PaLM |
| **GQA** | 头分成若干组，每组共用一份 K、V | 除以每组的头数 | Llama 2/3、Qwen |
| **MLA** | 把 K、V 压缩成一个低维向量来存，用的时候再还原 | 比 GQA 还小很多 | DeepSeek-V2/V3 |

**顺带讲一下位置编码 RoPE**（因为 MLA 要单独处理它）：
注意力本身不知道 token 的先后顺序。RoPE 的做法是按位置把 q、k 各自“旋转”一个角度，这样 q·k 的结果就只和**两个 token 的相对距离**有关。
MLA 存的是压缩后的向量，而 RoPE 的旋转和压缩不能直接合并，所以 MLA 把一小部分维度单独拿出来做 RoPE，其余维度不带位置信息。
把现成的 GQA 模型转成 MLA 时，选哪些维度保留 RoPE 就成了难点，长上下文性能就是在这里丢的（见 `SURVEY_zh.md` §4）。

## 第 6 章 量化：用更少的位存数字

### 6.1 数字格式

| 格式 | 每个数占 | 说明 |
|---|---|---|
| FP32 | 4 字节 | 训练时的“标准精度” |
| BF16 / FP16 | 2 字节 | 现在模型权重和 KV cache 的默认格式 |
| FP8 | 1 字节 | H100/H200 硬件原生支持 |
| INT8 | 1 字节 | 整数，需要配一个缩放系数 |
| INT4 / INT2 | 0.5 / 0.25 字节 | 激进压缩 |

KV cache 从 BF16 降到 INT4，大小变为原来的 1/4。

### 6.2 怎么量化：一个例子

把 4 个数 `[0.12, -0.50, 0.33, 0.90]` 量化成 INT4（可用的整数是 -7 到 7）：

1. 找最大绝对值：0.90。
2. 算缩放系数：scale = 0.90 / 7 = 0.1286。
3. 每个数除以 scale 后四舍五入：0.93 → 1，-3.89 → -4，2.57 → 3，7.0 → 7。
4. 存下的是整数 `[1, -4, 3, 7]` 加上一个 scale。
5. 用的时候乘回 scale：`[0.13, -0.51, 0.39, 0.90]`。和原值相比有一点误差，这就是量化误差。

### 6.3 离群值问题，以及为什么要讲“粒度”

如果这组数里有一个 9.0，scale 就变成 1.29，0.12、-0.5、0.33 全部会被舍入成 0，信息就丢了。

解决办法是**让一个 scale 管的数少一点**，这就是量化粒度：

- per-tensor：整个矩阵共用一个 scale。最粗，最容易被离群值拖垮。
- per-channel：每个通道（每一列）一个 scale。
- per-token：每个 token（每一行）一个 scale。
- per-group：每 32 或 128 个数一个 scale。

**KV 量化的一个经典发现**（KIVI）：K 里的离群值集中在少数几个通道上，所以 **K 按通道量化，V 按 token 量化**。另外，最近的几十个 token 先保留高精度，攒够一组再一起量化。

### 6.4 三种量化不要混淆

- **权重量化**：压缩模型参数，量化一次，永久生效。
- **激活量化**：压缩计算过程中的中间结果。
- **KV 量化**：压缩 KV cache。**师兄说的“量化时机”主要是指这个，以及混合架构里递归状态的量化。**

## 第 7 章 剪枝：去掉不重要的部分

“剪枝”在不同语境下剪的东西不一样，先分清楚：

### 7.1 剪权重（模型压缩）

- 非结构化：把单个不重要的权重置零。压缩率高，但硬件很难真正加速。
- 半结构化：每 4 个权重里置零 2 个（2:4 稀疏），NVIDIA GPU 能加速这种模式。
- 结构化：整头、整通道、整层地删，删完模型确实变小。

### 7.2 剪 KV cache（本方向说的“标准注意力剪枝”主要是这个）

不改模型，只在推理时少存一些 token 的 K、V。

- **淘汰（eviction）**：删掉不重要的 token 的 KV，删了就找不回来。
  - **怎么判断不重要**：最常用的依据是注意力分数。一个 token 过去被关注得越多，越可能有用（H2O 用的是累计注意力）。
  - **attention sink**：开头几个 token 不管内容是什么，总是得到很大的注意力，删掉它们模型就崩。StreamingLLM 的做法是“开头几个 token + 最近一段窗口”。
  - **什么时候删**：可以在 prefill 后一次性删，比如 SnapKV 用 prompt 末尾的注意力来挑；也可以在 decode 中边生成边删，比如 H2O、R-KV。
- **稀疏读取**：KV 全部保留，但每一步只读最相关的一部分（比如 Quest）。省带宽、省计算，不省显存。
- **降级和卸载**：不删，而是把不常用的 KV 降成低精度，或者挪到 CPU 内存，需要时再取回。

**核心难点**：现在看起来不重要的 token，将来可能会用到。长思维链推理里经常要引用很早以前算出的中间结果，删错一个就可能全盘出错。

### 7.3 稀疏注意力（介于剪枝和改结构之间）

每个 query 只和一部分 key 算注意力：

- **固定模式**：滑动窗口（只看最近 4K 个 token），或者“局部 + 少量全局”。
- **动态选择**：每个 query 先粗略估计哪些块相关，再只对这些块算精确注意力。
- **可训练稀疏**：把“选哪些块”这个模块也一起训练，比如 DeepSeek 的 NSA，以及 DSA 里的 Lightning Indexer。

## 第 8 章 线性注意力：换一种算法，把历史压进一个矩阵

前面的方法都是在标准注意力上“省一点”。线性注意力则是**换掉 softmax**，从根本上改变计算方式。

### 8.1 推导

标准注意力的输出是 o_t = Σ_i softmax(q_t·k_i) v_i。softmax 要求先把所有相似度算出来再归一化，所以必须保留全部 k_i。

如果**去掉 softmax**，直接用 q·k 当权重（这里先忽略归一化）：

```
o_t = Σ_i (q_t · k_i) v_i
    = Σ_i v_i (k_iᵀ q_t)
    = ( Σ_i v_i k_iᵀ ) q_t        ← 利用矩阵乘法的结合律，把 q_t 提到外面
    =        S_t      q_t
```

其中 **S_t = Σ_{i≤t} v_i k_iᵀ** 是一个 d_v × d_k 的矩阵，这就是**记忆矩阵**（也叫状态）。

它可以一步一步累加：

```
S_t = S_{t-1} + v_t k_tᵀ       （写入：把当前 token 的“键→值”关联加进去）
o_t = S_t q_t                  （读取：用 query 去查）
```

这样一来：
- **不需要存任何 token 的 K、V 了**，只需要存一个固定大小的 S。
- 每生成一个 token 的代价是常数，和前文多长无关。
- 写成上面这样，它就是一个 **RNN**（循环神经网络）：一个状态一步步往后传。

### 8.2 用一个小例子理解“记忆”

d_k = 2，value 只有 1 维：

1. 写入 k1=[1,0] → v1=3：S = [3, 0]。
2. 写入 k2=[0,1] → v2=5：S = [3, 5]。
3. 用 q=[1,0] 查询：S·q = 3。正确，取回了 v1。
4. 用 q=[0,1] 查询：得到 5。正确。

**问题 1：同一个 key 想更新值，累加会出错。** 再写入 k3=[1,0] → v3=7，S = [10, 5]，查 [1,0] 得到 10，而正确答案是 7。

**问题 2：容量有限。** 2 维的 key 最多只有 2 个互不干扰的方向。第 3 个不同的 key 必然和前面的重叠，彼此干扰。所以记忆矩阵能精确存的东西大约只有 d_k 对，存多了就会互相串。这就是线性注意力**精确回忆能力差**的根本原因（大海捞针、多键检索都会失败）。

### 8.3 记忆矩阵的写法：一步步演进

研究“怎么写这个矩阵”，就是师兄说的“记忆矩阵”方向：

| 写法 | 公式（直觉版） | 解决了什么 | 代表 |
|---|---|---|---|
| 纯累加 | S ← S + v kᵀ | — | 原始线性注意力 |
| 加衰减（遗忘门） | S ← α·S + v kᵀ，α < 1 | 旧记忆逐渐淡出，给新记忆腾地方 | RetNet、GLA、Mamba-2 |
| Delta rule | S ← S + β (v − S k) kᵀ | 先查出“当前存的值”，只写入差值，同一个 key 可以被正确覆盖 | DeltaNet |
| Gated Delta | 衰减 + Delta | 两者结合 | **Gated DeltaNet（GDN）**，用于 Qwen3-Next |
| 测试时训练 | 把 S 换成一个小网络，每来一个 token 做一步梯度下降 | 记忆的表达能力更强 | TTT、Titans |

用 8.2 的例子验证一下 delta rule（β=1）：写入 k3=[1,0] → v3=7 时，先查出当前值 S·k3 = 3，差值 7−3 = 4，只把这个 4 写进去，S = [7, 5]。查 [1,0] 得到 7，正确。
实际上，**delta rule 等价于对“S k ≈ v”这个目标做一步梯度下降**，所以这条线又被称为“在线学习式记忆”。

### 8.4 状态空间模型（SSM）和 Mamba

SSM 来自控制理论：h_t = A·h_{t-1} + B·x_t，y_t = C·h_t。这也是一个“状态往后传”的递归。
Mamba 让 A、B、C 随输入变化（称为“选择性”），根据内容决定记什么、忘什么。
Mamba-2 证明了：**SSM 和带衰减的线性注意力在数学上是同一类东西。** 所以现在常把它们统称为“线性 / 递归层”。

### 8.5 训练时怎么办：并行 vs 递归

RNN 式的递归一步依赖上一步，训练时没法并行，GPU 利用率很低。
好在线性注意力还有一种等价的并行写法：把所有 token 的 q、k、v 拼成矩阵一次算完。
实际用的是两者结合的 **chunkwise（分块）算法**：把序列切成长度为 64 到 256 的块，块内用矩阵乘法并行，块与块之间用递归传递状态。
这正是师兄说的“变种注意力的算法”要解决的问题，第 10 章细讲。

## 第 9 章 混合架构：两种层搭配使用

### 9.1 为什么要混

| | 标准注意力 | 线性 / 递归层 |
|---|---|---|
| 精确回忆（大海捞针、复制前文） | 强 | 弱，记忆有限 |
| 长序列的代价 | KV 线性增长，计算量平方增长 | 状态固定，代价线性增长 |

取长补短：**大部分层用便宜的线性层，少数层保留全注意力，负责精确检索。**

### 9.2 怎么混

最常见的是**层间交替**：比如每 4 层里 3 层用 GDN、1 层用全注意力（3:1）。实验发现，大约 3:1 时检索能力就接近饱和了。

```
第1层  GDN
第2层  GDN
第3层  GDN
第4层  全注意力   ← 存 KV cache
第5层  GDN
...（重复）
```

代表模型有 Jamba（Mamba + 注意力）、MiniMax-01（lightning 线性注意力 + softmax 注意力）、Qwen3-Next（GDN + 门控注意力）、Kimi Linear（KDA + MLA）。

### 9.3 混合之后推理时缓存什么

- GDN 层：每层存一个固定大小的记忆矩阵 S，**每生成一个 token，都要把 S 原地改写一遍**。
- 全注意力层：照常存 KV cache，**这是唯一随长度增长的部分**。
- 所以 KV 总量大约降到传统模型的 1/4，但长上下文时这部分仍然是瓶颈。

两种缓存的量化、释放、剪枝时机为什么不同，见 `CONCEPTS_zh.md`。一句话总结：**KV 是“写一次、读很多次、按 token 存”，S 是“每步都改、所有信息混在一起”。**

## 第 10 章 算法与 kernel：为什么“理论上快”不等于“实际上快”

### 10.1 GPU 的内存层次

```
HBM（显存）：大（H200 有 141 GB），但慢（约 4.8 TB/s）
   ↕
SRAM（片上缓存）：小（每个计算单元只有几百 KB），但极快
   ↕
计算单元：tensor core 做矩阵乘法极快，做其他运算慢得多
```

**写高效 kernel 的核心原则**：尽量把数据搬进 SRAM 一次，在里面多算几步，少在 HBM 和 SRAM 之间来回搬；尽量把计算凑成矩阵乘，好用上 tensor core。

### 10.2 FlashAttention 的思想

标准注意力会生成一个 n×n 的相似度矩阵。n=128K 时，这个矩阵根本放不下。
FlashAttention 的做法：把 Q、K、V 切成小块搬进 SRAM，边算边用 **online softmax** 增量地更新结果，**从不在 HBM 里存完整的 n×n 矩阵**。结果是精确的，没有任何近似，但速度快好几倍，显存从平方级降到线性级。

**启发**：算法本身没变，只是计算顺序和数据搬运方式变了，速度就能差几倍。

### 10.3 线性注意力也需要类似的算法

8.5 讲的分块算法，难点在于：
- 加了衰减和 delta rule 之后，块内的计算不再是简单的矩阵乘，需要数学技巧把它改写成矩阵乘。DeltaNet 用的是 WY 表示和 UT 变换。
- 写好的 kernel 集中在开源库 **flash-linear-attention（fla）** 里，基本都用 **Triton** 编写。Triton 是一种用类 Python 语法写 GPU kernel 的语言，比 CUDA 容易上手。

**现在的一个限制**：只有当记忆更新对旧状态是“线性的”（数学上叫仿射）时，才能精确地分块并行。更复杂的记忆规则没法高效训练，见 `SURVEY_zh.md` §5。

### 10.4 稀疏注意力的 kernel

只算一部分块，听起来能省很多，但如果选中的块在显存里东一块西一块，读取效率会很差，实际未必更快。NSA 的一个重要贡献就是把“选块”设计成对硬件友好的形式：按块选，同一个 GQA 组的头共享选择结果。

## 第 11 章 推理系统里的几个概念

做这个方向一定会碰到推理框架，主要是 **vLLM** 和 **SGLang**。

- **连续批处理（continuous batching）**：多个用户的请求拼在一起算；谁先生成完谁先退出，新请求随时加入。
- **PagedAttention**：借鉴操作系统的内存分页，KV cache 按固定大小的“页”分配和回收，避免显存碎片。这是 vLLM 的核心技术。
- **前缀缓存（prefix caching）**：很多请求有相同的开头（同一个系统提示词、同一篇文档），它们的 KV 只算一次，大家共享。SGLang 的 RadixAttention 用前缀树来管理。
- **投机解码（speculative decoding）**：用一个小模型先猜几个 token，大模型一次性并行验证，猜错的部分丢掉（回滚）。传统 KV 回滚只要截断就行，递归状态则需要事先保存快照。
- **卸载（offloading）**：把暂时不用的 KV 挪到 CPU 内存甚至硬盘。

## 第 12 章 怎么评价一个方法

**质量：**

| 指标 | 测什么 |
|---|---|
| 困惑度（perplexity） | 语言建模能力，越低越好。**注意**：长上下文能力差的模型，困惑度也可能很好看 |
| 大海捞针（NIAH） | 在长文本里藏一句话，看能不能找出来。还有多针（MK-NIAH）等变体 |
| RULER | 一组长上下文测试的合集，包括检索、多跳追踪、聚合等 |
| MQAR | 多键联想回忆，专门测“记忆容量”，线性注意力研究常用 |
| LongBench | 真实的长文档任务 |
| AIME / MATH-500 / GPQA | 推理能力，生成长思维链 |

**效率：**

| 指标 | 含义 |
|---|---|
| TTFT | 首 token 延迟，主要由 prefill 决定 |
| TPOT | 每个输出 token 的耗时，主要由 decode 决定 |
| 吞吐 | 每秒总共生成多少 token，和能同时服务多少请求有关 |
| 显存占用 | 权重 + KV cache / 状态 + 激活 |

**好论文的标准**：在**同等显存或计算预算**下，质量更好；或者在质量不降的前提下，显存和速度更省。还要报告**真实的运行速度**，而不只是理论计算量。

你提到师兄那边有 H200，总显存约 1 TB，算力基本不是限制了。这会改变什么：

- **以前做不了、现在能做的**：从头预训练中等规模的模型来验证新的记忆规则或混合方案；在 70B 级模型上做转换和蒸馏；128K 长度的长上下文微调。综述里第 2 节（混合架构选层）和第 4 节（转 MLA）的缺口，原本因为算力被我标成“吃力”，现在都可行了。
- **不变的**：KV cache 和递归状态在长上下文、高并发下照样是瓶颈（见 4.3），所以这个方向的研究价值不受影响。
- **真正的门槛**转移到了**工程能力**上：会不会写 Triton kernel，能不能改 vLLM / SGLang。`problem.md` 里的算力约束我已经按新情况更新了。
