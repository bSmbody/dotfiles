# 给 GPT 的第二轮选题 prompt（新开对话，整段复制粘贴）

---

你是一位资深机器学习研究员，正在帮一名刚入学的博士生选题。他的组里有大约 1 TB 显存的 H200 集群，算力基本不受限；但他本人是新手，工程上要靠组里支持。请**联网检索到今天为止的最新论文**（arXiv、OpenReview、会议论文集），提出**方法层面**的研究 idea，目标是 NeurIPS / ICML / ICLR 主会。

**这是第二轮。** 第一轮你（或另一个模型）生成了 1000 条候选和精选的 10 个。我们对其中排名前 5 的做了独立的对抗式审稿，审稿人自己读正文、自己查新：4 个被否决，1 个需要大改。本轮的目标不是数量，而是**少而精**：最多 3 个 idea，每个都要经得起领域专家逐条挑刺。

## 一、第一轮失败的三种模式（本轮必须逐条规避）

1. **先选工具，再找问题。** VarPro、Tensor-Train、NUFFT、Taylor 模型、最大耦合、Parareal、RTLS……把经典数学工具搬到注意力上，却没先算成本账。
   - NUFFT 方案：RoPE 只有 d/2 ≤ 64 个频率，2N 点 FFT 的计算量和直接用 tensor core 做矩阵乘相当，搬运的字节反而比不压缩的 K 还多。
   - Tensor-Train 方案：只能替代本来就很便宜的背景求和，top-k 选择所需的逐 token 扫描省不掉。
   - 这两个都是不做实验就能判死的。
2. **关键假设没有量级证据。** 例如 MLA 量化方案假设 score 和 value 的误差耦合很强；实测中 latent 只贡献约 7.5% 的 logit（RoPE 路径造成的损害是它的 2–7 倍，见 arXiv 2610.33625、2609.36760）。又如假设码组合统计的 TT 秩很低，却没有任何证据。
3. **检索漏掉最新工作。** 第一推荐的 TTT 方案被 3 天前发布的 ParaTTT（2610.38255）覆盖了大部分。另有多篇近 3 个月的近邻没被引用：Transformer-VQ、RAM-Net（2610.11214）、WitCert（2607.28699）、Runtime Observability（2608.05863）、EPIG-Tree（2609.20004）、Palu（2407.21118）。

## 二、本轮的硬性要求（缺任何一条，该 idea 作废）

**A. 问题优先。** 每个 idea 必须从一个**有测量数字的瓶颈**出发：引用某篇论文的具体章节和数字，说明在什么模型、什么长度下，时间或显存花在了哪里、花了多少。不允许从"某个数学工具很漂亮"出发。

**B. 成本账。** 凡是声称更快或更省的，都要给出一张理论账：每生成一个 token 的 FLOPs、HBM 读写字节数、额外的工作区，并与**当前最强的融合实现**对比。可参考的对比对象包括 FlashAttention/FlashDecoding、Palu 式的融合重建、FP8/INT4 KV、vLLM/SGLang 的分页 KV。按 H200 的参数计算（HBM 约 4.8 TB/s；BF16 dense 约 1 PFLOP/s），写清楚 compute-bound 和 memory-bound 的分界点。**账算不过来的，不要提。**

**C. 量级证据。** 每个 idea 列出 1 条最关键的假设，并给出已发表论文中实测到的**量级**（论文、章节、数字），说明这个量级足够大、能让方法有收益。如果找不到实测量级，就把"测这个量级"写成第一周的 kill test，并在排序中降级。

**D. 近 30 天检索。** 对每个 idea，单独检索最近 30 天的 arXiv，列出你检查过的、最接近的 3 篇近期论文，以及它们与本方案的差别。找不到确切论文时写"未找到"，**不要编造标题或编号**。

**E. 一句话死刑测试。** 写正文之前，先用一句话写出领域专家最可能用来否掉它的反对意见，然后在正文里正面回应。回应不了的，就换一个 idea。

## 三、已确认的事实（作为约束，并自行核实）

1. 在推理任务上，只要保住 prompt，按头随机淘汰推理过程的 KV，效果就能和 SnapKV、R-KV、VaSE、TriAttention 相当（2609.03430）。但单次 passcode 远距检索是重要反例。
2. 精确卸载（把所有未删的 KV 取回并参与计算）不损伤质量（2605.09490）；但选择性回读并不自动无损。
3. 只要 KV 存在 BF16 舍入级别的差异，83% 的贪心后缀就会分叉，首次分叉的中位位置在第 88 个 token（2607.28495）。不同运行配置的舍入差异可让超过 90% 的推理轨迹分叉（2506.09501）。
4. 在 DCKV（2610.36950）设定的模型和长度下，bf16 KV 时 GDN 状态约占单个请求显存的 17%（4K）和 7%（11K）；KV 被压缩之后，状态的占比会反过来变大。
5. 在预训练混合模型上，清零线性层状态对已缓存前缀的 NIAH-S1 几乎没有影响（≤1 点，2608.30386）。这不代表多针检索或纠错也不依赖递归状态。
6. 递归状态快照一次性存成 INT8，可以近乎无损地压缩 3.88 倍（2608.30386）。活跃状态仍需高精度。
7. 纯滑动窗口注意力加上 RL，数学成绩只比全注意力低 0.4 pp（1.5B）和约 1 pp（4B）（2606.11634）。注意该对比的训练步数并不相同。
8. 生产级稀疏 indexer 与精确 top-k 的重合度约为 60%，而且选择偏差对下游效果的影响会饱和（2512.03494）。
9. GDN/KDA/DeltaNet 的擦除向量就是 β·k。GDN-2、EDA、QED 已经把擦除和 key 解耦。
10. 长推理中，高熵 token 多是连接词或分叉点，许多数值片段的熵很低（2506.01939）。不能用熵来衡量事实的价值。

## 四、已被否掉的方向（不要再提，除非能明确说明怎样绕过死因）

| 方向 | 死因 |
|---|---|
| KV 淘汰的"事实覆盖度 / k 份拷贝 / 意外度 / 重算代价"打分 | 预算紧时覆盖不了；用熵加权会适得其反；中间结果很快失效 |
| 用"双胞胎解码"给每次淘汰单独算功劳 | 见事实 3 |
| 混合模型中借用状态精度、推迟 KV 降级 | KVpop、LazyEviction、BreadthKV 已有；"借出"永远还不回来 |
| 删全注意力 KV 时看 GDN 是否还记得 | LoLA、ContextCite、AT2 已有；见事实 5 |
| 记忆矩阵按读取频率或重要性保护记忆；子空间遗忘的 RLS | Palimpsa 已有；在叠加存储里没有"槽位"；均匀遗忘下的精确分块 RLS 已经存在 |
| 稀疏 selector 加探索块 / 自适应聚类抽样 | 短长度的稠密 teacher 就够了；见事实 8 |
| SSM/GDN 状态剪枝、快照压缩 | 见事实 4 和 6 |
| PQ 码组合统计 + Tensor-Train 读取 | 背景求和已接近饱和（与全注意力只差 0.01）；省不掉 top-k 扫描；Transformer-VQ 和 RAM-Net 已经有按码统计的精确 softmax |
| MLA 量化的 score/value 联合误差证书 | latent 只贡献约 7.5% 的 logit；2–4 bit 下按格子求最坏情况的界本身就空洞（WitCert） |
| 低秩 pre-RoPE K + NUFFT 直接打分 | 频率太少，FFT 不划算；Palu 的融合重建已经很快 |
| 图 RL 中共享 rollout 的 GLS 加权 | 只是 GraphPO 汇总权重的教科书式调参；EPIG-Tree 已有梯度 MSE 视角；标准化后的优势不是线性的 |
| VarPro 消元用于两层 TTT 快记忆 | ParaTTT 已做逐 token 精确联合损失 + 并行 kernel；近端 ridge 读出 = Longhorn + MesaNet；内部拟合误差可能和下游召回反向变化（2602.21204） |
| 按"修复集"给混合模型分配全注意力层（C14） | 模拟评审约 3/10；在相同字节下可能只相当于"随机挑最好的那组层"；LightTransfer（2410.13846）和 ReasonAlloc（2606.11164）为近邻 |

## 五、方向

起点是**长生成推理（长思维链）的记忆与计算效率**，涉及 KV 的淘汰、量化、卸载、读取，线性注意力 / SSM / 混合架构，以及记忆矩阵的更新规则。**你可以跳到相邻方向**，前提是它从一个真实的、有数字的瓶颈出发，并说明为什么那里比上面更有空间。可能的例子（仅供启发，不必采用）：
- 长推理服务中真正的端到端瓶颈：调度、prefill/decode 干扰、超长生成的 tail latency；
- 训练侧的长上下文 / 长 rollout 的记忆成本，例如 RL 训练中长 rollout 的 KV 和显存；
- 模型主动管理自己的上下文：折叠、摘要、检索。

## 六、交付内容

**第 0 部分：瓶颈地图。** 用 5–10 句话列出你找到的、带数字的长推理效率瓶颈（每条都要有论文、章节和数字），并标注每个瓶颈有多拥挤。

**第 1 部分：最多 3 个 idea。** 每个 idea 严格按以下格式写：
1. **一句话**（不超过 30 字）
2. **从哪个瓶颈出发**：论文、章节、数字
3. **一句话死刑测试**，以及你的回应
4. **核心机制**：讲清"什么对应什么"。如果借自别的领域，写明源头论文，以及它在源领域为什么有效
5. **成本账**：FLOPs、字节、工作区，对比最强的融合实现；compute-bound 和 memory-bound 的分界点
6. **关键假设及其量级证据**
7. **近 30 天最接近的 3 篇论文**，以及与它们的差别；再加上更早的 2 篇最接近的工作
8. **Baseline**（必须包括同字节下的保 prompt 随机淘汰和 FP8/INT4 KV）**和 benchmark**
9. **一周 kill test**：用多少卡、测什么、看到什么结果就放弃
10. **工程量**：需不需要新 kernel；新手难在哪里
11. **为什么这个 idea 比上表中被否掉的方向更有机会**

**第 2 部分：独立审稿。** 换成一位**专门研究这个子方向、每天读 arXiv**的审稿人身份，对每个 idea 重新检索一次。用 3–5 条反对意见逐条打分，标注为致命、严重或轻微，给出 1–6 分的评分，并判断保留、修改还是放弃。被判"放弃"的必须替换，直到剩下的每个都没有未解决的致命意见。

**第 3 部分：推荐。** 选出 1 个最推荐的 idea，给出前 4 周计划。第 1 周必须是 kill test。

**全文要求：不要编造实验数字和引用。不确定的地方明确标出。宁可只交 1 个过硬的 idea，也不要交 3 个勉强的。**
