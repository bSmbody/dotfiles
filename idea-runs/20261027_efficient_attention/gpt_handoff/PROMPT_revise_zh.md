# 给 GPT 的修改 prompt（在生成第一轮 1000 条候选的同一个对话里粘贴；新对话也能用）

---

我们对你精选的 10 个候选做了**独立的对抗式审稿**。前 5 个每个都由一位单独的审稿人审查，审稿人自己读正文、自己检索新论文，不采信你的自审结论。下面是结果。请根据这些意见**修改或放弃**它们，再用同样的标准检查后 5 个。

**原则：只做实质修改，不做措辞修补。** 如果某条致命意见无法用一个具体的机制改动加上证据来回应，就直接放弃，不要换个说法保留。宁可全部放弃，也不要勉强保留。

## 一、前 5 个的审稿结论

### B-C0005「先解输出层再更新记忆内部」：需要修改（新颖性）
- **最强反对**：ParaTTT（arXiv 2610.38255，2026-10-28 发布，你没有引用）已经对两层记忆做**逐 token 的精确联合损失**在线梯度下降：隐藏层能因读出误差得到功劳，读出用精确的 gated delta rule，训练用分块并行的 GLA/GDN kernel。它还把"MesaNet 式的最优读出"列为自己的下一步（附录 A）。
- **你的组件都有先例**：argmin_B ||BΦ − V||² + λ||B − B_old||² 就是 Longhorn（2407.14207）式的近端在线回归更新，只是搬到了 chunk 级、作用在特征上而不是 key 上；MesaNet 和 GKA 已经读出精确的 ridge 解。新的部分只剩"每个 chunk 做一次近端 ridge 读出，再对内部层走一步 envelope 梯度"这个组合。
- **VarPro 的理论不覆盖你的用法**：VarPro 的收敛收益是离线、多次迭代、样本数大于特征数时得到的。你只走一步，本质上是块坐标下降。
- **你的 kill test 指标无效**：在固定 KV 上看重构误差或未来 query 误差，并不能代表下游效果。2602.21204 §4.1 发现，推理时多走几步、把内部损失压得更低，反而会损害下游 LLM 表现。ParaTTT 更精确的 N=5 轨迹，也让 32K NIAH 从 16.0 降到 5.8。支持你的一方：Modular TTT（2608.07110）把深层快记忆输给浅层的原因，归结为单步更新下的层间耦合。
- **对 LaCT 的描述有误**：LaCT（2505.23884）用的是点积内部损失 −f(k)ᵀv 加 L2 权重归一化，不是 MSE 加近端项。你提的"同 chunk / 近端 Muon"基线是自己构造出来的变体，不是 LaCT。B009（figshare 上的 Delta TTT 逆桥）不在 arXiv 上，无法核实。
- **适定性问题**：chunk 很小时样本数少于特征数，ridge 只靠近端项维持适定。你的评测也只有固定 KV、MQAR 和 RULER，没有长生成。

**修改必须做到**：
1. 把 ParaTTT 作为最接近的已有工作和主 baseline，说明一个 chunk 串行的方法凭什么能赢过逐 token 精确又能并行的方法。或者把贡献改成在 ParaTTT 框架内加入"最优读出"；但这正是它公开宣布的下一步，撞车风险必须评估。
2. kill test 改用下游指标：多针 / 多 query 召回、长生成。固定 KV 的重构误差只能作为诊断。
3. 正确描述 LaCT 并据此重设基线；说明小 chunk 下的适定性。

### A-C004「把整段记忆变成小矩阵链」：否决
- PQ-HSA（2609.33746）的逐 token 码扫描主要服务于 **top-k 选择**，选择带来 +0.16 macro 的提升。它的背景项用列表均值，在 1% 预算下离全注意力只差 −0.010。TT 收缩只能给出求和，给不出 token 身份，所以扫描和有意义的误差都省不掉。
- Transformer-VQ（2309.16354）已经用按码计数和按码 value 和，在不逐 token 扫描的情况下算出精确 softmax。RAM-Net（2610.11214）附录 A.5 的硬写入极限，正是乘积量化 key 上带联合地址计数和 value 均值的 softmax。
- "低 TT 秩"没有任何证据。

### A-C007「让误差检查记住键值的联系」：否决
- RAQ-MLA（2610.33625）§3：在 GLM-4.7-Flash 上，latent 内容项只占 7.5% 的 logit 归因。QuantMLA（2609.36760）§2.2：在 6 个 MLA 模型上，RoPE 路径造成的损害是内容路径的 1.9–6.9 倍。所以利用 score/value 耦合，只能收紧误差里的次要项。
- WitCert（2607.28699）显示，2–4 bit 下按格子求最坏情况的界本身就是空洞的；求这个格子上的精确最坏值也低不过格子真实的最坏情况。Runtime Observability（2608.05863）已经在运行时对 MLA latent 缓存做证书，你没有引用。

### A-C118「不用还原整片键也能加上位置」：否决
- RoPE 只有 d/2 ≤ 64 个频率，即每个求和只有 32–64 个源点。按 FINUFFT 自己的成本模型（1808.06736 §3.1.1、Remark 2），源点数远小于输出数时，直接求和（矩阵乘）更好。
- 每个秩分量、每个 query 头都要做一次 2N 点 FFT。在 N=128K、r=32、fp32 下，每个 query 头每一步约 64 MB，比直接读取未压缩的 bf16 K（约 32 MB）还多。
- Palu（2407.21118 §4.5.2）已经做了融合的"重建 + RoPE + 点积"kernel。RelFlexformer 的 Lemma 3.3 本身就支持直接求和这个结论。

### C0102「共享一次结果不把它当成多次证据」：否决
- 本质上是用教科书式的带偏差约束 GLS，替换 GraphPO（2606.18954）那一个汇总权重 w。EPIG-Tree（2609.20004）已经把 Greensmith 式的"梯度 MSE ≠ 值 MSE"引入树形 rollout，并给出分配律。
- GraphPO 的优势会除以组内标准差，还有 (1 − η) 系数、效率项和 PPO 裁剪，"终局结果 → 梯度的线性算子"并不存在。
- 和长生成的记忆管理无关。

## 二、请你做的事

**第 1 步：处理前 5 个。** 每个只能有两种结论：
- **放弃**：用一句话写清楚死因，并写出你从中吸取的教训，供后续选题参考。
- **大改后保留**（只适用于你能给出实质改动的情况）：按下面的"修改卡"格式重写。

**第 2 步：用同样的三项检查过一遍后 5 个**（A-C002、A-C005、A-C064、B-C0007、B-C0002）：
1. **成本账**：每个 token 的 FLOPs、HBM 字节、工作区，对比最强的融合实现（FlashDecoding、Palu、FP8/INT4 KV、SANTA 等）。按 H200 算（约 4.8 TB/s，BF16 dense 约 1 PFLOP/s）。账算不过来就放弃。
2. **量级证据**：关键假设有没有已发表的实测量级？没有的话，能不能在一周内测出来？
3. **近 30 天检索**：重新检索最近 30 天的 arXiv，列出最接近的 3 篇。特别核查这些近邻：Nectar、Delta Attention、LiteCache、SANTA、JSSA、H-CGA、quasi-DEER/ELK、ParaRNN、GradLev、GSA-2、Gated KalmaNet。
然后给出保留、大改或放弃的结论。

**第 3 步：修改卡格式**（每个保留的 idea 一张）：
1. 一句话（不超过 30 字）
2. **逐条回应审稿意见**：原意见 → 具体改动 → 支持改动的证据（论文、章节、数字）。不允许只改措辞。
3. 修改后的核心机制，以及"什么对应什么"
4. 成本账
5. 关键假设及其量级证据
6. 近 30 天最接近的 3 篇论文及差别
7. Baseline（必须包括同字节下的保 prompt 随机淘汰和 FP8/INT4）和 benchmark（必须有下游任务，不能只有代理指标）
8. 一周 kill test：用多少卡、测什么、看到什么结果就放弃
9. 修改后的自评：1–6 分，以及剩余的最大风险

**第 4 步：总结。** 列一张表，包含 10 个候选的最终结论、一句话理由、修改后的评分。如果最后一个都没保留，就直说，并写出这 10 个失败共同说明了这个领域的什么规律，以及下一轮应该往哪里找。

**要求：不要编造实验数字或引用；不确定的地方明确标出。**
