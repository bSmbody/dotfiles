# 给 GPT 的选题 prompt（直接整段复制粘贴）

---

你是一位资深的机器学习研究员，正在给一位刚入学的博士生选题。他的组里有约 1 TB 显存的 H200 集群，算力基本不受限，但他本人是新手，工程上需要组里帮忙。请你**联网检索到今天为止的最新论文**（arXiv、OpenReview、各大会议论文集），提出**方法层面**的研究 idea，目标是 NeurIPS / ICML / ICLR 主会档次。

## 一、大方向（可以突破，但先读懂）

起点是**高效注意力与长生成推理的记忆管理**：长思维链推理会生成几万个 token，KV cache 是边生成边涨的，于是问题变成历史信息留哪些、用什么形式存（精确 KV、量化 KV、线性注意力的递归状态）、放在哪（GPU / CPU）、存多久。涉及的子领域包括：
- 标准 softmax 注意力的 KV 淘汰、量化、卸载、稀疏读取；
- 变种注意力，即线性注意力 / SSM / Gated DeltaNet（GDN）/ MLA / 可训练稀疏注意力（NSA、DSA）的压缩；
- 混合架构：多数层用 GDN，少数层用全注意力，例如 Qwen3-Next、Kimi Linear。在这类架构里，KV 和递归状态的量化时机、释放时机都和传统模型不同；
- 记忆矩阵的更新规则（delta rule、RLS、TTT 等）；
- 这些结构的高效算法与 kernel。

**如果你判断上述方向整体太拥挤，可以提出相邻的、更有潜力的方向。** 但要说明为什么更有潜力，以及它和上面的问题有什么关系。

## 二、已经确认的事实（请当作约束使用，并自行核实）

1. 在推理任务上，只要保住 prompt，对推理过程的 KV 按头随机淘汰，效果就和 SnapKV、R-KV、VaSE、TriAttention 相当（arXiv 2609.03430）。现有的逐 token 打分思路可能整体有问题。
2. 推理模型在 KV 淘汰下的准确率，取决于**被永久删除**的比例，而不是 GPU 上保留了多少。卸载到 CPU、需要时取回的 token 不伤害准确率（2605.09490）。
3. 缓存上舍入级别的差异，就会让 83–90% 的长推理轨迹在几十到几百个 token 内走上另一条路径。所以任何依赖"两条轨迹保持一致"的方法基本不可行。
4. bf16 KV 下，混合模型的 GDN 状态只占单个请求显存的约 17%（4K token）和 7%（11K token）。显存的大头是全注意力层的 KV（2610.36950）。
5. 预训练混合模型里，把所有线性层的状态清零，NIAH 只变化 ≤1 点（2608.30386）。检索几乎全部走注意力层，GDN 不是检索的备份。
6. 递归状态快照一次性存成 INT8 就能近乎无损压缩 3.88 倍（2608.30386）。状态压缩的 baseline 已经很强。
7. 只用纯滑动窗口注意力加 RL，数学成绩只比全注意力低 0.4 pp（1.5B）和 1 pp（4B）（2606.11634）。on-policy 训练可能抹平架构上的差异。
8. 生产环境的稀疏注意力 indexer 每步漏掉约 40% 的精确 top-k，而且多数无害（2512.03494）。
9. GDN、KDA、DeltaNet 的擦除向量就是 β·k，没有偏离 key 方向的分量。
10. 长推理模型写入自己算出的中间结果时，熵几乎为零；高熵的是 "wait"、"however" 这类连接词（2506.01939）。

## 三、已经被否掉的 idea（请不要重复提出，除非你能明确说明怎样绕开它们的死因）

| 被否的 idea | 死因 |
|---|---|
| KV 淘汰时按"事实覆盖度"或"k 份拷贝"来保留 | 预算紧时做不到给每个事实都留足拷贝；按写入时的意外度加权会适得其反（见事实 10） |
| 按"重新推导代价"（DTR 式）给推理步骤估价 | 中间结果一两句后就不再被用到；KV 被删后模型会陷入循环，而不是重新推导 |
| 用"双胞胎解码"给每一轮淘汰单独算功劳 | 见事实 3 |
| 混合模型里先借用状态精度、推迟 KV 降级，之后再还 | 推迟决策已有 KVpop、LazyEviction、BreadthKV；而且新 KV 每一步都在到达，借出去的精度永远还不回来 |
| 删全注意力 KV 时，看 GDN 是否还"记得"这条信息 | 同一个头内的版本已有 LoLA；用随机联合遮挡估价已有 ContextCite、AT2；而且见事实 5 |
| 记忆矩阵按"读取频率"（LRU/LRUA）或持续学习的重要性来保护记忆 | 已有 Palimpsa；在叠加存储下没有"槽位"可言；见事实 9 |
| 在子空间上遗忘，让 RLS 记忆可以分块并行 | 均匀遗忘的精确分块 RLS 已经存在；在 chunk 边界做一次满秩修正就能达到同样效果 |
| 给稀疏 selector 加探索块，或用自适应聚类抽样 | 短长度的稠密 teacher 就能便宜地提供精确信号；见事实 8 |
| 按输入自适应地剪枝 SSM/GDN 状态，或压缩前缀快照 | 见事实 4 和事实 6 |

## 四、目前唯一存活的候选（你可以批评、改进，或提出更好的替代）

**C14：按"修复集"给混合模型分配全注意力层**
- 思路：把 Qwen3-4B 转成 GDN 混合模型，在学生自己生成的长推理轨迹上做 on-policy 蒸馏，但只训练 GDN 路径，冻结 teacher 的注意力路径，这样"全部换回全注意力"就严格等于 teacher。然后对每个残留的错误，用 delta debugging 找出"最少要把哪几层换回全注意力才能修好它"，把全注意力优先分给修好错误最多的层，层数 K 由数据决定。
- 头条主张：用 K ≤ 6 层全注意力，达到 Opal 每 4 层留 1 层（9/36）的 AIME 成绩，让随长度增长的 KV 至少减少 33%。
- 模拟评审给出 4/4/3，录用把握约 3.2/10。核心弱点有三个：
  - 没有在**相同 KV 字节数**下，和"Opal 9/36 + FP8/INT4 + 长推理淘汰"做对比，也没证明两种做法可以叠加；
  - 提升刚好卡在噪声边缘；
  - 事实 7 提示：联合训练之后，选哪几层可能根本不重要。
  - 第三版补上了"相同 KV 字节数下和压缩对比"，但录用把握反而降到 2.7/10。原因有三个：
    - 在预测门槛上，它只相当于"16 组随机分配里挑最好的"；
    - 漏引了 LightTransfer（arXiv 2410.13846），这篇在长推理上做层级的混合转换，并且和 SnapKV 叠加；
    - 漏引了 ReasonAlloc（2606.11164），这篇不需训练、按层分配长推理解码的 KV 预算。

## 五、各方向必须比较的 baseline（新 idea 请从这里挑）

- **长推理 KV 淘汰**：随机淘汰（2609.03430）、H2O、SnapKV、R-KV、KVP、ForesightKV、DistillCache、KVpop、LazyEviction、BreadthKV
- **混合模型的注意力 KV**：GateSight、HeadWiseKV、LoLA、LESS、SWAX
- **递归状态压缩**：DAMP、STEPQuant、PACE、LeapQuant、DASC，以及一次性 INT8
- **记忆矩阵**：GDN、GDN-2、EDA、Palimpsa、QED、MesaNet、Bayesian Layer、Preconditioned DeltaNet、Gated KalmaNet；评测用 MQAR、RULER MK-NIAH
- **混合选层**：Opal、KL-guided、FlashMorph、DASH、DtR、PostNAS、Super Apriel、HALO、NLL-guided
- **可训练稀疏注意力**：NSA、MSA、SAS、SpotAttention、Lightning Indexer，以及随机路由对照

## 六、你要交付的内容

请先用 5–10 句话判断：**这个领域里哪些子方向已经拥挤，哪些还有空间。** 要给出证据，也就是具体论文。

然后提出 **5 个 idea**，按你估计的潜力排序，至少 1 个不在第一节列出的子领域内。每个 idea 严格按以下格式写：

1. **一句话**（不超过 30 字，不用行话）
2. **要解决的具体失败**：现有方法在什么设定下、具体怎么失败，引用你读过正文的论文。
3. **核心机制**：最好是从别的领域迁移过来的机制，写清源头论文，以及它在源领域为什么有效。要讲清楚"什么对应什么"，不需要写公式。
4. **最接近的已有工作和差异**：至少列 2 篇，并做一次近 12 个月的检索，证明没人做过。**如果你找不到确切的论文，就说"未找到"，不要编造论文标题或编号。**
5. **为什么可能成立**：最关键的一条假设，以及支持它的证据。
6. **Baseline 和 benchmark**：从第五节挑，再补上你认为缺的。
7. **一个便宜的 kill test**：一周内、少量 GPU 就能跑完，能判断这个 idea 该不该继续。写清楚"看到什么结果就放弃"。
8. **主要风险**：结合第二节的事实，逐条检查会不会撞上。
9. **工程量**：需要不需要写新的 CUDA/Triton kernel？对一个新手来说，难点在哪里？

## 七、自我审查（必须做）

每个 idea 写完之后，请扮演一位**专门挑刺的领域内审稿人**，用 3 句话给出最强的反对意见。然后判断这个 idea 该**保留**、**修改**还是**放弃**。被判"放弃"的，换一个新的补上，直到 5 个 idea 都通过自审。

最后给出你最推荐的 **1 个 idea**，以及它前 4 周的执行计划。
