# Toward a Better Understanding of Probabilistic Delta Debugging

## What this paper does
Analyzes ddmin, the classic delta-debugging algorithm that shrinks a failure-inducing list of elements to a 1-minimal sublist that still exhibits a property psi, and ProbDD, its Bayesian variant that keeps a per-element probability of being essential and deletes the subset with highest expected reduction gain. It shows ProbDD's probabilities act as monotone counters, proposes the simpler counter-based CDD, and reports that ProbDD is faster than ddmin at the cost of not guaranteeing 1-minimality.

## Goal-by-goal answers
### Goal: What is the core mechanism of ddmin / ProbDD, what does it return, and what does each query cost?
Input: a list L that exhibits psi, and a predicate psi(sublist) -> T/F (one "test" per call). ddmin partitions L into subsets of size s, tests each subset alone and each complement; when one keeps psi it recurses on it, otherwise it halves s; it ends with a 1-minimal list, meaning removing any single element loses psi [full text, Section II-A]. ProbDD gives each element a probability l.p of being essential, picks the subset maximizing expected gain |S| * prod(1 - l.p), and after a failed deletion raises the probabilities of the elements in S by factor 1/(1 - prod(1 - l.p)) [Section II-B, Algorithm 1]. The bottleneck of ddmin is low-success queries (complement queries and revisits); ProbDD wins by avoiding them [Section IV-F].

### Goal: What assumptions does it rely on, and what guarantees break?
The output is a minimal property-preserving subset with respect to a test oracle; minimization is NP-complete, so the algorithms return a local (1-minimal) optimum, not a global one [Section I, contribution list]. ProbDD skips revisits, so "the deletion of a certain subset may enable a previously tried subset to become removable" and the result is not always 1-minimal (1.11% of 6,871 runs on BM_C, ~1.49 extra removable elements); wrapper frameworks iterate to a fixpoint to recover it [Section IV-G]. Its theoretical analysis assumes the list size divides the subset size [Section III-A1]. The paper does not treat flaky (non-deterministic) tests; correctness assumes psi is a deterministic predicate.


### Goal: Does ddmin's 1-minimality guarantee depend on monotonicity, and how do wrappers recover minimality lost by skipped revisits?
ddmin returns "a minimal subset of L that still preserves psi, from which excluding any single element will make the minimal subset lose psi", and it terminates only when no subset can be divided further, i.e., after testing at single-element granularity [full text, Section II-A, Step 3]. That terminal property is checked by executed tests relative to the predicate, so it holds without monotonicity; what can fail is global minimality (Section I). ProbDD skips revisit queries, and "the deletion of a certain subset may enable a previously tried subset to become removable", leaving 1.11% of runs on BM_C non-1-minimal; wrapper frameworks (Picireny, Chisel) "employ iterative loops to achieve a fixpoint", which recovers the missed reductions [Section IV-G].
