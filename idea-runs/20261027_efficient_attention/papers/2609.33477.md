# Just Let Linear States Forget the Distant Past: Prefix Caching via SuffixReplay for Hybrid LLMs

## What this paper does
SuffixReplay is an SGLang prefix-caching system for hybrid LLMs that stores no linear-attention state checkpoints. It keeps a sparse set of the linear layers' input hidden states ("anchors", layer-wise and token-wise sparse) and, on a hit at any 64-token page boundary, approximates the state by replaying a short recent suffix, relying on decay to make the distant past negligible. On OLMo-Hybrid-7B, Qwen3.5-4B and Qwen3.6-27B-FP8 it retains >=94% of full-recompute quality while storing 0.36-0.51x the state bytes of SGLang's native cache.

## Goal-by-goal answers
### Goal: What does a hybrid state checkpoint cost relative to KV, and how does SuffixReplay bound storage and replay?
In Qwen3.5-4B one linear-attention state checkpoint is about 49 MiB versus about 32 KiB of KV per token, roughly 1,500x [full text, Section 1]. SGLang stores one checkpoint every 8192 tokens by default; SuffixReplay caps anchor storage at B_ckpt/8192 per token (R2) and replays k = min(0.05 n, k_max) anchors [Sections 3.1, 4.3]. Smaller SGLang prefill chunks to densify checkpoints quadruple state bytes per cached token at 2048 [Section 7.7, Table 5].
### Goal: Where does suffix replay fall short, by its own account?
"SuffixReplay relies on linear-attention states progressively forgetting earlier inputs and therefore does not directly apply to recurrences that preserve all past contributions"; the replay budget is model dependent and calibrated offline: the Qwen models meet the quality target at k=128 whereas OLMo-Hybrid-7B needs k=512, and OLMo still retains only 91.4% on RULER and 95.9% on LongBench QA [full text, Sections 1, 4.3, 7.6, 9].
