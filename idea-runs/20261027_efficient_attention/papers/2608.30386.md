# DASC: Decay-Aware State Compression for Hybrid Linear-Attention Serving

## What this paper does
Compresses recurrent-state checkpoints used for prefix caching in hybrid models (Qwen3-Next GDN, Kimi-Linear/Kimi-K3 KDA). It derives per-unit "retention horizons" from the decay parameters in the weights, keeps only long-horizon heads (GDN) or key channels (KDA) in a ragged checkpoint, and on reuse zero-fills omitted units (dasc-nr) or refreshes them by replaying a bounded suffix (dasc-wr). Implemented in SGLang; 1.32-2.22x checkpoint compression, TTFT down 16-42%.

## Goal-by-goal answers
### Goal: What mechanism selects which recurrent-state units are removed, and is the selection fixed or input-dependent?
Static. The input-dependent gate input a_t is replaced by one fixed representative value a_s per model, giving a static log-decay g_s and horizon H_s = ln(eps)/g_s; units with H_s > W_max are kept via a mask "constructed once offline and ... independent of serving requests" [full text, Sections 3.3, 4.1, Eqs 2-3]. The static horizon correlates with empirical horizon (Spearman ~0.80-0.90) but only 0.44-0.63 with observed state magnitude, and the authors say it is "a ranking heuristic ... rather than a complete importance measure" [full text, Section 3.4, Table 1b].
### Goal: What does it report as its limitation on long-context recall under state pruning?
NIAH-S1 is insensitive (zeroing all linear states changes it <=1 point because full-attention KV carries retrieval) [full text, Section 3.2, Table 1a]; the authors state selection "must be conservative" because states matter for multi-key, aggregation and reasoning tasks [full text, Section 1]. At larger W_max quality drops (Kimi-K3 up to 2.67 points on IMOAnswerBench at 512; Kimi-Linear MMLU-Pro 60.2-66.9 vs 67.5 dense) and recovering it needs suffix replay compute (dasc-wr) [full text, Sections 5.2, 5.4].


### Goal: What unit granularity does DASC use for GDN versus KDA, how much compression does it reach on GDN, and how does dasc-wr refresh omitted units?
Units are one complete head for GDN (per-head gated decay) and one key channel (h, k), i.e. S_{h,:,k}, for KDA (channel-wise decay), with the state S in R^{d_v x d_k} read as o_t = S_t q_t and updated by S_{t-1} Diag(alpha_t)(I - beta_t k_t k_t^T) + beta_t v_t k_t^T [full text, Section 3.1 Eq 1; Section 4.1]. Capacity on head-wise GDN (Qwen3-Next) is only 1.10/1.32/1.60/2.49x at W_max = 16/64/128/512 versus up to 28.24x on channel-wise KDA, because "channel-wise KDA exposes more removable units than head-wise GDN" [Section 5.3]. dasc-wr replays a bounded suffix from a zero scratch state and copies back only omitted units; at W_max=128 it improves Kimi-Linear end tasks by 0.8-7.5 points over zero-fill, but its recompute overhead "can offset the capacity benefit" [Sections 4.2, 5.3, 5.4].
