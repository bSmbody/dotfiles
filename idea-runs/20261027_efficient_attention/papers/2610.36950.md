# DCKV: Learned Transform Coding of the Prompt KV Cache in Hybrid Language Models

## What this paper does
A learned, entropy-coded codec for the stored prompt KV cache of the full-attention layers of a hybrid (Qwen3.5-2B: 6 attention + 18 GDN layers). One joint transform over keys and values of all attention layers, a learned per-component quantization step, and conditional entropy models (token-conditioned, checkerboard context), trained against the frozen LM on code length plus output KL. >55x fewer bytes than bf16 at <=1.8-point loss; restores the full bf16 cache before decoding.

## Goal-by-goal answers
### Goal: How does it treat the attention-layer KV cache versus the recurrent state, and is the byte budget shared between them?
"DCKV compresses the attention cache and keeps the recurrent state exact, so methods for the recurrent state can be used together with it" [full text, Section 2 "Hybrid models"; Section 3.1]. Request memory is payload + 132 uncompressed positions + the 9.84 MiB recurrent state [Section 3.6]. "At prompts of 4K to 11K tokens the recurrent state takes about three quarters of the memory of a stored request. A smaller payload then reduces the request memory by a much smaller fraction than the stored cache" [Section 1]; at 32K the payload exceeds a third of request memory. The distortion is output KL with the state held exact, so the codec never trades KV bytes against state bytes.
### Goal: When is rounding/quantization committed or precision changed (timing), and is that schedule fixed or input-adaptive?
Compress once after prefill, restore once before decoding [Section 3.1, Figure 1]; it does not reduce peak GPU memory or TPOT, and each rate needs its own codec/training run [Limitations "Rate control", "Codec weights and peak memory"]. Decode-time KV growth is not handled.
