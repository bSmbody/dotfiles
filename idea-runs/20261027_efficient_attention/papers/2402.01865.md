# What Will My Model Forget? Forecasting Forgotten Examples in Language Model Refinement

## What this paper does
It forecasts which upstream examples a language model will forget when it is updated on a new online example, without running the updated model. The forecasting models are a frequency-threshold baseline, a logit-change model derived from the first-order (NTK) kernel, and a representation inner-product classifier. Replaying the examples forecast to be forgotten reduces forgetting more than random replay or MIR on BART0 and FLAN-T5.

## Goal-by-goal answers
### Goal: How does it forecast which stored examples an update will make the model forget, and when is that forecast exact and cheap?
To first order, one gradient step on x_i changes the logits of x_j by Theta(x_j, x_i) Theta^{-1}(x_i, x_i) times x_i's own logit change, where Theta is the gradient inner-product kernel [full text, Section 3.2, Eq 2]. "When only fine-tuning the LM heads, obtaining Theta(x_j, x_i) does not require running repetitive inference": the gradients are the representations, so the kernel is an inner product of representations [Section 3.2]. In that linear-head case the fixed (untrained) forecaster reaches F1 69.57 / 68.37 with no learned parts. A trained representation inner-product classifier sigma(h(x_j) h(x_i)^T) plus a per-example frequency prior reaches 79.32 / 67.81 [Section 3.3, Eq 4; Section 5.1]. Under full fine-tuning or LoRA the fixed kernel fails and only the learned version stays competitive [Section 5.1].

### Goal: Does acting on the forecast help, and what is the assumption?
Yes. Replaying forecast-forgotten examples cuts the EM drop from 9.3% (no replay) to 1.6% on BART0 and to 0.3/0.6/0.1% on the FLAN-T5 models, better than random replay and MIR; replaying the ground-truth forgotten set reaches <1% [Section 5.2, Table 3]. The assumption is that interference between an update and a stored example is governed by their kernel similarity, which is exact for a linear readout and approximate otherwise [Sections 3.2-3.3]. Recall of the forecast drops over long update streams while precision stays stable [Section 5.1, Figure 3].
