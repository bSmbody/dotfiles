# An Efficient Diagnosis Algorithm for Inconsistent Constraint Sets (FastDiag)

## What this paper does
Model-based diagnosis for over-constrained problems: given a background knowledge base CKB and a set of requirements C such that CKB ∪ C is inconsistent, find a minimal diagnosis, a smallest-by-inclusion set Delta ⊆ C whose deletion restores consistency. Classical methods first compute minimal conflict sets (QuickXplain) and then minimal hitting sets of the conflicts (Reiter's HSDAG). FastDiag computes one preferred minimal diagnosis directly, by divide and conquer over C, with the cost of computing one conflict.

## Goal-by-goal answers
### Goal: What are conflicts and diagnoses, and how is a diagnosis found with consistency checks only?
A conflict set CS ⊆ C is one with CKB ∪ CS inconsistent; a diagnosis Delta ⊆ C is one with CKB ∪ (C − Delta) consistent; minimal diagnoses are exactly the minimal hitting sets of the minimal conflicts [full text, Section 3, Definitions 3-5]. FastDiag splits C into C1, C2; if AC − C1 is already consistent, C2 is not needed; otherwise it recurses, and a singleton left while AC is still inconsistent is part of the diagnosis [Section 4, Algorithm 1]. More diagnoses come from an HSDAG over FastDiag calls, deleting one element of a found diagnosis and re-running [Section 4, "Calculating n>1 Diagnoses"].

### Goal: What does it cost, and how are preferences among diagnoses expressed?
Worst case 2d·log2(n/d) + 2d consistency checks for one minimal diagnosis of size d among n elements; best case log2(n/d) + 2d [Section 5]. A total order over elements (e.g., user importance) defines a lexicographic "preferred diagnosis", which FastDiag returns when several exist [Section 4, Definitions 6-7]. The method is complete in the sense that if C holds exactly one minimal diagnosis FD finds it [Section 4, "FastDiag Properties"]. The check is assumed deterministic (logical consistency).
