# ArborKV: Structure-Aware KV Cache Management for Scaling Tree-based LLM Reasoning

## What this paper does
A KV-cache manager for Tree-of-Thoughts-style search. Thought blocks are nodes of a search tree. Each closed block gets a score that fuses search value, boundary confidence and accumulated attention. A per-block retention ratio then multiplies that score by exponential decays in depth and in tree distance to the active leaf, with an off-path discount. Within a block it keeps the tail plus attention heavy hitters. Evicted blocks keep their token text, and when backtracking returns to a block its KV is rebuilt by one prefill pass ("lazy rehydration"). Reports up to about 4x peak KV reduction on ToT benchmarks.

## Goal-by-goal answers

### Goal: Does it value cached blocks by dependencies between reasoning steps, or by how costly an evicted block is to recover?
No. Dependencies enter only as search-tree geometry: the active path Path* is pinned, and the weight w_i = s_i^gamma exp(-lambda_d d_i) exp(-lambda_Delta Delta_i) decays with depth and with distance to the active leaf [full text, Section 3; Section 4, Eq 2-3]. The allocation is a separable concave program (psi_i(k) = -w_i log k), so k_i ∝ w_i [Section 4, "Optimization view"]. Recovery cost does not enter the value at all. Recovery is exact and mechanical: evicted token spans are kept, and their KV is re-prefilled when a block re-enters the active path [Section 4, "Lazy rehydration"]. That is a DTR-like replay of the KV from stored tokens, not a re-derivation by the model. The tree is the search controller's branch tree, not an operand graph inside one linear chain of thought.
