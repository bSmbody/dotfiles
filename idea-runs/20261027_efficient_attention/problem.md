# Efficient attention for long-context and long-reasoning models

## Problem definition
Given a Transformer-style language model (or a multimodal / video LLM built on one) that must handle long inputs or generate long reasoning traces, reduce the cost of attention — the KV cache that grows linearly with length and the compute that grows quadratically — while keeping quality. The design space has five parts: (1) pruning or evicting tokens / KV entries of standard softmax attention at inference; (2) pruning and compressing variant attention mechanisms (linear attention, state-space / recurrent layers, latent-compressed attention such as MLA, sparse attention); (3) hybrid architectures that mix a few full-attention layers with many linear or recurrent layers; (4) the fixed-size memory matrix (recurrent state / fast weights) that linear attention and its variants maintain, and the rule that updates it; (5) the algorithms that make variant attention fast and trainable (chunkwise-parallel forms, hardware-aware kernels, trainable sparse attention). Input: a long context or a reasoning task. Output: the model's continuation or answer. Typical evaluation: quality on long-context benchmarks (RULER, LongBench, needle-in-a-haystack, long-video QA), reasoning benchmarks with long chain-of-thought (AIME / MATH-500 / GPQA), language-modeling perplexity, plus memory, latency and throughput as a function of length.

## Challenge
Every way of cutting attention cost loses information somewhere. Token / KV eviction decides from current attention scores which entries to drop, but a token that looks unimportant now can be needed later, and long chain-of-thought keeps revisiting earlier steps. Linear attention and state-space models compress the whole history into a fixed-size memory matrix, so exact recall and in-context retrieval degrade as length grows. Hybrids recover recall by keeping some full-attention layers, but then the KV cache of those layers is the bottleneck again, and which layers to keep, in what ratio, is chosen by hand. Concrete failure: a 7B reasoning model with a KV-eviction budget of 2K tokens matches the full cache on short questions, but on long-CoT math it drops an intermediate result it later needs and its accuracy collapses; replacing most layers with linear attention keeps memory flat but fails multi-key needle retrieval at 32K.

## Constraints
- **Venue and deadline**: a top ML venue main track (NeurIPS / ICML / ICLR class; the simulated panel uses NeurIPS main track). No fixed deadline; assume about 4–6 months from idea to submission.
- **Scope**: methods that cut the memory or compute of attention for long-context and long-chain-of-thought inference in text LLMs, covering standard softmax attention, variant attention (linear / recurrent / sparse / latent) and hybrid models. Out of scope: weight quantization or weight pruning, MoE routing, visual-token pruning specific to multimodal models, pure serving-system scheduling with no new method, and new benchmarks or analyses as the main contribution.
- **Team**: a new PhD student (the user) with a senior labmate who suggested the direction. Kernel engineering is a real cost: prefer methods that reuse existing kernels (flash-linear-attention, FlashAttention, vLLM / SGLang paged KV) or need at most modest Triton work, and say so when a method needs a new kernel.
- **Compute** (updated 2026-10-27 by the user): the senior labmate's H200 cluster, about 1 TB of GPU memory in total (≈8×H200 141 GB). Compute is effectively not the binding constraint: pretraining small-to-mid models, converting / distilling public models up to ~70B, and long-context (128K) fine-tuning are all feasible.
- **Literature**: no cutoff — search up to today (2026-10-27). arXiv work from the last 12 months counts as prior or concurrent work.
