## 0. 背景：问题出在哪，五个方向怎么分工

标准 softmax 注意力有两笔开销：
- **计算**：每个 token 要和前面所有 token 算相似度，计算量随长度平方增长。
- **显存**：前面每个 token 的 K、V 都得存着（KV cache），显存随长度线性增长。

长上下文、长视频、长思维链推理都卡在这两笔开销上。推理模型动辄生成几万 token，KV cache 往往比模型权重还大。

```
标准注意力太贵
 ├─ 不改结构，少存少算 ──→ ① 标准注意力剪枝（KV 淘汰、稀疏注意力）
 └─ 改结构 ──→ 变种注意力（线性注意力 / SSM / MLA / 可训练稀疏）
               ├─ 线性注意力的核心是一个固定大小的 ③ 记忆矩阵：怎么写、怎么忘
               ├─ 要训练得动、跑得快，靠 ⑤ 专门的并行算法和 kernel
               ├─ 记忆矩阵装不下 → ② 混合架构：保留几层全注意力
               └─ 还想更省 → ④ 对变种结构再剪枝、压缩、量化
```

几个后面会反复出现的名词：
- **线性注意力的记忆矩阵 S**：一个 d_k×d_v 的矩阵。每个 token 往里写一次 v kᵀ，读的时候用 q 去查。它的大小不随长度变化，所以显存是常数，但能存的东西有上限（大约 d_k 对不互相干扰的键值）。
- **Gated DeltaNet（GDN）**：目前最主流的线性注意力层。写入前先用当前的 k 查出旧值，再按误差修正，这叫 delta rule。另外乘一个衰减门，让旧记忆逐渐遗忘。Qwen3-Next 这一代混合模型用的就是 GDN。
- **MLA**：DeepSeek 的潜在注意力。K、V 先压成一个低维向量再缓存。一部分维度带位置编码（RoPE），其余维度不带。
- **NSA / 可训练稀疏注意力**：每个 query 只挑一部分 KV 块来算。挑选的模块叫 selector 或 indexer，和模型一起训练。
- **常用评测**：RULER、NIAH（大海捞针，分单针 S-NIAH 和多针 MK-NIAH）、MQAR（多键联想回忆，专测记忆容量）、LongBench；推理任务看 AIME、MATH-500、GPQA。

## 1. 标准注意力剪枝（KV cache 淘汰）

**已有工作：**
- **按历史打分，删了就不要。**
  - H2O 用累计注意力加最近窗口 [2306.14048]；
  - R-KV 是专门给推理模型做的，用最近窗口的注意力减去 key 之间的冗余度 [2505.24133]；
  - 还有按“这个 token 隔多久会被重新关注一次”来决定删谁的 [2506.15969]。
- **学一个打分器预测“将来有没有用”。**
  - KVP 用 RL 训练，奖励是被删 token 将来会得到的注意力 [2602.10238]；
  - ForesightKV 先用“黄金淘汰”标签做监督，再用 GRPO 训练 [2602.03203]；
  - DistillCache 拿每一步的输出分布去对齐全 cache 模型 [2608.08878]。
- **按 query 挑页，但全部保留。** Quest 给每一页 KV 记录 key 的最小值和最大值，用来快速估计相关性，每个 query 只算最相关的页，cache 仍然全部驻留在显存里 [2406.10774]。
- **不直接删，而是降级存储。** 降到 INT2 或 4-bit 冷存储 [2608.05326] [2610.08811]，或者挪到 CPU 内存，需要时再取回 [2610.02713] [2605.09490]。
- **一个很打脸的基线 [2609.03430]**：只要保住 prompt，把推理过程里的 token 每个头随机删，效果就和 SnapKV、R-KV、VaSE、TriAttention 差不多。

**存在的问题：**
1. **每个 token 单独打分，不看“保留下来的整体”。** 现有方法给每个 token、每个头各打一个分，按分数排序决定删谁，默认价值可以简单相加。实际上并不是这样：
   - 同一个信息在推理里常被复述好几次，多份拷贝可以互相替代；
   - 同一个事实在不同头里的拷贝，叠加起来的效果远大于单份：一个头保留时检索成功率 3%，两个头 60%，八个头 99% [2609.03430]。

   所以按 token 排序会把预算浪费在冗余拷贝上，却丢掉只说过一次的关键中间结果。KVP 的作者自己也写了“不建模跨头依赖”。
2. **学出来的淘汰器训练时用的是固定文本，部署时却是自由生成。** 训练时所有 token 都是全 cache 模型生成的，淘汰器只需要保证“下一个 token 的分布不变”。但实际部署时，删错一个 token 会改变模型接下来写的内容，可能陷入重复循环、文本错乱、忘掉题目要求的量、推理越写越长 [2608.15797]，还可能在预算从 70% 降到 50% 时，准确率从 22% 直接掉到 0 [2605.09490]。这些后果在训练目标里完全看不到，相当于淘汰器版本的 exposure bias。

## 2. 混合注意力架构

**已有工作：**
- **固定比例穿插。** 在 72 个小模型上的对照实验 [2507.06457] 发现：全注意力层越多，RULER 检索越好，到大约 3:1 时饱和；语言模型 loss 几乎不随比例变化，所以**光看 perplexity 选不出好的混合方案**。另外，单独表现好的线性层，放进混合架构里不一定好。
- **把现成 Transformer 改造成混合模型：保留哪几层全注意力。** 现有方法各用一种打分信号：
  - 每次恢复一层，看 KL 降多少 [2512.20569]；
  - 逐层学门控 [2606.30562]；
  - 可微分搜索 [2605.20936]；
  - beam search 加 perplexity [2603.26556]；
  - 留一法看 MMLU 掉多少 [2511.02651]。

  不管用哪种信号，**保留多少层仍然要人手定**。
- **蒸馏目标。** perplexity 会掩盖 5–21 个百分点的生成质量差距 [2603.26556]。Opal 证明对长思维链必须用 on-policy 蒸馏，也就是让学生模型在自己生成的轨迹上学：AIME'24 上 on-policy 得 33.3，off-policy 只有 17.1 [2609.31947]。
- **压缩保留层的 KV。** 混合模型里只有全注意力层的 KV 会随长度增长，100K token 时是 GDN 状态的 42 倍 [2610.14754]。相关方法有 GateSight [2610.14754]、HeadWiseKV [2609.02029]，以及只管 prefill 阶段的稀疏方法 [2606.07703]。

**存在的问题：**
1. **选保留层用的是固定文本上的信号，可长推理崩溃发生在模型自己生成的轨迹上。** 所有选层方法都在 teacher-forced 的固定文本上打分。Opal 已经指出，长生成失败的主因是：学生模型犯一个错，改变了后续输入，这个错误再通过递归状态一路累积下去。这种失败只有在学生自己 rollout 时才会出现。Opal 只用这个信号来训练权重，保留哪些层仍然是“每 4 层留 1 层”的固定规则。也就是说，“哪些层对长推理关键”这个问题还没有人用对的信号回答过。
2. **压缩全注意力层的 KV 时，没考虑 GDN 层里其实还记着同样的历史。** 现有方法只衡量“删掉这个 token 对本层注意力输出的影响”，把注意力 cache 和递归记忆当成两套互不相干的系统。理想的做法是两者分工：GDN 已经记住的，注意力 cache 就不用再存。只有 HOLA [2607.02303] 用了类似原则（只精确保存递归状态表示得最差的 token），但它是从头训练的模型，不能直接用来压缩现成的混合模型。

## 3. 记忆矩阵：怎么写、怎么忘

**已有工作：**
- **统一视角 [2501.12352]**：线性注意力、门控线性注意力 / SSM、DeltaNet、TTT 都可以看成“对历史 (k, v) 对做在线回归”。门控等于按时间远近给每一对降权，delta rule 等于对当前这一对做一步 SGD。
- **遗忘加修正写入。** Gated DeltaNet 在 delta rule 上乘一个数据相关的衰减 [2412.06464]，它自己的实验就展示了两难：衰减太多就记不住，不衰减又会让不同记忆互相覆盖（memory collision）。
- **更细的擦除和写入控制。** 有按通道分开的擦除门和写入门 [2605.22791]，有在独立地址上做秩一擦除的 [2606.26560]，也有 KronLSTM [2610.26834]。这些门都只根据**当前 token** 计算。
- **更好的步长。** 有从 Kaczmarz 投影推导步长的 [2605.08587]，也有在线学习对角预条件的 [2605.13473]。
- **考虑写入干扰的二阶方法。** Kalman 式更新只保留对角协方差 [2609.07816]；VLA 用 Sherman-Morrison 维护一个稠密矩阵，等价于 RLS [2605.11196]；MesaNet 每个 token 用共轭梯度精确求解一次最小二乘 [2506.05233]。RLS 类方法是唯一能在 key 数量超过维度时仍然完成 MQAR 的。

**存在的问题：**
1. **保留谁只看写入时刻，不看以后会不会被读。** 所有更新规则都在写入时就决定了一条记忆能留多久，依据是新旧顺序加上当前 token 的门控。记忆装满以后，只能按写入顺序淘汰，没法因为“这条记忆以后会被查”而优先保留它。数据很直观：
   - MK-NIAH 从 1K 到 4K，成功率从 72.6 掉到 37.8 [2605.22791]；
   - RLS 在容量的 1.5 倍时，MQAR 掉到 0.044，因为它会优先覆盖最近写入的方向 [2605.11196]。

   MesaNet 的作者原话是：“RNN 需要预先知道哪些信息值得保存。”
2. **考虑写入干扰的更新要么精确但慢，要么快但丢掉了关键信息。** 判断“这次写入会不会冲掉别的记忆”，需要 key 之间的协方差，而协方差是一个稠密的 d_k×d_k 矩阵。精确维护它要么只能串行递推（慢 3–5 倍），要么每步迭代求解。能并行的版本把它压成对角，恰好丢掉了编码干扰的那部分非对角项。

## 4. 变种注意力的剪枝与压缩

**已有工作：**
- **剪线性注意力 / SSM 的状态维度。** 剪 key 通道再用 LoRA 恢复 [2602.04852]，不用数据剪头 [2602.02195]，按系统能量截断 SSM 的模态 [2602.00534]，剪混合模型 prefix cache 里的状态 [2608.30386]。
- **状态低精度存储。** 按“量化误差乘以衰减保留率”选哪些通道留 FP16 [2608.27513]，或者按寿命分配位宽 [2609.38169]。另外有研究发现，每步重新量化的误差会随解码长度不断累积 [2610.15139] [2610.15709]。
- **把现成的 MHA/GQA 模型转成 MLA。**
  - MHA2MLA：用范数启发式决定哪些维度保留 RoPE，再对 K、V 权重做 SVD [2502.14837]；
  - 其他方法有的从 SVD 初始化后接 KD 加 DPO [2503.11132]，有的用激活加权 SVD 并按层分配秩 [2603.17946]，有的兼容 QKNorm 和 MoE [2610.17202]，还有转换后逐层修正 [2607.27269]。

**存在的问题：**
1. **剪状态用的是离线定好的固定掩码，但真正被用到的状态单元会随输入变化。** 现有方法都离线选好一组保留的通道、头或精度，默认重要性是模型本身的固定属性。但 [2607.11796] 精确测量后发现，选择性 SSM 实际在用的状态单元会随内容迁移，而且几百个 token 内就会变。按当前输入挑选的“理想”方法用一半预算就能胜过所有静态规则，甚至胜过不剪枝的原模型；可是现有的因果调度器（只看过去、不偷看未来）只能拿回这部分收益的 2–26%。纯递归的 GDN-1.3B 剪掉 50% 状态后，NIAH-4K 从 81.3 掉到 61.9 [2602.04852]。
2. **转 MLA 时只做逐 token 重建，看不到长距离的位置误差。** 转换的目标是重建每个 token 的 K、V，校准文本也很短。而把一部分 key 维度从 RoPE 挪到无位置编码路径造成的误差，大小随相对距离变化，这一项在这些目标里权重为零。后果是短上下文没问题，长上下文崩掉：不训练直接转换时，常识题从 59.85 降到 52.68，LongBench 却从 27.40 降到 1.06 [2610.17202]。要恢复只能做 128K 长度的微调，单机 24 GB 卡做不了。

## 5. 变种注意力的算法与 kernel

**已有工作：**
- **线性注意力的分块并行（chunkwise）。**
  - DeltaNet 用 WY 表示加 UT 变换，把 delta rule 的递推改写成矩阵乘，让 tensor core 能用上 [2406.06484]；
  - TFLA 在块内再做 FlashAttention 式的切分 [2503.14376]；
  - MDN 把精确分块推广到带动量的更新 [2605.05838]；
  - DeltaTTT 让两层的非线性记忆也能并行训练 [2610.08553]。
- **可训练、对硬件友好的稀疏注意力。**
  - NSA：压缩、选择、滑窗三个分支，按块选择，同一个 GQA 组内共享 [2502.11089]；
  - FSA：调换 kernel 的循环顺序 [2508.18224]；
  - MSA：单独的 indexer，用 KL 损失对齐主分支 [2606.13392]；
  - DashAttention：用 entmax 路由，可以端到端求导 [2605.18753]；
  - 精确 top-k 需要 O(N²) 的打分，DeepSeek 的 Lightning Indexer 和精确 top-k 只有约 60% 一致 [2512.03494]。
- **对照研究 [2603.02227]**：hard top-k 的门控得不到梯度；软门控和模型一起训练时，学出来的路由几乎不比随机好（ppl 71.22 对 71.24），因为模型本身会去适应路由的错误，作者称为“routing absorption”。

**存在的问题：**
1. **能精确并行的记忆更新，必须对旧状态是仿射的。** 所有精确的分块算法，都靠把“与状态无关的线性变换的连乘”展开成三角求解加矩阵乘。一旦写入对当前状态是非线性的（比如在非线性小网络上做一步梯度），就没有精确的并行训练算法了。现有的绕法实际上改变了学习规则本身：TTT、Titans 改成块内非因果，DeltaTTT 改成每层各自的局部目标。这一点直接限制了第 3 节：更有表达力的记忆规则，必须先迁就 kernel。
2. **稀疏注意力的 selector 只能从自己选中的块里学。** 训练 selector 的梯度或损失都只在它已经选中的块上计算：hard top-k 没有梯度，MSA 的 KL 只在选中的 token 上算，entmax 在支撑集外导数为零。漏选了一个相关块，就永远得不到纠正信号。现在只能靠稠密的预热阶段补救，又把省下来的算力花回去了。这正是“现在看着不重要、以后要用”的 token 被漏掉的根源。

## 6. 横向看：几个反复出现的根本问题

**① 只按单个单元打分，不看整体组合和冗余。**
KV 淘汰按 token 排序，不考虑拷贝之间可以互相替代（第 1 节）；混合模型的 KV 压缩不考虑 GDN 状态里已经记住的内容（第 2 节）；记忆矩阵淘汰只看写入顺序，不看读取需求（第 3 节）。问题都在于：**一条信息该不该留，取决于其他地方还有没有它、以后会不会用到它**，而现有方法都是对单个单元打分。

**② 在固定文本上训练和选择，在自由生成时部署。**
学出来的 KV 淘汰器（第 1 节）和混合架构的选层（第 2 节）有同一个毛病：都在 teacher-forced 的固定文本上优化，看不到“删错或选错之后，模型自己写出来的东西越来越偏”。长思维链推理恰恰是这种误差累积最严重的场景。

**③ 离线定死，不随输入调整。**
状态剪枝和量化用固定掩码（第 4 节），转 MLA 用短窗口校准（第 4 节）。重要性其实会随内容和距离变化。

**④ 算法的形式反过来限制了模型设计。**
精确并行要求记忆更新对旧状态是仿射的，所以更强的记忆规则用不了（第 3、5 节）；稀疏 selector 的梯度只覆盖选中的块，所以漏选的块永远学不回来（第 5 节）。

**一个值得记住的事实**：在推理任务上，精心设计的 KV 淘汰方法不比随机删除强 [2609.03430]。这说明这个子领域现有的打分思路可能整体有问题，值得重新想。

## 7. 和你的情况怎么对接

**和“推理”方向的交汇点**：第 1 节的两个缺口、第 2 节的第一个缺口、第 3 节的第一个缺口，评测里都包含长思维链，比如“推理中途需要回头读前面的中间结果”。如果你仍然想做推理相关的研究，这几个点最自然。

**按算力粗分**（假设 2–4 张 24 GB 卡，还需要你确认）：

| 方向 | 需要什么 | 在当前算力下 |
|---|---|---|
| 第 1 节：推理模型的 KV 淘汰 | 冻结 ≤8B 模型，只训练小打分器或不训练 | **最可行**，有现成的随机基线和探针 [2609.03430] |
| 第 2 节缺口 1：混合模型选层 | 转换并蒸馏推理模型，需要几十亿 token 级的训练 | 吃力，可能只能做 1–3B |
| 第 2 节缺口 2：混合模型的 KV 压缩 | 需要现成的 GDN 混合模型 | Qwen3-Next 是 80B MoE，24 GB 卡跑不动，得找小的 GDN 混合模型 |
| 第 3 节：记忆矩阵更新规则 | ≤400M 从头预训练，加上 MQAR、NIAH 评测 | 可行，但要会写 Triton kernel，否则速度上站不住 |
| 第 4 节缺口 1：状态剪枝 | GDN、Mamba 1.3B 级 checkpoint | 可行 |
| 第 4 节缺口 2：转 MLA | 8B 模型做 LoRA 级修复 | 可行，前提是方法本身不需要长上下文微调 |
