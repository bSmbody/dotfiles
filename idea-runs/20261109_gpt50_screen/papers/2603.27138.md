# ScoutAttention: Efficient KV Cache Offloading via Layer-Ahead CPU Pre-computation for LLM Inference

## What this paper does
DAC 2026. KV-offload serving in which important KV blocks sit in HBM and the rest in DRAM. Attention over the non-resident top-k blocks is computed on the CPU (co-attention) and merged with the GPU part by the FlashAttention LSE merge. To hide CPU latency, the CPU part for layer i+1 starts one layer early, using a predicted query W_Q^{i+1} X^i. Periodic asynchronous recall refreshes the GPU-resident blocks. Implemented in SGLang with Quest-style block selection; Qwen3-8B/14B on LongBench.

## Goal-by-goal answers
### Goal: Does it compute exact partial attention with an approximate/stale query and merge it with a fresh one (overlap with C10)?
Yes, at a lag of one layer. CPU-side attention over the non-resident top-k blocks uses Q_pred^{i+1} = W_Q^{i+1} X^i and is merged on the GPU with the GPU-side attention [full text, Sections 3.2-3.3, Alg 1]. Accuracy drops slightly relative to InfiniGen "from using predicted queries for CPU side attention". The CPU part is ~8% of the budget, and the loss is 2.5% / 2.1% vs full attention at budgets 1024 / 2048 [Section 4.2].
### Goal: What temporal-locality / drift numbers does it report?
On average less than 15% of important blocks change between consecutive tokens [Section 3.2, Fig 6a]. Importance drifts steadily as decoding progresses, so the CPU share rises. Per-layer recall intervals keep it below 12%: the average CPU ratio is 8.2% and the average recall interval is 8.7 steps [Section 3.4]. PCIe 4.0 transfer reaches only ~15 GB/s at 128 KB pages, vs ~100 GB/s CPU attention throughput [Sections 2.3, 3.2].
### Goal: Headline systems result?
5.1x decode throughput over FullKV at 64K input on Qwen3-14B, up to 2.1x over InfiniGen/HGCA; GPU idle time 6% vs 57-61% for the baselines [Section 4.3].
