# GOTS: Greedy Orthogonal Token Selection for High-Resolution Vision-Language Models

## What this paper does
Training-free, query-agnostic visual token reduction for high-res VLMs (Qwen-VL, InternVL). On the post-encoder visual feature matrix X (N x d) it runs QR with column pivoting (incremental modified Gram-Schmidt): repeatedly pick the token whose residual orthogonal to the span of already-kept tokens has the largest energy. Kept tokens are forwarded unchanged (original features + positions) to the LLM. Up to ~6.9x prefill speedup at 5% retention on OCRBench.

## Goal-by-goal answers
### Goal: Does GOTS write orthogonal residuals/innovations into the context, or only select original tokens? Does it handle crops or re-looks?
Selection only: "forwards retained visual tokens together with their positional metadata to the VLM" [full text, Method/Overview]; the residual r_i is only a scoring/pivot quantity (Eq. 6-8). Single image, one-shot selection; no notion of a second observation, crop or zoom (no crop/zoom/multi-turn in the body).
### Goal: In what space and under what rank limit is the orthogonality computed?
On vision-encoder output features x_i in R^d; budget K "typically K <= d" because span(X_S) is at most d-dimensional; terminates early when residual energy < 1e-12 [full text, Method, Eq. 1, QRCP section]. Cost O(KNd). Implication for C5: once >= d tokens of the full image are stored, every new token's linear orthogonal complement is (numerically) zero, so linear "innovation" in this feature space cannot measure novelty of a re-look.
### Goal: What efficiency is reported?
OCRBench, Qwen2.5-VL-7B, 5% retention: visual tokens 2093.8 -> 104.2, LLM prefill 170.95 -> 24.87 ms, model-side TTFT 433 -> 295 ms incl. 4.06 ms selection overhead [full text, Inference Efficiency / Table 3].
