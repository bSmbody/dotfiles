# RefreshKV: Updating Small KV Cache During Long-form Generation

## What this paper does
A training-free decode method that alternates between full-KV attention steps and steps over a small partial cache (top-K tokens from the most recent full step, plus newly generated tokens). A full step is triggered per layer when the cosine similarity between the current averaged query and the query of the last full step falls below a threshold, checked every QC steps. The full KV stays in memory. Evaluated with Llama-3.1-8B and Qwen2-7B on long-input, long-output tasks (HTML-to-TSV, Chain-of-key, summarization, RULER), plus continued pretraining.

## Goal-by-goal answers
### Goal: Does it read the full (far) cache once per S steps and reuse that read in between (overlap with C10's "far read once per B tokens")?
Yes, with selection instead of a lag. Full attention runs every S steps, adaptively by query similarity (thresholds 0.85 for Llama, 0.95 for Qwen). In between, attention uses the top-K set from the last full step [full text, Section 2.2]. The gain comes "mostly from refreshing the partial KV cache, instead of performing occasion full attention" [Section 5.2, Table 4]. The adaptive stride beats a fixed stride at equal time [Section 5.1, Table 3].
### Goal: How much does stale far access cost on copy-heavy long generation?
On HTML-to-TSV (mostly copying), SnapKV/H2O get 0 F1 and RefreshKV recovers only 52% (Llama) / 42% (Qwen) of full-attention performance. On Chain-of-key, where the next key depends on the just-generated key, eviction methods fail beyond two keys [Section 1, Section 4.2]. Continued pretraining with RefreshKV improves it further [Section 6]. Limitation: no memory saving [Limitations].
