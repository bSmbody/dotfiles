# Fault-tolerant linear solvers via selective reliability

## What this paper does
Argues that future extreme-scale machines cannot afford uniform reliability and proposes algorithm/system codesign in which most data and computation run in a cheap unreliable mode and a small part runs reliably. It defines reliability models (statistical, sandbox, finer-grained type-system models), desired properties of fault-tolerant iterations (eventual convergence, gradual degradation), and Fault-Tolerant GMRES (FT-GMRES): a reliable outer Flexible GMRES that treats each unreliable inner solve as a possibly different preconditioner. It adds an OS interface that reports uncorrectable memory faults to the application. Experiments with injected faulty SpMVs show FT-GMRES converges where restarted GMRES stagnates.

## Goal-by-goal answers
### Goal: How does the sandbox / inner-outer model split reliable and unreliable work and data?
In the sandbox model an untrusted guest computation runs in isolation, may return wrong values, and is forced to return in finite time; the host may stop it "if the host suspects the guest may have wandered astray" [full text, Section 4.2]. FT-GMRES puts "Inner solve (unreliable)" inside a reliable FGMRES outer loop, which tolerates a different preconditioner at each iteration, so faults look like bad preconditioners [Section 6.2, Algorithm 3]. Faults are allowed in all "large" data and computations of the inner iterations only (matrices, preconditioners, vectors); the small projected least-squares problem and control data must be reliable because errors there have a large effect [Section 7.1.1]. Goal: "store most of its data and spend most of its computations in unreliable mode" [Section 5.2].
### Goal: What must the reliable phase do to keep the result correct?
Inner iterations may use approximate local repair, but outer iterations need exact operators. Strategy: start each inner iteration with correct data, allow corruption, and "at the end of the inner iteration, refresh the correct values in the sparse matrix, even if no faults were detected there. This ensures correctness even if undetected faults occurred." Outer iterations are infrequent, so more can be spent on recovery there [Section 7.3.4]. Three tiers result: always-reliable small data; data unreliable in inner phases that the outer phase must refresh to correct values; unreliable scratch data needing no restore [Section 7.4]. Plain iterative refinement lacks eventual convergence, since one large fault in the last residual can spoil the answer [Section 5.1].
### Goal: How does convergence degrade with fault rate?
With 1, 3 or 5 of every 10 inner SpMVs faulty, FT-GMRES convergence slows only gradually, and outer-iteration counts rise little with fault rate (one outlier). With faults in 2 of 10 SpMVs it beats restarted and non-restarted GMRES on all three test matrices [Section 8.2, Figs 2-8].
