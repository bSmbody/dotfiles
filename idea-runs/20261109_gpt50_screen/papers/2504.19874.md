# TurboQuant: Online Vector Quantization with Near-optimal Distortion Rate

## What this paper does
Data-oblivious online vector quantizer. A random rotation makes each coordinate of a unit vector follow a concentrated Beta (near-Gaussian) law with near-independent coordinates, so per-coordinate Lloyd-Max scalar codebooks (precomputed per bit-width) are near-optimal for MSE (TurboQuant_mse). Because MSE-optimal codes bias inner products, TurboQuant_prod spends b-1 bits on the MSE quantizer and 1 bit on a QJL sketch of the residual, giving an unbiased inner-product estimate. Proves distortion within a small constant of an information-theoretic lower bound. Applied to KV cache (Llama-3.1-8B, Ministral-7B; NIAH, LongBench-E) and to nearest-neighbour search.

## Goal-by-goal answers
### Goal: What is the method and its theoretical guarantee?
Random rotation, then per-coordinate optimal scalar quantizer on the Beta law; norms stored in floating point for non-unit vectors [full text, Section 1.3, Section 3.1]. MSE distortion <= (sqrt(3)pi/2)/4^b; for b=1..4 about 0.36, 0.117, 0.03, 0.009 [Section 1.3, Theorem 1]. TurboQuant_prod is unbiased with inner-product distortion <= sqrt(3)pi^2 ||y||^2/(d 4^b) [Section 3.2, Theorem 2]; a matching-order lower bound is Theorem 3 [Section 3.3].
### Goal: What models, lengths and headline KV results are reported?
Llama-3.1-8B-Instruct NIAH 4k-104k at 0.25 memory ratio: TurboQuant 0.997 = full precision, vs KIVI 0.981, PolarQuant 0.995, SnapKV 0.858, PyramidKV 0.895 [Section 4.2, Figure 4]. LongBench-E average: full 50.06; TurboQuant 3.5-bit 50.06, 2.5-bit 49.44; KIVI 3-bit 48.50 [Section 4.3, Table 1]. Non-integer bits come from splitting channels into outlier/non-outlier sets with separate bit widths (2.5 bits = 32 channels at 3 bits + 96 at 2) [Section 4.3]. It quantizes generated tokens too, unlike KIVI/PolarQuant [Section 4.3].
### Goal: What does it not evaluate, and is code or kernel support stated?
No long-generation reasoning benchmark (no AIME/MATH/long CoT), no throughput or kernel; experiments on one A100 [Section 4]. No code repository stated in the paper. Later papers use a community vLLM implementation (PR #38479) [2606.03458, Appendix D; 2605.17757, Section 5.1].
