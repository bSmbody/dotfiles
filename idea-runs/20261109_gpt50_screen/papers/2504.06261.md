# Hogwild! Inference: Parallel LLM Generation via Concurrent Attention

## What this paper does
Runs several instances ("workers") of one reasoning LLM in parallel over a shared KV cache, so every worker attends to the others' tokens as they are generated, with no fine-tuning. The cache is split into blocks (prompt plus shared step history, each worker's current unfinished step). Each worker sees the blocks in its own order. Instead of re-encoding or re-rotating cached keys, the current query is rotated once per block (RoPE relative-position trick), so each block exists once in memory. Workers are prompted to collaborate, with an injected "Wait, am I doing redundant work?" every ~1K tokens. Tested on QwQ-32B, Qwen3, Phi-4-R+, DeepSeek-R1 on LIMO, LiveCodeBench, OlympiadBench, AIME25. NeurIPS 2025.

## Goal-by-goal answers
### Goal: How do workers share KV, how are positions handled, and what does one decode step cost?
All workers decode as one batch; new tokens' KV are appended to their own block and are visible to all workers within the same step, "even before they are processed by all layers" [full text, Section 3.4]. Blocks store keys at positions 0..len(block); the query is rotated to the relative offset of each block, giving n(n+1) query rotations for n workers and "only one copy of each cache block" [Section 3.4; Appendix B]. The main ("combined") layout moves a worker's finished paragraph (ending in \n\n) to the end of a shared chat-like history and keeps others' unfinished steps as recent tokens, because with a contiguous layout "workers will eventually pay less attention to each other because of the thousands of tokens between their latest steps" [Section 3.2; Appendix A]. Every layer of every worker reads all workers' blocks. Measured on L40S with QwQ-32B-AWQ, the attention call at long contexts is about 40% (2 workers) and 100% (4 workers) slower than FlashAttention, with near-linear token throughput scaling [Section 4.4, Table 2].

### Goal: What results and limitations are reported, especially on scale, length and model size?
Training-free collaboration emerges: workers split sub-tasks, cross-check and pivot; accuracy per number of sequential forward passes beats single-worker and self-consistency on LIMO and holds on LiveCodeBench, OlympiadBench and AIME25 [Sections 4.1-4.2]. Token-wise visibility scores higher in collaborativeness than step-wise visibility [Section 4.3, Figure 7]. Limitations: "reduced robustness when applied to smaller models or longer contexts" [Section 5]; Qwen3-1.7B/4B "get distracted from the task" [Section 4.1]; 6 workers saturate at worse accuracy than 3-4, attributed to running out of trained sequence length because the union of workers' tokens grows n times faster [Appendix E.1]. Workers trained single-thread can be "too focused" and miss others' findings unless prompted [Section 3.3]. Only dense Transformers (plus mention of local attention and MLA) are discussed; recurrent/hybrid layers are not [Appendix B "Attention variants"].
