# SAW-INT4: System-Aware 4-Bit KV-Cache Quantization for Real-World LLM Serving

## What this paper does
Asks which INT4 KV methods survive real serving constraints (paged blocks, coalesced access, fused FlashAttention-style decode). It argues token eviction, mixed precision, channel-wise scales, codebook lookups and PCA/SVD bases all conflict with paged fused kernels, so token-wise INT4 is the viable base. It adds block-diagonal Hadamard rotation (BDR, order 128, keys only suffices) fused into a Triton decode kernel, in SGLang, and compares against KMeans VQ, Hessian-aware and Kitty under one protocol.

## Goal-by-goal answers
### Goal: Which accuracy protocol and what results on reasoning models?
Qwen3-4B-Thinking-2507 (and Qwen3-8B, GLM-4.7-FP8) on GPQA, HumanEval, LCB v6, AIME25, MATH500; T=0.6, max sequence 32K, μ±σ over 5 runs [full text, Section 3.1]. Naive token-wise INT4 collapses to near zero on Qwen3-4B; BDR block 16→64→128 gives mean 54.83→72.29→73.11 vs BF16 75.64; KMeans C=2048 72.81; Hessian-aware 63.23; KMeans+rotation 73.35. Qwen3-8B BDR-128 69.97 vs BF16 70.84; GLM-4.7 naive INT4 already 77.21 vs 77.89 [full text, Section 3.1, Tables 2–3]. So the need for rotation is model-dependent.

### Goal: How is serving efficiency measured and what is found?
Kernel microbenchmarks favour plain INT4 over fused rotation, but end-to-end the gap vanishes [full text, Section 4.2, Fig. 3–4]. Metrics: TPS_sys (total output tokens / wall time), per-request decode TPS, and TTFT, swept over concurrency on Qwen3-4B/8B/32B and GLM-4.7 (8×H100) [full text, Appendix D]. Qwen3-8B, short context (256 in / 1024 out): BF16 ~3% faster at concurrency 32; INT4/INT4+BDR +13.5%/+11.2% TPS_sys at concurrency 128. Long context (16K in / 1K out): at high concurrency INT4 shows lower per-request TPS but much lower TTFT, because 4× more token slots admit more requests [full text, Appendix D]. Kitty and other non-SGLang methods measured with HF generate fall far below SGLang BF16 [full text, Section 1, Fig. 2]. Outputs are 1K tokens, not long CoT, and there is no FP8-KV or cost-per-correct comparison.
