# SwarmEvolve: Latent Agent Swarms for Evolutionary Discovery and Optimization [2611.08483]

## What this paper does
LLM-guided evolutionary program search (AlphaEvolve/OpenEvolve style) where each round runs 10 swarms x 45 = 450 latent agents on one GPU (Qwen3 8B/14B/32B-FP8). Agents never decode text: following LatentMAS (training-free), each latent step maps the last hidden state h_t back to an input embedding via a ridge-regression alignment matrix W_a and rescales it to the mean token-embedding norm; 40 latent steps per agent, each adding one KV position. Agents reading the same parent program share its KV through paged attention. A novelty filter represents each agent by its mean hidden state over the 40 steps, centers/normalizes within the swarm, and keeps 30 of 45 by greedy farthest-point selection in cosine distance (cost 0.05 min per hour). A summarizer reads the concatenated KV caches [problem; 30 agents; parent programs; instruction] (keys re-rotated with RoPE to their new offsets, values unchanged) and decodes one program. Swarm types: refinement, hybridization (crossover), exploration, fresh-start.

## Key results
21 math-discovery and scientific-computing problems, 60 min on one GPU. Highest average score with all three models; 5-13x more programs evaluated per hour; reaches baselines' 60-min scores in a median 3-8 min; with Qwen3 8B improves on AlphaEvolve's published constructions on 3 problems. Time breakdown (8B): latent reasoning 7%, latent communication 4%, writing programs 66%; baselines spend 57-87% on text reasoning. Ablation: latent 0.804 vs text-40-token 0.796 vs text-256-token 0.767 average best score; swarm size helps early, all sizes converge later (LLM capability limit).

## Limitations stated
All agents must share one model (KV readable only by same model); requires standard attention: linear-attention/SSM/hybrid models compress the past into a fixed-size state, so merging several agents' states is unsolved; KV memory per round grows with agents x latent steps x layers.

## Innovation pattern (orchestrator note)
(1) a primitive whose cost profile changed (latent reasoning + KV-passing, from LatentMAS); (2) pushed to extreme scale (hundreds of agents); (3) free by-products reused as mechanisms (hidden states as a diversity metric; KV concatenation as crossover); (4) evaluator-rich setting with a time-to-quality metric.
