# Thousand-Brains Systems: Sensorimotor Intelligence for Rapid, Robust Learning and Inference

## What this paper does
Evaluates Monty, an implementation of a "thousand-brains system" modelled on cortical columns, on 3D object recognition and pose estimation (YCB). Monty is built from many semi-independent learning modules (LMs), each fed by its own sensor patch. Each LM keeps its own set of hypotheses (object id, rotation, location in the object's reference frame, evidence score) and updates them as the sensor moves. LMs exchange information only through a standard message format (Cortical Messaging Protocol, CMP: pose + features in a common body-centric frame). One use of CMP is lateral "voting", by which LMs bias each other's hypothesis evidence to reach consensus in fewer movements.

## Goal-by-goal answers

### Goal: What is the voting mechanism between modules: what is exchanged, over which channel, and in which reference frame?
Each LM runs its own full inference: hypotheses H = {(object m_k, rotation R_k, location x_k,t, evidence e_k,t)}, with evidence raised or lowered by how well each new observation matches the stored model near the hypothesised location [full text, Section 3.3, Eq 3-6]. Voting is a separate, lateral channel: with all-to-all bidirectional connectivity, a sending LM transmits its hypotheses (object id, location, normalised evidence in [-1, 1]) as CMP signals [Section 3.5]. Before sending, each hypothesised location is shifted by the instantaneous displacement between the two LMs' sensors, expressed in the shared body-centric frame and rotated into the hypothesised object frame (x_hat = x + R_k^-1 d_t). So a vote arrives already expressed in the receiver's coordinates. The receiver raises the evidence of its own hypotheses in proportion to how near they are to incoming vote locations [Section 3.5]. The authors stress that this is not bag-of-features agreement ("we both see mug features"). A vote helps only if it agrees with the receiver's hypothesis about where the object is [Section 3.5; Section 4.2.2]. In practice senders transmit only a subset of higher-evidence hypotheses, chosen by a threshold [Section 3.5].

### Goal: What does voting buy, and how does it scale with the number of modules?
With a grid of sensor patches (up to 8 SM-LM pairs), and convergence declared when k=2 LMs terminate, Monty "converge[s] to a likely representation with far fewer steps, a result that scales with the number of SMs", while classification accuracy stays "approximately level" [full text, Section 4.2.2, Fig 6C-D]. The text gives no exact step counts; the effect is shown in the figure. Voting therefore cuts the number of sequential steps (movements) needed, not the per-step cost of each module.

### Goal: What does voting rely on, and what are its stated limits?
(1) A common reference frame: CMP poses are in body-centric coordinates, so displacements between modules are well defined. Voting even works between independently moving sensors, such as two fingers on different hands, provided the displacement is updated [Section 3.5; Section 4.2.2]. (2) Modules stay self-sufficient: "Monty is able to leverage voting, but is not dependent on it". A single LM can still recognise objects by moving, only more slowly [Section 4.2.2]. Votes bias evidence and never overwrite a module's own hypotheses. (3) Voting complements movement and does not replace it, because only a fraction of the world is perceived at once [Section 4.2.2]. The paper reports no failure mode of voting such as herding; its experiments are on object recognition only.
