# Gemma 4 Technical Report

## What this paper does
Technical report of Gemma 4 (open-weight, 2.3B to 31B, dense and MoE 26B-A4B, multimodal, with a thinking mode). For long-context efficiency it keeps Gemma 3's local:global sliding-window interleave and adds p-RoPE on global layers, keys reused as values in global layers, and cross-layer KV sharing in the small models; it also releases an autoregressive MTP drafter head for speculative decoding and QAT checkpoints.

## Goal-by-goal answers
### Goal: What attention/KV structure does Gemma 4 use and what KV saving is claimed?
"4-to-1 local attention blocks for E2B and 5-to-1 for the rest"; "re-using keys as values in the global attention layers (except in E2B and E4B), i.e., values=keys"; p-RoPE with p=0.25 on global layers, RoPE on local; "effectively reducing the global KV cache by 37.5%"; KV cache shared "with ratios of 20/35 and 18/42 for the E2B and E4B model" [full text, Section 2 "Long-context efficiency"; also Section 1 "up to 37.5%"]. Memory with and without a 32K KV cache is tabulated for raw and quantized models [Section 2.5, Table 3].

### Goal: What decoding-acceleration component ships with it, and does it interact with the attention structure?
An MTP drafter: a 4-layer Transformer block (three local, one global attention layer; width 256 for E2B/E4B, 1024 for 26B-A4B and 31B) that "cross-attends to the KVs of the main model", eliminating MTP prefill; for E2B/E4B the vocabulary projection is replaced by top-k over token clusters (d x 262,000 -> d x 4096) "while preserving a similar acceptance rate" [Section 2.6]. Thinking mode improves reasoning (e.g. AIME 2026 no tools 89.2 for 31B vs 20.8 for Gemma 3 27B) [Section 4.2 table], so long generations hit the global layers' growing KV. No long-context limitation is stated in the sections read.
