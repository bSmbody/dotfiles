# Don't Read Everything: A Curvature-Conditioned Query for Linear Attention

## What this paper does
CCQ adds a read-time correction to linear attention. It maintains the running key covariance Sigma_t, which it derives as the curvature of a second-order expansion of the softmax log-partition, and contracts each query along high-variance memory directions, q - lambda_t Sigma_t q, before reading the state. The write rule is unchanged. Attached to GLA and Gated DeltaNet at 500M/1.3B, it improves perplexity, S-NIAH 8K, length extrapolation and LongBench.

## Goal-by-goal answers
### Goal: Does CCQ use a key-space second-moment matrix, and does it change what the state retains?
It keeps a d_k x d_k running key second moment and a key mean per head, with no decay [full text, Section 3.2, Idea 2 / Eq 9-10]. The matrix is used only at the read step: "Because S_t is never modified, CCQ slots onto a backbone's read without changing its write rule" [Section 3.2]. Retention and forgetting are untouched. The authors note that the covariance is undecayed even though GDN forgets, so "Sigma_t need not match the backbone's effective memory", and they leave "query-dependent, decay-aligned, and low-rank variants" to future work [Limitations]. The statistic is built from keys (what was written), not from queries (what was read).
### Goal: Can a d_k x d_k second-moment matrix be carried with existing chunkwise kernels, and at what cost?
Yes. The prefix sum of k k^T has the form of a linear-attention state with the value stream replaced by keys, so it is carried by one extra reduction per chunk plus a masked intra-chunk block [Appendix B / Eq 21-22]. The cost is about 16% lower training throughput, 8-10% more prefill latency, about 35% lower decode throughput and 50% more recurrent state [Limitations].
