# RECAP: Calibrating Low-Bit Reasoning Models on the History They Read

## What this paper does
RECAP is a PTQ calibration method (on top of FlatQuant) for W4A4KV4 / W4A8KV4 reasoning models. It (i) calibrates on the model's own FP reasoning trajectories with "dynamic prefixes": historical K/V are regenerated with the current quantizer while only a rotating 4K active block is reconstructed (12K prefix); (ii) adds a "prefix read geometry" penalty that weights each historical key and value error by how strongly later queries read it, using a diagonal-block GGN of the attention Jacobian. Evaluated on R1-Distill-Qwen-1.5B/7B and Qwen3-4B on MATH500, AIME-120, GSM8K, GPQA-D, LiveCodeBench with 32K output limit.

## Goal-by-goal answers
### Goal: What K-vs-V sensitivity formulas does it derive, and do they relate to attention concentration?
First-order: delta y_s = sum_t a_st delta v_t + sum_t (a_st/sqrt d)(v_t - y_s) q_s^T delta k_t [full text, Sec 3.3 Eq 8]. Diagonal K and V blocks of the GGN: G^K_t = E_s[a_st^2 ||v_t - y_s||^2 / d * q_s q_s^T], g^V_t = E_s[a_st^2], expected over future (in-block) queries, summed over GQA query heads [Eq 9]. So value sensitivity is exactly the squared attention weight (sum p^2 when aggregated), and key sensitivity is a^2 times the value contrast ||v_t - y_s||^2 times query energy, which vanishes when one token takes all the mass (y -> v_j). This is the output-MSE version of seed 1's asymmetry, already written down and averaged over the future query distribution, but used only as a calibration loss weight, "weighting key and value errors asymmetrically" -- not for bit allocation [abstract, Eq 10]. Cross-position and K-V cross terms are omitted.

### Goal: Does it show that quantization errors on history matter specifically for long CoT, and length effects?
Yes. Under W4A4KV4 AIME-120 improves 9.7/8.6/15.8 points over FlatQuant across the three models, LiveCodeBench +4.6/6.4/8.3, while GSM8K and GPQA gains stay <= 3.1 and 2.1 [Sec 4.2]. Read geometry adds +2.3-3.3 AIME-120 points with 4.8-11.8% fewer tokens [Sec 4.3]. On MATH500, of 101 questions flipped correct->incorrect by FlatQuant, 96 had longer quantized outputs, often near the 32K cap [Sec 4.3]. Importance scores fitted on three trajectories rank the best 10% of repairs on a held-out one near chance (AUC 0.43-0.50) [Sec 2.2] -- evidence against static per-token importance transfer.

### Goal: Is any allocation or online control involved?
No. All statistics are collected once from the FP model and frozen; nothing is needed at inference [Sec 3.3]. KV stays uniform 4-bit groups of 128.
