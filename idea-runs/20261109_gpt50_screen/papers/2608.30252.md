# Strong Drafts Need Compact Memories: Long-Context Speculative Decoding with Compressed KV Cache

## What this paper does
MASW (EMNLP 2026 Findings) gives a strong independent draft model (Llama-3.2-3B or 3.1-8B) a compressed draft-side KV memory. The memory has sink tokens, an exact local window (W=S=128), and periodically materialized memory slots produced by trained "mirrored" K/V projections. Compression is 4x or 8x. The target keeps its full KV and runs standard lossless verification. The argument: long-context SD needs draft capacity, because EAGLE-style one-layer heads lose acceptance at long prefixes. A strong draft, however, pays a KV-access cost per token that grows with the prefix (T ≈ αd² + βLd), so its memory has to be compressed [Section 3].

## Goal-by-goal answers
### Goal: What speedups at which lengths, versus EAGLE/EAGLE-3?
Setup: Llama-3.1-8B and 70B targets, LongBench summarization (GovReport, QMSum, MultiNews), prefixes 8K-32K, greedy, batch size 1, 8xH100 [Section 5.1]. Results for the 8B target [Table 1]:
- MASW: up to 2.08x at 32K.
- EAGLE-3: 0.92x / 0.96x / 1.01x / 1.06x at 8K / 16K / 24K / 32K, tok/iter ~2.06.
- EAGLE: 0.59x-1.08x.
- Full-KV SD with the L3B draft: 1.18x → 0.98x as the prefix grows.
- SWA draft: down to 0.37x.

For the 70B target, MASW gets up to 3.33x, EAGLE-3 0.44x-0.52x, and full-KV SD with L3B 2.46x → 2.03x [Table 1]. Draft-side memory drops by over 70% [abstract].

### Goal: How does the gain change with prefix length?
Full-KV SD loses speedup as the prefix grows, because draft KV traffic grows with it. MASW's best settings gain speedup with context on 8B and stay flat on 70B [Section 5.2]. Note that this is long input with short output (summaries), not long generated CoT.

### Goal: Stated limitations?
[Limitations]: the adaptor is trained on only 2B tokens at 8K context; only the K/V projections are trained, which may cap slot capacity; window, sink and slot interval are fixed, and adaptive allocation is left for future work; applying it to self-speculative drafting may weaken cost-effectiveness and is untested. All main latency numbers are at bs=1 [Section 5.1].
