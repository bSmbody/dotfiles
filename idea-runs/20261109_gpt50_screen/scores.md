
### C2 verdict
- **Verdict**: reject(reason=no evidence of headroom; decomposes into token-type mixed precision plus a trained pointer-copy head)
- **Evidence**:
  - [2509.20534] (GPT's cited source) does exist, but it is hash consing in JuliaSymbolics: identical symbolic subexpressions are deduplicated through a canonical weak-reference table. C2 does not deduplicate anything. A repeated literal's KV differs with its context, so the borrowed principle ("store canonical objects once, refer by address") does not establish what C2 needs: that a literal's downstream use depends only on its identity.
  - [2607.07144] (GPT's named neighbour) does exist and does what GPT says: it losslessly archives an already-quantized VQ index stream and supports random access and substring search on GPT-2. GPT's stated difference is correct, but this is not the closest prior work.
  - The "literals stay in high precision" half is per-token mixed-precision KV with a token-type importance rule. MiKV [2402.18096] keeps important tokens in high precision and the rest low. IntactKV [2403.01241] keeps one token class (pivots) exact. SemKV [2608.28911] finds that above the quality cliff, importance indicators are interchangeable and the gain of mixing is grid interpolation, which argues against a token-type rule giving anything extra. Addendum 1 also excludes precision-allocation rules.
  - The "copy head fetches raw bytes" half is the pointer-generator / CopyNet output interface [1704.04368][1603.06393][2307.06962]. In a decoder-only LLM the exact token ids are already stored at no cost, so the only new part is training a copy switch into a low-bit-KV model.
  - The target failure is a run that never stops: with 2-bit KV, Qwen3-8B hits the AIME25 length cap 11% -> 42% of the time, and LCB 11% -> 71% [2609.38121]. BreadthKV [2610.05685] also finds that derailed runs that hit the length cap dominate the loss. Neither source attributes the failures to copying literals wrongly, so C2 targets a failure mode nobody has shown is the main cost.
- **Strongest objection in 1 sentence**: In deep layers a literal's KV carries computed context (what the number means and the partial results built on it), so a byte table can only repair the emitted copy token and not the attention reads that compute with it; the remaining fix, keeping literal KV in high precision, is a known token-selective mixed-precision rule that the user has excluded.

#### Notes
- **Closest prior work**:
  - MiKV [2402.18096] and IntactKV [2403.01241]: token-selective high-precision KV.
  - SemKV [2608.28911]: indicators are interchangeable above the cliff.
  - Pointer-generator [1704.04368] and CopyNet [1603.06393]: copy-from-context output.
  - Fractal KV [2607.07144]: lossless symbolic storage of quantized KV, a different object.
  - Searches run:
    - All dates: numeric tokens in high precision; token-aware mixed precision; pointer/copy mechanisms in LLMs; outlier tokens kept in full precision; copy heads / retrieval heads under KV compression; numbers and digits under KV quantization.
    - Since 2025-06: the same themes again for recent work.
  - No paper combined a lossless literal side table with a low-bit KV copy path, so the exact combination is unclaimed. Each half is standard, though, and the combination has no motivating measurement.
- **Plausibility at memory saturation**:
  - Per-token cost: the generated token ids already sit in memory at about 4 bytes per token. Storing literals "losslessly" saves nothing on its own. Keeping their KV in BF16 costs 16 bits per value against 2.
  - Memory cost: if 15-25% of math-CoT tokens are digits, operators or identifiers, the average rises from about 2 to about 4-5.5 bits. That gives back most of the 2-bit saving, and the gain is already known to be grid interpolation [2608.28911].
  - Pointer-only variant: literal KV stays at 2 bits and only the output copy is exact. This fixes errors where the wrong digit is emitted while copying. It cannot fix attention reads in which later tokens compute with the number (carrying in arithmetic, comparisons, substitution), because those read the literal's deep-layer K and V, not its id. Re-embedding the raw id at layer l is not the layer-l V.
  - Training cost: the switch needs LoRA training and changes the output distribution.
  - Net: memory, latency and accuracy gains are unlikely, unless literal copy errors turn out to cause a large share of the 2-bit runaways. No evidence shows that.
- **Cheapest falsification (training-free, about 1 GPU-day)**:
  - Setup: Qwen3-8B on AIME25 (30 problems x 4 seeds) with OSCAR/KIVI INT2 KV.
  - Arms: (a) uniform INT2; (b) INT2 with the KV of every literal token (regex over digits, operators, identifiers) kept in BF16; (c) INT2 with the same number of randomly chosen tokens kept in BF16.
  - Measures: accuracy and length-cap hit rate.
  - Second check: teacher-force BF16 traces through the INT2 model and measure what fraction of first-divergence positions are copies of an earlier literal.
  - Kill condition: if (b) is not clearly better than (c) at equal bytes, or literal copies are a small share of divergences, there is no headroom for C2. Arm (b) is an upper bound on C2's accuracy benefit, since exact copies are at most as good as exact KV.


### C1 verdict
- **Verdict**: reject(reason=prior-work: the read-time cell-variance logit correction is 2605.26266; the joint-V term vanishes for the independent K/V quantizers used in practice)
- **Evidence**:
  - [2605.26266] (GPT's own cited id; it exists: ICML 2026 workshops, May 2026) already does the training-free, read-time version of C1. It models the cached key as k_hat + uniform cell noise and subtracts b_i = log E[e^{delta_i}] from every quantized score, in exact form (sum of log sinh(a)/a) and in Taylor form b_i = sigma_i^2/2 = (1/24d) sum_c q_c^2 Delta_{i,c}^2. The correction uses only the stored step sizes and the query, needs no extra memory, and has grouped, per-channel and QuaRot (Hq) variants (Sec 4.2, Eq 12-15, App E/F). This is exactly the orchestrator's "exp(q.mu + q^T Sigma q / 2)" form. GPT's claimed difference ("it only fixes the logit bias") therefore reduces to the V and cross terms below.
  - The joint (K,V) part only adds something under a joint codebook. Every practical 2-bit LLM KV quantizer quantizes K and V independently: KIVI-style and OSCAR [2605.17757], KVarN [2606.03458], TurboQuant/QJL [2504.19874, 2406.03482], and the VQ methods CQ [2405.03917] and NOVA-KV [2608.04074] (separate key and value transforms and codebooks). Under that factorization E[e^{qK}V | C] = E[e^{qK}|C_K] * E[V|C_V]. The numerator correction is then the same key correction times the value centroid, and the Rao-Blackwell "K-V correlation" term Sigma_VK q is exactly zero. Making it nonzero needs a new joint (K,V) vector quantizer, kernels and per-cell cross-covariances. That is a different, heavier project, and nobody has shown the term is large.
  - "Calibrate the cell distributions" only makes sense for fixed codebooks (VQ: CQ, NOVA-KV). In per-token affine INT2 (KIVI, OSCAR, KVarN) the cells are defined by per-token scales and are not reusable objects. There the only statistic available is the uniform-noise variance, which 2605.26266 already uses.
  - In decode the expected gain is small and may not hit the target pathology. 2605.26266 itself says single-token decoding "offers less headroom", and that the correction helps little when attention is concentrated on a few cached tokens (Sec 6). Its LLM evidence is teacher-forced NLL under chunked prefill only (App O). KVarN [2606.03458] traces long-CoT degradation to per-token scale (magnitude) errors that accumulate over steps, which is realization error, not mean bias. An in-expectation correction leaves the per-realization noise unchanged.
- **Strongest objection in 1 sentence**: The nearly-free part of C1 is already published as the Jensen-bias correction of [2605.26266]. The only new piece, the joint K-V marginalization, is identically zero for the independent K/V quantizers used in practice, so the delta reduces to "apply 2605.26266 to long-CoT decoding", which is an evaluation, not a method.

#### Notes
- **Closest prior work**: [2605.26266] (the same mechanism for key cells, video diffusion plus an LLM partial-prefill NLL diagnostic). Neighbours: [2608.04074] NOVA-KV (attention-product-distortion transform coding with MSE-optimal VQ, so centroids are already conditional means); [2608.02691] OptR (minimizes post-W_O attention-output error from both the K- and V-induced terms, learned rotations); [2504.19874] TurboQuant_prod and [2406.03482] QJL (unbiased inner-product estimators, which are still biased after exp, i.e. they have the Jensen bias C1 targets); [2606.03458] KVarN (2-bit error accumulation in reasoning decode comes from token-scale errors). Queries run (11 in total; the arXiv web fallback returned 0 hits for long multi-word phrasings): "quantized KV cache softmax bias correction", "Jensen bias attention quantization", "expected exponential quantization noise attention", "quantization noise softmax attention correction", "KV cache vector quantization" (since 2025-09), "attention-aware KV cache quantization" (since 2025-09), "KV cache quantization reasoning models" (since 2025-09), "quantized attention unbiased softmax", "joint key value quantization", "vector quantization joint key value codebook KV cache", "Rao-Blackwell attention". No hit proposes joint (K,V) cell marginalization. The only hit on the bias mechanism is 2605.26266.
- **Plausibility at memory saturation**: Bytes at read time are unchanged. b_i comes from the scales already stored per group, a VQ variant needs a per-centroid q^T Sigma_c q lookup table computed once per query, and the FLOPs are a few multiply-adds per group next to QK^T. So C1 cannot change the bits x L^2 cost directly. It can only lower cost per correct answer by recovering accuracy and length at the same 2 bits, for example by cutting the Qwen3-8B AIME25 cap-hit rate from 42% back toward 11% under OSCAR INT2 [2609.38121]. That premise is weak. (i) In single-token decode a correction that is uniform across tokens cancels inside softmax. Only differences in sigma_i^2 across tokens matter, plus the competition with the BF16 sink and recent windows (OSCAR keeps 64 + 256 BF16 tokens [2605.17757]), so there is some headroom, but it is second order. (ii) Runaways are more plausibly driven by realization errors on a few high-mass tokens and by scale errors that accumulate [2606.03458], which an expectation correction does not touch, as 2605.26266 itself concedes for concentrated attention. (iii) The joint-V term is zero for the independent quantizers above. The expected gain is small but nonzero. It is worth knowing as a free plug-in baseline for other candidates, not as a paper.
- **Cheapest falsification**: Take about 20 BF16 Qwen3-8B AIME25 traces of 20-40K tokens. Replay them teacher-forced in HF with OSCAR- or KIVI-style INT2 KV, once plain and once with the 2605.26266 Taylor correction (Eq 15, about 20 lines in the attention function, with the BF16 sink and recent windows as the unquantized set). Measure per-token KL to BF16 next-token distributions, overall and in the 2K tokens before each point where the INT2 free run starts looping. If the correction closes less than ~20% of the INT2-to-BF16 KL gap, C1 is dead in every form (the joint-V extension can only add a term that is zero under these quantizers). This takes one GPU-day and needs no new kernel.

### C6 verdict
- **Verdict**: reject(reason=interval-read primitive already exists; low-dim signature cannot carry video-QA content and a frozen VLM cannot read it; no efficiency gain over streaming KV memories)
- **Evidence**:
  - [1603.03788] (GPT's source, exists, accurately cited for Chen's identity, Thm 1.2) also shows level k has d^k terms and that the signature encodes increments/areas of a path, not its content (1-D signature depends only on X_b - X_a). The math claim is correct; it is the payload that is weak.
  - [2001.00706] Signatory (ICLR 2021) already implements the exact mechanism C6 proposes: O(L) prefix Sig and InvertSig, then Sig(x_i..x_j) = InvertSig(x_1..x_i) ⊠ Sig(x_1..x_j) in O(1), plus online update; it warns of numerical instability for large i,j (exactly the long-video regime).
  - [2405.20799] Rough Transformers (NeurIPS 2024) already feed global S_{0,t_k} and local window signatures as compressed tokens to attention over long sequences; they note O(d^n) size and rely on small raw d and end-to-end training — neither holds for a frozen VLM over 1000+-dim visual features.
  - [2602.22142] (GPT's novelty foil, exists, CVPR 2026) trains order awareness and does entropy-gated coarse-to-fine recall of frame KV; the contrast GPT draws is accurate but WeaveTime is not the closest efficiency baseline.
  - [2511.07278] StreamKV and [2605.22269] MuKV (CVPR 2026) already give training-free segment-/multi-granularity summaries plus retrieval of real KV that the frozen LLM attends to; summarizing an interval is cheap there (mean pooling), so O(1) interval reads attack a non-bottleneck.
  - Novelty queries (path signature video; signature transformer video; log-signature video recognition; rough path video; signature kernel video; path signature multimodal; signature video large language model; Chen identity signature streaming; segment tree / prefix sum memory streaming video; interval query long video memory; streaming video LLM memory KV compression; rough transformer; since-2024 path signature) found no signature-based memory for video LLMs — so the application is unclaimed, but only skeleton-action signature work (Logsig-RNN 2110.13008, 1707.03993; not read) exists in video.
- **Strongest objection in 1 sentence**: The only new part is "apply Signatory's O(1) interval query to a tiny projection of VLM features", and a few-hundred-number geometric summary of feature motion is neither what video QA needs nor something a pretrained VLM can consume without training a new readout, so there is no cost-per-correct-answer win over StreamKV/MuKV-style KV memories.

#### Notes
- **Closest work**: mechanism — [2001.00706] (Path class: prefix signature + inverse, O(1) arbitrary interval, streaming update) and [2405.20799] (prefix/window signatures as Transformer tokens for long sequences). Target-problem — [2511.07278], [2605.22269], [2602.22142] (streaming video KV memory with segment summaries and retrieval). No 2025-2026 paper applies signatures to video-LLM memory.
- **Plausibility**: Truncated signature size is sum_{k<=n} d^k, so to stay near one token's width (~4K floats) one needs e.g. d=8, n=3 (584) or d=16, n=3 (4368): per-frame visual features (hundreds of tokens x ~1-4K dims) must be squashed to 8-16 channels before the signature is even taken. Higher levels then encode ordered co-variation of those few channels (Lévy areas, etc.), which helps "did A happen before B along these directions" but discards appearance detail, OCR, counting, and spatial layout that dominate Video-MME/MLVU errors; level 1 is just the endpoint difference, so a constant object present throughout an interval is invisible unless a basepoint/time augmentation is added. A frozen LLM has no way to read a tensor-algebra element: it needs a trained projection into its embedding space (GPT's own minimal experiment admits "light-train projection and readout"), which turns this into training a new memory adapter, and the readout must learn exponentially-sized, factorially-decaying, badly-scaled features. The O(1) interval read also requires knowing which interval to read; for QA the interval is unknown, so you still search over intervals (and the search cost, not the per-interval summary, is what StreamKV/MuKV optimize). Memory is fine (one ~600-4K-float vector per block boundary), but real KV memories already hit low memory via pruning, and their payload is directly attendable. Finally, S[0,a]^{-1} ⊗ S[0,b] cancels large prefix terms in float16/32 over thousands of frames, the instability Signatory flags. Net: not an efficiency gain over existing streaming video KV memories, and likely an accuracy loss.
- **Cheapest falsification**: no LLM needed. On Video-MME (or NExT-QA temporal subset) extract Qwen3-VL vision-encoder frame features, PCA to d in {8,16}, and compare a linear/MLP probe on (a) level-3 signature of the ground-truth or uniformly chosen interval vs (b) equal-float-count mean/max pooling of the same features (and of the unprojected features), predicting the multiple-choice answer given a question embedding. If (a) does not beat (b) at equal floats — especially on temporal-order questions where it should shine — the idea is dead; also log the relative error of S[0,a]^{-1}⊗S[0,b] vs direct computation in fp32 for 1-hour videos at 1 fps.


### C5 verdict
- **Verdict**: reject(reason=linear "innovation" is ill-posed in a non-linear ViT token space; the readable form collapses to known cross-view crop-token pruning, with a small saving)
- **Evidence**:
  - [2607.23913] (GOTS, the only id GPT cites; exists, Jul 2026) runs QR-with-pivoting on post-encoder features of ONE image and forwards the *original* selected tokens; the orthogonal residual is only a scoring quantity. It also states the rank ceiling K <= d: span(X) is at most d-dimensional, so once a full image has put >= d tokens in context (Qwen-VL: ~1-4K tokens), every crop token's linear orthogonal complement is numerically ~0 regardless of how much new detail it carries. GPT's stated delta ("decompose all observations, change what a re-look writes") is real in wording but its premise is broken by this rank fact.
  - [2501.05179] (GlobalCom2, AAAI 2026) already uses the global thumbnail to decide, training-free, how many and which crop tokens are redundant (thumbnail-guided per-crop ratio + holistic TopK), keeping >90% accuracy at 90% compression. That is the practical "only write what the global view lacks" mechanism, done by selection.
  - [2509.14199] (GRT) does innovation coding for video (key frame + SSIM-gated P-frame patches) and, tellingly, feeds the pretrained ViT the *changed patches themselves*, not pixel residuals, because residual signals are not what the encoder was trained on. Swap "time" for "scale" and this is C5's only training-free readable variant.
  - [2610.27341] (LoRe, NeurIPS 2026) attacks the same cost (redundant tokens/turns in thinking-with-images) by writing ZERO new tokens: it rescales cached value entries of the box region; it notes this cannot recover detail lost in encoding, which is the narrow niche C5 would have to win in.
- **Strongest objection in 1 sentence**: Crop tokens are a non-linear re-encoding at a different scale, so their "orthogonal innovation" w.r.t. the full-image token span is either ~zero (rank-saturated span) or an out-of-distribution residual the frozen LLM cannot read, leaving only thumbnail-guided crop-token pruning, which GlobalCom2/GOTS/GRT-style gating already cover.

#### Notes
- **Source check**: the cited source is "Kailath innovations representation (not found on arXiv)" — classical linear-Gaussian estimation, where innovation = new measurement minus its linear prediction from past measurements. It works because measurements are linear in a shared state; that is exactly the condition that fails here (ViT features are a non-linear, resolution-dependent function of pixels). Only id cited by GPT: [2607.23913], verified, does selection only.
- **Queries run (arXiv, mostly --since 2025)**: redundant visual tokens zoom crop thinking with images; thinking with images token cost; crop token reuse full image; incremental visual tokens zoom-in; residual visual encoding crop high-res; multi-turn zoom token redundancy; zoom visual token redundancy; crop visual tokens reuse; zoom-in token compression; visual token reuse multi-turn; redundant crop tokens; multi-scale visual token deduplication; high-resolution crop global thumbnail redundant tokens; Laplacian pyramid visual tokens; residual tokens high-resolution VL; zoom KV cache reuse vision; orthogonal complement visual tokens; innovation tokens multimodal. No paper writes orthogonal-complement innovations for re-looks (the literal mechanism is unclaimed), but the closest prior covers every *workable* version: [2501.05179] (thumbnail-guided crop-token compression), [2607.23913] (span-residual selection), [2509.14199] (innovation-gated patch tokenization, video), [2610.27341] (no-new-token re-look via KV value scaling). Other hits seen by title/abstract only (not cited): Q-Zoom (2604.06912, coarse-to-fine RoI with gating), FALCON (2501.16297, registers to remove crop redundancy), OPO (2611.04943, RL for observation actions).
- **Plausibility**: There are two readings and neither works cleanly. (i) Feature space: crop tokens come from re-running a non-linear ViT on an upsampled sub-image, so they are not linear combinations of the full-image tokens even where content is identical (different receptive field, scale, RoPE/2D positions); worse, a 1-4K-token full image already spans most of R^d (d ~ 1-3.5K after the merger), so the least-squares complement is tiny for every token and novelty is not measured by it. Storing "innovation + reconstruction coefficients" also asks the LLM to recombine inputs linearly, but what the LLM consumes are K/V after non-linear layers, so input-level linear reconstruction is not what attention sees; without training it would read the residual as noise. (ii) Pixel space (A = crop/upsample operator on the field F): the innovation is the high-pass band missing from the downsampled view, which is well defined, but a ViT emits one token per patch whether you feed it the crop or its residual, so tokens are only saved by dropping low-residual patches, i.e., a gating rule like GRT/GlobalCom2; the residual image itself is out of distribution for the frozen encoder ("light-train a readout" becomes encoder+connector training). On the efficiency side, a re-look adds ~256-1K visual tokens to a context that, for reasoning VLMs, holds thousands of CoT tokens; prefix caching already avoids re-encoding the full image across turns, and LoRe shows the turn overhead, not the crop tokens, dominates latency. Even a 50-70% cut of crop tokens is a small share of cost per correct answer, and it does not touch the long-CoT KV that problem.md targets. It is a "what is written" mechanism (passes the Addendum's no-control-loop test), but it is weak on value and premise.
- **Cheapest falsification (half a GPU-day)**: Qwen2.5-VL-7B (or Qwen3-VL-4B), V*-Bench + HR-Bench with ground-truth crops. Extract merger-output tokens for the full image X and the crop C. Measure (1) the fraction of ||C||^2 inside span(X) and inside rank-r truncations (r = 64...1024): if it is ~1 at full rank, linear innovation is degenerate; (2) accuracy when the crop's tokens are replaced, at a matched token budget k, by (a) C's orthogonal residual tokens, (b) top-k crop tokens by residual energy, unchanged (GOTS across views), (c) GlobalCom2-style thumbnail-guided TopK, (d) all crop tokens. C5 survives only if (a) is close to (d) and beats (b)/(c) at the same k; prediction: (a) collapses, and (b) ~ (c).


### C3 verdict
- **Verdict**: reject(reason=saves a negligible share of decode bytes; the K read it cannot touch dominates)
- **Evidence**:
  - [2605.01910] GPT's ids are real. SANTA does sample each head independently (i.i.d., stratified, or systematic with one offset per query), and under GQA the V traffic is the union of the group's samples [Section 2.1, Section 3.4]. So the claimed delta, coupling the samples across heads, is real and not proposed there. But SANTA only sparsifies V. Keys are read in full to form p_h. The authors themselves bound the worst-case 4-head union at <=1.56% of V rows (S=128, 32k). That union is all that coupling can shrink.
  - [1903.00632] Real paper, but it is on pairwise-optimal coupling of many variables (pairwise disagreement <= 2d/(1+d), built from shared randomness). GPT's "common mass min_h p_hi, then residuals" is the classic all-agree common-component coupling. It is valid and keeps marginals, so each head stays unbiased, but it is not the construction this paper proves optimal. The grounding is loose but harmless.
  - [2607.24593], [2610.19026] Sharing one sparse read set across a query group / KV head is standard for deterministic top-k: PIVOT shares the scan across grouped queries, and JSSA selects per KV head with a GQA kernel. Both also cut the key-scoring cost, which C3 leaves untouched. [2410.16179] MagicPIG and [2510.05688] vAttention are earlier sampling-based decode attention. No prior work found that couples stochastic attention samples across heads, so the narrow delta survives.
- **Strongest objection in 1 sentence**: With GQA, FlashDecoding already reads each K/V tile once per group, and SANTA already reads all keys plus only ~1-2% of V rows, so coupling can at most turn a ~4S-row union into ~S rows. That is <1% of per-step KV bytes for Qwen3-8B at 32k (about 384 of 65k rows per KV head), and the cost is correlated per-head errors that no longer average out through o_proj.

#### Notes
- **Closest prior work**: [2605.01910] SANTA (per-head independent sampled V, union over GQA; mean-group-query sharing on the K side). [2607.24593] PIVOT and [2610.19026] JSSA (group-shared deterministic sparse reads). [2410.16179] MagicPIG and [2510.05688] vAttention (sampling-based decode attention). Queries run (12): maximal coupling attention heads; coupled sampling attention grouped query; stochastic attention sampling value rows decoding; sampling-based attention unbiased estimator KV cache; shared sparse index grouped-query attention decoding; head-shared token selection GQA sparse attention; common random numbers attention sampling; Monte Carlo attention decoding memory bound; and, since 2025-06, importance sampling attention decoding; sampling attention output unbiased; query group union sparse attention GQA; stochastic sparse attention. None hit cross-head coupled sampling.
- **Plausibility in long-CoT decoding at memory saturation**:
  - *What a step costs.* In batched decode at saturation, step time is set by KV bytes. Under GQA, FlashDecoding already loads each K and V tile once per KV head for all G query heads, so dense reads are already "co-read". Forming p_h needs q_h·k_i for every key, so 100% of K is read whatever is done with V. SANTA-style sampling then reads only the union of sampled V rows, at most G·S rows.
  - *The ceiling.* Take Qwen3-8B (G=4) at n=32k with S=128. Independent sampling reads at most 512 V rows; perfect coupling reads at least 128. The saving is at most 384 rows out of 65,536 K+V rows per KV head, about 0.6% of step bytes. In reality heads in a group differ, so sum_i min_h p_hi < 1 and the saving is smaller.
  - *Overheads.* The min-over-heads needs every head's normalised p first, which forces a global-sync pass like S2ANTA-prop, plus extra compute.
  - *Accuracy risk.* Each head stays unbiased, but head errors become positively correlated, so the variance of the o_proj sum goes up. That is dangerous in 10K-60K-token CoT, where small per-step noise compounds into runaways.
  - *Free baseline.* Sharing the systematic offset U across a group's heads already gives quantile coupling at zero cost.
  - *Where it could matter.* Only when keys are also cheap: after top-k/page preselection to n'~2k candidates, or with low-dim key scoring as in JSSA. There the V union can be ~10% of bytes, but the method then becomes "a sampling tail on top of a sparse-attention method". That is vAttention's territory, and the gain is still modest.
- **Cheapest falsification**: offline in HF, no kernel. Dump per-layer, per-head softmax distributions from Qwen3-8B on ~5 AIME25 traces at decode positions 4k/16k/32k. For S in {64,128,256}, compute (a) the group overlap sum_i min_h p_hi, and (b) the expected unique V rows per KV head under independent S2ANTA-sys, shared-offset systematic, and min-coupling. Express the coupling saving as a fraction of total K+V bytes per step. If the best-case saving is below ~2% of bytes (expected: <1%), the idea is dead. If it is above ~10% with top-k preselection, re-scope it as a tail estimator for sparse attention.


### C4 verdict
- **Verdict**: reject(reason=incremental over SANTA; value-only savings with key scan as floor, no memory-capacity gain; cube/Carathéodory weighting replaceable by a cheap control variate)
- **Evidence**:
  - [2510.14916] exists and is real, but it is DETERMINISTIC Carathéodory-Steinitz pruning of a positive quadrature rule (kernel-vector elimination, QR/Givens downdates, O(N^2) per removed node, sequential) with no randomization and no E[w]=p; GPT's "martingale elimination with E[w]=p and exact moments" is instead the survey-sampling cube method of Deville-Tillé [2407.13613], a classical technique.
  - [2609.35629] exists (SANTA++, 2026-09): samples key TEAMS from representative-key routing and applies inverse-inclusion (importance) correction precisely so that it does NOT read all keys. C4 needs the exact p over all tokens, so its true baseline is SANTA, not SANTA++.
  - [2605.01910] SANTA (ICML 2026) already does C4's setting: full key scan, exact p, sample S V-rows from p, unbiased, with stratified/systematic variance reduction; at accuracy-matching S=128 of 32K it gets only ~1.5x attention-kernel and ~1.25x end-to-end speedup, because the full key scan is ~50% of KV bytes and is untouched.
  - [2610.24991] (2026-10) PPS/threshold sampling with Horvitz-Thompson estimator plus centered (value-spread) certificates, again paying an all-keys (4-bit) pass and saving on values; another close occupant of the "unbiased value sampling with variance control" slot.
  - [2407.13613] Under a linear outcome model the cube method's variance gain equals regression adjustment on the balanced covariates (Prop 3), so C4's projected-moment balance buys what a linear control variate on u=Pv buys, and the exact balance can fail at the landing phase.
- **Strongest objection in 1 sentence**: With the exact p in hand the only bytes left to save are the sampled V rows, which SANTA already reduces to well under 1% of V at S=128, so a better-balanced sampler cannot move cost per correct answer while the full key scan (and unchanged KV capacity) remain the floor.

#### Notes
- **Closest prior work**: SANTA / S^2ANTA [2605.01910] (same regime, same unbiased V-sampling, stratified/systematic variance reduction); Certified Sparse Attention via Perturbed Retrieval [2610.24991] (PPS + HT + centered bounds); SANTA++ [2609.35629] (grouped routing, avoids the key scan). The mechanism itself is the cube method / balanced sampling [2407.13613]. Ten+ queries run (sampling attention importance sampling KV, control variate attention, unbiased sparse attention, Carathéodory attention, moment-matching sparse attention, recombination quadrature attention, balanced sampling cube method, kernel quadrature recombination, plus 2026 recency queries "stochastic attention", "sampling attention variance reduction", "importance sampling attention", "attention output correction sparse"): no hit applies balanced/Carathéodory moment-constrained sampling to attention, so the narrow delta is unclaimed, but it is a variance tweak on SANTA. (Efficient Attention via Control Variates, 2302.04542, is random-feature linear attention with training, not this; seen by title/abstract only.)
- **Plausibility at long-CoT memory saturation**: At memory saturation the binding constraint is KV capacity (batch size), and C4 stores everything plus u=Pv, so batch size does not grow; the only lever is per-step attention latency. Computing p needs all keys (Qwen3-8B: 8 KV heads x 128 x 2 B = 2 KB of K per token per layer, half of KV bytes), so even zero V reads cap attention speedup below 2x, and SANTA already sits near that cap (1.5x kernel, 1.25x e2e). C4 also reads u for every token (r/d of V bytes, e.g. 12.5% of V at r=16), and with GQA each of the 4 query heads sharing a KV head has its own p and w, so V reads are the union of four samples. The weight-generation step is a per-(query head, layer, token) cube flight phase over n ~ 10-60K units with r+1 constraints, O(n r^2) and sequential over units, which is GPU-hostile and likely costs more time than the V reads it avoids; a linear control variate o_hat = SANTA + B(sum p u - SANTA_u) gives the same projected exactness in O(n r) fully parallel. Stochastic attention noise compounding over 30K decoded tokens is also untested (SANTA's reasoning checks are GSM8K/MMLU), so it may raise runaway/cap-hit rates exactly where cost lives.
- **Cheapest falsification**: Offline, no kernel: dump decode-time (q, K, V) from Qwen3-8B on ~20 AIME long-CoT traces at positions 8K-32K; per head, with P = top-16 PCA of V, compare relative L2 error of the attention output at equal V-row budget S in {32, 128} for S^2ANTA-sys, S^2ANTA-sys + linear control variate on u, and cube-balanced sampling, and report the sampled-V bytes as a fraction of total attention bytes at the S where the error matches bf16-vs-INT8 noise. Kill if cube-balanced is not clearly better than the control variate, or if sampled-V bytes are already < ~10% of attention bytes at that S (no headroom). A few GPU-hours.


### C7 verdict
- **Verdict**: reject(reason=no real compute saving: VLM test cost grows with pooled tokens, fixed-budget pools give false negatives on small targets, and single-pass / hierarchical search already beats O(k log n))
- **Evidence**:
  - [2006.08420] (GPT's source, exists; pure coding theory, no learning) states non-adaptive exact identification with disjunct matrices needs Omega(k^2 log_k n) tests (O(k^2 log n) by random construction); O(k log n) holds only for list-disjunct (superset + second stage) or adaptive schemes. The candidate's "fixed disjunct matrix, ~O(k log n)" claim is wrong by a factor k, and the error-tolerant variants handle FN or FP but not both fast (Section 3.3), while VLM OR readouts have both.
  - [2608.04452] (GPT's novelty contrast, exists) Q-CueGraph uses one OWLv2 detector pass plus one reader pass on natural images (Section 3.5) and reaches 0.832 on V*Bench with Qwen2.5-VL-7B; the contrast "fixed codes vs selected crops" is real but shows the baseline already costs ~O(1) MLLM passes, not n.
  - [2011.10704] Neural Group Testing already transfers group testing to NN inference (adaptive, non-adaptive double pooling, feature-space max merge); savings exist only because the trunk after the merge has fixed cost per group and require fine-tuning; pixel-space merging loses recall.
  - [2305.07639] already does fixed m x n pooling matrices over max-superposed feature maps with CS/GT decoding; C7's "fixed set code + algebraic decoding" is this, moved from images-in-a-batch to regions-in-an-image.
  - [2502.17422] MLLM accuracy collapses on small targets in large/downsampled views (Table 1) yet attention localises them in one pass; [2608.30705] VisLens does V* search in a single pass (0.98 s vs 8.78 s Thyme); [2411.16044] ZoomEye's quadtree search is already adaptive coarse-to-fine and needs an extra "latent" prompt because coarse existence answers are unreliable; [2503.01222] composing more crops into one image hurts single-instance fine-grained accuracy.
  - [2312.14135] V*Bench has k = 1 (attribute) or 2 (spatial) targets, so group testing's k << n regime offers at most a few-fold saving over log-depth hierarchical search, and nothing over single-pass localisation.
- **Strongest objection in 1 sentence**: A VLM "test" costs tokens proportional to the pixels it is shown, so a pool either shows the regions at native resolution (total cost = n x column weight >= one full-resolution pass) or downsamples them (the small-target false negatives that zooming exists to fix), and the only regime where pooling is cheap, a light head on shared encoder features, makes testing every region individually nearly free and group testing pointless.

#### Notes
- **GPT's ids**: [2006.08420] exists (Cheraghchi & Nakos, efficiently decodable disjunct / list-disjunct matrices, no ML). [2608.04452] exists (Q-CueGraph, Aug 2026, query-conditioned evidence graphs; natural-image branch = OWLv2 detections + composed window).
- **Closest prior work**: mechanism-level, [2011.10704] Neural Group Testing and [2305.07639] pooled-matrix CS/GT over superposed features (both items = whole images). Target-level, the efficient-visual-search line: [2502.17422] ViCrop (attention localisation, 1-2 passes), [2608.30705] VisLens (single pass), [2411.16044] ZoomEye and [2312.14135] V* (hierarchical log-depth search), [2503.01222] RAP (retriever-scored crops composed into one layout), [2608.04452] Q-CueGraph (detector + one composed window). Searches (group testing + vision / LLM / neural network, pooled testing image regions, binary search image regions VLM, composite multi-crop VLM, hierarchical zoom MLLM, high-resolution visual search 2025-11..2026-11) found no paper applying group-testing codes to region search inside a VLM; the delta is real but narrow, and the mechanism itself is not new.
- **Plausibility**: The OR readout is the weak link. To answer "is the target in any of these regions" a VLM must see the regions; on a composite or masked image at a fixed token budget each region is shrunk by roughly the pool size, which is exactly the small-object regime where MLLMs fail ([2502.17422] Table 1, [2503.01222] Section 3.3, ZoomEye's need for a latent-confidence prompt). The resulting false negatives are fatal for group testing because a negative pool rules out all its members. At native resolution there is no FN problem but no saving either: total visual tokens = sum of pool sizes = n x (tests per region) >= n, i.e. at least one full high-resolution pass, and each region enters O(k log n) pools. In V*-style tasks k = 1-2 and n is ~20-40 tiles at 336-448 px for a 2246x1582 image, so disjunct designs need ~k^2 log n = 10-25 tests, no better than n per-region queries and worse than hierarchical quad-tree search (~k log4 n, adaptive) or single-pass attention / logit-lens localisation (~1 extra pass, [2608.30705]). Feature-space superposition (NGT-style max-merge of region tokens before the LLM) would cut tokens, but it is off-distribution for a frozen VLM, needs real training, and if it is a small set-predicate head on encoder features, scoring each region individually with that head costs almost nothing next to one LLM prefill. The forward-pass saving is therefore not real against the baselines that matter.
- **Cheapest falsification (one afternoon)**: Qwen2.5-VL-7B on V*Bench. Tile each image into n native-res tiles; for the GT-target tile, build pools of size s in {1, 2, 4, 8} with random distractor tiles, rendered (a) as a fixed-budget composite and (b) as native-res multi-image input. Ask "Is there a <target>? Yes/No" and measure pool-level recall and visual tokens per test. Compare the decoded localisation accuracy and total tokens against one full-resolution pass with ViCrop-style attention argmax. Kill C7 if (a) recall at s = 4 falls below ~95% (one FN per decode wipes out the target) or (b) total tokens of the design are >= the single full-res pass at matched localisation accuracy.
