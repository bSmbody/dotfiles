
### C2 verdict
- **Verdict**: reject(reason=no evidence of headroom; decomposes into token-type mixed precision plus a trained pointer-copy head)
- **Evidence**:
  - [2509.20534] (GPT's cited source) does exist, but it is hash consing in JuliaSymbolics: identical symbolic subexpressions are deduplicated through a canonical weak-reference table. C2 does not deduplicate anything. A repeated literal's KV differs with its context, so the borrowed principle ("store canonical objects once, refer by address") does not establish what C2 needs: that a literal's downstream use depends only on its identity.
  - [2607.07144] (GPT's named neighbour) does exist and does what GPT says: it losslessly archives an already-quantized VQ index stream and supports random access and substring search on GPT-2. GPT's stated difference is correct, but this is not the closest prior work.
  - The "literals stay in high precision" half is per-token mixed-precision KV with a token-type importance rule. MiKV [2402.18096] keeps important tokens in high precision and the rest low. IntactKV [2403.01241] keeps one token class (pivots) exact. SemKV [2608.28911] finds that above the quality cliff, importance indicators are interchangeable and the gain of mixing is grid interpolation, which argues against a token-type rule giving anything extra. Addendum 1 also excludes precision-allocation rules.
  - The "copy head fetches raw bytes" half is the pointer-generator / CopyNet output interface [1704.04368][1603.06393][2307.06962]. In a decoder-only LLM the exact token ids are already stored at no cost, so the only new part is training a copy switch into a low-bit-KV model.
  - The target failure is a run that never stops: with 2-bit KV, Qwen3-8B hits the AIME25 length cap 11% -> 42% of the time, and LCB 11% -> 71% [2609.38121]. BreadthKV [2610.05685] also finds that derailed runs that hit the length cap dominate the loss. Neither source attributes the failures to copying literals wrongly, so C2 targets a failure mode nobody has shown is the main cost.
- **Strongest objection in 1 sentence**: In deep layers a literal's KV carries computed context (what the number means and the partial results built on it), so a byte table can only repair the emitted copy token and not the attention reads that compute with it; the remaining fix, keeping literal KV in high precision, is a known token-selective mixed-precision rule that the user has excluded.

#### Notes
- **Closest prior work**:
  - MiKV [2402.18096] and IntactKV [2403.01241]: token-selective high-precision KV.
  - SemKV [2608.28911]: indicators are interchangeable above the cliff.
  - Pointer-generator [1704.04368] and CopyNet [1603.06393]: copy-from-context output.
  - Fractal KV [2607.07144]: lossless symbolic storage of quantized KV, a different object.
  - Searches run:
    - All dates: numeric tokens in high precision; token-aware mixed precision; pointer/copy mechanisms in LLMs; outlier tokens kept in full precision; copy heads / retrieval heads under KV compression; numbers and digits under KV quantization.
    - Since 2025-06: the same themes again for recent work.
  - No paper combined a lossless literal side table with a low-bit KV copy path, so the exact combination is unclaimed. Each half is standard, though, and the combination has no motivating measurement.
- **Plausibility at memory saturation**:
  - Per-token cost: the generated token ids already sit in memory at about 4 bytes per token. Storing literals "losslessly" saves nothing on its own. Keeping their KV in BF16 costs 16 bits per value against 2.
  - Memory cost: if 15-25% of math-CoT tokens are digits, operators or identifiers, the average rises from about 2 to about 4-5.5 bits. That gives back most of the 2-bit saving, and the gain is already known to be grid interpolation [2608.28911].
  - Pointer-only variant: literal KV stays at 2 bits and only the output copy is exact. This fixes errors where the wrong digit is emitted while copying. It cannot fix attention reads in which later tokens compute with the number (carrying in arithmetic, comparisons, substitution), because those read the literal's deep-layer K and V, not its id. Re-embedding the raw id at layer l is not the layer-l V.
  - Training cost: the switch needs LoRA training and changes the output distribution.
  - Net: memory, latency and accuracy gains are unlikely, unless literal copy errors turn out to cause a large share of the 2-bit runaways. No evidence shows that.
- **Cheapest falsification (training-free, about 1 GPU-day)**:
  - Setup: Qwen3-8B on AIME25 (30 problems x 4 seeds) with OSCAR/KIVI INT2 KV.
  - Arms: (a) uniform INT2; (b) INT2 with the KV of every literal token (regex over digits, operators, identifiers) kept in BF16; (c) INT2 with the same number of randomly chosen tokens kept in BF16.
  - Measures: accuracy and length-cap hit rate.
  - Second check: teacher-force BF16 traces through the INT2 model and measure what fraction of first-divergence positions are copies of an earlier literal.
  - Kill condition: if (b) is not clearly better than (c) at equal bytes, or literal copies are a small share of divergences, there is no headroom for C2. Arm (b) is an upper bound on C2's accuracy benefit, since exact copies are at most as good as exact KV.


### C1 verdict
- **Verdict**: reject(reason=prior-work: the read-time cell-variance logit correction is 2605.26266; the joint-V term vanishes for the independent K/V quantizers used in practice)
- **Evidence**:
  - [2605.26266] (GPT's own cited id; it exists: ICML 2026 workshops, May 2026) already does the training-free, read-time version of C1. It models the cached key as k_hat + uniform cell noise and subtracts b_i = log E[e^{delta_i}] from every quantized score, in exact form (sum of log sinh(a)/a) and in Taylor form b_i = sigma_i^2/2 = (1/24d) sum_c q_c^2 Delta_{i,c}^2. The correction uses only the stored step sizes and the query, needs no extra memory, and has grouped, per-channel and QuaRot (Hq) variants (Sec 4.2, Eq 12-15, App E/F). This is exactly the orchestrator's "exp(q.mu + q^T Sigma q / 2)" form. GPT's claimed difference ("it only fixes the logit bias") therefore reduces to the V and cross terms below.
  - The joint (K,V) part only adds something under a joint codebook. Every practical 2-bit LLM KV quantizer quantizes K and V independently: KIVI-style and OSCAR [2605.17757], KVarN [2606.03458], TurboQuant/QJL [2504.19874, 2406.03482], and the VQ methods CQ [2405.03917] and NOVA-KV [2608.04074] (separate key and value transforms and codebooks). Under that factorization E[e^{qK}V | C] = E[e^{qK}|C_K] * E[V|C_V]. The numerator correction is then the same key correction times the value centroid, and the Rao-Blackwell "K-V correlation" term Sigma_VK q is exactly zero. Making it nonzero needs a new joint (K,V) vector quantizer, kernels and per-cell cross-covariances. That is a different, heavier project, and nobody has shown the term is large.
  - "Calibrate the cell distributions" only makes sense for fixed codebooks (VQ: CQ, NOVA-KV). In per-token affine INT2 (KIVI, OSCAR, KVarN) the cells are defined by per-token scales and are not reusable objects. There the only statistic available is the uniform-noise variance, which 2605.26266 already uses.
  - In decode the expected gain is small and may not hit the target pathology. 2605.26266 itself says single-token decoding "offers less headroom", and that the correction helps little when attention is concentrated on a few cached tokens (Sec 6). Its LLM evidence is teacher-forced NLL under chunked prefill only (App O). KVarN [2606.03458] traces long-CoT degradation to per-token scale (magnitude) errors that accumulate over steps, which is realization error, not mean bias. An in-expectation correction leaves the per-realization noise unchanged.
- **Strongest objection in 1 sentence**: The nearly-free part of C1 is already published as the Jensen-bias correction of [2605.26266]. The only new piece, the joint K-V marginalization, is identically zero for the independent K/V quantizers used in practice, so the delta reduces to "apply 2605.26266 to long-CoT decoding", which is an evaluation, not a method.

#### Notes
- **Closest prior work**: [2605.26266] (the same mechanism for key cells, video diffusion plus an LLM partial-prefill NLL diagnostic). Neighbours: [2608.04074] NOVA-KV (attention-product-distortion transform coding with MSE-optimal VQ, so centroids are already conditional means); [2608.02691] OptR (minimizes post-W_O attention-output error from both the K- and V-induced terms, learned rotations); [2504.19874] TurboQuant_prod and [2406.03482] QJL (unbiased inner-product estimators, which are still biased after exp, i.e. they have the Jensen bias C1 targets); [2606.03458] KVarN (2-bit error accumulation in reasoning decode comes from token-scale errors). Queries run (11 in total; the arXiv web fallback returned 0 hits for long multi-word phrasings): "quantized KV cache softmax bias correction", "Jensen bias attention quantization", "expected exponential quantization noise attention", "quantization noise softmax attention correction", "KV cache vector quantization" (since 2025-09), "attention-aware KV cache quantization" (since 2025-09), "KV cache quantization reasoning models" (since 2025-09), "quantized attention unbiased softmax", "joint key value quantization", "vector quantization joint key value codebook KV cache", "Rao-Blackwell attention". No hit proposes joint (K,V) cell marginalization. The only hit on the bias mechanism is 2605.26266.
- **Plausibility at memory saturation**: Bytes at read time are unchanged. b_i comes from the scales already stored per group, a VQ variant needs a per-centroid q^T Sigma_c q lookup table computed once per query, and the FLOPs are a few multiply-adds per group next to QK^T. So C1 cannot change the bits x L^2 cost directly. It can only lower cost per correct answer by recovering accuracy and length at the same 2 bits, for example by cutting the Qwen3-8B AIME25 cap-hit rate from 42% back toward 11% under OSCAR INT2 [2609.38121]. That premise is weak. (i) In single-token decode a correction that is uniform across tokens cancels inside softmax. Only differences in sigma_i^2 across tokens matter, plus the competition with the BF16 sink and recent windows (OSCAR keeps 64 + 256 BF16 tokens [2605.17757]), so there is some headroom, but it is second order. (ii) Runaways are more plausibly driven by realization errors on a few high-mass tokens and by scale errors that accumulate [2606.03458], which an expectation correction does not touch, as 2605.26266 itself concedes for concentrated attention. (iii) The joint-V term is zero for the independent quantizers above. The expected gain is small but nonzero. It is worth knowing as a free plug-in baseline for other candidates, not as a paper.
- **Cheapest falsification**: Take about 20 BF16 Qwen3-8B AIME25 traces of 20-40K tokens. Replay them teacher-forced in HF with OSCAR- or KIVI-style INT2 KV, once plain and once with the 2605.26266 Taylor correction (Eq 15, about 20 lines in the attention function, with the BF16 sink and recent windows as the unquantized set). Measure per-token KL to BF16 next-token distributions, overall and in the 2K tokens before each point where the INT2 free run starts looping. If the correction closes less than ~20% of the INT2-to-BF16 KL gap, C1 is dead in every form (the joint-V extension can only add a term that is zero under these quantizers). This takes one GPU-day and needs no new kernel.

### C6 verdict
- **Verdict**: reject(reason=interval-read primitive already exists; low-dim signature cannot carry video-QA content and a frozen VLM cannot read it; no efficiency gain over streaming KV memories)
- **Evidence**:
  - [1603.03788] (GPT's source, exists, accurately cited for Chen's identity, Thm 1.2) also shows level k has d^k terms and that the signature encodes increments/areas of a path, not its content (1-D signature depends only on X_b - X_a). The math claim is correct; it is the payload that is weak.
  - [2001.00706] Signatory (ICLR 2021) already implements the exact mechanism C6 proposes: O(L) prefix Sig and InvertSig, then Sig(x_i..x_j) = InvertSig(x_1..x_i) ⊠ Sig(x_1..x_j) in O(1), plus online update; it warns of numerical instability for large i,j (exactly the long-video regime).
  - [2405.20799] Rough Transformers (NeurIPS 2024) already feed global S_{0,t_k} and local window signatures as compressed tokens to attention over long sequences; they note O(d^n) size and rely on small raw d and end-to-end training — neither holds for a frozen VLM over 1000+-dim visual features.
  - [2602.22142] (GPT's novelty foil, exists, CVPR 2026) trains order awareness and does entropy-gated coarse-to-fine recall of frame KV; the contrast GPT draws is accurate but WeaveTime is not the closest efficiency baseline.
  - [2511.07278] StreamKV and [2605.22269] MuKV (CVPR 2026) already give training-free segment-/multi-granularity summaries plus retrieval of real KV that the frozen LLM attends to; summarizing an interval is cheap there (mean pooling), so O(1) interval reads attack a non-bottleneck.
  - Novelty queries (path signature video; signature transformer video; log-signature video recognition; rough path video; signature kernel video; path signature multimodal; signature video large language model; Chen identity signature streaming; segment tree / prefix sum memory streaming video; interval query long video memory; streaming video LLM memory KV compression; rough transformer; since-2024 path signature) found no signature-based memory for video LLMs — so the application is unclaimed, but only skeleton-action signature work (Logsig-RNN 2110.13008, 1707.03993; not read) exists in video.
- **Strongest objection in 1 sentence**: The only new part is "apply Signatory's O(1) interval query to a tiny projection of VLM features", and a few-hundred-number geometric summary of feature motion is neither what video QA needs nor something a pretrained VLM can consume without training a new readout, so there is no cost-per-correct-answer win over StreamKV/MuKV-style KV memories.

#### Notes
- **Closest work**: mechanism — [2001.00706] (Path class: prefix signature + inverse, O(1) arbitrary interval, streaming update) and [2405.20799] (prefix/window signatures as Transformer tokens for long sequences). Target-problem — [2511.07278], [2605.22269], [2602.22142] (streaming video KV memory with segment summaries and retrieval). No 2025-2026 paper applies signatures to video-LLM memory.
- **Plausibility**: Truncated signature size is sum_{k<=n} d^k, so to stay near one token's width (~4K floats) one needs e.g. d=8, n=3 (584) or d=16, n=3 (4368): per-frame visual features (hundreds of tokens x ~1-4K dims) must be squashed to 8-16 channels before the signature is even taken. Higher levels then encode ordered co-variation of those few channels (Lévy areas, etc.), which helps "did A happen before B along these directions" but discards appearance detail, OCR, counting, and spatial layout that dominate Video-MME/MLVU errors; level 1 is just the endpoint difference, so a constant object present throughout an interval is invisible unless a basepoint/time augmentation is added. A frozen LLM has no way to read a tensor-algebra element: it needs a trained projection into its embedding space (GPT's own minimal experiment admits "light-train projection and readout"), which turns this into training a new memory adapter, and the readout must learn exponentially-sized, factorially-decaying, badly-scaled features. The O(1) interval read also requires knowing which interval to read; for QA the interval is unknown, so you still search over intervals (and the search cost, not the per-interval summary, is what StreamKV/MuKV optimize). Memory is fine (one ~600-4K-float vector per block boundary), but real KV memories already hit low memory via pruning, and their payload is directly attendable. Finally, S[0,a]^{-1} ⊗ S[0,b] cancels large prefix terms in float16/32 over thousands of frames, the instability Signatory flags. Net: not an efficiency gain over existing streaming video KV memories, and likely an accuracy loss.
- **Cheapest falsification**: no LLM needed. On Video-MME (or NExT-QA temporal subset) extract Qwen3-VL vision-encoder frame features, PCA to d in {8,16}, and compare a linear/MLP probe on (a) level-3 signature of the ground-truth or uniformly chosen interval vs (b) equal-float-count mean/max pooling of the same features (and of the unprojected features), predicting the multiple-choice answer given a question embedding. If (a) does not beat (b) at equal floats — especially on temporal-order questions where it should shine — the idea is dead; also log the relative error of S[0,a]^{-1}⊗S[0,b] vs direct computation in fp32 for 1-hour videos at 1 fps.
