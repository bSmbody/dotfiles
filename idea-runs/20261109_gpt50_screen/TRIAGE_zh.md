筛选标准：
- (a) 是不是**推理效率**的机制（以每答对一题的成本为目标）；
- (b) 3 个月内用 8×H200 能否完成，只允许不训练或轻量训练；
- (c) 收益在真实推理负载下说得通，读写字节和计算量不会反而变多；
- (d) 是否一看就属于已知的拥挤方向。

## 对这批 idea 的整体评价
1. **矫枉过正**：GPT 自报 50 个里有 49 个的机制来源在 ML 以外，结果大量 idea 是"漂亮的数学迁移"，但不针对推理效率，或者需要模型学会全新的输出协议。
2. **查新偏轻**：每条只保留一个最近邻，像 D2-01 这种疑似撞车的情况没被拦住。
3. **好的苗子集中在两类**：一类是"在读出数学上做文章、不改模型"（D1-02、D4-01、D4-03）；另一类是多模态里"减少重看和搜索的开销"（D6-01、D6-09）。

## 入围 7 个的审稿结果（reviewer 快速查新 + 对抗审稿，全文见 scores.md）

**7/7 否决。**

| # | GPT 编号 | 结论 | 致命问题 | 最接近的已有工作 | 最便宜的证伪实验 |
|---|---|---|---|---|---|
| C1 | D1-02 胞腔联合边缘化 | 否决 | K 和 V 分开量化时，"联合"那一项恒为零，剩下的就是 logit 偏差修正 | Quantized Keys Steal Attention 2605.26266 | 校准胞腔方差，加修正项，对比 2605.26266 的修正 |
| C2 | D1-03 精确字面量旁路 | 否决 | 本质是"按 token 类型混合精度 + 指针复制"，没有提升空间 | token 类型混合精度一类工作；Fractal KV 2607.07144 | 字面量 token 保 FP8，其余 2 bit，看准确率差距 |
| C3 | D4-01 最大耦合共读 | 否决 | 只省 ≤0.6% 字节；GQA 本来就共享读取；仍要读全部 key 才能算分布 | SANTA 2605.01910 | 统计各头共同质量，算实际省下的字节 |
| C4 | D4-03 守恒求积读取 | 否决 | 相对 SANTA 只是增量；只省 value 读取，key 扫描是下限；不省显存容量；Carathéodory 权重可用廉价控制变量替代 | SANTA 2605.01910、SANTA++ 2609.35629、2407.13613 | 同读取次数下，控制变量版 vs 求积版 |
| C5 | D6-01 正交创新式重看 | 否决 | 裁剪图的正交补在 token 张成空间里几乎为零 | GlobalCom2 2501.05179、GOTS 2607.23913、GRT 2509.14199、LoRe 2610.27341 | 测重看 token 投到已有视觉 token 张成空间后的残差能量 |
| C6 | D6-03 Chen 签名视频记忆 | 否决 | 签名方法 + 区间读取已有多篇 | Signatory 2001.00706、Rough Transformers 2405.20799、StreamKV 2511.07278、MuKV 2605.22269 | — |
| C7 | D6-09 组合编码视觉搜索 | 否决 | VLM 一次测试的 token 成本正比于池里的区域数，总计不省；固定预算压缩会漏掉小目标；单次定位或层级搜索已经更好 | ViCrop 2502.17422、VisLens 2608.30705、ZoomEye 2411.16044、V* 2312.14135、Neural Group Testing 2011.10704 | V*Bench 上把目标块和 1/3/7 个干扰块组池，测池召回率和 token 成本 |

**共同死因**：
1. 数学上漂亮，但没算 GPU 上真实的读写和 token 账（C3、C4、C7）；
2. 机制的"新"部分在实际条件下退化成已有方法（C1 → logit 修正；C5 → 正交 token 选择；C2 → 混合精度）；
3. 查新只给一个近邻，没拦住撞车（C6）。
