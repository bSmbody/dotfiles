# LPOSS: Label Propagation Over Patches and Pixels for Open-vocabulary Semantic Segmentation

## What this paper does
LPOSS refines VLM patch predictions by label propagation on a graph of DINO patch features (kNN appearance times Gaussian position affinity), solved jointly across all sliding windows so the whole image interacts. LPOSS+ adds a second label propagation on a pixel graph (RGB affinity in an r×r neighbourhood), initialised with the upsampled patch-level result, to fix block artifacts near boundaries. An oracle that downsamples ground truth to patch resolution quantifies how much patch-level prediction loses. Evaluated with mIoU and Boundary IoU on eight benchmarks.

## Goal-by-goal answers

### Goal: (axis: small objects and stuff classes) What mechanism does it use that affects small or thin objects, and at what resolution/scale is the class decision made?
LPOSS refines MaskCLIP-style patch predictions Y_vlm by label propagation Y = L_inv(S) Y_vlm over a kNN graph of DINO patch features times a Gaussian spatial kernel, jointly over all sliding windows (window 224, stride 112) [full text, Sec 3.3-3.4, Eq 7-8]. LP minimises Q(Ŷ) = (1−α)Σ||Ŷ_i − Y_i||² + αΣ S_ij||Ŷ_i/√D_ii − Ŷ_j/√D_jj||² — a fidelity term to the initial VLM prediction plus smoothness; footnote: LP here "refine[s] predictions for all nodes which are already labeled" [Sec 3.2, Eq 5]. LPOSS+ adds a second LP on a pixel graph (r×r neighbourhood, RGB affinity) initialised with the upsampled LPOSS output [Sec 3.5, Eq 10]. So pixel-level output is a smoothed redistribution of patch-level class evidence.

### Goal: (axis: small objects and stuff classes) What mechanism does it use for stuff classes / large regions / many-class benchmarks, and what global context or class-competition handling does it apply?
Context comes from geodesic similarities over the whole-image patch graph (no window-limited prediction) [Sec 3.4]. No class-side handling; classes compete by argmax after propagation. LPOSS+ gives Stuff 26.5, ADE 22.3, City 37.9 (ViT-B/16) [Table 1].

### Goal: (axis: small objects and stuff classes) What does it report as its limitation or failure on small objects or stuff classes, and which knobs are set per dataset?
Oracle: ground truth downsampled to patch resolution (P=16) and upsampled yields only 85.2 mIoU on average, with the lowest ceilings on Cityscapes (73.6) and ADE20K (80.6), and 69.5 Boundary IoU [Table 1-2, Sec 3.5] — patch-level decisions inherently lose small structures. Pixel-level LP improves mIoU by only +0.8 on average (Stuff +0.6, ADE +0.5, City +0.6) but Boundary IoU more (+1.8) [Sec 4.3, Table 1-2], i.e. it mostly sharpens boundaries of already-predicted classes. LP rarely harms images, except when the initial MaskCLIP output is very noisy [Sec 6.2]. Window size matters (VOC20 weak at 224; 448/224 window comparable) [Sec 4.3].


### Goal: (reviewer R1, C3) Is aspect-preserving overlapping-window inference already the standard protocol in training-free OVSS, and how much does it matter on Cityscapes?
Yes for the CLIP line: "Current approaches [25, 28, 44, 48] perform feature extraction and prediction in a sliding-window fashion to handle test images of arbitrary resolution", averaging per-window predictions per pixel, because ViTs "generalize poorly to resolutions and aspect ratios different from the ones used during training" [full text, Sec 3, "Class prediction using a sliding window approach"]. Table 3 (smaller side resized to 448) shows the effect: ProxyCLIP goes from 13.6 mIoU on Cityscapes without windows to 33.6 (448/224 windows) and 36.0 (224/112), CLIP-DINOiser from 28.2 to 31.1 and 36.3, LPOSS+ from 28.5 to 37.9; averages move by only 1.5-10 points [Table 3]. "The largest drop in the performance happens on the Cityscapes dataset, which has an aspect ratio that is furthest from the square aspect ratio" used in training [Sec 4, "Impact of sliding windows"]. Window size preference differs by method [Sec 4]. So uniform overlapping windows that keep the aspect ratio are the default CLIP-OVSS protocol and are worth the most exactly on Cityscapes.
