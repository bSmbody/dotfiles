# Looking Beyond the Window: Global-Local Aligned CLIP for Training-free Open-Vocabulary Semantic Segmentation

## What this paper does
GLA-CLIP (CVPR 2026) targets inconsistency between independently processed sliding windows. In the last attention layer each window's DINO-derived queries attend to keys/values from all windows (Key-Value Extension); queries are replaced by proxy anchors (iterated means of globally similar tokens) to remove a bias toward inner-window tokens; and a dynamic normalization rescales and thresholds attention per query using the count of high-similarity tokens as an object-scale proxy and the number of windows as a noise proxy. It is a plug-in for ProxyCLIP, ClearCLIP, SCLIP and CLIP-DINOiser settings, evaluated on eight standard benchmarks.

## Goal-by-goal answers

### Goal: (axis: small objects and stuff classes) What mechanism does it use that affects small or thin objects, and at what resolution/scale is the class decision made?
GLA-CLIP keeps the standard sliding-window protocol (frozen CLIP ViT-B/16 values, DINO ViT-B/8 as VFM for queries/keys; crop/stride as in ProxyCLIP) and changes only the last-layer attention [full text, Sec 3.1.2, 4.1]. Key-Value Extension lets each window's queries attend to keys/values gathered from all L windows (Eq 6-9). Proxy anchors replace each query by the iterated mean of all global keys whose cosine similarity exceeds ρ=0.6 (Eq 10-12, T=2 steps). Small objects are handled only by "Dynamic Normalization" (Eq 13-15): Attn_i = w_i (S_proxy − (u/NL)·Σ_j S_proxy,ij), with u = 1+λ1·log(1+L) depending only on the number of windows, and w_i = 1+λ2/|P_i|, where |P_i| (count of tokens above ρ) is used as a proxy for object scale [Sec 3.4]. Class decisions remain per patch on the window token grid; no re-encoding at a different scale is done.

### Goal: (axis: small objects and stuff classes) What mechanism does it use for stuff classes / large regions / many-class benchmarks, and what global context or class-competition handling does it apply?
The motivation for KV extension is explicitly stuff: the window-limited receptive field "becomes especially pronounced when semantically coherent regions (such as large objects or spatially continuous stuff categories) are partitioned across multiple windows" [Sec 3.2]. Large regions receive permissive normalization (small w_i) so they aggregate many outer-window tokens; the qualitative example is road vs sidewalk on Cityscapes [Sec 4.2]. There is no class-side (text) handling; competition between classes is plain argmax over cosine logits.

### Goal: (axis: small objects and stuff classes) What does it report as its limitation or failure on small objects or stuff classes, and which knobs are set per dataset?
Without dynamic normalization, extending attention globally lets small-object queries be "dominated by irrelevant tokens" [Sec 3.4]. Fig 5 shows |P_i| correlates with class size on Cityscapes (road/terrain large, person/rider small) [Sec 5.3]. But the hyperparameter study states that λ1 (the window-count-driven masking threshold) matters while "λ2 has minimal impact on performance" [Sec 5.4] — i.e. the per-query, scale-dependent term carries little of the gain. Dataset-specific tuning ("Best") gives 44.3 vs 44.0 for the shared setting [Table 2]. Stated limitations: compute cost of using all tokens from other windows, and hyperparameters may need re-tuning per backbone [Sec 6].
