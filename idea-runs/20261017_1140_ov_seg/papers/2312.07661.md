# CLIP as RNN: Segment Countless Visual Concepts without Training Endeavor

## What this paper does
CaR (CVPR 2024) is a training-free open-vocabulary segmenter built from frozen CLIP and run as a recurrence. Each step proposes one gradCAM mask per remaining text query. It marks that mask on the image with a visual prompt (red circle, background blur, gray background), re-scores the prompted images with CLIP, and removes queries whose matched score falls below a threshold. The loop repeats until the query set stops changing, and the last step's masks are post-processed. It reports large gains over earlier zero-shot methods on Pascal VOC, COCO-Object and Pascal Context, plus referring segmentation.

## Goal-by-goal answers

### Goal: (reviewer C1) What does each recurrent step re-measure, what rule eliminates text queries, and is the re-query local (per location, zoomed) or image-level?
Each step works as follows (Algorithm 1, Eq 3–6) [full text, Sec 3.2–3.3]:
1. CLIP scores the image against the current queries h_{t−1}.
2. CLIP-ES gradCAM with class affinity, plus added background queries, gives one mask proposal per query.
3. Each proposal is binarised at η and drawn on the image as a visual prompt.
4. CLIP classifies the N prompted images against the N queries, with a softmax over queries. The diagonal entry P_ii is the score of query i on its own mask.
5. A query is dropped if P_ii < θ, a manually set threshold.

The loop stops when h_t = h_{t−1}. The re-measurement is image-level: the whole image is re-encoded with a prompt highlighting the mask. Nothing is cropped or zoomed, and the vocabulary is pruned for the whole image, not per location. The recurrence is essential: one step (T = 1) gives 15.2 mIoU, against 67.6 with recurrence. Most VOC and COCO images need two steps [Sec 4.2, Table 2].

### Goal: (reviewer C1) What does it say about small objects, and on which benchmarks is it evaluated?
CaR is evaluated on Pascal VOC, COCO-Object and Pascal Context, plus referring-segmentation sets. In the parts read, it does not report ADE20K or Cityscapes [Sec 1, Sec 4]. The authors list small objects as a weakness to address with extra modules: "incorporating additional trainable modules such as Feature-Pyramid Networks can significantly improve its capability in handling small objects" [App I]. The stated limitation is that performance is bounded by the pre-trained VLM [App H].


### Goal: (innovator C3) Which visual-prompt edits does CaR compare, what does each do to the pixels it covers, and what does removing image content (rather than marking it) cost CLIP's recognition?
CaR draws the mask proposal onto the image with a circle, a contour, background blur, a gray background (the region outside the mask converted to grayscale, so structure is kept and only colour is removed), or a "mask" prompt that blacks out every pixel outside the mask [full text, Sec 3.3, Fig 4; App C code]. On Pascal VOC (Table 4): circle 66.9, contour 66.0, blur 66.4, gray 66.1, mask 61.8, and circle + blur 67.6 mIoU [Sec 4.2, Table 4]. The authors note that blacking out, "a common practice for most previous open-vocabulary segmentation approaches", gives the lowest score, and adopt prompts that "highlight the foreground as well as preserve the context in the background" [Sec 3.3, Sec 4.2]. So every CaR prompt keeps or marks content; none removes a region in order to ask whether the concept is still present elsewhere, and the one prompt that deletes content (blacking out the context) costs about 5 mIoU against the context-preserving ones. Larger CLIP backbones understand visual prompts better [Sec 4.2, Table 3].
