# ZoomEye: Enhancing Multimodal LLMs with Human-Like Zooming Capabilities through Tree-Based Image Exploration

## What this paper does
ZoomEye (EMNLP 2025) is a training-free, model-agnostic tree search that lets a multimodal LLM zoom into high-resolution images. The image is a tree: the root is the whole image, and each node splits into four equal sub-patches until the encoder's native resolution is reached. The MLLM ranks nodes by its own yes/no confidence that a visual cue is in the view, or could be found by zooming further. Search stops when the model says it can answer, and the answer is formed from the union box of the visited nodes. It improves V* Bench and HR-Bench by large margins for 3–8B MLLMs.

## Goal-by-goal answers

### Goal: (reviewer C2) What does a tree node represent, and what model signal decides which nodes are expanded or zoomed?
A node is a crop box of the image. A crop larger than the encoder's resolution is split into four equal children, recursively down to that limit [full text, Sec 3.2]. Each node's priority is a depth-weighted sum of two confidences, computed from the Yes/No next-token logits: "existing confidence" (prompt "Is there a o in the sub-patch?") and "latent confidence" ("Is it possible to find a o by further zooming the sub-patch?"). Latent confidence gets more weight at shallow depth, where the cue may be too small to see [Sec 3.3, Alg 2]. So the model's own crop-level recognition of the named cue decides which crops are zoomed.

### Goal: (reviewer C2) Is it training-free, and does it handle several targets, all instances of a target, or dense per-pixel output?
It is training-free and model-agnostic [Sec 1, Sec 6]. Before searching, the MLLM lists k visual cues from the question. "Type 1" cues need one instance, and their search stops at the answering-confidence threshold. For "type 2" cues (all instances, e.g. counting) "S is not applied, and we search the whole tree to add all nodes with sufficient existing confidence" [Sec 3.5, Table 1]. The output is a text answer from the union bounding box of the selected nodes. There is no per-pixel output, no map of what is already explained, and no rule for which view is authoritative for which region [Sec 3.5].

### Goal: (reviewer C2) What do its ablations and limitations say about cost and about fixed splitting?
Accuracy rises with the number of search steps and then plateaus, a "vision-level test-time scaling" [Sec 4.4.1, Fig 4]. When the searched box covers at least 50% of the target, LLaVA-ov-7B's accuracy is 93.45%, against 54.55% when it does not [Table 4]. Splitting into 4, 9 or 16 children gives similar accuracy, at 8.2, 5.7 and 5.0 average search steps [Table 5]. The authors list as limitations the hand-set ranking and stopping heuristics, and fixed-size patches that "may not align well with the semantic regions", so that cues "may be fragmented or overlooked" [Sec 6].


### Goal: (innovator C3) In the all-instance (type 2) search, does a node's test change once an instance inside it has been found, or is every node holding any instance positive?
Every node is tested on the unedited crop. The type-2 routine visits nodes breadth-first up to depth 2, computes each node's existing confidence for the cue, appends the node to L if it is at least τ2 = 0.8, and always enqueues all its children [full text, App, Alg "Zoom Eye Type 2"; implementation details, τ2 = 0.8, max depth 2 "to save costs"]. Nothing found in a node is removed or masked before its children or siblings are tested, so a node is positive whenever any instance of the cue is visible in it, whether or not that instance was already captured by another node, and expansion is exhaustive rather than gated [Sec 3.5; App Alg]. The selected nodes are merged into one union box for the answer [Sec 3.5].
